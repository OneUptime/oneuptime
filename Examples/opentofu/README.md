# OneUptime with OpenTofu

The OneUptime provider is published to the [OpenTofu Registry](https://search.opentofu.org/provider/oneuptime/oneuptime/latest) and `tofu` is a tested path, not an assumption: the provider's end-to-end suite runs its fixtures against **both** OpenTofu and Terraform on every pull request (`.github/workflows/terraform-provider-e2e.yml`).

## Contents

| Directory | What it is |

## Running these

```bash
export ONEUPTIME_API_KEY="<project api key>"
cd quickstart
tofu init
tofu plan
tofu apply
```

Create the API key in **Project Settings > API Keys** in the OneUptime dashboard. It must be a **project** API key with create/read/update/delete on the resource types you manage — a user key or a self-hosted master key fails with `ProjectId required`.

Self-hosted: set `-var oneuptime_url=https://oneuptime.example.com`, and read [Self-Hosted Setup](https://oneuptime.com/docs/terraform/self-hosted) before pinning a provider version.

## What is actually OpenTofu-specific

Very little, and that is the point. The provider is a standard plugin-protocol-6 provider, so OpenTofu drives it through the same mechanisms it inherited.

- **The source address is unchanged.** `source = "oneuptime/oneuptime"` has no registry hostname, so OpenTofu resolves it against `registry.opentofu.org` and Terraform against `registry.terraform.io`. The provider is published to both. Do not hard-code a hostname.
- **The `terraform` block stays `terraform`.** It is a language keyword, not a reference to the Terraform CLI. OpenTofu reads it as-is.
- **`.tf` files work unchanged.** OpenTofu additionally reads `.tofu` files and ignores `.tf` files that have a `.tofu` sibling. That is the escape hatch for configuration only OpenTofu should see; nothing here needs it, and using it would make these examples Terraform-incompatible for no gain.
- **Version constraints.** OpenTofu's version series starts at 1.6.0, so a `required_version = ">= 1.5.0"` constraint written for Terraform is satisfied by every OpenTofu release.
- **Lock files and state are the same.** Both engines write `.terraform.lock.hcl` and `terraform.tfstate`. A lock file records the registry it resolved against, so a lock file generated by one engine will not satisfy the other — commit whichever your CI uses, and regenerate with `tofu init -upgrade` if you switch.
- **Variables.** OpenTofu reads `TF_VAR_*` as well as `TOFU_VAR_*`, so existing tooling keeps working.
