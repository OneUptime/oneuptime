# Runbooks that get used

Author: [oneuptime](https://www.github.com/oneuptime)

Tags: On-Call, Incident Management

Description: Short, tested runbooks beat long ones nobody opens. How to write one an on-call engineer can follow at three in the morning.

A runbook is only useful if the person paged at three in the morning opens it and can follow it half awake.

## Keep it to one page

Start with the symptom the alert describes, then list the checks in the order you would run them. Link to dashboards instead of describing them.

## Test it

Run every step yourself before you need it. A step that has never been run is a guess.
