# Marks of other companies' products

The marks OneUptime shows next to a third-party product's name: the storage
an audit log export or a backup goes to, the security tools a project
connects, its clouds and AI providers, Slack and Microsoft Teams, the tools
Import from another tool reads, the languages and frameworks the telemetry
guide and the website's OpenTelemetry guides are written for, the tools the
website compares OneUptime with, and the chat apps, infrastructure and code
hosts the icon set names.

`ProviderLogo.ts` names them. `ProviderLogoMarks.ts` says how each one is
drawn and the box its mark sits in; `Marks/<logo>.ts` holds each mark's
shapes. In the product, `Common/UI/Components/ProviderLogo/ProviderLogoImage.tsx`
draws them, each mark loaded on its own the first time a page shows it
(`ProviderLogoMarkLoader.ts`), and the icon set (`Common/UI/Components/Icon`)
draws its brand glyphs from the same marks. The website draws them into its
pages from `AllProviderLogoMarks.ts`.

## The rule: one colour, as an icon

Every mark is drawn the way OneUptime's own icons are: an inline SVG whose
every shape is filled with the current colour (`currentColor`). It takes the
colour of the icons around it - the grey of a tile, the indigo of a picked
row, the light grey of the dark theme - so a list of products reads as one
set with the generic things beside them (a webhook, syslog), and nothing
looks pasted in.

- **Never an image.** No PNG, JPEG or WebP, no `<img>` of an SVG file, no
  data URL: a mark is path data in a TypeScript module.
- **Never the brand's colours.** One colour. The only shading is the one a
  brand's own mark has: a shape it draws lighter (UptimeRobot's halo) keeps
  that lightness as an opacity of the same colour.
- **The brand's own shapes, unaltered.** Never redrawn, cropped into another
  shape, stretched or rotated. Each box is fitted to its drawing, so the
  proportions are the mark's own; the colour is the only change.
- **Official.** Each mark is the brand's own one-colour mark: from its own
  kit (Microsoft's Fluent UI Fabric glyphs), or from a collection that
  reproduces brands' marks faithfully and drops a brand that asks it to,
  [Simple Icons](https://simpleicons.org) (its drawings are CC0 unless the
  table below names another licence). The marks stay their owners'
  trademarks.
- **Within the brand's rules.** Where a brand's rules allow no logo in a
  product like this, or none in one colour, the product is drawn by one of
  OneUptime's icons instead; where a product is one of a maker's many and
  has no one-colour mark of its own, by its maker's mark (both below).
- **Local.** Every mark is part of the installation: an installation without
  the internet draws every one, and no brand learns who opened a page.
- **Named.** Every mark is shown with the product's name beside it (one
  drawn without words has the name as its accessible name): a mark
  identifies the brand's product, never OneUptime's.

## Kept in colour on purpose, outside this registry

- **Sign in with Microsoft** (the sign-in pages): Microsoft's sign-in
  branding asks for its four-colour logo on the button.
- **Mobile Apps** (Settings): Google Play's mark in its colours on the store
  badge, as Google's badge guidelines ask. Apple's mark is one colour
  already.
- **OneUptime's own logo**, and a logo a licence replaces it with: the
  product's own brand, drawn from its own files.
- **Emails**: no email carries another company's mark. Mail clients do not
  draw inline SVG (Gmail drops it, Outlook does not render it), so the only
  image an email has of its own is OneUptime's logo as a PNG attachment
  (`Common/Server/Utils/Mail/EmailLogo.ts`), or a logo its operator
  uploaded.

The guards list each of these with its reason; anything new fails them.

## Adding a mark

For a new product, in the product or on the website:

1. Find the brand's own one-colour mark: its press kit's black or white
   mark, its own monochrome glyph, or [Simple Icons](https://simpleicons.org)
   (read the icon's licence and its brand's guidelines in Simple Icons'
   data). Never a colour logo recoloured from an image, never a PNG. Check
   that it is the mark the brand uses today: a collection can lag a
   rebrand (Simple Icons still draws Okta's old ring, not the Aura Okta has
   used since 2022).
2. Read the brand's rules. If they allow no logo in a product like this, or
   none in one colour, give the product an icon of OneUptime's in
   `PROVIDER_LOGO_STAND_IN_ICONS` and its row above; if it is one of a
   maker's products without a mark of its own, draw it by its maker's
   (`PROVIDER_LOGOS_DRAWN_BY_THEIR_MAKERS_MARK`).
3. Add the logo to `ProviderLogo` and `PROVIDER_LOGO_NAMES`, its shapes to
   `Marks/<logo>.ts` (every shape a path: no colour, no stroke, no
   transform), its box fitted to the drawing to `PROVIDER_LOGO_MARK_BOXES`,
   its loader to `ProviderLogoMarkLoader.ts`, its line to
   `AllProviderLogoMarks.ts`, a row below, and the logo to the catalog
   entry that names the product.

`Common/Tests/Types/ProviderLogo` and `Common/Tests/UI/Components/ProviderLogo`
hold every mark to these rules, and fail on an image, a second colour or a
mark without its row here.
