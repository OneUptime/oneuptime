# モニターの作成

モニターは、ウェブサイト、API、ホスト、Kubernetes クラスターなど、運用しているものをチェックし、動かなくなったときに知らせます。**モニターを作成** は、まず何を監視するか、次に何をチェックするか、最後にどのくらいの頻度かを尋ねます。種類、名前、チェックする対象以外は、ほとんどのモニターに合うデフォルト値から始まります。

## モニター情報

**モニター** を開いて **モニターを作成** をクリックします。最初の質問は **モニターの種類**、つまり何を監視するかです。

- 最もよく作成される 6 つの種類が最初に並びます: **Website**、**API**、**Ping**、**ポート**、**SSL 証明書**、そして cron ジョブや webhook からのハートビート用の **受信リクエスト** です。
- **その他のモニターの種類** を押すと、ほかのすべての種類がカテゴリーごとに表示されます。たとえば **インフラストラクチャ** (Kubernetes、Docker、Host) や **テレメトリ** (ログ、メトリクス、トレース) です。ステータスを自分で設定するモニター **手動** は **その他** にあります。
- または検索ボックスに入力します。`k8s`、`postgres`、`heartbeat`、`tls` など、普段使っている言葉で見つかり、**Enter** で最初の候補を選べます。

選んだ種類は 1 行に縮まります。別の種類にするには **変更** をクリックし、選び直している途中で **Escape** を押すと元の種類のままになります。

次に **名前** を入力します。アラートやインシデントのタイトルに使われます。**説明** と **ラベル** は任意で、**その他の項目** の中にあります。

**手動** モニターはそれ以上何も必要ないので、このステップに **モニターを作成** があります。

## 条件

このステップは、何をチェックするかから始まります。ウェブサイトならその URL で、入力欄に例が表示されます。ほかの種類では、ホスト、クエリ、クラスター、ログのフィルターなどを入力します。**モニターをテスト** で、保存する前に一度チェックを実行できます。

その下の **モニター条件** は、モニターがステータスを変える、インシデントを宣言する、またはアラートを作成するタイミングを決めます。新しいモニターは、ほとんどのモニターに合う条件から始まり、それぞれが何をチェックし何をするかを示す 1 行に折りたたまれています。たとえば新しいウェブサイトのモニターは、サイトが応答しないかエラーのステータスコードを返すと、オフラインになりインシデントを宣言します。条件をクリックすると開いて変更できます。**条件を追加** は、開いた状態ですぐ入力できる条件を追加します。

このステップでは、**次へ** をクリックするまで何も未入力として表示されません。

## プローブと間隔

プローブがチェックするモニターは、このステップで終わります: Website、API、Ping、IP、Port、SSL Certificate、DNS、DNSSEC、NTP、Domain、SQL Query、Database Health、Synthetic Monitor、Custom JavaScript Code、External Status Page。**プローブ** はチェックを実行するマシンで、プロジェクトのデフォルトのプローブがあらかじめ選択されています。**監視間隔** は **5 分ごと** から始まります。**モニターを作成** をクリックします。

ほかの種類はすべて **条件** のステップから作成します。

## テンプレートやリンクから始める

モニターテンプレートや、OneUptime のほかの場所 (メトリクスのグラフ、ネットワークデバイス、検出ルール) にあるモニター作成用のリンクからは、種類が選ばれ、ほかの項目も入力された状態で **モニターを作成** が開きます。別の種類にするには **変更** をクリックします。テンプレート自体のフォームも同じ種類の選択を使います: [モニターテンプレート](/docs/monitor/monitor-templates) を参照してください。
