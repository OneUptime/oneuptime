# チェックと照合

テーブルのヘルスは、テーブルが変更されているかどうかを示します。 **チェック** は中身が正しいかどうかを、 **照合** はデータの 2 つのコピーが一致しているかどうかを示し、 **dbt のテスト** は dbt が作成するテーブルについて報告します。どれもデータベースの収集が実行される場所 (OneUptime またはそのプローブ) で実行され、データベースの外に出るのは数値だけです。ただし、プロジェクトが、失敗した行のマスク済みのサンプルを保持することを選んだ場合を除きます。

## チェック

チェックは、テーブルの **チェック** タブで追加します:

| チェック | 読み取る内容 |
| --- | --- |
| **NULL の割合** | 列が空である行の割合 |
| **重複の割合** | ほかの行の値と重複している値の割合 |
| **異なる値の数** | 列に含まれる異なる値の数 |
| **最小**、**最大**、**平均**、**合計** | 数値列が対象 (行がないときの合計は 0) |
| **無効な値の割合** | 指定したリストに含まれない値の割合 |
| **形式不一致の割合** | Email、UUID、Country Code など、選んだ形式ではない値、または自分で指定した正規表現に一致しない値の割合 (SQL Server と Dataverse 以外のすべてのエンジン) |
| **孤立行の数** | 値が、別のテーブルの列に一致するものを持たない行 |
| **行数** | テーブルの行数。 **分割する列** と組み合わせると特に役立ちます |
| **カスタム SQL** | 自分で書いた読み取り専用の SELECT 1 つが返す、 `value` という名前の数値 (MongoDB では集計パイプラインが返す数値) |
| **失敗した行** | 自分で書いた読み取り専用の SELECT 1 つが返す行の数: 存在してはならない行です。0 が正常です (MongoDB では、パイプラインが最後に返すドキュメント) |

各チェックは、15 分、1 時間、6 時間、または 1 日ごとに、ステートメントのタイムアウト付きの読み取り専用トランザクションの中で、1 つの集計ステートメントとして実行されます。その値は `oneuptime.data.check.value` として、 `oneuptime.data.check.id`、`oneuptime.data.check.name`、`oneuptime.data.check.segment` とともに書き込まれます。

## 推奨チェック

同じタブの **推奨チェック** は、テーブルの列の名前と型だけから、その列に必要なチェックを提案します: id が一意であること、 `customer_id` に一致する行が `customers` にあること、メールアドレスがメールアドレスの形式であること、金額が負でないこと、ステータスがいつもの値を保っていること、テナントごとに分かれたテーブルをテナントごとに数えること、といったものです。Data Security がメールアドレス、電話番号、または IP アドレスを保持していると把握している列は、名前に関係なくその形式が求められます。1 つ追加することも、すべて追加することも、1 つを今後表示しないようにすることもできます。

## 1 文から作るチェック

**文からチェックを作成** は、「注文の合計が負になることはない」のようなルールを、そのルールに違反する行を数えるカスタム SQL チェックに、エンジン自身の SQL で変換し、違反する行があればアラートを出します。 **チェックを追加** で追加する前にクエリを確認でき、ほかのカスタム SQL チェックと同じ制約がすべて適用されます。プロジェクトで OneUptime AI がオンになっている必要があります。MongoDB では、結果は集計パイプラインになります。

## セグメント

**分割する列** は、テナントやリージョンなど、列の値ごとにチェックを 1 回ずつ実行します: 上位 100 個のセグメントそれぞれに、1 つの系列と 1 つのアラートがあります。セグメント化した行数のチェックは、ほかのテナントが送り続けているのに 1 つのテナントだけがデータを送らなくなったときにアラートを出します。

## チェックのアラート

チェックでアラートを出すには、 **アラート条件** を設定します:

- **異常に高い** または **異常に低い** は、各値を、週のその時間帯についてそのチェック自身が学習したベースラインと比較します。
- **上回る** または **下回る** は、値をしきい値と比較します。

チェックを保存すると、あなたとして、あなたの権限で、そのチェックのメトリクスモニターが作成されます。条件を空にすると、モニターは削除されます。

チェックの **ステータス** は、 **チェック** と、そのテーブルの **チェック** タブで、チェックの状態を示します: アラートが開いている間は **失敗中**、開いていなければ **合格**、クエリが失敗したときは **実行できませんでした** です。アラートのないチェックは **実行** とだけ表示され、クエリが動いたことだけがわかります。失敗中のチェックと、実行できなかったチェックは、 **概要** にも表示されます。

## チェックのコスト

チェックはアプリケーションとデータベースを取り合い、読み取った量で課金されるウェアハウスでは、お金がかかります。次の 3 つで抑えられます:

- **サンプル割合** は、すべての行ではなく一部の行を読み取ります。割合を読み取るチェックが対象です: NULL の割合、平均、無効な値の割合、形式不一致の割合。ほとんどのエンジンはテーブルのページごとスキップします。MySQL、Redshift、ClickHouse、MongoDB はすべての行を読み取りますが、残りの処理は省かれます。Dataverse ではサンプリングせず、チェックはすべての行を読み取ります。ビューでは使えないことがあり、その場合はチェックがそう表示します。
- **チェックが読み取れる上限 (GB)** は、**設定** にあり、BigQuery や Athena のチェックが、そのギガバイト数を超えて読み取る前に停止します。変更するまでは 10 です。
- **データベースが混み合っているときは待機** は、**設定** にあり、PostgreSQL、MySQL、SQL Server のデータベースが混み合っていそうなとき、実行時期になったチェックを次の収集まで見送ります。オフにするまでオンで、チェックが待機したときはデータベースに表示されます。

## 失敗した行

数値は何かがおかしいことを伝え、いくつかの行は何がおかしいかを伝えます。**設定** の **失敗した行を保持** が、「失敗した行」「無効な値の割合」「形式不一致の割合」「孤立行の数」のチェックが見つけた行を最大 20 件保持し、チェックの **失敗した行** に表示されます。この設定はオンにするまでオフのままです。機密性の高い列は、行が読み取られる場所で、Data Security がそこで見つけたものや列の名前に基づいてマスクされるため、データベースやプローブの外に出るものはすでにマスクされています。スキャンで見つかっておらず、名前からも判別できない機密性の高い列は、そのまま保持されます。

行は OneUptime に保存されます。OneUptime Cloud では OneUptime のサーバーに、セルフホストのインストールではお客様自身のサーバーに保存されます。プロジェクトのチェックを読み取れる人は誰でもそれらを見ることができます。チェックが保持するのは最後の実行の行だけで、**失敗した行を保持** をオフにすると、各チェックが保持していた行は削除されます。

## ファイルでのチェック

手で書いたチェックは、テーブルを変更するコードからずれていきます。リポジトリで管理し、同じプルリクエストでレビューしてください:

```yaml
checks:
  - name: Orders have a total
    table: public.orders
    type: Null Percent
    column: total
    every: 60
    alert: { when: Above, threshold: 1 }
  - name: Emails look right
    table: public.customers
    database: Orders database
    type: Format Mismatch Percent
    column: email
    format: Email
    sample_percent: 10
  - name: Orders have a customer
    table: public.orders
    type: Orphan Count
    column: customer_id
    references: public.customers.id
  - name: No negative totals
    table: public.orders
    type: Failing Rows
    query: SELECT id FROM orders WHERE total < 0
    alert: { when: Above, threshold: 0 }
```

CI から、[OneUptime CLI](/docs/cli/index) と API キーで適用します:

```bash
oneuptime data-checks apply checks.yaml --dry-run
oneuptime data-checks apply checks.yaml --prune
```

同じテーブルで同じ名前を持つチェックは同じチェックなので、ファイルを 2 回適用しても何も変わりません。ファイル内のどこかに誤りがあると、何も適用されずエラーで終了するため、プルリクエストでは `--dry-run` を実行し、マージ時に適用してください。`--prune` を付けると、以前の apply が作成したチェックのうち、ファイルに名前がなくなったものが削除されます。手で追加したチェックが削除されることはありません。ファイルから作られたチェックは、その行にそう表示され、次の apply で、手で変更された内容は上書きされます。

キーは `name`、`table`、`database`、`type`、`column`、`segment`、`accepted_values`、`format`、`pattern`、`references`、`query`、`sample_percent`、`every`、`alert`、`description`、`enabled` です。

## 照合

コピーはずれていきます: ウェアハウスの注文がアプリケーションのデータベースより少ない、移行で行が失われた、といったことです。 **照合** では、1 つまたは 2 つのデータベースにある 2 つのテーブルについて、1 つの尺度を比較します:

- **行数**
- 列の **合計**
- 列の **異なる値の数**
- **カスタム SQL**: `value` という名前の 1 つの数値を返す読み取り専用のクエリ

照合には許容範囲があります: **絶対値** による量か、ソースの値に対する **パーセント** です。それぞれの側は、照合が作成して管理する専用のチェックによって、そのデータベースの収集とともに読み取られます。そのため、ネットワーク内の PostgreSQL のテーブルと、Snowflake にあるそのコピーを比較することもできます。2 つの値は、両方が互いに 15 分以内に読み取られた時点で比較されます。照合は次のメトリクスを書き込みます:

- `oneuptime.data.reconciliation.drifted`: 2 つの値が許容範囲を超えてずれていれば 1、一致していれば 0。照合のモニターはこの値を読み取ります。
- `oneuptime.data.reconciliation.difference`: ターゲットの値からソースの値を引いたもの。
- `oneuptime.data.reconciliation.difference_percent`: その差を、ソースの値に対するパーセントで表したもの。

スケジュールでロードされるコピーは、ソースより遅れます: 両方で確定済みの尺度 (1 時間より古い行など) をカスタム SQL で比較するか、許容範囲で遅れを見込んでください。

## dbt のテスト

dbt のビルドの後、 `oneuptime dbt upload` がプロジェクトのアーティファクトを送信します ( [リネージとパイプライン](/docs/data-observability/lineage-and-pipelines) を参照)。すると、監視対象のテーブルの各テストが、最後の結果と、失敗として見つかった行とともに、そのテーブルの **チェック** タブに表示されます。失敗したテストでアラートを開くには、 **失敗時にアラート** を選びます。
