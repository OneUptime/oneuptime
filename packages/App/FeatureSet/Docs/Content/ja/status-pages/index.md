# ステータスページ概要

ステータスページは、あなたが監視しているものすべての公開された顔です。「うちだけの問題ですか?」というメールを送る代わりに、顧客が開ける URL が 1 つあるということです。公開すると決めたサービスの現在の状態、対応中のインシデント、予定しているメンテナンス、そしてページ上部に固定したいお知らせが表示されます。

午前 2 時に何かが壊れたとき、サポートの問い合わせ対応で最初にリンクを貼るのがステータスページです。購読者への通知もここから出ていきます — だからこそ、障害の最中ではなく、必要になる前に用意しておく価値があります。

ステータスページはダッシュボード左ナビゲーションの **基本** グループにある **ステータスページ** の配下にあります。このページで扱う内容はすべてステータスページ単位です。プロジェクトは好きなだけステータスページを持てます — 顧客向けの公開ページ、社内向けの非公開ページ、特定の市場向けのリージョン別ページなど。

## ひと目で

- **作成に必要なのは 2 つのフィールドだけ。** 新しいステータスページが尋ねるのは **名前** と **説明** だけです。リソース、ブランディング、ドメインはすべて後から設定します。
- **訪問者が見るのはリソース。** ページ上の各行が **ステータスページ リソース** です — モニター（またはモニターグループ）に、独自の表示名、ツールチップ、稼働率のオプションを持たせたものです。グループは長いページをセクションに分け、入れ子にもできます。
- **初日からプレビュー URL がある。** どのステータスページにもプレビュー用のリンクが付くので、カスタムドメインを用意する前に実物を確認できます。
- **訪問者向けのルートは設定で開閉する。** インシデント、お知らせ、予定されたイベント、購読ページは、それぞれ **詳細設定** の該当トグルがオンのときだけ現れます。
- **非公開にする方法は 3 つ。** プライベートユーザー、マスターパスワード、SAML SSO / OIDC です — さらに IP ホワイトリストもあります。
- **購読者には自動で伝わる。** メール、SMS、Slack、Microsoft Teams、Webhook の購読者がページをフォローでき、チャネルごとに独自のトグルがあります。

## キー用語

| 用語                     | 意味                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| **ステータスページ**     | 独自のブランディング、ドメイン、リソース、購読者を持つ 1 つの公開（または非公開）ページ。`StatusPage` モデル。              |
| **リソース**             | 訪問者が見る 1 行 — 表示名と稼働率オプションを付けてページに出したモニターまたはモニターグループ。                          |
| **グループ**             | リソースをまとめる名前付きのセクション。グループは他のグループの中に入れ子にでき、各階層が配下すべての状態を集約します。   |
| **お知らせ**             | 1 つ以上のステータスページに投稿するメッセージ。開始日時と、任意で終了日時を持ちます。                                      |
| **購読者**               | メール、SMS、Slack、Microsoft Teams、Webhook のいずれかでページをフォローしている人（またはシステム）。                     |
| **カスタムドメイン**     | あなた自身のドメイン — `status.example.com` — を CNAME と SSL 証明書でページに向けたもの。                                  |
| **プライベートユーザー** | 非公開のステータスページにログインできるアカウント。OneUptime のプロジェクトユーザーとは別物です。                          |

## ステータスページを作成する

1. **ステータスページ → すべてのステータスページ** を開き、**ステータスページを作成** をクリックします。
2. **Create New Status Page** のモーダルで **名前**（必須、2 文字以上）を入力し、必要なら **説明** も入れます。
3. **ステータスページを作成** をクリックします。

作成フォームはこれで全部です。戻ってきた一覧には **名前**、**説明**、**ラベル**、**所有者** が並び、**ステータスページID**、**名前**、**説明** で絞り込めます。

新しいページを開くと **概要** 画面に着きます。ここにはカードが 2 つあります。ページ本体へのリンクを持つ **Status Page Preview URL** と、いま設定した名前・説明・ラベルを編集できる **ステータスページの詳細** です。

次にやることを、役に立つ順におおまかに並べると次のとおりです。

- ページに中身を持たせるためにリソースを追加する — [ステータス ページのリソースとグループ](/docs/status-pages/resources-and-groups) を参照。
- ページタイトル、ファビコン、ロゴ、カバーを設定し、カスタムドメインを紐付ける — [ステータス ページのブランディングとドメイン](/docs/status-pages/branding-and-domains) を参照。
- どのチャネルで購読できるようにするかを決める — [購読者とお知らせ](/docs/status-pages/subscribers) を参照。
- **詳細設定** でページに何を出すかを調整する。

## どこに何があるか

ステータスページを開くと、そのページ専用の左サイドメニューが 9 つのセクションに分かれています。このドキュメント群を読むときの地図として使ってください。

| セクション         | 中身                                                                                                                                          |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **基本**           | **概要**、**アナウンス**、**所有者**。                                                                                                        |
| **リソース**       | **リソース** 画面ひとつ — 左にグループ、右に選択したグループのモニター。                                                                      |
| **購読者**         | **メール購読者**、**SMS 購読者**、**Slack 購読者**、**MS Teams 購読者**、**Webhook購読者**、**購読者設定**。                                  |
| **通知ログ**       | **通知ログ** — 購読者に何が送られたか。                                                                                                       |
| **監査**           | **監査ログ**。                                                                                                                                |
| **ブランディング** | **基本ブランディング**、**HTML、CSS、JavaScript**、**カスタムドメイン**、**ヘッダー**、**フッター**、**概要ページ**、**言語**。               |
| **セキュリティ**   | **プライベートユーザー**、**SSO**、**OIDC**、**SCIM**、**認証設定**。                                                                         |
| **AI**             | **MCP**。                                                                                                                                     |
| **詳細**           | **Monitor Rules**、**埋め込みステータス**、**レポート**、**カスタムフィールド**、**詳細設定**、**ステータスページを削除**。                    |

探し始める前に知っておきたい、名前まわりのクセが 2 つあります。

- **リソース** という項目名になるのは、プロジェクトでモニターグループが有効なときだけです。そうでなければ **モニター** と表示されます。どちらでも同じ画面です。
- グループ専用のページはありません。グループとリソースは統合され、かつての `/groups` ルートはリソース画面へリダイレクトされます。

個々のページの外側では、**ステータスページ** セクション自体に **アナウンス** を含む **もっと** セクションと、**アナウンステンプレート**、**購読者テンプレート**、**カスタムフィールド**、**所有者ルール**、**ラベルルール** を収めた折りたたみ式の **設定** セクションがあります。これらはプロジェクト全体のもので、すべてのステータスページで共有されます。

## 訪問者が見るもの

公開ページはそれ自体が 1 つのアプリで、少数のルートを持ちます。

- `/` — **概要**。
- `/incidents` と `/incidents/:id` — インシデント一覧と個別のインシデント。
- `/announcements` と `/announcements/:id`。
- `/scheduled-events` と `/scheduled-events/:id`。
- `/subscribe/email`、`/subscribe/sms`、`/subscribe/slack`、`/subscribe/microsoft-teams`、`/subscribe/webhooks`。
- `/rss` — フィード。
- `/login`、`/sso`、`/master-password` — 非公開ページでのみ意味を持ちます。

上部のナビバーには常に **概要** が出ます。それ以外は有効にしたときだけ現れます。**インシデント**、**お知らせ**、**予定されたイベント** はそれぞれのトグルが必要で、**購読する** には **購読者ページを表示** と、少なくとも 1 つの購読チャネルの両方が必要です。非公開ページにはさらに **ログアウト** が加わります。

### 概要ページ

概要は、ほとんどの訪問者が目にする唯一のページです。上から順に、次のものが表示されます。

1. **公開中のお知らせ** — 開始日時を過ぎ、終了日時をまだ迎えていないお知らせ。
2. **全体ステータスのバナー** — すべてのリソースが影響を受けているのか一部だけなのかを 1 行でまとめたもの。
3. **全体の稼働率**。オンにした場合のみ。既定ではオフです。
4. **リソースグループ** — それぞれのリソース、現在の状態、稼働率の履歴バーとともに表示されます。
5. **進行中のインシデント**。
6. **予定されたメンテナンスイベント**。

何も載っていない作りたてのページには、ダッシュボードからリソースを追加するよう促す空の状態が表示されます — つまり **リソース** 画面へ向かう合図です。

そもそも何がインシデントをこのページに載せ、何が取り下げるのかについては、[インシデントの状態と重大度](/docs/incidents/states-and-severities) を参照してください。

## ページに表示する内容を選ぶ

表示の切り替えはほとんどが 1 か所にまとまっています。**ステータスページ → 対象のページ → 詳細 → 詳細設定** です。カードごとに **Edit Settings** ボタンがあります。

**インシデント設定**:

- **インシデントを表示**（`showIncidentsOnStatusPage`）— 既定でオン。オフにすると **インシデント** のナビ項目も消えます。
- **インシデント履歴の表示（日数）**（`showIncidentHistoryInDays`）— インシデント一覧がどこまでさかのぼるか。既定は 14 です。
- **インシデントラベルを表示**（`showIncidentLabelsOnStatusPage`）— 既定でオフ。

**エピソード設定** — インシデントエピソードに対する同じ 3 つのスイッチです。**エピソードを表示**（`showEpisodesOnStatusPage`、既定でオン）、**エピソード履歴の表示（日数）**（既定 14）、**エピソードラベルを表示**（既定でオフ）。エピソードはインシデントを別の見せ方にしたものではなく、独自のエンドポイントを持つ独立したモデルです。

**お知らせの設定**:

- **お知らせを表示**（`showAnnouncementsOnStatusPage`）— 既定でオン。
- **お知らせ履歴の表示（日数）**（`showAnnouncementHistoryInDays`）— 既定は 14。

**スケジュールされたイベントの設定**:

- **定期メンテナンスイベントを表示**（`showScheduledMaintenanceEventsOnStatusPage`）— 既定でオン。
- **予定イベント履歴の表示（日数）**（`showScheduledEventHistoryInDays`）— 既定は 14。
- **イベントラベルを表示**（`showScheduledEventLabelsOnStatusPage`）— 既定でオフ。

**稼働時間履歴設定**:

- **稼働率履歴の表示（日数）**（`showUptimeHistoryInDays`）— 各リソースの横に出る稼働率バーの長さ。既定は 90 で、1 から 90 のあいだで指定します。リソースやグループの **稼働率を表示** と **ステータス履歴チャートを表示** はすべてこの数値を参照します。

**購読者設定**:

- **購読者ページを表示**（`showSubscriberPageOnStatusPage`）— 既定でオン。加えてチャネルごとの有効化トグルが 5 つあります。同じチャネルのトグルは **購読者** セクションの専用画面 **購読者設定** にも出てきます。設定する場所としてはそちらを本命と考えてください。

**Powered By OneUptimeブランディング**:

- **「Powered By OneUptime」ブランディングを非表示** — 既定でオフなので、オンにするまで訪問者向けのフッターには "Powered by OneUptime" と表示されます。

**色の設定はここにありません。** 稼働率バーの色はここではなく、**デフォルトのバーの色**、バーの色のルール、**ダウンタイムモニターのステータス**、**全体的な稼働率を表示** はすべて **ステータスページ → 対象のページ → ブランディング → 概要ページ** にあります。テーマやブランドカラーの設定はどこにもありません。これらのコントロールを越える調整は **カスタム CSS** で行います。

## 公開する前にプレビューする

どのステータスページでも **概要** 画面に **Status Page Preview URL** カードがあり、ページ本体へ直接飛べます。リソースを追加している最中や、カスタムドメインをまだ用意していないあいだに使ってください。

裏側では、公開ルートのすべてに `/status-page/{statusPageId}/...` 配下のプレビュー版が存在します。プレビューの概要、プレビューのインシデント一覧、プレビューの購読ページ、といった具合です。つまりダッシュボードのプレビューから取った URL やスクリーンショットは、カスタムドメインを紐付けた後に顧客が見るものとは一致しません。Runbook やメールに貼るリンクは必ず確認してください。

## ページを見られる人を制限する

すべてのステータスページが一般公開向けとは限りません。制御はすべて **セキュリティ** セクションにあります。

### プライベートユーザー

**ステータスページ → 対象のページ → セキュリティ → 認証設定** で **一般に公開**（`isPublicStatusPage` カラム）をオフにします。すると訪問者は `/login` に着き、サインインが必要になります。

サインインできる人は **ステータスページ → 対象のページ → セキュリティ → プライベートユーザー** で追加します。**一括追加** のアクションがあり、メールアドレスの一覧を貼り付けると 1 件ずつ招待メールが送られます。プライベートユーザーには、OneUptime のプロジェクトアカウントとは別のパスワード忘れ・リセットのフローがあります。

### マスターパスワード

**認証設定** には **マスターパスワード** カードもあり、**マスターパスワードを要求** のトグルとパスワード本体を持ちます。訪問者は `/master-password` に着き、共有の秘密ひとつでページを開きます。

**マスターパスワードとプライベートユーザーは併用できません。** マスターパスワードがオンのあいだ、プライベートユーザーによる認証は無効になり、**プライベートユーザー** 画面にはその旨のバナーが出ます。

### SSO と OIDC

ID プロバイダーと結び付けた非公開ページには、**ステータスページ → 対象のページ → セキュリティ → SSO** で SAML（サインオン URL、発行者、x509 証明書、署名方式とダイジェスト方式）を、**ステータスページ → 対象のページ → セキュリティ → OIDC** で OpenID Connect（ディスカバリ URL、発行者、クライアント ID とシークレット、スコープ、クレーム名）を設定します。**SCIM** は IdP からプライベートユーザーを自動でプロビジョニングします。これらはプラン機能の対象なので、すべてのインストールで使えるとは限りません。

**SSO 設定** カードには **ログインにSSOを強制**（`requireSsoForLogin`、既定でオフ）があります。オンにする前に SSO の設定をテストしてください — うまく動かない場合、自分自身がステータスページから締め出されます。

### IP ホワイトリスト

**認証設定** には `ipWhitelist` カラムに紐づく **IP ホワイトリスト** カードもあります。既知のネットワークからのみ応答させたいページのためのものです。

## 埋め込みバッジと RSS フィード

ページ以外の場所にステータスを出す方法が 2 つあります。

**埋め込みステータスバッジ。** **ステータスページ → 対象のページ → 詳細 → 埋め込みステータス** の **埋め込みステータスバッジ** カードで **埋め込みステータスバッジを有効化**（`enableEmbeddedOverallStatus`、既定でオフ）をオンにします。`embeddedOverallStatusToken` と組み合わせて `/badge/:statusPageId` からバッジが配信されるので、現在の全体ステータスをドキュメント、アプリのフッター、マーケティングページに置けます。

**RSS フィード。** どのステータスページも `/rss` を配信します。タイトルは "{status page name} Updates" で、各項目には `Incident: `、`Announcement: `、`Scheduled Maintenance: ` の接頭辞が付きます。メールで購読するよりリーダーやチャットボットに流し込みたい人に便利です。

自分でデータを取りに行きたい場合、ステータスページは概要、インシデント、予定メンテナンスイベント、お知らせ、エピソードの公開読み取りエンドポイントに支えられています — [公開 API](/docs/status-pages/public-api) を参照してください。
