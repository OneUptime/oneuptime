# オンコールスケジュール

オンコールスケジュールは、その時々に誰がオンコールかを決めます。メンバーは交代で担当し、それぞれ一定期間オンコールを務めた後、次の人に引き継ぎます。スケジュールをオンコールポリシーのエスカレーションルールに追加すると、そのレベルが実行されたときに、スケジュールでオンコール中の人にポリシーが通知します。

## 交代で担当する人

**オンコールスケジュール** ページでスケジュールを作成すると、フォームは **名前** と **誰が交代で担当しますか？** を尋ねます。**ユーザーを追加** をクリックし、交代する順にメンバーを選びます。メンバーは 1 人ずつオンコールを担当し、最初の人はスケジュールの作成と同時にオンコールになります。選んだメンバーはスケジュールの最初のレイヤー **Layer 1** になり、24 時間オンコールを担当します。新しいスケジュールはその後 **レイヤー** ページで開き、そこでローテーションを変更したり、レイヤーを追加したりできます。

**誰が交代で担当しますか？** は省略できます。空のままにすると、スケジュールはレイヤーなしで作成され、**レイヤー** ページでレイヤーを追加するまで誰もオンコールになりません。この質問は、レイヤーを追加できる人にだけ表示されます。

それ以外は **その他の項目** の下にあり、開くまで折りたたまれています。

- **1 回の担当期間**: **1 日**、**1 週間**、**2 週間**、**1 か月** から選び、変更しなければ **1 週間** です。誰かを選ぶと表示されます。各メンバーはその期間オンコールを担当し、スケジュールを作成した時刻に次の人に引き継ぎます。
- **タイムゾーン**: 引き継ぎ時刻とオンコールの時間帯が適用されるタイムゾーンです。最初はあなたのタイムゾーンになっています。
- **説明** と **ラベル**。

誰かを選んでいて **その他の項目** の内容を何も変更していない間は、折りたたまれた見出しにこれから起こることが表示されます。各メンバーが 1 週間ずつオンコールを担当し、その後次の人に引き継ぎます。

## レイヤー

スケジュールのローテーションは、**レイヤー** ページのレイヤーで構成されます。レイヤーは上から順に評価され、オンコール中の人がいる最上位のレイヤーが通知します。メインのローテーションを上に、予備の担当を下に置いてください。

**レイヤーを追加** は、最初のレイヤーと同じように始まるレイヤーを追加します。今からオンコール、各メンバー 1 週間ずつ、24 時間です。レイヤーを展開すると、メンバーを追加したり、開始日時、引き継ぎの間隔、最初の引き継ぎ日時、オンコールの時間帯を変更したりできます。

各メンバーはどこでも同じ色で表示されるので、ひと目で追えます。各レイヤー、最終スケジュールとそのオーバーライド、**スケジュールタイムライン** のすべてで同じ色です。

## API または Terraform でスケジュールを作成する

オンコールスケジュールは `/api/on-call-duty-policy-schedule` リソースです。そのレイヤーとレイヤー内のメンバーは `/api/on-call-duty-schedule-layer` と `/api/on-call-duty-schedule-layer-user` リソースです。

- `miscDataProps` に `firstLayerUsers`（交代する順のユーザー ID のリスト）を指定してスケジュールを作成すると、ダッシュボードと同じように最初のレイヤーが作成されます。**Layer 1** で、今からオンコール、24 時間です。`firstLayerRotation` は 1 回の担当期間を `{"_type": "Recurring", "value": {"intervalType": "Week", "intervalCount": 1}}` のようなローテーションで指定します。指定しない場合は 1 週間です。各ユーザーはプロジェクトのメンバーである必要があり、呼び出し元にはレイヤーを作成する権限が必要です。そうでない場合、スケジュールは作成されません。
- これらを指定せずに作成したスケジュールには、これまでどおりレイヤーがありません。Terraform のスケジュールリソースはこれらを送信しません。
- `rotation` を指定せずに作成したレイヤーは、これまでどおり毎日引き継ぎます。
