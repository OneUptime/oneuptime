# エスカレーションルール

オンコールポリシーは、レベルごとに人を呼び出します。各エスカレーションルールが 1 つのレベルです。誰を呼び出すか、そして次のレベルを呼び出す前に誰かが確認するまでどれだけ待つかを決めます。ポリシーのルールは、その **エスカレーションルール** ページに順番に表示されます。

## 最初に通知する相手

**オンコールポリシー** ページでオンコールポリシーを作成すると、フォームは **名前** と **最初に誰に通知しますか？** を尋ねます。この質問は **通知する** と同じピッカーを使い、オンコールスケジュール、チーム、ユーザーを必要なだけ選べます。選んだ相手はポリシーの最初のエスカレーションルール **Level 1** になり、次のレベルを呼び出す前に確認を **30 分** 待ちます。作成したポリシーはその **エスカレーションルール** ページで開き、そこでレベルを追加できます。

**最初に誰に通知しますか？** は省略できます。空のままにすると、ポリシーはエスカレーションルールなしで作成されます。ルールを追加するまで誰も呼び出さず、概要にもそう表示されます。説明とラベルは **その他の項目** の下にあります。この質問は、エスカレーションルールを追加できる人にだけ表示されます。

## エスカレーションルールを追加する

オンコールポリシーを開き、サイドメニューで **エスカレーションルール** を選んで **エスカレーションルールを追加** をクリックします。ダイアログは 2 つのことだけを尋ねる短い 1 ページです。

- **通知する** — このレベルで誰を呼び出すか。1 つのピッカーでオンコールスケジュール、チーム、ユーザーを選べます。**対応者を追加** をクリックして検索し、必要なだけ選びます。少なくとも 1 つが必要です。
  - **オンコールスケジュール** は、レベルの実行時にオンコール中の人を呼び出します。特定の人ではありません。
  - **チーム** は、チームのすべてのメンバーを呼び出します。
  - **ユーザー** は直接呼び出されます。
- **エスカレーションまでの時間（分）** — 次のレベルを呼び出す前に確認をどれだけ待つか。初期値は **30 分** です。レベルに合わせて変更してください。

その他はすべて **その他の項目** の下にあり、開くまで折りたたまれています。

- **名前** — 任意です。名前のないルールはレベルにちなんで呼ばれます。ポリシーの最初のルールは **Level 1**、2 番目は **Level 2** というようになります。名前欄には、ルールに付く名前が表示されます。
- **説明** — 任意のメモです。たとえば、このレベルが誰をなぜ呼び出すかなど。

折りたたまれていても、**その他の項目** の見出しには 2 つの項目名が並び、ルールにあるもの（説明、または自分で付けた名前）が表示されます。

## レベルが人を呼び出す仕組み

インシデントまたはアラートがポリシーに届くと、**Level 1** がすぐに対応者を呼び出します。待ち時間内に誰も確認しなければ **Level 2** が呼び出され、リストの下へと続きます。最後のレベルの待ち時間が確認のないまま過ぎると、ルールの下にある **繰り返しポリシー** が繰り返すよう設定されていれば、許可された回数だけ **Level 1** からやり直し、そうでなければ停止します。

**エスカレーションルール** ページ上部の概要には、はしご全体が表示されます。各レベルがいつ呼び出され、誰を呼び出し、最後のレベルの後に何が起きるかがわかります。対応者の一部を呼び出せないレベルは、そのカードで知らせます。ラベルをクリックすると、誰がなぜ呼び出せないかを確認できます。

各レベルが呼び出す人への連絡方法は、その人自身のオンコールルールで決まります。**ユーザー設定** > **オンコールルール** には、インシデント、インシデントエピソード、アラート、アラートエピソードのタブがあり、重大度ごとのカードに、どの通知方法をどれだけ待ってから使うかが表示されます。プロジェクト管理者は **ユーザー** > メンバー > **オンコールルール** でメンバーのルールを確認・変更できます。

## ルールの編集、並べ替え、削除

- **ルールを編集** は、同じ 1 ページのダイアログを、現在のルールの内容で開きます。対応者、待ち時間、そして **その他の項目** の下の名前と説明が入っています。対応者を追加または削除して保存します。名前を空にすると、ルールは再びレベルの名前になります。
- ルールの **⋯** メニューの **上へ移動** と **下へ移動** でレベルを変更します。レベルにちなんで名付けられたルールは、位置に合った名前を保ちます。**Level 3** が **Level 2** を越えて上に移動すると、2 つの名前が入れ替わります。**Managers** のように自分で選んだ名前は、ルールがどこへ移動しても変わりません。
- **ルールを削除** は、まず確認を求め、そのレベルが誰を呼び出すかを示します。レベルを削除すると下のレベルが繰り上がり、レベルにちなんで名付けられたルールはそれに合わせて名前が変わります。

## API または Terraform でルールを作成する

エスカレーションルールは `/api/on-call-duty-policy-escalation-rule` リソースです。ルールが呼び出すユーザー、チーム、スケジュールは `/api/on-call-duty-policy-escalation-rule-user`、`-team`、`-schedule` リソースです。

- `name` を指定せずに作成したルールは、ダッシュボードと同じくレベルにちなんで名付けられます。ポリシーの 3 番目のレベルになるルールは **Level 3** です。Terraform のエスカレーションルールリソースでは、引き続き名前が必要です。
- `escalateAfterInMinutes` には、ダッシュボード以外では既定値がありません。これを指定せずに作成したルールは待ちません。このレベルが実行されるとすぐに次のレベルが呼び出されます。明示的に設定してください。ダッシュボードの推奨値は 30 です。
- レベルにちなんで名付けられたルールの名前が変わるのは、ダッシュボードでルールを移動または削除したときです。API や Terraform で `order` を変更しても、変わるのは順序だけです。
- `miscDataProps` に `onCallSchedules`、`teams`、`users`（ID のリスト）を含めて `/api/on-call-duty-policy` でオンコールポリシーを作成すると、ダッシュボードと同じく最初のエスカレーションルールが作られます。それらを呼び出す **Level 1** で、`escalateAfterInMinutes` は 30 です。すべての ID がプロジェクトに属し、呼び出し元がエスカレーションルールを作成できる必要があります。そうでない場合、ポリシーは作成されません。これらを指定せずに作成したポリシーには、これまでどおりルールがありません。Terraform のポリシーリソースはこれらを送信しません。
