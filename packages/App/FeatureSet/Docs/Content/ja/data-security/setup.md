# データセキュリティを設定する

データセキュリティが読み取るのは、許可したものだけです。各クラウド接続は 3 つのレベルのいずれかで読み取られ、自分で運用しているデータベースは指定した接続文字列で読み取られ、テレメトリには何も必要ありません。このページでは、それぞれの選択で OneUptime が何を読み取れるようになるか、付与される正確な権限、そして読み取ったもののうち OneUptime が何を保持するかを説明します。

:::cards
- [レベルを選ぶ](#接続ごとにレベルを選ぶ): オフ、設定のみ、設定とコンテンツのサンプルのいずれか。
- [各レベルが付与するもの](#各レベルが付与するもの): AWS のアクション、Azure と Google Cloud のロール。
- [自分で運用するデータベースをスキャンする](#自分で運用するデータベースをスキャンする): 読み取り専用の接続文字列、またはネットワーク内のプローブ。
- [OneUptime が保持するもの](#oneuptime-が保持するもの): 件数、場所、マスクされたサンプル。値そのものは決して保持しません。
- [データセキュリティに露出を解消させる](#データセキュリティに露出を解消させる): 接続に与えられる唯一の書き込み権限。オンにするまではオフです。
:::

## 接続ごとにレベルを選ぶ

| レベル | フォームでの表示 | OneUptime が読み取るもの |
| --- | --- | --- |
| オフ | **オフ** | データストアの設定もコンテンツも読み取りません。それでもデータセキュリティは、クラウドのインベントリが知っているデータストアを、インベントリがそれについて示す内容とともに一覧します: RDS データベースが暗号化されているか、公開されているか、削除から保護されているか、バックアップされているか、そして DynamoDB テーブルを特定の時点に復元できるかどうかです。 |
| 設定 | **設定のみ** | すべてのデータストアがどう設定されているか: 誰がアクセスできるか、どのように暗号化、バックアップ、バージョニング、ログ記録、レプリケーション、タグ付けされているか。データは決して読み取らず、シークレットも決して読み取りません。 |
| コンテンツ | **設定とコンテンツのサンプル** | それに加えて、S3 バケット、Azure ストレージアカウント、Cloud Storage バケット、BigQuery データセットが保持するもののサンプル。 |

すべての接続は **オフ** から始まります。各レベルが各クラウドで実行するコマンドは、 [クラウドアカウントを接続する](/docs/telemetry/cloud-accounts#データセキュリティ) に一字一句そのまま載っています。接続のレベルを変更するには、次のようにします。

:::steps
### 接続を開く

**クラウド → 接続** を開きます。接続の **編集** を選ぶか、新しいアカウントを接続します。

### レベルを選ぶ

**その他の項目** で、 **データセキュリティ** を目的のレベルに設定します。

### コマンドをもう一度実行する

フォームに表示されるコマンドはレベルに応じて変わります。接続したときと同じように、クラウドのシェルで実行してください: 新しいレベルに必要なものだけを付与し、それ以上は付与しません。その後 **変更を保存** を選びます。新しい接続の場合は **接続** を選びます。
:::

新しいレベルでの読み取りは 1 時間以内に始まり、データストアの **今すぐチェック** か **今すぐスキャン** を使うとすぐに始まります。ロールがまだ何を許可していても、OneUptime が読み取るのは接続のレベルが示すものだけです: レベルを下げると、読み取りはすぐに止まります。アクセス自体も取り除くには、新しいコマンドを実行します: AWS では、ポリシーが下のレベルのものに置き換わります。 **オフ** は何も追加しないので、以前のコマンドが付与したものはそのまま残ります。それは自分で削除してください: AWS では `aws iam delete-role-policy --role-name <your role> --policy-name OneUptimeDataSecurity` で、Azure と Google Cloud ではコンテンツのレベルが追加したロールを削除します。

## 各レベルが付与するもの

### Amazon Web Services

設定のレベルでは、読み取り専用のポリシーの横に、2 つ目のインラインポリシー `OneUptimeDataSecurity` がロールに追加されます。このポリシーには、データセキュリティのリーダーが呼び出す読み取りアクションがそのまま含まれます。どれも設定を読み取るだけで、データを読み取ったり何かを書き込んだりするものはありません。

| OneUptime がそれを使う目的 | アクション |
| --- | --- |
| バケットを一覧し、それぞれに誰がアクセスできるか、どのように暗号化、バージョニング、ログ記録、コピー、タグ付けされているかを読み取る | `s3:ListAllMyBuckets`、`s3:GetBucketLocation`、`s3:GetBucketPolicyStatus`、`s3:GetBucketPublicAccessBlock`、`s3:GetAccountPublicAccessBlock`、`s3:GetBucketAcl`、`s3:GetBucketPolicy`、`s3:GetEncryptionConfiguration`、`s3:GetBucketVersioning`、`s3:GetBucketLogging`、`s3:GetBucketOwnershipControls`、`s3:GetReplicationConfiguration`、`s3:GetBucketTagging` |
| データベースへの到達経路、暗号化、バックアップと、手動スナップショットの共有先を読み取る | `rds:DescribeDBInstances`、`rds:DescribeDBClusters`、`rds:DescribeDBSnapshots`、`rds:DescribeDBSnapshotAttributes`、`rds:DescribeDBClusterSnapshots`、`rds:DescribeDBClusterSnapshotAttributes`、`dynamodb:ListTables`、`dynamodb:DescribeTable`、`dynamodb:DescribeContinuousBackups`、`redshift:DescribeClusters`、`redshift:DescribeLoggingStatus` |
| 検索ドメイン、キャッシュ、ファイルシステムの設定を読み取る | `es:ListDomainNames`、`es:DescribeDomains`、`elasticache:DescribeReplicationGroups`、`elasticfilesystem:DescribeFileSystems` |
| AWS 独自のキー (alias/aws/...) と自分で管理するキーを区別する | `kms:ListAliases` |

コンテンツのレベルでは、同じポリシーに 3 つのアクションが追加され、それぞれ専用のリソースに適用されます。

| アクション | 許可される対象 | 用途 |
| --- | --- | --- |
| `s3:ListBucket` | `arn:aws:s3:::*` | バケットのオブジェクト名を一覧する |
| `s3:GetObject` | `arn:aws:s3:::*/*` | サンプリングするオブジェクトの先頭のバイトを読み取る |
| `kms:Decrypt` | `*`。ただし `kms:ViaService` が `s3.*.amazonaws.com` の場合のみ | KMS キーで暗号化されたオブジェクトを S3 経由でのみ読み取る: キーが保護するほかのものを直接復号することは決してない |

ロールの代わりに **アクセス キー** を使う場合、ポリシーはグループ `OneUptimeDataSecurity` に付けられ、キーのユーザーがそのグループに追加されます: IAM ではユーザー自身のインラインポリシーは合計 2,048 文字までで、その大半を読み取り専用のポリシーが占めるからです。AWS Organization 全体を読み取る接続では、すべてのアカウントのロールに同じポリシーが追加されます。

### Microsoft Azure

設定のレベルでは何も追加されません: 接続の **監視閲覧者** ロールが、Azure Resource Manager を通じてすでにすべてのリソースの設定を読み取っています。コンテンツのレベルでは、組み込みの **ストレージ BLOB データ閲覧者** ロールが、接続と同じスコープに追加されます: サブスクリプション、またはテナントのルート管理グループです。

### Google Cloud

設定のレベルでは何も追加されません: 接続の **Cloud Asset 閲覧者** ロールが、すでにすべてのリソースの設定と IAM ポリシーを読み取っています。コンテンツのレベルでは、2 つのロール `roles/storage.objectViewer` と `roles/bigquery.dataViewer` がプロジェクトまたは組織に追加され、BigQuery API `bigquery.googleapis.com` が有効になります。

## データセキュリティに露出を解消させる

別の設定を選ばない限り、接続が行うのは読み取りだけです。 **その他の項目** で **データセキュリティ** の横にある **データセキュリティ対応** を使うと、データセキュリティがデータストアのパブリックアクセスをブロックし、そのスナップショットの共有を停止できるようにもなります: データストアの問題から **ここで修正** で行う方法 ( [データセキュリティのチェックと問題](/docs/data-security/checks-and-issues#ここで修正) を参照) と、セキュリティオペレーションのプレイブックから行う方法です。 **パブリックアクセスと共有をブロック** を選ぶまでは **オフ** で、選ぶとフォームに表示されるコマンドが、範囲の狭い書き込み権限をひとつだけ、単独で付与します。

| クラウド | コマンドが追加するもの | 許可される操作 |
| --- | --- | --- |
| AWS | 3 つ目のインラインポリシー `OneUptimeDataSecurityResponse` | `s3:GetBucketPublicAccessBlock`、`s3:PutBucketPublicAccessBlock`、`rds:DescribeDBSnapshotAttributes`、`rds:DescribeDBClusterSnapshotAttributes`、`rds:ModifyDBSnapshotAttribute`、`rds:ModifyDBClusterSnapshotAttribute`: バケットの Block Public Access と、手動スナップショットの共有先 |
| Azure | 接続のスコープに付与されるカスタムロール `OneUptime Data Security Response` | `Microsoft.Storage/storageAccounts/read` と `Microsoft.Storage/storageAccounts/write`: 匿名 BLOB アクセスなどのストレージアカウントの設定。キーには決して触れない |
| Google Cloud | カスタムロール `oneuptimeDataSecurityResponse` | `storage.buckets.get` と `storage.buckets.update`: パブリックアクセスの防止などのバケットの設定 |

付与されるものはどれも、データを読み取ったり、何かを削除したり、誰がサインインできるかを変更したりしません。 **オフ** に戻すと、データセキュリティはすぐにそれを使わなくなります。AWS でアクセス自体も取り除くには、 `aws iam delete-role-policy --role-name <your role> --policy-name OneUptimeDataSecurityResponse` でポリシーを削除します。

## コンテンツのサンプルが任意である理由

設定のレベルでは、露出しているものが見つかります: 公開されたバケット、インターネットに開かれたデータベース、暗号化、バックアップ、アクセスログの欠如などです。データストアが何を保持しているかはわからないため、何も見つからなかったデータストアは最も低い機密度である公開として扱われ、その問題の重大度は公開データの場合と同じになります。ウェブサイトの画像が入った公開バケットは緊急事態ではありませんが、カード番号が入った公開バケットは緊急事態です。

コンテンツのサンプルがあれば、この 2 つを区別できます。サンプルは各データストアの機密度を保持しているものから決めるので、同じ不備でもカード番号なら重大、画像なら低になります。また、コンテンツにしか現れないものも見つかります: シークレット、カードのセキュリティコード、入力されたままの形で保存されたパスワード、テスト用データストアにある本番データのコピーです。

そのため、多くのチームは次の順に進めます: まずすべての場所で設定のレベルを使い、次にデータストアが何を保持しているかを知る必要がある場所でコンテンツのサンプルを使います。コンテンツのスキャンは、データストアの **設定** にある **コンテンツをスキャン** で特定のデータストアだけ、またはプロジェクト全体でオフにすることもできます。

## コンテンツのスキャンが読み取るもの

スキャンはプロジェクトの上限の範囲内でデータストアを少しだけ読み取り、残りがあっても 8 分で停止します。次のスキャンはそこから続けます: 前回読み取ってから変更されていないオブジェクトはスキップします。ただし、その読み取りが 7 日以上前の場合は除きます。

- **バケットとコンテナー** は、数ではなく種類ごとにサンプリングされます。まずオブジェクト名が一覧されます。その数はスキャンが読み取れる数の最大 10 倍で、200,000 を超えることはありません。各名前は、日付、UUID、長い 16 進数の並び、数字を `*` にしたパターンになるので、 `exports/2026-10-27/users-0001.csv` は `exports/*/users-*.csv` になります。各パターンの最新のオブジェクトが読み取られます。どのパターンでも 2 つ目を読む前に各パターンから 1 つずつ読み、1 つのパターンからは最大 5 つです。各オブジェクトは先頭から読み取られます: 1 つのオブジェクトにつき最大 **オブジェクトあたりのバイト数** 、合計で **スキャンあたりのバイト数** までです。Azure ストレージアカウントでは、1 回のスキャンでサンプリングするコンテナーは最大 10 個です。
- **ファイルはその形式に合わせて読み取られます。** CSV と TSV は列ごと、JSON と JSON Lines はパスごと、`.env`、`.ini`、`.properties`、TOML、YAML はキーごと、XML と HTML はテキストとして、Word、Excel、PowerPoint のファイルはテキストとセルごと、それ以外はすべて自由テキストとして読み取られます。gzip ファイルは先に展開されます。画像、Parquet、Avro、PDF などのバイナリ形式は読み取られず、スキャンにそのことが示されます。
- **データセットとデータベース** はテーブルごとに読み取られます: 最大 **スキャンあたりのテーブル数** のテーブルを、それぞれ **テーブルあたりの行数** の行まで読み取ります。

各スキャンは、読み取ったものの記録を名前で残します: オブジェクト、テーブル、サービスの名前だけで、その内容は決して残しません。読み取れなかったもの (クラウドが拒否したリクエスト、期限、バイト数の上限) はスキャンの警告になり、スキャンには **一部成功** と表示されます。

## 自分で運用するデータベースをスキャンする

データセキュリティは、PostgreSQL と MySQL のデータベースを 2 つの方法のどちらかでサンプリングします。データベース製品が監視しているデータベースや、サービスマップ上でサービスが通信しているデータベースは、すでにデータストアになっています。どのスキャンでも見つからないデータベースは、自分でデータストアとして追加してください。

- **OneUptime のワーカーから。** データストアの **設定** で、 **接続文字列** に `postgresql://reader:password@db.internal:5432/app` のような読み取りしかできない接続文字列を設定します。保存時に暗号化され、API から返されることはありません。読み取りだけができ、それ以外は何もできないデータベースユーザーを使ってください。
- **ネットワーク内のプローブから。** **スキャン元プローブ** でプローブを選び、 **プローブ接続変数** に、そのプローブ上で接続文字列を保持している環境変数の名前を入力します。プローブはネットワークの内側からデータベースを読み取り、見つけたものだけを送り返します: 接続文字列が OneUptime に届くことはありません。プローブの実行方法は [カスタムプローブ](/docs/probe/custom-probe) を参照してください。

## OneUptime が保持するもの

各場所 (列、フィールド、オブジェクトのパターン、テレメトリの属性) で見つかったデータタイプごとに、検出結果は次のものを保持します。

- サンプリングした値のうちいくつにそれが含まれていたか、全体でいくつだったか、そしてそのうちいくつがよく知られたテスト値だったか。
- 異なる値がいくつ一致したか。スキャナーのメモリ内にだけ置かれ、スキャンとともに破棄されるハッシュから推定します。
- 信頼度と、その場所の名前がデータタイプを示していたかどうか。
- 最大 3 つのマスクされたサンプル。何かがスキャナーの外に出る前に、スキャナーの中でマスクされます。

生の値は決して保持しません。値の種類ごとに、人が見分けられても使えないようにマスクされます。

| 値 | マスクされたサンプル |
| --- | --- |
| メールアドレス | `j***@e******.com`: 名前とドメインの最初の文字、そしてトップレベルのラベル |
| カード番号 | `**** **** **** 4242`: PCI DSS がカードの表示に認めている末尾 4 桁 |
| シークレット | 長い場合は最初の 4 文字と最後の 4 文字、短い場合は最初の 2 文字、秘密鍵の場合はヘッダーのみ |
| URL または接続文字列 | パスワード以外のすべて |
| IP アドレス | 最初の部分であるネットワークだけで、残りは隠される |
| 名前から見つかった値 | 最初の 1 文字の後に `****` |
| 文書の区分表示 | 「Confidential」のように、書かれたままの区分表示: 文書が何であるかを示すもの |
| その他 | 末尾の 2〜4 文字。区切り文字は残す (例: `***-**-6789`) |

プロジェクトの設定で **マスクされたサンプルを保持** をオフにすると、件数だけを保持します: 各データストアの次のスキャンから、書き込まれる検出結果にサンプルは保持されません。

データストア間のデータのコピーは、値ではなくフィンガープリントで見つかります: データタイプごとに 16 ビットの数値 128 個で、プロジェクト独自のキーでハッシュ化されます ( [フィンガープリントが非公開に保たれる仕組み](/docs/data-security/flows-access-residency#フィンガープリントを非公開に保つしくみ) を参照)。

サンプルではまだ残っているものを見逃すことがあるため、検出結果は最後にスキャンで確認されてから 30 日間、そのデータストアに数えられます。90 日間確認されなかった検出結果は削除されます。1 つのデータストアが保持する検出結果は最大 2,000 件です。

## 設定

データセキュリティの設定はプロジェクトごとに 1 セットで、データセキュリティのメニューの **設定** セクションにあります。最初は次のデフォルト値になっています。

| 設定 | デフォルト | 内容 |
| --- | --- | --- |
| **設定をチェック** | オン | すべてのデータストアでチェックを実行します。オフにすると、問題が開くことも、変わることも、クローズされることもありません。 |
| **コンテンツをスキャン** | オン | コンテンツの権限が付与されている場合に、データストアのコンテンツをサンプリングします。 |
| **テレメトリをスキャン** | オン | プロジェクトのログ、トレース、例外、リプレイ、AI の会話をサンプリングします。 |
| **マスクされたサンプルを保持** | オン | 各検出結果に最大 3 つのマスクされたサンプルを保持します。オフにすると件数だけを保持します。 |
| **セキュリティケースを開く** | オン | 重大度が「重大」の問題が開いたときに、データストアごとにまとめたセキュリティケースを開きます。 |
| **アラートを発生** | オフ | 重大度が「重大」の問題が開いたときに、オンコール担当者を呼び出すアラートを発生させます。 |
| **アラートの重大度** | 空 | それらのアラートの重大度。空の場合は、プロジェクトで最も重い重大度になります。 |
| **インシデントを宣言** | オフ | 重大度が「重大」の問題が開いたときに、インシデント対応プロセスで扱うインシデントを宣言します。 |
| **インシデントの重大度** | 空 | それらのインシデントの重大度。空の場合は、プロジェクトで最も重い重大度になります。 |
| **所有者に通知** | オン | データストアで問題が開いたときに、その所有者にメールを送ります。 |
| **スキャンあたりのオブジェクト数** | 2,000 | バケットの 1 回のスキャンで読み取るオブジェクトの最大数。10〜50,000。 |
| **オブジェクトあたりのバイト数** | 65,536 (64 KB) | 1 つのオブジェクトから読み取る最大バイト数。1,024〜4,194,304。 |
| **スキャンあたりのバイト数** | 52,428,800 (50 MB) | 1 回のコンテンツのスキャンで読み取る合計の最大バイト数。65,536〜1,073,741,824。 |
| **テーブルあたりの行数** | 1,000 | 1 つのテーブルから読み取る最大行数。10〜100,000。 |
| **スキャンあたりのテーブル数** | 200 | 1 回のスキャンで読み取る最大テーブル数。1〜5,000。 |
| **テレメトリのサンプルサイズ** | 500 | テレメトリのスキャンが、各サービスとシグナルについて読み取る最近のレコードの数。10〜10,000。 |
| **スキャン間隔 (時間)** | 24 | データストアのコンテンツを再度サンプリングする頻度。1〜720。 |
| **機密扱いしない** | 空 | サポート用のアドレスなど、決して検出結果にならない値。 |
| **オフにしたデータタイプ** | 空 | プロジェクトのスキャンが探さない組み込みデータタイプ: **組み込みデータタイプ** の下にあるスイッチ。 |

## トラブルシューティング

:::details データストアにコンテンツがスキャンされていないと表示される
スキャンに理由が表示されます: 「コンテンツのスキャンには、接続のコンテンツの権限、またはデータベースの接続文字列が必要です。」データストアの接続を **設定とコンテンツのサンプル** にしてコマンドをもう一度実行するか、データベースに接続文字列を指定してください。また、データストアとプロジェクトの設定の両方で **コンテンツをスキャン** がオンになっていることも確認してください。
:::

:::details チェックで判断できないと表示される
リーダーが読み取れなかった事実 (ロールにない権限、有効になっていない API) は不明として扱われ、推測されることはありません。そのチェックは判断できないと報告し、そのチェックが開いた問題は開いたままになります: OneUptime が確認できなかったからといって、不備が修正されたと結論づけることは誰にもできないからです。設定の読み取りの警告に、読み取れなかったものが示されます。不足しているものを付与するには、接続のコマンドをもう一度実行してください。
:::

:::details S3 バケットや BigQuery データセットが表示されない
これらはクラウドのインベントリではなく、設定の読み取りから得られます。接続を **設定のみ** 以上にして、コマンドをもう一度実行してください。
:::

:::details スキャンに一部成功と表示される
すべてを読み取る前に上限に達しました: 8 分、 **スキャンあたりのバイト数** 、 **スキャンあたりのオブジェクト数** 、またはクラウドが拒否したリクエストです。どれだったかは警告に示されます。次のスキャンは、変更されていないものをスキップしながら続きを読み取ります。または上限を引き上げてください。
:::
