# エピソード

エピソードは、関連するインシデント、または関連するアラートをひとつにまとめ、チームがひとつのものとして対応できるようにします。確認する場所がひとつ、オーナーがひとまとまり、確認と解決を行う状態もひとつです。グループ化ルールはエピソードを開き、インシデントやアラートが届くたびにそこへ追加します（[インシデントのグループ化ルール](/docs/incidents/settings#インシデントのグループ化ルール)を参照）。インシデントを自分でエピソードに追加することもでき、一度に複数を追加できます。エピソードから追加する方法と、インシデントの一覧から追加する方法があります。

このページの内容はすべて、アラートのエピソードでも同じように動きます。「インシデント」を「アラート」に読み替えてください。インシデントのエピソードは **インシデント → エピソード**、アラートのエピソードは **アラート → エピソード** にあります。

## エピソードからインシデントを追加する

エピソードを開き、サイドメニューの **所属インシデント**（`/dashboard/{projectId}/incidents/episodes/{episodeId}/incidents`）を選んで、**インシデントを追加** をクリックします。ダイアログには、あなたが閲覧できて、まだエピソードに入っていないインシデントのうち新しい順に 50 件が、番号、タイトル、状態、重大度とともに表示されます。古いものはタイトルか番号で検索してください。`INC-42`、`42`、`#42` のいずれでもインシデント 42 が見つかります。

- 必要な数だけチェックを入れます。一度に 100 件までです。ボタンに件数が表示されます: **インシデントを 3 件追加**。
- すでに別のエピソードに入っているインシデントには、タイトルの下にそのエピソードの番号とともにその旨が表示されます。ここに追加しても、元のエピソードからは外れません。インシデントは複数のエピソードに入ることができます。
- 追加できないものがあると、ダイアログは開いたままで、それらを理由とともに表示します。残りは追加されます。

## インシデントの一覧から追加する

**インシデント** の一覧、またはモニターのインシデント一覧など他のインシデント一覧でインシデントを選択し、**一括操作** を開きます。

| 操作 | 内容 |
| --- | --- |
| **既存のエピソードに追加** | エピソードを 1 つ選びます。進行中のエピソードが新しい順に先に並び、その後に最近解決済みのものが続きます。それ以外のエピソードはタイトルか番号で検索できます。追加する前に、選択したインシデントのうち何件がすでにそのエピソードに入っているか（そのまま残ります）、何件が別のエピソードに入っているか（そちらにも残ります）がダイアログに表示されます。 |
| **新しいエピソードに追加** | 選択したインシデントを含むエピソードを作成します。尋ねるのはタイトルと重大度だけで、どちらも選択した中で最も重大なインシデントから入力されます。プライベートなインシデントのタイトルがコピーされることはありません。オーナー、オンコールポリシー、メモはエピソードのページで追加します。 |

どちらも、選択したインシデントを 100 件まで受け付けます。結果には、追加された件数、すでにエピソードに入っていた件数、追加されなかったものとその理由が、エピソードを開くリンクとともに表示されます。

## 追加すると起きること

- **エピソードのフィードに 1 件のエントリ** が追加され、追加されたインシデントすべてを示します。最初の 20 件は番号とタイトルで、残りはその件数で示します。エピソードの Slack または Microsoft Teams のチャンネルへの投稿も、インシデントごとではなく 1 回だけです。プライベートなインシデントは番号だけで示されます。
- **各インシデント自身のフィード** には、どのエピソードに追加されたかが記録されます。
- **エピソードの重大度** は、既存のエピソードに追加されたインシデントのうち最も重大なものに合わせて引き上げられ、下がることはありません。新しいエピソードは、選んだ重大度で始まります。
- **解決済みのエピソードは解決済みのままです。** 追加しても再オープンされず、追加によってインシデントの状態が変わることもありません。
- **エピソードのオーナーに通知されます。** 1 件だけ追加されたときと同じく、インシデントが追加されたことが伝わります。エピソードをインシデントとともに作成した場合は、エピソード作成の通知がそれらも含みます。

## インシデントを外す

**所属インシデント** で、行の **削除**、または **一括操作** から選択した行に対して実行すると、そのインシデントはこのエピソードからだけ外れます。インシデント自体は削除されず、入っている他のエピソードにはそのまま残ります。

## 追加できるユーザー

追加するには、インシデントをエピソードに追加する権限が必要です。Project Owner、Project Admin、Project Member、Incident Admin、Incident Member の各ロールと、Create Incident Episode Member を持つカスタムロールにこの権限があります。追加できるのは、あなたが閲覧できるインシデントだけです。プライベートなインシデントを追加できるのは、そのオーナーと、プロジェクトのオーナーおよび管理者だけです。新しいエピソードに追加するには、エピソードを作成する権限も必要です。使えない操作はロックされ、そのツールチップに不足している権限が表示されます。

## API で追加する

1 回のリクエストで複数のインシデントをエピソードに追加します。

```bash
curl -X POST 'https://oneuptime.com/api/incident-episode-member/add-incidents' \
  -H "ApiKey: $ONEUPTIME_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "incidentEpisodeId": "<episode id>",
    "incidentIds": ["<incident id>", "<incident id>"]
  }'
```

レスポンスは、送ったインシデントそれぞれを 1 回ずつ、追加された、すでにエピソードに入っていた、追加されなかった（とその理由）のいずれかとして返します。ID が 100 件を超えるリクエストは拒否されます。

```json
{
  "added": ["<incident id>"],
  "alreadyInEpisode": ["<incident id>"],
  "notAdded": [
    {
      "id": "<incident id>",
      "reason": "This incident does not exist in this project, or you do not have access to it."
    }
  ]
}
```

アラートの場合は、`alertEpisodeId` と `alertIds` を `/api/alert-episode-member/add-alerts` に送ります。インシデントを含むエピソードを作成するには、エピソードを作成するリクエスト `POST /api/incident-episode` で、それらの ID を `{ "data": { "title": "Checkout outage" }, "miscDataProps": { "incidentIdsToAdd": ["<incident id>"] } }` の形で送ります。アラートのエピソードの場合は、`POST /api/alert-episode` に `alertIdsToAdd` を付けて送ります。いずれかを追加できない場合、エピソードは作成されません。
