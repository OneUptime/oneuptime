# 外部 MCP サーバー

OneUptime AI は、AI に質問で、Slack と Microsoft Teams での回答で、またインシデントやアラートを調査・修正する間、OneUptime の外部にある MCP サーバー(AWS、Azure、GitHub など、クラウドやコードホスト、自分たちのチームが動かしているもの)のツールを使えます。**プロジェクト設定 → AI → 外部 MCP サーバー** でサーバーを一度追加すれば、次の質問と次のインシデントから OneUptime AI がそれを使います。

:::cards
- [サーバーを追加する](#サーバーを追加する): アドレスと、OneUptime のサインイン方法です。
- [OneUptime AI がサーバーで行うこと](#oneuptime-ai-がサーバーで行うこと): 調査では読み取るツールを、修正ではそれ以外のツールも使います。
- [ツールを読み取り専用としてマークする](#ツールを読み取り専用としてマークする): kAgent のサーバーのように、サーバーが何も示さない場合です。
- [AI に質問で](#ai-に質問で): サーバーのツールの一覧表示や使用を頼めます。変更はあなたの承認を待ちます。
- [Slack と Microsoft Teams で](#slack-と-microsoft-teams-で): 質問した人のために、読み取るツールを使います。
- [ルールが使えるサーバーを選ぶ](#ルールが使えるサーバーを選ぶ): ルールが一部を選ばない限り、すべてです。
- [安全性](#安全性): サーバーが OneUptime AI にさせられることと、させられないことです。
:::

このページは、OneUptime AI が接続するサーバーについて説明します。逆に Claude や Cursor などの AI アシスタントを OneUptime に接続するには、[MCP サーバー](/docs/ai/mcp-server) を参照してください。

## 始める前に

- プロジェクトで **OneUptime AI がオン** になっていて、使える LLM プロバイダーがあること: [LLM プロバイダー](/docs/ai/llm-provider) を参照してください。
- **サーバーの MCP アドレス。** Streamable HTTP と、以前からある SSE 付きの HTTP のどちらにも対応しています。サーバーがどちらを話すかは、OneUptime が接続時に判断します。
- **OneUptime のサインイン方法:** API トークン、サーバー独自のヘッダー、または ID プロバイダーの OAuth クライアント資格情報。
- **Project Owner または Project Admin** がサーバーを追加・変更・テスト・削除します。プロジェクトメンバーと閲覧者は閲覧できます。OneUptime Cloud では、サーバーの追加に Growth プラン以上が必要です。

## サーバーを追加する

:::steps
### 外部 MCP サーバーを開く
**プロジェクト設定 → AI → 外部 MCP サーバー** に移動し、**外部 MCP サーバーを作成** をクリックします。

### 場所を指定する
OneUptime AI や、AI の行動を読む人がサーバーを識別する **名前** と、`https://mcp.example.com/mcp` のような **URL** を指定します。**その他の項目** の **説明** には、サーバーの用途を書きます。OneUptime AI はこれを読んで適切なサーバーを選びます。

### OneUptime のサインイン方法を選ぶ
**認証** でカードを一つ選び、求められる内容を入力します([認証](#認証) を参照)。

### OneUptime が見つけたものを確認する
保存すると OneUptime がすぐに接続し、**接続をテスト** ダイアログに見つけたものが表示されます: サーバー、通信方法、そして各ツール(**読み取り専用** または **変更を加える可能性あり** の印付き)です。接続できなかった場合は、その理由と確認すべき点がダイアログに表示されます。
:::

サーバーの一覧には、各サーバーの状態(**接続済み**、**接続できません**(ポインターを合わせると理由を表示)、**未確認**、**オフ**)と、提供するツールの数が表示されます。サーバーのページには、詳細、OneUptime AI に使用を許可するスイッチ、**ツール** があり、**接続をテスト** で再接続してツールを読み直せます。テストでは、サーバーのツールは一つも呼び出しません。

## 認証

| 認証 | OneUptime が送るもの | 入力するもの |
| --- | --- | --- |
| **サインインなし** | なし | なし。サインインが不要なサーバー、またはネットワーク内からのみ到達できるサーバー向けです。 |
| **Bearer トークン** | `Authorization: Bearer <token>` | **トークン** |
| **カスタムヘッダー** | 入力したヘッダーを、すべてのリクエストで | ヘッダーごとに名前と値(`X-API-Key` など)。最大 10 個。 |
| **OAuth クライアント資格情報** | ID プロバイダーに要求したトークンを bearer トークンとして送り、期限切れ前に再要求します | 専用のステップで **トークン URL**、**クライアント ID**、**クライアントシークレット**。**スコープ** と **オーディエンス** は **その他の項目** に |

トークン、ヘッダーの値、クライアントシークレットは暗号化して保存され、保存した本人にも二度と表示されません。編集時は空欄で始まり、空欄のままにすると保存済みの値が保たれます。サーバーのページには送信するヘッダーの名前だけが表示され、値は表示されません。**認証** を変更すると、以前のサインイン方法が使っていたシークレットは削除されます。

**URL** にトークンやパスワードを入れないでください。サーバーを読める人は誰でもアドレスを読めるうえ、ユーザー名やパスワードを含むアドレスは拒否されます。

## OneUptime AI がサーバーで行うこと

サーバーが提供するツールは、読み取るだけのものか、何かを変更する可能性があるもののどちらかです。OneUptime はツールについてサーバーが示す内容(`readOnlyHint`)に従います。サーバーが読み取り専用と示していないツールは、プロジェクト管理者が読み取り専用としてマークしない限り、何かを変更する可能性があるものとして扱われます([ツールを読み取り専用としてマークする](#ツールを読み取り専用としてマークする) を参照)。どのツールにも何も示さないサーバーもあります。その場合、誰かがツールをマークするまでは、調査ではそのサーバーのツールを一つも使えず、AI に質問ではそのツールの呼び出しがそれぞれあなたの承認を待ちます。

```mermaid title="OneUptime AI が自らどのツールをいつ使うか"
flowchart TB
    T["MCP サーバーの<br/>ツール"] --> Q{"読むだけの<br/>ツールか"}
    Q -->|"はい"| R["調査と修正の<br/>両方で使う"]
    Q -->|"いいえ"| C["修正でのみ<br/>使う"]
    C --> A{"ルールの<br/>承認"}
    A -->|"修正前に<br/>確認する"| P["提案し、<br/>人が承認する"]
    A -->|"確認せずに<br/>修正する"| M["ルールが指定<br/>したサーバー<br/>経由ですぐに<br/>実行する"]
```

| | 読み取るだけのツール | 何かを変更する可能性があるツール |
| --- | --- | --- |
| **調査** | OneUptime 自身のデータとともに使います | 使いません: OneUptime が呼び出しを拒否します |
| **修正** | 修正内容を考えるために使います | AI ルールの **修正** に従い、承認のために提案するか、すぐに使います |
| **AI に質問** | 頼まれたときに使います | 呼び出しごとにあなたが承認してから使います |
| **Slack と Microsoft Teams** | 頼まれたときに使います | 使いません: そこには承認カードがないため、OneUptime AI は AI に質問へ案内します |

**調査では**、OneUptime AI は使えるサーバーのツールを一覧表示し、読み取るツールを呼び出して、OneUptime 自身には見えないもの(クラウドアカウント、デプロイ、課題トラッカーなど)を確認します。その応答を根本原因分析に使います。[AI SRE](/docs/ai/ai-sre) を参照してください。

**修正では**、使えるサーバーが何かを変更する可能性があるツールを提供している場合、OneUptime AI はそのサーバーを通じた修正を考えます。根本原因分析がある場合は、その後です:

- **修正前に確認する** — 加える予定の変更はそれぞれ記録され、どこにも送信されません。インシデントの **OneUptime AI** カードの **修復** ステップはそれらを 1 文にまとめ、**確認して承認** を押すと、サーバー、ツール、送信内容とともに順番に一覧表示されます。**承認して実行** を押すと、その変更をその順番どおり、あなたの名前で実行します。承認には Runbook の開始と同じ権限が必要です。失敗した変更があると、その後の変更は実行されません。
- **確認せずに修正する** — OneUptime AI が自ら変更を加え、各変更は送信前に記録されます。これを行うのは、MCP サーバーを指定しているルールで、ほかに一致したルールが先に確認を求めておらず、ほかに自動でインシデントを修正しているもの(クラスターやホストの AI エージェント、または Runbook)がなく、ルールが 1 時間に自動で行える修正の上限に達していない場合だけです。それ以外では変更は提案されます。ルールが設定されていない場合や、MCP サーバーを指定していないルールでは、すべての変更が提案されます。

1 回の修正で加える変更は最大 5 件です。その後、OneUptime はすべての修正と同様にインシデントのモニターを監視します。自動的に元に戻されることはありません。MCP ツールには OneUptime が知り得る取り消し方法がないため、うまくいかなかった修正は人に委ねられ、**修復** ステップに各サーバーの応答が表示されます。

OneUptime AI にサーバーを使わせないようにするには、そのページで **OneUptime AI にこのサーバーの使用を許可する** をオフにします。オフにする前に確認があり、オフにするとそのサーバーはどの調査や修正でも使われなくなり、そのサーバーを使う提案済みの修正は承認できなくなります。

## ツールを読み取り専用としてマークする

ツールが読み取るだけかどうかを何も示さないサーバーもあります。kAgent のツールサーバーは、`k8s_get_resources` を含め、どのツールについても何も示さないため、OneUptime AI はそれぞれを何かを変更する可能性があるものとして扱います。ツールが読み取るだけだとわかっている場合は、プロジェクト所有者またはプロジェクト管理者がそのツールを読み取り専用としてマークでき、OneUptime AI はそれ以降、そのツールを読み取るだけのものとして使います。調査と修正でも、Slack と Microsoft Teams でも使い、AI に質問では承認カードなしで実行します。

:::steps
### サーバーのツールカードを開く
**プロジェクト設定 → AI → 外部 MCP サーバー** に移動し、サーバーを開きます。その **ツール** カードに、サーバーが何も示していないツールの数が表示されます。

### ツールを選ぶ
ツールの横にある **読み取り専用としてマーク** をクリックします。ダイアログには、ツールが何をするかについてサーバーが示す内容と、ツールが受け取る引数、そしてマークすることの意味が表示されます。

### マークする
ダイアログで **読み取り専用としてマーク** をクリックします。ツールに **読み取り専用** と表示され、誰がいつマークしたかも示されます。
:::

- **一度に一つのツール。** 複数のツールをまとめてマークする方法はありません。
- **サーバーが何も示していないツールだけ。** サーバーが何かを変更する可能性があると示しているツール(`readOnlyHint: false` または `destructiveHint: true`)はマークできません。MCP ライブラリの中には、作者が何も指定していないすべてのツールにそう書き込むものがあります。mcp-go がそうなので、kAgent のツールサーバーはバージョン 0.2 ではすべてのツールについてそう示します。バージョン 0.3 以降は何も示さないため、そのツールはマークできます。
- **明らかに何かを変更するツールは対象外。** 名前から何かを変更するとわかるツール(`delete`、`apply`、`create`、`update`、`restart` など)、渡されたコマンドを実行するツール、変更を有効にできる引数を持つツール(`should_install` や `dry_run` など)はマークできず、その行に理由が表示されます。これらのチェックが見つけるのは明らかな場合だけです。ツールが何をするかを読んでからマークしてください。
- **サーバーがツールを変更すると、マークは適用されなくなります。** マークは、OneUptime が読み込んだときのツールの名前、説明、入力スキーマを保持します。OneUptime AI は実行のたびにツールを読み直します。たとえばアップグレードの後などに、サーバーがそのいずれかを変更していると、そのツールは誰かが再びマークするまで、再び何かを変更する可能性があるものとして扱われます。その行には、サーバーがツールを変更したことが **再びマーク** とともに表示されます。kAgent は起動するたびに `k8s_generate_resource` の説明を新たに書き込むため、このツールのマークは kAgent が再起動するたびに失効します。
- **誰がいつマークしたかが記録されます。** マークされた各ツールには、誰がいつマークしたかが表示されます。[監査ログ](/docs/configuration/audit-logs) がオンのときは、ツールのマークとマークの解除がプロジェクトの監査ログに記録されます。**マークを外す** を押すと、OneUptime AI はただちに、そのツールを使う前に再び確認するようになります。

プロジェクトメンバーと閲覧者は、どのツールがマークされているかと、誰がマークしたかを見られます。

## AI に質問で

AI に質問と、インシデントやアラートの **OneUptime AI** カードの下の会話では、質問する人のために、オンになっているすべてのサーバーを使えます。「AWS にはどんなツールがある?」と聞くと、OneUptime AI はツールを一覧表示し、それぞれにできることの印を付けます。サーバーと名前を指定してツールを使うよう頼むと、そのツールを呼び出し、返ってきた内容で答えます。

- **読み取るだけのツール** は、どの権限モードでもすぐに実行されます: サーバーが読み取り専用と示すツールと、プロジェクト管理者がマークしたツールです。
- **それ以外のツール** は、**自動実行** でもあなたを待ちます。承認カードにはサーバーとツールが示され、送信される内容がそのまま表示されます。あなたが許可するまで、サーバーには何も届きません。**読み取り専用** の会話では、そのようなツールは一切提示されません。
- **あなたの権限で決まります。** サーバーを使うには、プロジェクトの外部 MCP サーバーを読むのと同じ権限が必要です。サーバーを通じた変更を承認するには、MCP サーバーを通じた修正を承認するときと同じく、Runbook の実行を開始する権限が必要です。拒否された呼び出しは理由を示し、何も送信しません。

AI ルールが指定するサーバーは、ルールに一致したものに対して OneUptime AI が自ら使うサーバーです。AI に質問では、サーバーはあなたが選びます。

## Slack と Microsoft Teams で

Slack と Microsoft Teams での OneUptime AI の回答でも、質問した人のために、オンになっているすべてのサーバーを使えます。「Kubernetes にはどんなツールがある?」や「Kubernetes サーバーを使って shop の Pod を一覧表示して」のように、Kubernetes の代わりにあなたのサーバーの名前を入れて聞くと、サーバーのツールが返した内容で答えます。

- **読み取るツールだけ。** サーバーが読み取り専用と示すツールと、プロジェクト管理者がマークしたツールです。チャットアプリには承認カードがないため、それ以外のツールがそこで使われることはありません。それ以外のツールを頼まれると、OneUptime AI はそう伝え、呼び出しごとにあなたが承認する AI に質問へ案内します。
- **質問した人として。** 回答は、あなたの Slack または Microsoft Teams のアカウントが接続されている OneUptime アカウントとして、その権限で実行されます。アカウントがプロジェクトの外部 MCP サーバーを読めない人の回答では、MCP ツールは一切使われません。接続されていないアカウントの人は、まず接続するよう求められ、接続するまで回答を受け取れません。
- **会話の全員が回答を読みます。** 回答には、サーバーのツールが返した内容も含まれます。自分だけが見るべきものは、ダイレクトメッセージで聞いてください。

## ルールが使えるサーバーを選ぶ

AI ルールはそれぞれ、一致したものに対して OneUptime AI が使える MCP サーバーを指定できます。項目は **その他の項目** の **MCP サーバー** です。一部を選ぶまで、OneUptime AI はすべてのサーバーを使え、折りたたまれたセクションにもそう表示されます。

- **何も選ばない** — プロジェクトのオンになっているすべてのサーバー。
- **一部を選ぶ** — 選んだサーバーのみ。確認せずに修正する AI ルールでは、サーバーを指定することが、OneUptime AI がそれらの変更を確認なしで行える条件でもあります。

調査する複数のルールが一致した場合、OneUptime AI はいずれかのルールが許可するすべてのサーバーを使えます。ルールを読み取れない場合、その調査では MCP サーバーを一つも使いません。どのルールにも一致しないインシデントやアラートで誰かが開始した調査は、すべてのサーバーを使えます。一致したルールのうち修正するものはそれぞれ、自分のサーバーを通じた修正を個別に考え、サーバーを指定していないルールは、すべてのサーバーを通じた一つの修正を共有します。

## 安全性

- **サーバーが返すのはデータであり、指示ではありません。** OneUptime AI は、ツールの説明や応答を OneUptime の外部からのテキストとして読みます。それによってルール、承認、OneUptime AI ができることが変わることはありません。
- **ツールには受け取るものだけが渡ります。** OneUptime は、ツールのスキーマが示す引数だけをツールに送ります。OneUptime AI が書いたそれ以外の内容は OneUptime の中にとどまります。
- **AI を有効化 をオフにすると、すべての呼び出しが止まります。** **AI を有効化** がオフのとき、OneUptime はサーバーに何も送りません。調査、修正、AI に質問、Slack、Microsoft Teams のどの呼び出しも、すでに人が承認したものでさえ送られません。
- **アドレスは接続のたびに確認されます。** OneUptime は自身のアドレスやリンクローカルアドレスには接続しません。OneUptime Cloud ではプライベートネットワークのアドレスも拒否するため、サーバーのパブリックアドレスを使ってください。セルフホストの OneUptime は、`DATA_SOURCE_BLOCK_PRIVATE_ADDRESSES=true` が設定されていない限りプライベートアドレスにも到達できます。リダイレクトには従いません。
- **上限。** 1 つのプロジェクトのサーバーは最大 20 台で、OneUptime が読み込むツールはサーバーごとに最大 200 個です。接続は 20 秒、ツールの一覧取得は 30 秒、ツールの呼び出しは 60 秒でタイムアウトします。2 MB を超える応答は拒否されます。実行による MCP サーバーの呼び出しは、プロジェクトが実行あたりの上限を設定している場合、その上限に数えられます。
- **すべての呼び出しが記録されます。** 各呼び出しは実行のステップとしてアクティビティに表示され(AI に質問では回答のステップの中に表示されます)、修正による各変更はサーバーの応答とともに **修復** ステップに表示されます。Slack や Microsoft Teams での回答は、読み取った各サーバーとツールを出典に挙げます。その背後のモデル呼び出しは **プロジェクト設定 → AI → AI ログ** にあります。

## トラブルシューティング

:::details 接続できない、またはテストが失敗する
**接続をテスト** ダイアログに、何がうまくいかなかったかと確認すべき点が表示されます: アドレス(OneUptime Cloud でのプライベートアドレス、応答しないホスト)、サインイン(サーバーが拒否したトークンやヘッダー、トークンを返さなかったトークン URL)、またはサーバーの MCP アドレスではない URL です。サーバーのページの **編集** で設定を直し、もう一度テストしてください。
:::

:::details OneUptime AI がサーバーを使わない
**OneUptime AI にこのサーバーの使用を許可する** がオンになっていることと、サーバーのツールが読み込まれていることを確認してください。**ツール** カードにツールが一覧表示され、それぞれに **読み取り専用** か **変更を加える可能性あり** の印が付きます。**接続をテスト** でツールを読み直せます。次に、AI に質問で「AWS にはどんなツールがある?」と、AWS の代わりにあなたのサーバーの名前を入れて聞いてください。ツールが一覧表示されるか、サーバーに到達できない理由や使えない理由が示されます。調査については、インシデントに一致したルールが **その他の項目** でほかのサーバーを指定していないことも確認してください。調査で使われるのは **読み取り専用** のツールだけなので、どのツールにも何も示さないサーバーでは、プロジェクト管理者が読み取るだけのツールをマークするまで、調査で使えるツールがありません([ツールを読み取り専用としてマークする](#ツールを読み取り専用としてマークする) を参照)。
:::

:::details 読み取り専用としてマークしたツールが再び承認を待つ
マークされてから、サーバーがそのツールを変更しています。**ツール** カードのその行にそう表示され、**接続をテスト** で OneUptime が今読み込む内容を確認できます。**再びマーク** で開くダイアログで何が変わったかを確認し、まだ読み取るだけなら再びマークしてください。サーバーが今は何かを変更する可能性があると示しているツールは、再びマークできません。
:::
