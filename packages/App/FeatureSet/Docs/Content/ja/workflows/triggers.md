# トリガー

トリガーはワークフローの最初のブロックです — ワークフローがいつ動くかを決めます。どのワークフローにもトリガーはちょうど 1 つで、4 種類から選びます。

## 手動

**ビルダー** ページで **ワークフローを実行** をクリックし、トリガーの入力欄を埋めて、**Run Workflow Manually** で確定すると、その場でワークフローを実行できます。手動トリガーは JSON のペイロードを受け取り、ワークフローの残りの部分がそれを読めます。

向いている場面: 「この鍵をローテーションする」「テストアラートを送る」のように、ボタン 1 つで済ませたい自動化。

**出力**: 貼り付けた JSON。何も入れなければ空のオブジェクトです。

## スケジュール

cron 式を使って、繰り返しのスケジュールでワークフローを実行します。

向いている場面: 毎晩のクリーンアップ、1 時間ごとの同期、週次のレポート。

**設定項目**: cron 式。よく使うものをいくつか挙げます。

- `0 * * * *` — 毎時 0 分ちょうど。
- `*/5 * * * *` — 5 分ごと。
- `0 9 * * 1` — 毎週月曜の午前 9 時。

システムが短時間だけ利用できなくなっていた場合、復旧しだいその実行が拾われます — 短い停止で取りこぼしを心配する必要はありません。

## Webhook

OneUptime が専用の URL を作ります。その URL を叩いたものは何であれ、ワークフローを開始します。リクエストのヘッダー、クエリパラメータ、ボディがそのまま渡されます。

向いている場面: 他のツールから OneUptime にデータを受け取ること — CI/CD のコールバック、他の監視ツールからのアラート、CRM での申し込みなど。

**出力**:

- **リクエストヘッダー** — 受信したリクエストのすべてのヘッダー。
- **Request Query Params** — パース済みのクエリ文字列。
- **リクエストボディ** — パース済みのボディ（JSON でなければ生のテキスト）。

この URL は `GET` と `POST` の両方を受け付けます。呼び出し側にはすぐ受領の応答が返り、ワークフロー自体はバックグラウンドで動きます。

この URL はパスワードだと思って扱ってください。手に入れた人は誰でも、あなたのワークフローを開始できます。

## OneUptime イベントトリガー

OneUptime にあるほぼすべてのもの — モニター、インシデント、アラート、定期メンテナンス、ステータスページ、オンコールポリシー、チーム — がワークフローのトリガーになれます。それぞれに 3 つのイベントがあります。

- **On Create** — 新しく追加されたときに発火します。
- **On Update** — 変更されたときに発火します。
- **On Delete** — 削除されたときに発火します。

これが、ループで様子を見に行かなくても「OneUptime で X が起きたら Y をする」を組み立てる方法です。

レコード全体が次のブロックに渡されます。たとえば **インシデント → On Create** トリガーは新しいインシデントを渡すので、次のブロックはそのタイトル、説明、重大度、その他どのフィールドでも読めます。

### 最もよく使われるイベント

- **インシデント** — インシデントが発生した、更新された（確認済み、解決済み）、削除されたときに反応する。
- **アラート** — アラートについても同じ 3 つ。
- **モニター** — モニターが追加・編集・削除されたときに反応する。
- **定期メンテナンス** — メンテナンス枠が予定されたら、自動で告知する。
- **ステータスページ 購読者** — ステータスページを購読してくれた人を迎える。
- **On-Call Duty Policy** — スケジュールの変更を別の当番管理システムに同期する。

**Add Trigger** パネルで名前を検索すれば、目当てのものが見つかります。

## どのトリガーを使うべきか

| やりたいこと                             | 選ぶもの            |
| ---------------------------------------- | ------------------- |
| ボタンを押してワークフローを実行したい   | **手動**            |
| 繰り返しのスケジュールで実行したい       | **スケジュール**    |
| 別のシステムからデータを送ってほしい     | **Webhook**         |
| OneUptime 内の出来事に反応したい         | **OneUptime イベント** |

ワークフローが持てるトリガーは 1 つだけです。同じ自動化を 2 通りの方法で開始したいなら、共通のロジックを 1 つのワークフローに作り、**Execute Workflow** コンポーネントを使って薄い「ラッパー」ワークフロー 2 つから呼び出してください。
