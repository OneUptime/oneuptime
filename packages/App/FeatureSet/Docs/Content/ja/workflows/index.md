# ワークフロー 概要

ワークフローを使うと、コードを書かずに OneUptime での作業を自動化できます。キャンバスにブロックをいくつか置いて線でつなげば、何かが起きたとき — インシデントが発生したとき、スケジュールの時刻が来たとき、別のツールが OneUptime にデータを送ってきたとき — に動く自動化のできあがりです。

ワークフローはプロジェクトの裏方だと考えてください。イベントに反応し、他のツールとやり取りし、あなたが自分の仕事に集中しているあいだ、静かに辻褄を合わせ続けます。

## ワークフローでできること

- **OneUptime を他のツールにつなぐ** — インシデントを Slack に送る、Jira のチケットを作る、自社スタックの Webhook に投げる。
- **OneUptime で起きたことに反応する** — 重大なインシデントが作成されたら、オンコールのチームに通知してチケットを自動で起票する。
- **スケジュールでジョブを走らせる** — 5 分ごと、毎晩、毎週月曜の朝。
- **外部からデータを受け取る** — 専用の URL を通して、他のシステムから OneUptime にデータを送ってもらう。
- **よくある自動化を使い回す** — 一度作れば、他のどのワークフローからでも呼び出せます。

## ワークフローの仕組み

どのワークフローも 3 つの部分でできています。

1. **トリガー** — ワークフローを開始させるもの。手動のボタン、スケジュール、受信 Webhook、あるいは OneUptime 内のイベント（新しいインシデントなど）です。
2. **1 つ以上のコンポーネント** — ワークフローが行うこと。メッセージを送る、HTTP 呼び出しをする、ちょっとしたチェックを走らせる、条件で分岐する。
3. **それらをつなぐ線** — ブロックからブロックへ線を引いて、順番を決めます。

これらはすべてキャンバス上で目に見えるかたちで組み立てます。ほとんどのワークフローにコーディングは要りませんが、必要なら JavaScript のスニペットを足せます。

## キー用語

| 用語                 | 意味                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------- |
| **ワークフロー**     | 自動化ひとまとまり — 名前と、キャンバスと、オン/オフの切り替えです。                    |
| **トリガー**         | 最初のブロック。ワークフローがいつ動くかを決めます。どのワークフローにもちょうど 1 つ。 |
| **コンポーネント**   | 動作のブロック — メッセージを送る、リクエストを投げる、条件を確かめる。                 |
| **実行**             | ワークフローの 1 回分の実行。タイムスタンプと各ブロックの出力とともに保存されます。     |
| **グローバル変数**   | API キーのような値。一度保存すれば、どのワークフローからでも使えます。                  |

## OneUptime 内でワークフローが見つかる場所

左のナビゲーションで **ワークフロー** を開きます。このセクションには次があります。

- **ワークフロー** — ワークフローの一覧。新しく作るのも、既存のものを開くのもここからです。
- **グローバル変数** — すべてのワークフローで共有される値。
- **実行とログ** — プロジェクト内のすべてのワークフローにまたがる実行履歴。

1 つのワークフローを開くと、そのワークフロー自身の左メニューには次があります。

- **概要** — 名前、説明、ラベル、そして **有効** の切り替え。
- **ビルダー** — ワークフローを設計するキャンバス。
- **ワークフロー変数** — このワークフローだけに紐づく値。
- **実行とログ** — このワークフローのすべての実行と、その詳細。
- **設定** — Webhook のシークレット、複製、エクスポート。

## 最初のワークフローを作る

1. **作る** — 出発点を選び、ワークフローに名前を付けます。
2. **トリガーを選ぶ** — 手動、スケジュール、Webhook、あるいは OneUptime のイベント。
3. **コンポーネントを足す** — キャンバスに動作を追加してつなぎます。
4. **オンにする** — **概要** ページで **有効** を入れます。無効なワークフローはまったく実行できません。手動でも動きません。
5. **試す** — **ビルダー** で **ワークフローを実行** をクリックし、実行ログを眺めます。

## クイック例

重大なインシデントが作成されたら Slack に投稿したい、としましょう。

1. 「Critical incidents to Slack」という名前でワークフローを作ります。
2. **On Create Incident** トリガーを選びます。
3. **If / Else** ブロックを足します。インシデントのタイトルに「Sev 1」が含まれるかどうかを確認するよう設定します。
4. **はい** の分岐から **Slack** ブロックを足します。チャンネルを選び、メッセージを書きます。
5. ワークフローをオンにします。

次に誰かがタイトルに「Sev 1」の入ったインシデントを立てた瞬間、Slack が光ります。

## ワークフローと OneUptime の他の機能との関係

- **モニター** が問題を見つけます。**インシデント** がそれを記録します。**ワークフロー** がそれに反応します。
- **Runbook** は人のための手順書です。ワークフローは人の手を介さない自動化です。判断を人がするなら Runbook を、手順が自動で決まるならワークフローを使ってください。
- **ワークスペース接続**（Slack、Teams）は、ワークフローがメッセージを送る先です。
