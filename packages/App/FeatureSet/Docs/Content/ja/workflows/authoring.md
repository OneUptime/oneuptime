# ワークフローを作成する

ワークフローを作るには、**ワークフロー** を開いて **ワークフローを作成** をクリックします。**ワークフローを作成** ダイアログでは、まずどう始めるかを選び、次に名前を付けます。Slack の Webhook URL など、独自の設定が必要なテンプレートでは、もう 1 ステップでその入力を求められます。

どう始めるかを選びます。

- ダイアログのいちばん上にある **ゼロから作成** を選ぶと、空のキャンバスから始まります。ほとんどのワークフローはここから始まります。
- **またはテンプレートから始める** には、**おすすめ** のテンプレートがいくつか並びます。ほかのテンプレートを見るには、検索ボックスの横でカテゴリ（**インシデント**、**モニター**、**Jira** など）や **すべてのテンプレート** を選ぶか、**テンプレートを検索…** に入力します。入力した言葉はすべて一致する必要があります。

テンプレートをクリックすると、その内容を確認できます。トリガー、構成するブロック、入力を求められる設定です。確認したら **このテンプレートを使う** をクリックするか、テンプレートをダブルクリックします。検索ボックスでは矢印キーでテンプレートを選び、**Enter** で使えます。`/` で検索ボックスに戻ります。

ワークフローはオフの状態で作成されるため、オンにするまで何も実行されません。作成したワークフローは **ビルダー** で開きます。ここがワークフローを設計するキャンバスです。

## キャンバス

ゼロから作ったワークフローには、**Choose what starts this workflow** と書かれた破線のブロックが 1 つだけ置かれています。そのブロックが出発点です — クリックしてトリガーを選びます。テンプレートから作ったワークフローは、最初からブロックが配置された状態で開きます。

どのワークフローにも、いちばん上に **トリガー** がちょうど 1 つあります。それ以外はすべて、何かを行う **コンポーネント** です。2 つめのトリガーを追加すると 1 つめが置き換わり、最後の 1 つを削除すると破線のプレースホルダーが戻ってきます。

ブロックの追加:

- **トリガー** — 破線のプレースホルダーのブロックをクリックします。**Add Trigger** というパネルが開きます。
- **それ以外のすべて** — キャンバス上部のツールバーで **コンポーネントを追加** をクリックします。同じパネルが **コンポーネントを追加** という見出しで開きます。

どちらのパネルも、ほとんどのワークフローで使うブロックが **Popular** の下に並んだ状態で開き、その後にほかの組み込みブロックが続きます。**OneUptime resources** の下で **Incident** などのリソースをクリックすると、それに対してできることが表示されます。**Browse all resources** にはすべてのリソースが並んでいます。検索もできます。`create incident` のように数語を入力すると、いちばん近いものが先頭に来ます。`/` を押すと検索ボックスに移動し、矢印キーで結果の間を移動して、**Enter** で強調表示中のブロックを追加します。ブロックをクリックすると、そのブロックが追加されます。

新しいブロックは、キャンバスでいちばん下にあるブロックのさらに下に置かれます。新しいトリガーは、いちばん上にある古いトリガーと入れ替わります。新しいブロックは選択された状態になり、画面の外に置かれた場合は、見えるところまでだけキャンバスがスクロールします。設定は自動では開きません。設定する準備ができたら、ブロックをクリックしてください。必須の設定が空のあいだは、ブロックに **Click to set up** と表示されます。ブロックは好きな場所へドラッグできます。動かすあいだ、キャンバスはグリッドに吸着します。ブロックの位置は保存されるので、次に開いた人も、あなたが残した配置をそのまま見ることになります。

変更は自動で保存されます。ツールバーのピルがその様子を伝えます。保存中は **Saving…**、終われば **保存しました**、うまくいかなければ **保存できませんでした** です。保存ボタンはなく、公開のための別のステップもありません。

## ブロックの中身

| 項目                              | 役割                                                                                                                                                                                                        |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier**（**ID** の下）     | ブロック上に表示される短い id で、`log-1` のような形です。他のブロックはこの id でこのブロックを指すので、名前を変えると、そこを指していた `{{local.components.…}}` の参照はすべて壊れます。ブロックの見出しはコンポーネント自身の名前で、変えられません。 |
| **設定**                          | そのブロックが仕事をするのに必要なもの — URL、Slack のチャンネル、メッセージの本文など。任意の項目には **(Optional)** と付き、それ以外は必須です。あまり使わない設定は **その他の項目** に折りたたまれています。見出しにはその項目名が並び、値が入っているものが表示されます。 |
| **入力**                          | 上端にある点で、前のブロックからの線がここに入ってきます。トリガーにはありません — その前に動くものが何もないからです。                                                                                    |
| **出力**                          | 下端に並ぶ点で、すぐ上にラベルが付いており、ここから次のブロックへ線が出ていきます。多くのブロックは **成功** と **エラー** の出力を分けて持っているので、どちらの場合も扱えます。                          |

## ブロックをつなぐ

あるブロックの下側にある点から、次のブロックの上側にある点まで、下向きにドラッグします。引いた線が、次に何が動くかを決めます。

- **成功** からつなぐと、前のブロックがうまくいったときだけ次のブロックが動きます。
- **エラー** からつなぐと、前のブロックが失敗したときだけ次のブロックが動きます。
- 出力をどこにもつながなければ、その経路はそこで終わります。

1 つの出力を複数のブロックにつなぐこともできます。それらはすべて動きますが、並列ではなく、1 本のキューで順番に動きます。分岐どうしの順序をあてにしないでください。時間が重なることも期待しないでください。1 回の実行でどのブロックも高々 1 回しか動かないので、前のブロックへ戻る線を引いても、そのブロックが 2 回動くことはありません。

## ブロックを設定する

ブロックをクリックすると（または **Tab** でブロックに移動して **Enter** を押すと）、その設定がダイアログで開きます。設定ごとにふさわしい入力欄 — テキスト欄、ドロップダウン、コードエディター、切り替えスイッチなど — が用意されています。入力したら **保存** をクリックします。

同じダイアログには、次のものもあります。

- **削除** — このブロックを取り除きます。
- **Run just this step** — ワークフローの残りを動かさずに、このブロックだけを単独で実行します。他のステップから読むはずだった値は空のまま渡り、送信・書き込み・削除は本当に実行されます。
- **ドキュメント**、**Inputs**、**Outputs**、**Returns** — このブロックが何を受け取り、何を返すかをまとめたリファレンスカードです。

ほとんどのテキスト欄は変数を受け付けます — これが、ブロックからブロックへデータが流れる仕組みです。構文を手で打つのではなく、エディターの値ピッカーを使ってください。選んだブロックと項目から、正しい参照を組み立ててくれます。[ワークフロー 変数](/docs/workflows/variables) を参照してください。

## 組み立てながら行われるチェック

ビルダーは変更のたびにグラフ全体を検査し、見つけたことをツールバーのピルに表示します。ピルをクリックすると **Problems with this workflow** が開き、問題が一覧されます。項目を選ぶと、原因のブロックまで移動します。キャンバス上では、必須の設定がまだ空のブロックに **Click to set up** と表示され、それ以外の問題があるブロックには隅にバッジが付きます。エラーは赤、警告はオレンジです。バッジにマウスを合わせると、何が問題なのかを読めます。

ここで捕まるのは、実行が失敗するまで目に見えないたぐいの間違いです — トリガーがない、2 つのブロックが同じ id を使っている、id にピリオドが入っている、どこからもつながっていないブロックがある、必須の設定が空のまま、JSON の形が壊れている、`{{ }}` の中に空白がある、存在しないステップや戻り値を参照している、といったものです。

ただし 1 つだけ検査できないことがあります。変数名が実在するかどうかです。名前を変えた変数の影響は、実行ログでしか分かりません。

## 最初のワークフロー

キャンバスの感触をつかむ、いちばん手っ取り早い手順です。

1. 破線のプレースホルダーのブロックをクリックし、**Add Trigger** パネルで **手動** をクリックします。
2. **コンポーネントを追加** をクリックし、**Popular** の下にある **ログ** をクリックします。新しいブロックはトリガーの下に置かれます。トリガーの **Execute** の点から、ログ ブロックの入力の点まで線を引きます。
3. **Click to set up** と表示されたログ ブロックをクリックし、**値** に `Hello from {{local.components.manual-1.returnValues.value.name}}` を設定します。`manual-1` はトリガーの **Identifier** で、トリガーのブロック上に表示されています — 一致しているか確かめてください。
4. ビルダーの上部で **有効** をオンにします。無効のワークフローはまったく実行できません。手でも動かせません。この手順を飛ばしても、**ワークフローを実行** が先にオンにするか尋ねます。
5. **ビルダー** に戻って **ワークフローを実行** をクリックし、**JSON** の欄に `{ "name": "Ada" }` を入れて **Run Workflow Manually** をクリックし、**Run** で確定します。
6. **Workflow Run** のパネルがひとりでに開き、実行を追いかけます。ログには `Value:` に続いて `Hello from Ada` と出ます。

この繰り返し — 足して、つないで、設定して、実行して、ログを読む — が、これから作るすべてのワークフローの組み立て方です。

## オンにする

新しいワークフローは無効の状態で始まります。複製したものも、インポートしたものも同じです。ワークフローがオフのあいだは、ビルダーのキャンバスの上にそのことが表示され、**ワークフローをオンにする** ボタンが出ます。

**有効** の切り替えは **ビルダー** の上部、**コンポーネントを追加** と **ワークフローを実行** の隣にあります。ワークフローの **概要** ページにもあります。**ワークフローの詳細** カードで **ワークフローを編集** をクリックしてください。このカードには、いまの状態が緑の **有効** か赤の **無効** のピルで表示されます。オン/オフを切り替えられるのは、そのワークフローを編集できるユーザーだけです。それ以外のユーザーには、切り替えがグレー表示されます。

無効のワークフローはまったく動きません。トリガーは無視され、**ワークフローを実行** も **Run just this step** も同様です。オフのあいだにワークフローやそのブロックを実行すると、ビルダーは代わりに **このワークフローをオンにしますか？** と尋ねます。**オンにして実行**（または **オンにしてステップを実行**）を押すと、ワークフローがオンになり、頼んだ実行が、入力した値のまま行われます。ですから順番はこうなります。組み立て、**ワークフローを実行** で試し、実行ログを読み、トリガーが発火する準備がまだなら **有効** をオフに戻します。ワークフロー全体を動かさずにブロックを 1 つだけ試したいときは、そのブロックの設定にある **Run just this step** を使ってください。

それ以外の方法で無効のワークフローを動かそうとしても、同じ案内とともに拒否されます。Webhook URL を呼び出すと、HTTP 400 と「This workflow is turned off, so it can't run. Turn it on with the Enabled switch at the top of its Builder, then try again.」が返ります。そのワークフローを呼び出す **Execute Workflow** ブロックは **Error** の経路に進み、エラーには呼び出したワークフローの名前が入ります。

削除せずにワークフローを止めておきたいときは、**有効** をオフにします。新しい実行は始まりません。実行の途中のものは最後まで走りますが、**Sleep** ブロックで止まって待っている実行は、目を覚ました時点で打ち切られ、エラーとして記録されます。

## 整理する

- ブロックはドラッグで動かせます。配置は保存されます。
- 線を消すには、どちらかの端を点から引き離して、キャンバスの何もない場所に落とします。
- ブロックを消すには、クリックして設定ダイアログの下にある **削除** を使います。ブロックや線を選んで Backspace を押しても消えます。
- ブロックを 1 つだけ複製する方法はありません。ワークフローの **設定** ページにある **Duplicate Workflow** はワークフローをまるごとコピーします。コピーの名前はあらかじめ入力され、プロジェクトのワークフローの次の番号が付きます (「Nightly Sync」は「Nightly Sync 2」としてコピーされます)。コピーは無効の状態で開きます。
- ブロックは上から下へ積んで、動く向きに読めるようにしましょう — 入力は上端、出力は下端なので、流れは自然と下に向かいます。
