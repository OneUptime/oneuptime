# ワークフローを作成する

ワークフローを作るには、**ワークフロー** を開いて **ワークフローを作成** をクリックします。**Create a workflow** というウィザードが案内してくれます。まず **Start from** で **Start from scratch** かテンプレートのどれかを選び、次に **名前** を決め、最後に **設定** のステップ — これは選んだテンプレート自身に設定項目があるときだけ現れます。

作成できたら、左メニューの **ビルダー** を開きます。ここがワークフローを設計するキャンバスです。

## キャンバス

ゼロから作ったワークフローには、**Please click here to add trigger** と書かれた破線のブロックが 1 つだけ置かれています。そのブロックが出発点です — クリックしてトリガーを選びます。テンプレートから作ったワークフローは、最初からブロックが配置された状態で開きます。

どのワークフローにも、いちばん上に **トリガー** がちょうど 1 つあります。それ以外はすべて、何かを行う **コンポーネント** です。2 つめのトリガーを追加すると 1 つめが置き換わり、最後の 1 つを削除すると破線のプレースホルダーが戻ってきます。

ブロックの追加:

- **トリガー** — 破線のプレースホルダーのブロックをクリックします。**Add Trigger** というパネルが開きます。
- **それ以外のすべて** — キャンバス上部のツールバーで **コンポーネントを追加** をクリックします。同じパネルが **コンポーネントを追加** という見出しで開きます。

どちらのパネルも検索でき — `/` を押すと検索ボックスに移動します — カテゴリごとにまとまっています。ブロックを 1 つ選んで **Add to Workflow** をクリックしてください。

新しいブロックはいつもキャンバスの同じ場所に置かれるので、すでに置いてあるものの上に重なることがあります。ドラッグしてどかしてください。動かすあいだ、キャンバスはグリッドに吸着します。ブロックの位置は保存されるので、次に開いた人も、あなたが残した配置をそのまま見ることになります。

変更は自動で保存されます。ツールバーのピルがその様子を伝えます。保存中は **Saving…**、終われば **保存しました**、うまくいかなければ **保存できませんでした** です。保存ボタンはなく、公開のための別のステップもありません。

## ブロックの中身

| 項目                              | 役割                                                                                                                                                                                                        |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier**（**ID** の下）     | ブロック上に表示される短い id で、`log-1` のような形です。他のブロックはこの id でこのブロックを指すので、名前を変えると、そこを指していた `{{local.components.…}}` の参照はすべて壊れます。ブロックの見出しはコンポーネント自身の名前で、変えられません。 |
| **設定**                          | そのブロックが仕事をするのに必要なもの — URL、Slack のチャンネル、メッセージの本文など。任意の項目には **(Optional)** と付き、それ以外は必須です。あまり使わない設定は **詳細** の折りたたみの中にあります。 |
| **入力**                          | 上端にある点で、前のブロックからの線がここに入ってきます。トリガーにはありません — その前に動くものが何もないからです。                                                                                    |
| **出力**                          | 下端に並ぶ点で、すぐ上にラベルが付いており、ここから次のブロックへ線が出ていきます。多くのブロックは **成功** と **エラー** の出力を分けて持っているので、どちらの場合も扱えます。                          |

## ブロックをつなぐ

あるブロックの下側にある点から、次のブロックの上側にある点まで、下向きにドラッグします。引いた線が、次に何が動くかを決めます。

- **成功** からつなぐと、前のブロックがうまくいったときだけ次のブロックが動きます。
- **エラー** からつなぐと、前のブロックが失敗したときだけ次のブロックが動きます。
- 出力をどこにもつながなければ、その経路はそこで終わります。

1 つの出力を複数のブロックにつなぐこともできます。それらはすべて動きますが、並列ではなく、1 本のキューで順番に動きます。分岐どうしの順序をあてにしないでください。時間が重なることも期待しないでください。1 回の実行でどのブロックも高々 1 回しか動かないので、前のブロックへ戻る線を引いても、そのブロックが 2 回動くことはありません。

## ブロックを設定する

ブロックをクリックすると、その設定がダイアログで開きます。設定ごとにふさわしい入力欄 — テキスト欄、ドロップダウン、コードエディター、切り替えスイッチなど — が用意されています。入力したら **保存** をクリックします。

同じダイアログには、次のものもあります。

- **削除** — このブロックを取り除きます。
- **Run just this step** — ワークフローの残りを動かさずに、このブロックだけを単独で実行します。他のステップから読むはずだった値は空のまま渡り、送信・書き込み・削除は本当に実行されます。
- **ドキュメント**、**Inputs**、**Outputs**、**Returns** — このブロックが何を受け取り、何を返すかをまとめたリファレンスカードです。

ほとんどのテキスト欄は変数を受け付けます — これが、ブロックからブロックへデータが流れる仕組みです。構文を手で打つのではなく、エディターの値ピッカーを使ってください。選んだブロックと項目から、正しい参照を組み立ててくれます。[ワークフロー 変数](/docs/workflows/variables) を参照してください。

## 組み立てながら行われるチェック

ビルダーは変更のたびにグラフ全体を検査し、見つけたことをツールバーのピルに表示します。ピルをクリックすると **Problems with this workflow** が開き、問題が一覧されます。項目を選ぶと、原因のブロックまで移動します。問題のあるブロックには、キャンバス上でも赤いバッジが付きます。

ここで捕まるのは、実行が失敗するまで目に見えないたぐいの間違いです — トリガーがない、2 つのブロックが同じ id を使っている、id にピリオドが入っている、どこからもつながっていないブロックがある、必須の設定が空のまま、JSON の形が壊れている、`{{ }}` の中に空白がある、存在しないステップや戻り値を参照している、といったものです。

ただし 1 つだけ検査できないことがあります。変数名が実在するかどうかです。名前を変えた変数の影響は、実行ログでしか分かりません。

## 最初のワークフロー

キャンバスの感触をつかむ、いちばん手っ取り早い手順です。

1. 破線のプレースホルダーのブロックをクリックし、**Add Trigger** パネルで **手動** を選んで、**Add to Workflow** をクリックします。
2. **コンポーネントを追加** をクリックし、（**Utils** の下にある）**ログ** を選んで **Add to Workflow** をクリックします。新しいブロックをトリガーから離れた場所へドラッグし、トリガーの **Execute** の点から、ログ ブロックの入力の点まで線を引きます。
3. ログ ブロックを開き、**値** に `Hello from {{local.components.manual-1.returnValues.value.name}}` を設定します。`manual-1` はトリガーの **Identifier** で、トリガーのブロック上に表示されています — 一致しているか確かめてください。
4. **概要** に移動し、**ワークフローの詳細** カードで **ワークフローを編集** をクリックして、**有効** をオンにします。無効のワークフローはまったく実行できません。手でも動かせません。
5. **ビルダー** に戻って **ワークフローを実行** をクリックし、**JSON** の欄に `{ "name": "Ada" }` を入れて **Run Workflow Manually** をクリックし、**Run** で確定します。
6. **Workflow Run** のパネルがひとりでに開き、実行を追いかけます。ログには `Value:` に続いて `Hello from Ada` と出ます。

この繰り返し — 足して、つないで、設定して、実行して、ログを読む — が、これから作るすべてのワークフローの組み立て方です。

## オンにする

新しいワークフローは無効の状態で始まります。複製したものも、インポートしたものも同じです。

**有効** の切り替えは、ワークフローの **概要** ページにある **ワークフローの詳細** カードの中です — 設定ページではありません。同じカードに、いまの状態が緑の **有効** か赤の **無効** のピルで表示されます。

無効のワークフローはまったく動きません。手動の実行も、トリガーによる実行とまったく同じように「This workflow is not enabled」で拒否されます。ですから順番はこうなります。まず有効にし、**ワークフローを実行** で試し、実行ログを読み、トリガーが発火する準備がまだなら **有効** をオフに戻します。ワークフロー全体を動かさずにブロックを 1 つだけ試したいときは、そのブロックの設定にある **Run just this step** を使ってください。

削除せずにワークフローを止めておきたいときは、**有効** をオフにします。新しい実行は始まりません。実行の途中のものは最後まで走りますが、**Sleep** ブロックで止まって待っている実行は、目を覚ました時点で打ち切られ、エラーとして記録されます。

## 整理する

- ブロックはドラッグで動かせます。配置は保存されます。
- 線を消すには、どちらかの端を点から引き離して、キャンバスの何もない場所に落とします。
- ブロックを消すには、クリックして設定ダイアログの下にある **削除** を使います。ブロックや線を選んで Backspace を押しても消えます。
- ブロックを 1 つだけ複製する方法はありません。ワークフローの **設定** ページにある **Duplicate Workflow** はワークフローをまるごとコピーし、コピーは無効の状態で作られます。
- ブロックは上から下へ積んで、動く向きに読めるようにしましょう — 入力は上端、出力は下端なので、流れは自然と下に向かいます。
