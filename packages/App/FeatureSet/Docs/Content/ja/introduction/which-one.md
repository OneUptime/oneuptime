## インシデント、アラート、それ以外の問題のどれか

ほとんどの問題はインシデントかアラートのどちらかで、その問題が誰に影響するかで選びます。それ以外は OneUptime が記録しておくもので、どれもインシデントやアラートにつながることがあります。

| 記録 | 何か | 使うとき |
| --- | --- | --- |
| [インシデント](/docs/incidents/index) | ユーザーに影響する問題です。オンコール担当者を呼び出し、ステータスページに表示できます。 | 顧客が気付いている、またはすぐに気付くとき。障害、速度低下、失敗するチェックアウトなど。 |
| [アラート](/docs/alerts/index) | チームにとっての問題です。オンコール担当者を呼び出せますが、ステータスページには表示されません。 | ユーザーが気付く前にチームが動くべきとき。ディスクの容量不足、期限切れが迫った証明書など。 |
| [エピソード](/docs/incidents/episodes) | 関連するインシデント、または関連するアラートを、1 つにまとめて扱うものです。 | 1 つの原因が多くのインシデントやアラートを発生させたとき。グループ化ルールがエピソードを自動で開きます。 |
| [例外](/docs/telemetry/exceptions) | コードがスローする 1 つのエラーの発生をすべてまとめたもので、スタックトレース付きです。 | バグを修正したいとき。例外モニターは、エラーが急増したときにアラートやインシデントを発生させられます。 |
| [AI インサイト](/docs/ai/ai-sre#インサイト-先回りの検出) | 何かが呼び出しを行う前に、OneUptime がテレメトリで見つけた問題です。エラーログの急増など。 | 早めの警告がほしいとき。インサイトは誰も呼び出さず、インシデントも開きません。受信トレイで待ちます。 |
| [セキュリティケース](/docs/telemetry/security-cases) | 調べる価値のある 1 つの脅威で、同じユーザー、ホスト、アドレスに関するすべての検出を含みます。 | セキュリティチームが調査するとき。ユーザーに影響がある場合は、ケースの **インシデントを宣言** でインシデントを開きます。 |

アラートは、それが一部だったと判明したインシデントにリンクできるので、アラートから始めても失うものはありません。

## ワークフロー、Runbook、プレイブック、AI ルールのどれか

4 つとも自動で実行できます。何に対して動くか、誰がステップを書いたかで選びます。

| ツール | 何をするか | 使うとき |
| --- | --- | --- |
| [ワークフロー](/docs/workflows/index) | トリガーが発火すると実行される、キャンバス上のブロックです。インシデントの作成、スケジュールの時刻の到来、別のツールからの URL の呼び出しなど。 | コードを書かずに、OneUptime をほかのツールとつないだり、そのレコードを操作したりしたいとき。 |
| [Runbook](/docs/runbooks/index) | 対応手順をステップにしたもので、手動のチェックリストからスクリプト、HTTP リクエスト、kubectl までを、インシデント、アラート、メンテナンスイベントに対して実行します。 | 対応者が毎回同じステップをたどるべきとき。Runbook ルールは、一致したインシデントで Runbook を開始します。 |
| [プレイブック](/docs/telemetry/security-cases#プレイブック) | セキュリティケースに応答するステップです。証拠の保全、オンコール担当者の呼び出し、ユーザーの停止など。 | セキュリティチームが、同じ種類の脅威に毎回同じ方法で対応するとき。 |
| [AI ルール](/docs/ai/ai-sre#調査修正されるインシデント) | OneUptime AI がどの新しいインシデントとアラートを調査・修正するか、そして先に確認を求めるかを決めます。 | OneUptime AI に一部のインシデントだけを扱わせたい、または確認なしで修正させたいとき。ルールがなければ、すべてを調査します。 |

## モニターグループ、サービス、ラベルのどれか

3 つとも物事をまとめますが、読み手が異なります。組み合わせて使うこともでき、サービスのモニターで 1 つのモニターグループを作り、そのすべてに同じラベルを付けられます。

| 選択肢 | 何か | 使うとき |
| --- | --- | --- |
| [モニターグループ](/docs/monitor/monitor-groups) | 複数のモニターを 1 つのステータス (その中で最も悪いもの) にまとめたもので、独自の稼働率を持ちます。 | Checkout のように複数のモニターでできているものを、顧客がステータスページで 1 行で見られるようにしたいとき。 |
| [サービス](/docs/telemetry/services) | OneUptime がテレメトリの中で見つけたアプリケーションで、そのログ、トレース、メトリクス、インシデント、所有者を 1 ページにまとめます。 | 1 つのアプリケーションについてのすべてを 1 か所で見たいとき。 `service.name` から自動的に現れます。 |
| [ラベル](/docs/configuration/label-and-owner-rules) | モニターやその他ほとんどのレコードに付けるタグです。1 つのレコードに複数付けられます。 | 一覧を絞り込んだり、チームの権限を制限したり、ルールでレコードを選び出したりしたいとき。 |

モニターグループは最初はオフです。 **プロジェクト設定 → 詳細 → 機能フラグ** でオンにします。

## プローブ、エージェント、コレクター、Runner のどれか

OneUptime のほとんどは、何もインストールせずに使えます。OneUptime が外部から見られないものに届かせたいときだけ、何かをインストールします。どれも外向きに接続し、それぞれ独自の種類のキーを使います。

| インストールするもの | 何をするか | インストールするとき | 使うキー |
| --- | --- | --- | --- |
| [カスタムプローブ](/docs/probe/custom-probe) | ネットワークの内側から、モニターのチェックを実行します。 | チェック対象がファイアウォールの内側にあるとき。OneUptime 自身のプローブは、公開されているものをチェックします。 | 独自のプローブ ID とキー |
| [インフラストラクチャエージェント](/docs/monitor/server-monitor) | 1 台のマシンの CPU、メモリ、ディスク、プロセスを Server / VM モニターに報告します。 | 1 台のサーバーを 1 つのモニターで監視し、その数値に条件を設定したいとき。 | モニターのシークレットキー |
| [OpenTelemetry Collector](/docs/telemetry/hosts) | マシンのメトリクス、ログ、プロセスを送信します。 **ホストを追加** がコマンド 1 つでインストールします。 | マシンを、そのテレメトリとともに **ホスト** に表示したいとき。 | 取り込みキー |
| [Kubernetes エージェント](/docs/telemetry/kubernetes-agent) | クラスターのメトリクス、イベント、ログ、トレースを収集します。Helm でインストールします。 | Kubernetes を運用しているとき。 | 取り込みキー |
| [Runner](/docs/runbooks/agents) | Bash、SSH、kubectl などの Runbook のステップを、インフラストラクチャの内側で実行します。 | Runbook が自社のホストやクラスターに届く必要があるとき。 | 独自の Runner ID とキー |

### 取り込みキーと API キーのどちらか

| キー | できること | 作成する場所 |
| --- | --- | --- |
| [取り込みキー](/docs/telemetry/ingestion-keys) | プロジェクトにテレメトリを送ることだけです。 | **プロジェクト設定 → テレメトリと APM → 取り込みキー** |
| [API キー](/docs/permissions/index#api-キー) | 与えた権限の範囲で、API、CLI、Terraform、AI アシスタントからプロジェクトを読み書きします。 | **プロジェクト設定 → 詳細 → API キー** |

どちらも、もう一方の代わりにはなりません。

## ダッシュボード、公開ダッシュボード、ステータスページのどれか

誰に見せるかで選びます。

| 共有するもの | 誰が見るか | 使うとき |
| --- | --- | --- |
| [ダッシュボード](/docs/dashboards/index) | プロジェクトにサインインする人。 | チームがチャートや一覧を見るとき。オンコール用の画面、チーム独自のビューなど。 |
| [公開ダッシュボード](/docs/dashboards/sharing) | リンクを知っている誰でも。ただし、パスワードを追加したり、特定の IP アドレスに限定したり、独自ドメインでホストしたりした場合は別です。 | パートナーや壁の画面など、プロジェクト外の人にチャートを見せたいとき。 |
| [ステータスページ](/docs/status-pages/index) | 顧客。公開なら誰でも、非公開なら招き入れたユーザーだけ。 | 顧客が、サービスが動いているかを知り、インシデントやメンテナンスの知らせを受けたいとき。 |

ステータスページはインシデントと、モニターに付けた名前で語り、ダッシュボードはその裏にある数値を示します。
