# Global SSO（インスタンス全体のシングルサインオン）

Global SSO を使用すると、OneUptime の **インスタンス管理者**（マスター管理者）が単一の SAML 2.0 または OpenID Connect（OIDC）アイデンティティプロバイダーを **インスタンスレベルで一度だけ** 設定し、サーバー上の任意のプロジェクトに接続できます。これはプロジェクトごとの SSO に対するインスタンス全体の対応物です。各プロジェクトのオーナーがそれぞれ独自のアイデンティティプロバイダーを設定するのではなく、マスター管理者がインスタンス全体に提供できるものを 1 つ設定します。

Global SSO（インスタンス全体の「Require SSO for Login」トグルを含む）は OneUptime のすべてのエディションに含まれます。Community Edition を含むすべてのセルフホストインスタンスで利用でき、ライセンスは不要です。インスタンス管理の機能であるため、OneUptime Cloud には適用されません。各エディションに含まれる機能については [Enterprise Edition](/docs/self-hosted/enterprise) をご覧ください。

## Global SSO とプロジェクト SSO の比較

|                | プロジェクト SSO                                  | Global SSO                                               |
| -------------- | ------------------------------------------------- | -------------------------------------------------------- |
| 設定者         | プロジェクトのオーナー/管理者（プロジェクト設定） | インスタンスのマスター管理者（管理ダッシュボード）       |
| 範囲           | 単一のプロジェクト                                | インスタンス全体 — 任意のプロジェクトに接続可能          |
| サインイン結果 | その 1 つのプロジェクトへのアクセス               | ユーザーがアクセスできるすべてのプロジェクトへのアクセス |

## Global SSO のセットアップ

1. **管理ダッシュボードを開く**

   - マスター管理者としてサインインし、**Admin** > **設定** > **Global SSO**（SAML の場合）または **Global OIDC**（OpenID Connect の場合）を開きます。

2. **プロバイダーを作成する**

   - **Create Global SSO** をクリックします。
   - SAML の場合: **名前** を入力し、アイデンティティプロバイダーの **サインオンURL** と **発行者** を入力し、**公開証明書** を貼り付けます。その他は **詳細** に自動で入力されます: **署名方式**（`RSA-SHA256`）、**ダイジェストメソッド**（`SHA256`）、説明（`Sign in with` と名前）。IdP が必要とする場合にのみ変更してください。保存するとプロバイダーのページが開きます。
   - OIDC の場合: **名前**、**発行者 URL**、IdP に登録したアプリの **クライアントID** と **クライアントシークレット** を入力します。IdP のディスカバリ URL を **発行者 URL** に貼り付けることもできます。その他は **詳細** に自動で入力されます: **ディスカバリ URL**（発行者に `/.well-known/openid-configuration` を付けたもの）、**スコープ**（`openid email profile`）、`email` と `name` のクレーム名、説明（`Sign in with` と名前）。IdP が必要とする場合にのみ変更してください。保存するとプロバイダーのページが開きます。

3. **OneUptime の URL をアイデンティティプロバイダーにコピーする**

   - プロバイダーを開く（リスト内の行をクリック）と、**Identity Provider URLs** カードが表示されます。
   - SAML の場合、**ACS URL (Reply URL)** と **Issuer (Entity ID)** を IdP（Okta、Azure AD、OneLogin、JumpCloud など）にコピーします。
   - OIDC の場合、**Redirect URI** を IdP の許可されたリダイレクトリストにコピーします。

4. **プロバイダーをテストする**
   - プロバイダーのページにある **Test this SSO provider** リンクを使用して、アイデンティティプロバイダーを介したエンドツーエンドのサインインを実行します。リンクが機能するには、プロバイダーが **有効** になっている必要があります。グローバルプロバイダーを有効にすると、ログインページに「Sign in with SSO」オプションが追加されるだけです。SSO を強制したり、誰かをロックアウトしたりすることは決してないため、安全に有効化、テストし、必要に応じて再度無効化できます。

## ユーザーのサインイン方法

グローバルプロバイダーの動作は、プロジェクトを接続するかどうかによって異なります。

- **プロジェクトを接続しない（default-all / invite-first）:** ユーザーはプロバイダーでサインインし、**すでにメンバーになっている任意のプロジェクト** にアクセスできます。新規ユーザーは自動的には作成され **ません** — ユーザーはまずプロジェクトに招待される必要があります。メンバーシップが他の場所で管理されている全社的な SSO にはこれを使用します。

- **プロジェクトを接続する（自動プロビジョニング）:** プロバイダーを開き、**Attached Projects** テーブルを使用して、それぞれにデフォルトチームのセットを持つ 1 つ以上のプロジェクトを接続します。サインインしたユーザーは、初回ログイン時にそれらのプロジェクトに **自動プロビジョニング** され、デフォルトチームに追加されます。リストを作成するには、一度に 1 つのプロジェクトとチームを追加します。接続を変更するには、それを削除して再度追加します。

プロジェクトが接続されている場合でも自動的なアカウント作成を防ぎたい場合は、プロバイダーで **Disable Sign Up with SSO** を有効にします。そうすると、ユーザーはサインインする前に招待される必要があります。

## SSO の強制

グローバルプロバイダーを設定しても、誰にも使用を強制することはありません。パスワードログインも引き続き機能します。SSO を必須にするには、**Require SSO for Login** コントロールを使用します。

- **プロジェクトごと:** プロジェクトは SSO を必須にでき、オプションで _特定の_ プロバイダー（プロジェクトまたはグローバル）を必須にできます。
- **インスタンス全体:** **Admin** > **設定** > **認証** には、インスタンス全体のすべてのユーザーに対して SSO を強制する **ログインに SSO を必須にする** トグルがあります。マスター管理者がロックアウトされないように、マスター管理者は引き続き対象外となります。
