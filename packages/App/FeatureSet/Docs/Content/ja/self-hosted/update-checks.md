# アップデートとセキュリティの確認

セルフホストの OneUptime は 1 日に 1 回、新しいリリースが出ているかどうかと、OneUptime が公開したセキュリティアドバイザリが実行中のバージョンに影響するかどうかを GitHub に問い合わせます。影響するアドバイザリがある場合は、マスター管理者にアップグレードを求めます。このページでは、この確認で送信される内容、表示される内容、確認をオフにする方法を説明します。

:::cards
- [確認で送信される内容](#確認で送信される内容): 公開情報についての 2 つの問い合わせだけで、インストールについては何も送りません。
- [表示される内容](#表示される内容): フッター、管理者ダッシュボード、アドバイザリごとに 1 通のメール。
- [確認をオフにする](#確認をオフにする): インターネットに接続できないネットワーク向け、またはミラーを使う場合。
:::

## 確認で送信される内容

ワーカーは GitHub の API (`api.github.com`) に、トークンなしで次の 2 つのリクエストを送信します:

| リクエスト | 問い合わせる内容 |
| --- | --- |
| `GET /repos/OneUptime/oneuptime/releases/latest` | OneUptime の最新リリースはどれか |
| `GET /repos/OneUptime/oneuptime/security-advisories?state=published` | OneUptime が公開したセキュリティアドバイザリ、それぞれが影響するバージョン、それを修正するリリース |

これらのリクエストには、インストールに関する情報は何も含まれません。実行中のバージョンも、そのアドレスも、ユーザー、プロジェクト、監視データに関する情報も含まれません。GitHub からは、他のリクエストと同じくサーバーのパブリック IP アドレスと、OneUptime を名乗る `User-Agent` が見えます。アドバイザリが実行中のバージョンに影響するかどうかはサーバー上で判定され、ブラウザーが GitHub を呼び出すことはありません。

確認はワーカーの起動時に実行され、その後は 1 日に 1 回実行されます。GitHub に再び問い合わせるのは多くても 12 時間に 1 回で、リクエストが失敗した後は多くても 1 時間に 1 回です。

## 表示される内容

通知されるのはマスター管理者だけです。アップグレードできるのはマスター管理者であり、それ以外の人に、サーバーが既知のセキュリティ問題のあるバージョンを実行していると伝えると、パッチが適用されていないサーバーを教えることになるからです。

- 新しいリリースが出ると、Dashboard と管理者ダッシュボードのフッターに **アップデートがあります** が表示されます。クリックするとアップグレードガイドが開きます。
- 実行中のバージョンに影響する公開済みのセキュリティアドバイザリがある場合は、代わりに赤色の **セキュリティアップデート** が表示されます。
- その場合、管理者ダッシュボードの最初のページに、各アドバイザリの重大度、影響するバージョン、修正するリリース、GitHub 上のアドバイザリへのリンクが一覧表示されます。確認が最後にアドバイザリを読み取った日時と、直近の確認が失敗した場合はその理由も表示されます。
- マスター管理者と管理者通知メール (管理者ダッシュボードの **設定** > **メール**) には、実行中のバージョンに影響するアドバイザリごとに 1 通のメールが届きます。同じアドバイザリについて 2 通目が届くことはありません。

影響するアドバイザリがないバージョンを実行すると、これらはすぐにすべて消えます。アップグレードの方法は [アップグレード](/docs/installation/upgrading) を参照してください。

## 確認をオフにする

インターネットに接続できないネットワークの場合や、サーバーから GitHub に接続させたくない場合は、確認をオフにしてください。オフにすると、何も表示されず、メールも送信されません。

:::tabs
@tab Kubernetes
```yaml
updateCheck:
  disabled: true
```
@tab Docker Compose
```bash
DISABLE_UPDATE_CHECK=true
```
`config.env` に設定してから、`npm start` を実行します。
:::

代わりにネットワーク内のミラーと照合するには、確認の宛先をミラーに向けます。ミラーは GitHub と同じ形式で応答する必要があります。

| Helm の値 | Docker Compose の設定 | 既定値 |
| --- | --- | --- |
| `updateCheck.url` | `LATEST_RELEASE_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/releases/latest` |
| `updateCheck.securityAdvisoriesUrl` | `SECURITY_ADVISORIES_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/security-advisories` |

## GitHub に到達できない場合

インターネットに接続できないネットワークでは、リクエストの失敗は想定どおりのことであり、エラーではありません。ワーカーはそれをデバッグレベルでログに記録し、最後に読み取った内容を保持して、後で再試行します。管理者ダッシュボードには、アドバイザリを最後に読み取った日時と、直近の確認が失敗した理由が表示されます。理由は、GitHub のレート制限、GitHub への経路がない、タイムアウト、GitHub 以外からの応答のいずれかです。
