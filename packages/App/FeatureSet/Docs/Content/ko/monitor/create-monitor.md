# 모니터 만들기

모니터는 웹사이트, API, 호스트, Kubernetes 클러스터처럼 운영 중인 대상을 확인하고, 작동을 멈추면 알려 줍니다. **모니터 생성** 은 먼저 무엇을 모니터링할지, 다음으로 무엇을 확인할지, 마지막으로 얼마나 자주 확인할지를 묻습니다. 유형, 이름, 확인할 대상을 제외한 모든 항목은 대부분의 모니터에 맞는 기본값으로 시작합니다.

## 모니터 정보

**모니터** 로 이동해 **모니터 생성** 을 클릭합니다. 첫 질문은 **모니터 유형**, 즉 무엇을 모니터링할지입니다.

- 가장 많이 만드는 여섯 가지 유형이 먼저 나옵니다: **Website**, **API**, **Ping**, **포트**, **SSL Certificate**, 그리고 cron 작업과 webhook의 하트비트용 **Incoming Request** 입니다.
- **더 많은 모니터 유형** 은 나머지 모든 유형을 카테고리별로 보여 줍니다. 예를 들어 **인프라** (Kubernetes, Docker, Host) 와 **텔레메트리** (로그, 메트릭, 트레이스) 가 있습니다. 상태를 직접 정하는 모니터인 **Manual** 은 **Other** 아래에 있습니다.
- 또는 검색 상자에 입력하세요. `k8s`, `postgres`, `heartbeat`, `tls` 처럼 이미 쓰는 단어를 알아듣고, **Enter** 로 첫 번째 결과를 고릅니다.

고른 유형은 한 줄로 줄어듭니다. 다른 유형을 고르려면 **변경** 을 클릭하고, 고르는 도중 **Escape** 를 누르면 원래 유형이 유지됩니다.

그다음 **이름** 을 입력합니다. 이름은 경고와 인시던트 제목에 쓰입니다. **설명** 과 **레이블** 은 선택 사항이며 **추가 필드** 안에 있습니다.

**Manual** 모니터는 더 필요한 것이 없으므로 이 단계에 **모니터 생성** 이 있습니다.

## 기준

이 단계는 무엇을 확인할지부터 시작합니다. 웹사이트라면 그 URL이며, 입력란에 예시가 보입니다. 다른 유형은 호스트, 쿼리, 클러스터, 로그 필터 등을 묻습니다. **모니터 테스트** 는 저장하기 전에 확인을 한 번 실행합니다.

그 아래의 **모니터 기준** 은 모니터가 상태를 바꾸거나, 인시던트를 선언하거나, 경고를 만드는 때를 정합니다. 새 모니터는 대부분의 모니터에 맞는 기준으로 시작하며, 각 기준은 무엇을 확인하고 무엇을 하는지 말해 주는 한 줄로 접혀 있습니다. 예를 들어 새 웹사이트 모니터는 사이트가 응답하지 않거나 오류 상태 코드로 응답하면 오프라인으로 표시되고 인시던트를 선언합니다. 기준을 클릭하면 열어서 바꿀 수 있습니다. **기준 추가** 는 바로 입력할 수 있도록 열린 기준을 하나 추가합니다.

이 단계에서는 **다음** 을 클릭하기 전까지 아무것도 누락으로 표시되지 않습니다.

## 프로브 및 간격

프로브가 확인하는 모니터는 이 단계로 끝납니다: Website, API, Ping, IP, Port, SSL Certificate, DNS, DNSSEC, Domain, SQL Query, Database Health, Synthetic Monitor, Custom JavaScript Code, External Status Page. **프로브** 는 확인을 실행하는 머신이며, 프로젝트의 기본 프로브가 미리 선택되어 있습니다. **모니터링 간격** 은 **5분마다** 로 시작합니다. **모니터 생성** 을 클릭합니다.

나머지 유형은 모두 **기준** 단계에서 만듭니다.

## 템플릿이나 링크에서 시작하기

모니터 템플릿, 그리고 OneUptime의 다른 곳(메트릭 차트, 네트워크 장치, 탐지 규칙)에 있는 모니터 생성 링크는 유형이 이미 선택되고 나머지가 채워진 상태로 **모니터 생성** 을 엽니다. 다른 유형을 고르려면 **변경** 을 클릭합니다. 템플릿 자체의 양식도 같은 유형 선택기를 씁니다: [모니터 템플릿](/docs/monitor/monitor-templates) 을 참고하세요.
