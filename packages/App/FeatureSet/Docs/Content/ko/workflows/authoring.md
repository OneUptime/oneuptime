# 워크플로 작성

워크플로를 만들려면 **워크플로**를 열고 **워크플로 생성**을 클릭하세요. **Create a workflow** 마법사가 순서대로 안내합니다. 먼저 **Start from**, 그다음 **이름**, 마지막으로 **구성** 단계인데, 이 단계는 고른 템플릿이 자체 설정을 요구할 때만 나타납니다.

**Start from**에서 어떻게 시작할지 고릅니다.

- 검색 상자 옆의 **처음부터 시작**을 누르면 빈 캔버스로 시작합니다.
- 템플릿을 고르면 바로 동작하는 워크플로를 받아 원하는 대로 바꿀 수 있습니다. 이 단계는 **추천** 템플릿 몇 가지를 보여 주며 열립니다. 나머지는 **인시던트**, **모니터**, **Jira** 같은 카테고리에 템플릿 수와 함께 들어 있고, **모든 템플릿**에는 전부가 나옵니다. 검색은 모든 템플릿을 살펴봅니다. 입력한 단어가 모두 일치해야 하며, 각 카테고리에는 일치한 템플릿 수가 표시됩니다.

템플릿을 클릭하면 고르기 전에 무엇을 하는지 볼 수 있습니다. 트리거, 이루는 단계, 그리고 물어볼 설정입니다. **이 템플릿 사용**을 누르면 **이름**으로 넘어가며, **Enter**나 더블클릭도 같습니다. 화살표 키로 목록을 이동하고, `/`를 누르면 검색 상자로 돌아갑니다.

만들고 나면 왼쪽 메뉴에서 **빌더**를 여세요. 워크플로를 설계하는 캔버스가 바로 여기입니다.

## 캔버스

처음부터 만든 워크플로는 **Choose what starts this workflow**라고 적힌 점선 블록 하나로 시작합니다. 이 블록이 출발점이니, 클릭해서 트리거를 고르세요. 템플릿으로 만든 워크플로는 블록이 이미 배치된 채로 열립니다.

모든 워크플로에는 맨 위에 **트리거**가 정확히 하나 있습니다. 나머지는 전부 무언가를 수행하는 **구성 요소**입니다. 트리거를 하나 더 추가하면 기존 트리거를 대체하고, 마지막 트리거를 지우면 점선 자리 표시자가 다시 나타납니다.

블록 추가하기:

- **트리거** — 점선 자리 표시자 블록을 클릭합니다. **Add Trigger** 패널이 열립니다.
- **그 밖의 모든 것** — 캔버스 위쪽 도구 모음에서 **구성 요소 추가**를 클릭합니다. 같은 패널이 **Add Component** 제목으로 열립니다.

두 패널 모두 대부분의 워크플로우가 쓰는 블록이 **Popular** 아래에 놓인 채로 열리고, 그 뒤에 나머지 기본 제공 블록이 이어집니다. **OneUptime resources** 아래에서 **Incident** 같은 리소스를 클릭하면 그것으로 할 수 있는 일이 나옵니다. **Browse all resources**에는 모든 리소스가 있습니다. 검색할 수도 있습니다. `create incident`처럼 몇 단어를 입력하면 가장 가까운 결과가 맨 위에 옵니다. `/`를 누르면 검색창으로 이동하고, 화살표 키로 결과 사이를 이동하며, **Enter**로 강조 표시된 블록을 추가합니다. 블록을 클릭하면 바로 추가됩니다.

새 블록은 캔버스에서 가장 아래에 있는 블록 밑에 놓이고, 새 트리거는 맨 위의 기존 트리거 자리에 들어갑니다. 새 블록은 선택된 상태가 되며, 보이지 않는 곳에 놓이면 캔버스가 그 블록이 보일 만큼만 스크롤됩니다. 설정은 저절로 열리지 않습니다. 설정할 준비가 되면 블록을 클릭하세요. 필수 설정이 비어 있는 동안에는 블록에 **Click to set up**이 표시됩니다. 블록은 원하는 곳으로 끌어다 옮길 수 있고, 캔버스는 이동하는 동안 격자에 맞춰 정렬해 줍니다. 블록 위치는 저장되므로 다음 사람도 여러분이 남긴 그대로의 배치를 보게 됩니다.

변경 사항은 자동으로 저장됩니다. 도구 모음의 알약 표시가 이를 알려 줍니다. 저장이 진행 중이면 **Saving…**, 끝나면 **저장됨**, 실패하면 **저장할 수 없습니다**가 나타납니다. 저장 버튼도, 별도의 게시 단계도 없습니다.

## 블록에 있는 것들

| 항목                         | 하는 일                                                                                                                                                                                                |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier** (**ID** 아래) | 블록에 표시되는 짧은 id로, `log-1` 같은 형태입니다. 다른 블록이 이 블록을 가리킬 때 쓰는 이름이므로, 이름을 바꾸면 이 블록을 가리키던 `{{local.components.…}}` 참조가 모두 깨집니다. 블록의 제목은 구성 요소 자체의 이름이라 바꿀 수 없습니다. |
| **설정**                  | 블록이 제 일을 하는 데 필요한 것 — URL, Slack 채널, 메시지 본문 등입니다. 선택 항목에는 **(Optional)** 표시가 붙고, 나머지는 모두 필수입니다. 자주 쓰지 않는 설정은 **고급** 영역을 펼치면 나옵니다. |
| **Input**                     | 위쪽 가장자리에 있는 점으로, 앞선 블록에서 오는 선이 여기로 들어옵니다. 트리거에는 없습니다 — 트리거보다 먼저 실행되는 것은 없기 때문입니다.                                                                                       |
| **Outputs**                   | 아래쪽 가장자리를 따라 있는 점들로, 바로 위에 이름이 붙어 있으며 다음 블록으로 선이 나갑니다. 많은 블록이 **Success**와 **Error** 출력을 따로 두어 두 경우를 모두 처리할 수 있게 합니다.                  |

## 블록 연결하기

한 블록 아래쪽의 점에서 다음 블록 위쪽의 점까지 끌어당기세요. 여러분이 그은 선이 다음에 무엇이 실행될지 결정합니다.

- **Success**에서 연결하면 앞선 블록이 성공했을 때만 다음 블록이 실행됩니다.
- **Error**에서 연결하면 앞선 블록이 실패했을 때만 다음 블록이 실행됩니다.
- 출력을 아무 데도 연결하지 않으면 그 경로는 거기서 끝납니다.

출력 하나를 여러 블록에 연결할 수도 있습니다. 모두 실행되지만, 병렬이 아니라 하나의 대기열에서 차례대로 실행됩니다. 분기 사이의 순서에 기대지 말고, 시간상 겹쳐 실행되리라 가정하지도 마세요. 각 블록은 한 번의 실행에서 최대 한 번만 동작하므로, 앞선 블록으로 되돌아가는 고리를 만들어도 그 블록이 두 번 실행되지는 않습니다.

## 블록 설정하기

블록을 클릭하면(또는 **Tab**으로 블록에 이동해 **Enter**를 누르면) 대화 상자에 설정이 열립니다. 설정마다 알맞은 입력 방식이 준비되어 있습니다 — 텍스트 필드, 드롭다운, 코드 편집기, 토글 등입니다. 값을 채우고 **저장**을 클릭하세요.

같은 대화 상자에서 다음도 찾을 수 있습니다.

- **삭제** — 이 블록을 제거합니다.
- **Run just this step** — 워크플로의 나머지 없이 이 블록 하나만 실행합니다. 다른 단계에서 읽어 왔을 값은 비어 있는 상태로 들어오지만, 이 블록이 보내거나 쓰거나 지우는 일은 실제로 일어납니다.
- **문서**, **Inputs**, **Outputs**, **Returns** — 이 블록이 무엇을 기대하고 무엇을 만들어 내는지 알려 주는 참고 카드입니다.

대부분의 텍스트 필드는 변수를 받습니다 — 데이터가 블록에서 블록으로 흐르는 방식이 바로 이것입니다. 문법을 손으로 입력하기보다 편집기의 값 선택기를 사용하세요. 고른 블록과 필드로 올바른 참조를 만들어 줍니다. [워크플로우 변수](/docs/workflows/variables)를 참고하세요.

## 만드는 동안 이루어지는 검사

빌더는 변경이 있을 때마다 그래프 전체를 검사하고, 결과를 도구 모음의 알약 표시로 알려 줍니다. 이를 클릭하면 **Problems with this workflow**가 열려 문제 목록을 보여 주고, 원인이 된 블록으로 바로 이동시켜 줍니다. 캔버스에서는 필수 설정이 아직 비어 있는 블록에 **Click to set up**이 표시되고, 그 밖의 문제가 있는 블록에는 모서리에 배지가 붙습니다. 오류는 빨간색, 경고는 주황색입니다. 배지에 마우스를 올리면 무엇이 잘못됐는지 읽을 수 있습니다.

실행이 잘못되기 전까지는 눈에 띄지 않는 실수들이 여기서 잡힙니다. 트리거 없음, 같은 id를 쓰는 두 블록, id 안의 점, 아무것도 연결되지 않은 블록, 비어 있는 필수 설정, 잘못된 형식의 JSON, `{{ }}` 안의 공백, 존재하지 않는 단계나 반환값에 대한 참조 등입니다.

한 가지는 검사할 수 없습니다. 변수 이름이 실제로 있는지 여부입니다. 이름이 바뀐 변수는 실행 로그에서만 드러납니다.

## 첫 워크플로 만들기

캔버스를 가장 빠르게 익히는 방법입니다.

1. 점선 자리 표시자 블록을 클릭한 다음 **Add Trigger** 패널에서 **Manual**을 클릭합니다.
2. **구성 요소 추가**를 클릭한 다음 **Popular** 아래의 **Log**를 클릭합니다. 새 블록은 트리거 아래에 놓입니다. 트리거의 **Execute** 점을 Log 블록의 입력 점까지 연결합니다.
3. **Click to set up**이 표시된 Log 블록을 클릭하고 **값**을 `Hello from {{local.components.manual-1.returnValues.value.name}}`로 설정합니다. `manual-1`은 트리거 블록에 표시된 트리거의 **Identifier**이니 일치하는지 확인하세요.
4. 빌더 상단에서 **활성화됨**을 켭니다. 비활성화된 워크플로는 손으로도 실행할 수 없습니다. 이 단계를 건너뛰면 **워크플로 실행**이 먼저 켤지 묻습니다.
5. 다시 **빌더**로 돌아와 **워크플로 실행**을 클릭하고, **JSON** 필드에 `{ "name": "Ada" }`를 넣은 뒤 **Run Workflow Manually**를 클릭하고 **Run**으로 확인합니다.
6. **Workflow Run** 패널이 저절로 열리며 실행 과정을 따라갑니다. 로그에는 `Value:`에 이어 `Hello from Ada`가 나타납니다.

추가하고, 연결하고, 설정하고, 실행하고, 로그를 읽는 이 흐름이 앞으로 모든 워크플로를 만드는 방식입니다.

## 워크플로 켜기

새 워크플로는 비활성화 상태로 시작하고, 복제하거나 가져온 워크플로도 마찬가지입니다. 워크플로가 꺼져 있는 동안에는 빌더가 캔버스 위에 이를 알리고 **워크플로 켜기** 버튼을 보여 줍니다.

**활성화됨** 스위치는 **빌더** 상단의 **구성 요소 추가**와 **워크플로 실행** 옆에 있습니다. 워크플로의 **개요** 페이지에도 있습니다. **워크플로 세부 정보** 카드에서 **워크플로 편집**을 클릭하세요. 이 카드는 현재 상태를 초록색 **활성화됨** 또는 빨간색 **비활성화** 알약 표시로 보여 줍니다. 워크플로를 편집할 수 있는 사람만 켜거나 끌 수 있고, 다른 사람에게는 스위치가 흐리게 보입니다.

비활성화된 워크플로는 아예 실행되지 않습니다. 트리거가 무시되고, **워크플로 실행**과 **Run just this step**도 마찬가지입니다. 꺼져 있는 동안 워크플로나 그 블록을 실행하면 빌더가 대신 **이 워크플로를 켜시겠습니까?**라고 묻습니다. **켜고 실행**(또는 **켜고 단계 실행**)을 누르면 워크플로가 켜진 다음, 요청한 실행이 입력한 값 그대로 진행됩니다. 그러니 순서는 이렇습니다. 만들고, **워크플로 실행**으로 시험해 보고, 실행 로그를 읽고, 트리거가 발생해도 될 만큼 준비되지 않았다면 **활성화됨**을 다시 끄세요. 전체를 실행하지 않고 블록 하나만 시험하려면 그 블록의 설정에서 **Run just this step**을 사용하면 됩니다.

그 밖에 비활성화된 워크플로를 시작하려는 모든 시도도 같은 안내와 함께 거부됩니다. 웹훅 URL을 호출하면 HTTP 400과 함께 "This workflow is turned off, so it can't run. Turn it on with the Enabled switch at the top of its Builder, then try again."가 반환됩니다. 이 워크플로를 호출하는 **Execute Workflow** 블록은 **Error** 경로로 진행하고, 오류에는 호출한 워크플로의 이름이 담깁니다.

워크플로를 지우지 않고 잠시 멈추려면 **활성화됨**을 끄세요. 새 실행은 시작되지 않습니다. 이미 진행 중이던 실행은 끝까지 진행되지만, **Sleep** 블록에서 대기 중이던 실행은 깨어날 때 취소되고 오류로 기록됩니다.

## 정리하기

- 블록을 끌어다 옮길 수 있습니다. 배치는 저장됩니다.
- 선을 지우려면 선의 양쪽 끝 중 하나를 점에서 떼어 내 빈 캔버스에 놓으세요.
- 블록을 지우려면 블록을 클릭하고 설정 대화 상자 아래쪽의 **삭제**를 사용하세요. 블록이나 선을 선택하고 Backspace를 눌러도 지워집니다.
- 블록 하나만 복제하는 방법은 없습니다. 워크플로의 **설정** 페이지에 있는 **Duplicate Workflow**는 워크플로 전체를 복사하며, 복사본은 비활성화 상태로 만들어집니다.
- 블록을 위에서 아래로 쌓아 실행되는 방향대로 읽히게 하세요. 입력은 위쪽 가장자리에, 출력은 아래쪽 가장자리에 있으므로 흐름이 자연스럽게 아래로 이어집니다.
