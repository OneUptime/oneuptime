# 트리거

트리거는 워크플로의 첫 번째 블록으로, 워크플로가 언제 실행될지를 정합니다. 모든 워크플로에는 트리거가 정확히 하나 있습니다. 네 가지 중에서 고르면 됩니다.

## Manual

**빌더** 페이지에서 **워크플로 실행**을 클릭하고, 트리거의 필드를 채운 다음, **Run Workflow Manually**로 확인하면 워크플로가 필요할 때 실행됩니다. Manual 트리거는 JSON 페이로드를 받으며, 워크플로의 나머지 부분이 이를 읽을 수 있습니다.

이런 경우에 좋습니다: "이 키를 교체" 또는 "테스트 알림 보내기"처럼 버튼 하나로 끝내고 싶은 자동화.

**출력**: 붙여 넣은 JSON, 아무것도 넣지 않았다면 빈 객체.

## Schedule

cron 표현식을 사용해 반복 일정에 맞춰 워크플로를 실행합니다.

이런 경우에 좋습니다: 야간 정리 작업, 시간별 동기화, 주간 보고서.

**설정**: cron 표현식. 자주 쓰이는 몇 가지는 다음과 같습니다.

- `0 * * * *` — 매시 정각.
- `*/5 * * * *` — 5분마다.
- `0 9 * * 1` — 매주 월요일 오전 9시.

시스템이 잠시 사용할 수 없는 상태였다면 복구되는 즉시 해당 실행이 처리되므로, 짧은 장애로 놓친 시각은 걱정하지 않아도 됩니다.

## Webhook

OneUptime이 고유 URL을 만들어 줍니다. 그 URL을 호출하는 모든 것이 워크플로를 시작시킵니다. 요청의 헤더, 쿼리 매개변수, 본문이 함께 전달됩니다.

이런 경우에 좋습니다: 다른 도구에서 OneUptime으로 데이터를 받아 오기 — CI/CD 콜백, 다른 모니터링 도구의 알림, CRM의 신규 가입 등.

**출력**:

- **Request Headers** — 수신 요청의 모든 헤더.
- **Request Query Params** — 파싱된 쿼리 문자열.
- **Request Body** — 파싱된 본문(JSON이 아니면 원문 텍스트).

이 URL은 `GET`과 `POST`를 모두 받습니다. 호출한 쪽은 곧바로 접수 응답을 받고, 워크플로 자체는 백그라운드에서 실행됩니다.

이 URL은 비밀번호처럼 다루세요. 이를 가진 사람은 누구든 여러분의 워크플로를 시작시킬 수 있습니다.

## OneUptime 이벤트 트리거

OneUptime 안의 거의 모든 것 — 모니터, 인시던트, 경고, 예정된 유지 관리, 상태 페이지, 온콜 정책, 팀 — 이 워크플로를 트리거할 수 있습니다. 각각은 세 가지 이벤트를 제공합니다.

- **On Create** — 새로 추가될 때 발생합니다.
- **On Update** — 변경될 때 발생합니다.
- **On Delete** — 삭제될 때 발생합니다.

반복문으로 무언가를 계속 확인하지 않고도 "OneUptime에서 X가 일어나면 Y를 한다"를 만드는 방법이 바로 이것입니다.

레코드 전체가 다음 블록으로 전달됩니다. 예를 들어 **Incident → On Create** 트리거는 새 인시던트를 넘겨주므로, 다음 블록이 그 제목, 설명, 심각도를 비롯한 어떤 필드든 읽을 수 있습니다.

### 팀이 가장 많이 사용하는 이벤트

- **Incident** — 인시던트가 열리거나, 변경되거나(확인, 해결), 삭제될 때 반응합니다.
- **Alert** — 경고에 대해 동일한 세 가지를 제공합니다.
- **Monitor** — 모니터가 추가되거나, 수정되거나, 제거될 때 반응합니다.
- **Scheduled Maintenance** — 유지 관리 시간대가 예약되면 자동으로 알립니다.
- **Status Page Subscriber** — 상태 페이지를 구독한 사람을 환영합니다.
- **On-Call Duty Policy** — 일정 변경을 다른 근무표 시스템과 동기화합니다.

원하는 것을 찾으려면 **Add Trigger** 패널에서 이름으로 검색하세요.

## 어떤 트리거를 사용해야 할까요?

| 하고 싶은 일…                     | 선택                |
| ----------------------------------- | ------------------- |
| 버튼을 눌러 워크플로 실행           | **Manual**          |
| 반복 일정에 맞춰 실행               | **Schedule**        |
| 다른 시스템이 데이터를 밀어 넣게 하기 | **Webhook**         |
| OneUptime 내부의 일에 반응          | **OneUptime 이벤트** |

워크플로에는 트리거가 하나만 있을 수 있습니다. 같은 자동화를 시작하는 방법이 두 가지 필요하다면, 공통 로직을 워크플로 하나에 만들어 두고 **Execute Workflow** 구성 요소를 사용해 얇은 "래퍼" 워크플로 두 개에서 호출하세요.
