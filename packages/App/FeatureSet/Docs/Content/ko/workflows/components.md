# 구성 요소

구성 요소는 트리거 뒤에 붙여 나가는 조립 블록입니다. 하나하나가 한 가지 일 — 메시지 보내기, API 호출하기, 조건 확인하기 — 을 하고, 그다음에 오는 것과 연결됩니다.

이 페이지는 그 목록입니다. 캔버스에서 추가하고 연결하는 방법은 [워크플로우 작성](/docs/workflows/authoring)을 보세요.

## API

임의의 URL로 HTTP 요청을 보냅니다.

**설정**:

- **Method** — `GET`, `POST`, `PUT`, `PATCH`, `DELETE` 중 하나.
- **URL** — 호출할 주소.
- **Headers** — 함께 보낼 헤더.
- **Body** — `POST` / `PUT` / `PATCH`의 요청 본문.

**Outputs**:

- **Success** — 호출이 성공했을 때(2xx 응답) 발생합니다. 상태 코드, 헤더, 본문을 함께 넘깁니다.
- **Error** — 네트워크 실패나 2xx가 아닌 응답에서 발생합니다. 오류 메시지를 함께 넘깁니다.

이럴 때 사용하세요: 모든 외부 API, 사내 관리용 엔드포인트, 전용 구성 요소가 없는 모든 통합.

## AI

### Generate Text with AI

프롬프트와 선택적인 JSON 컨텍스트로 텍스트 응답 하나를 생성합니다. 이 구성 요소는 프로젝트에 설정된 기본 LLM 제공자를 사용하며, 사용할 수 있는 설치 전역 제공자가 있으면 그쪽으로 넘어갑니다. 제공자 자격 증명과 엔드포인트는 중앙에서 설정하며, 워크플로 인자가 아닙니다.

**설정**:

- **System Instructions** — 모델의 역할, 어조, 제약을 안내하는 선택 항목.
- **Prompt** — 필수 항목인 작업 지시. 워크플로 변수와 앞선 구성 요소의 출력을 넣을 수 있습니다.
- **Context** — 요청에 의도적으로 함께 넣는 선택적 JSON. 명시적인 메시지 종료 신뢰 표시 뒤에 덧붙여지며, 이후 메시지 전체에서 신뢰할 수 없는 데이터로 취급됩니다.
- **Temperature** — `0`에서 `1` 사이의 변동 폭. 예측 가능한 자동화를 위해 기본값은 `0.2`입니다.
- **Maximum Output Tokens** — `1`에서 `4096` 사이. 기본값은 `1024`입니다.

System Instructions, Prompt, 직렬화된 Context는 합쳐서 50,000자로 제한됩니다. 제공자 요청은 최대 60초까지 진행되며 한 번만 시도합니다. 프로젝트당 워크플로 AI 요청은 동시에 세 개까지 실행할 수 있습니다.

**Outputs**:

- **Response** — 생성된 텍스트.
- **Provider**와 **Model** — 호출에 사용된 설정.
- **Total Tokens**와 **Completion Tokens** — 제공자가 보고한 사용량.
- **LLM Log ID** — 이 호출에 대한 과금 대상 AI 로그 항목.
- **Error** — 검증, 접근, 제공자, 예산, 결제, 타임아웃 오류가 있을 경우 그 내용.

응답을 사용해야 하는 구성 요소에는 **Success**를 연결하세요. **Error**는 대비 경로나 알림, 로그 경로에 분명하게 연결하세요. 이 구성 요소는 도구 정의나 제공자 고유 기능 필드 없이 모델 요청을 한 번만 보냅니다. 스스로 OneUptime을 조회하거나, API를 호출하거나, 프로젝트 데이터를 바꿀 수 없습니다. OneUptime이 고정으로 넣는 구성 요소 안전 지침을 빼면, 여러분이 설정한 System Instructions, Prompt, Context만이 해당 필드의 워크플로 변수가 해석된 뒤 제공자에게 전달됩니다. 모델은 제공자가 관리하는 고유 기능을 가질 수 있으므로, 설정된 제공자와 모델은 여전히 신뢰 경계입니다.

모델 출력은 신뢰할 수 없는 텍스트입니다. 고객에게 나가는 커뮤니케이션에 쓰기 전에 반드시 검토하고, 워크플로의 파괴적인 동작을 자유 형식 AI 텍스트만으로 승인하지 마세요. 제공자, 외부 전송, 로깅, 비용에 관한 내용은 [워크플로우 설정 및 보안](/docs/workflows/configuration)을 보세요.

## Webhook (outbound)

"보내고 잊어버리는" 경우를 위한 API 구성 요소의 간단한 버전입니다. JSON 본문을 URL로 POST합니다.

응답을 읽어야 한다면 **API**를, 알림만 보내고 넘어가면 된다면 **Webhook**을 사용하세요.

## Slack

Slack 채널에 메시지를 게시합니다.

**설정**:

- **채널** — 채널 이름. 봇이 이미 그 채널에 들어가 있어야 합니다.
- **메시지** — 보낼 텍스트. Slack 서식을 지원합니다.

먼저 **프로젝트 설정 → 워크스페이스 → Slack**에서 Slack을 프로젝트에 연결하세요. [Slack 워크스페이스 연결](/docs/workspace-connections/slack)을 보세요.

## Microsoft Teams

Microsoft Teams 채널에 메시지를 게시합니다.

**설정**:

- **Team and channel** — 게시할 위치.
- **메시지** — 보낼 텍스트.

설정 방법은 [Microsoft Teams 워크스페이스 연결](/docs/workspace-connections/microsoft-teams)을 보세요.

## Discord

수신 웹훅 URL을 통해 Discord 채널에 메시지를 게시합니다.

## Telegram

봇 토큰과 채팅 ID로 Telegram 채팅에 메시지를 보냅니다.

## Email

OneUptime을 통해 이메일을 보냅니다.

**설정**:

- **받는 사람** — 수신자의 이메일 주소.
- **제목** — 제목 줄.
- **Body** — Markdown 또는 HTML로 작성한 메시지.

이메일은 프로젝트에 설정된 발신자 주소로 나갑니다 — [SMTP](/docs/emails/smtp)를 보세요.

## Custom Code

다른 블록으로는 할 수 없는 일이 필요할 때 짧은 JavaScript를 실행합니다.

**설정**:

- **코드** — 여러분의 JavaScript. 마지막 값(또는 async 함수에서 return한 값)이 블록의 출력이 됩니다.
- **Arguments** — 넘겨줄 수 있는 이름 붙은 값들.

**Outputs**: 성공(여러분이 반환한 값)과 오류(발생한 예외).

이럴 때 사용하세요: 두 시스템 사이에서 데이터 모양 바꾸기, 간단한 계산하기, 전용 블록을 둘 만큼은 아닌 모든 일. 더 무거운 스크립트가 필요하다면 [Runbook](/docs/runbooks/index)을 사용하세요.

## JSON

텍스트와 JSON 사이를 변환합니다.

- **JSON → Text** — JSON 객체를 문자열로 만듭니다. 다음 블록이 텍스트를 기대할 때 유용합니다.
- **Text → JSON** — 문자열을 JSON 객체로 파싱합니다. 텍스트로 도착한 값에서 필드를 읽어야 할 때 유용합니다.

## Conditions

비교 결과에 따라 분기합니다. **Add Component** 패널에서 이 블록의 이름은 **If / Else**이며 조건 범주에 있습니다.

**설정**:

- **Left value** — 보통 앞선 블록에서 온 값.
- **Operator** — `==`, `!=`, `>`, `>=`, `<`, `<=`, `contains`, `starts with`, `ends with`.
- **Right value** — 비교 대상.

**Outputs**: **예**와 **아니오**. 원하는 분기에 다음 블록을 연결하세요.

## Delay

계속 진행하기 전에 정해진 시간만큼 워크플로를 멈춥니다. 다른 시스템이 따라올 시간을 조금 줘야 할 때 유용합니다.

## Log

실행 로그에 한 줄을 씁니다. 외부에 미치는 영향은 없고, 워크플로 로그에 표시되어 여러분이 읽을 수 있을 뿐입니다. 디버깅에 요긴합니다.

## Execute Workflow

이 워크플로에서 다른 워크플로를 호출합니다. 호출된 워크플로는 독립적으로 실행되며, 이쪽 워크플로는 그것이 끝나기를 기다리지 않고 계속 진행합니다.

공통 로직을 공유할 때 사용하세요. "인시던트 채널에 게시" 워크플로를 한 번 만들어 두고, 그 채널에 알려야 하는 다른 워크플로에서 호출하면 됩니다.

워크플로끼리 서로 계속 호출하는 고리에 빠지지 않도록 안전 한도가 있습니다. [워크플로우 설정 및 보안](/docs/workflows/configuration)을 보세요.

## OneUptime 데이터 구성 요소

OneUptime의 모든 레코드 종류(모니터, 인시던트, 경고, 상태 페이지, 온콜 정책 등 다수)에 대해 **Add Component** 패널에는 다음 구성 요소들이 준비되어 있습니다 — 유형 이름으로 검색하세요. 각 제목은 레코드 유형에서 자동으로 만들어지므로, Monitor 계열은 이렇게 나옵니다.

- **Find One Monitor** — 쿼리에 맞는 레코드 하나를 읽습니다.
- **Find Many Monitors** — 쿼리에 맞는 레코드 목록을 읽습니다.
- **Create One Monitor** — JSON 객체로 레코드 하나를 추가합니다.
- **Create Many Monitors** — JSON 배열로 레코드 여러 개를 추가합니다.
- **Update One Monitor** — 일치하는 레코드 하나에 쓰기 페이로드를 적용합니다.
- **Update Many Monitors** — 일치하는 레코드들에 Limit까지 쓰기 페이로드를 적용합니다.
- **Delete One Monitor** — 일치하는 레코드 하나를 삭제합니다.
- **Delete Many Monitors** — 일치하는 레코드를 Limit까지 삭제합니다.

같은 계열에서 트리거도 세 개 — **On Create Monitor**, **On Update Monitor**, **On Delete Monitor** — 나옵니다. [워크플로우 트리거](/docs/workflows/triggers)를 보세요.

각 유형은 자신의 모델이 허용하는 구성 요소만 제공합니다. 읽기 전용 유형에는 Find 구성 요소 두 개뿐이니, 패널에서 **Delete One Monitor**를 찾을 수 없다면 그 유형이 삭제를 허용하지 않는 것입니다.

워크플로가 OneUptime 데이터를 읽고 바꾸는 방법이 바로 이것입니다. 예를 들어 CI 도구에서 온 웹훅이 **Create One Incident**로 실패 내용을 담은 인시던트를 열 수 있습니다.

## 레코드 다루기

데이터 구성 요소의 모든 필드는 레코드 자체의 **컬럼** 이름을 기준으로 합니다 — 대시보드 화면의 라벨이 아니라 API가 쓰는 그 이름입니다. ID 컬럼은 `_id`입니다. 컬럼 이름을 입력하는 곳이라면 어디서든 `id` 표기도 별칭으로 받아 주지만, 레코드가 돌려주는 것은 `_id`이므로 읽을 때는 이쪽을 보세요.

```json
{ "_id": "00000000-0000-0000-0000-000000000000" }
```

**Query**는 구성 요소가 어떤 레코드를 대상으로 할지 결정합니다. 키는 컬럼이고, 값은 일치시킬 내용입니다.

```json
{ "monitorType": "Website", "isEnabled": true }
```

쿼리는 언제나 워크플로가 실행되는 프로젝트로 범위가 한정됩니다. 다른 프로젝트의 레코드에는 닿을 수 없고, 프로젝트를 직접 쿼리에 넣을 필요도 없습니다.

Create One의 **JSON Object**, Create Many의 **JSON Array**, Update 구성 요소들의 **Data (JSON Object)**는 쓸 필드를 같은 방식으로 담습니다.

```json
{ "name": "Checkout API", "monitorType": "Website" }
```

컬럼이 아닌 키는 거부되지 않고 무시됩니다 — 무시된 키는 실행 로그에 적히니 필드가 반영되지 않으면 그곳을 확인하세요. Find 구성 요소와 트리거에 있는 **Select Fields**는 같은 컬럼 키에 `true` 값을 씁니다: `{"_id": true, "name": true}`.

**건너뛰기**와 **Limit**은 Find Many, Update Many, Delete Many에 있는 숫자 필드 두 개입니다 — `Skip: 0`에 `Limit: 100`이면 일치하는 것 중 처음 백 개를 가져옵니다. Limit의 기본값은 `10`이고, Update Many와 Delete Many에서는 몇 개가 돌아오는지가 아니라 실제로 몇 개가 기록되는지를 제한합니다. 그러니 `Items Deleted: 10`은 열 개가 일치했다는 뜻이 아니라 열 개가 삭제됐다는 뜻입니다. 열 개보다 많이 바꿀 생각이라면 Limit을 올리세요.

**Success**와 **Error**는 쿼리가 무엇을 찾았는지가 아니라 쿼리가 실행됐는지를 알려 줍니다. 아무것도 일치하지 않은 쿼리는 `0`을 반환하고도 Success로 빠져나갑니다 — 그건 실패가 아닙니다. 일치한 것이 있는지에 따라 분기하려면 반환된 개수를 **If / Else** 블록에서 읽으세요.

## 어떤 구성 요소를 사용해야 할까요?

간단한 원칙 몇 가지입니다.

- 하려는 일에 전용 블록(Slack, Email, OneUptime 레코드)이 있다면 그것을 쓰세요 — 오류 처리가 더 낫고 로그도 더 명확합니다.
- 그 밖의 외부 API에는 **API**를 쓰세요.
- 명시적으로 고른 워크플로 데이터를 요약하거나 분류하거나 문장으로 다듬으려면 **Generate Text with AI**를 쓰세요.
- 블록 사이에서 데이터 모양을 바꾸려면 **Custom Code**나 **JSON**을 쓰세요.
- 값에 따라 다른 동작을 하려면 **Conditions**를 쓰세요.
