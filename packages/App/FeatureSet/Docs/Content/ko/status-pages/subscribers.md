# 구독자 및 공지

상태 페이지는 사람들이 찾아가는 곳입니다. 구독자는 굳이 찾아가고 싶지 않은 사람들이죠 — 이메일 주소나 전화번호, Slack 웹훅, HTTP 엔드포인트를 한 번 남겨 두면 그다음부터는 업데이트가 그들에게 찾아갑니다.

공지는 같은 일의 나머지 절반입니다. 결제가 500을 반환한다는 사실은 모니터가 방문자에게 알려 줄 수 있습니다. 하지만 토요일에 데이터베이스를 이전한다는 것, 서드파티 공급자가 오늘 상태가 좋지 않다는 것, 어제 읽은 그 인시던트가 완전히 마무리되었다는 것은 어떤 모니터도 알려 주지 못합니다. 공지는 점검이 볼 수 없는 모든 것을 위한 자유 서식 채널이며, 구독자 목록 전체로 똑같이 퍼져 나갑니다.

이 페이지는 둘 다 다룹니다 — 다섯 가지 구독 채널과 방문자가 가입하는 방법, 구독자가 무엇을 받아 볼지 고르는 방식, 이중 옵트인과 구독 취소 흐름, 그리고 공지를 작성하고 예약하고 템플릿으로 만드는 방법까지.

## 구독 채널

상태 페이지는 다섯 가지 채널을 지원하며, 각각 상태 페이지에 자체 토글이 있습니다. **상태 페이지 → 해당 페이지 → 구독자 → 구독자 설정**으로 이동하세요.

- **이메일 구독자 활성화** (`enableEmailSubscribers`) — 기본으로 켜져 있습니다. 나머지는 직접 켜기 전까지 모두 꺼진 상태입니다.
- **SMS 구독자 활성화** (`enableSmsSubscribers`) — 기본으로 꺼져 있습니다.
- **Slack 구독자 활성화** (`enableSlackSubscribers`) — 기본으로 꺼져 있습니다.
- **Microsoft Teams 구독자 활성화** (`enableMicrosoftTeamsSubscribers`) — 기본으로 꺼져 있습니다.
- **웹훅 구독자 활성화** (`enableWebhookSubscribers`) — 기본으로 꺼져 있습니다.

각 채널은 상태 페이지 사이드 메뉴의 **구독자** 아래에 자체 목록도 갖습니다. **이메일 구독자**, **SMS 구독자**, **Slack 구독자**, **MS Teams 구독자**, **Webhook 구독자**죠. 누가 가입했는지 살펴보거나, 직접 손으로 추가하거나, 특정 구독자에게 **노트**(`internalNote`) 항목을 남기는 곳이 바로 여기입니다.

**토글 하나만으로는 부족합니다.** 상태 페이지 내비게이션 바의 **구독** 항목은 **구독자 페이지 표시**(`showSubscriberPageOnStatusPage`)가 켜져 있고 *동시에* 채널이 최소 하나 활성화되어 있을 때만 나타납니다. **이메일 구독자 활성화**를 켜 두고 **구독자 페이지 표시**를 끈 채로 두면 방문자는 가입 양식에 닿을 방법이 없습니다.

같은 다섯 개 토글은 **고급 설정**의 **구독자 설정** 카드 안에 **구독자 페이지 표시**와 나란히 한 번 더 나타납니다. 아래에 있는 컬럼은 동일하므로 화면 하나를 골라 거기서만 작업하세요. 나머지 구독자 설정이 모여 있는 전용 **구독자 설정** 페이지를 쓰는 편이 낫습니다.

## 방문자가 구독 페이지에서 보는 것

**구독** 페이지에는 활성화된 채널마다 탭이 하나씩 있는 하위 메뉴가 있습니다 — **이메일**, **SMS**, **Slack**, **MS Teams**, **Webhooks** — 각각 `/subscribe/email`, `/subscribe/sms`, `/subscribe/slack`, `/subscribe/microsoft-teams`, `/subscribe/webhooks`에 대응합니다. 각 탭은 꼭 필요한 최소한만 묻습니다.

- **이메일** — 제목은 **이메일로 구독**, 필드는 **이메일 주소** 하나이며 플레이스홀더는 `subscriber@company.com`입니다.
- **SMS** — 제목은 **SMS로 구독**, 필드는 **전화번호** 하나이며 플레이스홀더는 `+11234567890`입니다.
- **Slack** — 제목은 **Slack으로 구독**이고, (검증에 쓰이는) **Slack 워크스페이스 이름**과 **Slack 수신 웹훅 URL**을 받으며 플레이스홀더는 `https://hooks.slack.com/services/...`입니다.
- **MS Teams** — 제목은 **Microsoft Teams로 구독**이고, **Microsoft Teams 워크스페이스 이름**과 **Microsoft Teams 수신 웹훅 URL**을 받으며 플레이스홀더는 `https://outlook.office.com/webhook/...`입니다.
- **Webhooks** — 제목은 **웹훅으로 구독**, 필드는 **웹훅 URL** 하나입니다. 상태 페이지 이벤트가 있을 때마다 이 주소로 JSON `POST` 요청이 전송됩니다.

제출 버튼에는 **구독**이라고 적혀 있고, 가입에 성공하면 *구독이 완료되었습니다.*라고 표시됩니다. 페이지에는 **새 구독** / **기존 구독 관리** 구분도 있어서, 이미 구독한 사람이 예전 이메일을 뒤지지 않고도 자기 설정으로 돌아올 수 있습니다.

## 구독자가 리소스와 이벤트 유형을 고르게 하기

기본적으로 구독자는 페이지에 있는 모든 것을 받습니다. **고급 구독자 설정** 카드의 토글 두 개가 이를 바꿉니다.

- **구독자가 리소스를 선택하도록 허용** (`allowSubscribersToChooseResources`) — 기본으로 꺼져 있습니다. 켜면 구독 양식에 **모든 리소스 구독** 토글이 생기고, 이를 해제하면 **구독할 리소스 선택**이 나타나 방문자가 리소스를 개별로 고를 수 있습니다.
- **구독자가 이벤트 유형을 선택하도록 허용** (`allowSubscribersToChooseEventTypes`) — 기본으로 꺼져 있습니다. 모양은 같습니다. **모든 이벤트 유형 구독** 토글이 있고, 해제하면 그 아래에 **구독할 이벤트 유형 선택**이 나타납니다.

이벤트 유형은 `Incident`, `Announcement`, `Scheduled Event`입니다.

선택 결과는 구독자 레코드에 **Is Subscribed to All Resources**(`isSubscribedToAllResources`, 기본값 true), **Is Subscribed to All Event Types**(`isSubscribedToAllEventTypes`, 기본값 true), **Subscribed to Resources**, **Subscribed to Event Types**로 저장됩니다.

이런 경우에 좋습니다: 여러 제품을 아우르는 페이지. API만 쓰는 고객은 마케팅 사이트가 흔들릴 때마다 알림을 받고 싶어 하지 않습니다. 아예 구독을 끊는 모습을 지켜보느니, 직접 목록을 좁히게 두세요.

같은 카드에는 **구독자 시간대**도 있습니다.

## 이메일 이중 옵트인

이메일 구독자는 언제나 확인 절차를 거칩니다. 이메일 주소로 구독자가 생성되고 이미 확인된 상태로 만들어진 것이 아니라면, **Is Subscription Confirmed**(`isSubscriptionConfirmed`)는 강제로 `false`가 되고 여섯 자리 **Subscription Confirmation Token**이 생성됩니다. 그러면 OneUptime이 `{statusPageUrl}/confirm-subscription/{statusPageSubscriberId}?verification-token={token}` 형태의 확인 링크를 이메일로 보냅니다. 방문자는 **구독 확인** 페이지에 도착하고, 절차가 끝나면 *구독이 확인되었습니다*를 보게 됩니다.

SMS, Slack, Microsoft Teams, 웹훅 구독자는 이 과정을 건너뜁니다 — 생성 시점에 `isSubscriptionConfirmed`가 이미 `true`로 설정됩니다.

**확인되지 않았다면 아무 소식도 가지 않습니다.** 알림을 위해 구독자를 가져오는 쿼리는 `isUnsubscribed: false`와 `isSubscriptionConfirmed: true`로 걸러냅니다. 링크를 한 번도 클릭하지 않은 이메일 주소는 **이메일 구독자** 목록에 남아 있으면서 아무것도 받지 못합니다. 분명히 구독했는데 소식이 없다고 하는 사람이 있다면 그 컬럼부터 확인하세요.

이메일 확인을 끄는 토글은 없습니다 — 상태 페이지를 통해 가입한 모든 사람에게 무조건 적용됩니다. 구독자별로 따로 있는 **Send You Have Subscribed Message**(`sendYouHaveSubscribedMessage`, 기본값 true) 컬럼은 구독이 확인된 뒤 나가는 "구독되었습니다" 이메일을 제어합니다.

## 구독 관리와 해지

구독자에게 가는 모든 이메일에는 `{statusPageUrl}/update-subscription/{statusPageSubscriberId}` 형태의 구독 취소 링크가 들어 있습니다. 그 페이지의 제목은 **구독 업데이트**이고, 여기서 설정을 바꾸거나 구독을 취소할 수 있다고 방문자에게 안내합니다. 페이지에는 다음이 있습니다.

- 해당 페이지가 허용하는 리소스 및 이벤트 유형 선택기.
- **구독 취소** 토글. 모든 리소스의 구독을 취소한다는 설명이 붙어 있으며, **구독 취소 여부**(`isUnsubscribed`, 기본값 false)에 기록됩니다.
- **구독 업데이트**라고 적힌 제출 버튼. 저장하면 *변경 사항이 저장되었습니다.*라고 표시됩니다.

링크를 잃어버린 사람은 **구독** 페이지의 **기존 구독 관리**를 이용해 **관리 링크 보내기**를 누릅니다. OneUptime은 링크가 담긴 이메일을 보냈으며 도착하지 않으면 스팸 폴더를 확인하라고 답합니다.

이 모든 것을 뒷받침하는 엔드포인트는 `POST .../subscribe/:statusPageId`, `POST .../manage-subscription/:statusPageId`, `POST .../get-subscription/:statusPageId/:subscriberId`, `PUT .../update-subscription/:statusPageId/:subscriberId`입니다.

구독을 취소해도 행이 지워지는 것이 아니라 플래그가 뒤집힐 뿐이라, 레코드는 **구독 취소 여부**가 설정된 채로 채널 목록에 남습니다. 나중에 특정 주소로 메일이 왜 더 이상 가지 않는지 설명해야 할 때 유용합니다.

## 구독자가 알림을 받는 대상

구독자는 위의 세 가지 이벤트 유형에 대해 소식을 받지만, 각 출처마다 별도의 스위치가 있어 실수로 발송되는 일은 없습니다.

### 공지 알림

공지 자체에는 **Should subscribers be notified?**(`shouldStatusPageSubscribersBeNotified`)가 있으며, 생성 양식에서는 **상태 페이지 구독자에게 알림** 체크박스로 노출되고 기본으로 켜져 있습니다. 공지가 **영향받은 모니터(선택 사항)**에서 모니터를 지정하면 알림은 그 모니터로 범위가 좁혀지고, 비워 두면 모든 구독자에게 알림이 갑니다.

### 예정된 유지 관리 이벤트

예정된 유지 관리 이벤트에는 자체 구독자 컬럼 묶음이 있습니다. **Should subscribers be notified when event is created?**, **Should subscribers be notified when event is changed to ongoing?**, **Should subscribers be notified when event is changed to ended?**, 그리고 사전 안내를 위한 **Subscriber notifications before the event**와 **Next subscriber notification before the event at?**입니다. 이벤트의 **상태 페이지**가 어느 페이지에 표시될지를 정하고, **Should be visible on status page?**가 표시 여부 자체를 정합니다.

### 인시던트

`Incident`는 세 번째 이벤트 유형입니다. 애초에 인시던트가 상태 페이지에 올라가게 만드는 것 — 어떤 리소스를 건드리는지, 어떤 상태가 계속 보이게 하는지 — 는 [인시던트 상태 및 심각도](/docs/incidents/states-and-severities)에서 다룹니다.

상태 페이지 사이드 메뉴의 **알림 로그** 섹션(`{id}/notification-logs`)은 이 페이지가 실제로 무엇을 보냈는지 확인해야 할 때 찾는 곳입니다.

## 알림 템플릿 맞춤 설정하기

**구독자 설정**의 **알림 템플릿** 카드는 이 상태 페이지가 쓰는 템플릿을 **템플릿 이름**, **이벤트 유형**, **알림 방법** 컬럼과 함께 나열합니다 — 모든 상황에 하나의 정형 문구를 쓰는 대신 이벤트 유형별, 채널별로 문구를 달리할 수 있습니다.

프로젝트 전체 템플릿은 한 단계 위인 **상태 페이지 → 설정 → 구독자 템플릿**에 **공지 템플릿**과 나란히 있습니다.

## 이메일 바닥글, 사용자 지정 SMTP, Twilio

**구독자 설정**에 있는 카드 세 개가 더 있어서 구독자 메시지가 프로젝트를 떠나는 방식을 제어합니다.

- **이메일 바닥글 설정** — **사용자 지정 이메일 바닥글 텍스트 활성화**와 **구독자 이메일 알림 바닥글 텍스트**로 구독자 이메일에 직접 만든 바닥글을 넣습니다.
- **사용자 지정 SMTP** — **사용자 지정 SMTP 구성**은 구독자 이메일을 기본 서버 대신 자체 메일 서버로 보냅니다.
- **Twilio 구성** — **Twilio 구성**은 SMS 구독자에게 사용할 Twilio 계정입니다.

이메일 구독자가 있다면 사용자 지정 SMTP는 일찍 해 둘 만합니다. 자기 도메인에서 오는 메일은 필터링될 가능성이 훨씬 낮고, 새벽 2시에 그것을 읽는 고객에게 신뢰받을 가능성은 훨씬 높습니다.

## 공지

공지는 프로젝트 수준의 레코드(`StatusPageAnnouncement` 모델)로, 하나 이상의 상태 페이지로 퍼뜨리며 필요하면 특정 모니터로 범위를 좁히고 표시되는 기간을 지정할 수 있습니다.

**상태 페이지 → 더보기 → 공지**에서, 또는 개별 상태 페이지 사이드 메뉴의 **공지**에서 만듭니다. 생성 양식은 네 단계 마법사입니다.

1. **기본 정보** — **공지사항 제목**(필수, 최소 두 글자), **설명**(마크다운, 선택), 그리고 상태 페이지에서 공지와 함께 제공할 파일을 위한 **첨부 파일**.
2. **상태 페이지** — **이 상태 페이지에 공지사항 표시**. 필수인 다중 선택 항목입니다. 공지 하나로 여러 페이지를 한 번에 겨냥할 수 있습니다.
3. **영향받는 리소스** — **영향받은 모니터(선택 사항)**. 아무것도 고르지 않으면 모든 구독자에게 알림이 갑니다.
4. **일정 및 설정** — **공지사항 표시 시작 시점**(필수, 기본값은 지금), **공지사항 표시 종료 시점**(선택), **상태 페이지 구독자에게 알림**(기본으로 켜짐).

방문자는 `/announcements`에서 공지를 읽으며, **활성 공지사항**과 **지난 공지사항**으로 나뉘고 각각 **공지 시각**이 찍힙니다. 현재 진행 중인 공지는 개요 페이지 맨 위에도 고정됩니다. 보여 줄 것이 없으면 페이지에는 *공지사항 없음*과 함께 지금까지 게시된 공지가 없다는 안내가 표시됩니다.

첨부 파일은 `GET {statusPageCrudPath}/status-page-announcement/attachment/:statusPageId/:announcementId/:fileId`에서 제공되며, 상태 페이지 자체와 동일한 읽기 검사를 거칩니다 — 비공개 페이지의 첨부 파일은 비공개로 유지됩니다.

## 공지 예약이 동작하는 방식

**Show At**(`showAnnouncementAt`)과 **End At**(`endAnnouncementAt`)이 모든 것을 좌우하지만, 개요 페이지와 공지 목록은 서로 다른 질문을 던지고 그 차이가 사람들을 헷갈리게 합니다.

- **개요 페이지**는 `showAnnouncementAt`이 과거이고 `endAnnouncementAt`이 미래이거나 비어 있을 때 공지를 표시합니다.
- **`/announcements` 목록**은 `showAnnouncementAt`이 **공지사항 기록 표시(일 단위)**(`showAnnouncementHistoryInDays`, 기본값 14) 안에 드는 공지를 가져온 다음, 클라이언트 쪽에서 활성과 지난 것으로 나눕니다.

미리 대비해 둘 만한 두 가지 결과가 있습니다.

- **종료 날짜가 없는 공지는 만료되지 않습니다.** **공지사항 표시 종료 시점**을 비워 두면 개요 페이지에 무기한 고정된 채로 남습니다. 기간이 정해진 것에는 종료 날짜를 지정하세요.
- **오래되었지만 여전히 활성인 공지가 목록에서 사라질 수 있습니다.** `showAnnouncementHistoryInDays`보다 더 전에 시작했다면 개요에는 남으면서 `/announcements`에서는 빠집니다. 장기간 유지하는 안내가 있다면 기록 기간을 늘리세요.

공지가 아예 표시될지 여부는 **고급 설정**의 **공지사항 설정** 카드가 제어합니다. **공지사항 표시**(`showAnnouncementsOnStatusPage`, 기본값 true)와 **공지사항 기록 표시(일 단위)**(기본값 14)죠. **공지사항 표시**가 꺼져 있으면 공지 엔드포인트는 요청을 아예 거부합니다.

## 공지 템플릿

같은 종류의 안내를 반복해서 올린다면 — 월간 유지 관리 사전 안내나 되풀이되는 서드파티 성능 저하처럼 — 미리 만들어 두세요. **상태 페이지 → 설정 → 공지 템플릿**은 `StatusPageAnnouncementTemplate` 모델을 저장하며, 양식은 **템플릿 이름**, **템플릿 설명**, **공지사항 제목**, **설명**, **이 상태 페이지에 공지사항 표시**, **영향받은 모니터(선택 사항)**, **구독자에게 알림**을 묻습니다. 덕분에 퍼뜨릴 범위와 알림 여부를 매번이 아니라 한 번만 결정하면 됩니다.

## 웹훅 구독자와 SSRF 방어

웹훅 구독자는 상태 페이지 이벤트가 있을 때마다 JSON `POST` 요청을 받습니다. 그래서 상태 페이지 업데이트를 자기 시스템 — 챗봇, 사내 대시보드, 티켓 큐 — 으로 흘려보내는 가장 쉬운 방법이기도 합니다.

구독은 공개 페이지에서 이루어지는 공개 작업이므로 OneUptime은 대상 주소를 지킵니다.

- 일반 **웹훅 URL**은 수락되기 전에 검증되며, 사설·루프백·링크 로컬·클라우드 메타데이터 주소는 거부됩니다. OneUptime 배포 환경 내부의 무언가로 구독을 향하게 할 수는 없습니다.
- **Slack 수신 웹훅 URL**은 반드시 `https://hooks.slack.com/services/`로 시작해야 합니다.

웹훅 구독이 가입 단계에서 거부되었다면, 내부 주소이거나 형식이 잘못된 URL인지부터 확인하세요.
