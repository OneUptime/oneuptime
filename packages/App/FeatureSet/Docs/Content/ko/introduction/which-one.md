# 무엇을 써야 할까요?

## 인시던트, 경고 또는 다른 종류의 문제?

대부분의 문제는 인시던트 아니면 경고이며, 그 문제가 누구에게 영향을 주는지로 고릅니다. 나머지는 OneUptime이 대신 보관하는 기록이며, 모두 인시던트나 경고로 이어질 수 있습니다.

| 기록 | 무엇인가 | 이럴 때 사용 |
| --- | --- | --- |
| [인시던트](/docs/incidents/index) | 사용자에게 영향을 주는 문제입니다. 온콜 담당자를 호출하고 상태 페이지에 표시될 수 있습니다. | 고객이 알아차렸거나 곧 알아차릴 때: 장애, 속도 저하, 실패하는 결제. |
| [경고](/docs/alerts/index) | 팀을 위한 문제입니다. 온콜 담당자를 호출할 수 있지만, 상태 페이지에는 절대 표시되지 않습니다. | 사용자가 알아차리기 전에 팀이 조치해야 할 때: 차 가는 디스크, 곧 만료될 인증서. |
| [에피소드](/docs/incidents/episodes) | 관련된 인시던트나 관련된 경고를 하나로 묶어 다루는 것입니다. | 원인 하나가 많은 인시던트나 경고를 일으켰을 때. 그룹화 규칙이 에피소드를 대신 열어 줍니다. |
| [예외](/docs/telemetry/exceptions) | 코드가 던지는 한 오류의 모든 발생을 스택 트레이스와 함께 묶은 것입니다. | 버그를 고치고 싶을 때. 예외 모니터는 오류가 급증하면 경고나 인시던트를 발생시킬 수 있습니다. |
| [AI 인사이트](/docs/ai/ai-sre#인사이트-선제적-감지) | 무언가 호출하기 전에 OneUptime이 텔레메트리에서 찾아낸 문제로, 오류 로그 급증 같은 것입니다. | 조기 경고를 원할 때. 인사이트는 아무도 호출하지 않고 인시던트도 열지 않으며, 받은 편지함에서 기다립니다. |
| [보안 케이스](/docs/telemetry/security-cases) | 살펴볼 가치가 있는 하나의 위협으로, 같은 사용자, 호스트 또는 주소에 대한 모든 탐지가 담깁니다. | 보안 팀이 조사할 때. 사용자가 영향을 받으면 케이스에서 **인시던트 선언**으로 인시던트를 엽니다. |

경고는 나중에 그것이 속한 것으로 밝혀진 인시던트에 연결할 수 있으므로, 경고로 시작해도 잃는 것이 없습니다.

## 워크플로, 런북, 플레이북 또는 AI 규칙?

넷 모두 스스로 실행될 수 있습니다. 무엇을 대상으로 동작하는지, 누가 단계를 작성했는지로 고릅니다.

| 도구 | 하는 일 | 이럴 때 사용 |
| --- | --- | --- |
| [워크플로](/docs/workflows/index) | 트리거가 발생하면 실행되는 캔버스 위의 블록입니다: 인시던트 생성, 일정 시각 도래, 다른 도구의 URL 호출. | 코드 없이 OneUptime을 다른 도구와 연결하거나 그 레코드를 처리하고 싶을 때. |
| [런북](/docs/runbooks/index) | 수동 체크리스트부터 스크립트, HTTP 요청, kubectl까지 대응 절차를 단계로 만든 것으로, 인시던트, 경고 또는 유지 관리 이벤트에서 실행합니다. | 대응자가 매번 같은 단계를 따라야 할 때. 런북 규칙은 일치하는 인시던트에서 런북을 시작합니다. |
| [플레이북](/docs/telemetry/security-cases#플레이북) | 보안 케이스에 대응하는 단계입니다: 증거 보존, 온콜 담당자 호출, 사용자 정지. | 보안 팀이 같은 종류의 위협에 매번 같은 방식으로 대응할 때. |
| [AI 규칙](/docs/ai/ai-sre#조사하고-수정하는-인시던트) | OneUptime AI가 어떤 새 인시던트와 경고를 조사하고 수정할지, 먼저 물어볼지를 정합니다. | OneUptime AI가 일부 인시던트만 다루거나 묻지 않고 수정해야 할 때. 규칙이 없으면 모두 조사합니다. |

## 모니터 그룹, 서비스 또는 레이블?

셋 모두 여러 가지를 한데 모으지만, 보는 사람이 다릅니다. 함께 쓸 수도 있습니다. 서비스의 모니터로 하나의 모니터 그룹을 만들고, 모두에 같은 레이블을 붙일 수 있습니다.

| 선택지 | 무엇인가 | 이럴 때 사용 |
| --- | --- | --- |
| [모니터 그룹](/docs/monitor/monitor-groups) | 여러 모니터를 하나의 상태(그중 가장 나쁜 상태)로 묶은 것으로, 자체 가동 시간을 가집니다. | Checkout처럼 여러 모니터로 이루어진 것을 고객이 상태 페이지에서 한 행으로 보게 하고 싶을 때. |
| [서비스](/docs/telemetry/services) | OneUptime이 텔레메트리에서 찾은 애플리케이션으로, 로그, 트레이스, 메트릭, 인시던트, 소유자를 한 페이지에 모읍니다. | 애플리케이션 하나에 관한 모든 것을 한곳에서 보고 싶을 때. `service.name`에서 저절로 나타납니다. |
| [레이블](/docs/configuration/label-and-owner-rules) | 모니터와 대부분의 다른 레코드에 붙이는 태그입니다. 한 레코드에 여러 개를 붙일 수 있습니다. | 목록을 필터링하거나, 팀의 권한을 제한하거나, 규칙에서 레코드를 골라내고 싶을 때. |

모니터 그룹은 꺼진 상태로 시작합니다. **프로젝트 설정 → 고급 → 기능 플래그**에서 켜세요.

## 프로브, 에이전트, 컬렉터 또는 Runner?

OneUptime의 대부분은 아무것도 설치할 필요가 없습니다. OneUptime이 외부에서 볼 수 없는 것에 닿아야 할 때만 무언가를 설치하세요. 각각은 바깥 방향으로 연결하며, 저마다 고유한 종류의 키를 씁니다.

| 설치 대상 | 하는 일 | 이럴 때 설치 | 사용하는 키 |
| --- | --- | --- | --- |
| [사용자 지정 프로브](/docs/probe/custom-probe) | 네트워크 안에서 모니터의 확인을 실행합니다. | 확인할 대상이 방화벽 뒤에 있을 때. OneUptime 자체 프로브는 공개된 것을 확인합니다. | 자체 프로브 ID와 키 |
| [인프라 에이전트](/docs/monitor/server-monitor) | 머신 한 대의 CPU, 메모리, 디스크, 프로세스를 Server / VM 모니터에 보고합니다. | 서버 한 대를 모니터 하나로 지켜보고, 그 수치에 기준을 걸고 싶을 때. | 모니터의 비밀 키 |
| [OpenTelemetry Collector](/docs/telemetry/hosts) | 머신의 메트릭, 로그, 프로세스를 보냅니다. **호스트 추가**가 명령 하나로 설치합니다. | 머신을 텔레메트리와 함께 **호스트** 아래에 두고 싶을 때. | 수집 키 |
| [Kubernetes 에이전트](/docs/telemetry/kubernetes-agent) | 클러스터의 메트릭, 이벤트, 로그, 트레이스를 수집합니다. Helm으로 설치합니다. | Kubernetes를 운영할 때. | 수집 키 |
| [Runner](/docs/runbooks/agents) | Bash, SSH, kubectl 같은 런북 단계를 인프라 안에서 실행합니다. | 런북이 자체 호스트와 클러스터에 닿아야 할 때. | 자체 Runner ID와 키 |

### 수집 키 또는 API 키?

| 키 | 할 수 있는 일 | 만드는 곳 |
| --- | --- | --- |
| [수집 키](/docs/telemetry/ingestion-keys) | 프로젝트에 텔레메트리를 보내는 것뿐입니다. | **프로젝트 설정 → 텔레메트리 및 APM → 수집 키** |
| [API 키](/docs/permissions/index#api-키) | 부여한 권한으로 API, CLI, Terraform 또는 AI 어시스턴트를 통해 프로젝트를 읽고 변경합니다. | **프로젝트 설정 → 고급 → API 키** |

어느 쪽도 다른 쪽을 대신할 수 없습니다.

## 대시보드, 공개 대시보드 또는 상태 페이지?

누가 봐야 하는지로 고르세요.

| 공유 대상 | 보는 사람 | 이럴 때 사용 |
| --- | --- | --- |
| [대시보드](/docs/dashboards/index) | 프로젝트에 로그인하는 사람. | 팀이 차트와 목록을 지켜볼 때: 온콜 화면, 팀 자체의 뷰. |
| [공개 대시보드](/docs/dashboards/sharing) | 링크가 있는 누구나. 단, 비밀번호를 추가하거나, 특정 IP 주소로 제한하거나, 자체 도메인에서 호스팅하면 예외입니다. | 파트너나 벽에 걸린 화면처럼 프로젝트 밖의 사람이 차트를 봐야 할 때. |
| [상태 페이지](/docs/status-pages/index) | 공개라면 고객 누구나, 비공개라면 들여보낸 사용자만. | 고객이 서비스가 동작하는지 알고, 인시던트와 유지 관리 소식을 받고 싶어 할 때. |

상태 페이지는 인시던트와 모니터에 붙인 이름으로 이야기하고, 대시보드는 그 뒤에 있는 숫자를 보여 줍니다.
