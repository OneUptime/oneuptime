# 인시던트 개요

OneUptime의 인시던트는 무언가 고장났을 때 팀이 중심에 두고 모이는 기록입니다. 번호, 제목, 심각도, 현재 상태, 영향을 받는 리소스, 그리고 대응하는 동안 팀이 적어 내려간 모든 것 — 노트, 근본 원인, 해결 조치, 그리고 누가 무엇을 했는지 기록하는 추가 전용 피드 — 을 담고 있습니다.

인시던트는 모니터가 빨갛게 변한 순간을 조직적인 대응으로 바꿔 놓는 장치입니다. 인시던트를 선언하면 알맞은 온콜 로테이션이 호출되고, 모든 변경 사항을 통지받는 소유자가 추가되고, 런북이 시작되며 — 원한다면 — 장애가 공개 상태 페이지에 게시되어 고객이 "혹시 알고 계신가요?"라고 묻는 티켓을 열지 않게 됩니다.

새벽 3시에 직접 인시던트를 선언할 수도 있고, 모니터의 기준이 일치하는 순간 모니터가 대신 선언하게 둘 수도 있습니다. 어느 쪽이든 인시던트는 같은 객체이고, 같은 수명 주기를 거치며, 마지막에 같은 기록을 남깁니다.

## 한눈에 보기

- **최상위 기능** — 대시보드 왼쪽 내비게이션의 **인시던트**, 경로는 `/dashboard/{projectId}/incidents`입니다.
- **기본 제공 상태 세 가지** — **확인됨**, **인지됨**, **해결됨**이 새 프로젝트마다 생성됩니다. 직접 추가할 수도 있으며, 기본 제공 세 가지는 이름과 색상을 바꿀 수 있지만 삭제는 절대 되지 않습니다.
- **기본 제공 심각도 세 가지** — **심각한 인시던트**, **주요 인시던트**, **경미한 인시던트**. 심각도는 색상과 순서를 가진 이름표일 뿐, 그 자체로는 아무 동작도 하지 않습니다.
- **들어오는 경로 네 가지** — **인시던트 선언** 마법사, **템플릿에서 생성**, 모니터 기준 규칙, 그리고 `POST /api/incident`.
- **프로젝트별 번호** — 모든 인시던트에 인시던트 번호가 붙고, 기본적으로 `#42`처럼, 또는 직접 정한 접두사를 붙여 `INC-42`처럼 표시됩니다.
- **두 종류의 노트** — 팀을 위한 비공개 노트(내부 노트), 상태 페이지 구독자를 위한 공개 노트.
- **설정은 프로젝트 설정이 아니라 인시던트 아래에 있습니다** — 상태, 심각도, 템플릿, 사용자 정의 필드, 규칙 엔진은 모두 **인시던트 → 설정**과 **인시던트 → 규칙**에 있습니다.

## 주요 용어

이 섹션의 다른 모든 페이지에 계속 등장하는 몇 개의 단어가 있습니다. 이것부터 정리하고 넘어가세요.

| 용어                   | 무엇을 뜻하는가                                                                                                                                       |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **인시던트**           | 기록 그 자체 — 제목, 설명, 심각도, 현재 상태, 영향을 받는 리소스, 그리고 대응 중에 그 위에 적힌 모든 것입니다.                                       |
| **인시던트 상태**      | 인시던트가 수명 주기의 어디에 있는지입니다. 이름, 색상, `order`와 의미를 부여하는 플래그를 가진 프로젝트 범위의 행입니다.                            |
| **인시던트 심각도**    | 얼마나 심각한지입니다. 이름, 색상, `order`를 가진 프로젝트 범위의 행입니다. 순수한 분류일 뿐 — 제품 어디에서도 특정 심각도를 특별 취급하지 않습니다. |
| **인시던트 번호**      | `#42`로, 또는 접두사를 설정했다면 `INC-42`로 표시되는 프로젝트별 카운터입니다.                                                                       |
| **영향받는 리소스**    | 인시던트에 연결하는 모니터, 호스트, Kubernetes 클러스터, Docker 호스트, 서비스 등의 인프라입니다.                                                    |
| **공개 노트**          | 상태 페이지 독자와 구독자를 위해 쓰는 업데이트입니다. 상태 페이지 타임라인에 렌더링됩니다.                                                           |
| **비공개 노트**        | 대응 팀을 위한 내부 노트(`IncidentInternalNote` 모델)입니다. 상태 페이지에는 절대 나가지 않습니다.                                                   |
| **소유자**             | 인시던트를 책임지는 사용자 또는 팀입니다. 소유자는 생성될 때, 노트가 올라올 때, 상태가 바뀔 때 통지를 받습니다.                                      |
| **인시던트 피드**      | 인시던트 **개요**에 있는 추가 전용 활동 타임라인으로, 상태 변경, 노트, 소유자 변경, 규칙 실행, 알림을 기록합니다.                                    |
| **상태 타임라인**      | 인시던트가 언제, 어떤 상태에, 얼마나 오래 있었는지에 대한 기록이며 각 전환의 구독자 알림 상태도 함께 담습니다.                                       |

## OneUptime이 모든 프로젝트에 기본 생성하는 세 가지 상태

프로젝트가 생성되면 OneUptime은 정확히 세 개의 인시던트 상태를 다음 순서로 만들어 둡니다.

| 상태             | 순서  | 색상               | 무엇을 뜻하는가                                                            |
| ---------------- | ----- | ------------------ | ------------------------------------------------------------------------- |
| **확인됨**       | 1     | 빨강 (`#fd625e`)   | 갓 만들어진 인시던트가 들어가는 상태입니다. 이것이 생성 상태입니다.       |
| **인지됨**       | 2     | 노랑 (`#ffbf53`)   | 누군가 인시던트를 맡아 작업하고 있습니다.                                 |
| **해결됨**       | 3     | 초록 (`#2ab57d`)   | 인시던트가 끝났습니다. 상태 페이지에서 내려가게 하는 것이 바로 해결입니다. |

이름은 그저 이름표일 뿐이고, 실제로 동작을 좌우하는 것은 상태 행에 달린 세 개의 불리언 `isCreatedState`, `isAcknowledgedState`, `isResolvedState`입니다. 각 플래그는 프로젝트당 하나의 상태만 갖는 것을 전제로 합니다.

이 구분은 들리는 것보다 훨씬 중요합니다.

- `isCreatedState`는 새 인시던트가 어디서 시작할지 결정합니다. 생성 시 상태를 명시하지 않으면 OneUptime이 프로젝트의 생성 상태를 찾아 사용합니다.
- `isAcknowledgedState`와 `isResolvedState`는 인시던트 헤더의 **Acknowledge** 및 **해결** 버튼, 인시던트 **개요**의 통계 타일 두 개, 사이드 메뉴의 **활성 인시던트** 개수 배지를 움직입니다.
- **활성 인시던트**는 오직 "현재 상태가 해결 상태가 아니다"로만 정의됩니다. 따라서 직접 추가한 상태는 해결 상태가 아닌 한 모두 활성입니다.

**이름에 주의하세요.** 첫 번째 기본 상태의 이름은 **확인됨**이지만, 제품 안의 여러 설명은 여전히 이를 생성 상태라고 부릅니다. 프로젝트의 상태 목록에서 "생성됨"을 찾고 있다면, 그것은 **확인됨**이라는 이름의 행입니다.

상태는 **인시던트 → 설정 → 인시던트 상태**에서 직접 추가할 수 있습니다. 새 상태는 정렬된 목록의 맨 끝에 추가되며 끌어서 순서를 바꿀 수 있습니다. 플래그가 달린 세 상태는 삭제할 수 없고 — OneUptime이 막습니다 — 대신 이름과 색상은 바꿀 수 있습니다. UI가 상태 이름을 동적으로 읽는 이유가 여기에 있습니다.

순서는 보기 좋으라고 있는 게 아니라 실제로 강제됩니다. 인시던트는 현재 상태보다 순서상 앞선 상태로 이동할 수 없습니다.

자세한 내용은 [인시던트 상태 및 심각도](/docs/incidents/states-and-severities)에 있습니다.

## OneUptime이 모든 프로젝트에 기본 생성하는 세 가지 심각도

새 프로젝트에는 심각도 세 개도 함께 생깁니다.

| 심각도                | 순서  | 색상               | 무엇을 뜻하는가                                             |
| --------------------- | ----- | ------------------ | ---------------------------------------------------------- |
| **심각한 인시던트**   | 1     | 적갈색 (`#b70400`) | 고객 영향이 매우 크고 즉시 대응이 필요합니다.              |
| **주요 인시던트**     | 2     | 빨강 (`#fd625e`)   | 영향이 크고 대개 즉시 대응이 필요합니다.                   |
| **경미한 인시던트**   | 3     | 노랑 (`#ffbf53`)   | 영향이 작고 보통 업무 시간 안에 처리됩니다.                |

기본 제공 심각도의 전체 설명은 [인시던트 상태 및 심각도](/docs/incidents/states-and-severities)에 있습니다.

심각도가 가진 것은 `name`, `description`, `color`, `order`가 전부입니다. 플래그도 없고, "심각한 인시던트"를 다른 행과 다르게 취급하는 코드 경로도 없습니다. 심각도는 사람이 우선순위를 가르는 방식이고, 온콜 규칙을 쓸 때 일치 조건으로 쓸 수 있습니다 — 하지만 심각도를 고르는 것만으로는 누구도 호출되지 않습니다.

심각도는 **인시던트 → 설정 → 인시던트 심각도**에서 편집하거나 추가합니다.

## 인시던트의 일생

### 1. 선언된다

네 가지 경로가 모두 같은 객체로 이어집니다.

- **직접** — 인시던트 목록에서 **인시던트 선언**을 클릭합니다. **인시던트 세부 정보**, **영향받는 리소스**, **인시던트 역할**, **온콜**, **더보기** 다섯 단계로 이루어진 **새 인시던트 선언** 마법사가 열립니다.
- **템플릿에서** — **템플릿에서 생성**을 클릭하고 저장해 둔 **인시던트 템플릿**을 고릅니다. 템플릿은 제목, 설명, 심각도, 초기 상태, 리소스, 온콜 정책, 소유자, 레이블을 미리 채워 줍니다.
- **모니터에서** — "인시던트를 선언한다" 토글을 켜 둔 모니터 기준 규칙은 필터가 일치하는 순간 인시던트를 자동으로 만듭니다. 여기서 제목과 설명에는 `{{variable}}` 템플릿을 쓸 수 있습니다.
- **API로** — API 키와 함께 `POST /api/incident`를 호출합니다. `declaredAt`, 생성 상태, 인시던트 번호는 서버가 채워 줍니다.

필드 하나하나에 대한 설명은 [인시던트 선언](/docs/incidents/declaring-incidents)을 보세요.

### 2. 알아야 할 사람들이 알게 된다

생성 시 OneUptime은 설정해 둔 자동화를 실행합니다. 레이블 규칙, 온콜 규칙, 소유자 규칙, 런북 규칙입니다. 인시던트에 연결된 온콜 정책은 — 직접 붙였든, 템플릿에서 왔든, 일치하는 온콜 규칙이 합쳐 넣었든 — 병렬로 실행됩니다.

소유자에게는 이메일, SMS, 전화, 푸시, WhatsApp으로 알림이 가며, 각 사용자의 알림 설정을 따릅니다. 소유자가 한 명도 없는 인시던트라면 알림이 버려지는 대신 프로젝트 소유자에게 대신 전달됩니다.

인시던트가 상태 페이지에 보이고 구독자 알림이 켜져 있다면 구독자도 소식을 듣습니다. 알림은 크론으로 1분마다 돌기 때문에 즉시 발송이 아니라 최대 1분 정도의 지연을 예상하세요.

### 3. 팀이 대응한다

대응자는 인시던트를 인지하고, 영향받는 리소스를 붙이고, 런북을 실행하고, 인시던트 역할을 배정하고, 알게 된 것을 적어 나갑니다 — 팀을 위한 비공개 노트, 고객을 위한 공개 노트, 그리고 그림이 뚜렷해지면 **근본 원인**과 **해결** 페이지까지. 이 모든 활동은 **개요** 페이지의 **인시던트 피드**에 쌓입니다.

### 4. 해결된다

**해결**을 클릭하면 인시던트가 해결 상태로 옮겨지고, 상태 타임라인에 기록이 찍히고, 지속 시간 시계가 멈추고, 인시던트를 보여 주던 상태 페이지의 활성 영역에서 사라집니다. 그러기 위해 다른 것을 바꿀 필요는 없습니다 — 상태 페이지 쿼리가 보는 것은 해결 상태 플래그뿐입니다.

그다음에는 포스트모템을 작성할 수 있고, 원한다면 상태 페이지에 게시할 수도 있습니다.

## 대시보드에서 인시던트가 있는 곳

왼쪽 내비게이션에서 **인시던트**를 엽니다. 사이드 메뉴는 다음 섹션들로 나뉘어 있습니다.

| 섹션          | 여기서 하는 일                                                                                                                                                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **개요**      | **모든 인시던트**와 **활성 인시던트** — 뒤쪽에는 해결 상태가 아닌 인시던트 개수를 담은 빨간 배지가 붙습니다.                                                              |
| **에피소드**  | 인시던트 에피소드. 자체 페이지를 가진 별도의 묶음 기능입니다.                                                                                                              |
| **AI**        | **조사**와 **해결** — 자동 조사와 자동 해결 설정입니다.                                                                                                                    |
| **워크스페이스** | 인시던트용 **Slack** 및 **Microsoft Teams** 연결입니다.                                                                                                                 |
| **규칙**      | 규칙 엔진들입니다. **그룹화 규칙**, **온콜 규칙**, **소유자 규칙**, **Runbook 규칙**, **개인정보 보호 규칙**, **레이블 규칙**, **SLA 규칙**, **Reminder Rules**.           |
| **설정**      | **인시던트 상태**, **인시던트 심각도**, **인시던트 템플릿**, **노트 템플릿**, **포스트모템 템플릿**, **사용자 정의 필드**, **인시던트 역할**, **기타 설정**.               |

**규칙**과 **설정**은 기본적으로 접혀 있습니다 — 이 문서의 나머지가 가리키는 페이지를 찾으려면 펼치세요. 인시던트 구성은 프로젝트 설정 아래가 아니라 전부 여기에 있습니다.

인시던트 목록 자체는 **인시던트 번호**, **제목**, **상태**, **심각도**, **영향받는 리소스**, **선언됨**, **기간**, **레이블**, **소유자**를 보여 주며, 여러 건을 한 번에 닫을 수 있도록 **상태 변경** 일괄 작업도 제공합니다.

## 인시던트의 각 페이지에 있는 것

인시던트를 열면 왼쪽 사이드 메뉴가 이렇게 묶여 있습니다.

- **개요** — **인시던트 세부 정보** 카드(제목, 심각도, 레이블, 인시던트 번호, 선언 시각, 선언자, 온콜 정책), **영향받는 리소스** 카드, 그리고 **인시던트 피드**. 그 위에는 인지까지 걸린 시간, 해결까지 걸린 시간, 총 **기간** 통계 타일이 있습니다.
- **상태 타임라인** — 인시던트가 거쳐 온 모든 상태와 각 전환의 **시작**, **종료**, **기간**, 구독자 알림 상태입니다. **원인 보기**와 **로그 보기**가 각 변경이 왜 일어났는지 설명해 줍니다.
- **SLA** — 이 인시던트의 SLA 추적입니다.
- **설명**, **근본 원인**, **해결** — 세 개의 마크다운 페이지입니다. 상태 페이지에 나가는 것은 설명입니다.
- **런북** — 이 인시던트에 연결된 런북 실행입니다.
- **포스트모템** — 사후 기록이며, 원하면 상태 페이지에 게시할 수 있습니다.
- **역할**, **온콜 실행**, **소유자** — 누가 붙어 있는지, 어떤 정책이 실행됐는지, 누가 통지받는지입니다.
- **알림 로그**, **AI 로그**, **감사 로그** — 무엇이 발송됐고 무엇이 바뀌었는지입니다.
- **비공개 노트**와 **공개 노트** — 사이드 메뉴의 **노트** 섹션 아래에 있습니다.
- **사용자 정의 필드**, **설정**, **인시던트 삭제** — **고급** 아래에 있습니다. **설정** 페이지에는 **상태 페이지에 표시**, **비공개 인시던트**, **Reminders** 카드가 있습니다.

협업 페이지는 [인시던트 메모, 소유자 및 피드](/docs/incidents/notes-owners-and-feed)에서 깊이 다룹니다.

## 인시던트가 OneUptime의 나머지와 맞물리는 방식

- **모니터가 문제를 발견하고, 인시던트가 그것을 기록합니다.** 모니터 기준 규칙은 제목, 심각도, 온콜 정책, 소유자, 레이블, 해결 노트를 미리 채운 채 인시던트를 자동으로 선언할 수 있습니다. 거기서 쓸 수 있는 변수는 [인시던트 및 알림 템플릿](/docs/monitor/incident-alert-templating)을 보세요.
- **호출은 온콜 정책이 담당합니다.** 선언 마법사의 **온콜** 단계에서, 템플릿에서, 또는 **인시던트 → 규칙 → 온콜 규칙**을 통해 정책을 붙이세요. 일치하는 규칙은 모두 실행되며, 실행되는 집합은 모든 일치 규칙과 직접 붙인 것을 합쳐 중복을 제거한 결과입니다.
- **런북이 무엇을 해야 하는지 알려 줍니다.** 런북 규칙은 조건에 맞는 인시던트가 생성되면 절차를 자동으로 연결하고, 대응자는 인시던트에서 직접 실행할 수도 있습니다. [Runbook 개요](/docs/runbooks/index)를 보세요.
- **상태 페이지가 고객에게 알립니다.** 페이지에서 인시던트 표시가 켜져 있고, 인시던트가 상태 페이지에 보이도록 표시되어 있고, 현재 상태가 해결 상태가 아닐 때 인시던트가 상태 페이지의 활성 목록에 나타납니다. 비공개 인시던트는 언제나 모든 상태 페이지에서 숨겨집니다. [상태 페이지 개요](/docs/status-pages/index)를 보세요.
- **워크플로우가 그 주변을 자동화합니다.** **On Create Incident**, **On Update Incident**, **On Delete Incident** 트리거로 인시던트 수명 주기 위에 노코드 자동화를 만들 수 있습니다. [워크플로우 개요](/docs/workflows/index)를 보세요.
