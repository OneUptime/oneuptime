# 에피소드

에피소드는 서로 관련된 인시던트나 서로 관련된 알림을 하나로 묶어, 팀이 하나로 다룰 수 있게 합니다. 한곳에서 보고, 한 무리의 소유자가 맡고, 하나의 상태를 확인하고 해결합니다. 그룹화 규칙은 에피소드를 열고, 인시던트와 알림이 들어올 때마다 거기에 추가합니다([인시던트 그룹화 규칙](/docs/incidents/settings#인시던트-그룹화-규칙) 참고). 인시던트를 직접 에피소드에 넣을 수도 있으며, 한 번에 여러 개를 넣을 수 있습니다. 에피소드에서 넣거나 인시던트 목록에서 넣으면 됩니다.

이 페이지의 모든 내용은 알림 에피소드에서도 똑같이 동작합니다. "인시던트"를 "알림"으로 바꿔 읽으세요. 인시던트 에피소드는 **인시던트 → 에피소드**에, 알림 에피소드는 **알림 → 에피소드**에 있습니다.

## 에피소드에서 인시던트 추가하기

에피소드를 열고 사이드 메뉴에서 **구성원 인시던트**(`/dashboard/{projectId}/incidents/episodes/{episodeId}/incidents`)를 고른 다음 **인시던트 추가**를 클릭합니다. 대화 상자에는 내가 볼 수 있고 아직 에피소드에 없는 인시던트 중 가장 최근 50개가 번호, 제목, 상태, 심각도와 함께 나열됩니다. 더 오래된 것은 제목이나 번호로 검색하세요. `INC-42`, `42`, `#42` 모두 인시던트 42를 찾습니다.

- 필요한 만큼 선택하세요. 한 번에 100개까지입니다. 버튼에 개수가 표시됩니다: **인시던트 3개 추가**.
- 이미 다른 에피소드에 있는 인시던트는 제목 아래에 그 에피소드의 번호와 함께 그렇다고 표시됩니다. 여기에 추가해도 그 에피소드에 그대로 남습니다. 인시던트는 여러 에피소드에 속할 수 있습니다.
- 추가할 수 없는 것이 있으면 대화 상자가 열린 채로 그 항목들을 이유와 함께 보여 주고, 나머지는 추가됩니다.

## 인시던트 목록에서 인시던트 추가하기

**인시던트** 목록이나 모니터의 인시던트 목록 같은 다른 인시던트 목록에서 인시던트를 선택하고 **일괄 작업**을 엽니다.

| 작업 | 하는 일 |
| --- | --- |
| **기존 에피소드에 추가** | 에피소드를 하나 고릅니다. 진행 중인 에피소드가 최신순으로 먼저 나오고, 그다음에 최근 해결된 에피소드가 나옵니다. 다른 에피소드는 제목이나 번호로 검색해 찾으세요. 추가하기 전에 대화 상자는 선택한 인시던트 중 몇 개가 이미 그 에피소드에 있는지(그대로 둡니다), 몇 개가 다른 에피소드에 있는지(거기에도 남습니다) 알려 줍니다. |
| **새 에피소드에 추가** | 선택한 인시던트가 들어 있는 에피소드를 만듭니다. 제목과 심각도만 묻고, 둘 다 선택한 인시던트 중 가장 심각한 것에서 채워집니다. 비공개 인시던트의 제목은 절대 복사되지 않습니다. 소유자, 온콜 정책, 메모는 에피소드 페이지에서 추가하세요. |

두 작업 모두 선택한 인시던트를 100개까지 받습니다. 결과에는 추가된 개수, 이미 에피소드에 있던 개수, 추가되지 않은 항목과 그 이유가 에피소드를 여는 링크와 함께 표시됩니다.

## 추가하면 일어나는 일

- **에피소드 피드에 항목 하나**가 추가되어 추가된 모든 인시던트를 알립니다. 처음 20개는 번호와 제목으로, 나머지는 몇 개 더 있는지로 알립니다. 에피소드의 Slack 또는 Microsoft Teams 채널에도 인시던트마다가 아니라 한 번만 게시됩니다. 비공개 인시던트는 번호로만 표시됩니다.
- **각 인시던트의 피드**에는 어느 에피소드에 추가되었는지가 기록됩니다.
- **에피소드의 심각도**는 기존 에피소드에 추가된 인시던트 중 가장 심각한 것으로 올라가며, 내려가지는 않습니다. 새 에피소드는 고른 심각도로 시작합니다.
- **해결된 에피소드는 해결된 상태로 남습니다.** 추가해도 다시 열리지 않으며, 추가해도 인시던트의 상태는 바뀌지 않습니다.
- **에피소드 소유자에게 알림이 갑니다.** 하나만 추가될 때와 마찬가지로 인시던트가 추가되었다는 사실이 전달됩니다. 에피소드를 인시던트와 함께 만들면 에피소드 생성 알림이 이를 포함합니다.

## 인시던트 빼기

**구성원 인시던트**에서 행의 **제거**를 누르거나 **일괄 작업**에서 선택한 행에 실행하면 인시던트가 이 에피소드에서만 빠집니다. 인시던트 자체는 삭제되지 않으며, 속한 다른 에피소드에는 그대로 남습니다.

## 추가할 수 있는 사람

추가하려면 에피소드에 인시던트를 추가할 권한이 필요합니다. Project Owner, Project Admin, Project Member, Incident Admin, Incident Member 역할과 Create Incident Episode Member가 있는 사용자 지정 역할에 이 권한이 있습니다. 내가 볼 수 있는 인시던트만 추가할 수 있습니다. 비공개 인시던트는 그 소유자와 프로젝트 소유자 및 관리자만 추가할 수 있습니다. 새 에피소드에 추가하려면 에피소드를 만들 권한도 필요합니다. 사용할 수 없는 작업은 잠겨 있으며, 도구 설명에 부족한 권한이 표시됩니다.

## API로 추가하기

한 번의 요청으로 여러 인시던트를 에피소드에 추가합니다.

```bash
curl -X POST 'https://oneuptime.com/api/incident-episode-member/add-incidents' \
  -H "ApiKey: $ONEUPTIME_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "incidentEpisodeId": "<episode id>",
    "incidentIds": ["<incident id>", "<incident id>"]
  }'
```

응답은 보낸 인시던트를 각각 한 번씩, 추가됨, 이미 에피소드에 있음, 추가되지 않음과 그 이유 중 하나로 알려 줍니다. ID가 100개를 넘는 요청은 거부됩니다.

```json
{
  "added": ["<incident id>"],
  "alreadyInEpisode": ["<incident id>"],
  "notAdded": [
    {
      "id": "<incident id>",
      "reason": "This incident does not exist in this project, or you do not have access to it."
    }
  ]
}
```

알림의 경우 `alertEpisodeId`와 `alertIds`를 `/api/alert-episode-member/add-alerts`로 보냅니다. 인시던트가 들어 있는 에피소드를 만들려면, 에피소드를 만드는 요청 `POST /api/incident-episode`에 그 ID들을 `{ "data": { "title": "Checkout outage" }, "miscDataProps": { "incidentIdsToAdd": ["<incident id>"] } }` 형태로 함께 보냅니다. 알림 에피소드는 `POST /api/alert-episode`에 `alertIdsToAdd`를 함께 보냅니다. 그중 하나라도 추가할 수 없으면 에피소드가 만들어지지 않습니다.
