# ईमेल प्रदाता

OneUptime का ईमेल SMTP सर्वर के बजाय किसी ईमेल प्रदाता के HTTPS API से भेजें: Amazon SES, SendGrid, Mailgun, Postmark या Resend। कोई प्रोजेक्ट किसी SMTP कॉन्फ़िगरेशन के लिए इनमें से एक चुनता है, और स्व-होस्टेड इंस्टॉलेशन अपना सारा मेल इनमें से किसी एक से भेज सकता है। API तक HTTPS पर पोर्ट 443 से पहुँचा जाता है, इसलिए जिन नेटवर्क में SMTP पोर्ट ब्लॉक हैं, उनसे भी ईमेल बाहर जाता है, और हर प्रदाता की कुंजी एन्क्रिप्ट करके सहेजी जाती है।

:::cards
- [Amazon SES](#amazon-ses): एक IAM एक्सेस कुंजी, या सर्वर की अपनी IAM भूमिका, और वह क्षेत्र जिसमें आपका प्रेषक सत्यापित है।
- [SendGrid](#sendgrid): Mail Send एक्सेस वाली API कुंजी।
- [Mailgun](#mailgun): एक API कुंजी, भेजने वाला डोमेन और उसका क्षेत्र।
- [Postmark](#postmark): सर्वर का API टोकन।
- [Resend](#resend): भेजने की अनुमति वाली API कुंजी।
- [समस्या निवारण](#समस्या-निवारण): हर प्रदाता के इनकार का क्या मतलब है।
:::

## प्रदाता चुनना

:::tabs
@tab प्रोजेक्ट
**प्रोजेक्ट सेटिंग्स > सूचनाएं > सूचना चैनल** पर **और सेटिंग्स** खोलें, फिर **कस्टम SMTP कॉन्फ़िग्स** कार्ड में **SMTP कॉन्फ़िगरेशन बनाएँ** क्लिक करें। **प्रदाता** चरण पर एक **नाम** डालें और प्रदाता चुनें। अगला चरण उस प्रदाता की सेटिंग्स पूछता है, और **प्रेषक** चरण में **प्रेषक ईमेल** और **प्रेषक नाम** पूछे जाते हैं। सहेजने के बाद, कॉन्फ़िगरेशन की पंक्ति पर **परीक्षण ईमेल भेजें** से जाँचें कि वह काम करता है।
@tab स्व-होस्टेड इंस्टेंस
Admin Dashboard में **सेटिंग्स** खोलें, फिर **सूचनाएँ > ईमेल**। **ईमेल सर्वर सेटिंग्स** कार्ड में **सर्वर संपादित करें** क्लिक करें और **ईमेल सर्वर प्रकार** के रूप में प्रदाता चुनें। उसके नीचे प्रदाता का कार्ड दिखता है, जैसे **Amazon SES सेटिंग्स**: उसका संपादन बटन क्लिक करें, जैसे **Amazon SES संपादित करें**, और प्रदाता की सेटिंग्स और **प्रेषक** चरण भरें। जब तक ज़रूरी सब कुछ नहीं भरा जाता, कार्ड बताता है कि क्या कमी है, और हर ईमेल यह बताते हुए अस्वीकार किया जाता है कि कौन सी सेटिंग भरनी है।
:::

| प्रदाता | यह क्या पूछता है | OneUptime कहाँ भेजता है |
| --- | --- | --- |
| Amazon SES | एक्सेस कुंजी ID, सीक्रेट एक्सेस कुंजी, क्षेत्र | `https://email.<region>.amazonaws.com` (SES API v2) |
| SendGrid | API कुंजी | `https://api.sendgrid.com/v3/mail/send` |
| Mailgun | API कुंजी, डोमेन, क्षेत्र | `https://api.mailgun.net` या `https://api.eu.mailgun.net` |
| Postmark | सर्वर API टोकन | `https://api.postmarkapp.com/email` |
| Resend | API कुंजी | `https://api.resend.com/emails` |

हर ईमेल अपने टेक्स्ट भाग के साथ जाता है, और उसकी इमेज (OneUptime का लोगो, स्क्रीनशॉट) इनलाइन अटैचमेंट के रूप में जाती हैं। जब कोई प्रदाता भेजने की रफ़्तार सीमित करता है, या उसकी अपनी तरफ़ कोई गड़बड़ी होती है, तो OneUptime प्रदाता के बताए समय तक रुककर फिर से कोशिश करता है; बाकी हर इनकार प्रदाता के जवाब के साथ सूचना लॉग में रखा जाता है।

## Amazon SES

:::steps
### प्रेषक सत्यापित करें

[Amazon SES कंसोल](https://console.aws.amazon.com/ses/) में, उस क्षेत्र में जहाँ से आप भेजेंगे, **Identities** के तहत वह पता सत्यापित करें जिससे आप भेजते हैं, या उसका डोमेन। जब तक आपका खाता SES सैंडबॉक्स में है, हर प्राप्तकर्ता को भी सत्यापित करें, या प्रोडक्शन एक्सेस का अनुरोध करें।

### एक्सेस कुंजी बनाएँ

OneUptime के लिए एक IAM यूज़र बनाएँ, जिसकी पॉलिसी आपकी पहचान पर `ses:SendEmail` की अनुमति देती हो, फिर उसके लिए एक एक्सेस कुंजी बनाएँ:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ses:SendEmail",
      "Resource": "arn:aws:ses:us-east-1:123456789012:identity/example.com"
    }
  ]
}
```

AWS पर स्व-होस्टेड इंस्टॉलेशन कुंजी छोड़कर उसी पॉलिसी के साथ [सर्वर की IAM भूमिका से साइन इन](#सर्वर-की-iam-भूमिका-से-साइन-इन-करें) भी कर सकता है।

### Amazon SES चरण भरें

**एक्सेस कुंजी ID** और **सीक्रेट एक्सेस कुंजी** डालें, और वह **क्षेत्र** चुनें जिसमें आपकी पहचान सत्यापित है, जैसे `us-east-1`।
:::

### सर्वर की IAM भूमिका से साइन इन करें

AWS पर स्व-होस्टेड इंस्टॉलेशन अपने ईमेल उस IAM भूमिका के रूप में भेज सकता है जो AWS सर्वर को देता है, और OneUptime में कोई एक्सेस कुंजी संग्रहीत नहीं होती: AWS जो क्रेडेंशियल देता है वे कुछ घंटों में समाप्त हो जाते हैं, और OneUptime उनके समाप्त होने से पहले नए ले लेता है। यह केवल सर्वर के अपने ईमेल के लिए है। किसी प्रोजेक्ट का Amazon SES कॉन्फ़िग हमेशा एक्सेस कुंजी से साइन इन करता है, क्योंकि सर्वर की भूमिका सर्वर की अपनी AWS पहचान है, किसी प्रोजेक्ट की नहीं।

भूमिका को ऊपर दी गई पॉलिसी दें, फिर OneUptime को उस भूमिका के रूप में चलाएँ:

:::tabs
@tab Amazon EKS
सर्विस अकाउंट के लिए IAM भूमिकाओं के साथ, अपने क्लस्टर के OIDC प्रदाता के लिए ट्रस्ट पॉलिसी वाली भूमिका बनाएँ, और Helm चार्ट से भूमिका के ARN वाला एक सर्विस अकाउंट बनवाएँ। OneUptime के app और worker पॉड उसी के रूप में चलते हैं:

```yaml title="values.yaml"
serviceAccount:
  create: true
  annotations:
    eks.amazonaws.com/role-arn: arn:aws:iam::123456789012:role/oneuptime-ses
```

EKS Pod Identity के साथ, इसके बजाय भूमिका और उस सर्विस अकाउंट के बीच एक Pod Identity एसोसिएशन बनाएँ, और एनोटेशन छोड़ दें।
@tab Amazon ECS
भूमिका को OneUptime की टास्क परिभाषा की **Task role** के रूप में सेट करें।
@tab Amazon EC2
भूमिका को इंस्टेंस से उसकी इंस्टेंस प्रोफ़ाइल के रूप में जोड़ें। अगर OneUptime इंस्टेंस पर Docker में चलता है, तो इंस्टेंस मेटाडेटा की hop सीमा 2 करें, ताकि कंटेनर उस तक पहुँच सकें:

```bash
aws ec2 modify-instance-metadata-options --instance-id <instance-id> --http-put-response-hop-limit 2 --http-endpoint enabled
```
:::

फिर Admin Dashboard में **Amazon SES संपादित करें** पर क्लिक करें, **प्रमाणीकरण प्रकार** के रूप में **इस सर्वर की IAM भूमिका** चुनें, और **क्षेत्र** डालें। इसे सहेजने पर पहले संग्रहीत कोई भी एक्सेस कुंजी हटा दी जाती है।

OneUptime सर्वर के क्रेडेंशियल वहीं ढूँढता है जहाँ AWS SDK ढूँढते हैं, इस क्रम में: उसके परिवेश में `AWS_ACCESS_KEY_ID` और `AWS_SECRET_ACCESS_KEY`, एक वेब आइडेंटिटी टोकन (`AWS_ROLE_ARN` और `AWS_WEB_IDENTITY_TOKEN_FILE`), Amazon ECS और EKS Pod Identity का कंटेनर क्रेडेंशियल एंडपॉइंट, फिर EC2 की इंस्टेंस मेटाडेटा सेवा (IMDSv2)।

## SendGrid

SendGrid में **Settings > API Keys** खोलें और **Mail Send** एक्सेस वाली कुंजी बनाएँ, और वह पता सत्यापित करें जिससे आप भेजते हैं (Single Sender Verification), या उसका डोमेन (Domain Authentication)। कुंजी को **SendGrid** चरण पर **API कुंजी** में डालें।

## Mailgun

Mailgun में अपना भेजने वाला डोमेन जोड़ें और सत्यापित करें, जैसे `mg.example.com`, फिर उसके लिए एक सेंडिंग कुंजी बनाएँ, या अपने खाते की API कुंजी इस्तेमाल करें। **Mailgun** चरण पर **API कुंजी** और **डोमेन** डालें, और वह **क्षेत्र** चुनें जिसमें डोमेन बनाया गया था: Mailgun के EU क्षेत्र के डोमेन के लिए `EU`, बाकी सबके लिए `US`। **प्रेषक ईमेल** उसी डोमेन का पता होना चाहिए। सैंडबॉक्स डोमेन केवल अपने अधिकृत प्राप्तकर्ताओं को भेजता है।

## Postmark

Postmark में वह सर्वर खोलें जो मेल भेजता है, फिर उसका **API Tokens** टैब, और सर्वर API टोकन कॉपी करें: खाते के टोकन से मेल नहीं भेजा जा सकता। इसे **Postmark** चरण पर **सर्वर API टोकन** में डालें। **प्रेषक ईमेल** एक पुष्टि किया गया सेंडर सिग्नेचर होना चाहिए, या किसी सत्यापित डोमेन का पता। जब तक Postmark आपके खाते को मंज़ूरी नहीं देता, मेल केवल आपके अपने डोमेन के पतों पर जाता है।

## Resend

Resend में **Domains** के तहत अपना डोमेन जोड़ें और सत्यापित करें, फिर **API Keys** के तहत भेजने की अनुमति वाली API कुंजी बनाएँ। इसे **Resend** चरण पर **API कुंजी** में डालें, और **प्रेषक ईमेल** में अपने सत्यापित डोमेन का पता रखें। Resend का अपना टेस्ट डोमेन केवल आपके अपने पते पर भेजता है।

## समस्या निवारण

जो परीक्षण ईमेल नहीं जाता, वह इसकी वजह बताता है। किसी भी दूसरे ईमेल के लिए, **प्रोजेक्ट सेटिंग्स > सूचनाएं > सूचना लॉग** का **ईमेल** टैब खोलें और उसकी पंक्ति पर **स्थिति संदेश देखें** चुनें।

:::details "Amazon SES needs a verified identity in …"
**प्रेषक ईमेल**, या उसका डोमेन, कॉन्फ़िगरेशन में सेट क्षेत्र में सत्यापित नहीं है, या खाता SES सैंडबॉक्स में है और प्राप्तकर्ता सत्यापित नहीं है। उसे उसी क्षेत्र में सत्यापित करें, या प्रोडक्शन एक्सेस का अनुरोध करें।
:::

:::details "Amazon SES does not recognize the access key" या "did not accept the request's signature"
**एक्सेस कुंजी ID** जाँचें, यह भी कि कुंजी IAM में सक्रिय है, और कि **सीक्रेट एक्सेस कुंजी** वही है जो उसके साथ बनाई गई थी। सर्वर की घड़ी गलत होने पर भी सिग्नेचर अस्वीकार किया जाता है।
:::

:::details "The access key may not send with Amazon SES"
IAM यूज़र की पॉलिसी आपकी पहचान पर `ses:SendEmail` की अनुमति नहीं देती। ऊपर दी गई पॉलिसी जोड़ें।
:::

:::details "This server has no AWS credentials"
सर्वर अपनी IAM भूमिका से साइन इन करता है, पर AWS उसे कोई क्रेडेंशियल नहीं देता। उसे उस भूमिका के रूप में चलाएँ, जैसा [सर्वर की IAM भूमिका से साइन इन करें](#सर्वर-की-iam-भूमिका-से-साइन-इन-करें) बताता है, फिर OneUptime के पॉड या टास्क दोबारा शुरू करें: पॉड को अपनी भूमिका की सेटिंग्स शुरू होते समय मिलती हैं। Amazon EC2 पर Docker में, संदेश यह भी बताता है कि इंस्टेंस मेटाडेटा की hop सीमा कब बहुत कम है।
:::

:::details "This server's IAM role may not send with Amazon SES" या "did not let this server assume the role"
भूमिका की पॉलिसी आपकी पहचान पर `ses:SendEmail` की अनुमति नहीं देती: ऊपर दी गई पॉलिसी जोड़ें। या, Amazon EKS पर, भूमिका की ट्रस्ट पॉलिसी आपके क्लस्टर के OIDC प्रदाता और OneUptime के सर्विस अकाउंट के लिए `sts:AssumeRoleWithWebIdentity` की अनुमति नहीं देती।
:::

:::details "Mailgun has no domain … in its US region"
डोमेन उस क्षेत्र में नहीं है जहाँ कॉन्फ़िगरेशन भेजता है। **डोमेन** जाँचें, और अगर डोमेन EU क्षेत्र में बनाया गया था, तो **क्षेत्र** को `EU` पर सेट करें।
:::

:::details "is not a confirmed sender signature in Postmark" या "is not a verified domain in Resend"
प्रदाता के डैशबोर्ड में **प्रेषक ईमेल** की प्रेषक के रूप में पुष्टि करें, या उसका डोमेन सत्यापित करें।
:::

:::details "did not accept the API key" या "did not accept the server API token"
कॉन्फ़िगरेशन पर कुंजी जाँचें: SendGrid की कुंजी को Mail Send एक्सेस चाहिए, Mailgun की सेंडिंग कुंजी केवल अपने डोमेन के लिए काम करती है, Postmark को सर्वर का टोकन चाहिए, और Resend की कुंजी को भेजने की अनुमति चाहिए।
:::
