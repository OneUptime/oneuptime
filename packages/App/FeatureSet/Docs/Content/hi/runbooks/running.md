# Runbook चलाना

Runbook execution बनने के तीन तरीके हैं:

1. **नियम के माध्यम से स्वचालित रूप से** — [Runbook नियम](/docs/runbooks/rules) देखें।
2. **Runbook पेज से मैन्युअल रूप से** — Runbook के अवलोकन पर **Run Now** क्लिक करें। यह किसी incident, alert या निर्धारित रखरखाव इवेंट से बंधा नहीं है।
3. **एंटिटी फ़ीड से मैन्युअल रूप से** — incident, alert या निर्धारित रखरखाव इवेंट पर **Runbook चलाएं** क्लिक करें। execution उस एंटिटी से जुड़ता है।

## execution दृश्य

execution खोलकर उसका चेकलिस्ट UI देखें। प्रत्येक चरण दिखाता है:

- **स्थिति बैज** — Pending, Running, आपका इंतज़ार, Done, Skipped, Failed।
- **शीर्षक और विवरण** — execution के समय Runbook से कॉपी।
- **आउटपुट** (समेटा जा सकता है) — stdout, return मान, HTTP प्रतिक्रियाएँ।
- **त्रुटि संदेश** यदि चरण असफल हुआ।
- जिस चरण पर execution इंतज़ार कर रहा है, उस पर: **Mark complete** (Manual चरण) या **Approve & continue** (**Require approval** वाला चरण), और **छोड़ें**।
- execution रुका होने पर, बाद के उन ऑटोमेटेड चरणों पर भी **छोड़ें**, जिन्हें अनुमोदन की ज़रूरत नहीं।

execution अंतिम स्थिति में न होने पर पेज हर 3 सेकंड में पोल करता है, इसलिए ऑटोमेटेड चरण लगभग रीयल टाइम में पूरे होते दिखते हैं।

## चरणों को पूरा करना, अनुमोदित करना और छोड़ना

execution को आगे बढ़ाने के लिए केवल उसी चरण को पूरा चिह्नित करना, अनुमोदित करना या छोड़ना संभव है, जिस पर execution इंतज़ार कर रहा है। Manual चरण या **Require approval** वाले चरण को execution के उस तक पहुँचने से पहले न टिक किया जा सकता है, न छोड़ा जा सकता है — उसका काम execution को रोकना है, इसलिए वह निर्णय तभी स्वीकार करता है जब execution वहाँ पहुँच जाए (अनुमोदन के लिए, जब चरण चल चुका हो और आप उसका आउटपुट देख सकें)।

execution रुका होने पर आप बाद के ऐसे ऑटोमेटेड चरण को भी छोड़ सकते हैं जिसे अनुमोदन की ज़रूरत नहीं, ताकि execution आगे बढ़ने पर वह न चले। execution उसी चरण पर रुका रहता है जो आपका इंतज़ार कर रहा है। चरण चलते समय छोड़ना उपलब्ध नहीं है — execution के रुकने का इंतज़ार करें, या उसे रद्द करें। प्रत्येक चरण दर्ज करता है कि उसे किसने पूरा किया या छोड़ा।

## मैनुअल और ऑटोमेटेड चरणों का मिश्रण

क्लासिक प्रवाह:

1. **स्क्रिप्ट चरण**: सिस्टम स्थिति कैप्चर करना, S3 में लिखना।
2. **मैनुअल चरण**: "स्टेटस पेज बैनर के माध्यम से ग्राहकों को सूचित करें।" रिस्पॉन्डर टिक करता है।
3. **HTTP चरण**: PagerDuty से DBA को बुलाना।
4. **मैनुअल चरण**: "पुष्टि करें कि सेकंडरी DB अब प्राइमरी है।" रिस्पॉन्डर टिक करता है।
5. **स्क्रिप्ट चरण**: Slack पर "सब ठीक" संदेश भेजना।

चरण 2 और 4 execution को तब तक रोकते हैं जब तक टिक न हो जाए। चरण 1, 3, 5 स्वचालित रूप से चलते हैं। पूरा run एक execution, एक टाइमलाइन, एक स्रोत-सत्य है।

## execution रद्द करना

execution पेज पर **निष्पादन रद्द करें** क्लिक करें। मौजूदा चरण (यदि कोई हो) समाप्त होता है; आगे के चरण शुरू नहीं होते। स्थिति `Cancelled` हो जाती है।

## आउटपुट प्रतिधारण

प्रति-चरण आउटपुट **50KB** तक सीमित है ताकि भागते स्क्रिप्ट डेटाबेस को न फुलाएँ। बड़े आर्टिफ़ैक्ट चाहिए तो स्क्रिप्ट से S3 या logger में लिखें और return मान में URL रखें।

## Runbook दोबारा चलाना

Runbook execution एक एकल, अपरिवर्तनीय रिकॉर्ड है। दोबारा चलाने के लिए फिर से **Run Now** क्लिक करें — यह Runbook के मौजूदा चरणों के ताज़ा स्नैपशॉट के साथ नया execution बनाता है। मूल execution ऑडिट के लिए अछूता रहता है।

## पुराने executions ढूँढना

प्रत्येक Runbook का **निष्पादन** टैब इसकी सभी runs को स्थिति, तारीख सीमा और स्रोत एंटिटी फ़िल्टर के साथ सूचीबद्ध करता है। incident, alert या निर्धारित रखरखाव इवेंट पर **रनबुक** टैब उस एंटिटी से जुड़े runs दिखाता है।
