# स्व-होस्टिंग गाइड

इस पेज को ऊपर से नीचे तक फ़ॉलो करें और एक खाली सर्वर से अपने OneUptime तक पहुँचें, जो HTTPS पर चलता है, आपको एक टेस्ट ईमेल भेज चुका है और आपको अलर्ट कर सकता है। हर चरण इस बात पर ख़त्म होता है कि कैसे पता चले कि वह काम कर गया, और ब्योरे के लिए लंबे पेजों का लिंक देता है।

:::cards
- [OneUptime इंस्टॉल करें](#oneuptime-इंस्टॉल-करें): एक सर्वर पर Docker Compose, या Kubernetes पर Helm चार्ट।
- [सर्वर का सेटअप पूरा करें](#सर्वर-का-सेटअप-पूरा-करें): ईमेल, फिर SMS और कॉल, हर एक के साथ एक टेस्ट।
- [अपना इंस्टॉलेशन जाँचें](#अपना-इंस्टॉलेशन-जाँचें): एक कमांड जो बताती है कि क्या गड़बड़ है।
- [त्वरित शुरुआत](/docs/introduction/quickstart): आपका पहला मॉनिटर, पहली ऑन-कॉल नीति और पहला स्टेटस पेज।
:::

## आपको क्या चाहिए

- **एक सर्वर।** Docker Compose के लिए, OneUptime आज़माने के लिए 8 GB मेमोरी, 4 कोर और 20 GB डिस्क वाला Linux सर्वर, या टीम के लिए 16 GB, 8 कोर और 400 GB: देखें [साइज़िंग और क्षमता नियोजन](/docs/installation/sizing)। Helm चार्ट के लिए, एक Kubernetes क्लस्टर।
- **एक डोमेन नाम** जिससे लोग OneUptime खोलेंगे, जैसे `oneuptime.example.com`, एक DNS `A` रिकॉर्ड के साथ जो सर्वर की ओर इशारा करे। आप सर्वर के IP पते से शुरू कर सकते हैं, लेकिन Let's Encrypt के सर्टिफ़िकेट के लिए डोमेन नाम चाहिए।
- **पोर्ट 80 और 443**, इंटरनेट से पहुँचने योग्य, HTTPS के लिए।
- **ईमेल भेजने का एक तरीका**: एक मेल सर्वर, जैसे आपकी कंपनी का, Microsoft 365 या Google Workspace, या Amazon SES, SendGrid, Mailgun, Postmark या Resend पर एक खाता।
- **एक Twilio खाता**, SMS और फ़ोन कॉल से अलर्ट पाने के लिए। ईमेल और पुश सूचनाओं को इसकी ज़रूरत नहीं।

**काम कर गया जब** `dig +short oneuptime.example.com` सर्वर का IP पता दिखाए।

## OneUptime इंस्टॉल करें

:::tabs
@tab Docker Compose
नए Ubuntu, Debian या RHEL-आधारित सर्वर पर एक कमांड Docker, Git और Node.js को, जहाँ वे न हों, इंस्टॉल करती है, OneUptime को `oneuptime` फ़ोल्डर में क्लोन करती है, लोगों द्वारा इस्तेमाल होने वाला पता पूछती है और उसे शुरू करती है:

```bash
curl -fsSL https://oneuptime.com/install.sh | bash
```

यही काम हाथ से करने के लिए, Docker, Git और Node.js इंस्टॉल होने पर:

```bash
git clone --depth 1 --single-branch --branch release https://github.com/OneUptime/oneuptime.git
cd oneuptime
cp config.example.env config.env
```

`config.env` खोलें और उसकी पहली सेटिंग `HOST` को अपने डोमेन नाम या IP पते पर सेट करें, `http://` के बिना। यही एकमात्र सेटिंग है जिसे आपको बदलना है: ईमेल, SMS और कॉल Admin Dashboard में सेट होते हैं, और `ADVANCED` के नीचे की हर चीज़ जैसी है वैसी काम करती है। फिर OneUptime शुरू करें:

```bash
npm start
```

**काम कर गया जब** `npm start` **OneUptime is up!** और खोलने वाले पते के साथ ख़त्म हो। पहली शुरुआत में कुछ मिनट लगते हैं, जब तक Docker इमेज डाउनलोड करता है। अगर `npm start` उससे पहले रुक जाए, तो वह बताता है कि क्या बदलना है। [Docker Compose](/docs/installation/docker-compose) में हर ब्योरा है।
@tab Kubernetes
अपने डोमेन नाम या IP पते के साथ एक `values.yaml` बनाएँ, `http://` के बिना:

```yaml title="values.yaml"
host: oneuptime.example.com
```

चार्ट अपना डेटा आपके क्लस्टर की डिफ़ॉल्ट स्टोरेज क्लास पर रखता है। अगर `kubectl get storageclass` किसी को `(default)` नहीं दिखाता, तो उनमें से किसी एक के नाम के साथ `global.storageClass` जोड़ें। फिर चार्ट इंस्टॉल करें:

```bash
helm repo add oneuptime https://helm-chart.oneuptime.com/
helm install my-oneuptime oneuptime/oneuptime -f values.yaml
```

**काम कर गया जब** `kubectl get pods` हर पॉड को `Running` दिखाए और `helm install` का दिखाया पता OneUptime खोले। [चार्ट की इंस्टॉलेशन गाइड](https://github.com/OneUptime/oneuptime/blob/main/HelmChart/Public/oneuptime/docs/installation.md) में हर ब्योरा है।
:::

## HTTPS चालू करें

जब आपका डोमेन नाम सर्वर की ओर इशारा करने लगे, तो OneUptime को Let's Encrypt से मुफ़्त सर्टिफ़िकेट लेने दें। वह सर्टिफ़िकेट ख़ुद रिन्यू करता है।

:::tabs
@tab Docker Compose
ये मान `config.env` में सेट करें, फिर `npm start` दोबारा चलाएँ:

```ini title="config.env"
HOST=oneuptime.example.com
PROVISION_SSL=true
HTTP_PROTOCOL=https
```

क्या आप पहले से कोई रिवर्स प्रॉक्सी चलाते हैं, जैसे Caddy, Nginx या लोड बैलेंसर? `PROVISION_SSL=false` रखें, `HTTP_PROTOCOL=https` और `TRUSTED_PROXY_HOPS=2` सेट करें, और देखें [अपनी ख़ुद की रिवर्स प्रॉक्सी इस्तेमाल करें](/docs/installation/docker-compose#अपनी-ख़ुद-की-रिवर्स-प्रॉक्सी-इस्तेमाल-करें)।
@tab Kubernetes
ये मान `values.yaml` में सेट करें, फिर उन्हें लागू करें:

```yaml title="values.yaml"
host: oneuptime.example.com
httpProtocol: https
ssl:
  provision: true
```

```bash
helm upgrade my-oneuptime oneuptime/oneuptime -f values.yaml
```

इसके बजाय TLS को अपने ingress controller पर ख़त्म करने के लिए, `ssl.provision` बंद रखें और सिर्फ़ `httpProtocol: https` सेट करें।
:::

**काम कर गया जब** `https://oneuptime.example.com` बिना सर्टिफ़िकेट चेतावनी के खुले। पहला सर्टिफ़िकेट आमतौर पर कुछ मिनटों में आ जाता है। OneUptime को `localhost` पर आज़मा रहे हैं? यह चरण छोड़ दें: सर्टिफ़िकेट के लिए डोमेन नाम चाहिए।

## एडमिन खाता बनाएँ

अपना पता खोलें, जैसे `https://oneuptime.example.com`, और साइन अप करें। नए सर्वर का पहला खाता उसका मास्टर एडमिन बनता है, जो `/admin` पर Admin Dashboard खोल सकता है।

**काम कर गया जब** `/admin` Admin Dashboard खोले। जब तक ईमेल, HTTPS या साइन-अप का फ़ैसला बाक़ी है, वह **इस सर्वर का सेटअप पूरा करें** पर खुलता है।

## सर्वर का सेटअप पूरा करें

Admin Dashboard का **सर्वर सेटअप** पेज, `/admin/setup` पर, बताता है कि नए सर्वर को क्या चाहिए, सबसे ज़रूरी पहले। ईमेल, HTTPS और कौन साइन अप कर सकता है, ये ज़रूरी हैं। SMS और कॉल, एक ग्लोबल प्रोब, बैकअप और अपडेट जाँच की सलाह दी जाती है। हर आइटम में एक बटन है जो वह जगह खोलता है जहाँ उसे सेट किया जाता है, और `npm start` इस पेज का पता दिखाकर ख़त्म होता है।

:::steps
### ईमेल सेट अप करें

**ईमेल सेट अप करें** पर क्लिक करें। यह **सेटिंग्स > सूचनाएं > ईमेल** खोलता है, जहाँ आप अपना मेल सर्वर (ज़्यादातर पोर्ट `587` इस्तेमाल करते हैं) या ईमेल प्रदाता, और वह पता डालते हैं जिससे ईमेल जाते हैं। सेव करें, फिर **टेस्ट ईमेल भेजें** पर क्लिक करें और ख़ुद को एक भेजें।

**काम कर गया जब** ईमेल पहुँच जाए और चेकलिस्ट ईमेल को पूरा दिखाए। टेस्ट विफल होने पर वह दिखाता है कि मेल सर्वर ने क्या जवाब दिया: देखें [SMTP](/docs/emails/smtp#समस्या-निवारण)।

### चुनें कि कौन साइन अप कर सकता है

जो भी आपका पता खोल सकता है, वह साइन अप कर सकता है। जब आपकी टीम के खाते बन जाएँ, तो **सेटिंग्स > प्रमाणीकरण** में **साइन अप करने दें** बंद करें: जिन्हें आप किसी प्रोजेक्ट में बुलाते हैं, वे फिर भी जुड़ सकते हैं। साइन-अप खुले रखने के लिए **साइन-अप खुले रखें** पर क्लिक करें।

**काम कर गया जब** चेकलिस्ट साइन-अप को पूरा दिखाए।

### SMS और कॉल सेट अप करें, या सिर्फ़ ईमेल और पुश का उपयोग करें

SMS और फ़ोन कॉल से अलर्ट पाने के लिए **SMS और कॉल सेट अप करें** पर क्लिक करें और **सेटिंग्स > सूचनाएं > कॉल और SMS** में अपना Twilio खाता जोड़ें: [Twilio इंटीग्रेशन](/docs/self-hosted/twilio-integration) दिखाता है कि हर मान कहाँ मिलेगा। फिर **टेस्ट SMS भेजें** और **टेस्ट कॉल करें** पर क्लिक करें। इन्हें अपने गेटवे से भेजने के लिए देखें [SMS और कॉल गेटवे](/docs/self-hosted/sms-and-call-gateway)। अगर ईमेल और पुश सूचनाएं काफ़ी हैं, तो **सिर्फ़ ईमेल और पुश का उपयोग करें** पर क्लिक करें।

**काम कर गया जब** SMS पहुँच जाए और आपका फ़ोन बजे, या चेकलिस्ट आपका चुनाव दिखाए।
:::

[HTTPS चालू करें](#https-चालू-करें) काम करते ही HTTPS आइटम पूरा हो जाता है, और हर सुझाया गया आइटम बताता है कि क्या करना है।

## अपना इंस्टॉलेशन जाँचें

:::tabs
@tab Docker Compose
`oneuptime` फ़ोल्डर में doctor चलाएँ:

```bash
npm run doctor
```

यह हर कंटेनर, `config.env`, कि `HOST` इस सर्वर तक पहुँचता है, सर्टिफ़िकेट और ख़ाली डिस्क जाँचता है, और OneUptime से पूछता है कि वह अपने बारे में क्या देखता है, जैसे ईमेल और प्रोब। हर समस्या के साथ उसका समाधान आता है: देखें [अपना इंस्टॉलेशन जाँचें](/docs/installation/docker-compose#अपना-इंस्टॉलेशन-जाँचें)।
@tab Kubernetes
चार्ट की डायग्नोस्टिक स्क्रिप्ट अपने क्लस्टर पर चलाएँ, जैसा [चार्ट की समस्या निवारण गाइड](https://github.com/OneUptime/oneuptime/blob/main/HelmChart/Public/oneuptime/docs/troubleshooting.md#run-it) में बताया गया है। वह सिर्फ़ पढ़ती है, और जो मिला उसके सारांश के साथ ख़त्म होती है, सबसे गंभीर पहले।
:::

**काम कर गया जब** doctor **Everything looks right.** के साथ ख़त्म हो और `0` के साथ बाहर निकले। कुछ ठीक करना हो तो वह `1` के साथ, और जाँच न चला पाए तो `2` के साथ बाहर निकलता है। Kubernetes पर, सारांश में कोई `CRITICAL` निष्कर्ष नहीं होता।

## कुछ मॉनिटर करें और अलर्ट पाएँ

आपका सर्वर अब ईमेल भेज सकता है और लोगों को अलर्ट कर सकता है। [त्वरित शुरुआत](/docs/introduction/quickstart) प्रोडक्ट में आगे बढ़ती है: आपकी वेबसाइट के लिए एक मॉनिटर, एक ऑन-कॉल नीति जो साइट डाउन होने पर आपको अलर्ट करे, और एक स्टेटस पेज, लगभग पंद्रह मिनट में। उसका आख़िरी हिस्सा एक टेस्ट घटना घोषित करता है, ताकि आप अलर्ट आते देखें।

## समस्या निवारण

:::details npm start रुक जाता है और कहता है कि HOST अभी पता नहीं है
`config.env` में `HOST` अब भी एक प्लेसहोल्डर रखता है, जैसे `<your-address>`। उसे अपने डोमेन नाम या IP पते पर सेट करें, `http://` के बिना, और `npm start` दोबारा चलाएँ।
:::

:::details टेस्ट ईमेल विफल होता है
बटन के नीचे का संदेश मेल सर्वर का जवाब है। होस्ट नाम, पोर्ट, यूज़रनेम और पासवर्ड जाँचें, और यह भी कि मेल सर्वर आपको उस पते से भेजने देता है जिससे ईमेल जाते हैं। देखें [SMTP](/docs/emails/smtp#समस्या-निवारण)।
:::

:::details ब्राउज़र सर्टिफ़िकेट के बारे में चेतावनी देता है
Let's Encrypt को इंटरनेट से पहुँचने योग्य पोर्ट 80 और 443 चाहिए, और आपका डोमेन नाम इस सर्वर की ओर इशारा करता हो। कुछ मिनट रुकें, फिर `npm run doctor` चलाएँ: यह सर्टिफ़िकेट जाँचता है और बताता है कि क्या गड़बड़ है।
:::
