# अपडेट और सुरक्षा जाँच

दिन में एक बार, सेल्फ-होस्टेड OneUptime GitHub से पूछता है कि क्या कोई नई रिलीज़ आई है, और क्या OneUptime की प्रकाशित कोई सुरक्षा एडवाइज़री आपके चलाए जा रहे संस्करण को प्रभावित करती है। जब कोई एडवाइज़री उसे प्रभावित करती है, तो आपके मास्टर एडमिन से अपग्रेड करने को कहा जाता है। यह पेज बताता है कि जाँच क्या भेजती है, आपको क्या दिखता है, और इसे कैसे बंद करें।

:::cards
- [जाँच क्या भेजती है](#जाँच-क्या-भेजती-है): दो सार्वजनिक सवाल, और आपके इंस्टॉलेशन के बारे में कुछ भी नहीं।
- [आपको क्या दिखता है](#आपको-क्या-दिखता-है): फ़ुटर, एडमिन डैशबोर्ड और हर एडवाइज़री पर एक ईमेल।
- [इसे बंद करें](#इसे-बंद-करें): इंटरनेट एक्सेस के बिना वाले नेटवर्क के लिए, या मिरर इस्तेमाल करने के लिए।
:::

## जाँच क्या भेजती है

worker बिना टोकन के GitHub के API (`api.github.com`) को दो अनुरोध भेजता है:

| अनुरोध | यह क्या पूछता है |
| --- | --- |
| `GET /repos/OneUptime/oneuptime/releases/latest` | OneUptime की सबसे नई रिलीज़ कौन-सी है |
| `GET /repos/OneUptime/oneuptime/security-advisories?state=published` | OneUptime ने कौन-सी सुरक्षा एडवाइज़री प्रकाशित की हैं, हर एक किन संस्करणों को प्रभावित करती है और कौन-सी रिलीज़ उसे ठीक करती है |

इनमें आपके इंस्टॉलेशन के बारे में कुछ भी नहीं होता: न आपका चलाया जा रहा संस्करण, न उसका पता, और न आपके उपयोगकर्ताओं, प्रोजेक्ट या मॉनिटरिंग डेटा के बारे में कुछ भी। GitHub आपके सर्वर का सार्वजनिक IP पता देखता है, जैसे वह हर अनुरोध में देखता है, और एक `User-Agent` जिसमें OneUptime का नाम होता है। कोई एडवाइज़री आपके संस्करण को प्रभावित करती है या नहीं, यह आपके सर्वर पर तय होता है, और कोई भी ब्राउज़र GitHub को कॉल नहीं करता।

जाँच worker के शुरू होने पर चलती है, और उसके बाद दिन में एक बार। यह GitHub से दोबारा ज़्यादा से ज़्यादा हर 12 घंटे में एक बार पूछती है, और किसी अनुरोध के विफल होने के बाद ज़्यादा से ज़्यादा घंटे में एक बार।

## आपको क्या दिखता है

सिर्फ़ मास्टर एडमिन को बताया जाता है। अपग्रेड वही कर सकते हैं, और किसी और को यह बताना कि सर्वर किसी ज्ञात सुरक्षा समस्या वाला संस्करण चला रहा है, एक बिना पैच वाले सर्वर की ओर इशारा करना होगा।

- नई रिलीज़ आने पर Dashboard और एडमिन डैशबोर्ड के फ़ुटर में **अपडेट उपलब्ध** जुड़ जाता है। यह अपग्रेड गाइड खोलता है।
- अगर कोई प्रकाशित सुरक्षा एडवाइज़री आपके चलाए जा रहे संस्करण को प्रभावित करती है, तो वहाँ इसकी जगह लाल रंग में **सुरक्षा अपडेट** दिखता है।
- इसके बाद एडमिन डैशबोर्ड का पहला पेज हर एडवाइज़री की सूची दिखाता है: उसकी गंभीरता, वे संस्करण जिन्हें वह प्रभावित करती है, उसे ठीक करने वाली रिलीज़, और GitHub पर उसका लिंक। यह यह भी बताता है कि जाँच ने आख़िरी बार एडवाइज़री कब पढ़ीं, और अगर आख़िरी जाँच विफल रही, तो क्यों।
- आपके मास्टर एडमिन और एडमिन सूचना ईमेल (एडमिन डैशबोर्ड में **सेटिंग्स** > **ईमेल**) को आपके संस्करण को प्रभावित करने वाली हर एडवाइज़री के बारे में एक ईमेल मिलता है, और दूसरा कभी नहीं।

जैसे ही आप ऐसा संस्करण चलाते हैं जिसे कोई एडवाइज़री प्रभावित नहीं करती, यह सब हट जाता है। अपग्रेड करने के लिए [अपग्रेड करना](/docs/installation/upgrading) देखें।

## इसे बंद करें

इंटरनेट एक्सेस के बिना वाले नेटवर्क पर, या अगर आपके सर्वर को GitHub से संपर्क नहीं करना चाहिए, तो जाँच बंद कर दें। तब न कुछ दिखाया जाता है, न कोई ईमेल भेजा जाता है।

:::tabs
@tab Kubernetes
```yaml
updateCheck:
  disabled: true
```
@tab Docker Compose
```bash
DISABLE_UPDATE_CHECK=true
```
इसे `config.env` में सेट करें, फिर `npm start` चलाएँ।
:::

इसके बजाय अपने नेटवर्क के अंदर किसी मिरर से जाँच करने के लिए, जाँच को उस मिरर की ओर पॉइंट करें। मिरर को GitHub के ही ढाँचे में जवाब देना होगा।

| Helm मान | Docker Compose सेटिंग | डिफ़ॉल्ट |
| --- | --- | --- |
| `updateCheck.url` | `LATEST_RELEASE_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/releases/latest` |
| `updateCheck.securityAdvisoriesUrl` | `SECURITY_ADVISORIES_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/security-advisories` |

## जब GitHub तक नहीं पहुँचा जा सकता

इंटरनेट एक्सेस के बिना वाले नेटवर्क पर विफल अनुरोध अपेक्षित है, कोई त्रुटि नहीं। worker इसे debug स्तर पर लॉग करता है, आख़िरी बार पढ़ी गई जानकारी रखता है, और बाद में फिर से कोशिश करता है। एडमिन डैशबोर्ड बताता है कि एडवाइज़री आख़िरी बार कब पढ़ी गईं, और आख़िरी जाँच क्यों विफल रही: GitHub की रेट लिमिट, GitHub तक कोई रूट नहीं, टाइमआउट, या ऐसा जवाब जो GitHub का नहीं है।
