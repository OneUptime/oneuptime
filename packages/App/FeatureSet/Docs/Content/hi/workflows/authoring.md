# वर्कफ़्लो बनाना

वर्कफ़्लो बनाने के लिए **वर्कफ़्लो** खोलिए और **वर्कफ़्लो बनाएं** दबाइए। **एक वर्कफ़्लो बनाएं** डायलॉग पहले पूछता है कि आप शुरुआत कैसे करना चाहते हैं, फिर एक नाम। जिस template को अपनी सेटिंग्स चाहिए, जैसे Slack webhook URL, वह उन्हें एक और चरण में पूछता है।

चुनिए कि शुरुआत कैसे करनी है:

- डायलॉग में सबसे ऊपर **शुरू से बनाएं** आपको खाली canvas देता है। ज़्यादातर वर्कफ़्लो यहीं से शुरू होते हैं।
- **या किसी टेम्पलेट से शुरू करें** के नीचे कुछ **सुझाए गए** templates दिखते हैं। बाकी के लिए खोज बॉक्स के बगल में कोई श्रेणी चुनिए, जैसे **घटनाएं**, **मॉनिटर** या **Jira**, या **सभी टेम्पलेट**, या **टेम्पलेट खोजें…** में लिखिए। आपका लिखा हर शब्द मेल खाना चाहिए।

किसी template पर क्लिक करके देखिए कि वह क्या करता है: उसका trigger, वे blocks जिनसे वह बना है, और वे सेटिंग्स जो वह पूछेगा। फिर **यह टेम्पलेट इस्तेमाल करें** दबाइए, या template पर double-click कीजिए। खोज बॉक्स में तीर वाली keys कोई template चुनती हैं और **Enter** उसे इस्तेमाल करता है। `/` आपको खोज बॉक्स पर वापस लाता है।

वर्कफ़्लो बंद अवस्था में बनाए जाते हैं, इसलिए जब तक आप उन्हें चालू नहीं करते, कुछ भी नहीं चलता। नया वर्कफ़्लो **बिल्डर** में खुलता है, यही वह canvas है जिस पर आप उसे गढ़ते हैं।

## Canvas

खाली से शुरू किया गया वर्कफ़्लो एक अकेले dashed block के साथ खुलता है, जिस पर लिखा रहता है **Choose what starts this workflow**। वही शुरुआत का बिंदु है — trigger चुनने के लिए उस पर क्लिक कीजिए। template से बना वर्कफ़्लो अपने blocks पहले से लगे हुए खुलता है।

हर वर्कफ़्लो में सबसे ऊपर ठीक एक **trigger** होता है। बाकी हर चीज़ कोई न कोई काम करने वाला **घटक** है। दूसरा trigger जोड़ते ही पहला उसकी जगह छोड़ देता है, और आख़िरी trigger हटाने पर वही dashed placeholder लौट आता है।

Blocks जोड़ना:

- **Trigger** — dashed placeholder block पर क्लिक कीजिए। **Add Trigger** नाम का panel खुलता है।
- **बाकी सब कुछ** — canvas के ऊपर वाले toolbar में **घटक जोड़ें** दबाइए। वही panel खुलता है, बस शीर्षक **Add Component** होता है।

दोनों panel उन blocks के साथ खुलते हैं जिन्हें ज़्यादातर workflows इस्तेमाल करते हैं, **Popular** के नीचे, और उनके बाद बाक़ी built-in blocks आते हैं। **OneUptime resources** के नीचे **Incident** जैसे किसी resource पर क्लिक कीजिए और देखिए कि आप उसके साथ क्या कर सकते हैं; **Browse all resources** सभी को दिखाता है। या खोजिए: कुछ शब्द लिखिए, जैसे `create incident`, और सबसे क़रीबी नतीजा सबसे ऊपर आता है। खोज बॉक्स पर सीधे पहुँचने के लिए `/` दबाइए, नतीजों में आगे-पीछे जाने के लिए arrow keys, और हाइलाइट किया गया block जोड़ने के लिए **Enter**। किसी block पर क्लिक करते ही वह जुड़ जाता है।

नया block canvas के सबसे निचले block के नीचे आकर बैठता है, और नया trigger ऊपर पुराने trigger की जगह ले लेता है। नया block चुना हुआ रहता है, और अगर वह नज़र से बाहर गिरे तो canvas बस उतना खिसकता है जितने में वह दिख जाए। उसकी सेटिंग्स अपने आप नहीं खुलतीं: जब आप उसे सेट करने के लिए तैयार हों, block पर क्लिक कीजिए। जब तक उसकी ज़रूरी सेटिंग्स ख़ाली हैं, उस पर **Click to set up** लिखा रहता है। Blocks को जहाँ चाहें खींचिए; खींचते समय canvas grid से चिपकता चलता है। Blocks की जगहें सहेजी जाती हैं, इसलिए अगले व्यक्ति को वही सजावट दिखती है जो आप छोड़कर गए थे।

बदलाव अपने-आप सहेजे जाते हैं। toolbar में एक pill इसका हिसाब रखता है: बदलाव रास्ते में हो तो **Saving…**, फिर **सहेजा गया**, और बात न बनी तो **सहेजा नहीं जा सका**। न कोई Save बटन है, न अलग से publish का कोई कदम।

## Block पर क्या-क्या होता है

| फ़ील्ड                          | यह क्या करता है                                                                                                                                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier** (**ID** के नीचे) | block पर दिखने वाला छोटा id, जैसे `log-1`। बाकी blocks इसी से इस block को पहचानते हैं, इसलिए इसे बदलते ही इस पर आती हर `{{local.components.…}}` reference टूट जाती है। block का शीर्षक घटक का अपना नाम है, जिसे बदला नहीं जा सकता। |
| **सेटिंग्स**                     | अपना काम करने के लिए block को जो चाहिए — कोई URL, कोई Slack चैनल, कोई संदेश। वैकल्पिक फ़ील्ड पर **(वैकल्पिक)** लिखा रहता है; बाकी सब ज़रूरी हैं। कम काम आने वाली सेटिंग्स **और फ़ील्ड** के नीचे सिमटी रहती हैं; उसका शीर्षक उनके नाम दिखाता है और भरी हुई सेटिंग्स को उभारता है। |
| **Input**                     | ऊपरी किनारे पर बना बिंदु, जहाँ पिछले blocks से लाइनें आकर मिलती हैं। Triggers पर यह नहीं होता — उनसे पहले कुछ चलता ही नहीं।                                                                                       |
| **Outputs**                   | निचले किनारे पर बने बिंदु, जिनके ठीक ऊपर उनके नाम लिखे रहते हैं और जहाँ से लाइनें अगले blocks की ओर निकलती हैं। कई blocks में **सफलता** और **त्रुटि** के अलग-अलग outputs होते हैं, ताकि आप दोनों हालात सँभाल सकें।       |

## Blocks को जोड़ना

एक block के नीचे वाले बिंदु से खींचकर अगले block के ऊपर वाले बिंदु तक लाइए। आप जो लाइन खींचते हैं, वही तय करती है कि आगे क्या चलेगा।

- **सफलता** से जोड़ेंगे, तो अगला block तभी चलेगा जब पिछला block सफल रहा हो।
- **त्रुटि** से जोड़ेंगे, तो अगला block तभी चलेगा जब पिछला block नाकाम रहा हो।
- कोई output कहीं न जोड़ा हो, तो वह रास्ता वहीं खत्म हो जाता है।

एक output को कई blocks से जोड़ा जा सकता है। वे सब चलते हैं — पर एक के बाद एक, एक ही कतार में, साथ-साथ नहीं। शाखाओं के आपसी क्रम पर भरोसा मत कीजिए, और यह भी मत मान लीजिए कि वे एक ही समय पर चलेंगी। हर block एक run में ज़्यादा से ज़्यादा एक बार चलता है, इसलिए किसी पिछले block पर लौटता loop उसे दोबारा नहीं चलाएगा।

## Block की सेटिंग्स भरना

किसी block पर क्लिक कीजिए (या **Tab** से उस तक पहुँचकर **Enter** दबाइए), उसकी सेटिंग्स एक dialog में खुल जाती हैं। हर सेटिंग के लिए उसके मुताबिक input होता है — text फ़ील्ड, dropdown, code editor, toggle, वग़ैरह। भरिए और **सहेजें** दबा दीजिए।

इसी dialog में आपको ये भी मिलते हैं:

- **हटाएं** — यह block हटा दीजिए।
- **Run just this step** — बाकी वर्कफ़्लो के बिना सिर्फ़ इसी block को चलाइए। दूसरे चरणों से जो मान इसे मिलते, वे खाली आते हैं, पर यह जो भेजता, लिखता या मिटाता है वह सचमुच होता है।
- **दस्तावेज़ीकरण**, **Inputs**, **Outputs** और **Returns** — यह block क्या माँगता है और क्या देता है, इसके संदर्भ कार्ड।

ज़्यादातर text फ़ील्ड variables लेते हैं — data एक block से दूसरे तक इसी तरह पहुँचता है। syntax हाथ से टाइप करने के बजाय editor के value picker का इस्तेमाल कीजिए: आपके चुने हुए block और फ़ील्ड से वह सही reference खुद बना देता है। देखिए [वर्कफ़्लो वेरिएबल](/docs/workflows/variables)।

## बनाते-बनाते होती जाँच

आप जब भी कुछ बदलते हैं, बिल्डर पूरे graph की जाँच करता है और जो मिलता है उसे toolbar के एक pill में बता देता है। pill दबाने पर **Problems with this workflow** खुलता है, जो हर दिक़्क़त गिनाता है और आपको ज़िम्मेदार block तक ले जाता है। Canvas पर, जिस block की ज़रूरी सेटिंग्स अभी ख़ाली हैं उस पर **Click to set up** लिखा रहता है, और जिस block में कोई और गड़बड़ है उसके कोने में एक badge लगा रहता है: error के लिए लाल, warning के लिए पीला। क्या ग़लत है, यह पढ़ने के लिए badge पर माउस ले जाइए।

यह ठीक वे ग़लतियाँ पकड़ता है जो run बिगड़ने तक दिखती ही नहीं — कोई trigger न होना, दो blocks का एक ही id, id के भीतर बिंदु, ऐसा block जिससे कुछ जुड़ा ही न हो, कोई ज़रूरी सेटिंग खाली, बिगड़ा हुआ JSON, `{{ }}` के भीतर spaces, और ऐसे चरण या return value की reference जो है ही नहीं।

एक चीज़ यह नहीं जाँच सकता: कोई variable नाम मौजूद है या नहीं। नाम बदला हुआ variable सिर्फ़ run log में सामने आता है।

## आपका पहला वर्कफ़्लो

canvas की आदत पड़ने का सबसे तेज़ तरीका:

1. dashed placeholder block पर क्लिक कीजिए, फिर **Add Trigger** panel में **Manual** पर क्लिक कीजिए।
2. **घटक जोड़ें** दबाइए, फिर **Popular** के नीचे **Log** पर क्लिक कीजिए। नया block trigger के नीचे आकर बैठता है। Trigger के **Execute** बिंदु को Log block के input बिंदु से जोड़ दीजिए।
3. Log block पर क्लिक कीजिए, जिस पर **Click to set up** लिखा है, और उसका **मान** `Hello from {{local.components.manual-1.returnValues.value.name}}` कर दीजिए। `manual-1` trigger का **Identifier** है, जो trigger block पर लिखा दिखता है — मिलान कर लीजिए।
4. बिल्डर के ऊपर **सक्षम** चालू कर दीजिए। बंद वर्कफ़्लो बिल्कुल नहीं चलता, हाथ से भी नहीं; यह कदम छोड़ दें तो **वर्कफ़्लो चलाएं** पहले उसे चालू करने के लिए पूछता है।
5. वापस **बिल्डर** पर आकर **वर्कफ़्लो चलाएं** दबाइए, **JSON** फ़ील्ड में `{ "name": "Ada" }` डालिए, **Run Workflow Manually** दबाइए, और **Run** से पुष्टि कर दीजिए।
6. एक **Workflow Run** panel खुद-ब-खुद खुलकर run के साथ चलता है। log में `Value:` और उसके बाद `Hello from Ada` दिखता है।

यही चक्र — जोड़िए, जोड़-तोड़ कीजिए, सेटिंग्स भरिए, चलाइए, log पढ़िए — हर वर्कफ़्लो बनाने का तरीका है।

## इसे चालू करना

नए वर्कफ़्लो बंद हालत में शुरू होते हैं, और आप जो वर्कफ़्लो copy या import करते हैं वे भी। जब तक वर्कफ़्लो बंद है, बिल्डर canvas के ऊपर यह बताता है, साथ में **वर्कफ़्लो चालू करें** बटन भी।

**सक्षम** switch **बिल्डर** के ऊपर, **घटक जोड़ें** और **वर्कफ़्लो चलाएं** के बगल में है। यह वर्कफ़्लो के **अवलोकन** पेज पर भी है: **वर्कफ़्लो विवरण** कार्ड पर **वर्कफ़्लो संपादित करें** दबाइए; वही कार्ड मौजूदा हालत हरे **सक्षम** या लाल **अक्षम** pill के रूप में दिखाता है। वर्कफ़्लो को चालू या बंद सिर्फ़ वही लोग कर सकते हैं जो उसे संपादित कर सकते हैं; बाकी सबको switch धुँधला दिखता है।

बंद वर्कफ़्लो बिल्कुल नहीं चल सकता: उसका trigger अनदेखा होता है, और **वर्कफ़्लो चलाएं** व **Run just this step** भी। बंद रहते हुए आप वर्कफ़्लो या उसका कोई block चलाएँ, तो बिल्डर इसके बजाय पूछता है **यह वर्कफ़्लो चालू करें?**। **चालू करें और चलाएं** (या **चालू करें और चरण चलाएं**) वर्कफ़्लो को चालू करता है और फिर वही चलाता है जो आपने माँगा था, आपके दिए मानों के साथ। इसलिए क्रम यह है: बनाइए, **वर्कफ़्लो चलाएं** से परखिए, run log पढ़िए, और अगर trigger चलने देने को अभी तैयार नहीं हैं तो **सक्षम** वापस बंद कर दीजिए। पूरा वर्कफ़्लो चलाए बिना किसी एक block को परखना हो, तो उस block की सेटिंग्स में **Run just this step** का इस्तेमाल कीजिए।

बंद वर्कफ़्लो को शुरू करने वाली बाकी हर चीज़ भी यही सलाह देकर लौटा दी जाती है। उसके webhook URL पर call को HTTP 400 और "This workflow is turned off, so it can't run. Turn it on with the Enabled switch at the top of its Builder, then try again." मिलता है। उसे call करने वाला **Execute Workflow** block अपने **Error** रास्ते पर जाता है, और त्रुटि में call किए गए वर्कफ़्लो का नाम होता है।

वर्कफ़्लो को हटाए बिना रोकना हो, तो **सक्षम** बंद कर दीजिए। कोई नया run शुरू नहीं होता। जो run बीच में चल रहा है वह पूरा हो जाता है, पर **Sleep** block पर टिका run जागते ही रद्द कर दिया जाता है और त्रुटि के रूप में दर्ज होता है।

## सफ़ाई-सुथराई

- Blocks खींचकर इधर-उधर कीजिए। सजावट सहेज ली जाती है।
- कोई लाइन हटानी हो, तो उसका कोई एक सिरा बिंदु से खींचकर खाली canvas पर छोड़ दीजिए।
- कोई block हटाना हो, तो उस पर क्लिक कीजिए और उसकी सेटिंग्स dialog में सबसे नीचे **हटाएं** दबाइए। block या लाइन चुनकर Backspace दबाने से भी वह हट जाता है।
- किसी अकेले block की नक़ल बनाने का कोई तरीका नहीं है। वर्कफ़्लो के **सेटिंग्स** पेज पर मौजूद **Duplicate Workflow** पूरी चीज़ की नक़ल बनाता है। नक़ल का नाम पहले से भरा होता है, प्रोजेक्ट के वर्कफ़्लो के बाद की संख्या के साथ ("Nightly Sync" की नक़ल "Nightly Sync 2" बनती है), और नक़ल बंद हालत में खुलती है।
- Blocks को ऊपर से नीचे सजाइए ताकि वे उसी दिशा में पढ़े जाएँ जिस दिशा में चलते हैं — input ऊपरी किनारे पर हैं और output निचले किनारे पर, इसलिए बहाव अपने-आप नीचे की ओर जाता है।
