# Monitor Secrets

आप sensitive information जो आप अपने monitoring checks में उपयोग करना चाहते हैं उसे store करने के लिए secrets उपयोग कर सकते हैं। Secrets encrypted और सुरक्षित रूप से stored होते हैं।

### एक secret जोड़ना

secret जोड़ने के लिए, कृपया OneUptime Dashboard -> मॉनिटर -> सेटिंग्स -> सीक्रेट -> Create Monitor Secret पर जाएं।

![Create Secret](/docs/static/images/CreateMonitorSecret.png)

सीक्रेट को एक नाम और मान दें, फिर **एक्सेस** चरण में चुनें कि कौन-से मॉनिटर इसका उपयोग कर सकते हैं। इस उदाहरण में हमने एक `ApiKey` सीक्रेट जोड़ा है।

**कृपया ध्यान दें**: Secrets encrypted और सुरक्षित रूप से stored होते हैं। Save होने के बाद secret value दोबारा कभी नहीं दिखाई जाती — न table में, न edit form में, और न ही API पर। यदि आप value खो देते हैं, तो उसे उसके स्रोत से लेकर दोबारा सेट करना होगा। Secret rotate करने के लिए उसकी row पर **सीक्रेट मान अपडेट करें** बटन का उपयोग करें; उसे delete करके दोबारा बनाने की आवश्यकता नहीं है।

### चुनें कि कौन-से मॉनिटर सीक्रेट का उपयोग कर सकते हैं

हर सीक्रेट में इन तीन एक्सेस विकल्पों में से एक होता है:

- **सभी मॉनिटर**: प्रोजेक्ट का हर मॉनिटर सीक्रेट का उपयोग कर सकता है, जिसमें बाद में बनाए गए मॉनिटर भी शामिल हैं। इसका उपयोग उस क्रेडेंशियल के लिए करें जिसे कई मॉनिटर साझा करते हैं।
- **विशिष्ट मॉनिटर**: केवल आपके चुने हुए मॉनिटर सीक्रेट का उपयोग कर सकते हैं। यह डिफ़ॉल्ट विकल्प है, और इन विकल्पों के आने से पहले बनाए गए सीक्रेट इसी तरह काम करते हैं।
- **लेबल वाले मॉनिटर**: जिन मॉनिटरों पर आपके चुने हुए लेबलों में से कम से कम एक लेबल है, वे सीक्रेट का उपयोग कर सकते हैं। किसी मॉनिटर में इनमें से कोई लेबल जोड़ने पर उसे एक्सेस मिल जाता है, और लेबल हटाने पर मॉनिटर के अगली बार चलने से एक्सेस हट जाता है।

आप सीक्रेट की पंक्ति में **संपादित करें** से किसी भी समय विकल्प बदल सकते हैं। केवल चुने गए विकल्प की सूची रखी जाती है: **सभी मॉनिटर** पर जाने से सीक्रेट की मॉनिटर और लेबल सूचियाँ खाली हो जाती हैं, और **विशिष्ट मॉनिटर** तथा **लेबल वाले मॉनिटर** के बीच बदलने पर वह सूची खाली हो जाती है जिसे आप छोड़ रहे हैं।

कोई सीक्रेट किसी दूसरे प्रोजेक्ट के मॉनिटरों के लिए कभी उपलब्ध नहीं होता।

जो कोई भी उस मॉनिटर को संपादित कर सकता है जिसे सीक्रेट का उपयोग करने की अनुमति है, वह उस सीक्रेट को किसी भी ऐसे गंतव्य पर भेज सकता है जिससे मॉनिटर जुड़ता है। **सभी मॉनिटर** के साथ, इसमें वे सभी शामिल हैं जो प्रोजेक्ट में मॉनिटर बना या संपादित कर सकते हैं। **लेबल वाले मॉनिटर** के साथ, इसमें वे सभी भी शामिल हैं जो किसी मॉनिटर में इनमें से कोई लेबल जोड़ सकते हैं।

API में, एक्सेस विकल्प `monitorAccess` फ़ील्ड है: `All Monitors`, `Specific Monitors` या `Monitors With Labels`। `monitors` और `labels` फ़ील्ड में सूचियाँ होती हैं। `monitorAccess` के बिना बनाए गए सीक्रेट को `Specific Monitors` मिलता है।

### एक secret का उपयोग

आप निम्नलिखित monitoring types में secrets उपयोग कर सकते हैं:

- API (request headers, request body और URL में)
- Website, IP, Port, Ping, SSL Certificate (URL में)
- Synthetic Monitor, Custom Code Monitor (code में)
- SNMP Monitor (community string, SNMPv3 auth key और priv key में)

![Using Secret](/docs/static/images/UsingMonitorSecret.png)

secret उपयोग करने के लिए, उस field में `{{monitorSecrets.SECRET_NAME}}` जोड़ें जहाँ आप secret उपयोग करना चाहते हैं। उदाहरण के लिए, इस मामले में हमने Request Header field में `{{monitorSecrets.ApiKey}}` जोड़ा।

Synthetic या Custom Code monitor scripts execute होने से पहले probe पर Secrets inject किए जाते हैं, इसलिए `{{monitorSecrets.ApiKey}}` जैसे references चलने वाले script के अंदर decrypted value में resolve होते हैं।

यदि कोई मॉनिटर ऐसे सीक्रेट का संदर्भ देता है जिसका वह उपयोग नहीं कर सकता, तो संदर्भ जैसा है वैसा ही रहता है और उसे मान से नहीं बदला जाता।

जब आप किसी मॉनिटर को सहेजने से पहले उसका परीक्षण करते हैं, तो केवल **सभी मॉनिटर** के लिए उपलब्ध सीक्रेट भरे जाते हैं, क्योंकि नया मॉनिटर किसी सूची में नहीं होता और उस पर अभी कोई लेबल नहीं होता। मॉनिटर सहेजने के बाद, परीक्षण उन सभी सीक्रेट का उपयोग करते हैं जिनका मॉनिटर उपयोग कर सकता है।
