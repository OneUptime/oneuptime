# 檢查與對帳

資料表健康說明資料表是否在變更。**檢查** 說明資料表中保存的內容是否正確，**對帳** 說明資料的兩個複本是否一致，**dbt 的測試** 則回報 dbt 所建置資料表的情況。它們都在資料庫的收集執行的地方執行（由 OneUptime 或其探測器執行），離開資料庫的只有一個數字。

## 檢查

在資料表的 **檢查** 索引標籤上新增檢查：

| 檢查 | 讀取的內容 |
| --- | --- |
| **Null Percent** | 該欄為空的列所占的百分比 |
| **Duplicate Percent** | 與其他列的值重複的值所占的百分比 |
| **Distinct Count** | 該欄包含多少個不同的值 |
| **最小值**、**最大值**、**平均**、**總和** | 數值欄的相應值（沒有列時總和為 0） |
| **Invalid Percent** | 不在你提供的清單中的值所占的百分比 |
| **Format Mismatch Percent** | 不符合規則運算式的值所占的百分比（SQL Server 以外的所有引擎） |
| **Orphan Count** | 其值在另一個資料表的欄中找不到相符項目的列 |
| **Row Count** | 資料表中的列數，搭配 **Segment By** 使用最有用 |
| **自訂 SQL** | 你的一個唯讀 SELECT 所傳回、名為 `value` 的數字（在 MongoDB 中為聚合管線傳回的數字） |

每個檢查每 15 分鐘、每小時、每 6 小時或每天執行一次，作為一個彙總陳述式，在設有陳述式逾時的唯讀交易中執行。它的值會寫入為 `oneuptime.data.check.value`，並帶有 `oneuptime.data.check.id`、`oneuptime.data.check.name` 和 `oneuptime.data.check.segment`。

## 建議的檢查

同一個索引標籤上的 **Suggested Checks** 會只根據欄的名稱和類型，提供資料表的欄所需要的檢查：id 是唯一的、`customer_id` 在 `customers` 中有相符的列、電子郵件看起來像電子郵件、金額不是負數、狀態保持其通常的值，以及依租用戶拆分的資料表依租用戶計數。你可以新增一個、全部新增，或永久隱藏某一個。

## 用一句話撰寫檢查

**用一句話撰寫檢查** 會把「訂單的總額從不為負」這樣的規則，以你的引擎本身的 SQL 轉換成計算違反該規則之列的自訂 SQL 檢查，並在有任何違反時發出警示。在以 **新增檢查** 新增之前，你可以先閱讀查詢，它也受到與任何自訂 SQL 檢查相同的所有限制。這需要為專案開啟 OneUptime AI。

## 區段

**Segment By** 會針對某一欄的每個值（例如租用戶或區域）各執行一次檢查：最大的 100 個區段各有一個序列和一個警示。分區段的 Row Count 檢查會在某個租用戶停止傳送資料、而其他租用戶仍持續傳送時發出警示。

## 檢查的警示

設定 **Alert When** 以針對檢查發出警示：

- **Unusually High** 或 **Unusually Low** 會把每個值與它自己在每週該時段學習到的基準線進行比較。
- **高於** 或 **低於** 會把它與閾值進行比較。

儲存檢查時，會以你的身分、依你的權限為它建立一個指標監測器。清除該條件會移除該監測器。

## 對帳

複本會產生偏差：資料倉儲中的訂單比應用程式的資料庫少，或一次移轉遺失了列。對帳會在 **對帳** 下比較兩個資料表（位於同一個資料庫或兩個資料庫中）的一個量值：

- **Row Count**
- 某一欄的 **總和**
- 某一欄的 **Distinct Count**
- **自訂 SQL**：傳回一個名為 `value` 之數字的唯讀查詢

它有一個容差：一個 **絕對值** 數量，或來源值的一個 **百分比**。每一端都由對帳建立並維護的專屬檢查讀取，並隨其資料庫的收集一起進行，因此對帳可以把你網路中的 PostgreSQL 資料表與它在 Snowflake 中的複本進行比較。兩個值都在彼此相隔 15 分鐘內被讀取後，才會進行比較。對帳會寫入：

- `oneuptime.data.reconciliation.drifted`：兩者的偏差超出容差時為 1，一致時為 0。它的監測器讀取的就是這個值。
- `oneuptime.data.reconciliation.difference`：目標的值減去來源的值。
- `oneuptime.data.reconciliation.difference_percent`：該差值占來源值的百分比。

依排程載入的複本會落後其來源：可以用自訂 SQL 比較兩者都已穩定的量值，例如一小時以前的列，或在容差中為延遲預留空間。

## dbt 測試

dbt 建置完成後，`oneuptime dbt upload` 會傳送專案的建置成品（請參閱 [血緣與管線](/docs/data-observability/lineage-and-pipelines)）。之後，受監看資料表的每個測試都會顯示在該資料表的 **檢查** 索引標籤上，並附上它的最新結果和它找到的失敗列。選擇 **Alert on Failures**，即可讓失敗的測試開啟一個警示。
