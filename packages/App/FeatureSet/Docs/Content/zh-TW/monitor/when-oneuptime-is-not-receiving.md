# OneUptime 未接收資料時

當 OneUptime 重新啟動、升級或處理積壓的資料時，您的代理程式、收集器、探測器和心跳傳送端送出的任何內容都無法到達您的監控器。OneUptime 會記錄這種情況發生的時間，且從不把這段時間算到伺服器、主機或任何其他資源頭上：這段時間沒有被監控，所以不是停機時間。

## 運作方式

每個接收資料的 OneUptime 程序，只要能連線到存放資料的資料庫，就會每 30 秒記錄一次自己正在接收。OneUptime 會排除三類時間：

- 未接收：超過 90 秒沒有任何程序記錄。OneUptime 當時已停止、正在重新啟動或升級，或無法連線到它的某個資料庫。
- 重新連線：OneUptime 恢復接收後的最初 2 分鐘，此時代理程式正在重新連線並傳送它們保留的資料。
- 追趕：當等待處理的資料佇列落後超過一分鐘時，從佇列中仍在等待的最早資料算起的時間。

```mermaid title="OneUptime 排除的時間"
flowchart LR
    receiving["接收中"] -->|"90 秒沒有記錄"| down["未接收"]
    down -->|"有程序重新記錄"| grace["重新連線 2 分鐘"]
    grace --> again["接收中"]
```

不到 90 秒的重新啟動不算中斷：收集器會重新傳送未能送達的資料。

## 這段時間內的變化

| 位置 | OneUptime 的做法 |
| --- | --- |
| 伺服器 / 虛擬機器監控器 | **Is Online** 只計算 OneUptime 正在接收的分鐘數：預設情況下，伺服器在 OneUptime 本來能聽到的 3 分鐘沉默之後才算離線。 |
| 傳入請求與傳入郵件監控器 | **Recieved In Minutes** 和 **Not Recieved In Minutes** 只計算 OneUptime 正在接收的分鐘數。符合這類條件時，其原因會說明有多少分鐘被排除。 |
| 主機、Kubernetes、Docker、指標、日誌、追蹤以及其他讀取遙測資料的監控器 | 若檢查視窗中包含 OneUptime 未接收的時間，檢查會等待這段時間移出視窗，但在這段時間結束後最多等待 15 分鐘。在此之前一切不變：狀態不變，也不會開啟或解決任何事件或警示。當佇列落後時，檢查讀取到佇列所在的位置，而不是讀取到現在。 |
| 主機、叢集與其餘資產 | 只有在 OneUptime 正在接收期間，資源的沉默閾值（大多數為 15 分鐘）過去之後，資源才會變為 **已中斷**。 |
| 探測器與 AI 代理 | 在 OneUptime 正在接收期間沉默 3 分鐘後變為 **已中斷**。 |
| 主機、Docker 與 Podman 主機以及 Kubernetes 叢集的 **可用性** 圖表 | 這段時間以 **未監控** 的陰影顯示，折線在此處斷開，而不是跌到停機。正常運作時間徽章不計入這段時間；有資料的區間仍算作正常。 |
| 狀態頁面的正常運作時間與 SLO | 兩者都根據監控器狀態計算：沒有錯誤的狀態變化，就沒有錯誤的停機時間。 |

> [!NOTE]
> 排除時間並不是填補時間。在 OneUptime 無法聽到某個資源的時間裡，該資源絕不會顯示為正常：這段時間只是不做判斷。一旦 OneUptime 恢復接收，真正停機的資源會從那時起依據它傳送或沒有傳送的內容來判斷。

## 自架安裝

### 啟動時

OneUptime 程序啟動期間，會對狀態檢查以外的所有請求回應 `503 Service Unavailable` 和 `Retry-After: 5`，瀏覽器會收到一個自動重新載入的頁面。OpenTelemetry 收集器和 SDK 會重新傳送這樣的請求，而不是丟棄資料。`/status/ready` 在程序就緒之前一直失敗，因此 Kubernetes 在此之前不會將流量送給它。

### Worker 副本

只有傳入流量能夠到達的程序才會記錄 OneUptime 正在接收。若您執行的副本只處理佇列、前面沒有 ingress，請在這些副本上將 `RECEIVES_INGRESS_TRAFFIC` 設為 `false`。否則，在所有接收流量的副本都停機時它們仍會繼續記錄，這次故障又會算到您的資源頭上。Helm chart 已在它的 worker Pod 上設定此項，單一 OneUptime 容器則不需要任何設定。

```yaml title="Worker 容器"
env:
  - name: RECEIVES_INGRESS_TRAFFIC
    value: "false"
```

### 記錄的內容

當您升級到包含此記錄的版本時，OneUptime 開始保存這份記錄；之前的時間仍按原來的方式判斷。當沒有任何程序記錄自己正在接收時，自最後一次記錄以來的時間最多按一小時的中斷處理；之後沉默會重新計算，因此不再寫入的記錄無法長時間掩蓋資源的故障。記錄保留 400 天，當 OneUptime 無法讀取它們時，會按一直在接收的情況來判斷沉默。
