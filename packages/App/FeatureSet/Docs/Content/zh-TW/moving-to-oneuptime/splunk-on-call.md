# 從 Splunk On-Call 移轉

**從其他工具匯入** 只需幾分鐘就能把你的 Splunk On-Call（原名 VictorOps）設定搬到 OneUptime。使用你的 API ID 和一把唯讀 API 金鑰，OneUptime 會讀取你的使用者、團隊、輪換和上報策略，顯示找到的內容，並建立你勾選的內容。Splunk On-Call 中的任何內容都不會變更。

:::cards
- [匯入你的帳戶](#匯入你的-splunk-on-call-帳戶): 建立金鑰、讀取你的帳戶，並勾選要匯入的內容。
- [會匯入什麼](#會匯入什麼): 每筆 Splunk On-Call 記錄在 OneUptime 中會變成什麼。
- [完成移轉](#完成移轉): 匯入完成後要做的事。
:::

## 運作方式

```mermaid title="從 Splunk On-Call API 金鑰到報告"
flowchart TB
    key["API ID 和<br/>唯讀 API 金鑰"] --> read["OneUptime 讀取<br/>你的 Splunk On-Call 帳戶"]
    read --> preview["你查看找到的內容<br/>並勾選要匯入的內容"]
    preview --> import["匯入在<br/>背景執行"]
    import --> report["報告連結到<br/>建立的每筆記錄"]
```

- **金鑰只使用一次。** OneUptime 讀取你的帳戶期間，金鑰會與 API ID 一起加密保存；讀取一結束，無論成功與否，金鑰都會立即刪除。它不會再次顯示，也不會寫入任何記錄檔。
- **OneUptime 只讀取。** 它只呼叫 Splunk On-Call 自己的 API：`api.victorops.com`。Splunk On-Call 對每類請求每秒最多回應兩次，因此 OneUptime 會維持這個節奏；當 Splunk On-Call 要求放慢速度時，它會等待後再試。
- **在你開始匯入之前，不會建立任何內容。** 預覽會為每一項顯示：它是新的、已在 OneUptime 中（並按原樣使用）、已由先前的匯入帶入，或者無法匯入的原因。
- **再次執行絕不會重複建立。** OneUptime 會依 Splunk On-Call ID 記住每次匯入帶入的內容。在 Splunk On-Call 中新增人員或輪換後再次執行，只會建立新的內容。

## 開始之前

- **一個 OneUptime 專案，以及建立所匯入內容的權限。** 專案擁有者和專案管理員可以匯入所有內容。其他角色也可以執行匯入，並匯入他們有權建立的記錄類型。其餘內容會顯示為不匯入，並附上原因。
- **你的 Splunk On-Call API ID 和一把唯讀 API 金鑰。** 兩者都在 Splunk On-Call 的 **Integrations** > **API** 中。匯入絕不會寫入 Splunk On-Call，因此唯讀金鑰就足夠了。

## 匯入你的 Splunk On-Call 帳戶

:::steps
### 在 Splunk On-Call 中建立 API 金鑰
在 Splunk On-Call 中依序開啟 **Integrations** > **API**。你的 API ID 顯示在 API 金鑰上方。新建一把名為 `OneUptime import` 的 API 金鑰，勾選 **Read-only**，然後複製 API ID 和金鑰。

### 開啟匯入頁面
在 OneUptime 中依序開啟 **專案設定** > **從其他工具匯入**，然後選擇 **Splunk On-Call**。

### 連線 Splunk On-Call
將 API ID 貼到 **Splunk On-Call 的 API ID** 中，將金鑰貼到 **Splunk On-Call API 金鑰** 中，然後選擇 **讀取我的 Splunk On-Call 帳戶**。較大的帳戶需要幾分鐘，讀取期間你可以離開頁面。

### 勾選要匯入的內容
預覽依類型分區列出找到的內容。所有將被建立的內容一開始都已勾選，但不在任何團隊、輪換或上報策略中的人員除外。每一項下面，OneUptime 會說明哪些內容不會原樣匯入。當勾選的項目用到了你未勾選的內容時，它會提示，**一併勾選** 可以把它們勾選起來。

### 開始匯入
如果要邀請人員，請在 **將新成員邀請到** 中選擇他們加入的團隊。然後選擇 **開始匯入**。匯入在背景執行：你可以離開頁面，報告會在那裡等你。
:::

報告會統計已建立、已邀請和未匯入的數量，並列出每一項及其對應記錄的連結，失敗的排在最前面。先前的匯入列在同一頁面的 **先前的匯入** 下。

## 會匯入什麼

| Splunk On-Call 中 | OneUptime 中 | 方式 |
| --- | --- | --- |
| 使用者 | 專案成員 | 依電子郵件地址比對。尚未加入專案的人會被邀請加入你選擇的團隊。 |
| 團隊 | 團隊 | 連同成員一起建立。專案中已有同名團隊時按原樣使用，其成員保持不變。 |
| 輪換 | 待命排程 | 每個輪換都會成為一個歸其團隊擁有的排程，其中每個班次都會成為一個層，人員、開始時間、交接以及待命的日期和時段保持不變。現在在 Splunk On-Call 中待命的人，在 OneUptime 中也在待命。 |
| 上報策略 | 待命策略 | 歸策略所屬團隊擁有。每個步驟都會成為一條上報規則，呼叫相同的輪換和使用者。步驟的逾時時間成為該步驟之前的等待時間，中間沒有逾時的步驟會一起呼叫。 |

同一輪換中同時待命的班次會各自成為一個 OneUptime 排程，因為 OneUptime 的排程同一時間只有一人待命。原本呼叫該輪換的每個待命策略都會呼叫所有這些排程。排程沿用輪換中第一個班次的時區，其他時區的班次會把時段換算到這個時區。

## 不會匯入什麼

- **事件、警示及其歷史。** OneUptime 從你的設定開始，而不是從過去的事件開始。
- **整合、routing keys 和 alert rules。** 請改為將你的監測器和警示來源指向 OneUptime，請見 [完成移轉](#完成移轉)。
- **已排定的覆寫。** 匯入後，在 OneUptime 中新增你仍然需要的覆寫。
- **每個人的呼叫策略。** 每個人在接受邀請後，在自己的 **使用者設定** 中選擇被呼叫的方式。
- **OneUptime 中沒有完全對應項目的步驟。** 呼叫 webhook 或轉到另一個上報策略的步驟不會匯入，寄信到不屬於任何被匯入人員之地址的步驟也不會匯入。呼叫下一位或上一位待命人員的步驟會呼叫目前待命的人，預覽會說明有哪些變化。

## 限制

一次匯入最多建立 2,000 筆記錄：最多 500 人、200 個團隊、200 個待命排程和 200 個待命策略。超出限制的內容會顯示為不匯入。再次執行匯入即可帶入其餘部分。

在 OneUptime Cloud 上，你的方案不包含的記錄會顯示為不匯入，並註明所需的方案。

預覽保留一天。只有讀取帳戶的人才能勾選內容並開始匯入。專案擁有者和專案管理員可以看到每次匯入的進度和報告。

## 完成移轉

:::steps
### 檢查待命排程
在 **待命** > **待命排程** 中開啟每個排程，檢查現在是誰待命、接下來是誰。

### 確保每個人都能被呼叫
被邀請的人接受邀請後，新增用來接收呼叫的電話號碼、電子郵件地址或行動應用程式。**待命** > **就緒狀態** 會顯示哪些人還聯絡不上。

### 將警示傳送到 OneUptime
將你的監測器和發出警示的工具指向 OneUptime，並呼叫自己一次進行測試。

### 在 Splunk On-Call 中關閉呼叫
當 OneUptime 能呼叫到正確的人後，請在 Splunk On-Call 中關閉通知，以免有人被重複呼叫。
:::

## 疑難排解

:::details Splunk On-Call 不接受 API ID 和 API 金鑰
請檢查你是否從 **Integrations** > **API** 複製了 API ID 和完整的金鑰，以及該金鑰是否已在那裡被刪除。然後選擇 **再試一次**。
:::

:::details 預覽中缺少某類記錄
金鑰無法讀取該類記錄，預覽頂端會說明這一點。請在 **Integrations** > **API** 中檢查金鑰，然後重新讀取帳戶。
:::

:::details 有些項目無法勾選
每一項都會說明原因：專案中已有的名稱、先前的匯入已帶入的內容，或者你無權建立、或你的方案不包含的記錄。
:::
