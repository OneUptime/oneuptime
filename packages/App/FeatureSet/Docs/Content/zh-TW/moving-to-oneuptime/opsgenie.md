# 從 Opsgenie 移轉

Atlassian 正在停用 Opsgenie：Opsgenie 自 2025 年 6 月起停止銷售，並將於 2027 年 4 月結束支援。OneUptime 可以成為你的待命團隊的新家，**從其他工具匯入** 只需幾分鐘就能把團隊搬過來。使用一把唯讀的 Opsgenie API 金鑰，OneUptime 會讀取你的使用者、團隊、排程、上報和服務，顯示找到的內容，並建立你勾選的內容。Opsgenie 中的任何內容都不會變更。

:::cards
- [匯入你的帳戶](#匯入你的-opsgenie-帳戶): 建立金鑰、讀取你的帳戶，並勾選要匯入的內容。
- [會匯入什麼](#會匯入什麼): 每筆 Opsgenie 記錄在 OneUptime 中會變成什麼。
- [完成移轉](#完成移轉): 匯入完成後要做的事。
:::

## 運作方式

```mermaid title="從 Opsgenie API 金鑰到報告"
flowchart TB
    key["唯讀 API 金鑰<br/>和區域"] --> read["OneUptime 讀取<br/>你的 Opsgenie 帳戶"]
    read --> preview["你查看找到的內容<br/>並勾選要匯入的內容"]
    preview --> import["匯入在<br/>背景執行"]
    import --> report["報告連結到<br/>建立的每筆記錄"]
```

- **金鑰只使用一次。** OneUptime 讀取你的帳戶期間，金鑰會加密保存；讀取一結束，無論成功與否，金鑰都會立即刪除。它不會再次顯示，也不會寫入任何記錄檔。
- **OneUptime 只讀取。** 它只呼叫 Opsgenie 自己的 API：`api.opsgenie.com`，歐洲帳戶則是 `api.eu.opsgenie.com`。當 Opsgenie 要求放慢速度時，它會等待後再試。
- **在你開始匯入之前，不會建立任何內容。** 預覽會為每一項顯示：它是新的、已在 OneUptime 中（並按原樣使用）、已由先前的匯入帶入，或者無法匯入的原因。
- **再次執行絕不會重複建立。** OneUptime 會依 Opsgenie ID 記住每次匯入帶入的內容。在 Opsgenie 中新增人員或排程後再次執行，只會建立新的內容。

## 開始之前

- **一個 OneUptime 專案，以及建立所匯入內容的權限。** 專案擁有者和專案管理員可以匯入所有內容。其他角色也可以執行匯入，並匯入他們有權建立的記錄類型。其餘內容會顯示為不匯入，並附上原因。
- **一把具有 Read 和 Configuration access 權限的 Opsgenie API 金鑰。** 有了 Configuration access，金鑰才能讀取使用者、團隊、排程和上報。匯入絕不會寫入 Opsgenie。
- **你的 Opsgenie 區域。** 如果你在 `app.eu.opsgenie.com` 登入，你的帳戶在歐洲；否則在美國。

## 匯入你的 Opsgenie 帳戶

:::steps
### 在 Opsgenie 中建立 API 金鑰
在 Opsgenie 中依序開啟 **Settings** > **API key management**，然後選擇 **Add new API key**。將它命名為 `OneUptime import`，只授予 **Read** 和 **Configuration access**，然後複製金鑰。

### 開啟匯入頁面
在 OneUptime 中依序開啟 **專案設定** > **從其他工具匯入**，然後選擇 **Opsgenie**。

### 連線 Opsgenie
在 **你的 Opsgenie 帳戶在哪裡？** 下選擇 **美國** 或 **歐洲**。將金鑰貼到 **Opsgenie API 金鑰** 中，然後選擇 **讀取我的 Opsgenie 帳戶**。較大的帳戶需要幾分鐘，讀取期間你可以離開頁面。

### 勾選要匯入的內容
預覽依類型分區列出找到的內容。所有將被建立的內容一開始都已勾選，但在 Opsgenie 中關閉的排程，以及不在任何團隊、排程或上報中的人員除外。每一項下面，OneUptime 會說明哪些內容不會原樣匯入。當勾選的項目用到了你未勾選的內容時，它會提示，**一併勾選** 可以把它們勾選起來。

### 開始匯入
如果要邀請人員，請在 **將新成員邀請到** 中選擇他們加入的團隊。然後選擇 **開始匯入**。匯入在背景執行：你可以離開頁面，報告會在那裡等你。
:::

報告會統計已建立、已邀請和未匯入的數量，並列出每一項及其對應記錄的連結，失敗的排在最前面。先前的匯入列在同一頁面的 **先前的匯入** 下。

## 會匯入什麼

| Opsgenie 中 | OneUptime 中 | 方式 |
| --- | --- | --- |
| 使用者 | 專案成員 | 依電子郵件地址比對。尚未加入專案的人會被邀請加入你選擇的團隊。被封鎖的使用者不會匯入。 |
| 團隊 | 團隊 | 連同成員一起建立。專案中已有同名團隊時按原樣使用，其成員保持不變。 |
| 排程 | 待命排程 | 每個輪換都會成為一個層，人員、開始時間、輪次長度和時間限制保持不變，使用排程的時區，並歸排程所屬團隊擁有。 |
| 上報 | 待命策略 | 每條規則都會成為一條上報規則，呼叫相同的排程、使用者或團隊。延遲相同的規則一起呼叫，下一條上報規則之前的等待時間為兩次延遲之差。上報的重複次數成為策略的重複次數。 |
| 服務 | 服務 | 在服務目錄中建立，歸其團隊擁有。 |

如果排程的輪換會讓兩個人同時待命，它會依每個輪換拆分成一個 OneUptime 排程，因為 OneUptime 的排程同一時間只有一人待命。原本呼叫該排程的每個待命策略都會呼叫所有這些排程。

## 不會匯入什麼

- **警示、事件及其歷史。** OneUptime 從你的設定開始，而不是從過去的警示開始。
- **整合、心跳、警示策略和路由規則。** 請改為將你的監測器和警示來源指向 OneUptime，請見 [完成移轉](#完成移轉)。
- **排程的覆寫，以及已經結束的輪換。** 匯入後，在 OneUptime 中新增你仍然需要的覆寫。
- **每個人的通知規則。** 每個人在接受邀請後，在自己的 **使用者設定** 中選擇被呼叫的方式。
- **OneUptime 中沒有完全對應項目的步驟。** 呼叫下一位待命人員或團隊管理員的規則，會以 OneUptime 中最接近的方式匯入，預覽會說明有哪些變化。

## 限制

一次匯入最多建立 2,000 筆記錄：最多 500 人、200 個團隊、200 個待命排程、200 個待命策略和 500 個服務。超出限制的內容會顯示為不匯入。再次執行匯入即可帶入其餘部分。

在 OneUptime Cloud 上，你的方案不包含的記錄會顯示為不匯入，並註明所需的方案。

預覽保留一天。只有讀取帳戶的人才能勾選內容並開始匯入。專案擁有者和專案管理員可以看到每次匯入的進度和報告。

## 完成移轉

:::steps
### 檢查待命排程
在 **待命** > **待命排程** 中開啟每個排程，檢查現在是誰待命、接下來是誰。

### 確保每個人都能被呼叫
被邀請的人接受邀請後，新增用來接收呼叫的電話號碼、電子郵件地址或行動應用程式。**待命** > **就緒狀態** 會顯示哪些人還聯絡不上。

### 將警示傳送到 OneUptime
將你的監測器和發出警示的工具指向 OneUptime，並呼叫自己一次進行測試。

### 在 Opsgenie 中關閉呼叫
當 OneUptime 能呼叫到正確的人後，請在 Opsgenie 中關閉通知，以免有人被重複呼叫。
:::

## 疑難排解

:::details Opsgenie 不接受 API 金鑰
請檢查你是否複製了完整的金鑰、它是否是 **API key management** 中的金鑰而不是某個整合的金鑰、它是否有 **Read** 和 **Configuration access** 權限，以及你是否選擇了帳戶所在的區域。然後選擇 **再試一次**。
:::

:::details 預覽中缺少某類記錄
金鑰無法讀取該類記錄，預覽頂端會說明這一點。請為金鑰授予 **Configuration access**，然後重新讀取帳戶。
:::

:::details 有些項目無法勾選
每一項都會說明原因：被封鎖的使用者、專案中已有的名稱、先前的匯入已帶入的內容，或者你無權建立、或你的方案不包含的記錄。
:::
