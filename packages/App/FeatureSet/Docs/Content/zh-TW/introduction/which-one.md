# 該用哪一個？

OneUptime 中有些東西看起來很相似。本頁把每組相似的東西並排列出，並說明每一個的用途，讓你第一次就選對。每張表格都能在一個畫面內看完，表格的第一欄會開啟完整介紹該選項的頁面。

:::cards
- [事件、警示還是其他類型的問題？](#事件警示還是其他類型的問題): 問題在 OneUptime 中會變成什麼。
- [工作流程、操作手冊、劇本還是 AI 規則？](#工作流程操作手冊劇本還是-ai-規則): 要用什麼來自動化。
- [監測器群組、服務還是標籤？](#監測器群組服務還是標籤): 如何將你監控的內容分組。
- [探測器、代理程式、收集器還是 Runner？](#探測器代理程式收集器還是-runner): 要安裝什麼，以及每一個使用哪種金鑰。
- [儀表板、公開儀表板還是狀態頁面？](#儀表板公開儀表板還是狀態頁面): 要分享什麼，以及分享給誰。
:::

## 事件、警示還是其他類型的問題？

大多數問題不是事件就是警示：依問題影響的是誰來選擇。其他幾種是 OneUptime 為你保存的紀錄，它們每一種都可能引發事件或警示。

| 紀錄 | 是什麼 | 何時使用 |
| --- | --- | --- |
| [事件](/docs/incidents/index) | 影響使用者的問題。它可以呼叫待命人員，並顯示在你的狀態頁面上。 | 客戶已經察覺或很快就會察覺：服務中斷、變慢、結帳失敗。 |
| [警示](/docs/alerts/index) | 需要團隊處理的問題。它可以呼叫待命人員，但絕不會顯示在狀態頁面上。 | 團隊應在使用者察覺之前採取行動：快要寫滿的磁碟、即將到期的憑證。 |
| [片段](/docs/incidents/episodes) | 一組相關的事件或相關的警示，當作一個整體處理。 | 一個原因引發了許多事件或警示。分組規則會為你開啟片段。 |
| [例外](/docs/telemetry/exceptions) | 你的程式碼擲回的某個錯誤的每次發生，歸為一組，並附有堆疊追蹤。 | 你想修正一個錯誤。錯誤暴增時，例外監測器可以建立警示或事件。 |
| [AI 洞察](/docs/ai/ai-sre#洞察主動偵測) | OneUptime 在任何呼叫發生之前就在你的遙測中發現的問題，例如錯誤日誌暴增。 | 你想要及早收到警訊。洞察絕不會呼叫任何人，也絕不會開啟事件：它會在收件匣中等待。 |
| [安全案例](/docs/telemetry/security-cases) | 一個值得調查的威脅，關於同一個使用者、主機或位址的每次偵測都歸入其中。 | 你的資安團隊進行調查。使用者受到影響時，在案例上按下 **宣告事件** 即可開啟一個事件。 |

警示可以連結到它最終證實所屬的事件，因此從警示開始不會遺漏任何資訊。

## 工作流程、操作手冊、劇本還是 AI 規則？

這四種都可以自動執行。依它們作用的對象，以及步驟由誰撰寫來選擇。

| 工具 | 做什麼 | 何時使用 |
| --- | --- | --- |
| [工作流程](/docs/workflows/index) | 畫布上的區塊，在其觸發器觸發時執行：事件被建立、排程時間到了、其他工具呼叫一個 URL。 | 你想把 OneUptime 連接到其他工具，或對它的紀錄採取動作，而不必撰寫程式碼。 |
| [操作手冊](/docs/runbooks/index) | 把你的應變程序寫成步驟，從手動檢查清單到指令碼、HTTP 請求和 kubectl，在事件、警示或維護活動上執行。 | 應變人員每次都應遵循相同的步驟。Runbook 規則會在相符的事件上啟動操作手冊。 |
| [劇本](/docs/telemetry/security-cases#劇本) | 回應安全案例的步驟：保全證據、呼叫待命人員、停用使用者。 | 你的資安團隊每次都以相同的方式回應同一類威脅。 |
| [AI 規則](/docs/ai/ai-sre#哪些事件會被調查和修正) | 決定 OneUptime AI 調查並修復哪些新的事件和警示，以及是否要先詢問。 | OneUptime AI 只應處理部分事件，或不經詢問就進行修復。沒有規則時，它會調查每一個。 |

## 監測器群組、服務還是標籤？

這三種都能把東西歸在一起，但對象是不同的讀者。它們也可以搭配使用：一項服務的監測器可以組成一個監測器群組，而它們都可以帶有同一個標籤。

| 選項 | 是什麼 | 何時使用 |
| --- | --- | --- |
| [監測器群組](/docs/monitor/monitor-groups) | 把多個監測器彙總為一個狀態（取其中最差的），並擁有自己的正常運作時間。 | 對於由多個監測器組成的東西（例如 Checkout），客戶應在狀態頁面上只看到一列。 |
| [服務](/docs/telemetry/services) | OneUptime 在你的遙測中發現的應用程式，它的日誌、追蹤、指標、事件和擁有者都在一個頁面上。 | 你想把關於一個應用程式的一切放在同一個地方。它會根據自己的 `service.name` 自動出現。 |
| [標籤](/docs/configuration/label-and-owner-rules) | 你加在監測器和大多數其他紀錄上的標記。一筆紀錄可以帶有多個標籤。 | 你想篩選清單、限制團隊的權限，或在規則中挑出紀錄。 |

監測器群組預設為關閉：在 **專案設定 → 進階 → 功能旗標** 下開啟它們。

## 探測器、代理程式、收集器還是 Runner？

OneUptime 的大部分功能都不需要安裝任何東西：只有在需要連到 OneUptime 從外部看不到的內容時，才需要安裝。每一種都會對外連線，並使用自己那一類的金鑰。

| 安裝項目 | 做什麼 | 何時安裝 | 使用的金鑰 |
| --- | --- | --- | --- |
| [自訂探測器](/docs/probe/custom-probe) | 在你的網路內部執行監測器的檢查。 | 你要檢查的內容位於防火牆後方。OneUptime 自己的探測器檢查公開的內容。 | 它自己的探測器 ID 和金鑰 |
| [基礎設施代理程式](/docs/monitor/server-monitor) | 向 Server / VM 監測器回報一台機器的 CPU、記憶體、磁碟和處理程序。 | 你想為一台伺服器設定一個監測器，並針對它的數值設定條件。 | 該監測器的秘密金鑰 |
| [OpenTelemetry Collector](/docs/telemetry/hosts) | 傳送機器的指標、日誌和處理程序。**新增主機** 用一個指令安裝它。 | 你想讓一台機器連同它的遙測出現在 **主機** 下。 | 擷取金鑰 |
| [Kubernetes 代理程式](/docs/telemetry/kubernetes-agent) | 收集叢集的指標、事件、日誌和追蹤。你用 Helm 安裝它。 | 你在執行 Kubernetes。 | 擷取金鑰 |
| [Runner](/docs/runbooks/agents) | 在你的基礎設施內部執行操作手冊步驟，例如 Bash、SSH 和 kubectl。 | 你的操作手冊需要連到你自己的主機和叢集。 | 它自己的 Runner ID 和金鑰 |

### 擷取金鑰還是 API 金鑰？

| 金鑰 | 它讓你做什麼 | 在哪裡建立 |
| --- | --- | --- |
| [擷取金鑰](/docs/telemetry/ingestion-keys) | 把遙測傳送到專案，僅此而已。 | **專案設定 → 遙測與 APM → 擷取金鑰** |
| [API 金鑰](/docs/permissions/index#api-金鑰) | 透過 API、CLI、Terraform 或 AI 助理讀取和變更專案，權限由你授予。 | **專案設定 → 進階 → API 金鑰** |

兩者都無法取代對方。

## 儀表板、公開儀表板還是狀態頁面？

依誰應該看到它來選擇。

| 分享方式 | 誰看得到 | 何時使用 |
| --- | --- | --- |
| [儀表板](/docs/dashboards/index) | 登入你專案的人。 | 你的團隊查看圖表和清單：值班螢幕、團隊自己的檢視。 |
| [公開儀表板](/docs/dashboards/sharing) | 任何擁有連結的人，除非你加上密碼、限制只有某些 IP 位址可以存取，或在你自己的網域上代管它。 | 專案以外的人應該看到你的圖表，例如合作夥伴或牆上的螢幕。 |
| [狀態頁面](/docs/status-pages/index) | 你的客戶，可以公開，也可以只對你允許的私人使用者開放。 | 客戶想知道你的服務是否正常運作，並希望收到有關事件和維護的通知。 |

狀態頁面用事件和你為監測器取的名稱來溝通；儀表板則顯示它們背後的數字。
