# 設定與安全

在你把工作流程接上真實流量之前，本頁介紹值得先弄清楚的設定與安全限制。

## 把工作流程打開或關掉

每個工作流程在 **設定** 裡都有一個 **已啟用** 開關。關掉時工作流程不會執行——webhook 呼叫、排程時間點與 OneUptime 事件全都會被忽略。新建立的工作流程一開始是停用的。

把這個開關當成你的「可以上線了」關卡：

1. 把工作流程做好。
2. 在 **建構器** 上用貼近真實的值點擊 **執行工作流程**。
3. 檢查 **日誌**——確認每個區塊都走到你預期的地方。
4. 把 **已啟用** 打開。

把工作流程關掉不會中止已經在跑的執行；它只是不讓新的執行開始。

## 擁有者與標籤

- **擁有者**——被列為擁有者的使用者與團隊可以存取這個工作流程，並可以選擇在它失敗時收到通知。在 **設定 → 擁有者** 底下設定。
- **標籤**——用來替工作流程分組的標記。工作流程清單可以依標籤篩選，這讓忙碌的專案好逛很多。當你的工作流程是依團隊、依整合或依環境來組織時特別有用。
- **標籤規則**——在 **工作流程 → 設定 → 標籤規則** 底下，依名稱或描述的樣式自動替新工作流程套上標籤。
- **擁有者規則**——在 **工作流程 → 設定 → 擁有者規則** 底下，自動替新工作流程指派擁有者。

## 密鑰

如果某個全域變數裝著敏感內容，就把它標記為 **密鑰**。儲存之後，這個值在一般的 API 與 UI 讀取中都會被隱藏，而工作流程的日誌也會在寫入執行紀錄之前把解析出來的值抹除。

以下情況請使用密鑰變數：

- 外部服務的 API 金鑰。
- 驗證權杖。
- Webhook 簽章金鑰。
- 任何你不希望只有唯讀權限的人看到的東西。

不要把密鑰直接貼進區塊裡——像 `Authorization: Bearer eyJh...` 這樣的值最後會出現在工作流程和日誌中，任誰都看得到。請改用 `{{global.variables.MY_SECRET}}`。

## 匯出與匯入工作流程

你可以把工作流程以 JSON 檔的形式在專案之間搬移，或是在自架安裝與 OneUptime Cloud 之間搬移。

- **匯出**——開啟工作流程，使用 **設定** 底下的 **Export Workflow**。你也可以在工作流程清單中選取多個工作流程，一次匯出成同一個檔案。
- **匯入**——在 **工作流程** 清單上點擊 **Import JSON**，然後挑一個從任何 OneUptime 專案匯出的檔案。

這個檔案裝著工作流程的名稱、描述、啟用狀態與它的流程圖。它刻意不包含：

- **webhook 密鑰。** 工作流程建立時會產生一把新的，所以匯入後的工作流程有不同的 webhook 網址。原本呼叫舊網址的東西都得重新指向。
- **全域變數。** 讀取 `{{global.variables.MY_SECRET}}` 的區塊會保留這個參照，但值不在檔案裡。請在執行匯入的工作流程之前，先在目的專案建立這些變數。
- **擁有者與標籤。** 你專案自己的標籤規則與擁有者規則會套用到匯入的工作流程，就跟你親手建立它時一樣。

匯入的工作流程一律以 **已停用** 狀態建立，即使它在匯出來源那邊是啟用的——它的流程圖可能指向目的專案裡根本不存在的監測器、待命策略或其他工作流程。先檢視它、啟用它、用 **執行工作流程** 測一次，然後才讓它一直開著。複製工作流程的行為也一樣，所以在你動手編輯之前，複本絕不會跟著原本那個一起開跑。

由於流程圖是原封不動搬過去的，任何直接打在區塊裡的東西也會跟著走。這就是把憑證放進密鑰變數最實際的理由：匯出一個寫死權杖的工作流程，等於把那個權杖交給拿到檔案的人。

## 一次執行可以跑多久

每一次執行嘗試都有一個實際時間上的期限。執行器在每個元件之前與之後都會檢查它，一旦控制權回來，超時的執行就會被標記為 **Timeout**。會做網路或指令碼工作的元件也需要各自的逾時設定，因為執行器沒辦法強制中斷任意元件的程式碼。

AI 元件的提供者請求逾時是從剩餘的工作流程時間推算出來的，並以 60 秒為上限，留一點餘裕給記錄與收尾。

## 呼叫其他工作流程的限制

**Execute Workflow** 元件讓一個工作流程去呼叫另一個。為了避免 A 呼叫 B、B 又呼叫回 A 這種意外迴圈，鏈的深度有上限。超過限制的執行會以一則明確的錯誤結束。

如果你真的需要一條很長的鏈（例如每次執行處理一個項目的工作），通常更簡單的做法是用 **Custom Code** 在單一工作流程裡跑迴圈。

## Webhook 安全

Webhook 觸發器會給你一個專屬網址。任何知道這個網址的人都能打它。要防範誤觸與不請自來的呼叫方：

- 把這個網址當成密碼看待。不要公開分享，也不要提交到公開儲存庫。
- 對敏感的工作流程，請呼叫方在標頭裡送一個共用權杖（例如 `X-Webhook-Token`），並在做任何重要動作之前先用 **條件** 區塊檢查它。把預期的權杖存成密鑰變數。
- 對非常敏感的工作流程，寧可用 OneUptime 事件觸發器加上手動匯入的步驟，也別開一個公開的 webhook。

## 對外網路存取

API 與其他 HTTP 區塊的請求是從 OneUptime 發出的。如果你是自架，請確認你的安裝連得到你要呼叫的服務。如果你用 OneUptime Cloud，我們的對外 IP 範圍列在 [IP 位址](/docs/configuration/ip-addresses)，你可以在對方那端把它們放行。

## AI 元件

**Generate Text with AI** 會透過 OneUptime 設定好的 LLM 閘道送出一個請求。它使用專案的預設 LLM 提供者；專案若沒有，則使用整個安裝的全域提供者。請在 **專案設定 → 人工智慧 → LLM 提供商** 底下設定提供者；絕對不要把提供者的 API 金鑰或任意的模型端點放進工作流程本身。

AI 元件有一條明確的資料外送邊界：

- OneUptime 會把一段固定的元件安全指示，加上解析後的 **System Instructions**、**Prompt** 與序列化後的 **Context**，一起送給已設定的提供者。Context 會接在使用者訊息末尾一個明確的標記之後；那段固定指示會說明，該標記之後的一切都是不可信的資料，即使它裡面含有標籤或指令也一樣。
- 它不會自動附上觸發器內容、工作流程歷史、其他元件的輸出、專案記錄、遙測資料或密鑰。只有你在上述三個輸入中參照到的資料才會離開。
- 它不會送出任何工具定義或提供者原生的能力欄位。模型無法透過這個元件查詢 OneUptime、發出 HTTP 請求或變更專案資料。已設定的提供者與模型仍是一條由管理員把關的信任邊界，因此需要嚴格離線生成的安裝，應該選擇本身不帶提供者託管檢索能力的模型。
- 提供者層級的額外參數只限於一份允許清單，內容全是與生成調校有關的欄位。它們不能取代工作流程訊息、不能加入工具或提供者原生的網頁搜尋與資料來源、不能啟用非文字模態、不能要求多個候選結果、不能開啟串流、不能透過提供者的儲存旗標保留請求，也不能調高這個元件的輸出 token 上限。未知的未來能力欄位一律預設丟棄。
- System Instructions、Prompt、Context 與生成出來的 Response 值，在這個 AI 元件自己於自動工作流程執行日誌中的參數與回傳值項目裡會被遮蔽。執行進行期間，它們仍可供下游元件取用。如果你把其中之一插進另一個元件，適用的就是該元件的日誌政策，它可能會記下解析後的值；請把這種重複使用視為一次刻意的揭露。提供者與模型名稱、token 數量、LLM Log ID 以及安全的錯誤訊息仍會保留，以供維運與計費使用。提供者原始的錯誤內文則不會進入工作流程日誌、LLM 日誌、應用程式日誌與追蹤，因為提供者可能會把請求內容原樣回吐。

請把每一個被參照的變數都當成你有意送給提供者的資料。特別是，除非那樣的揭露確有必要、而且該提供者也獲准接收，否則不要把密鑰全域變數塞進提示或情境裡。像 Ollama 這種自架的本機提供者可以把請求留在你自己的基礎架構內；託管的提供者則是依該提供者的資料處理條款收下這個請求。

每一次呼叫都會記錄在 **專案設定 → 人工智慧 → AI 日誌**，包含提供者、模型、狀態、token、成本與計費資訊。提示與回應的預覽、以及提供者原始的錯誤細節都不會被儲存在 AI 日誌中。透過計費的全域提供者發出的呼叫會消耗專案的 AI 額度餘額。工作流程的 AI 也會計入專案每日的自主 AI token 預算；預算用盡時，元件會直接走 **錯誤** 路徑，不會去聯繫模型。專案的 AI 必須是啟用的。在 OneUptime Cloud 上，訂閱必須是付費的，而且需要 Growth 方案（或含有 Growth 功能的方案）；停用計費的自架安裝則沒有這道方案門檻。

內建的邊界讓無人值守的呼叫不會失控：System Instructions、Prompt 與序列化後的 Context 合計上限為 50,000 個字元；Temperature 必須介於 `0` 到 `1`；Maximum Output Tokens 必須介於 `1` 到 `4096`（預設 `1024`）；提供者請求只嘗試一次，且最多 60 秒後逾時。每個專案同時最多只有三個工作流程 AI 呼叫在跑；超出的呼叫會走 **錯誤** 路徑，可以由之後的工作流程執行重試。驗證、設定、存取、預算、餘額、並行數、提供者與逾時方面的失敗，全都會走 **錯誤** 路徑並填入 **錯誤** 輸出。在啟用正式環境的工作流程之前，請先把那條路徑接起來。

## 權限

工作流程遵循你專案的角色型存取控制。相關的權限有：

- **Create / Read / Edit / Delete Workflow**——對工作流程本身的基本權限。
- **執行工作流程**——手動執行工作流程或透過 API 觸發時需要。
- **Read Workflow Log**——檢視執行紀錄時需要。
- **Read / Create / Edit / Delete Workflow Variable**——對全域變數清單的控制權。

大多數工程師應該對工作流程有建立／編輯／讀取權限，但對變數沒有。把變數的編輯權留給管理專案密鑰的那些人。

## 方案限制

OneUptime Cloud 對較小的方案設有每月執行次數上限。你目前的上限顯示在 **專案設定 → 帳單** 底下。用完之後，新的觸發會被拒絕，直到下一個計費週期。自架安裝沒有這個限制。

## 什麼時候工作流程不是對的工具

有幾種情況你應該改用別的東西：

- **繁重的運算或大型資料集**——工作流程是設計來做輕量的黏合工作，不是拿來算數的。把繁重的工作放在你自己的基礎架構跑，讓工作流程去把它啟動就好。
- **長時間持續運算**——單一次執行嘗試應該很快結束。若只是被動的等待，例如「做 A、等兩小時、再做 B」，請用 **Sleep** 元件；它會把執行保存下來，稍後再恢復，期間不佔用工作者。
- **需要人參與其中、一步一步進行的事件處理**——那是 [Runbook 概觀](/docs/runbooks/index) 的用途。工作流程是給無人值守的自動化用的。
