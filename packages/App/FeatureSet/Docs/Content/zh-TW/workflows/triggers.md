# 觸發器

觸發器是工作流程裡的第一個區塊——它決定工作流程何時執行。每個工作流程都恰好有一個觸發器。你可以從四種當中挑一個。

## Manual

在 **建構器** 頁面點擊 **執行工作流程**、填好觸發器的欄位，再按 **Run Workflow Manually** 確認，就能隨時把工作流程跑起來。Manual 觸發器接受一段 JSON 內容，後面的區塊都讀得到。

適合：你想要有個按鈕的一鍵自動化，像是「輪替這把金鑰」或「送一則測試警示」。

**輸出**：你貼進去的那段 JSON；沒貼的話就是一個空物件。

## Schedule

用 cron 運算式讓工作流程重複執行。

適合：每晚清理、每小時同步、每週報表。

**設定**：一則 cron 運算式。幾個常見的：

- `0 * * * *`——每小時整點。
- `*/5 * * * *`——每 5 分鐘。
- `0 9 * * 1`——每週一早上 9:00。

如果系統短暫無法使用，那次執行會在恢復後立刻補上——短時間的中斷不必擔心錯過的排程點。

## Webhook

OneUptime 會建立一個專屬網址。任何東西打到那個網址就會啟動工作流程。請求的標頭、查詢參數與內文都會被帶進來。

適合：從別的工具把資料收進 OneUptime——CI/CD 回呼、其他監控系統的警示、你 CRM 裡的註冊事件。

**輸出**：

- **請求標頭**——傳入請求的所有標頭。
- **Request Query Params**——解析後的查詢字串。
- **請求內文**——解析後的內文（若不是 JSON 則為原始文字）。

這個網址同時接受 `GET` 與 `POST`。呼叫方會很快收到一個確認回應——工作流程本身在背景執行。

把這個網址當成密碼看待。拿到它的人都能啟動你的工作流程。

## OneUptime 事件觸發器

OneUptime 裡幾乎每一種東西——監測器、事件、警示、排定維護、狀態頁面、待命策略、團隊——都可以觸發工作流程。每一種都提供三個事件：

- **On Create**——新增一筆時觸發。
- **On Update**——變更一筆時觸發。
- **On Delete**——刪除一筆時觸發。

你就是靠這個做出「OneUptime 裡發生 X 時就做 Y」，而不必用迴圈一直去輪詢。

完整的記錄會被傳給下一個區塊。舉例來說，**事件 → On Create** 觸發器會傳出這筆新事件，於是下一個區塊可以讀它的標題、描述、嚴重程度，以及任何其他欄位。

### 團隊最常用的事件

- **事件**——在事件被開啟、更新（認領、解決）或刪除時做出反應。
- **警示**——警示也有同樣的三個事件。
- **監測器**——在監測器被新增、編輯或移除時做出反應。
- **排定維護**——排好維護時段後自動對外公告。
- **狀態頁面 訂閱者**——歡迎剛訂閱狀態頁面的人。
- **On-Call Duty Policy**——把排班異動同步到另一套值班系統。

在 **Add Trigger** 面板中用名稱搜尋，就能找到你要的那一個。

## 我該用哪一種觸發器？

| 如果你想…                           | 就挑                |
| ----------------------------------- | ------------------- |
| 按一個按鈕來執行工作流程            | **Manual**          |
| 依重複的排程執行                    | **Schedule**        |
| 讓另一套系統把資料推進來            | **Webhook**         |
| 對 OneUptime 內部發生的事做出反應   | **OneUptime 事件** |

一個工作流程只能有一個觸發器。如果你需要用兩種方式啟動同一套自動化，就把共用邏輯做成一個工作流程，再用 **Execute Workflow** 元件從兩個很薄的「外殼」工作流程去呼叫它。
