# 片段

片段把相關的事件或相關的警示歸為一組，讓團隊把它們當作一件事來處理：在一個地方檢視，由同一組負責人負責，只需確認和解決一個狀態。分組規則會開啟片段，並在事件和警示到來時把它們加進去（請參閱[事件分組規則](/docs/incidents/settings#事件分組規則)）。你也可以自己把事件放進片段，一次放多個：從片段中新增，或從事件清單中新增。

本頁的一切同樣適用於警示片段：把「事件」讀作「警示」即可。事件片段位於 **事件 → 片段**，警示片段位於 **警示 → 片段**。

## 從片段中新增事件

開啟片段，在側邊選單中選擇 **成員事件**（`/dashboard/{projectId}/incidents/episodes/{episodeId}/incidents`），然後點選 **新增事件**。對話方塊會列出你看得到、且尚未在該片段中的最近 50 個事件，每個都顯示編號、標題、狀態和嚴重程度。要尋找更早的事件，可以依標題或編號搜尋：`INC-42`、`42` 和 `#42` 都能找到事件 42。

- 需要幾個就勾選幾個，一次最多 100 個。按鈕會顯示數量：**新增 3 個事件**。
- 已經在另一個片段中的事件，會在標題下方註明，並列出那個片段的編號。把它新增到這裡，它仍會留在那裡：一個事件可以屬於多個片段。
- 如果有些無法新增，對話方塊會保持開啟，並列出它們和原因；其餘的會被新增。

## 從事件清單中新增事件

在 **事件** 清單或其他任何事件清單（例如某個監視器的事件清單）中選取事件，然後開啟 **批次動作**：

| 動作 | 作用 |
| --- | --- |
| **新增至現有片段** | 選擇一個片段。進行中的片段排在前面，由新到舊，之後是最近已解決的片段；依標題或編號搜尋可以找到其他任何片段。新增之前，對話方塊會說明所選事件中有多少已經在該片段中（維持原樣），有多少在另一個片段中（也會留在那裡）。 |
| **新增至新片段** | 建立一個包含所選事件的片段。它只詢問標題和嚴重程度，兩者都依所選事件中最嚴重的那個預先填好；私人事件的標題絕不會被複製。負責人、值班政策和備註請在片段自己的頁面上新增。 |

兩者都最多接受 100 個所選事件。結果會說明新增了多少、已在片段中的有多少、哪些沒有新增以及原因，並附上開啟該片段的連結。

## 新增會帶來什麼

- **片段的動態中只有一筆記錄**，列出每個新增的事件：前 20 個顯示編號和標題，其餘顯示還有多少個。它只會在片段的 Slack 或 Microsoft Teams 頻道中發布一次，而不是每個事件發布一次。私人事件只顯示編號。
- **每個事件自己的動態** 會記錄它被新增到哪個片段。
- **片段的嚴重程度** 會提高到新增至現有片段的事件中最嚴重的那個，而且從不降低。新片段以你選擇的嚴重程度開始。
- **已解決的片段維持已解決。** 向其中新增不會重新開啟它，新增也從不改變事件的狀態。
- **片段的負責人會收到通知**，得知有事件被新增，就像單獨新增一個事件時一樣。如果片段是連同這些事件一起建立的，片段本身的建立通知就涵蓋了它們。

## 移出事件

在 **成員事件** 中，對某一列點選 **移除**，或在 **批次動作** 中對所選列執行，只會把事件移出這個片段。事件本身不會被刪除，而且仍留在它所屬的其他片段中。

## 誰可以新增

新增需要把事件新增到片段的權限。Project Owner、Project Admin、Project Member、Incident Admin 和 Incident Member 角色都有此權限，具有 Create Incident Episode Member 的自訂角色也有。你只能新增自己看得到的事件：私人事件只能由其負責人以及專案的擁有者和管理員新增。新增至新片段還需要建立片段的權限。你無法使用的動作會被鎖定，其提示會說明缺少哪項權限。

## 使用 API

在一個請求中把多個事件新增到片段：

```bash
curl -X POST 'https://oneuptime.com/api/incident-episode-member/add-incidents' \
  -H "ApiKey: $ONEUPTIME_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "incidentEpisodeId": "<episode id>",
    "incidentIds": ["<incident id>", "<incident id>"]
  }'
```

回應對傳送的每個事件各說明一次：已新增、已在片段中，或未新增及原因。包含超過 100 個 ID 的請求會被拒絕。

```json
{
  "added": ["<incident id>"],
  "alreadyInEpisode": ["<incident id>"],
  "notAdded": [
    {
      "id": "<incident id>",
      "reason": "This incident does not exist in this project, or you do not have access to it."
    }
  ]
}
```

對於警示，把 `alertEpisodeId` 和 `alertIds` 傳送到 `/api/alert-episode-member/add-alerts`。要建立一個已包含事件的片段，在建立片段的請求 `POST /api/incident-episode` 中帶上它們的 ID，形式為 `{ "data": { "title": "Checkout outage" }, "miscDataProps": { "incidentIdsToAdd": ["<incident id>"] } }`；警示片段則使用 `POST /api/alert-episode` 並帶上 `alertIdsToAdd`。只要其中有一個無法新增，就不會建立片段。
