# 資源與群組

資源就是狀態頁面上的一列——一個監測器（或監測器群組），帶著訪客看得懂的名稱、目前的狀態，以及選擇性的正常運作時間數字與歷史圖表。群組則是裝資源的區塊，讓一個掛了四十個監測器的頁面讀起來是「API」、「Web app」和「Data pipeline」，而不是一份看不到底的清單。

這兩者都在同一個畫面上建立。開啟一個狀態頁面，在側邊選單選 **資源**（在沒有啟用監測器群組的專案上，這個項目會寫成 **監測器**）。群組以前有自己的頁面，現在沒有了，舊的 `/groups` 網址會直接轉址到這裡。

把這部分做對，狀態頁面其餘的部分就只是裝飾了。訪客靠這些列判斷「是我的問題還是他們的問題」，所以請用客戶談論你產品時的說法來命名——是 **Checkout API**，不是 `prod-checkout-lb-healthcheck-us-east-1`。

## 資源畫面

畫面一分為二。左邊是列出頁面上所有群組的導覽器，右邊是你所選群組的內容。

- **群組導覽器（左）** —— 一棵群組樹，上方有搜尋框（**Search groups...**），下方有一個即時計數，像是 `3 groups · 12 resources`。當頁面的群組多到放不下時，會出現一個 **Show N more of M** 按鈕展開其餘的。
- **Top of page** —— 導覽器裡的第一列。它裝的是不屬於任何群組的資源，工具提示也把話講明了：訪客會先看到這些，位置在所有群組之上。如果頁面完全沒有群組，右側面板的標題會改成 **所有資源**。
- **資源面板（右）** —— 以你所選的群組為標題。它的標頭上有 **Edit Group**、主要的 **新增監測器** 按鈕，以及一個 **More actions** 溢位選單。

卡片標頭本身還有兩個按鈕：**New Group**，以及一個裝著 **Import groups from CSV** 與 **重新整理** 的三點溢位選單。

卡片描述會隨著你頁面的形狀改變。已經有群組時，它會說這就是訪客看到的全部內容，請在左邊挑一個群組來編輯其中的東西。還沒有群組時，它會提示你建立一個，把較長的頁面切成區塊。

**空白狀態會告訴你該做什麼。** 空群組會顯示 **No monitors here yet**，並附上 **新增監測器**、**Add Multiple**，以及——只有在狀態頁面完全沒有群組時才會出現的——**Create a Group**。搜尋不到任何結果時會顯示 **No resources match your search**。空的導覽器則會說明群組能把較長的狀態頁面切成區塊，而且可以巢狀。

## 新增一個監測器

先選好你要讓資源落腳的群組（或選 **Top of page** 放一列不分群的），然後點擊 **新增監測器**。這個對話框標題是 **Add a monitor to {group}**，有兩個步驟：**監測器詳細資訊** 與 **進階**。

在 **監測器詳細資訊** 上：

- **監測器** —— 你專案裡的監測器下拉選單，佔位文字為 **選擇監測器**。必填。
- **顯示名稱** —— 必填。這是訪客讀到的文字，而且與監測器本身的名稱分開儲存，所以你可以在這裡改名而不影響監控。
- **描述** —— 選填的 Markdown，顯示在該列底下。適合用一句話說明這個服務實際上在做什麼。

如果你的專案啟用了監測器群組，下拉選單底下會有一個連結寫著 **Add a Monitor Group instead.**——點它，**監測器** 下拉選單就會換成 **監測器 群組** 下拉選單（**選擇監測器群組**）。連結接著會翻成 **Add a Monitor instead.**，讓你可以換回去。當你希望頁面上的一列代表好幾項合起來看的檢查時，就用監測器群組。

### 一次加好幾個

**Add Multiple**（在 **More actions** 選單裡也叫 **Add multiple monitors**）會開啟 **Add Multiple Monitors**。它一樣是兩個步驟，只是第一步變成 **監測器** 多選，而不是單一下拉選單，而且你在 **進階** 上選的顯示選項會套用到你挑的每一個監測器。這是把新頁面填滿最快的方式。

## 資源上的顯示選項

**進階** 這個步驟在單筆新增表單和批次對話框上完全相同。這裡的每一項都是逐一資源設定的——同一個群組裡的兩列可以有不同的設定。

| 欄位                                                     | 用途                                                                                               |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **工具提示**（`displayTooltip`）                         | 顯示在狀態頁面上資源旁邊的額外文字。適合用來標明範圍：「美國與歐洲客戶」。                         |
| **顯示目前資源狀態**（`showCurrentStatus`）              | 預設開啟。在該列旁邊顯示即時狀態——運作中、效能下降、離線。                                        |
| **顯示正常運作時間 %**（`showUptimePercent`）            | 預設關閉。在資源旁邊顯示正常運作時間百分比。                                                       |
| **選擇運作時間精確度**（`uptimePercentPrecision`）       | 只有在 **顯示正常運作時間 %** 開啟後才出現。必填，預設為一位小數。                                 |
| **顯示狀態歷史記錄圖表**（`showStatusHistoryChart`）     | 預設開啟。顯示該資源逐日的正常運作時間歷史長條圖。                                                 |

第一步裡的 **顯示名稱**（`displayName`）與 **描述**（`displayDescription`）同樣只影響顯示——它們永遠不會改動監測器本身。

## 正常運作時間百分比與歷史圖表

**顯示正常運作時間 %** 與 **顯示狀態歷史記錄圖表** 都取決於一個放在別處的設定。它們涵蓋的時間範圍是 **狀態頁面 → 你的頁面 → 進階 → 進階設定** 底下、**正常運作時間歷史記錄設定** 卡片裡的 **顯示正常運作時間歷史記錄（天數）**。它接受 1 到 90 天，預設為 90。

所以順序是：先逐一資源打開開關，再為整個頁面設定一次時間範圍。

**精確度是個判斷題。** **選擇運作時間精確度** 下拉選單提供 `99% (No Decimal)`、`99.9% (One Decimal)`、`99.99% (Two Decimal)` 與 `99.999% (Three Decimal)`。小數位越多看起來越精準，也越容易引來對第三位數的爭論；如果你的 SLA 承諾三個九，就對到三個九，不要再多。

群組也有自己一份這些開關——見下文——所以群組可以顯示匯總後的百分比，而底下的個別監測器保持安靜，反過來也行。

歷史圖表長條的顏色，以及哪些監測器狀態算「停機」，都在 **概覽頁面** 這個品牌畫面上設定，詳見 [狀態頁品牌與網域](/docs/status-pages/branding-and-domains)。

## 群組

點擊 **New Group** 開啟 **Create New Status Page Group**。表單有三個步驟：**群組詳細資料**、**版面配置** 與 **進階**。

**群組詳細資料**：

- **群組名稱**（`name`）—— 必填。這是訪客看到的區塊標題。
- **群組描述**（`description`）—— 選填的 Markdown，顯示在標題底下。
- **Parent Group**（`parentStatusPageGroupId`）—— 選填。保持 **No parent group (top level)** 就讓群組留在最上層。
- **預設在狀態頁面上展開**（`isExpandedByDefault`）—— 這個區塊對訪客而言一開始是展開還是收合。

**進階** 在群組層級複製了資源的那些開關：

- **顯示目前群組狀態**（`showCurrentStatus`）—— 預設開啟。在群組標題旁邊顯示一個狀態。
- **顯示正常運作時間 %**（`showUptimePercent`）—— 預設關閉，開啟後會出現 **選擇運作時間精確度**。

編輯的方式如出一轍：面板標頭的 **Edit Group**，或導覽器該列選單裡的 **Edit group**，都會開啟 **Edit Status Page Group**，並附上 **儲存變更** 按鈕。

面板標頭會為目前開啟的設定顯示標籤——**Grid**、**Collapsed by default**、**Uptime %**——讓你不必打開表單就能看出一個群組是怎麼設定的。

### 管理一個群組

導覽器的每列選單裡有 **Edit group**、**Move up**、**Move down**、**顯示 ID** 與 **刪除群組**。面板的 **More actions** 溢位選單則是同一批動作的完整說法——**Edit this group**、**Add a sub group**、**Move group up**、**Move group down**、**Show group ID**、**重新整理** 與 **Delete this group**。沒填名稱就儲存的群組會呈現為 **Untitled group**，那通常代表你本來是想打點什麼的。

## 巢狀群組

群組可以巢狀：在子群組上設定 **Parent Group**，或使用導覽器的 **Add a sub group inside this group** 動作。表單本身的說明文字描述了它設想的形狀——類似 Corporate Units › Region › Market——並指出每一層都會顯示其下所有內容匯總後的狀態與正常運作時間。

當一個群組有子群組時，資源面板會出現一列 **Sub groups** 標籤，直接連進每個子群組，讓你不必回到導覽器就能走完整個階層。

巢狀在大型頁面上才划算：把區域放進產品底下的主機服務商，或把市場放進事業單位底下的零售商。而在只有十二個監測器的頁面上，單一層級反而更友善。

## 清單版面與格線版面

**版面配置** 這個步驟設定群組的 **檢視模式**（`viewMode`），它會改變群組對外呈現的方式。

| 如果你想要…                                                    | 就選                     |
| -------------------------------------------------------------- | ------------------------ |
| 顯示單純的垂直服務清單，一列一項                               | **List**（預設）         |
| 以矩陣呈現同一項服務跨多個區域或租戶的狀況                     | **Grid**                 |

選 **Grid** 之後會多出四個欄位：

- **列軸標籤** —— 列這個維度的名稱，佔位文字為 `Service`。
- **列軸數值** —— 各個列本身，用 **Add Row** 一次加一個（佔位文字 `e.g. Auth`）。
- **欄軸標籤** —— 欄這個維度，佔位文字為 `Region`。
- **欄軸數值** —— 用 **Add Column** 新增（佔位文字 `e.g. US-East`）。

格線群組裡的每個監測器接著會被放進一個儲存格，所以批次對話框會在詢問監測器的同時，用你自己的軸標籤問你列和欄。

**先架好軸，再加監測器。** 沒有列或欄的格線群組會顯示一則琥珀色提示，說在軸存在之前沒有地方可以放監測器，並附上一個 **Set up the grid** 按鈕——而且在你把軸架好之前，**新增監測器** 按鈕會被收起來。

## 排定訪客看到的順序

順序是明確指定的，不是按字母排的，而且在三個地方設定：

- **群組內的資源** —— 拖曳某一列。面板上就寫著：**Drag a row to change the order visitors see**。
- **群組彼此之間** —— 導覽器列選單裡的 **Move up** / **Move down**，或面板溢位選單裡的 **Move group up** / **Move group down**。
- **未分群的資源** —— 它們住在 **Top of page**，永遠呈現在所有群組之上，所以把大家最先確認的那一項放在那裡。

**有兩種情況拖曳會失效。** 用 **Search in {group}...** 搜尋框篩選面板時，重新排序會被停用——面板會告訴你 `N of M shown · drag to reorder is off while filtering`，所以請先清掉搜尋。另外，格線群組從來就不支援拖曳排序，因為位置是由列軸與欄軸決定的。

把大家最常問的服務放在最上面。在故障期間來到頁面的訪客，通常看完第一個畫面就不再往下讀了。

## 從 CSV 匯入群組

用手工建出一層層的階層很煩人。卡片標頭的三點溢位選單裡有 **Import groups from CSV**，它會開啟 **Import Groups from CSV** 對話框。

流程是：用 **Download CSV Template** 取得 `status-page-groups-template.csv`，填好它，**Choose CSV File**，然後 **Preview Import** 先檢查會建立什麼，再真的寫進去。接著 **Import results** 表格會把每一列標成 **Created**、**Failed** 或 **Skipped** 並附上原因，所以壞掉的一列不會無聲無息地消失。

只有 `name` 是必填的。可接受的欄位如下：

| 欄位                     | 它設定什麼                                           |
| ------------------------ | ---------------------------------------------------- |
| `name`                   | 群組名稱。必填。                                     |
| `parentName`             | 這個群組要巢狀進去的那個群組的名稱。                 |
| `description`            | 群組描述。                                           |
| `isExpandedByDefault`    | 這個區塊對訪客而言是否一開始就展開。                 |
| `showCurrentStatus`      | 群組標題旁邊是否顯示狀態。                           |
| `showUptimePercent`      | 群組旁邊是否顯示正常運作時間百分比。                 |
| `uptimePercentPrecision` | 那個百分比要用幾位小數。                             |
| `viewMode`               | `List` 或 `Grid`。                                   |
| `rowAxisLabel`           | 格線群組的列維度名稱。                               |
| `rowAxisValues`          | 格線群組的列數值。                                   |
| `columnAxisLabel`        | 格線群組的欄維度名稱。                               |
| `columnAxisValues`       | 格線群組的欄數值。                                   |

匯入建立的是群組，不是資源——之後再用 **新增監測器** 或 **Add Multiple** 把監測器加進去。
