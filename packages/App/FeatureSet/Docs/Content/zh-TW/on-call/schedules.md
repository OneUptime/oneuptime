# 待命排程

待命排程決定每個時刻由誰待命。排程中的人輪流待命：每人待命一段時間，然後由下一個人接手。將排程加入待命策略的上報規則後，執行到該層級時，策略會通知排程中正在待命的人。

## 誰輪流待命

在 **待命排程** 頁面建立排程時，表單會詢問 **名稱** 和 **誰輪流待命？**。點選 **新增使用者**，依輪替順序選擇人員：他們逐一待命，排程建立後第一個人立即開始待命。他們會成為排程的第一層 **Layer 1**，全天候待命。新排程接著會在其 **層** 頁面開啟，您可以在那裡變更輪替或新增更多層。

**誰輪流待命？** 為選填。留空時，排程建立後沒有任何層：在您於其 **層** 頁面新增層之前，不會有人待命。只有可以新增層的人才會看到這個問題。

其他內容都在 **進階** 下，在您展開之前保持摺疊：

- **每次待命時長**：**1 天**、**1 週**、**2 週** 或 **1 個月**，不變更時為 **1 週**。選擇人員後才會詢問。每人待命這麼長的時間，然後在排程建立時的同一時刻由下一個人接手。
- **時區**：交接時間和待命時段所依據的時區。預設為您的時區。
- **描述** 和 **標籤**。

在已選擇人員且 **進階** 下沒有任何變更時，摺疊的標題會說明將會發生什麼：每人待命一週，然後由下一個人接手。

## 層

排程的輪替由其 **層** 頁面上的層組成。層依由上而下的順序讀取：有人待命的最上層負責通知，因此請把主要輪替放在上面，把備援待命放在下面。

**新增層** 會新增一個與第一層同樣開始的層：從現在開始待命，每人一週，全天候。展開一層即可新增人員，並變更其開始時間、交接頻率、首次交接時間以及待命時段。

## 使用 API 或 Terraform 建立排程

待命排程是 `/api/on-call-duty-policy-schedule` 資源；其層以及層中的人員是 `/api/on-call-duty-schedule-layer` 和 `/api/on-call-duty-schedule-layer-user` 資源。

- 在 `miscDataProps` 中帶上 `firstLayerUsers`（依輪替順序排列的使用者 ID 清單）建立排程，會像儀表板一樣為其建立第一層：**Layer 1**，從現在開始待命，全天候。`firstLayerRotation` 以輪替的形式說明每次待命的時長，例如 `{"_type": "Recurring", "value": {"intervalType": "Week", "intervalCount": 1}}`；未提供時為一週。每位使用者都必須是專案成員，呼叫方必須有權建立層，否則不會建立排程。
- 不帶這些資料建立的排程與以前一樣沒有層；Terraform 的排程資源不會傳送它們。
- 不帶 `rotation` 建立的層與以往一樣每天交接。
