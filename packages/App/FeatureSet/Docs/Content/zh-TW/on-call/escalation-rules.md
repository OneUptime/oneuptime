# 上報規則

待命策略會分層級呼叫人員。每條上報規則就是一個層級：呼叫誰，以及在呼叫下一層級之前等待有人確認多久。策略的規則會依序列在其 **上報規則** 頁面上。

## 首先呼叫誰

在 **待命策略** 頁面建立待命策略時，表單會詢問它的 **名稱** 和 **首先通知誰？**。這個問題使用與 **通知** 相同的選擇器：待命排程、團隊和人員，需要多少就選多少。所選對象會成為策略的第一條上報規則 **Level 1**，在呼叫下一層級之前等待 **30 分鐘** 的確認。之後，新策略會在其 **上報規則** 頁面開啟，你可以在那裡新增更多層級。

**首先通知誰？** 是選填的。留空時，策略會在沒有上報規則的情況下開始：在你新增規則之前，它不會呼叫任何人，其概覽也會提示這一點。描述和標籤位於 **進階** 下。只有可以新增上報規則的人才會看到這個問題。

## 新增上報規則

開啟待命策略，在側邊選單中選擇 **上報規則**，然後點選 **Add Escalation Rule**。對話框只有一頁，只問兩件事：

- **通知** —— 此層級要呼叫誰。一個選擇器即可選擇待命排程、團隊和人員：點選 **新增回應者**，搜尋並依需要選擇。至少需要選擇一個。
  - **待命排程** 會呼叫該層級執行時正在待命的人，而不是固定的某個人。
  - **團隊** 會呼叫團隊中的每位成員。
  - **人員** 會被直接呼叫。
- **升級延遲（分鐘）** —— 在呼叫下一層級之前等待確認的時間。初始值為 **30 分鐘**，可依層級需要修改。

其他所有內容都在 **進階** 下，在你開啟之前保持收合：

- **名稱** —— 選填。未命名的規則會以其層級命名：策略的第一條規則是 **Level 1**，第二條是 **Level 2**，依此類推。名稱欄位會顯示規則將得到的名稱。
- **描述** —— 選填的備註，例如此層級呼叫誰以及原因。

當規則有描述或你自己取的名稱時，**進階** 的標題會顯示 **已設定**。

## 各層級如何呼叫人員

當事件或警示到達策略時，**Level 1** 會立即呼叫其回應者。如果在等待時間內無人確認，則呼叫 **Level 2**，依此類推。最後一個層級的等待時間過去後仍無人確認時，如果規則下方的 **重複策略** 設定為重複，策略會在允許的次數內從 **Level 1** 重新開始，否則停止。

**上報規則** 頁面頂部的摘要會顯示整個階梯：每個層級何時被呼叫、呼叫誰，以及最後一個層級之後會發生什麼。如果某個層級並非所有回應者都能被呼叫，其卡片上會提示；點選該標籤可查看是誰以及原因。

## 編輯、重新排序和刪除規則

- **Edit rule** 會開啟同一個單頁對話框，並填入規則的目前內容：回應者、等待時間，以及 **進階** 下的名稱和描述。新增或移除回應者後儲存即可。清空名稱會讓規則重新使用其層級的名稱。
- 規則 **⋯** 選單中的 **Move up** 和 **Move down** 用來變更其層級。以層級命名的規則會保持與位置相符的名稱：當 **Level 3** 上移越過 **Level 2** 時，兩者會互換名稱。你自己取的名稱（例如 **Managers**）無論規則移到哪裡都保持不變。
- **Delete rule** 會先請你確認，並說明該層級呼叫誰。刪除一個層級後，其下方的層級會依序上移，以層級命名的規則也會相應重新命名。

## 使用 API 或 Terraform 建立規則

上報規則是 `/api/on-call-duty-policy-escalation-rule` 資源；規則呼叫的人員、團隊和排程是 `/api/on-call-duty-policy-escalation-rule-user`、`-team` 和 `-schedule` 資源。

- 不帶 `name` 建立的規則會像在控制台中一樣以其層級命名：成為策略第三層級的規則名為 **Level 3**。Terraform 的上報規則資源仍然需要名稱。
- `escalateAfterInMinutes` 在控制台之外沒有預設值。不帶該值建立的規則不會等待：此層級執行後會立即呼叫下一層級。請明確設定它 —— 控制台建議使用 30。
- 以層級命名的規則會在你於控制台中移動或刪除規則時重新命名。透過 API 或 Terraform 修改 `order` 只會改變順序。
- 在 `miscDataProps` 中帶上 `onCallSchedules`、`teams` 或 `users`（ID 清單）透過 `/api/on-call-duty-policy` 建立待命策略時，會像在控制台中一樣為其建立第一條上報規則：呼叫這些對象的 **Level 1**，`escalateAfterInMinutes` 為 30。每個 ID 都必須屬於該專案，且呼叫方必須有權建立上報規則，否則不會建立該策略。不帶這些值建立的策略和以前一樣沒有規則；Terraform 的策略資源不會傳送它們。
