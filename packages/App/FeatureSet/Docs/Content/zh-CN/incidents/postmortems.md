# 事后分析

事后分析是事件之后的复盘：发生了什么、为什么发生、给用户造成了什么损失，以及接下来要改变什么。在 OneUptime 中，您直接在事件上编写它。它可以从您自己的模板或 OneUptime AI 的草稿开始，也可以作为事件的收尾更新发布到您的状态页上。每份事后分析还有一个状态，**事件 → 事后分析** 汇集了每个事件的事后分析，让您看到哪些还没写完。

:::cards
- [编写事后分析](#编写事后分析): 在事件的事后分析页面上，分五步完成。
- [从模板或 AI 草稿开始](#从模板或-ai-草稿开始): 使用您的大纲，或由 OneUptime AI 填写的大纲。
- [发布到状态页](#发布到状态页): 展示给客户，并只通知订阅者一次。
- [跟踪每份事后分析的进展](#跟踪每份事后分析的进展): 未开始、草稿、已完成，或您自己的状态。
- [查看所有事后分析](#查看所有事后分析): 按所有者、严重程度和状态筛选，找出还没写完的。
- [片段的事后分析](#片段的事后分析): 为一组事件写一份复盘。
:::

## 事后分析如何组成

事后分析由三部分组成，都在事件上：用 Markdown 编写的备注；附件，例如截图和报告；以及它是否显示在您的状态页上。它们位于事件侧边菜单 **调查** 下的 **事后分析** 页面上。事后分析还有一个说明它进展到哪一步的状态，以及所有者：即事件的所有者。

```mermaid title="从已解决的事件到已发布的事后分析"
flowchart TB
    R["事件已解决"] --> A["开启草稿时，<br/>OneUptime AI 起草"]
    R --> W["或由您开始：空白、<br/>模板或 AI"]
    A --> E["您的团队编辑它"]
    W --> E
    E --> P{"在状态页上<br/>发布吗？"}
    P -->|"是"| S["状态页显示它"]
    S --> N["订阅者只会<br/>收到一次通知"]
    P -->|"否"| K["它只留在您的团队内"]
```

## 编写事后分析

:::steps
### 打开事后分析

打开事件，然后点击其侧边菜单中 **调查** 下的 **事后分析**。**事后分析** 卡片显示事后分析的 **状态** 和 **所有者**、备注、附件，以及事后分析是否显示在状态页上。

### 点击撰写事后分析

**撰写事后分析** 对话框在第一步 **事后分析** 上打开。事后分析写好之后，卡片上的按钮变为 **编辑事后分析备注**，它会打开相同的步骤。

### 编写备注并附加文件

用 Markdown 编写 **事后分析备注**：发生了什么、影响、如何解决以及后续行动。在 **事后分析附件** 下添加截图、报告或时间线。

### 选择是否发布

点击 **下一步**。在 **状态页** 步骤中，**在状态页上发布** 默认关闭，因此事后分析只留在您的团队内。要展示给客户，请参阅 [发布到状态页](#发布到状态页)。

### 保存事后分析

点击 **保存更改**。卡片会显示备注和附件。事后分析的状态会从 **未开始** 变为 **草稿**：请参阅 [事后分析如何推进](#事后分析如何推进)。
:::

对备注的每次更改都会记录在事件的动态中，如果事件有 Slack 或 Microsoft Teams 频道，还会发布到该频道。只要事后分析尚未发布，状态页订阅者就不会收到任何相关消息。

编写事后分析需要 Project Owner、Project Admin、Project Member、Incident Admin 或 Incident Member 角色，或拥有 Edit Incident 权限的自定义角色。任何能读取事件的人都能读取它的事后分析。

## 从模板或 AI 草稿开始

两个按钮可以为您填写备注。还没有写任何内容时，它们位于 **撰写事后分析** 旁边：**从模板开始**（在项目有事后分析模板后出现）和 **Generate with AI**。事后分析写好之后，它们位于 **编辑事后分析备注** 旁边的 **⋯** 菜单中，名为 **应用模板** 和 **Generate with AI**。两者都会打开同一个编辑器，备注已填好，事后分析的其余部分保持原样。在您点击 **保存更改** 之前不会保存任何内容，所以请先阅读并修改备注。

### 应用模板

项目有事后分析模板后，就会出现 **应用模板**。您可以在 **事件 → 设置 → 事后分析模板** 下创建模板：请参阅 [事后分析模板](/docs/incidents/settings#事后分析模板)。在 OneUptime Cloud 上，模板需要 Growth 套餐。

点击 **从模板开始**，或 **⋯** 菜单中的 **应用模板**，在 **应用事后分析模板** 对话框的 **选择模板** 下选择一个模板，然后点击 **应用模板**。如果项目只有一个模板，它已经被选中。

### 用 AI 生成

点击 **Generate with AI**。**Generate Postmortem with AI** 对话框在 **选择模板** 下提供大纲：**Standard Postmortem**、**Detailed Technical Postmortem** 或 **Brief Postmortem**，然后是您自己的事后分析模板。**Template Preview** 显示大纲，您可以在生成之前修改它。

点击对话框底部的 **Generate with AI**。OneUptime AI 会读取事件（它的描述、根本原因和修复、状态时间线、公开和私密备注、其 Slack 或 Microsoft Teams 频道中的消息，以及 [其通话](/docs/workspace-connections/video-calls#通话转录) 中说过的内容），并按照您的大纲编写事后分析。随后编辑器会打开并显示结果。

生成需要在 **项目设置 → 人工智能 → AI Features** 下为项目打开 AI，并需要一个 LLM 提供商：请参阅 [LLM 提供商](/docs/ai/llm-provider)。它还需要 Project Owner 或 Project Admin 角色，或拥有 Edit Incident 权限的自定义角色：其他角色可以编写事后分析，但不能生成。

### 让 OneUptime AI 在事件解决时起草

打开 **事件解决后起草事后分析** 后，每当事件被解决，OneUptime AI 都会起草事后分析，将其保存为备注，并发布到事件的动态中供您的团队审阅。该开关位于 **事件 → 人工智能 → 设置**，新项目默认打开。

- 它从不替换已经写好的备注。
- 它从不写入已经发布的事后分析，否则草稿会未经审阅就出现在状态页上。
- 它需要为项目打开 AI，并且一旦项目达到每日 AI 限额，当天就会停止。请参阅 [自动事后分析](/docs/ai/ai-sre#自动事后分析)。
- 如果事件解决时其通话的转录仍在途中，它会等待 OneUptime AI 读取转录，以便草稿包含通话中说过的内容：在提供商准备转录期间最多等待六小时。请参阅 [录制并转录每次通话](/docs/workspace-connections/video-calls#录制并转录每次通话)。

#### 选择哪些事件获得草稿及其模板

没有规则时，每个已解决的事件都会获得一份按 OneUptime AI 标准大纲起草的草稿。同一页面 **更多设置** 下的 **事后分析规则** 可以改变这一点：

- 规则匹配 **所有事件**，或按监视器、严重程度、标签、监视器标签、标题和描述筛选的 **仅符合条件的事件**，与 AI 规则相同。
- 规则的 **模板** 是草稿可以遵循的事后分析模板。没有模板时，草稿遵循标准大纲；有一个时，遵循该模板；有多个时，遵循 OneUptime AI 认为最适合该事件的模板。草稿在动态中的帖子会注明它遵循的模板。
- 规则的 **更多字段** 中的 **LLM 提供商** 是 OneUptime AI 撰写草稿并挑选其模板时使用的提供商。不选择时，使用项目的默认提供商，否则使用全局提供商。草稿在动态中的帖子会注明规则选择的提供商，或改用的提供商以及原因。请参阅 [规则使用哪个 LLM 提供商](/docs/ai/ai-sre#规则使用哪个-llm-提供商)。
- 从列表顶部开始，第一条与事件匹配的已启用规则做出决定：拖动规则即可改变其位置。没有任何规则匹配的事件不会获得草稿；在规则无法读取期间，任何事件都不会获得草稿。
- **事件解决后起草事后分析** 仍然是关闭草稿的唯一开关。规则只决定 OneUptime AI 自行起草的草稿：无论规则如何规定，**Generate with AI** 都会提供所有大纲。
- 创建、编辑和重新排序规则需要 Project Owner 或 Project Admin 角色。在 OneUptime Cloud 上，模板需要 Growth 套餐：低于该套餐时，规则仍然决定哪些事件获得草稿，而每份草稿都遵循标准大纲。

## 发布到状态页

已发布的事后分析是事件面向客户的收尾更新：状态页会显示备注，在事件时间线中突出显示，并附带可下载的附件。

:::steps
### 打开状态页步骤

点击 **编辑事后分析备注**，然后点击 **下一步** 进入 **状态页** 步骤。

### 打开在状态页上发布

打开 **在状态页上发布**。会再出现两个字段：默认打开的 **通知订阅者**，以及默认为当前时间的 **事后分析发布于**。

### 决定通知谁以及显示的时间

关闭 **通知订阅者** 即可发布而不通知订阅者。更改 **事后分析发布于** 可以在事后分析旁显示另一个时间。

### 发布

点击 **保存更改**。卡片现在会显示 **事后分析在状态页上可见？**、**通知订阅者**、**订阅者通知状态** 和 **事后分析发布于**。
:::

以下因素决定客户能否看到它、能否收到通知：

- **事件必须显示在状态页上。** 状态页只会在它显示的事件上显示事后分析：**在状态页面上可见** 已打开，且事件不是私密的。
- **备注必须有内容。** 用空备注发布的事后分析不会显示，也不会通知任何人。
- **订阅者只会收到一次通知**，即状态页第一次显示该事后分析时。再次保存，或在发布状态下编辑它，会更新页面但不通知任何人。取消发布后再次发布会再次通知他们。在事件隐藏时发布的事后分析，会在事件变为可见时发送。
- **“通知订阅者”在通知发出时才读取。** 在事后分析发布后再打开它，不会发送任何内容。

**订阅者通知状态** 显示通知是否已发出，失败时提供 **重试**。每种情况请参阅 [事后分析](/docs/status-pages/subscribers#事后分析)，另请参阅 [重试和重新发送](/docs/status-pages/subscribers#重试和重新发送)。

**事后分析发布于** 也是 **事后分析用时** 测量中事后分析被视为发布的时间：请参阅 [现成的测量](/docs/incidents/settings#现成的测量)。

## 跟踪每份事后分析的进展

每个事件的事后分析都处于项目的某个事后分析状态中，显示在其 **事后分析** 卡片顶部的 **状态** 下。新项目有四个状态。处于 **未开始** 或 **草稿** 的事后分析还没写完；处于 **已完成** 或 **无需** 的则不是：

| 状态 | 含义 | 是否还没写完 |
| --- | --- | --- |
| **未开始** | 还没有人撰写这份事后分析。 | 是 |
| **草稿** | 事后分析正在撰写中。 | 是 |
| **已完成** | 事后分析已撰写完成。 | 否 |
| **无需** | 此事件不需要事后分析。 | 否 |

### 事后分析如何推进

OneUptime 会在三个时刻自动移动事后分析：

- 新事件的事后分析从 **未开始** 开始；如果事件声明时带有备注，则从 **草稿** 开始；如果该备注同时发布，则从 **已完成** 开始。
- 处于 **未开始** 的事后分析有了第一条备注后，会移至 **草稿**，无论是有人撰写、应用模板，还是由 OneUptime AI 起草。
- 在状态页上发布它会将其移至 **已完成**，除非它已经完成。

它从不倒退：清空备注，或将事后分析从状态页撤下，都不会改变它的状态。有人在同一次保存中选择的状态始终有效。

### 自己移动

在事件的 **事后分析** 页面上，或在事后分析列表中它所在的行里，点击状态，然后在 **将事后分析移至** 下选择一个状态。事后分析会立即移动。移动事后分析需要能撰写事后分析的角色，任何能读取该事件的人都能看到其事后分析的进展。

### 定制自己的状态

如果您的流程有自己的步骤，例如审核，请为它添加一个状态。打开 **事件 → 设置 → 事后分析状态**，点击 **创建事后分析状态**，为它设置名称（例如 **审核中**）、颜色和描述。新状态会放在 **已完成** 的正上方；拖动状态即可更改其位置。

状态所在的位置决定它被视为什么，显示在 **视为** 下：在 **草稿** 之上为 **未开始**；从 **草稿** 往下为 **进行中**；从 **已完成** 往下为 **完成**，不再待完成。位于两者之间的 **审核中** 仍待完成；位于 **已完成** 之下的 **无需** 则不是。

**未开始**、**草稿** 和 **已完成** 是内置状态，因为 OneUptime 会把事后分析移入它们：您可以重命名并更改颜色，但不能删除或归档，它们也会保持原有顺序。不再使用的状态，可以从其所在行的 **⋯** 菜单中归档：任何人都无法再将事后分析移入它，其中的事后分析会保持不变直到有人移动它们，列表仍可按它筛选。表格下方折叠的 **已归档的事后分析状态** 会列出这些状态，并可用 **取消归档** 恢复。创建、编辑和删除状态需要 Project Owner、Project Admin 或 Incident Admin 角色，或拥有事后分析状态相应权限的自定义角色。

## 查看所有事后分析

**事件 → 事后分析** 按从新到旧的顺序列出项目中每个事件的事后分析，包含 **事件**、**标题**、**事后分析状态**、**严重程度**、**所有者** 和 **已声明** 列。点击某行的 **查看** 会打开该事件的 **事后分析** 页面。

列表上方，每个状态都有一个磁贴，统计处于该状态的事后分析数量。点击磁贴只列出这些事后分析，再次点击即可列出全部。

使用列表上方的筛选条件筛选：**所有者**（个人或团队）、**严重程度**、**事后分析状态**、**事件状态**、**标签** 和 **受影响的资源**。要查看某个团队在最严重的事件上还欠哪些事后分析，请在 **所有者** 下选择该团队，在 **严重程度** 下选择严重程度，并在 **事后分析状态** 下选择 **未开始** 和 **草稿**。筛选条件保存在页面地址中，因此您可以将列表加入书签或分享出去。

要一次更改多个，请选中它们并打开 **批量操作**：**更改事后分析状态** 会将它们全部移至同一个状态，例如将不需要事后分析的事件移至 **无需**；**Add Owner** 和 **Remove Owner** 会更改它们的所有者。

## 片段的事后分析

事件片段也有一个 **事后分析** 页面，位于 **调查** 下：为片段中的所有事件写一份复盘。点击 **编辑事后分析** 来编写它。**应用模板** 和 **Generate with AI** 的作用与在事件上相同，AI 会读取片段及其成员事件。

片段的事后分析只有备注：它没有附件，也没有状态页显示它。片段解决时，OneUptime AI 不会自动起草。生成需要 Project Owner 或 Project Admin 角色，或拥有 Edit Incident Episode 权限的自定义角色。它也没有状态，事后分析列表也不包含它。

警报和计划维护事件没有事后分析。

## 通过 API

事后分析是事件上的一组字段，与事件的其他部分一样通过 `/api/incident` 读写：

| 字段 | 含义 |
| --- | --- |
| `postmortemNote` | 备注，使用 Markdown。 |
| `showPostmortemOnStatusPage` | 事后分析是否已发布到您的状态页。初始为 `false`。 |
| `notifySubscribersOnPostmortemPublished` | 发布时是否通知订阅者。初始为 `true`。 |
| `postmortemPostedAt` | 状态页在它旁边显示的时间。 |
| `postmortemStatusId` | 事后分析的状态：项目的某个状态，位于 `/api/incident-postmortem-status`。 |

在已写好的 `postmortemNote` 上将 `showPostmortemOnStatusPage` 写为 `true` 会发布事后分析，与对话框的效果相同。除非同一次写入设置了 `postmortemStatusId`，否则它还会将事后分析移至 **已完成**。

## 故障排除

:::details 卡片上没有应用模板
项目还没有事后分析模板，或者您的角色无法读取模板。请在 **事件 → 设置 → 事后分析模板** 下创建一个。在 OneUptime Cloud 上，模板需要 Growth 套餐。
:::

:::details Generate with AI 提示 AI 已关闭，或您没有权限
请在 **项目设置 → 人工智能 → AI Features** 下打开 AI。生成需要 Project Owner 或 Project Admin 角色，或拥有 Edit Incident 权限的自定义角色，即使对能编辑事后分析的人也是如此。
:::

:::details 事后分析没有显示在状态页上
检查三件事：**在状态页上发布** 已打开，备注不为空，并且事件显示在状态页上（**在状态页面上可见** 已打开，且不是私密的）。
:::

:::details 订阅者没有收到事后分析的通知
发布时 **通知订阅者** 是关闭的，或者事件是隐藏的：这种情况下，事件一变为可见就会发送。卡片上的 **订阅者通知状态** 会说明是哪种情况。
:::

:::details 事件解决时没有出现 AI 草稿
事件已经有备注、事后分析已经发布、没有事后分析规则与之匹配，或者 **事件解决后起草事后分析** 是关闭的。项目必须打开 AI，并且项目不能已达到每日 AI 限额。如果事件的通话有转录正在途中，草稿会在 OneUptime AI 读取转录之后出现。
:::

:::details 写了备注后事后分析的状态没有变化
只有处于 **未开始**，或处于 **草稿** 之上的自定义状态的事后分析，才会在第一条备注写入时自动推进。已在进行中或已完成的事后分析保持不变，有人在同一次保存中选择的状态也保持不变。请通过它的状态自己移动：请参阅 [自己移动](#自己移动)。
:::
