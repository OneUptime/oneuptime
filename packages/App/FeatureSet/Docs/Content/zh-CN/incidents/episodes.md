# 片段

片段把相关的事件或相关的警报归为一组，让团队把它们当作一件事来处理：在一个地方查看，由同一组负责人负责，只需确认和解决一个状态。分组规则会打开片段，并在事件和警报到来时把它们加进去（参见[事件分组规则](/docs/incidents/settings#事件分组规则)）。你也可以自己把事件放进片段，一次放多个：从片段中添加，或从事件列表中添加。

本页的一切同样适用于警报片段：把“事件”读作“警报”即可。事件片段位于 **事件 → 片段**，警报片段位于 **警报 → 片段**。

## 从片段中添加事件

打开片段，在侧边菜单中选择 **成员事件**（`/dashboard/{projectId}/incidents/episodes/{episodeId}/incidents`），然后点击 **添加事件**。对话框列出你能看到、且尚未在该片段中的最近 50 个事件，每个都显示编号、标题、状态和严重程度。要查找更早的事件，可以按标题或编号搜索：`INC-42`、`42` 和 `#42` 都能找到事件 42。

- 需要几个就勾选几个，一次最多 100 个。按钮会显示数量：**添加 3 个事件**。
- 已经在另一个片段中的事件，会在标题下方注明，并给出那个片段的编号。把它添加到这里，它仍会留在那里：一个事件可以属于多个片段。
- 如果有些无法添加，对话框会保持打开，并列出它们和原因；其余的会被添加。

## 从事件列表中添加事件

在 **事件** 列表或其他任何事件列表（例如某个监视器的事件列表）中选择事件，然后打开 **批量操作**：

| 操作 | 作用 |
| --- | --- |
| **添加到现有片段** | 选择一个片段。进行中的片段排在前面，从新到旧，之后是最近已解决的片段；按标题或编号搜索可以找到其他任何片段。添加之前，对话框会说明所选事件中有多少已经在该片段中（保持原样），有多少在另一个片段中（也会留在那里）。 |
| **添加到新片段** | 创建一个包含所选事件的片段。它只询问标题和严重程度，两者都根据所选事件中最严重的那个预先填好；私有事件的标题绝不会被复制。负责人、值班策略和备注请在片段自己的页面上添加。 |

两者都最多接受 100 个所选事件。结果会说明添加了多少、已在片段中的有多少、哪些没有添加以及原因，并附上打开该片段的链接。

## 添加会带来什么

- **片段的动态中只有一条记录**，列出每个添加的事件：前 20 个显示编号和标题，其余显示还有多少个。它只会在片段的 Slack 或 Microsoft Teams 频道中发布一次，而不是每个事件发布一次。私有事件只显示编号。
- **每个事件自己的动态** 会记录它被添加到了哪个片段。
- **片段的严重程度** 会提高到添加到现有片段的事件中最严重的那个，并且从不降低。新片段以你选择的严重程度开始。
- **已解决的片段保持已解决。** 向其中添加不会重新打开它，添加也从不改变事件的状态。
- **片段的负责人会收到通知**，得知有事件被添加，就像单独添加一个事件时一样。如果片段是连同这些事件一起创建的，片段自身的创建通知就涵盖了它们。

## 移出事件

在 **成员事件** 中，对某一行点击 **移除**，或在 **批量操作** 中对所选行执行，只会把事件移出这个片段。事件本身不会被删除，并且仍留在它所属的其他片段中。

## 谁可以添加

添加需要把事件添加到片段的权限。Project Owner、Project Admin、Project Member、Incident Admin 和 Incident Member 角色都有此权限，带有 Create Incident Episode Member 的自定义角色也有。你只能添加自己能看到的事件：私有事件只能由其负责人以及项目的所有者和管理员添加。添加到新片段还需要创建片段的权限。你无法使用的操作会被锁定，其提示会说明缺少哪项权限。

## 使用 API

在一个请求中把多个事件添加到片段：

```bash
curl -X POST 'https://oneuptime.com/api/incident-episode-member/add-incidents' \
  -H "ApiKey: $ONEUPTIME_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "incidentEpisodeId": "<episode id>",
    "incidentIds": ["<incident id>", "<incident id>"]
  }'
```

响应对发送的每个事件各说明一次：已添加、已在片段中，或未添加及原因。包含超过 100 个 ID 的请求会被拒绝。

```json
{
  "added": ["<incident id>"],
  "alreadyInEpisode": ["<incident id>"],
  "notAdded": [
    {
      "id": "<incident id>",
      "reason": "This incident does not exist in this project, or you do not have access to it."
    }
  ]
}
```

对于警报，把 `alertEpisodeId` 和 `alertIds` 发送到 `/api/alert-episode-member/add-alerts`。要创建一个已包含事件的片段，在创建片段的请求 `POST /api/incident-episode` 中带上它们的 ID，形式为 `{ "data": { "title": "Checkout outage" }, "miscDataProps": { "incidentIdsToAdd": ["<incident id>"] } }`；警报片段则使用 `POST /api/alert-episode` 并带上 `alertIdsToAdd`。只要其中有一个无法添加，就不会创建片段。
