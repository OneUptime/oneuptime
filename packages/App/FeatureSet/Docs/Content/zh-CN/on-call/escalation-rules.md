# 升级规则

值班策略按级别呼叫人员。每条升级规则就是一个级别：呼叫谁，以及在呼叫下一级之前等待有人确认多长时间。策略的规则按顺序列在其 **升级规则** 页面上。

## 首先呼叫谁

在 **值班策略** 页面创建值班策略时，表单会询问它的 **名称** 和 **首先通知谁？**。这个问题使用与 **通知** 相同的选择器：值班计划、团队和人员，需要多少就选多少。所选对象会成为策略的第一条升级规则 **Level 1**，在呼叫下一级之前等待 **30 分钟** 的确认。随后，新策略会在其 **升级规则** 页面打开，你可以在那里添加更多级别。

**首先通知谁？** 是可选的。留空时，策略在没有升级规则的情况下开始：在你添加规则之前，它不会呼叫任何人，其概览也会提示这一点。描述和标签位于 **更多字段** 下。只有可以添加升级规则的人才会看到这个问题。

## 添加升级规则

打开值班策略，在侧边菜单中选择 **升级规则**，然后点击 **添加升级规则**。对话框只有一页，只问两件事：

- **通知** —— 此级别呼叫谁。一个选择器即可选择值班计划、团队和人员：点击 **添加响应人**，搜索并按需选择。至少需要选择一个。
  - **值班计划** 会呼叫该级别执行时正在值班的人，而不是固定的某个人。
  - **团队** 会呼叫团队中的每位成员。
  - **人员** 会被直接呼叫。
- **升级延迟（分钟）** —— 在呼叫下一级之前等待确认的时长。初始值为 **30 分钟**，可按级别需要修改。

其他所有内容都在 **更多字段** 下，在你打开之前保持折叠：

- **名称** —— 可选。未命名的规则以其级别命名：策略的第一条规则是 **Level 1**，第二条是 **Level 2**，依此类推。名称字段会显示规则将得到的名称。
- **描述** —— 可选的备注，例如此级别呼叫谁以及原因。

收起时，**更多字段** 的标题会列出这两项，并标出规则已有的那一项：描述，或你自己取的名称。

## 各级别如何呼叫人员

当事件或告警到达策略时，**Level 1** 会立即呼叫其响应人。如果在等待时间内无人确认，则呼叫 **Level 2**，依此类推。最后一级的等待时间过去后仍无人确认时，如果规则下方的 **重复策略** 设置为重复，策略会在允许的次数内从 **Level 1** 重新开始，否则停止。

以已确认或已解决状态创建的事件、告警或片段（即事后补录的）不会执行任何策略：不会呼叫任何人，其 Feed 会记录这一点并列出这些策略。

**升级规则** 页面顶部的摘要显示整个阶梯：每个级别何时被呼叫、呼叫谁，以及最后一级之后会发生什么。如果某个级别并非所有响应人都能被呼叫，其卡片上会提示；点击该标签可查看是谁以及原因。

某一级别通知到的每个人如何被联系，由其本人的值班规则决定：**用户设置** > **值班规则**，其中有事件、事件片段、警报和警报片段四个标签页，每个严重程度一张卡片，列出使用哪种通知方式以及等待多久。项目管理员可以在 **用户** > 该成员 > **值班规则** 中查看和修改成员的规则。

新项目中的短信、语音电话、WhatsApp 和 Telegram 默认关闭：在 OneUptime Cloud 上，每条消息都从项目余额中支付；自托管安装则需要先设置 Twilio 账户或 Telegram 机器人。渠道开启之前，项目中的任何人都无法在该渠道上添加通知方式。只有项目所有者或拥有 **Manage Billing** 权限的用户才能开启渠道，位置在 **项目设置 > 通知 > 通知设置** 的 **通知渠道** 卡片中——项目管理员不能。其他人在渠道关闭的任何地方都会被准确告知谁可以开启：在他们自己该渠道的通知方式列表上方、在他们的设置清单中，以及在需要该渠道时收到的消息里。

## 编辑、重新排序和删除规则

- **Edit rule** 会打开同一个单页对话框，并填入规则的当前内容：响应人、等待时间，以及 **更多字段** 下的名称和描述。添加或移除响应人后保存即可。清空名称会让规则重新使用其级别的名称。
- 规则 **⋯** 菜单中的 **Move up** 和 **Move down** 用于更改其级别。以级别命名的规则会保持与位置相符的名称：当 **Level 3** 上移越过 **Level 2** 时，两者会互换名称。你自己取的名称（例如 **Managers**）无论规则移到哪里都保持不变。
- **Delete rule** 会先请你确认，并说明该级别呼叫谁。删除一个级别后，其下方的级别会依次上移，以级别命名的规则也会相应重命名。

## 使用 API 或 Terraform 创建规则

升级规则是 `/api/on-call-duty-policy-escalation-rule` 资源；规则呼叫的人员、团队和计划是 `/api/on-call-duty-policy-escalation-rule-user`、`-team` 和 `-schedule` 资源。

- 不带 `name` 创建的规则会像在控制台中一样以其级别命名：成为策略第三级的规则名为 **Level 3**。Terraform 的升级规则资源仍然需要名称。
- `escalateAfterInMinutes` 在控制台之外没有默认值。不带该值创建的规则不会等待：此级别执行后会立即呼叫下一级。请显式设置它 —— 控制台建议使用 30。
- 以级别命名的规则会在你于控制台中移动或删除规则时重命名。通过 API 或 Terraform 修改 `order` 只会改变顺序。
- 在 `miscDataProps` 中带上 `onCallSchedules`、`teams` 或 `users`（ID 列表）通过 `/api/on-call-duty-policy` 创建值班策略时，会像在控制台中一样为其创建第一条升级规则：呼叫这些对象的 **Level 1**，`escalateAfterInMinutes` 为 30。每个 ID 都必须属于该项目，且调用方必须有权创建升级规则，否则不会创建该策略。不带这些值创建的策略和以前一样没有规则；Terraform 的策略资源不会发送它们。
