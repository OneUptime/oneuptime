# 值班计划

值班计划决定每时每刻由谁值班。计划中的人轮流值班：每人值班一段时间，然后由下一个人接班。把计划加入值班策略的升级规则后，执行到该级别时，策略会通知计划中正在值班的人。

## 谁轮流值班

在 **值班计划** 页面创建计划时，表单会询问 **名称** 和 **谁轮流值班？**。点击 **添加用户**，按轮换顺序选择人员：他们逐一值班，计划创建后第一个人立即开始值班。他们成为计划的第一层 **Layer 1**，全天候值班。新计划随后会在其 **层** 页面打开，您可以在那里更改轮换或添加更多层。

**谁轮流值班？** 是可选的。留空时，计划创建后没有任何层：在您于其 **层** 页面添加层之前，不会有人值班。只有可以添加层的人才会看到这个问题。

其他内容都在 **更多字段** 下，在您展开之前保持折叠：

- **每次值班时长**：**1 天**、**1 周**、**2 周** 或 **1 个月**，不更改时为 **1 周**。选择了人员后才会询问。每人值班这么长时间，然后在计划创建时的同一时刻由下一个人接班。
- **时区**：交接时间和值班时段所依据的时区。默认是您的时区。
- **描述** 和 **标签**。

在已选择人员且 **更多字段** 下没有任何更改时，折叠的标题会说明将会发生什么：每人值班一周，然后由下一个人接班。

## 层

计划的轮换由其 **层** 页面上的层组成。层按从上到下的顺序读取：有人值班的最上面一层负责通知，因此请把主要轮换放在上面，把后备值班放在下面。

**添加层** 会添加一个与第一层同样开始的层：从现在开始值班，每人一周，全天候。展开一层即可添加人员，并更改其开始时间、交接频率、首次交接时间以及值班时段。

每个人在所有地方都使用同一种颜色，便于一眼找到：在每一层、最终计划及其覆盖中，以及在 **值班时间线** 上。

## 使用 API 或 Terraform 创建计划

值班计划是 `/api/on-call-duty-policy-schedule` 资源；其层以及层中的人员是 `/api/on-call-duty-schedule-layer` 和 `/api/on-call-duty-schedule-layer-user` 资源。

- 在 `miscDataProps` 中带上 `firstLayerUsers`（按轮换顺序排列的用户 ID 列表）创建计划，会像仪表板一样为其创建第一层：**Layer 1**，从现在开始值班，全天候。`firstLayerRotation` 以轮换的形式说明每次值班的时长，例如 `{"_type": "Recurring", "value": {"intervalType": "Week", "intervalCount": 1}}`；不提供时为一周。每个用户都必须是项目成员，调用方必须有权创建层，否则不会创建计划。
- 不带这些数据创建的计划与以前一样没有层；Terraform 的计划资源不会发送它们。
- 不带 `rotation` 创建的层与以往一样每天交接。
