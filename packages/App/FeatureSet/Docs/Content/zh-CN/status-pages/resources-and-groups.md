# 资源与分组

资源就是状态页上的一行——一个监视器（或一个监视器组），配上访客看得懂的名称、一个当前状态，以及可选的正常运行时间数字和历史图表。分组则是装着资源的区块，好让一个挂着四十个监视器的页面读起来是"API""Web 应用""数据管道"，而不是一份没完没了的清单。

两者都在同一个界面上搭建。打开一个状态页，在侧边菜单里选 **资源**（在没有启用监视器组的项目上，这一项写作 **监视器**）。分组过去有自己的页面，现在没有了，旧的 `/groups` 地址会直接重定向到这里。

把这部分做对了，状态页其余的部分不过是装饰。访客就是靠这些行来判断"是我的问题还是他们的问题"，所以给它们起名要按客户谈论你产品的方式来——**Checkout API**，而不是 `prod-checkout-lb-healthcheck-us-east-1`。

## Resources 界面

这个界面一分为二。左边是列出页面上所有分组的导航栏；右边是你选中的那个分组的内容。

- **分组导航栏（左）**——一棵分组树，上方有一个搜索框（**Search groups...**），下方有一个实时计数，形如 `3 groups · 12 resources`。当页面上的分组多到放不下时，会出现一个 **Show N more of M** 按钮把其余的展开。
- **Top of page**——导航栏里的第一行。它装的是不属于任何分组的资源，它的工具提示把含义说得很清楚：访客最先看到这些，位置在所有分组之上。如果页面完全没有分组，右侧面板的标题会改成 **All resources**。
- **资源面板（右）**——标题就是你选中的分组。它的头部有 **Edit Group**、主按钮 **添加监视器**，以及一个 **More actions** 溢出菜单。

卡片头部本身还有两个按钮：**New Group**，以及一个装着 **Import groups from CSV** 和 **刷新** 的三点溢出菜单。

卡片的描述文字会随着你页面的形态变化。有分组时，它说的是这里就是访客看到的全部内容，请在左侧选一个分组来编辑其中的内容。还没有分组时，它会提示你创建一个，把较长的页面切成区块。

**空状态会告诉你该做什么。** 空分组显示 **No monitors here yet**，配上 **添加监视器**、**Add Multiple**，以及——仅当这个状态页一个分组都没有时——**Create a Group**。搜索没有命中任何内容时显示 **No resources match your search**。空的导航栏会说分组能把较长的状态页切成区块，并且可以嵌套。

## 添加一个监视器

先选中你希望资源落进去的分组（要放没有分组的行就选 **Top of page**），然后点击 **添加监视器**。弹窗标题是 **Add a monitor to {group}**，有两步：**监视器详情** 和 **高级**。

在 **监视器详情** 上：

- **监视器**——你项目中监视器的下拉框，占位符 **选择监视器**。必填。
- **显示名称**——必填。这是访客读到的文字，它与监视器自身的名称分开存储，所以你可以在这里改名而不动监控本身。
- **描述**——可选的 Markdown，显示在这一行下方。适合用一句话说明这个服务到底是干什么的。

如果你的项目启用了监视器组，下拉框下面会有一个链接写着 **Add a Monitor Group instead.**——点它，**监视器** 下拉框就会换成 **监视器 组** 下拉框（**选择监视器组**）。链接随即翻转成 **Add a Monitor instead.**，让你可以退回去。当你想让页面上的一行代表若干个合并起来的检查时，就用监视器组。

### 一次加好几个

**Add Multiple**（在 **More actions** 菜单里也叫 **Add multiple monitors**）会打开 **Add Multiple Monitors**。它同样是两步，只是第一步换成了 **监视器** 多选而不是单个下拉框，而你在 **高级** 上选的显示选项会应用到你挑中的每一个监视器上。这是给新页面铺底最快的方式。

## 资源上的显示选项

单个添加表单和批量弹窗上的 **高级** 这一步是一样的。这里的一切都是按资源来的——同一分组里的两行可以配得完全不同。

| 字段                                                     | 用途                                                                                               |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **工具提示**（`displayTooltip`）                         | 在状态页上显示在资源旁边的补充文字。适合交代适用范围："美国和欧洲客户"。                            |
| **显示当前资源状态**（`showCurrentStatus`）              | 默认开启。在这一行旁边显示实时状态——运行正常、性能下降、离线。                                      |
| **显示正常运行时间百分比**（`showUptimePercent`）        | 默认关闭。在资源旁边显示一个正常运行时间百分比。                                                    |
| **选择正常运行时间精度**（`uptimePercentPrecision`）     | 只有在 **显示正常运行时间百分比** 打开后才出现。必填，默认一位小数。                                |
| **显示状态历史记录图表**（`showStatusHistoryChart`）     | 默认开启。显示该资源逐日的正常运行时间历史条形图。                                                  |

第一步里的 **显示名称**（`displayName`）和 **描述**（`displayDescription`）同样只影响展示——它们从不改动监视器本身。

## 正常运行时间百分比与历史图表

**显示正常运行时间百分比** 和 **显示状态历史记录图表** 都依赖一个位于别处的设置。它们覆盖的时间窗口是 **状态页面 → 你的页面 → 高级 → 高级设置** 里 **正常运行时间历史设置** 卡片中的 **显示正常运行时间历史记录（天数）**。取值 1 到 90 天，默认 90。

所以顺序是：先按资源逐个打开开关，再为整个页面统一设定这个窗口。

**精度是个判断题。** **选择正常运行时间精度** 下拉框提供 `99% (No Decimal)`、`99.9% (One Decimal)`、`99.99% (Two Decimal)` 和 `99.999% (Three Decimal)`。小数位越多看起来越精确，也越容易在第三位上引发争论；如果你的 SLA 承诺的是三个九，就对齐到三个九，不要更多。

分组有自己的一套同名开关——见下文——所以可以让分组显示汇总百分比，而里面的单个监视器保持安静，或者反过来。

历史图表条形的颜色，以及哪些监视器状态算作"故障"，是在 **概览页面** 品牌界面上设置的，见[状态页品牌与域名](/docs/status-pages/branding-and-domains)。

## 分组

点击 **New Group** 打开 **Create New Status Page Group**。表单有三步：**分组详情**、**布局** 和 **高级**。

**分组详情**：

- **分组名称**（`name`）——必填。这是访客看到的区块标题。
- **分组描述**（`description`）——可选的 Markdown，显示在标题下方。
- **Parent Group**（`parentStatusPageGroupId`）——可选。保持 **No parent group (top level)** 就让这个分组留在顶层。
- **默认在状态页上展开**（`isExpandedByDefault`）——访客打开页面时这个区块是展开还是收起。

**高级** 是资源那套开关在分组层面的镜像：

- **显示当前分组状态**（`showCurrentStatus`）——默认开启。在分组标题旁边显示一个状态。
- **显示正常运行时间百分比**（`showUptimePercent`）——默认关闭，打开后会出现 **选择正常运行时间精度**。

编辑走的是同一套路子：面板头部的 **Edit Group**，或导航栏行菜单里的 **Edit group**，都会打开带 **保存更改** 按钮的 **Edit Status Page Group**。

面板头部会用小标签显示当前已开启的设置——**Grid**、**Collapsed by default**、**Uptime %**——这样不用打开表单就能看出一个分组是怎么配的。

### 管理一个分组

导航栏的行菜单里有 **Edit group**、**Move up**、**Move down**、**显示 ID** 和 **Delete group**。面板的 **More actions** 溢出菜单里是它们的长版本——**Edit this group**、**Add a sub group**、**Move group up**、**Move group down**、**Show group ID**、**刷新** 和 **Delete this group**。没填名字就保存的分组会渲染成 **Untitled group**，这通常说明你本来是想打点什么的。

## 嵌套分组

分组是可以嵌套的：在子分组上设置 **Parent Group**，或者用导航栏的 **Add a sub group inside this group** 操作。表单自带的帮助文字描述了它所面向的结构——类似"业务单元 › 区域 › 市场"——并说明每一层都会显示其下所有内容汇总后的状态和正常运行时间。

当一个分组有子分组时，资源面板会显示一行 **Sub groups** 小标签，直接链到每个子分组，让你不用回到导航栏就能在层级里走动。

嵌套在大页面上才划得来：托管服务商把区域嵌在产品里，零售商把市场嵌在业务单元里。而在一个只有十二个监视器的页面上，一层扁平结构更友好。

## 列表布局与网格布局

**布局** 这一步为分组设定 **查看模式**（`viewMode`），它会改变分组对外渲染的样子。

| 如果你想……                                                          | 就选                   |
| ------------------------------------------------------------------- | ---------------------- |
| 展示一份朴素的竖排服务清单，一行一个                                | **List**（默认）       |
| 把同一个服务在多个区域或多个租户上的状态排成一张矩阵                | **Grid**               |

选了 **Grid**，会再多出四个字段：

- **行轴标签**——行这个维度的名称，占位符 `Service`。
- **行轴值**——行本身，用 **Add Row** 一次加一个（占位符 `e.g. Auth`）。
- **列轴标签**——列这个维度，占位符 `Region`。
- **列轴数值**——用 **Add Column** 添加（占位符 `e.g. US-East`）。

网格分组里的每个监视器随后都会被放进某个单元格，所以批量弹窗会在选监视器的同时问你行和列，并使用你自己定的轴标签。

**先把轴建好，再加监视器。** 一个没有行也没有列的网格分组会显示一条琥珀色提示，说在轴存在之前监视器无处安放，并给出一个 **Set up the grid** 按钮——在你把轴建好之前，**添加监视器** 按钮是收起来的。

## 排列访客看到的顺序

顺序是明确指定的，不是按字母排的，并且在三个地方设置：

- **分组内部的资源**——拖动某一行。面板上就是这么说的：**Drag a row to change the order visitors see**。
- **分组彼此之间**——导航栏行菜单里的 **Move up** / **Move down**，或者面板溢出菜单里的 **Move group up** / **Move group down**。
- **未分组的资源**——它们待在 **Top of page**，并且永远渲染在所有分组之上，所以把大家最先要看的那一项放在这里。

**有两种情况拖动是关掉的。** 用 **Search in {group}...** 框过滤面板会禁用重新排序——面板会提示 `N of M shown · drag to reorder is off while filtering`，先清空搜索即可。另外网格分组从不支持拖动排序，因为位置由行轴和列轴决定。

把最多人问起的服务放在最上面。故障期间来到页面上的访客，通常看完第一屏就不再往下读了。

## 从 CSV 导入分组

手工搭一棵很深的层级树很磨人。卡片头部的三点溢出菜单里有 **Import groups from CSV**，它会打开 **Import Groups from CSV** 弹窗。

流程是：**Download CSV Template** 拿到 `status-page-groups-template.csv`，填好，**Choose CSV File**，然后 **Preview Import** 在真正写入之前先核对会创建些什么。随后 **Import results** 表格会把每一行标为 **Created**、**Failed** 或 **Skipped** 并附上原因，所以坏掉的那一行不会悄无声息地消失。

只有 `name` 是必填的。可接受的列如下：

| 列                       | 它设定什么                                           |
| ------------------------ | ---------------------------------------------------- |
| `name`                   | 分组名称。必填。                                     |
| `parentName`             | 这个分组所嵌套进去的那个分组的名称。                 |
| `description`            | 分组描述。                                           |
| `isExpandedByDefault`    | 这个区块对访客来说是否默认展开。                     |
| `showCurrentStatus`      | 分组标题旁边是否显示状态。                           |
| `showUptimePercent`      | 分组旁边是否显示正常运行时间百分比。                 |
| `uptimePercentPrecision` | 那个百分比保留几位小数。                             |
| `viewMode`               | `List` 或 `Grid`。                                   |
| `rowAxisLabel`           | 网格分组的行维度名称。                               |
| `rowAxisValues`          | 网格分组的行取值。                                   |
| `columnAxisLabel`        | 网格分组的列维度名称。                               |
| `columnAxisValues`       | 网格分组的列取值。                                   |

导入只创建分组，不创建资源——之后再用 **添加监视器** 或 **Add Multiple** 把监视器加进去。
