# 数据产品

使用数据的人——分析师、财务、高管、AI 代理——思考的是他们使用的东西：“收入仪表板的那些表”，而不是数据库。**数据产品** 为这些表命名，带有所有者、消费者和新鲜度 SLA，并告诉所有依赖它的人今天的数据是否已经到位。

## 创建数据产品

在 **数据可观测性 > 数据产品** 下创建数据产品：为它命名、选择它的表，并为它设定以下一种或两种 SLA：

- **每天的更新截止时间（UTC）：** 每天的数据在当天的该时间之前到达。从该时间起，每个表都必须在当天发生过更改；在此之前，昨天的加载仍然有效。总是晚半小时的加载，每天都会有半小时处于延迟状态。
- **最大时长：** 任何表的最后一次更改都不能早于这个时长。

每五分钟，系统会根据 SLA 检查每个产品的表。只要有任何一个表延迟，产品就是 **Late**，其数据的时间点就是这些表中最早的那次最后更改。它会写入 `oneuptime.data.product.late_tables` 和 `oneuptime.data.product.data_age`，因此你可以把所有产品的新鲜度并排绘制成图表。

## 在状态页上

保存产品时，还会以你的身份、按你的权限为它创建一个 **监视器**。表延迟期间，该监视器处于性能下降状态，并以项目中最低的严重程度打开一个事件和一个警报，它们会自行解决。把它作为资源添加到私有或公开的状态页上：订阅的消费者会在产品延迟以及重新变得新鲜时收到通知。请参阅 [状态页资源](/docs/status-pages/resources-and-groups)。

## 作为 SLO

保存产品时，还会基于它的监视器创建一个 **SLO**：数据准时的时间占比，对照产品在 30 天内的目标，并带有每个 SLO 一开始就有的快速和慢速消耗速率警报。请参阅 [SLO](/docs/slo/introduction)。删除产品会同时删除它的监视器和 SLO。

## “data as of”徽章

每个产品都有一个 **徽章**，说明其数据截至何时：准时时为绿色，不准时时为琥珀色并带有“late”。从产品的 **概览** 将它嵌入 BI 仪表板、wiki 页面或 README：

```markdown
![Data as of](https://oneuptime.com/api/data-observability/data-products/<data product ID>/badge?token=<badge token>)
```

它的链接无需登录即可打开，因此请像对待共享链接一样对待它。**重置徽章链接** 会生成一个新链接并停用旧链接。
