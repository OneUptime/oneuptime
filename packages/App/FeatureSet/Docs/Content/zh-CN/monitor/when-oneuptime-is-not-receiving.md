# OneUptime 未接收数据时

当 OneUptime 重启、升级或处理积压的数据时，你的代理、采集器、探测器和心跳发送方发出的任何内容都无法到达你的监控器。OneUptime 会记录这种情况发生的时间，并且从不把这段时间算到服务器、主机或任何其他资源头上：这段时间没有被监控，所以不是停机时间。

## 工作原理

每个接收数据的 OneUptime 进程，只要能连接到存放数据的数据库，就会每 30 秒记录一次自己正在接收。OneUptime 会排除三类时间：

- 未接收：超过 90 秒没有任何进程记录。OneUptime 当时已停止、正在重启或升级，或者无法连接到它的某个数据库。
- 重新连接：OneUptime 恢复接收后的最初 2 分钟，此时代理正在重新连接并发送它们保留的数据。
- 追赶：当等待处理的数据队列落后超过一分钟时，从队列中仍在等待的最早数据算起的时间。

```mermaid title="OneUptime 排除的时间"
flowchart LR
    receiving["接收中"] -->|"90 秒没有记录"| down["未接收"]
    down -->|"有进程重新记录"| grace["重新连接 2 分钟"]
    grace --> again["接收中"]
```

不到 90 秒的重启不算中断：采集器会重新发送未能送达的数据。

## 这段时间内的变化

| 位置 | OneUptime 的做法 |
| --- | --- |
| 服务器 / 虚拟机监控器 | **Is Online** 只计算 OneUptime 正在接收的分钟数：默认情况下，服务器在 OneUptime 本可以听到的 3 分钟沉默之后才算离线。 |
| 入站请求和入站邮件监控器 | **Recieved In Minutes** 和 **Not Recieved In Minutes** 只计算 OneUptime 正在接收的分钟数。满足这类条件时，其原因会说明有多少分钟被排除。 |
| 主机、Kubernetes、Docker、指标、日志、追踪以及其他读取遥测数据的监控器 | 如果检查窗口中包含 OneUptime 未接收的时间，检查会等待这段时间移出窗口，但在这段时间结束后最多等待 15 分钟。在此之前一切不变：状态不变，也不会打开或解决任何事件或警报。当队列落后时，检查读取到队列所在的位置，而不是读取到现在。 |
| 主机、集群和其余资产 | 只有在 OneUptime 正在接收期间，资源的沉默阈值（大多数为 15 分钟）过去之后，资源才会变为 **已断开**。 |
| 探测器和 AI 代理 | 在 OneUptime 正在接收期间沉默 3 分钟后变为 **已断开**。 |
| 主机、Docker 和 Podman 主机以及 Kubernetes 集群的 **可用性** 图表 | 这段时间以 **未监控** 的阴影显示，折线在此处断开，而不是跌到宕机。正常运行时间徽章不计入这段时间；有数据的区间仍算作正常。 |
| 状态页面的正常运行时间和 SLO | 两者都根据监控器状态计算：没有错误的状态变化，就没有错误的停机时间。 |

> [!NOTE]
> 排除时间并不是填补时间。在 OneUptime 无法听到某个资源的时间里，该资源从不会显示为正常：这段时间只是不做判断。一旦 OneUptime 恢复接收，真正宕机的资源会从那时起根据它发送或没有发送的内容来判断。

## 自托管安装

### 启动时

OneUptime 进程启动期间，会对除状态检查以外的所有请求返回 `503 Service Unavailable` 和 `Retry-After: 5`，浏览器会收到一个自动重新加载的页面。OpenTelemetry 采集器和 SDK 会重新发送这样的请求，而不是丢弃数据。`/status/ready` 在进程就绪之前一直失败，因此 Kubernetes 在此之前不会向它发送流量。

### Worker 副本

只有入站流量能够到达的进程才会记录 OneUptime 正在接收。如果你运行的副本只处理队列、前面没有 ingress，请在这些副本上把 `RECEIVES_INGRESS_TRAFFIC` 设为 `false`。否则，在所有接收流量的副本都宕机时它们仍会继续记录，这次故障又会算到你的资源头上。Helm chart 已经在它的 worker Pod 上设置了这一项，单个 OneUptime 容器则无需任何设置。

```yaml title="Worker 容器"
env:
  - name: RECEIVES_INGRESS_TRAFFIC
    value: "false"
```

### 记录的内容

当你升级到包含此记录的版本时，OneUptime 开始保存这份记录；之前的时间仍按原来的方式判断。当没有任何进程记录自己正在接收时，自最后一次记录以来的时间最多按一小时的中断处理；之后沉默会重新计算，因此不再写入的记录无法长时间掩盖资源的故障。记录保留 400 天，当 OneUptime 无法读取它们时，会按一直在接收的情况来判断沉默。
