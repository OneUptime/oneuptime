# 触发器

触发器是工作流里的第一个方块——它决定工作流什么时候运行。每个工作流恰好有一个触发器。可选的类型有四种。

## 手动

在 **生成器** 页面点 **运行工作流**，填好触发器的字段，再用 **Run Workflow Manually** 确认，就能按需跑一次工作流。手动触发器接受一段 JSON 载荷，工作流后面的部分可以读取它。

适合：那些你希望有个按钮的一键自动化，比如"轮换这个密钥"或者"发一条测试告警"。

**输出**：你粘贴进去的那段 JSON；如果没粘，就是一个空对象。

## 计划

用一个 cron 表达式，让工作流按重复的时间表运行。

适合：夜间清理、每小时同步、每周报表。

**设置**：一个 cron 表达式。几个常见的：

- `0 * * * *`——每小时整点一次。
- `*/5 * * * *`——每 5 分钟一次。
- `0 9 * * 1`——每周一上午 9:00。

如果系统短暂不可用，这次运行会在恢复后立刻被捡起来执行——短时间的故障不用担心错过某个时间点。

## Webhook

OneUptime 会生成一个专属 URL。任何东西访问这个 URL 都会启动工作流。请求的头部、查询参数和正文都会被一并传入。

适合：把数据从别的工具接进 OneUptime——CI/CD 回调、其他监控系统的告警、你 CRM 里的注册事件。

**输出**：

- **Request Headers**——入站请求的全部头部。
- **Request Query Params**——解析后的查询字符串。
- **Request Body**——解析后的正文（如果不是 JSON，就是原始文本）。

这个 URL 同时接受 `GET` 和 `POST`。调用方会很快收到一个确认响应——工作流本身在后台运行。

把这个 URL 当密码看待。拿到它的人都能启动你的工作流。

## OneUptime 事件触发器

OneUptime 里几乎所有东西——监视器、事件、告警、计划维护、状态页、值班策略、团队——都能触发一个工作流。每一种都提供三个事件：

- **On Create**——新建一条时触发。
- **On Update**——某一条被修改时触发。
- **On Delete**——某一条被删除时触发。

"OneUptime 里一旦发生 X，就去做 Y"这类自动化就是这么搭出来的，不需要你写个循环去反复查。

完整的记录会传给下一个方块。举个例子，**Incident → On Create** 触发器会把新建的那个事件传下去，于是下一个方块就能读到它的标题、描述、严重级别，以及其他任意字段。

### 团队最常用的那些事件

- **Incident**——在事件被开启、被更新（确认、解决）或被删除时做出反应。
- **Alert**——告警的同样三个事件。
- **Monitor**——在监视器被添加、编辑或移除时做出反应。
- **Scheduled Maintenance**——维护窗口一被安排好，就自动对外发公告。
- **Status Page Subscriber**——欢迎刚刚订阅了状态页的人。
- **On-Call Duty Policy**——把排班变更同步到另一套值班系统。

在 **Add Trigger** 面板里按名字搜索，就能找到你要的那个。

## 我该用哪种触发器？

| 如果你想…                    | 就选               |
| ---------------------------- | ------------------ |
| 点个按钮来运行工作流         | **手动**           |
| 按重复的时间表运行           | **计划**           |
| 让另一个系统把数据推进来     | **Webhook**        |
| 对 OneUptime 内部的事做出反应 | **OneUptime 事件** |

一个工作流只能有一个触发器。如果同一套自动化需要两种启动方式，就把共用的逻辑做成一个工作流，再用 **Execute Workflow** 组件从两个很薄的"包装"工作流里调用它。
