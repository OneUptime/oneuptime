# 创建工作流

要新建一个工作流，打开 **工作流** 并点 **创建工作流**。**创建工作流** 对话框会先问你怎么开始，再让你起个名字。如果模板本身需要设置，比如 Slack webhook URL，还会多一步让你填写。

选择怎么开始：

- 对话框最上方的 **从零开始** 给你一块空白画布。大多数工作流都从这里开始。
- **或者从模板开始** 下面列出几个 **推荐** 模板。想看其他模板，可以在搜索框旁边选一个类别，比如 **事件**、**监视器** 或 **Jira**，或者选 **全部模板**，也可以在 **搜索模板…** 里输入。你输入的每个词都要能匹配上。

点一下模板就能看到它做什么：它的触发器、由哪些块组成，以及它会让你填写哪些设置。然后点 **使用此模板**，或者双击模板。在搜索框里，方向键可以选模板，按 **Enter** 就会使用它。按 `/` 回到搜索框。

工作流创建后默认处于关闭状态，在你开启之前不会运行任何内容。新的工作流会在 **生成器** 中打开，那就是你设计工作流的画布。

## 画布

从零开始的工作流，打开时只有一个虚线方块，上面写着 **Choose what starts this workflow**。那个方块就是起点——点它来挑一个触发器。用模板创建的工作流，打开时方块已经摆好了。

每个工作流最上面恰好有一个 **触发器**。除此之外的每一个方块都是干活的 **组件**。再加一个触发器会顶掉原来那个；删掉最后一个触发器，虚线占位方块又会回来。

添加方块：

- **触发器**——点那个虚线占位方块，会打开一个标题为 **Add Trigger** 的面板。
- **其余所有方块**——点画布上方工具栏里的 **添加组件**，同一个面板会打开，标题变成 **添加组件**。

两个面板打开时，大多数工作流都会用到的方块排在 **Popular** 下面，后面是其他内置方块。在 **OneUptime resources** 下面点一个资源，比如 **Incident**，就能看到能对它做什么；**Browse all resources** 列出了全部资源。也可以搜索：输入几个词，比如 `create incident`，最接近的结果排在最前面。按 `/` 跳到搜索框，用方向键在结果之间移动，按 **Enter** 添加高亮的那个方块。点一下方块就会把它加进来。

新方块会落在画布上最下面那个方块的下方，新的触发器则会顶替最上面的旧触发器。新方块处于选中状态；如果它落在视野之外，画布只会滚动到刚好能看见它为止。它的设置不会自动打开：准备好设置时，再点这个方块。在必填设置填好之前，方块上会显示 **Click to set up**。方块可以随意拖动；拖的时候画布会自动对齐网格。方块的位置会被保存，下一个人看到的还是你留下的那个布局。

改动自动保存。工具栏里有个小标签在跟踪这件事：改动还在路上时是 **Saving…**，成功之后是 **已保存**，没成功则是 **无法保存**。这里没有保存按钮，也没有单独的发布步骤。

## 一个方块上都有什么

| 字段                          | 它是干什么的                                                                                                                                                                                                |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier**（在 **ID** 下面） | 方块上显示的那个短 id，比如 `log-1`。别的方块靠它来引用这个方块，所以给它改名会让每一个指向它的 `{{local.components.…}}` 引用全部失效。方块的标题是组件自己的名字，改不了。 |
| **设置**                      | 这个方块干活需要的东西——一个 URL、一个 Slack 频道、一段消息正文。可选字段标着 **(Optional)**，其余都是必填的。不常用的设置收在 **高级** 折叠区里面。 |
| **Input**                     | 上边缘的那个圆点，前面方块的连线接到这里。触发器没有输入——它们之前没有任何东西会运行。                                                                                       |
| **Outputs**                   | 下边缘的那一排圆点，标签就写在它们正上方，连线从这里出去接到后面的方块。很多方块有各自独立的 **成功** 和 **错误** 输出，两种情况你都能分别处理。                  |

## 连接方块

从一个方块底部的圆点往下拖到下一个方块顶部的圆点。你画的这条线决定接下来跑什么。

- 从 **成功** 接出去，下一个方块只在前一个跑通时运行。
- 从 **错误** 接出去，下一个方块只在前一个失败时运行。
- 某个输出你没接线，这条路就到此为止。

一个输出可以接到好几个方块。它们都会运行——但是排成一队一个接一个地跑，不是并行。别指望分支之间有固定的先后，也别指望它们在时间上重叠。每个方块在一次运行里最多跑一次，所以一条绕回前面方块的连线不会让它再跑一遍。

## 配置一个方块

点一个方块（或者用 **Tab** 移到它上面再按 **Enter**），它的设置会在一个对话框里打开。每项设置都配了合适的输入方式——文本框、下拉框、代码编辑器、开关等等。填好后点 **保存**。

同一个对话框里还有：

- **删除**——移除这个方块。
- **Run just this step**——只跑这一个方块，不带工作流的其余部分。它本该从别的步骤读到的值会是空的；而它发出去、写进去或删掉的东西，是真的会发生。
- **文档**、**Inputs**、**Outputs** 和 **Returns**——这个方块期望什么、产出什么的参考卡片。

大多数文本框都接受变量——数据就是这样从一个方块流到下一个的。与其手敲语法，不如用编辑器里的取值选择器：你选好方块和字段，它就把正确的引用拼出来。见[工作流变量](/docs/workflows/variables)。

## 搭建过程中的检查

你每改一次，生成器都会把整张图检查一遍，并把结果报在工具栏的一个小标签上。点这个标签会打开 **Problems with this workflow**，里面逐条列出问题，并把你带到出问题的那个方块。在画布上，必填设置还空着的方块会显示 **Click to set up**；有其他问题的方块会在角上带一个标记：错误是红色，警告是琥珀色。把鼠标移到标记上就能看到具体哪里不对。

它抓的正是那些不跑一次就看不出来的毛病——没有触发器、两个方块用了同一个 id、id 里带了点号、某个方块没人连、必填的设置空着、JSON 格式不对、`{{ }}` 里面有空格，以及引用了并不存在的步骤或返回值。

有一件事它查不了：变量名到底存不存在。改过名的变量只有在运行日志里才会露馅。

## 你的第一个工作流

想快点摸清这张画布，就这么来：

1. 点那个虚线占位方块，再在 **Add Trigger** 面板里点 **Manual**。
2. 点 **添加组件**，再点 **Popular** 下面的 **日志**。新方块会落在触发器下方。把触发器的 **Execute** 圆点连到日志方块的输入圆点上。
3. 点一下显示 **Click to set up** 的日志方块，把它的 **值** 设成 `Hello from {{local.components.manual-1.returnValues.value.name}}`。`manual-1` 是触发器的 **Identifier**，就写在触发器方块上——对一下是不是一致。
4. 在生成器顶部把 **已启用** 打开。被禁用的工作流根本跑不了，手动也不行；如果跳过这一步，**运行工作流** 会先问你要不要把它打开。
5. 回到 **生成器**，点 **运行工作流**，在 **JSON** 字段里填 `{ "name": "Ada" }`，点 **Run Workflow Manually**，再用 **Run** 确认。
6. 一个 **Workflow Run** 面板会自己打开，跟着这次运行往下走。日志里会出现 `Value:`，后面跟着 `Hello from Ada`。

添加、连接、配置、运行、读日志——你之后搭的每一个工作流，走的都是这个循环。

## 把它打开

新建的工作流一开始是关着的，你复制出来或者导入进来的工作流也一样。工作流关着的时候，生成器会在画布上方提示这一点，并给出 **开启工作流** 按钮。

**已启用** 开关在 **生成器** 顶部，挨着 **添加组件** 和 **运行工作流**。工作流的 **概览** 页面上也有：在 **工作流详情** 卡片上点 **编辑工作流**，这张卡片会用绿色的 **已启用** 或红色的 **已禁用** 标签显示当前状态。只有能编辑这个工作流的人才能打开或关闭它；其他人看到的开关是灰的。

被禁用的工作流根本跑不了：它的触发器会被忽略，**运行工作流** 和 **Run just this step** 也一样。工作流关着的时候，如果你运行它或它的某个方块，生成器会改为询问 **开启此工作流？**。点 **开启并运行**（或 **开启并运行步骤**）会先打开工作流，再按你给的值运行你要的东西。所以顺序是：先搭好，用 **运行工作流** 测一测，读运行日志，如果你还没准备好让它的触发器真的开火，就把 **已启用** 关回去。想只测一个方块、不跑整个工作流，就用那个方块设置里的 **Run just this step**。

其他任何启动被禁用工作流的方式，也都会带着同样的提示被拒绝。调用它的 Webhook URL 会收到 HTTP 400 和 "This workflow is turned off, so it can't run. Turn it on with the Enabled switch at the top of its Builder, then try again."。调用它的 **Execute Workflow** 方块会走 **Error** 分支，错误里会写明被调用的是哪个工作流。

想暂停一个工作流又不想删掉它，把 **已启用** 关掉。不会再有新的运行开始。已经跑到一半的运行会跑完，但停在 **Sleep** 方块上的那次会在醒来时被取消，并记为一次错误。

## 收拾画布

- 拖动方块来挪位置，布局会被保存下来。
- 要删一条线，把它任意一端从圆点上拖开，丢在画布的空白处。
- 要删一个方块，点它，用设置对话框底部的 **删除**。选中一个方块或一条线按 Backspace 也能删。
- 没有办法单独复制一个方块。工作流 **设置** 页面上的 **Duplicate Workflow** 会把整个工作流复制一份，而且副本是禁用状态。
- 把方块自上而下摞起来，让它们读起来的方向就是它们跑起来的方向——输入在上边缘，输出在下边缘，流程自然往下走。
