# 工作流概览

工作流让你不写代码就能把 OneUptime 里的事情自动化。往画布上放几个方块，把它们连起来，你就得到了一段自动化——只要有事情发生它就会跑：一个事件被创建、一个计划到点了，或者别的工具把数据送进了 OneUptime。

把工作流当成你项目的后台帮手：它们对发生的事情做出反应，跟其他工具打交道，在你专心做自己那摊活儿的时候安静地把各处保持同步。

## 工作流能帮你做什么

- **把 OneUptime 接到你其他的工具上**——把事件发到 Slack、创建 Jira 工单、往你技术栈里的某个 Webhook 投递消息。
- **对 OneUptime 里发生的事做出反应**——严重事件一被创建，就通知值班团队并自动开一张工单。
- **按计划跑任务**——每五分钟一次、每天夜里一次、每周一早上一次。
- **接收外部数据**——通过一个专属 URL，让其他系统把数据推进 OneUptime。
- **复用常见的自动化**——搭一次，然后从任何别的工作流里调用它。

## 一个工作流是怎么运作的

每个工作流都由三部分组成：

1. **一个触发器**——决定工作流由什么启动。它可以是一个手动按钮、一个计划、一个入站 Webhook，或者 OneUptime 里发生的某件事（比如新建了一个事件）。
2. **一个或多个组件**——工作流具体干的活。发一条消息、发起一次 HTTP 调用、跑一次快速检查、按条件分支。
3. **它们之间的连线**——你从一个方块拉线到下一个，以此决定先后顺序。

这一切都在画布上可视化地搭出来。大多数工作流不需要写代码，不过需要的时候你也可以塞一小段 JavaScript。

## 关键术语

| 术语             | 含义                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| **工作流**       | 整段自动化——一个名称、一张画布，外加一个开关来打开或关闭它。             |
| **触发器**       | 最上面的那个方块。它决定工作流什么时候运行。每个工作流恰好有一个触发器。 |
| **组件**         | 一个动作方块——发送消息、发起请求、检查条件。                             |
| **运行**         | 工作流的一次执行。连同时间戳和每个方块的输出一起被保存下来。             |
| **全局变量**     | 一个你保存一次、然后在任何工作流里复用的值（比如一个 API key）。         |

## 在 OneUptime 里去哪儿找工作流

打开左侧导航里的 **工作流**。这一块包含：

- **工作流**——你的工作流列表。新建一个，或者打开一个已有的。
- **全局变量**——在你所有工作流之间共享的值。
- **运行和日志**——你项目里所有工作流的执行历史。

打开单个工作流，它自己的左侧菜单里有：

- **概览**——名称、描述、标签，以及 **已启用** 开关。
- **生成器**——你设计工作流的那张画布。
- **工作流变量**——只属于这一个工作流的值。
- **运行和日志**——这个工作流的每一次运行，带详情。
- **设置**——Webhook 密钥、复制和导出。

## 搭建你的第一个工作流

1. **创建**——挑一个起点，然后给工作流起个名字。
2. **选一个触发器**——手动、计划、Webhook，或者一个来自 OneUptime 的事件。
3. **添加组件**——把动作放到画布上，再连起来。
4. **把它打开**——在 **概览** 页面上把 **已启用** 拨到开。被禁用的工作流根本跑不起来，手动也不行。
5. **测试**——在生成器上点 **运行工作流**，然后盯着运行日志看。

## 一个小例子

假设你想在每次创建严重事件时往 Slack 里发一条消息：

1. 创建一个叫 "Critical incidents to Slack" 的工作流。
2. 选 **On Create Incident** 触发器。
3. 加一个 **If / Else** 方块。把它设成检查事件标题里是否含有 "Sev 1"。
4. 从 **是** 这条分支接出一个 **Slack** 方块。选好频道，写好消息。
5. 把工作流打开。

下次谁开了一个标题里带 "Sev 1" 的事件，Slack 那边就会亮起来。

## 工作流和 OneUptime 其余部分怎么配合

- **监视器** 发现问题。**事件** 记录问题。**工作流** 对问题做出反应。
- **运行手册** 是给人看的分步指南，工作流则是无人值守的自动化。需要人来做判断时用运行手册；步骤全都是自动的时候用工作流。
- **工作区连接**（Slack、Teams）是工作流把消息发出去的地方。
