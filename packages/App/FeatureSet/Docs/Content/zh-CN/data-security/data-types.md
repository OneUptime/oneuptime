# 敏感数据类型

数据安全能识别 143 种敏感数据：银行卡号、银行账户、43 个国家的国民身份证号、健康标识符、API 密钥和令牌，以及特殊类别的个人数据。每种都有一个类别、一个敏感度；如果它属于某一个国家，还会标明该国家。本页说明如何找到一个值，并列出每种数据类型，让你能判断某项内容为什么会被找到，并决定如何处理。

- [OneUptime AI 找到的数据类型](#oneuptime-ai-找到的数据类型): 在没有任何检测器能归类的字段中找到的、你们公司自己的数据类型。

## 如何找到一个值

```mermaid title="从候选值到发现"
flowchart TB
    shape["形态：由模式<br/>找到候选值"] --> valid{"是否通过<br/>其验证器？"}
    valid -->|"否"| none["没有发现"]
    valid -->|"是"| context["上下文：附近的词，<br/>或字段的名称"]
    context --> test{"是否为已知的<br/>测试值？"}
    test -->|"是"| apart["单独计数，<br/>绝不算作发现"]
    test -->|"否"| finding["发现，并附有<br/>其置信度"]
```

每次扫描——无论是一行日志、一个 CSV 单元格、一行数据库记录，还是对象开头的若干字节——都会执行相同的步骤：

1. **形态。** 每种数据类型都有用于找到候选值的模式：十六位数字，`AKIA` 加十六个字母，或者一个词、一个 `@` 加一个域名。模式绝不会在更长的词元内部匹配，因此不会在更长的一串数字中找到银行卡号。
2. **验证器。** 候选值必须通过其类型自身的规则：校验和（银行卡用 Luhn，IBAN 用 mod 97，Aadhaar 号码用 Verhoeff，大多数国民身份证号用校验位）、真实的日期、已知的前缀，或密钥所需的足够随机性。未通过的候选值根本不算发现。`000000000` 和 `123456789` 等占位符无法通过任何数字类型。
3. **上下文。** 候选值附近说明它是什么的词（默认为其前 64 个字符和后 32 个字符以内）会把它的置信度提高一级，名称指向该类型的字段也是如此。说明它是其他东西的词，例如订单号或运单号，会把置信度降低一级。没有校验和且形态常见的数字，例如护照号码或银行账户，只有在旁边有指明它的词时才会计入。
4. **已知测试值。** 公开发布的测试卡号（例如 Stripe 的 `4242 4242 4242 4242`）、示例 IBAN、`example.com` 及其他保留域名下的地址、文档用 IP 地址、政府文档中印出的示例 ID、`sk_test_` 等测试模式密钥以及占位密钥，都会单独计数。它们永远不会构成发现，因此满是这些值的数据存储会被视为测试环境，而不是数据泄露。
5. **置信度。** 剩下的就是发现，其确定程度取决于证据所能支持的程度。

| 置信度 | 含义 |
| --- | --- |
| **高** | 值通过了其验证器，并且它周围的词或它所在的字段说明了它是什么；对于字段而言，则是其大多数值都属于该类型。 |
| **中** | 值通过了其验证器，但周围没有任何内容可以确认它；或者字段的名称说明了它保存的内容，并且有一些值与之相符。 |
| **低** | 形态匹配，但没有任何内容可以确认它。 |

只有高和中置信度的发现才会计入：它们会使数据存储成为敏感数据存储，并可能打开问题。低置信度的发现会折叠列在数据存储上，供人判断：对正确的发现点击 **确认** 会使其变为高置信度，并在之后的扫描中保持为高。

当两种数据类型认领相同的字符时，更确定的发现胜出：先比较置信度，再比较哪个检测器自身的规则证明得更多，最后比较哪个匹配更长。

长值会以 64 KB 的窗口读取，窗口之间重叠 4 KB，因此值无论位于何处都能被完整找到；一个值最多读取 4 MB。

## 字段和列

列、JSON 字段或日志属性会作为一个整体来判断。它的名称暗示某种数据类型，它被抽样的值则加以证明。包含该类型的值所占的比例决定了发现的确定程度：

| 包含该类型的值 | 置信度 |
| --- | --- |
| 60% 或以上 | 高 |
| 25% 或以上 | 字段名称指向该类型时为高，否则为中 |
| 更少 | 字段名称指向该类型时为中，否则为低：一列其他内容中夹杂的几个电子邮件地址 |

值的平均长度超过 80 个字符的字段属于自由文本（备注、消息、描述），不应只保存一种类型。它的发现保留每个匹配各自获得的置信度，并注明是在自由文本中找到的。一个字段最多对 1,000 个值进行分类，每个值最多 16 KB。

字段的名称会被拆分成单词（`customerEmail`、`customer_email` 和 `customer-email` 都是“customer email”），当类型的名称提示中的单词按相同顺序相邻出现时即为匹配：“date of birth”匹配 `customer_date_of_birth`，而不匹配 `birth_city`。点分路径中只有最后一部分是字段自己的名称；当最后一部分是 `number`、`id` 或 `value` 这样的通用词时，还要加上它前面的部分：`customer.address.city` 不是街道地址，而 `card.number` 仍然是银行卡号。

有些数据类型无法通过其值来判断：没有任何模式能把人名和街道名区分开来，也没有任何模式能把宗教和其他词区分开来。当字段有值时，这些类型仅根据字段名称来查找：人名、用户名、性别、国籍、健康信息、种族或民族出身、宗教信仰、性取向、政治观点、工会会员身份、生物特征数据、基因数据和犯罪记录。此时，如果 60% 或以上的值看起来像姓名、用户名、性别或国籍，则为高，否则为中。

名称表明其保存密码的字段（`password`、`passwordHash`、`pwd`，而不是 `password_changed_at`）应该保存哈希：bcrypt、argon2、scrypt、PBKDF2 或数据存储可能使用的其他方案。空值、`********` 等占位符和加密值会被排除。如果其余的值中不是哈希的多于是哈希的，则该字段保存的是密码本身（任何模式都看不出来），数据存储将无法通过 [密码以明文存储](/docs/data-security/checks-and-issues#数据卫生) 这项检查。

### 没有任何检测器能归类的字段

名称不指向任何数据类型、值也不匹配任何检测器的列或字段，并不意味着它是安全的：它可能是你自己的客户编号，也可能是用另一种语言命名的列。项目开启 **启用 AI** 后，内容扫描会保留这类字段，每次扫描最多 200 个，并询问 OneUptime AI 每个字段包含项目的哪种数据类型，每个数据存储一次最多 40 个字段。它只会得到字段名、相邻字段的名称以及值的形状——每个字母写作 `a` 或 `A`，每个数字写作 `9`，因此 `AB-1234` 会变成 `AA-9999`——从不包含任何值。自由文本、少于 5 个值的字段、较小的整数，以及名称表示 ID、时间或状态的字段都不会被询问。

遥测扫描也以同样的方式保留没有任何检测器能归类的属性，来自服务的日志、Span、指标和其余遥测，每次扫描每个服务最多 50 个。它从不保留 OneUptime 自己的属性、OpenTelemetry 约定写在每条记录上用来说明记录来源的属性（例如服务、主机或 Pod），也从不保留自由文本，例如日志正文。

OneUptime AI 给出的每种类型都是一个低置信度发现，标记为 **由 OneUptime AI 建议**，并附上理由；理由以你项目的语言撰写，横跨该发现所在的整行显示。与任何低置信度发现一样，在有人在数据存储的 **内容** 页面上选择 **确认** 之前，它不计入任何内容；**标记为不敏感** 会将其驳回。已得到回答的字段在 30 天内不会再次询问，经人判断过的字段则不会再询问。

## 敏感度

| 敏感度 | 含义 |
| --- | --- |
| **受限** | 一旦泄露就会造成损害：密钥、银行卡号、健康记录、政府身份证件号码。 |
| **机密** | 个人数据，以及标记为机密的文档。 |
| **内部** | 企业自己的数据，不应提供给外部人员。 |
| **公开** | 未找到任何敏感内容。 |

数据存储的敏感度，等于其中以至少为中的置信度找到的最敏感数据类型的敏感度。测试值和标记为不敏感的发现不计入，未找到任何内容的数据存储为公开。如果要让数据存储比其发现所显示的更敏感或更不敏感，请在数据存储的 **设置** 中自行设置其敏感度：之后检查会使用这个值。

## 类别

| 类别 | 涵盖内容 | 个人数据 |
| --- | --- | --- |
| 密钥和凭据 | 可解锁其他系统的密码、API 密钥、令牌和私钥。 | 否 |
| 财务 | 银行卡号、银行账户、IBAN 和加密货币钱包。 | 是 |
| 健康 | 病历号、健康标识符、诊断和处方。 | 是 |
| 政府身份证件 | 国民身份证号、税号、护照号码和社会保障号码。 | 是 |
| 特殊类别 | GDPR 第 9 条最严格保护的数据：种族、宗教、性取向、政治、工会会员身份、生物特征和基因数据。 | 是 |
| 联系方式和身份 | 某人是谁以及如何联系到他们：电子邮件、电话、地址、出生日期、IP 地址。 | 是 |
| 商业机密 | 标记为机密、仅限内部或受特权保护的文档。 | 否 |

个人数据是指 GDPR、CCPA、LGPD 和 DPDP 所定义的、关于某个人的数据。只保存密钥和商业文档的数据存储不在隐私框架的范围内，但绝不会不在安全框架的范围内（请参阅 [数据安全合规](/docs/data-security/compliance)）。

## 内置数据类型

属于某一个国家的数据类型会用 ISO 3166-1 代码标明该国家：数据驻留规则和与国家绑定的框架会读取它（请参阅 [数据驻留](/docs/data-security/flows-access-residency#数据驻留规则)）。ID 是 API 和发现用来指称该类型的名称。

## 你自己的数据类型

为只有你的公司才有的内容添加一种数据类型：员工 ID、保单号、项目代码。前往 **数据安全 → 设置 → 数据类型**，在 **您的数据类型** 下添加它。从下一次扫描开始，它会像内置数据类型一样在存储桶、数据库和遥测中被扫描。

:::steps
### 说明它是什么

为它填写 **名称**（例如员工 ID）、**类别** 和 **灵敏度**：即保存它的数据存储有多敏感。**描述** 说明它是什么，供阅读它的发现的人参考。

### 说明如何找到它

输入 **模式**：匹配单个值的 JavaScript 正则表达式，例如 `EMP-\d{6}`。添加保存它的 **字段名称**（例如 `employee id`），以及出现在值附近时可确认它属于此类型的 **关键字**。将模式留空，则只根据字段名称查找该类型。

### 测试它

将示例文本粘贴到 **测试** 中，查看你的数据类型能在其中找到什么。它会在你的浏览器中对文本运行扫描器自己的代码：文本永远不会发送到 OneUptime，并且只测试其前 64 KB。
:::

在 **更多字段** 下，**忽略大小写** 会不区分字母大小写地匹配模式，**需要关键字** 只在值附近有关键字或字段名称表明它属于此类型时才计入该值，**校验和** 则要求值通过一项校验：**无**、**Luhn**（银行卡号带有的校验位）、**Mod97**（IBAN 的校验位）或 **Verhoeff**（Aadhaar 号码的校验位）。

模式会在你保存时被检查：它必须能编译、不匹配空文本，并且运行时间与文本长度呈线性关系。它由一个从不回溯的匹配器运行，因此无论模式怎么写，都不会拖住扫描。一种类型最多可有 50 个关键字和 50 个字段名称。

如果你的类型设置了校验和且值通过了校验，该值单独出现时为中，附近有关键字时为高；如果没有校验和，单独出现时为低，附近有关键字时为中。在列中，与每种类型一样，由匹配的值所占的比例决定。

### 描述

在新数据类型表单的顶部， **描述** 会为你填写表单。写下数据的样子，例如“我们的员工 ID 形如 EMP-123456，有时没有连字符”，愿意的话再添加几个示例，每行一个，然后选择 **填写表单** 。OneUptime AI 只会收到你的句子和示例的形态，绝不会收到示例本身：示例留在你的浏览器中， **测试** 会显示它的模式找到了其中几个。阅读它填写的内容，修改你想改的地方，然后保存：在你保存之前什么都不会保存，模式也会像你自己写的一样接受检查。使用描述需要为项目打开 **启用 AI** 。

## OneUptime AI 找到的数据类型

没有任何检测器能归类的字段中，常常有你们公司自己的数据类型，以含义相同的名称保存在很多地方：例如一家保险公司的保单号，在它所有的数据库中都放在名为 `policy_no`、`policyNumber` 和 `police_nr` 的列里。为项目打开 **启用 AI** 后，OneUptime AI 会在扫描保留的字段中找到这样的数据类型，并且只在你自己的扫描证实它之后才询问你。

:::steps
### 找到一组字段

当两个或更多数据存储中的三个或更多字段的大多数值具有同一种形态（各部分之间有没有分隔符都可以），并且它们的名称共享一个说明其内容的词时，这些字段组成一组。没有数字的形态、日期、时间或小数永远不会组成一组，而像 `id`、`no` 或 `number` 这样的词本身说明不了什么。

### 起草数据类型

OneUptime AI 为每个新组起草一个数据类型，一次最多 3 个，依据是字段的名称和值的形态，绝不使用任何值。草稿必须通过与已保存类型相同的检查，并能找到起草它所依据的形态。达不到要求的草稿会再请求一次，并附上原因。

### 接下来的扫描证实它

草稿在其组中每个数据存储的下一次扫描中运行，最长 48 小时或一个扫描间隔，以较长者为准。它不会产生任何发现：每次扫描都会统计它在组内字段和同一数据存储的其他所有字段中会找到多少个值。当它找到自身字段中至少 80% 的值、而其他值最多只找到 1% 时，才会被建议。在别处它几乎找到所有值的字段，以其他名称保存着相同的数据：这样的字段会被列出，而不会被算作它的缺点。
:::

每个草稿同时也会以收窄的形式计数：在组内字段之外，收窄的草稿只有在值旁边有其某个关键字，或值位于指向它的字段名称下时，才会找到该值。在别处找到太多值的草稿，如果收窄后足够，就以收窄的形式被建议。两种形式都不够的草稿会被放弃，它所在的组在 30 天内不会再被起草。

它建议的每个数据类型都在 **数据安全 → 设置 → 数据类型** 顶部以及 **数据安全 → 人工智能** 上的 **待审核的数据类型** 中等待，并附有扫描统计的结果，例如“匹配这 11 个字段中 98% 的值，以及同一数据存储中其他位置 0.1% 的值。” **添加数据类型** 会打开已用它填好的数据类型表单，供你修改和测试；保存后即添加该类型，扫描从下一次运行起就会找到它。 **不是数据类型** 会拒绝它：它永远不会再为这些字段被建议。添加需要一个可以创建数据类型的角色。

## 不敏感与从不敏感

扫描找到的内容可能并非看上去的那样：一列碰巧通过 Luhn 校验的订单号，或每一行日志中都有的你自己的支持邮箱地址。告诉 OneUptime 这一点，它就不再计入：

- **将发现标记为不敏感。** 在数据存储的 **内容** 页面上，对该发现选择 **标记为不敏感** 并说明原因。它将不再计入数据存储的敏感度或其检查，数据存储也会立即重新检查。该发现会带着标记和你的原因保留在数据存储上，让下一个人看到当时的决定。
- **将值添加到“从不敏感”**，它位于数据安全的设置中，适用于在任何地方都永远不算发现的值，例如 `support@yourcompany.com`。扫描器先对值进行规范化，再忽略大小写进行比较。
- **关闭内置数据类型。** 在 **数据安全 → 设置 → 数据类型** 页面的 **内置数据类型** 下，每种数据类型都有一个开关，拨动后立即保存。项目的任何扫描都不会查找已关闭的类型。

## OneUptime AI 的判定

项目开启 **启用 AI**，并在 **数据安全 → 人工智能** 下开启 **处理新问题** 后，OneUptime AI 会在每次扫描数据存储之后，对每个等待人来处理的发现给出判定。当扫描对某个发现没有把握时——低置信度发现，或 OneUptime AI 的某条建议——或者当中或高置信度的发现显示出错误匹配的迹象时，该发现就会等待处理：

- 匹配到的内容大多是已知的测试值；
- 字段的名称指向另一种数据类型，而不是这一种；
- ID 字段（例如 `order_number`、`invoice_no` 或 `ref_id`）中保存着一种用 Luhn 算法校验的类型（任意数字串中每十个就有一个能通过该校验），而字段的名称并不指向该类型。

判定为 **建议确认**、**不敏感** 或 **无法判断**，并附有以你项目的语言撰写的理由。判定横跨该发现所在的整行显示，位于数据存储的 **内容** 页面和 **遥测中** 页面上，并附上它所依据的你团队的决定，例如“您的团队已在 4 个数据存储中将 `order_number` 标记为不敏感”。**显示决定** 会逐一列出这些决定：其数据存储、其字段以及你的团队给出的原因。

### 作为先例的团队决定

OneUptime AI 会得到你的团队此前对同一数据类型的发现所做的决定，最多十条。首先是任何数据存储上同名字段中的决定：`order_number`、`orderNumber` 和 `public.orders.order_number` 都是“order number”。其中同一位置的决定排在最前，其次按决定的新旧排列，最新的在前。然后是名称或为其给出的原因表达了相同含义的字段，例如原因为“Shopify 订单号”的 `order_ref`。它会得知每个发现所在的位置、所做的决定以及给出的原因，原因中的任何值都会被去掉。它绝不会得到任何值、脱敏样本或记录。

自由文本中的发现，例如日志正文或消息中的发现，没有可供匹配的字段名称。它的先例是另一个数据存储上的同一位置，例如另一个服务的日志正文。

### OneUptime AI 自行决定的事

- **它绝不会将发现标记为不敏感**，无论规则如何。这由人来做，并附上自己的原因。当判定为 **不敏感** 时，**标记为不敏感** 会以 OneUptime AI 起草的原因开始，你可以修改它。
- **只有在 AI 规则允许时，它才会自行确认发现**：需要有一条针对该数据存储和数据类型、且 **判定** 为 **自动** 的数据安全 AI 规则。它还需要你的团队亲自确认过类似的发现，或者字段以该类型命名。该确认会记录在数据存储的 **时间线** 上以及 **数据安全 → 人工智能** 的 **由 AI 完成** 中，**撤销** 可以将其撤回。

否则，判定会在该发现所在的行上等待。如果项目有 AI 规则，只有当针对其数据存储和数据类型的规则开启了 **判定** 时，发现才会得到判定；仅限于某些检查或严重程度的规则针对的是问题，不会判定任何发现。每次扫描后，OneUptime AI 最多判定一个数据存储的 40 个发现，先判定从未判定过的发现，其余的在下一次扫描后判定。在之后的扫描中，只有当判定所依据的内容发生变化时（例如对类似发现做出了新的决定），才会再次询问该发现。

## 类似发现

在你确认某个发现或将其标记为不敏感后，**应用到类似发现** 会列出尚无人决定的类似发现：同一数据类型、位于同名字段中，在此数据存储以及你有权读取的所有其他数据存储上。每一项都已勾选。取消勾选你想单独判断的项，其余的项就会作为你自己的更改得到相同的决定，并附上你的原因；你无权更改的发现会保持原样。**暂不** 会让它们全部保持原样。自由文本中的发现永远没有类似发现：一段文本包含的内容并不能说明另一段文本的任何情况。

## 你的决定对扫描说明了什么

当你的团队将发现标记为不敏感时，OneUptime AI 会在 **数据安全 → 人工智能** 的 **等待您处理** 下提议对扫描的更改：

- **关闭内置数据类型**：当它的每个发现都被标记为不敏感，且至少有 2 个数据存储上的至少 3 个发现时。OneUptime AI 仅建议过的发现不计入。
- **将某个位置排除在数据存储的扫描之外**：当那里的每个发现都被标记为不敏感，且至少有 2 个时。它针对的是数据库列或遥测属性，扫描可以单独排除它们。

每项提议始终等待人来批准：停止查找的扫描会错过之后到来的真实数据。**从不敏感** 永远不会被提议，因为它保存的是值，而 OneUptime AI 从不会看到任何值。
