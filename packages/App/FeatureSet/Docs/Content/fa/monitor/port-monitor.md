# مانیتور پورت

پایش پورت به شما امکان می‌دهد در دسترس بودن یک پورت TCP مشخص روی یک میزبان را پایش کنید. OneUptime به‌صورت دوره‌ای تلاش می‌کند یک اتصال TCP به پورت مشخص‌شده برقرار کند و بررسی می‌کند که آیا باز و پاسخگوست یا نه.

## نمای کلی

مانیتورهای پورت آزمایش می‌کنند که یک پورت شبکه مشخص اتصال‌ها را می‌پذیرد یا نه. این کار به شما امکان می‌دهد:

- در دسترس بودن سرویس روی پورت‌های مشخص را پایش کنید
- کل زمان اتصال، شامل تفکیک نام DNS و برقراری اتصال TCP، را دنبال کنید
- راستی‌آزمایی کنید که سرویس‌هایی مانند پایگاه داده، سرور ایمیل و سرور برنامه در حال اجرا هستند
- قطعی سرویس را پیش از اثرگذاری بر کاربران تشخیص دهید

## ساخت یک مانیتور پورت

1. در داشبورد OneUptime به **Monitors** بروید
2. روی **Create Monitor** کلیک کنید
3. نوع مانیتور را **Port** انتخاب کنید
4. نام میزبان یا آدرس IP و شماره پورت را وارد کنید
5. معیارهای پایش را در صورت نیاز پیکربندی کنید

## گزینه‌های پیکربندی

### نام میزبان یا آدرس IP

نام میزبان یا آدرس IP میزبان هدف را وارد کنید (برای نمونه `example.com` یا `192.168.1.1`).

### پورت

شماره پورت موردنظر برای پایش را وارد کنید (۱ تا ۶۵۵۳۵). نمونه‌های رایج:

| پورت  | سرویس      |
| ----- | ---------- |
| 22    | SSH        |
| 25    | SMTP       |
| 80    | HTTP       |
| 443   | HTTPS      |
| 3306  | MySQL      |
| 5432  | PostgreSQL |
| 6379  | Redis      |
| 27017 | MongoDB    |

## زمان‌بندی اتصال

برای هدفی که نام میزبان است، OneUptime بررسی پورت را در دو فاز اندازه‌گیری می‌کند:

1. **تفکیک نام DNS** — زمان از آغاز بررسی تا شروع اولین تلاش اتصال TCP.
2. **اتصال TCP** — زمان از اولین تلاش اتصال TCP تا موفق شدن اتصال. این شامل زمان صرف‌شده برای امتحان آدرس دیگری هنگام نیاز به بازگشت میان IPv6/IPv4 هم می‌شود.

**کل زمان اتصال (DNS + TCP)** از آغاز بررسی تا موفق شدن اتصال TCP اندازه‌گیری می‌شود. این مقدار به‌عنوان همان زمان پاسخ موجود مانیتور پورت هم نگه داشته می‌شود، بنابراین معیارها، هشدارها و نمودارهای تاریخی فعلی همچنان از همان فیلد استفاده می‌کنند.

وقتی هدف یک آدرس IP باشد، نیازی به تفکیک نام DNS نیست، پس فاز DNS حذف می‌شود. نتایج قدیمی‌تری که پیش از در دسترس بودن زمان‌بندی فازی جمع‌آوری شده‌اند فقط کل زمان اتصال را نشان می‌دهند.

## معیارهای پایش

می‌توانید معیارهایی پیکربندی کنید که تعیین کنند پورت شما بر چه پایه‌ای آنلاین، تضعیف‌شده یا آفلاین در نظر گرفته شود:

### انواع فیلتر در دسترس

| نوع فیلتر                                   | توضیحات                                                                            |
| ------------------------------------------- | ---------------------------------------------------------------------------------- |
| آنلاین است                                  | اینکه پورت باز است و اتصال می‌پذیرد یا نه                                          |
| کل زمان اتصال (DNS + TCP) (میلی‌ثانیه)      | کل زمان اتصال، شامل تفکیک نام DNS وقتی هدف یک نام میزبان است                       |
| زمان تفکیک نام DNS پورت (میلی‌ثانیه)        | زمان تفکیک نام DNS پیش از اولین تلاش TCP؛ وقتی هدف یک IP است در دسترس نیست         |
| زمان اتصال TCP پورت (میلی‌ثانیه)            | زمان از اولین تلاش TCP تا موفق شدن اتصال، شامل بازگشت میان IPها                    |
| وقفه درخواست                                | اینکه تفکیک نام DNS یا تلاش اتصال TCP از محدودیت زمانی پیکربندی‌شده فراتر رفته یا نه |

### شرط‌های فیلتر

برای **آنلاین است** و **وقفه درخواست**:

- **درست** — شرط برقرار است
- **نادرست** — شرط برقرار نیست

برای **کل زمان اتصال (DNS + TCP)**، **زمان تفکیک نام DNS پورت** و **زمان اتصال TCP پورت**:

- **بزرگ‌تر از** — زمان پاسخ از یک آستانه فراتر می‌رود
- **کوچک‌تر از** — زمان پاسخ از یک آستانه کمتر است
- **بزرگ‌تر یا مساوی** — زمان پاسخ روی آستانه یا بالاتر از آن است
- **کوچک‌تر یا مساوی** — زمان پاسخ روی آستانه یا پایین‌تر از آن است

**این معیار را در یک بازه زمانی ارزیابی کن** یک چک‌باکس جداگانه در فرم معیار است، نه یک شرط فیلتر. آن را روشن کنید تا به‌جای مقدار آخرین بررسی، یک مقدار تجمیعی مقایسه شود — که زیر **ارزیابی** انتخاب می‌شود (میانگین، جمع، بیشینه، کمینه، همه مقادیر، هر مقدار) در پنجره‌ای که با **در (دقیقه) گذشته** تعیین می‌کنید.

**همه مقادیر** فقط وقتی مطابقت پیدا می‌کند که پنجره واقعاً با داده پوشیده شده باشد. مانیتوری که تازه ساخته شده، یا مانیتوری که ثبت بررسی‌هایش متوقف شده، تاریخچه کافی برای اظهارنظر درباره N دقیقه گذشته ندارد، بنابراین معیار به‌جای مطابقت با تنها داده موجود، منتظر می‌ماند. **هر مقدار** تنظیم مناسب برای «همان لحظه که یک بررسی از حد گذشت به من بگو» است و همچنان بی‌درنگ فعال می‌شود.

**اگر داده‌ای نبود** تعیین می‌کند تا وقتی پنجره نمی‌تواند پشتیبان معیار باشد چه اتفاقی بیفتد:

- **نادیده بگیر** (پیش‌فرض) — معیار مطابقت پیدا نمی‌کند. برای هشداردهی معمولی روی آستانه از این استفاده کنید.
- **فعال کن** — نبود داده را خودِ مشکل در نظر بگیر. برای بررسی‌های ضربان‌گونه که سکوت خودش شکست است از این استفاده کنید.
- **صفر در نظر بگیر** — پنجره را به‌عنوان یک صفر مقایسه کن. برای شمارنده‌هایی که «هیچ رویدادی» واقعاً یعنی صفر از این استفاده کنید.

وقتی هدف از پیش یک آدرس IP باشد، معیارهای تفکیک نام DNS مقداری برای ارزیابی ندارند. برای معیارهایی که باید هم با نام میزبان و هم با آدرس IP کار کنند، از کل زمان اتصال یا زمان اتصال TCP استفاده کنید.

### نمونه معیار

#### اگر پورت بسته است، آفلاین علامت بزن

- **نوع فیلتر**: آنلاین است
- **شرط فیلتر**: نادرست

#### هشدار اگر کل زمان اتصال از ۵۰۰ میلی‌ثانیه بیشتر شود

- **نوع فیلتر**: کل زمان اتصال (DNS + TCP) (میلی‌ثانیه)
- **شرط فیلتر**: بزرگ‌تر از
- **مقدار**: ۵۰۰

#### اگر کل اتصال کند است، تضعیف‌شده علامت بزن

- **نوع فیلتر**: کل زمان اتصال (DNS + TCP) (میلی‌ثانیه)
- **شرط فیلتر**: بزرگ‌تر از
- **مقدار**: ۲۰۰

#### هشدار اگر تفکیک نام DNS کند است

- **نوع فیلتر**: زمان تفکیک نام DNS پورت (میلی‌ثانیه)
- **شرط فیلتر**: بزرگ‌تر از
- **مقدار**: ۱۰۰

#### هشدار اگر برقراری اتصال TCP کند است

- **نوع فیلتر**: زمان اتصال TCP پورت (میلی‌ثانیه)
- **شرط فیلتر**: بزرگ‌تر از
- **مقدار**: ۲۵۰
