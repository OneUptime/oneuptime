# مانیتور سرور / ماشین مجازی

مانیتورینگ سرور و ماشین مجازی به شما امکان می‌دهد با نصب عاملی سبک که سنجه‌های سامانه را به OneUptime گزارش می‌دهد، سلامت و کارایی سرورها، ماشین‌های مجازی و دیگر زیرساخت‌هایتان را زیر نظر بگیرید.

## نمای کلی

مانیتورهای سرور از عامل زیرساختی نصب‌شده روی سرورهایتان برای جمع‌آوری و گزارش سنجه‌های سامانه استفاده می‌کنند. این به شما امکان می‌دهد:

- آپ‌تایم و دسترس‌پذیری سرور را زیر نظر بگیرید
- مصرف CPU، حافظه و دیسک را ردیابی کنید
- فرایندهای در حال اجرا را زیر نظر بگیرید
- بر پایه آستانه‌های بهره‌برداری از منابع، هشدار تنظیم کنید
- مشکل‌های زیرساخت را پیش از اثرگذاری بر سرویس‌هایتان تشخیص دهید

## ساختن یک مانیتور سرور

1. در داشبورد OneUptime به **Monitors** بروید
2. روی **Create Monitor** کلیک کنید
3. نوع مانیتور را **Server / VM** انتخاب کنید
4. یک **Secret Key** برای این مانیتور تولید می‌شود — برای پیکربندی عامل به آن نیاز خواهید داشت
5. برای راه‌اندازی عامل روی سرورتان، دستورالعمل نصب را دنبال کنید

## نصب عامل زیرساخت

عامل زیرساخت OneUptime دیمنی سبک و مبتنی بر Go است که سنجه‌های سامانه را جمع می‌کند و هر ۳۰ ثانیه به OneUptime می‌فرستد. از Linux، macOS و Windows پشتیبانی می‌کند.

### Linux / macOS

```bash
# Install the agent
curl -sSL https://oneuptime.com/docs/static/scripts/infrastructure-agent/install.sh | sudo bash

# Configure the agent
sudo oneuptime-infrastructure-agent configure --secret-key=YOUR_SECRET_KEY --oneuptime-url=https://oneuptime.com

# Start the agent
sudo oneuptime-infrastructure-agent start
```

به‌جای `YOUR_SECRET_KEY` کلید محرمانه‌ای را بگذارید که در تنظیمات مانیتورتان نمایش داده می‌شود، و اگر خودمیزبان هستید به‌جای `https://oneuptime.com` نشانی نمونه OneUptime خود را.

### Windows

1. آخرین عامل را از [انتشارهای GitHub](https://github.com/OneUptime/oneuptime/releases/latest) دانلود کنید
   - `oneuptime-infrastructure-agent_windows_amd64.zip` برای سامانه‌های x64
   - `oneuptime-infrastructure-agent_windows_arm64.zip` برای سامانه‌های ARM64
2. فایل zip را استخراج کنید
3. Command Prompt را به‌عنوان Administrator باز کنید و اجرا کنید:

```bash
# Configure the agent
oneuptime-infrastructure-agent configure --secret-key=YOUR_SECRET_KEY --oneuptime-url=https://oneuptime.com

# Start the agent
oneuptime-infrastructure-agent start
```

### پشتیبانی از پراکسی

اگر سرور شما از راه پراکسی به اینترنت وصل می‌شود، می‌توانید عامل را برای استفاده از آن پیکربندی کنید:

```bash
sudo oneuptime-infrastructure-agent configure --secret-key=YOUR_SECRET_KEY --oneuptime-url=https://oneuptime.com --proxy-url=http://proxy.example.com:8080
```

## فرمان‌های عامل

عامل زیرساخت از فرمان‌های زیر پشتیبانی می‌کند:

| فرمان | توضیح |
| ----------- | ---------------------------------------------------------- |
| `configure` | عامل را با کلید محرمانه و نشانی OneUptime شما پیکربندی می‌کند |
| `start` | سرویس عامل را آغاز می‌کند |
| `stop` | سرویس عامل را متوقف می‌کند |
| `restart` | سرویس عامل را بازراه‌اندازی می‌کند |
| `status` | وضعیت جاری سرویس را نشان می‌دهد |
| `logs` | گزارش‌های عامل را می‌بیند (`-n` برای شمار خط، `-f` برای دنبال کردن) |
| `uninstall` | سرویس عامل را حذف نصب می‌کند |

## سنجه‌های جمع‌آوری‌شده

عامل سنجه‌های زیر را از سرور شما جمع می‌کند:

### CPU

- **درصد مصرف CPU** — بهره‌برداری کلی از CPU به‌صورت درصد
- **هسته‌های CPU** — شمار هسته‌های CPU

### حافظه

- **حافظه کل** — کل حافظه در دسترس
- **حافظه مصرف‌شده** — حافظه‌ای که هم‌اکنون در استفاده است
- **حافظه آزاد** — حافظه آزاد در دسترس
- **درصد مصرف حافظه** — بهره‌برداری از حافظه به‌صورت درصد

### دیسک

برای هر دیسک/حجم سوارشده:

- **فضای کل دیسک** — ظرفیت کل دیسک
- **فضای مصرف‌شده دیسک** — فضایی که هم‌اکنون در استفاده است
- **فضای آزاد دیسک** — فضای آزاد در دسترس
- **درصد مصرف دیسک** — بهره‌برداری از دیسک به‌صورت درصد
- **مسیر دیسک** — مسیر سوار کردن دیسک

### فرایندها

- **نام فرایند** — نام فرایند در حال اجرا
- **شناسه فرایند (PID)** — شناسه فرایند
- **فرمان فرایند** — فرمان کاملی که برای آغاز فرایند به کار رفته است

## معیارهای مانیتورینگ

می‌توانید معیارهایی پیکربندی کنید تا مشخص شود سرور شما کی آنلاین، تنزل‌یافته یا آفلاین در نظر گرفته می‌شود.

### نوع‌های پالایه در دسترس

| نوع پالایه | توضیح |
| ------------------------ | -------------------------------------------------------------- |
| Is Online | اینکه آیا عامل سرور گزارش می‌دهد یا نه (بر پایه ضربان قلب) |
| CPU Usage (in %) | درصد جاری بهره‌برداری از CPU |
| Memory Usage (in %) | درصد جاری بهره‌برداری از حافظه |
| Disk Usage (in %) | درصد جاری بهره‌برداری از دیسک (برای مسیر دیسک مشخص) |
| Swap Usage (in %) | درصد جاری بهره‌برداری از swap |
| CPU IO Wait (in %) | درصد زمان CPU که صرف انتظار برای ورودی/خروجی می‌شود |
| Load Average (1 minute) | میانگین بار سامانه در آخرین دقیقه |
| Load Average (5 minute) | میانگین بار سامانه در ۵ دقیقه گذشته |
| Load Average (15 minute) | میانگین بار سامانه در ۱۵ دقیقه گذشته |
| Server Process Name | بررسی اینکه فرایندی با نامی مشخص در حال اجراست یا نه |
| Server Process Command | بررسی اینکه فرایندی با فرمانی مشخص در حال اجراست یا نه |
| Server Process PID | بررسی اینکه فرایندی با PID مشخص در حال اجراست یا نه |

### شرط‌های پالایه

برای سنجه‌های عددی (CPU، حافظه، دیسک، swap، انتظار ورودی/خروجی CPU، میانگین بار):

- **Greater Than** — مقدار از آستانه بیشتر است
- **Less Than** — مقدار زیر آستانه است
- **Greater Than or Equal To** — مقدار در آستانه یا بالاتر است
- **Less Than or Equal To** — مقدار در آستانه یا پایین‌تر است

گزینه **Evaluate this criteria over a period of time** یک جعبه انتخاب جداگانه روی فرم معیارهاست، نه یک شرط پالایه. آن را روشن کنید تا به‌جای مقدار آخرین بررسی، یک تجمیع — که زیر **Evaluate** انتخاب می‌شود (Average، Sum، Maximum Value، Minimum Value، All Values، Any Value) روی پنجره‌ای که با **For the last (in minutes)** تنظیم شده — سنجیده شود.

گزینه **All Values** فقط وقتی مطابقت می‌کند که پنجره واقعاً با داده پوشیده شده باشد. مانیتوری که تازه ساخته شده، یا مانیتوری که ثبت بررسی‌هایش متوقف شده، تاریخچه کافی ندارد که چیزی درباره N دقیقه گذشته بگوید، پس معیار به‌جای مطابقت با تنها خوانشی که دارد منتظر می‌ماند. گزینه **Any Value** تنظیمی است برای «همان لحظه که یک بررسی تنها آستانه را می‌شکند به من بگو» و همچنان بی‌درنگ شلیک می‌کند.

گزینه **If No Data** کنترل می‌کند وقتی پنجره نمی‌تواند پشتوانه معیار باشد چه اتفاقی می‌افتد:

- **Ignore** (پیش‌فرض) — معیار مطابقت نمی‌کند. برای هشداردهی آستانه‌ای معمولی از این استفاده کنید.
- **Trigger** — نبود داده را خودِ مشکل بدانید. برای بررسی‌های ضربان‌قلب‌مانند که سکوت خودش شکست است از این استفاده کنید.
- **Treat As Zero** — پنجره را به‌عنوان یک صفر تنها بسنجید. برای شمارنده‌هایی که «بدون رویداد» واقعاً یعنی صفر از این استفاده کنید.

برای بررسی فرایندها:

- **Is Executing** — فرایند هم‌اکنون در حال اجراست
- **Is Not Executing** — فرایند در حال اجرا نیست

### نمونه معیارها

#### اگر عامل گزارش دادن را متوقف کرد، سرور را آفلاین علامت بزن

- **Filter Type**: Is Online
- **Filter Condition**: False

#### وقتی مصرف CPU از ۹۰٪ گذشت هشدار بده

- **Filter Type**: CPU Usage (in %)
- **Filter Condition**: Greater Than
- **Value**: 90

#### وقتی مصرف دیسک از ۸۵٪ گذشت هشدار بده

- **Filter Type**: Disk Usage (in %)
- **Disk Path**: `/`
- **Filter Condition**: Greater Than
- **Value**: 85

#### وقتی مصرف حافظه از ۸۰٪ گذشت هشدار بده

- **Filter Type**: Memory Usage (in %)
- **Filter Condition**: Greater Than
- **Value**: 80

#### اگر فرایندی حیاتی از اجرا افتاد هشدار بده

- **Filter Type**: Server Process Name
- **Filter Condition**: Is Not Executing
- **Value**: `nginx`

## رفع اشکال

### عامل گزارش نمی‌دهد

- تأیید کنید عامل در حال اجراست: `sudo oneuptime-infrastructure-agent status`
- گزارش‌های عامل را بررسی کنید: `sudo oneuptime-infrastructure-agent logs -n 50`
- درست بودن کلید محرمانه را تأیید کنید
- مطمئن شوید سرور می‌تواند به نشانی نمونه OneUptime شما برسد
- بررسی کنید قواعد دیوار آتش اتصال‌های HTTPS خروجی را مجاز می‌کنند

### مصرف بالای منابع توسط عامل

عامل طوری طراحی شده که سبک باشد. اگر مصرف بالای منابع دیدید:

- عامل را بازراه‌اندازی کنید: `sudo oneuptime-infrastructure-agent restart`
- گزارش‌های عامل را برای خطاها بررسی کنید

### مشکل‌های پراکسی

- درست بودن نشانی و درگاه پراکسی را تأیید کنید
- مطمئن شوید پراکسی اتصال به نمونه OneUptime شما را مجاز می‌کند
- با این دوباره پیکربندی کنید: `sudo oneuptime-infrastructure-agent configure --proxy-url=http://proxy:port --secret-key=YOUR_KEY --oneuptime-url=YOUR_URL`

## بهترین شیوه‌ها

1. **آستانه‌های معنادار تنظیم کنید** — معیارهای تنزل و آفلاین را طوری پیکربندی کنید که با محدوده‌های عادی کارکرد سرورتان بخواند
2. **فرایندهای حیاتی را زیر نظر بگیرید** — از مانیتورینگ فرایند استفاده کنید تا مطمئن شوید سرویس‌های ضروری مانند کارسازهای وب و پایگاه‌های داده همیشه در حال اجرا هستند
3. **مصرف دیسک را پیش‌دستانه زیر نظر بگیرید** — مشکل‌های فضای دیسک می‌توانند به شکست برنامه بینجامند؛ خیلی پیش از پر شدن دیسک‌ها هشدار تنظیم کنید
4. **روی یک بازه زمانی بسنجید** — برای سنجه‌هایی مانند CPU که می‌توانند لحظه‌ای جهش کنند، «Evaluate this criteria over a period of time» را روشن کنید و از تجمیع زمانی استفاده کنید تا از هشدارهای کاذب پرهیز شود
5. **عامل را به‌روز نگه دارید** — گاه‌به‌گاه عامل زیرساخت را به‌روزرسانی کنید تا آخرین بهبودها و رفع اشکال‌ها را بگیرید
