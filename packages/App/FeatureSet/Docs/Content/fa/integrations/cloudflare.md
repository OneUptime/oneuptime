# Cloudflare

آنچه را فایروال [Cloudflare](https://www.cloudflare.com) در لبه انجام داد به رویدادهای امنیتی OneUptime وارد کنید: درخواست‌هایی که قاعده‌های مدیریت‌شده و سفارشی WAF، محدودیت نرخ، IP Access Rules، مدیریت بات و محافظت HTTP DDoS آن مسدود کردند، به چالش کشیدند یا ثبت کردند. هر کدام کنار درخواست‌های خود برنامهٔ شما قرار می‌گیرد، پس یک پرونده می‌گوید Cloudflare چه چیزی را متوقف کرد و چه چیزی باز هم به برنامهٔ شما رسید. OneUptime آن‌ها را با یک توکن API که فقط می‌تواند بخواند می‌خواند، و چیزی را در Cloudflare تغییر نمی‌دهد.

:::cards
- [راه‌اندازی اتصال](#راهاندازی-اتصال): یک توکن API با دو مجوز خواندن، و فرم اتصال.
- [چه چیزی وارد می‌شود](#چه-چیزی-وارد-میشود): کدام رویدادها، و هر کدام چگونه به یک رویداد امنیتی تبدیل می‌شود.
- [نظرسنجی چگونه کار می‌کند](#نظرسنجی-چگونه-کار-میکند): پنجره‌ای که هر نظرسنجی می‌خواند، و اینکه چرا ۱۰ دقیقه هم‌پوشانی دارد.
- [عیب‌یابی](#عیبیابی): معنای هر خطا، و آنچه باید تغییر دهید.
:::

## چگونه کار می‌کند

```mermaid title="از درخواستی که Cloudflare بر آن اقدام کرد تا یک رویداد امنیتی"
flowchart TB
    edge["فایروال Cloudflare<br/>روی یک درخواست<br/>اقدام می‌کند"] --> poll["OneUptime در بازهٔ<br/>اتصال نظرسنجی<br/>می‌کند"]
    poll --> zones["رویدادهای فایروال<br/>هر ناحیه از دفعهٔ<br/>پیش را می‌خواند"]
    zones --> event["هر کدام به‌صورت<br/>رویداد HTTP Activity<br/>ذخیره می‌شود"]
```

OneUptime هر دقیقه از هر اتصال فعالی که بازهٔ نظرسنجی‌اش گذشته نظرسنجی می‌کند. یک نظرسنجی ناحیه‌های حساب را فهرست می‌کند، از گرهٔ settings در GraphQL Analytics API می‌خواند که پلن هر ناحیه چه چیزی را مجاز می‌داند، و رویدادهای فایروال هر ناحیه را از نظرسنجی پیش تا کنون از مجموعه‌دادهٔ `firewallEventsAdaptive` ([Security Events](https://developers.cloudflare.com/waf/analytics/security-events/)) می‌خواند، قدیمی‌ترین‌ها نخست. هر رویداد به‌صورت یک رویداد HTTP Activity در [OCSF](https://schema.ocsf.io/) ذخیره می‌شود.

## پیش از شروع

- در OneUptime، نقش مالک پروژه، مدیر پروژه یا مدیر امنیت. عضو امنیت و بیننده امنیت می‌توانند اتصال‌ها و تاریخچهٔ اجرایشان را ببینند، اما نمی‌توانند آن‌ها را تغییر دهند.
- یک کاربر Cloudflare که بتواند برای ناحیه‌های حساب توکن API بسازد.
- ناحیه‌هایی که ترافیکشان از Cloudflare می‌گذرد: رکوردهای DNS آن‌ها پراکسی‌شده‌اند.
- HTTPS خروجی از برنامه و کارگرهای OneUptime به `api.cloudflare.com`.

## راه‌اندازی اتصال

اتصال با یک [توکن API](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/) می‌خواند، هرگز با Global API Key: توکن به حساب و ناحیه‌های آن محدود است، و می‌توانید آن را جداگانه باطل کنید. به دو [مجوز](https://developers.cloudflare.com/fundamentals/api/reference/permissions/) نیاز دارد، هر دو فقط خواندنی:

| مجوز | آنچه OneUptime با آن می‌خواند |
| --- | --- |
| `Zone > Zone > Read` | ناحیه‌ها، با حساب‌ها و پلن‌هایشان. |
| `Zone > Analytics > Read` | رویدادهای فایروال هر ناحیه، از طریق GraphQL Analytics API. |

:::steps
### ساختن یک توکن API

1. در داشبورد Cloudflare، **My Profile → API Tokens** را باز کنید، **Create Token** را برگزینید، و **Create Custom Token** را انتخاب کنید.
2. نامش را `oneuptime-security-events` بگذارید. زیر **Permissions**، `Zone > Zone > Read` و `Zone > Analytics > Read` را اضافه کنید.
3. زیر **Zone Resources**، همهٔ ناحیه‌های حساب، یا ناحیه‌هایی را که باید وارد شوند، بگنجانید.
4. **Continue to summary** و سپس **Create Token** را برگزینید، و توکن را کپی کنید. Cloudflare آن را فقط یک بار نشان می‌دهد.

### افزودن اتصال در OneUptime

**محصولات** > **رویدادهای امنیتی** > **اتصال‌ها** (`/dashboard/{projectId}/security-events/connections`) را باز کنید، روی **افزودن اتصال** کلیک کنید، زیر **امنیت ابری**، **Cloudflare** را برگزینید، و روی **بعدی** کلیک کنید. توکن را در **توکن API** بچسبانید. سپس OneUptime حساب‌ها و ناحیه‌هایی را که توکن می‌تواند بخواند فهرست می‌کند: **حساب** را برگزینید، و در **ناحیه‌ها** گزینهٔ **همه ناحیه‌ها** را نگه دارید، یا ناحیه‌هایی را که باید وارد شوند برگزینید.

### آزمایش پیش از ذخیره

روی **آزمودن این تنظیمات** زیر **آزمایش پیش از ذخیره** کلیک کنید. آزمایش هر مجوز را با مقدارهای فرم بررسی می‌کند، هر کدام را که نیست نام می‌برد، و چیزی ذخیره نمی‌کند. سپس روی **بعدی** کلیک کنید، به اتصال یک **نام** بدهید، و آن را بسازید.
:::

| تنظیم | چه چیزی وارد کنید |
| --- | --- |
| **حساب** | حساب Cloudflare برای خواندن، که از میان حساب‌هایی که توکن API شما می‌خواند برگزیده می‌شود. توکنی که فقط یک حساب را می‌خواند، آن را برایتان برمی‌گزیند. |
| **ناحیه‌ها** | اختیاری. خالی بودنش یعنی هر ناحیهٔ فعال حساب خوانده می‌شود، از جمله ناحیه‌هایی که بعدها اضافه می‌شوند. یک اتصال حداکثر ۵۰ ناحیه را می‌خواند. |
| **توکن API** | فقط خود توکن، بدون `Bearer`. رمزگذاری می‌شود، API هرگز آن را برنمی‌گرداند و دیگر هرگز نشان داده نمی‌شود. آن را با **به‌روزرسانی اطلاعات ورود** روی اتصال جایگزین کنید. |

گام **فراخوانی دوره‌ای** همچنین یک **توضیحات** اختیاری دارد، **فاصله فراخوانی (دقیقه)**، یک عدد صحیح از `1` تا `1440` که با `5` شروع می‌شود، و **فعال**، که از آغاز روشن است. رویدادهای Cloudflare درخواست‌اند، نه هشدار، پس فرم **بازکردن پرونده از** را نمی‌پرسد: پرونده‌ها از قاعده‌های تشخیصی می‌آیند که آن‌ها را می‌خوانند.

### دسترسی نوشتن انتخابی جداگانه است

این اتصال هرگز چیزی را در Cloudflare تغییر نمی‌دهد. مسدود کردن نشانی‌ها در آنجا یک موافقت جداگانه است که به مجوزهای نوشتن نیاز دارد: `Account > Account Filter Lists > Edit` برای فهرست‌ها، `Zone > Zone WAF > Edit` روی هر ناحیه‌ای که باید در آن مسدود کرد، و `Account > Account Firewall Access Rules > Edit` روی پلن‌هایی که فهرست کافی ندارند. آن‌ها را فقط وقتی مسدودسازی را روشن می‌کنید به توکن اضافه کنید.

## چه چیزی وارد می‌شود

هر رویداد فروشندهٔ `Cloudflare` و محصول `Cloudflare WAF` دارد، و یک رویداد HTTP Activity (`4002`) است.

| فیلد Cloudflare | در رویداد امنیتی |
| --- | --- |
| `clientIP` | IP اصلی، و `client.address` |
| `clientRequestHTTPHost`, `clientRequestPath`, `clientRequestQuery` | میزبان هدف، منبع هدف (مسیر و پرس‌وجو)، و `url.original` |
| `clientRequestHTTPMethodName`, `userAgent` | فعالیت، `http.request.method` و `user_agent.original` |
| `action` | وضعیت، و `oneuptime.edge.action` |
| `source`, `ruleId`, `description` | شناسهٔ قاعده، نام قاعده، و `cloudflare.source` |
| `rayName`, `clientCountryName`, `clientAsn` | `cloudflare.ray_id`، `cloudflare.client.country` و `cloudflare.client.asn` |
| `sampleInterval` | `oneuptime.edge.sample_interval` |

| آنچه Cloudflare کرد | وضعیت | `oneuptime.edge.action` | نتیجهٔ درخواست | شدت |
| --- | --- | --- | --- | --- |
| مسدود کرد، اتصال را بست، یا یک چالش شکست خورد | Blocked، یا Dropped برای اتصال بسته‌شده | `blocked` | Rejected | Low |
| با یک چالش مدیریت‌شده، JS یا تعاملی پاسخ داد | Challenge | `challenged` | Rejected | Low |
| چالشی پذیرفته شد، یا بازدیدکننده‌ای که پیش‌تر یکی را گذرانده بود | Allowed | `passed-challenge` | هیچ | Informational |
| آن را ثبت کرد و گذاشت رد شود | Logged | `logged` | کد وضعیت سرور مبدأ | Medium؛ High وقتی سرور مبدأ شکست خورد؛ Low وقتی درخواست را رد کرد |
| آن را با یکی از قاعده‌های skip یا allow شما گذاشت رد شود | Allowed | `let-through` | کد وضعیت سرور مبدأ | مانند یک درخواست ثبت‌شده |

درخواستی که یکی از قاعده‌های skip یا allow خود شما گذاشت رد شود، فقط وقتی وارد می‌شود که حمله‌ای در خود داشته باشد (تزریق SQL، پیمایش مسیر یا یک جستجوی Log4Shell)، یا WAF attack score در Cloudflare آن را حمله بداند. بقیه ترافیکی است که عمداً اجازه داده‌اید، مانند مانیتورهایتان: هر اجرا آن را می‌شمارد و کنار می‌گذارد.

Cloudflare از رویدادهای یک ناحیهٔ پرترافیک نمونه برمی‌دارد. هر رویداد بازهٔ نمونه‌برداری‌اش را نگه می‌دارد، یعنی تعداد درخواست‌های مشابهی که نمایندهٔ آن‌هاست، و هر شمارشی که OneUptime از آن‌ها می‌سازد *حدود* می‌گوید.

رویدادها در رویدادها، در کارزارها (درخواست‌های حمله بر اساس نشانی)، در ریسک موجودیت و در قاعده‌های تشخیص دیده می‌شوند. پرونده‌ای دربارهٔ یک نشانی، زیر **در لبه** در تأثیرش نشان می‌دهد Cloudflare با درخواست‌های آن نشانی چه کرد، کنار آنچه به برنامهٔ شما رسید. قاعده‌های Cloudflare در کتابخانهٔ قاعده‌ها آن‌ها را همان‌طور که اینجا وارد می‌شوند می‌خوانند: برخوردهای فراوان با قاعده‌های مدیریت‌شده از یک نشانی، نشانی‌ای که چالشی را گذراند و سپس حمله فرستاد، و حمله‌ای که Cloudflare گذاشت رد شود و به برنامهٔ شما رسید.

## نظرسنجی چگونه کار می‌کند

- **رویدادها بر اساس زمان رخ دادنشان در لبه خوانده می‌شوند.** داده‌های تحلیلی Cloudflare یک یا دو دقیقه پس از درخواست قابل پرس‌وجو هستند.
- **نخستین نظرسنجی ۲۴ ساعت به عقب نگاه می‌کند**، پس یک اتصال تازه بی‌درنگ رویدادهای اخیرش را نشان می‌دهد.
- **هر نظرسنجی بعدی ۱۰ دقیقه پیش از نشانگر ذخیره‌شده شروع می‌شود**، پس رویدادی که Cloudflare دیر خواندنی می‌کند در نظرسنجی بعدی خوانده می‌شود، و رویدادهای تکراری با Ray ID هر رویداد در پروژه کنار گذاشته می‌شوند.
- **یک نظرسنجی حداکثر ۲۴ ساعت پس از نشانگر را می‌خواند.** اتصالی که نشانگرش عقب افتاده، در رشته‌ای از پنجره‌های ۲۴ ساعته جبران می‌کند.
- **ناحیه‌ها به نوبت خوانده می‌شوند**، هر کدام یک صفحه تا ۲٬۰۰۰ رویداد، پس یک ناحیهٔ پرترافیک نمی‌تواند پیش از خوانده شدن یک ناحیهٔ کم‌ترافیک یک نظرسنجی را تمام کند.
- **محدودیت‌های نرخ Cloudflare رعایت می‌شوند.** Cloudflare در پنج دقیقه ۱٬۲۰۰ درخواست REST و ۳۰۰ پرس‌وجوی GraphQL را مجاز می‌داند. پاسخ `429` که می‌خواهد ۳۰ ثانیه یا کمتر صبر شود، صبر می‌شود و دوباره درخواست می‌شود؛ پاسخی طولانی‌تر نظرسنجی را متوقف می‌کند، و نظرسنجی بعدی ادامه می‌دهد.
- **ناحیه‌ای که توکن نمی‌تواند بخواند چیزی را معطل نمی‌کند.** ناحیه‌های دیگر وارد می‌شوند، اجرا **جزئی** است، و هشدارش آن ناحیه را نام می‌برد. در آنجا به توکن `Zone > Analytics > Read` بدهید، سپس با **واردکردن این بازه زمانی** آن پنجره را بازیابی کنید.
- **اجرای شکست‌خورده چیزی را تغییر نمی‌دهد.** پس از یک خطای شبکه، یا یک وضعیت خطا از Cloudflare، نشانگر و طول پنجره همان‌طور که بودند می‌مانند، و نظرسنجی بعدی همان پنجره را دوباره می‌خواند. تنها استثنا درخواستی است که مهلتش تمام شد: نشانگر می‌ماند، اما پنجرهٔ بعدی نصف طول دارد، چون پنجره‌ای که سنگین‌تر از آن است که به‌موقع پاسخ داده شود، در هر تلاش از مهلت می‌گذرد.

### وقتی یک پنجره بیش از توان یک نظرسنجی دارد

یک نظرسنجی حداکثر ۱۲۰ درخواست می‌فرستد، حداکثر ۲۰٬۰۰۰ رویداد می‌خواند، و پس از ۴ دقیقه می‌ایستد. رویدادها قدیمی‌ترین‌ها نخست خوانده می‌شوند، پس وقتی یک بودجه نظرسنجی را متوقف می‌کند، اجرا **جزئی** است و نظرسنجی بعدی از قدیمی‌ترین رویدادی که ناحیه‌های ناتمام تا آن خوانده شده بودند ادامه می‌دهد. وقتی نتوان هر ناحیه را دست‌کم یک بار خواند، OneUptime در عوض پنجره را کوتاه می‌کند:

1. **باریک کردن.** نظرسنجی بعدی پنجره‌ای به نصف طول را از همان نقطهٔ شروع می‌خواند، و تا وقتی پنجره‌ای کامل خوانده شود دوباره نصف می‌کند، تا حداقل یک دقیقه. هشدار اجرا همین را می‌گوید: `This window holds more records than one poll can read; the next poll reads a {n} minute window from the same starting point.` رویدادهایی که پیش‌تر از پنجرهٔ بلندتر وارد شده‌اند به‌عنوان تکراری رد می‌شوند.
2. **دوباره بزرگ کردن.** پس از اینکه پنجره‌ای کامل خوانده شد، نشانگر به انتهای آن می‌رود، و پنجرهٔ بعدی دوباره دو برابر می‌شود، تا ۲۴ ساعت.
3. **گذشتن از یک دقیقهٔ تنها.** اگر حتی یک دقیقه بیش از آنچه یک نظرسنجی می‌تواند بخواند داشته باشد، نظرسنجی از آن می‌گذرد، تا رویدادهای تازه‌تر همچنان برسند. اجرا **جزئی** می‌ماند، و **آخرین خطا** می‌گوید `More records were created in the one minute from {cursor} to {end} than one poll can read. Polling moved past this minute so newer records keep arriving; use Import this time range in Diagnostics on this minute to recover what one run can read.` آن دقیقه را با **واردکردن این بازه زمانی** وارد کنید تا آنچه یک اجرا می‌تواند بخواند بازیابی شود.

تغییر **فاصله فراخوانی (دقیقه)** هیچ‌کدام از این‌ها را تغییر نمی‌دهد: این تنظیم تعیین می‌کند یک نظرسنجی هر چند وقت شروع شود، نه اینکه پنجره‌اش از کجا شروع شود.

### اجرا، پیش‌نمایش و وارد کردن در صورت نیاز

روی **عیب‌یابی** یک اتصال کلیک کنید تا اجراهای اخیرش را ببینید و دستی با آن کار کنید. هر کسی که بتواند اتصال را تغییر دهد می‌تواند این‌ها را شروع کند؛ هر کسی که بتواند آن را ببیند می‌تواند تاریخچه را بخواند.

- **اجرای اکنون** بی‌درنگ یک نظرسنجی با نشانگر معمول شروع می‌کند، حتی وقتی اتصال **فعال** نیست.
- **پیش‌نمایش رویدادهای فایروال** یک بازهٔ زمانی تا ۷ روز را می‌خواند و چیزی وارد نمی‌کند.
- **واردکردن این بازه زمانی** پس از تأیید شما بازه‌ای تا ۷ روز را وارد می‌کند، بی‌آنکه نشانگر را جابه‌جا کند. رویدادهایی که پیش‌تر وارد شده‌اند رد می‌شوند. Cloudflare رویدادهای فایروال را ۳۱ روز نگه می‌دارد.
- **کپی عیب‌یابی** روی یک اجرا، گزارش آن را برای پشتیبانی کپی می‌کند. هرگز اعتبارنامه‌ها را در بر ندارد.

## آزمایش اتصال

**آزمایش اتصال** در ردیف یک اتصال، و **آزمودن این تنظیمات** در فرم، در فرایند API اجرا می‌شوند، نه در یک کارگر پس‌زمینه، پس یک آزمایش حتی وقتی مشکل از کارگرهاست هم پاسخ می‌دهد. این بررسی‌ها را به ترتیب انجام می‌دهد:

| بررسی | چه چیزی را بررسی می‌کند |
| --- | --- |
| **پیکربندی** | توکن، حساب و ناحیه‌ها درست‌شکل‌اند. وقتی این شکست بخورد با هیچ جایی تماس گرفته نمی‌شود. |
| **Verify the API token** | Cloudflare توکن را می‌پذیرد، توکن یک کاربر یا توکنی که مالکش حساب است، و توکن فعال است. توکنی که ظرف ۱۴ روز منقضی می‌شود یک هشدار است. |
| **List the zones** | توکن `Zone > Zone > Read` را دارد: ناحیه‌های حساب، و هر ناحیهٔ برگزیده را فهرست می‌کند. |
| **Read firewall events** | توکن روی هر ناحیه `Zone > Analytics > Read` را دارد. شکست، ناحیه‌هایی را که این مجوز را ندارند نام می‌برد. |
| **What each zone's plan gives** | پلن هر ناحیه رویدادهای فایروال را چه مدت نگه می‌دارد، و یک پرس‌وجو چه مدت می‌تواند باشد. ناحیه‌ای که پلنش هیچ رویدادی ندارد یک هشدار است. |
| **Firewall events available to import** | ۲۴ ساعت گذشته و ۷ روز گذشته حدوداً چند رویداد دارند. هیچ، یک هشدار است. |
| **Background workers**، **Poll scheduler**، **Security event storage** | سمت خود OneUptime: فرایندی کارهای صف Worker را برمی‌دارد، کار نظرسنجی هر دقیقه اجرا می‌شود، و انبارهٔ رویدادهای امنیتی پاسخ می‌دهد. |
| **فراخوانی زمان‌بندی‌شده** | برای یک اتصال ذخیره‌شده: نظرسنجی روشن است، هیچ اجرایی در انتظار یک کارگر گیر نکرده، و نظرسنجی‌ها به‌موقع اجرا می‌شوند. |

هر درخواست در یک آزمایش مهلتی ۲۰ ثانیه‌ای دارد. یک آزمایش هرگز چیزی وارد نمی‌کند یا نشانگر را جابه‌جا نمی‌کند، و هر بررسی شکست‌خورده می‌گوید چه چیزی را تغییر دهید.

## عیب‌یابی

**آخرین خطا** اتصال پیام خطای کامل را، با اعتبارنامه‌های پوشانده‌شده، نگه می‌دارد. وقتی اتصالی خطا دارد، برای خواندنش **مشاهده خطا** را در ستون **اقدام‌ها** آن برگزینید، و برای کپی کردنش **کپی خطا** را در کادر گفتگو. هر پیام درخواستی را که شکست خورده نام می‌برد، و دلیل خود Cloudflare را نقل می‌کند.

:::details آخرین خطا می‌گوید `Invalid API Token (1000)`
Cloudflare این توکن را نمی‌شناسد: حذف شده، چرخانده شده یا هرگز کامل چسبانده نشده است. Global API Key پیش از فرستاده شدن رد می‌شود. توکنی مانند بالا بسازید، و آن را با **به‌روزرسانی اطلاعات ورود** ذخیره کنید.
:::

:::details آخرین خطا می‌گوید `Unauthorized to access requested resource (9109)`
توکن نمی‌تواند ناحیه‌ها را فهرست کند. به آن `Zone > Zone > Read` بدهید، با ناحیه‌هایی که باید وارد شوند زیر **Zone Resources**.
:::

:::details آخرین خطا می‌گوید `cannot read the analytics of`
توکن روی ناحیه‌هایی که پیام نام می‌برد `Zone > Analytics > Read` را ندارد. آن را آنجا اضافه کنید، سپس با **واردکردن این بازه زمانی** آنچه را وارد نشده بازیابی کنید.
:::

:::details آخرین خطا می‌گوید `rate limit`
چیز دیگری که از همان کاربر Cloudflare استفاده می‌کند سهمیه‌اش را تمام کرده است. نظرسنجی وقتی پنج دقیقه بگذرد خودبه‌خود ادامه می‌دهد؛ برای جدا نگه داشتن سهمیه، به OneUptime توکنی از کاربر مخصوص خودش بدهید.
:::

:::details آخرین خطا می‌گوید `did not complete`
درخواست پاسخی نگرفت: پایان مهلت، نامی که resolve نمی‌شود، یا نشانی‌ای که رد شد. بررسی کنید که برنامه و کارگرهای OneUptime، از طریق هر پراکسی‌ای که به کار می‌برید، به `api.cloudflare.com` برسند.
:::

:::details پرونده‌ای اقدام‌های Cloudflare را نشان می‌دهد، اما هیچ‌کدام از درخواست‌های آن نشانی را در برنامهٔ شما نه
پشت Cloudflare، برنامهٔ شما نشانی‌های Cloudflare را می‌بیند، مگر اینکه نشانی بازدیدکننده را از سرآیند `CF-Connecting-IP` بخواند. آن نشانی را به‌عنوان `client.address` در لاگ‌ها و ترِیس‌هایتان بنویسید، تا OneUptime بتواند درخواست‌های برنامهٔ شما را با نشانی‌ای که Cloudflare بر آن اقدام کرد تطبیق دهد.
:::

:::details آزمایش موفق است، اما Last Polled برابر Never است
کار نظرسنجی هرگز اجرا نشده است. بررسی‌های **Background workers** و **Poll scheduler** را بخوانید. در یک نصب خودمیزبان، علت معمول `DISABLE_QUEUE_WORKERS=true` روی برنامه است، بدون استقرار کارگر جداگانه‌ای که کارها را بردارد: آن را روی `false` بگذارید، یا استقرار کارگر را اجرا کنید (Helm: `worker.enabled: true`، که به‌طور پیش‌فرض `false` است).
:::
