# راهنمای خودمیزبانی

این صفحه را از بالا تا پایین دنبال کنید تا از یک سرور خالی به OneUptime خودتان برسید که روی HTTPS اجرا می‌شود، یک ایمیل آزمایشی برایتان فرستاده و می‌تواند به شما هشدار بدهد. هر گام با این تمام می‌شود که از کجا بفهمید درست کار کرده، و برای جزئیات به صفحه‌های بلندتر پیوند می‌دهد.

:::cards
- [نصب OneUptime](#نصب-oneuptime): Docker Compose روی یک سرور، یا چارت Helm روی Kubernetes.
- [راه‌اندازی سرور را تمام کنید](#راهاندازی-سرور-را-تمام-کنید): ایمیل، سپس پیامک و تماس، هر کدام با یک آزمایش.
- [نصب خود را بررسی کنید](#نصب-خود-را-بررسی-کنید): یک فرمان که می‌گوید چه چیزی درست نیست.
- [شروع سریع](/docs/introduction/quickstart): نخستین مانیتور، نخستین سیاست آماده‌به‌کار و نخستین صفحهٔ وضعیت شما.
:::

## آنچه نیاز دارید

- **یک سرور.** برای Docker Compose، یک سرور Linux با ۸ GB حافظه، ۴ هسته و ۲۰ GB دیسک برای امتحان OneUptime، یا ۱۶ GB، ۸ هسته و ۴۰۰ GB برای یک تیم: [تعیین اندازه و برنامه‌ریزی ظرفیت](/docs/installation/sizing) را ببینید. برای چارت Helm، یک خوشهٔ Kubernetes.
- **یک نام دامنه** که دیگران با آن OneUptime را باز می‌کنند، مانند `oneuptime.example.com`، با یک رکورد DNS از نوع `A` که به سرور اشاره کند. می‌توانید با نشانی IP سرور شروع کنید، اما گواهی Let's Encrypt به نام دامنه نیاز دارد.
- **درگاه‌های ۸۰ و ۴۴۳**، در دسترس از اینترنت، برای HTTPS.
- **راهی برای فرستادن ایمیل**: یک سرور ایمیل، مانند سرور شرکتتان، Microsoft 365 یا Google Workspace، یا یک حساب در Amazon SES، SendGrid، Mailgun، Postmark یا Resend.
- **یک حساب Twilio**، برای دریافت هشدار با پیامک و تماس تلفنی. ایمیل و اعلان‌های فوری به آن نیازی ندارند.

**درست کار کرده وقتی** `dig +short oneuptime.example.com` نشانی IP سرور را چاپ کند.

## نصب OneUptime

:::tabs
@tab Docker Compose
روی یک سرور تازهٔ Ubuntu، Debian یا مبتنی بر RHEL، یک فرمان Docker، Git و Node.js را هر جا نباشند نصب می‌کند، OneUptime را در پوشهٔ `oneuptime` کلون می‌کند، نشانی‌ای را که دیگران به کار می‌برند می‌پرسد و آن را راه‌اندازی می‌کند:

```bash
curl -fsSL https://oneuptime.com/install.sh | bash
```

برای انجام همین کار با دست، با Docker، Git و Node.js نصب‌شده:

```bash
git clone --depth 1 --single-branch --branch release https://github.com/OneUptime/oneuptime.git
cd oneuptime
cp config.example.env config.env
```

فایل `config.env` را باز کنید و `HOST`، نخستین تنظیم آن، را روی نام دامنه یا نشانی IP خود بگذارید، بدون `http://`. این تنها تنظیمی است که باید تغییر دهید: ایمیل، پیامک و تماس در Admin Dashboard راه‌اندازی می‌شوند، و هر چه زیر `ADVANCED` است همان‌طور که هست کار می‌کند. سپس OneUptime را راه‌اندازی کنید:

```bash
npm start
```

**درست کار کرده وقتی** `npm start` با **OneUptime is up!** و نشانی‌ای که باید باز شود تمام شود. نخستین راه‌اندازی چند دقیقه طول می‌کشد، تا Docker ایمیج‌ها را دانلود کند. اگر `npm start` پیش از آن بایستد، می‌گوید چه چیزی را تغییر دهید. [Docker Compose](/docs/installation/docker-compose) همهٔ جزئیات را دارد.
@tab Kubernetes
یک `values.yaml` با نام دامنه یا نشانی IP خود بسازید، بدون `http://`:

```yaml title="values.yaml"
host: oneuptime.example.com
```

چارت داده‌هایش را روی کلاس ذخیره‌سازی پیش‌فرض خوشه نگه می‌دارد. اگر `kubectl get storageclass` هیچ کدام را `(default)` نشان نمی‌دهد، `global.storageClass` را با نام یکی از آن‌ها اضافه کنید. سپس چارت را نصب کنید:

```bash
helm repo add oneuptime https://helm-chart.oneuptime.com/
helm install my-oneuptime oneuptime/oneuptime -f values.yaml
```

**درست کار کرده وقتی** `kubectl get pods` هر پاد را `Running` نشان دهد و نشانی‌ای که `helm install` چاپ کرد OneUptime را باز کند. [راهنمای نصب چارت](https://github.com/OneUptime/oneuptime/blob/main/HelmChart/Public/oneuptime/docs/installation.md) همهٔ جزئیات را دارد.
:::

## HTTPS را روشن کنید

وقتی نام دامنه‌تان به سرور اشاره کرد، بگذارید OneUptime یک گواهی رایگان از Let's Encrypt بگیرد. گواهی را خودش تمدید می‌کند.

:::tabs
@tab Docker Compose
این مقدارها را در `config.env` بگذارید، سپس دوباره `npm start` را اجرا کنید:

```ini title="config.env"
HOST=oneuptime.example.com
PROVISION_SSL=true
HTTP_PROTOCOL=https
```

از پیش یک پراکسی معکوس دارید، مانند Caddy، Nginx یا یک توزیع‌کنندهٔ بار؟ `PROVISION_SSL=false` را نگه دارید، `HTTP_PROTOCOL=https` و `TRUSTED_PROXY_HOPS=2` را بگذارید، و [استفاده از پراکسی معکوس خودتان](/docs/installation/docker-compose#استفاده-از-پراکسی-معکوس-خودتان) را ببینید.
@tab Kubernetes
این مقدارها را در `values.yaml` بگذارید، سپس آن‌ها را اعمال کنید:

```yaml title="values.yaml"
host: oneuptime.example.com
httpProtocol: https
ssl:
  provision: true
```

```bash
helm upgrade my-oneuptime oneuptime/oneuptime -f values.yaml
```

برای این‌که TLS را به جای آن روی کنترل‌گر ingress خودتان پایان دهید، `ssl.provision` را خاموش بگذارید و فقط `httpProtocol: https` را تنظیم کنید.
:::

**درست کار کرده وقتی** `https://oneuptime.example.com` بدون هشدار گواهی باز شود. نخستین گواهی معمولاً در چند دقیقه می‌رسد. OneUptime را روی `localhost` امتحان می‌کنید؟ از این گام بگذرید: گواهی به نام دامنه نیاز دارد.

## حساب مدیر را بسازید

نشانی خود را باز کنید، مانند `https://oneuptime.example.com`، و ثبت‌نام کنید. نخستین حساب روی یک سرور تازه مدیر اصلی آن می‌شود و می‌تواند Admin Dashboard را در `/admin` باز کند.

**درست کار کرده وقتی** `/admin` صفحهٔ Admin Dashboard را باز کند. تا وقتی ایمیل، HTTPS یا تصمیم دربارهٔ ثبت‌نام باز مانده است، روی **راه‌اندازی این سرور را تمام کنید** باز می‌شود.

## راه‌اندازی سرور را تمام کنید

صفحهٔ **راه‌اندازی سرور** در Admin Dashboard، در `/admin/setup`، آنچه یک سرور تازه نیاز دارد را فهرست می‌کند، مهم‌ترین اول. ایمیل، HTTPS و این‌که چه کسی بتواند ثبت‌نام کند الزامی‌اند. پیامک و تماس، یک پروب سراسری، پشتیبان‌گیری و بررسی به‌روزرسانی پیشنهاد می‌شوند. هر مورد دکمه‌ای دارد که جایی را که در آن تنظیم می‌شود باز می‌کند، و `npm start` در پایان نشانی این صفحه را چاپ می‌کند.

:::steps
### ایمیل را راه‌اندازی کنید

روی **راه‌اندازی ایمیل** کلیک کنید. صفحهٔ **تنظیمات > اعلان‌ها > ایمیل‌ها** باز می‌شود، جایی که سرور ایمیل خود (بیشترشان از درگاه `587` استفاده می‌کنند) یا ارائه‌دهندهٔ ایمیل، و نشانی‌ای را که ایمیل‌ها از آن فرستاده می‌شوند وارد می‌کنید. ذخیره کنید، سپس روی **فرستادن ایمیل آزمایشی** کلیک کنید و یکی برای خودتان بفرستید.

**درست کار کرده وقتی** ایمیل برسد و فهرست بررسی، ایمیل را انجام‌شده نشان دهد. اگر آزمایش شکست بخورد، پاسخ سرور ایمیل را نشان می‌دهد: [SMTP](/docs/emails/smtp#عیبیابی) را ببینید.

### انتخاب کنید چه کسی بتواند ثبت‌نام کند

هر کسی که بتواند نشانی شما را باز کند، می‌تواند ثبت‌نام کند. وقتی حساب‌های تیمتان ساخته شد، **اجازه ثبت‌نام** را در **تنظیمات > احراز هویت** خاموش کنید: کسانی که به یک پروژه دعوت می‌کنید همچنان می‌توانند بپیوندند. برای باز گذاشتن ثبت‌نام، روی **ثبت‌نام باز بماند** کلیک کنید.

**درست کار کرده وقتی** فهرست بررسی، ثبت‌نام را انجام‌شده نشان دهد.

### پیامک و تماس را راه‌اندازی کنید، یا فقط از ایمیل و اعلان فوری استفاده کنید

برای دریافت هشدار با پیامک و تماس تلفنی، روی **راه‌اندازی پیامک و تماس** کلیک کنید و حساب Twilio خود را در **تنظیمات > اعلان‌ها > تماس و پیامک** اضافه کنید: [یکپارچه‌سازی Twilio](/docs/self-hosted/twilio-integration) نشان می‌دهد هر مقدار را کجا پیدا کنید. سپس روی **فرستادن پیامک آزمایشی** و **گرفتن تماس آزمایشی** کلیک کنید. برای فرستادن آن‌ها از درگاه خودتان، [درگاه پیامک و تماس](/docs/self-hosted/sms-and-call-gateway) را ببینید. اگر ایمیل و اعلان‌های فوری کافی است، روی **فقط ایمیل و اعلان فوری** کلیک کنید.

**درست کار کرده وقتی** پیامک برسد و تلفنتان زنگ بخورد، یا فهرست بررسی انتخاب شما را نشان دهد.
:::

مورد HTTPS همین که [HTTPS را روشن کنید](#https-را-روشن-کنید) کار کند انجام می‌شود، و هر مورد پیشنهادی می‌گوید چه باید کرد.

## نصب خود را بررسی کنید

:::tabs
@tab Docker Compose
در پوشهٔ `oneuptime`، doctor را اجرا کنید:

```bash
npm run doctor
```

هر کانتینر، `config.env`، رسیدن `HOST` به این سرور، گواهی و فضای خالی دیسک را بررسی می‌کند، و از OneUptime می‌پرسد از خودش چه می‌بیند، مانند ایمیل و پروب‌ها. هر مشکل با راه‌حلش می‌آید: [نصب خود را بررسی کنید](/docs/installation/docker-compose#نصب-خود-را-بررسی-کنید) را ببینید.
@tab Kubernetes
اسکریپت عیب‌یابی چارت را، همان‌طور که [راهنمای عیب‌یابی چارت](https://github.com/OneUptime/oneuptime/blob/main/HelmChart/Public/oneuptime/docs/troubleshooting.md#run-it) نشان می‌دهد، روی خوشهٔ خود اجرا کنید. فقط می‌خواند، و با خلاصه‌ای از آنچه پیدا کرد تمام می‌شود، بدترین اول.
:::

**درست کار کرده وقتی** doctor با **Everything looks right.** تمام شود و با `0` خارج شود. وقتی چیزی باید درست شود با `1`، و وقتی نتواند بررسی‌هایش را اجرا کند با `2` خارج می‌شود. روی Kubernetes، خلاصه هیچ یافتهٔ `CRITICAL` ندارد.

## چیزی را پایش کنید و هشدار بگیرید

سرور شما اکنون می‌تواند ایمیل بفرستد و به افراد هشدار بدهد. [شروع سریع](/docs/introduction/quickstart) در خود محصول ادامه می‌یابد: یک مانیتور برای وب‌سایتتان، یک سیاست آماده‌به‌کار که وقتی سایت از کار افتاد به شما هشدار می‌دهد، و یک صفحهٔ وضعیت، در حدود پانزده دقیقه. بخش آخر آن یک رخداد آزمایشی اعلام می‌کند تا رسیدن هشدار را ببینید.

## عیب‌یابی

:::details فرمان npm start می‌ایستد و می‌گوید HOST هنوز نشانی نیست
`HOST` در `config.env` هنوز یک جای‌نگهدار دارد، مانند `<your-address>`. آن را روی نام دامنه یا نشانی IP خود بگذارید، بدون `http://`، و دوباره `npm start` را اجرا کنید.
:::

:::details ایمیل آزمایشی شکست می‌خورد
پیام زیر دکمه همان پاسخ سرور ایمیل است. نام میزبان، درگاه، نام کاربری و گذرواژه را بررسی کنید، و این‌که سرور ایمیل اجازه دهد از نشانی‌ای که ایمیل‌ها از آن فرستاده می‌شوند بفرستید. [SMTP](/docs/emails/smtp#عیبیابی) را ببینید.
:::

:::details مرورگر دربارهٔ گواهی هشدار می‌دهد
Let's Encrypt به درگاه‌های ۸۰ و ۴۴۳ در دسترس از اینترنت، و نام دامنه‌ای که به این سرور اشاره کند نیاز دارد. چند دقیقه صبر کنید، سپس `npm run doctor` را اجرا کنید: گواهی را بررسی می‌کند و می‌گوید چه چیزی درست نیست.
:::
