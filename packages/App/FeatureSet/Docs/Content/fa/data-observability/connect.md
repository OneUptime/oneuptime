# اتصال یک پایگاه داده

مشاهده‌پذیری داده هر پایگاه داده را با حساب کاربری‌ای می‌خواند که فقط کاتالوگ آن را می‌خواند: چه جدول‌ها و نماهایی در آن هست، ستون‌ها، سطرها و اندازهٔ آن‌ها، و زمان تغییرشان. این صفحه کمترین چیزی را که هر موتور پایگاه داده نیاز دارد می‌گوید، اینکه چگونه با یک پراب یا با Database Agent که از قبل اجرا می‌کنید، رشته اتصال را درون شبکهٔ خودتان نگه دارید، و اینکه بعداً چگونه یک پایگاه داده را تغییر دهید، از مشاهده‌پذیری داده بردارید یا حذف کنید.

## پیش از شروع

- **نقشی که بتواند پایگاه داده متصل کند**: مالک پروژه، مدیر پروژه یا مدیر تله‌متری.
- **یک حساب کاربری فقط‌خواندنی**، که با دستورهای زیر ساخته می‌شود. بررسی‌هایی که بعداً اضافه می‌کنید سطرهای جدول‌هایی را که بررسی می‌کنند می‌خوانند، پس دسترسی `SELECT` روی آن جدول‌ها را فقط وقتی به حساب کاربری بدهید که بررسی‌ای اضافه می‌کنید.

## انتخاب کنید چه کسی متصل شود

در **مشاهده‌پذیری داده** > **پایگاه‌های داده**، **اتصال یک پایگاه داده** را انتخاب کنید، سپس:

- **OneUptime متصل می‌شود**: یک رشته اتصال جای‌گذاری کنید. به‌صورت رمزگذاری‌شده ذخیره می‌شود، فقط کارگرهای OneUptime از آن استفاده می‌کنند، و دیگر هرگز نمایش داده نمی‌شود.
- **یک پراب در شبکه من متصل می‌شود**: یکی از پراب‌های خود را انتخاب کنید و نام متغیر محیطی‌ای را روی پراب بنویسید که رشته اتصال را در خود دارد، مانند `ORDERS_DB_URL`. رشته اتصال هرگز از شبکهٔ شما بیرون نمی‌رود. [پراب‌های سفارشی](/docs/probe/custom-probe) را ببینید.
- **Database Agent من متصل می‌شود**: سرور پایگاه داده‌ای را انتخاب کنید که [Database Agent](/docs/telemetry/databases) آن از قبل کنارش اجرا می‌شود، و نام پایگاه داده‌ای را روی آن بنویسید که باید خوانده شود. عامل آن را با حساب‌های کاربری محیط خودش می‌خواند، پس هیچ حساب کاربری‌ای در OneUptime ذخیره نمی‌شود. [از راه Database Agent](#از-راه-database-agent) را ببینید.

پایگاه داده‌ای که از قبل برای امنیت داده متصل شده است هم بدون نیاز به اتصال تازه زیر نظر گرفته می‌شود، و همین‌طور هر مجموعه‌داده BigQuery که [اتصال ابری](/docs/telemetry/cloud-accounts) شما پیدا کرده است.

## پایگاه‌های داده‌ای که می‌توانید وصل کنید

**پایگاه‌های داده‌ای که می‌توانید وصل کنید**، زیر **پایگاه‌های داده**، آنچه را پروژه شما از پیش می‌شناسد و هنوز کسی وصل نکرده فهرست می‌کند: پایگاه‌های داده‌ای که ترِیس‌های شما با آن‌ها حرف می‌زنند، آن‌هایی که در حساب‌های ابری شما هستند، و آن‌هایی که Database Monitoring زیر نظر دارد. **اتصال** فرم را از روی آنچه از هر کدام معلوم است شروع می‌کند، با یک رشته اتصال که باید پر کنید. **پنهان کردن** یکی را از بازگشت نگه می‌دارد. تا وقتی وصل نکنید چیزی خوانده نمی‌شود.

## از راه Database Agent

Database Agent از قبل به سرور پایگاه داده‌اش دسترسی دارد و متریک‌های آن را می‌فرستد. وقتی مالکش آن را روشن کند، می‌تواند پایگاه‌های داده PostgreSQL، MySQL و MariaDB آن سرور را برای مشاهده‌پذیری داده هم بخواند: `ONEUPTIME_DATA_OBSERVABILITY=true` را به `.env` عامل اضافه کنید و `docker compose up -d` را اجرا کنید. تا آن زمان، عامل با **مشاهده‌پذیری داده خاموش** فهرست می‌شود، و پایگاه داده‌ای که از راه آن متصل شده است می‌گوید چه باید کرد.

OneUptime به عامل می‌گوید کدام پایگاه داده را بخواند و نوبت کدام بررسی‌ها رسیده است، هر کدام با نوعش و جدول و ستون‌هایی که می‌خواند. هرگز دستور یا حساب کاربری‌ای نمی‌فرستد. عامل هر دستور را خودش می‌سازد، از همان قالب‌های ثابتی که کالکتورهای خود OneUptime به کار می‌برند، و هر کدام را در یک تراکنش فقط‌خواندنی با سقف 30 ثانیه اجرا می‌کند. یک بررسی را فقط وقتی اجرا می‌کند که هر جدول و ستونی که نام می‌برد در کاتالوگی باشد که همین حالا خوانده است، هر مقداری را که بررسی با آن مقایسه می‌کند به‌صورت پارامتر به دستور می‌دهد، و برای هر بررسی یک عدد برمی‌گرداند، هرگز یک سطر. بررسی‌های **SQL سفارشی** و **ردیف‌های ناموفق** فقط جایی اجرا می‌شوند که مالک عامل `ONEUPTIME_DATA_OBSERVABILITY_ALLOW_CUSTOM_SQL=true` را تنظیم کرده باشد؛ جاهای دیگر این را می‌گویند، و همهٔ بررسی‌های دیگر اجرا می‌شوند.

عامل کاتالوگ را با `ONEUPTIME_DATA_OBSERVABILITY_DATABASE_USERNAME`، یا با حساب کاربری کالکتور، می‌خواند و بررسی‌ها را با `ONEUPTIME_DATA_OBSERVABILITY_CHECKS_USERNAME`، یا با حساب کاربری کاتالوگ، اجرا می‌کند: به هر کدام فقط آنچه را بدهید که زبانه‌های زیر برایش فهرست کرده‌اند. README عامل همهٔ متغیرها را فهرست می‌کند.

## یک حساب کاربری فقط‌خواندنی برای هر موتور

:::tabs
@tab PostgreSQL
```sql
CREATE ROLE oneuptime_reader LOGIN PASSWORD '...';
GRANT CONNECT ON DATABASE orders TO oneuptime_reader;
GRANT USAGE ON SCHEMA public TO oneuptime_reader;
```

رشته اتصال: `postgres://oneuptime_reader:...@orders-db.internal:5432/orders?sslmode=require`. OneUptime جدول‌های `pg_class`، `pg_stat_user_tables` و `pg_attribute` را می‌خواند: یک جدول وقتی تغییر کرده است که شمارنده‌های درج، به‌روزرسانی یا حذف آن جابه‌جا شده باشند، و وقتی خوانده شده است که شمارنده‌های اسکن آن جابه‌جا شده باشند.
@tab MySQL and MariaDB
```sql
CREATE USER 'oneuptime_reader'@'%' IDENTIFIED BY '...';
GRANT SHOW VIEW, REFERENCES ON orders.* TO 'oneuptime_reader'@'%';
GRANT SELECT ON performance_schema.table_io_waits_summary_by_table TO 'oneuptime_reader'@'%';
```

`performance_schema` به OneUptime اجازه می‌دهد نوشتن‌ها و خواندن‌های میان دو جمع‌آوری را ببیند؛ بدون آن هم `information_schema.TABLES` همچنان می‌گوید هر جدول آخرین بار کی تغییر کرده است.
@tab SQL Server
```sql
CREATE LOGIN oneuptime_reader WITH PASSWORD = '...';
CREATE USER oneuptime_reader FOR LOGIN oneuptime_reader;
GRANT VIEW DEFINITION TO oneuptime_reader;
GRANT VIEW DATABASE STATE TO oneuptime_reader;
```

`VIEW DATABASE STATE` به OneUptime اجازه می‌دهد اندازه‌ها، آخرین به‌روزرسانی‌ها و آخرین خواندن‌ها را بخواند.
@tab Amazon Redshift
```sql
CREATE USER oneuptime_reader PASSWORD '...';
GRANT USAGE ON SCHEMA public TO oneuptime_reader;
ALTER USER oneuptime_reader SYSLOG ACCESS UNRESTRICTED;
```

با یک رشته اتصال PostgreSQL به نقطه پایانی کلاستر یا workgroup متصل شوید، مانند `postgres://oneuptime_reader:...@cluster.abc123.us-east-1.redshift.amazonaws.com:5439/dev?sslmode=require`. `SYSLOG ACCESS UNRESTRICTED` به OneUptime اجازه می‌دهد تعداد سطرها و اندازه‌ها، آخرین نوشتن‌ها و خواندن‌های همهٔ کاربران، و تبار داده را از لاگ کوئری بخواند. بدون آن هم تغییر تعداد سطرهای یک جدول همچنان نشان می‌دهد که جدول کی تغییر کرده است.
@tab Snowflake
```sql
CREATE ROLE ONEUPTIME_READER;
GRANT USAGE ON DATABASE ANALYTICS TO ROLE ONEUPTIME_READER;
GRANT USAGE ON ALL SCHEMAS IN DATABASE ANALYTICS TO ROLE ONEUPTIME_READER;
GRANT REFERENCES ON ALL TABLES IN DATABASE ANALYTICS TO ROLE ONEUPTIME_READER;
GRANT USAGE ON WAREHOUSE CHECKS_WH TO ROLE ONEUPTIME_READER;
GRANT IMPORTED PRIVILEGES ON DATABASE SNOWFLAKE TO ROLE ONEUPTIME_READER;
CREATE USER ONEUPTIME_READER DEFAULT_ROLE = ONEUPTIME_READER RSA_PUBLIC_KEY = 'MIIBIjANBgkqh...';
GRANT ROLE ONEUPTIME_READER TO USER ONEUPTIME_READER;
```

Snowflake از راه SQL API خود با احراز هویت جفت‌کلید خوانده می‌شود. با JSON متصل شوید:

```json
{ "account": "myorg-myaccount", "user": "ONEUPTIME_READER", "privateKey": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----", "database": "ANALYTICS", "warehouse": "CHECKS_WH", "role": "ONEUPTIME_READER" }
```

کاتالوگ با `SHOW` خوانده می‌شود که به هیچ warehouse نیازی ندارد، پس جمع‌آوری هیچ اعتباری مصرف نمی‌کند. فقط بررسی‌ها روی warehouse اجرا می‌شوند، طبق زمان‌بندی‌ای که به آن‌ها می‌دهید.
@tab Google BigQuery
هر مجموعه‌داده‌ای که اتصال ابری شما پیدا کرده است، با حساب سرویس همان اتصال زیر نظر گرفته می‌شود. نقش‌های **BigQuery Metadata Viewer** و **BigQuery Job User** را برای خواندن کاتالوگ روی پروژه، **BigQuery Data Viewer** را روی جدول‌هایی که بررسی‌هایتان می‌خوانند، و **BigQuery Resource Viewer** را برای تبار داده از jobهای آن به این حساب بدهید.

هر جمع‌آوری `__TABLES__` مجموعه‌داده (سطرها، بایت‌ها و آخرین تغییر، بدون هزینه) و `INFORMATION_SCHEMA.COLUMNS` آن (با صورت‌حساب حداقلی 10 MB در BigQuery) را می‌خواند. برای اتصال یک مجموعه‌داده بدون اتصال ابری، JSON با کلید یک حساب سرویس بدهید:

```json
{ "projectId": "my-project", "dataset": "analytics", "location": "US", "serviceAccountJson": { "type": "service_account", "...": "..." } }
```
@tab ClickHouse
```sql
CREATE USER oneuptime_reader IDENTIFIED BY '...' SETTINGS readonly = 2;
GRANT SHOW TABLES, SHOW COLUMNS ON *.* TO oneuptime_reader;
GRANT SELECT ON system.parts TO oneuptime_reader;
GRANT SELECT ON system.part_log TO oneuptime_reader;
GRANT SELECT ON system.query_log TO oneuptime_reader;
```

ClickHouse از راه رابط HTTP خود خوانده می‌شود، روی پورت ۸۴۴۳ با TLS (ClickHouse Cloud) یا ۸۱۲۳ بدون آن: `clickhouse://oneuptime_reader:...@abc123.us-east-1.aws.clickhouse.cloud:8443/analytics`. یک پایگاه داده را نام ببرید تا فقط همان زیر نظر گرفته شود، یا آن را ننویسید تا همهٔ پایگاه‌های داده به‌جز پایگاه‌های خود سرور زیر نظر گرفته شوند. `system.parts` به OneUptime اجازه می‌دهد هر درج را ببیند (ادغام به حساب نمی‌آید)، `system.part_log`، هر جا سرور آن را نگه دارد، زمان هر درج را می‌دهد، و `system.query_log` ساعتی یک بار آخرین خواندن‌ها و تبار داده را می‌دهد. هر دستور به‌صورت فقط‌خواندنی اجرا می‌شود، پس حتی حساب کاربری‌ای که اجازهٔ نوشتن دارد هم نمی‌تواند بنویسد.
@tab Databricks
```sql
GRANT USE CATALOG, BROWSE ON CATALOG main TO `oneuptime-reader`;
GRANT USE SCHEMA ON CATALOG main TO `oneuptime-reader`;
GRANT USE CATALOG ON CATALOG system TO `oneuptime-reader`;
GRANT USE SCHEMA, SELECT ON SCHEMA system.access TO `oneuptime-reader`;
```

هر catalog در Unity Catalog یک پایگاه داده است. با یک service principal متصل شوید، یا با یک توکن دسترسی شخصی به‌صورت `"token"` به‌جای `clientId` و `clientSecret`:

```json
{ "host": "adb-1234567890123456.7.azuredatabricks.net", "clientId": "...", "clientSecret": "...", "catalog": "main", "warehouseId": "abc123def456" }
```

کاتالوگ، ستون‌های آن و آخرین commit هر جدول Delta بدون هیچ SQL warehouse از REST API مربوط به Unity Catalog می‌آیند، پس جمع‌آوری هیچ هزینهٔ محاسباتی ندارد. بررسی‌ها، و تبار داده و آخرین خواندن‌ها از `system.access.table_lineage` که ساعتی یک بار خوانده می‌شوند، روی SQL warehouseای اجرا می‌شوند که نام می‌برید؛ دسترسی **Can use** روی آن را به service principal بدهید.
@tab Oracle
```sql
CREATE USER oneuptime_reader IDENTIFIED BY "...";
GRANT CREATE SESSION TO oneuptime_reader;
GRANT READ ON sales.orders TO oneuptime_reader;
GRANT SELECT_CATALOG_ROLE TO oneuptime_reader;
```

Oracle از طریق پروتکل خودش و بدون نصب کلاینت Oracle خوانده می‌شود: `oracle://oneuptime_reader:...@orders-db.internal:1521/ORCLPDB1`. این کاربر جدول‌هایی را می‌بیند که اجازهٔ خواندنشان را دارد: برای هر جدولی که باید پایش شود `READ` بدهید؛ با آن می‌تواند پرس‌وجو کند و هرگز قفل یا تغییر نمی‌دهد. `SELECT_CATALOG_ROLE` به OneUptime اجازه می‌دهد اندازهٔ هر جدول را بخواند، و `ALL_TAB_MODIFICATIONS` درج‌ها، به‌روزرسانی‌ها و حذف‌های هر جدول از آخرین آمارش و زمان آخرین تغییرش را می‌دهد.
@tab Amazon Athena
یک پایگاه دادهٔ Glue یک پایگاه داده است. جدول‌ها و نماهای آن، ستون‌ها و آمارشان، و آخرین commit هر جدول Iceberg از API ‏Glue Data Catalog می‌آید که هیچ داده‌ای نمی‌خواند و هزینه‌ای ندارد. بررسی‌ها به‌صورت پرس‌وجوهای Athena در workgroup‌ای که نام می‌برید اجرا می‌شوند. با کلیدهای یک کاربر یا نقش IAM وصل شوید که بتواند `glue:GetDatabase` و `glue:GetTables` را فراخوانی کند و برای بررسی‌ها پرس‌وجوهای Athena را در workgroup با دسترسی خواندن به دادهٔ جدول‌ها اجرا کند:

```json
{ "region": "us-east-1", "accessKeyId": "AKIA...", "secretAccessKey": "...", "database": "analytics", "workgroup": "primary", "outputLocation": "s3://acme-athena-results/oneuptime/" }
```
@tab MongoDB
```javascript
use admin
db.createUser({
  user: "oneuptime_reader",
  pwd: "...",
  roles: [{ role: "readAnyDatabase", db: "admin" }]
})
```

MongoDB با درایور خودش خوانده می‌شود: `mongodb+srv://oneuptime_reader:...@cluster0.example.mongodb.net/`، یا `mongodb://` با میزبان‌های یک replica set. پایگاه داده‌ای که در مسیر آمده تنها پایگاه دادهٔ پایش‌شده است؛ بدون آن، هر پایگاه داده‌ای که این کاربر اجازهٔ خواندنش را دارد پایش می‌شود، و `{ role: "read", db: "orders" }` به جای `readAnyDatabase` آن را به یکی محدود می‌کند. اسناد، اندازه و نوشتن‌های هر کالکشن از `$collStats` می‌آیند، و زمان دریافت آخرین سند از جدیدترین `_id` آن. فیلدهای آن از اسکیمای JSON اعتبارسنج آن می‌آیند، یا در غیر این صورت از نام‌ها و نوع‌های فیلدهای 100 سند جدیدتر آن، که در خود پایگاه داده محاسبه می‌شوند تا هیچ مقداری از آن بیرون نرود. اسناد در صورت وجود روی یک secondary خوانده می‌شوند، و بررسی سفارشی یک پایپ‌لاین تجمیع به صورت JSON است.
@tab Microsoft Dataverse
OneUptime به‌عنوان یک برنامه وارد محیط می‌شود. یک برنامه در Microsoft Entra ID ثبت کنید و به آن یک راز کلاینت بدهید. سپس آن را به‌عنوان کاربر برنامه به محیط اضافه کنید: در Power Platform admin center محیط را باز کنید و سپس **Settings** > **Users + permissions** > **Application users** > **New app user** را برگزینید. به آن یک نقش امنیتی بدهید که اجازهٔ خواندن جدول‌هایی را داشته باشد که زیر نظر دارید.

با JSON متصل شوید:

```json
{ "environmentUrl": "https://contoso.crm.dynamics.com", "tenantId": "72f988bf-86f1-41af-91ab-2d7cd011db47", "clientId": "11111111-2222-3333-4444-555555555555", "clientSecret": "..." }
```

یا با یک رشته اتصال Dataverse، به همان شکلی که SDKهای آن می‌پذیرند: `AuthType=ClientSecret;Url=https://contoso.crm.dynamics.com;ClientId=...;ClientSecret=...`. اگر مستأجر را ننویسید، محیط خودش می‌گوید در کدام مستأجر است.

یک محیط خودش صدها جدول دارد، پس فقط این‌ها زیر نظر گرفته می‌شوند: جدول‌های اصلی کسب‌وکار (`account`، `contact`، `lead`، `opportunity`، `quote`، `salesorder`، `invoice`، `product`، `incident`، `email`، `phonecall`، `appointment`، `task` و `annotation`) و جدول‌های سفارشی خودتان. جدول‌های برنامه‌های Microsoft، که نامشان با `msdyn_`، `adx_` یا یک پیشوند `ms` دیگر شروع می‌شود، کنار گذاشته می‌شوند. هر جدول دیگری را با نام منطقی‌اش نام ببرید تا آن هم زیر نظر گرفته شود: `"tables": ["msdyn_workorder", "systemuser"]`.

هر پنج دقیقه، Web API تعریف هر جدول، سطرهای آن و جدیدترین `modifiedon` آن را می‌دهد، که زمان آخرین تغییر آن است. سطرها از شمارشی می‌آیند که Dataverse روزی یک بار انجام می‌دهد، پس ممکن است تا یک روز عقب باشند. ستون‌ها ساعتی یک بار خوانده می‌شوند. هر جمع‌آوری دو درخواست می‌فرستد، و برای هر جدول زیر نظر یک درخواست دیگر، که همه در سقف 6,000 درخواست در هر پنج دقیقه برای برنامه حساب می‌شوند. درخواستی که لحظه‌ای در Dataverse ناموفق شود، یا Dataverse بخواهد چند ثانیه برایش صبر شود، دوباره فرستاده می‌شود، حداکثر دو بار؛ وقتی بخواهد بیشتر صبر شود، بقیهٔ خواندن‌ها منتظر جمع‌آوری بعدی می‌مانند. اگر Dataverse نتواند جدولی را بخواند، فقط همان جدول کنار گذاشته می‌شود، با کد و پیام خطای خود Dataverse، و تا تلاش بعدی‌اش رد می‌شود: یک ساعت بعد، سپس دو ساعت، سپس چهار ساعت، و حداکثر یک روز. صفحهٔ پایگاه داده این جدول‌ها را زیر **جدول‌های ردشده** فهرست می‌کند. **جمع‌آوری همین حالا** همه را یک‌جا دوباره درخواست می‌کند، و تغییری در جدول‌های محیط یا در برنامه‌ای که آن‌ها را می‌خواند نیز همین کار را می‌کند. یک جدول را مستثنا کنید تا دیگر خوانده نشود.

بررسی‌ها به‌صورت SQL فقط‌خواندنی روی نقطه پایانی TDS محیط، روی پورت ۱۴۳۳ یا ۵۵۵۸، و با ورود به‌عنوان همان برنامه اجرا می‌شوند. این نقطه پایانی روشن است، مگر اینکه یک مدیر آن را خاموش کرده باشد. هر جا کنترل دسترسی در سطح کاربر برای آن روشن باشد، نقش برنامه به امتیاز **Allow user to access TDS endpoint** نیاز دارد. SQL آن نه عبارت باقاعده دارد، نه `WITH` و نه نمونه، پس یک بررسی در آنجا همهٔ سطرها را می‌خواند.
:::

## چه چیزی خوانده می‌شود، و هر چند وقت یک بار

| چه چیزی | چه زمانی |
| --- | --- |
| جدول‌ها، نماها، ستون‌ها، سطرها، اندازه و آخرین تغییر | هر پنج دقیقه |
| بررسی‌ها | هر 15 دقیقه، هر ساعت، هر 6 ساعت یا هر روز، همان‌طور که هر بررسی تعیین می‌کند |
| تبار داده و آخرین خواندن‌ها از تاریخچهٔ کوئری | ساعتی یک بار، از آخرین خواندن به بعد |

هر دستور به‌صورت فقط‌خواندنی اجرا می‌شود، با مهلت زمانی دستور و قفل، هر جا موتور پایگاه داده آن‌ها را داشته باشد. اگر Snowflake، Databricks، BigQuery، Athena، ClickHouse یا Dataverse درخواستی را لحظه‌ای نپذیرد یا در پاسخ به آن ناموفق شود، با وضعیت 429 یا 503، یا با پاسخ خودش مبنی بر اینکه بیش از حد مشغول است، آن درخواست دوباره فرستاده می‌شود، حداکثر دو بار و با حداکثر یک دقیقه انتظار در هر جمع‌آوری، و هرگز به شکلی که بتواند یک دستور را دو بار اجرا کند. رشته اتصال هرگز در لاگ ثبت نمی‌شود و از هر پیام خطا حذف می‌شود. آماری که حساب کاربری اجازهٔ خواندنش را ندارد، با یک اخطار روی پایگاه داده کنار گذاشته می‌شود و هرگز باعث ناموفق شدن جمع‌آوری نمی‌شود. اتصال به نشانی‌های خصوصی در OneUptime Cloud رد می‌شود: از یک پراب استفاده کنید.

## مدیریت یک پایگاه داده

هر پایگاه داده یک صفحهٔ **تنظیمات** دارد: **تنظیمات** را روی ردیف آن زیر **پایگاه‌های داده**، یا در منوی آن، انتخاب کنید.

- **ویرایش جزئیات** نام آن را تغییر می‌دهد. امنیت داده همین نام را نشان می‌دهد.
- **تغییر اتصال** به آن یک حساب کاربری تازه، یک پراب دیگر یا یک Database Agent می‌دهد. رشته اتصال ذخیره‌شده دیگر هرگز نمایش داده نمی‌شود: برای نگه داشتنش فیلد را خالی بگذارید. انتقال یک پایگاه داده به یک Database Agent رشته اتصال ذخیره‌شدهٔ آن را حذف می‌کند، مگر اینکه امنیت داده با آن از محتوای پایگاه داده نمونه‌برداری کند.
- **توقف پایش**، در **نمای کلی** آن، خواندنش را مدتی متوقف می‌کند و جدول‌ها و تاریخچهٔ آن‌ها را نگه می‌دارد. **پایش دوباره** آن را از سر می‌گیرد.
- **برداشتن از مشاهده‌پذیری داده** خواندنش را متوقف می‌کند و جدول‌ها، بررسی‌ها و تاریخچهٔ آن‌ها را فراموش می‌کند. امنیت داده پایگاه داده، اتصال آن و یافته‌های اسکن‌هایش را نگه می‌دارد، و پایگاه داده دوباره زیر **پایگاه‌های داده‌ای که می‌توانید وصل کنید** پیشنهاد می‌شود.
- **حذف پایگاه داده** آن را همراه با آنچه مشاهده‌پذیری داده و امنیت داده از آن نگه می‌دارند از OneUptime حذف می‌کند. تأییدیه پیش از آن فهرست می‌کند چه چیزهایی حذف می‌شوند.

پایگاه داده‌ای که اینجاست، مخزن دادهٔ امنیت داده هم هست. تا وقتی امنیت داده به آن متکی است (پایگاه داده را یافته، کسی آن را آنجا افزوده، یا یافته‌ها، مسائل، اسکن‌ها، مالکان یا سابقهٔ پردازشی از آن دارد)، فقط کسی که مجاز به حذف مخازن دادهٔ امنیت داده است می‌تواند آن را حذف کند، و فقط کسی که مجاز به ویرایش آن‌هاست می‌تواند اتصالی را که امنیت داده با آن از محتوا نمونه‌برداری می‌کند تغییر دهد. صفحهٔ تنظیمات این را کنار دکمهٔ مربوط می‌گوید. مانیتورهایی که یک پایگاه داده را پایش می‌کنند با رفتن آن نگه داشته می‌شوند: آن‌ها را در **مانیتورها** حذف کنید.

## ریپلیکاهای خواندنی

ریپلیکای خواندنی PostgreSQL یا SQL Server شمارنده‌های نوشتن خود را جابه‌جا نمی‌کند، پس جدولی در آن می‌تواند بدون تغییر به نظر برسد در حالی که تغییر می‌کند. OneUptime می‌بیند که ریپلیکاست، شمارنده‌ها را کنار می‌گذارد، این را روی پایگاه داده می‌گوید، و به اندازه و سطرهای جدول برمی‌گردد. جایی که می‌توانید primary را متصل کنید، یا برای جدول‌های مهم یک [ستون تازگی](/docs/data-observability/table-health) نام ببرید.

## مسیرهای ذخیره‌سازی

هر چیزی که به آن متکی هستید در یک پایگاه داده نیست. خروجی‌ای که هر شب در یک باکت می‌نشیند مانند هر جدولی می‌تواند دیر برسد یا کوتاه باشد. زیر **مسیرهای ذخیره‌سازی**، برای باکتی که [اتصال ابری](/docs/telemetry/cloud-accounts) شما پیدا کرده، روی Amazon S3، Google Cloud Storage یا یک حساب ذخیره‌سازی Azure، **ویرایش مسیرها** را انتخاب کنید و مسیرهای مهم را نام ببرید، هر کدام در یک خط. در Azure، هر مسیر را با نام کانتینر آن شروع کنید.

هر مسیر آن‌گاه زیر **جدول‌ها** نشان داده می‌شود: تازه‌ترین شیء آن زمان آخرین تغییر آن است، شیءهای آن سطرهای آن هستند، و اندازهٔ آن‌ها اندازهٔ آن، و همان هشدارها اعمال می‌شوند. فقط نام‌ها، اندازه‌ها و زمان‌ها خوانده می‌شود، هرگز یک شیء. مسیری که بیش از 10000 شیء دارد شمار، اندازه یا تازه‌ترین شیء دقیق ندارد و این را می‌گوید: مسیر محدودتری را نام ببرید.

## عیب‌یابی

- **پایگاه داده «Database Agent آماده نیست» را نشان می‌دهد.** عامل اکنون نمی‌تواند آن را بخواند، و صفحهٔ پایگاه داده دلیلش را می‌گوید: هیچ Database Agent به سرور آن متصل نیست، یا عامل برای مشاهده‌پذیری داده خاموش است (`ONEUPTIME_DATA_OBSERVABILITY=true` آن را روشن می‌کند)، خبری از آن نرسیده است، بیش از حد قدیمی است (`install.sh` آن را دوباره اجرا کنید)، یا روی سروری است که نه PostgreSQL است و نه MySQL.
- **جمع‌آوری از پایگاه داده ناموفق است.** پیام آن دلیلش را می‌گوید: میزبانی که OneUptime نمی‌تواند به آن برسد، حساب کاربری‌ای که رد شده است، یا حالتی از TLS که سرور نمی‌پذیرد. پایگاه داده‌ای را که درون شبکهٔ شماست از راه یک پراب متصل کنید. برای Snowflake، Databricks، BigQuery، Athena، ClickHouse و Dataverse، پیام می‌گوید چه چیزی خوانده می‌شد و کد و پیام خطای خود سرویس را می‌آورد، همراه با شناسهٔ درخواست یا کوئری‌ای که پشتیبانی آن سرویس می‌تواند ردیابی کند، هر جا سرویس چنین شناسه‌ای بدهد. **جمع‌آوری همین حالا** بی‌درنگ دوباره تلاش می‌کند، و صفحه نتیجه را نشان می‌دهد.
- **جدول‌ها هیچ آخرین تغییری نشان نمی‌دهند.** حساب کاربری نمی‌تواند آمار موتور پایگاه داده را بخواند: آنچه را زبانهٔ موتور شما فهرست کرده اعطا کنید، یا صبر کنید تا تعداد سطرهای یک جدول دو بار تغییر کند.
- **یک جدول پیدا نیست.** در طرح‌واره‌ای است که حساب کاربری نمی‌تواند از آن استفاده کند، یا روی پایگاه داده مستثنا شده است. دسترسی `USAGE` روی طرح‌وارهٔ آن بدهید، یا استثنا را بردارید.
- **یک جدول MySQL ستونی ندارد.** حساب کاربری به `REFERENCES` نیاز دارد، همان‌طور که بالا آمد: ستون‌های یک جدول را نشان می‌دهد بی‌آنکه اجازهٔ خواندن سطرهای آن را بدهد.
- **یک محیط Dataverse می‌گوید برنامه را رد کرده است.** برنامه را به‌عنوان کاربر برنامه، با یک نقش امنیتی که اجازهٔ خواندن جدول‌ها را داشته باشد، به محیط اضافه کنید، همان‌طور که در زبانهٔ Microsoft Dataverse آمده است.
- **یک جدول Dataverse رد می‌شود.** Dataverse نتوانست آن را بخواند، و **جدول‌های ردشده** در صفحهٔ پایگاه داده دلیلش را به زبان خود Dataverse می‌گوید. اگر نقش امنیتی برنامه اجازهٔ خواندن جدول را ندارد، این اجازه را به آن بدهید، سپس **جمع‌آوری همین حالا** را انتخاب کنید: همهٔ جدول‌های ردشده یک‌جا دوباره درخواست می‌شوند.
- **یک جدول Dataverse پیدا نیست.** فقط جدول‌های اصلی کسب‌وکار و جدول‌های سفارشی خودتان زیر نظر گرفته می‌شوند. آن را با نام منطقی‌اش در `tables` نام ببرید.
