# درگاه پیامک و تماس

‏OneUptime می‌تواند پیامک‌ها و تماس‌هایش را به‌جای Twilio از راه درگاهی بفرستد که خودتان اداره می‌کنید. وقتی قواعد شما ایجاب می‌کند که هر پیام از ارائه‌دهندهٔ پیامک و تماس صوتی خودتان بگذرد، یا از سامانه‌ای که پیش از بیرون رفتن پیام از شبکهٔ شما آن را بررسی می‌کند، از آن استفاده کنید. ‏OneUptime هر پیامک و هر تماس را به‌صورت یک درخواست JSON امضاشده برای درگاه شما می‌فرستد، و درگاه شما آن را تحویل می‌دهد.

:::cards
- [راه‌اندازی درگاه](#راهاندازی-درگاه): یک URL، و یک رمز امضا که برایتان ساخته می‌شود.
- [آنچه درگاه شما دریافت می‌کند](#آنچه-درگاه-شما-دریافت-میکند): برای هر پیامک یا تماس، یک درخواست JSON امضاشده.
- [اقدام روی یک فراخوان](#اقدام-روی-یک-فراخوان): تأیید، تشدید یا برطرف کردن از راه یک تماس یا یک پاسخ.
- [تحویل و تلاش دوباره](#تحویل-و-تلاش-دوباره): وقتی درگاه شما از کار افتاده چه می‌شود.
:::

## چگونه کار می‌کند

```mermaid title="یک پیامک از راه درگاه خودتان"
flowchart LR
    OneUptime["OneUptime"]
    Gateway["درگاه شما"]
    Provider["ارائه‌دهندهٔ پیامک و<br/>تماس صوتی شما"]
    Phone["تلفن"]
    OneUptime -->|"درخواست JSON امضاشده"| Gateway
    Gateway --> Provider
    Provider --> Phone
```

درگاه، برای هر چیزی که از راه حساب Twilio خودِ سرور می‌رفت، جای آن حساب را می‌گیرد: فراخوان‌های آنکال، اعلان‌ها، کدهای تأیید و پیامک‌های مشترکان صفحهٔ وضعیت. پروژه‌هایی که پیکربندی Twilio خودشان را روی کارت **پیکربندی Twilio** در **تنظیمات پروژه** > **اعلان‌ها** > **تنظیمات اعلان** می‌افزایند، همچنان از راه همان پیکربندی می‌فرستند. کلیدهای پیامک و تماسِ هر پروژه، و جایی که صورت‌حساب روشن است موجودی آن، همان‌طور بررسی می‌شوند که برای Twilio.

## راه‌اندازی درگاه

:::steps
1. در Admin Dashboard به **تنظیمات** > **تماس و پیامک** بروید، و روی کارت **SMS and Call Provider** روی **Edit Provider** کلیک کنید.
2. ‏**Your own gateway** را برگزینید، و **Gateway URL** را وارد کنید. درگاه می‌تواند در شبکهٔ خصوصی شما باشد.
3. ذخیره کنید. ‏OneUptime یک رمز امضا برایتان می‌سازد. آن را از روی کارت در درگاهتان کپی کنید.
4. روی **Send Test** کلیک کنید. درگاه شما باید با یک وضعیت 2xx پاسخ دهد و چیزی نفرستد.
:::

برای جایگزین کردن رمز، **Signing Secret** را در **فیلدهای بیشتر** خالی کنید و ذخیره کنید: ‏OneUptime رمز تازه‌ای می‌سازد. برای بازگشت به Twilio، **Twilio** را برگزینید و ذخیره کنید.

## آنچه درگاه شما دریافت می‌کند

هر پیامک و هر تماس یک درخواست `POST` با بدنهٔ JSON و این سرآیندهاست:

| سرآیند | مقدار |
| --- | --- |
| `Content-Type` | `application/json` |
| `X-OneUptime-Event` | `sms`، `call` یا `test` |
| `X-OneUptime-Signature` | `sha256=` و پس از آن HMAC-SHA256 بدنه به‌صورت hex، با رمز امضا به‌عنوان کلید |
| `User-Agent` | `OneUptime-CallAndSmsGateway/1.0` |

```json title="An on-call page by SMS"
{
  "version": 1,
  "event": "sms",
  "id": "7c5b0d0e-3e5f-4d1a-9a4f-2b8e6c1d9f00",
  "sentAt": "2026-10-27T09:30:00.000Z",
  "to": "+15551234567",
  "message": "OneUptime: A new alert has been created. Alert #42: Database is down…",
  "isSensitive": false,
  "project": {
    "id": "0f6b8c3a-1d2e-4f5a-8b9c-0d1e2f3a4b5c",
    "name": "Production"
  },
  "actions": {
    "acknowledge": "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/acknowledge?token=…",
    "escalate": "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/escalate?token=…",
    "resolve": "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/resolve?token=…"
  }
}
```

| فیلد | چیست |
| --- | --- |
| `version` | برای این شکل همیشه `1`. فقط فیلدهایی به آن افزوده می‌شود. |
| `event` | `sms`، `call` یا `test`، مانند `X-OneUptime-Event`. |
| `id` | یکتا برای این پیام، و در همهٔ تلاش‌ها برای تحویل آن یکسان: با آن پیامی را که پیش‌تر فرستاده‌اید نادیده بگیرید. |
| `sentAt` | زمانی که OneUptime آن را فرستاد، در قالب ISO 8601. |
| `to` | شمارهٔ تلفن، در قالب E.164. در آزمایش `null`. |
| `message` | متن پیامک، یا آنچه تماس می‌گوید. یک پیامک حداکثر 1,600 نویسه است، و متن یک تماس حداکثر 16,384 نویسه. متن بلندتر کوتاه می‌شود و با یادداشتی پایان می‌یابد که می‌گوید بقیه‌اش در OneUptime است. |
| `isSensitive` | برای کد تأیید `true`. پیام را از لاگ‌های خودتان بیرون نگه دارید. |
| `project` | `id` و `name` پروژه، یا `null` وقتی هیچ پروژه‌ای آن را نفرستاده است. |
| `actions` | برای یک فراخوان آنکال، پیوندهایی که روی آن اقدام می‌کنند. در غیر این صورت `null`. |

تماس به‌صورت توصیف فرستاده می‌شود، نه اسکریپت: `message` همان چیزی است که تماس می‌گوید، بدون «برای تأیید 1 را فشار دهید» که Twilio می‌گوید. اقدام‌ها را به روش خودتان، مثلاً با فشردن کلیدها، ارائه دهید و پیوند متناظر را فراخوانی کنید.

### بررسی امضا

پیش از تجزیهٔ بدنهٔ خام درخواست، HMAC آن را حساب کنید و با سرآیند مقایسه کنید. این بررسی همان بررسی [کانال سفارشی](/docs/self-hosted/custom-notification-channels#بررسی-امضا) است، پس یک تأییدکننده برای هر دو کافی است:

```javascript title="Node.js"
const crypto = require("crypto");

function isFromOneUptime(rawBody, signatureHeader, secret) {
  const expected =
    "sha256=" + crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  const received = String(signatureHeader || "");

  return (
    received.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(received), Buffer.from(expected))
  );
}
```

## اقدام روی یک فراخوان

وقتی فرد در یک تماس یا با یک پاسخ واکنش نشان می‌دهد، درگاه شما یک درخواست `POST` به پیوند متناظر در `actions` می‌فرستد. پیوندها همان‌طور کار می‌کنند که پیوندهای یک کانال سفارشی: به کلید API نیازی ندارند، هر کدام توکنی فقط برای همان فراخوان دارد که 7 روز معتبر است، و اقدام به نام فردی ثبت می‌شود که فراخوانده شده بود. برای هر اقدام و پاسخ آن، [اقدام روی یک فراخوان](/docs/self-hosted/custom-notification-channels#اقدام-روی-یک-فراخوان) را ببینید.

```bash title="Acknowledge a page"
curl -X POST "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/acknowledge?token=…"
```

## تحویل و تلاش دوباره

یک درخواست وقتی تحویل‌شده به شمار می‌آید که درگاه شما ظرف 10 ثانیه با یک وضعیت 2xx پاسخ دهد. درخواستی که به آن پاسخی داده نشد، یا با 408، 429 یا یک وضعیت 5xx پاسخ گرفت، پس از 1 ثانیه و سپس پس از 4 ثانیهٔ دیگر دوباره فرستاده می‌شود: روی هم سه تلاش. با هر وضعیت 4xx دیگری، درخواست دوباره فرستاده نمی‌شود.

گزارش پیامک یا تماس، و برای یک فراخوان آنکال گزارش آنکالِ آن فرد، `Sent to the SMS and call gateway (HTTP 200).` یا دلیل تحویل نشدن را نشان می‌دهد، هرگز URL را. ‏OneUptime نمی‌فهمد که پیام به گوشی رسیده است یا نه، پس یک پیامک به محض اینکه درگاه شما آن را بپذیرد فرستاده‌شده نشان داده می‌شود، و شماره‌ای که از آن بیرون رفته خالی می‌ماند.

## درخواست‌های آزمایشی

‏**Send test** درخواستی می‌فرستد که در آن `event` برابر `test` است، و `to`، `project` و `actions` برابر `null`. با یک وضعیت 2xx به آن پاسخ دهید و چیزی نفرستید.
