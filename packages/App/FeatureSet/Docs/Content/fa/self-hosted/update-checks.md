# بررسی‌های به‌روزرسانی و امنیت

یک OneUptime خودمیزبان روزی یک بار از GitHub می‌پرسد که آیا نسخهٔ تازه‌تری منتشر شده است، و آیا اطلاعیهٔ امنیتی‌ای که OneUptime منتشر کرده بر نسخه‌ای که اجرا می‌کنید اثر می‌گذارد. اگر چنین باشد، از مدیران اصلی شما خواسته می‌شود ارتقا دهند. این صفحه می‌گوید این بررسی چه چیزی می‌فرستد، چه چیزی می‌بینید و چطور آن را خاموش کنید.

:::cards
- [این بررسی چه چیزی می‌فرستد](#این-بررسی-چه-چیزی-میفرستد): دو پرسش عمومی، و هیچ چیز دربارهٔ نصب شما.
- [آنچه می‌بینید](#آنچه-میبینید): پانویس، داشبورد مدیریت و یک ایمیل برای هر اطلاعیه.
- [بررسی را خاموش کنید](#بررسی-را-خاموش-کنید): برای شبکه‌ای بدون دسترسی به اینترنت، یا برای استفاده از یک آینه.
:::

## این بررسی چه چیزی می‌فرستد

worker دو درخواست را بدون توکن به API سرویس GitHub (`api.github.com`) می‌فرستد:

| درخواست | چه می‌پرسد |
| --- | --- |
| `GET /repos/OneUptime/oneuptime/releases/latest` | تازه‌ترین نسخهٔ OneUptime کدام است |
| `GET /repos/OneUptime/oneuptime/security-advisories?state=published` | OneUptime کدام اطلاعیه‌های امنیتی را منتشر کرده است، هر کدام بر کدام نسخه‌ها اثر می‌گذارد و کدام نسخه آن را برطرف می‌کند |

هیچ چیز دربارهٔ نصب شما در آن‌ها نیست: نه نسخه‌ای که اجرا می‌کنید، نه نشانی آن، و نه هیچ چیز دربارهٔ کاربران، پروژه‌ها یا دادهٔ پایش شما. GitHub نشانی IP عمومی سرور شما را می‌بیند، همان‌طور که در هر درخواستی می‌بیند، و یک `User-Agent` که نام OneUptime را در خود دارد. اینکه اطلاعیه‌ای بر نسخهٔ شما اثر می‌گذارد یا نه، روی سرور خودتان تعیین می‌شود، و هیچ مرورگری GitHub را فرا نمی‌خواند.

این بررسی هنگام راه‌اندازی worker اجرا می‌شود و پس از آن روزی یک بار. حداکثر هر ۱۲ ساعت یک بار دوباره از GitHub می‌پرسد، و پس از درخواستی که ناموفق بوده، حداکثر ساعتی یک بار.

## آنچه می‌بینید

فقط به مدیران اصلی خبر داده می‌شود. تنها آن‌ها می‌توانند ارتقا دهند، و گفتن به هر کس دیگری که سرور نسخه‌ای با یک مشکل امنیتی شناخته‌شده را اجرا می‌کند، یعنی نشان دادن سروری که وصله نشده است.

- وقتی نسخهٔ تازه‌تری منتشر شود، **به‌روزرسانی در دسترس است** به پانویس Dashboard و داشبورد مدیریت افزوده می‌شود. این برچسب راهنمای ارتقا را باز می‌کند.
- اگر یک اطلاعیهٔ امنیتی منتشرشده بر نسخه‌ای که اجرا می‌کنید اثر بگذارد، به‌جای آن **به‌روزرسانی امنیتی** با رنگ قرمز همان‌جا نشان داده می‌شود.
- سپس صفحهٔ نخست داشبورد مدیریت همهٔ اطلاعیه‌ها را فهرست می‌کند: شدت هر کدام، نسخه‌هایی که بر آن‌ها اثر می‌گذارد، نسخه‌ای که آن را برطرف می‌کند، و پیوندی به آن در GitHub. همچنین می‌گوید این بررسی آخرین بار کی اطلاعیه‌ها را خوانده است، و اگر آخرین بررسی ناموفق بوده، چرا.
- مدیران اصلی شما و ایمیل اعلان مدیریت (**تنظیمات** > **ایمیل‌ها** در داشبورد مدیریت) دربارهٔ هر اطلاعیه‌ای که بر نسخهٔ شما اثر می‌گذارد یک ایمیل دریافت می‌کنند، و هرگز ایمیل دومی دریافت نمی‌کنند.

به محض اینکه نسخه‌ای را اجرا کنید که هیچ اطلاعیه‌ای بر آن اثر نمی‌گذارد، همهٔ این‌ها از میان می‌رود. برای ارتقا، [ارتقا](/docs/installation/upgrading) را ببینید.

## بررسی را خاموش کنید

در شبکه‌ای بدون دسترسی به اینترنت، یا اگر سرور شما نباید با GitHub تماس بگیرد، این بررسی را خاموش کنید. آنگاه هیچ چیز نشان داده یا ایمیل نمی‌شود.

:::tabs
@tab Kubernetes
```yaml
updateCheck:
  disabled: true
```
@tab Docker Compose
```bash
DISABLE_UPDATE_CHECK=true
```
آن را در `config.env` تنظیم کنید، سپس `npm start` را اجرا کنید.
:::

برای اینکه به‌جای آن با یک آینه درون شبکهٔ خود بررسی کنید، بررسی را به آن آینه اشاره دهید. آینه باید با همان ساختارهای GitHub پاسخ دهد.

| مقدار Helm | تنظیم Docker Compose | پیش‌فرض |
| --- | --- | --- |
| `updateCheck.url` | `LATEST_RELEASE_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/releases/latest` |
| `updateCheck.securityAdvisoriesUrl` | `SECURITY_ADVISORIES_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/security-advisories` |

## وقتی GitHub در دسترس نیست

در شبکه‌ای بدون دسترسی به اینترنت، ناموفق بودن یک درخواست قابل انتظار است، نه یک خطا. worker آن را در سطح debug ثبت می‌کند، آنچه را آخرین بار خوانده نگه می‌دارد، و بعداً دوباره تلاش می‌کند. داشبورد مدیریت می‌گوید اطلاعیه‌ها آخرین بار کی خوانده شده‌اند، و چرا آخرین بررسی ناموفق بوده است: محدودیت نرخ GitHub، نبود مسیری به GitHub، پایان مهلت، یا پاسخی که از GitHub نیست.
