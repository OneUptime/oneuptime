# عامل Docker Swarm در OneUptime

## نمای کلی

عامل Docker Swarm در OneUptime خوشه‌ای Docker Swarm را زیر نظر می‌گیرد — گره‌ها، سرویس‌ها، وظیفه‌ها، پشته‌ها، شبکه‌های روپوش، اسرار، پیکربندی‌ها، حجم‌ها — به‌علاوه سنجه‌ها و گزارش‌های هر کانتینر. دو کانتینر همکار است که با Docker Compose روی گره **مدیر** خوشه اجرا می‌شوند:

1. **جمع‌کننده** — جمع‌کننده‌ای از پیش پیکربندی‌شده از OpenTelemetry که `docker_stats` را برای سنجه‌های کانتینر برداشت می‌کند، گزارش‌های کانتینر را دنبال می‌کند، و فایل عکس فوری موجودی را دنبال می‌کند، و پیش از فرستادن روی OTLP همه‌چیز را با هویت خوشه شما (`docker.swarm.cluster.name`) مهر می‌زند.
2. **پیمایشگر موجودی** — همراهی کوچک از `curl` + `jq` که هر ۵ دقیقه API مدیر Swarm را می‌پیماید (`/nodes`، `/services`، `/tasks`، `/networks`، `/secrets`، `/configs`، `/volumes`) و پشته‌ها را از برچسب سرویس `com.docker.stack.namespace` مشتق می‌کند، و به ازای هر شیء یک خط JSON می‌نویسد تا جمع‌کننده فوروارد کند.

خوشه با نخستین تله‌متری در OneUptime خودکار ثبت می‌شود، کلیدخورده بر پایه نام خوشه‌ای که پیکربندی می‌کنید.

## پیش‌نیازها

- ‏Docker Engine ‏20.10 به بالا با افزونه Docker Compose v2، **روی گره مدیر خوشه** (پیمایشگر موجودی نقطه‌های پایانی فقط-مدیر API را فرا می‌خواند).
- یک **کلید دریافت تله‌متری OneUptime** — از _Project Settings → Telemetry & APM → Ingestion Keys_ یکی بسازید و مقدارش را کپی کنید.

### عامل را کجا اجرا کنیم

روی **گره مدیر** اجرایش کنید. برای سنجه‌های کامل کانتینر به ازای هر گره، جمع‌کننده را روی هر گره اجرا کنید (همه با یک `DOCKER_SWARM_CLUSTER_NAME`)؛ پیمایشگر موجودی فقط لازم است روی یک مدیر اجرا شود. هنگام استقرار به‌صورت پشته swarm به‌جای Compose، پیمایشگر موجودی را با `node.role == manager` به مدیرها محدود کنید.

## شروع سریع — اسکریپت نصب

```bash
curl -sSL https://raw.githubusercontent.com/OneUptime/oneuptime/master/DockerSwarmAgent/install.sh -o install.sh
sh install.sh
```

اسکریپت نشانی OneUptime، کلید دریافت تله‌متری و نام خوشه شما را می‌پرسد، در `/opt/oneuptime-docker-swarm-agent` نصب می‌کند، و عامل را آغاز می‌کند.

## شروع سریع — Docker Compose

فایل‌های `docker-compose.yml`، `otel-collector-config.yaml` و `inventory-snapshot.sh` را از پوشه [`DockerSwarmAgent`](https://github.com/OneUptime/oneuptime/tree/master/DockerSwarmAgent) روی گره مدیری دانلود کنید، سپس کنارشان فایلی `.env` بسازید:

```bash
ONEUPTIME_URL=https://oneuptime.com
ONEUPTIME_SERVICE_TOKEN=your-telemetry-ingestion-key
DOCKER_SWARM_CLUSTER_NAME=my-swarm
```

سپس عامل را آغاز کنید:

```bash
chmod +x inventory-snapshot.sh
docker compose up -d
```

خوشه ظرف چند دقیقه در OneUptime پدیدار می‌شود، و صفحه‌های فهرست منابع (گره‌ها، سرویس‌ها، وظیفه‌ها، پشته‌ها، شبکه‌ها، اسرار، پیکربندی‌ها، حجم‌ها) پس از نخستین عکس فوری موجودی (حداکثر ۵ دقیقه) پر می‌شوند.

## چه چیزی جمع می‌شود

| سیگنال | منبع | چه چیزی را نیرو می‌دهد |
| ---------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------ |
| موجودی گره / سرویس / وظیفه / پشته / شبکه / راز / پیکربندی / حجم | پیمایشگر موجودی → API مدیر Swarm | فهرست منابع خوشه + صفحه‌های جزئیات |
| شمارهای خوشه (گره‌های آماده، وظیفه‌های در حال اجرا، سرویس‌ها، پشته‌ها، …) | مشتق‌شده از همان عکس فوری | کارت‌های نمای کلی + نشان‌های نوار کناری |
| ‏CPU / حافظه / pids / آپ‌تایم کانتینر | گیرنده `docker_stats` | زبانه Metrics |
| گزارش‌های stdout/stderr کانتینر | گیرنده `filelog` | زبانه Logs |

## متغیرهای محیطی

| متغیر | الزامی | پیش‌فرض | یادداشت‌ها |
| ----------------------------------- | -------- | ----------------------- | -------------------------------------------------------------------------------------------- |
| `ONEUPTIME_URL` | بله | `https://oneuptime.com` | نمونه OneUptime شما |
| `ONEUPTIME_SERVICE_TOKEN` | بله | — | کلید دریافت تله‌متری |
| `DOCKER_SWARM_CLUSTER_NAME` | بله | `docker-swarm` | کلید پیوستن خوشه (با Name خوشه در OneUptime می‌خواند) |
| `DOCKER_INVENTORY_INTERVAL_SECONDS` | خیر | `300` | هر چند وقت پیمایشگر عکس فوری موجودی را تازه می‌کند |
| `DOCKER_API_VERSION` | خیر | `1.44` | نسخه API ‏Docker Engine که جمع‌کننده و پیمایشگر موجودی حرف می‌زنند (رفع اشکال را ببینید) |

## چه تفاوتی با عامل میزبان Docker دارد

عامل میزبان Docker یک میزبان تنها را مدل می‌کند و `host.name` + `container.runtime=docker` را مهر می‌زند. عامل Swarm عمداً **فقط** `docker.swarm.cluster.name` را مهر می‌زند تا OneUptime تله‌متری را به خوشه swarm منتسب کند نه اینکه هر گره را خودکار به‌عنوان یک Host یا Docker Host مستقل ثبت کند.

## رفع اشکال

- **موجودی‌ای پدیدار نمی‌شود** — تأیید کنید پیمایشگر روی مدیری اجرا می‌شود (`docker node ls` باید آنجا موفق شود). گزارش‌های `docker compose logs oneuptime-docker-swarm-inventory` را برای خط‌های `failed to emit ...` بررسی کنید.
- **خوشه هرگز پدیدار نمی‌شود** — گزارش‌های جمع‌کننده و درست بودن `ONEUPTIME_SERVICE_TOKEN` / `ONEUPTIME_URL` را بررسی کنید.
- **وضعیت به Disconnected می‌لرزد** — خوشه پس از ۱۵ دقیقه بدون تله‌متری قطع علامت می‌خورد؛ مطمئن شوید کانتینر جمع‌کننده در حال اجرا می‌ماند.
- **جمع‌کننده با «client version is too new» بیرون می‌رود** — بیشینه نسخه API دیمن زیر پیش‌فرض `1.44` است (Docker Engine ‏20.10 روی `1.41` می‌ایستد)، پس گیرنده `docker_stats` آغاز نمی‌شود و کانتینر حلقه بازراه‌اندازی می‌زند. بیشینه را با `docker version --format '{{ .Server.APIVersion }}'` بررسی کنید، `DOCKER_API_VERSION` را در `.env` روی آن مقدار بگذارید، و روی هر گره‌ای که عامل را اجرا می‌کند `docker compose up -d` را اجرا کنید. یا `DOCKER_API_VERSION=` (خالی) بگذارید تا جمع‌کننده به‌جای سنجاق کردن، نسخه را با دیمن مذاکره کند.
