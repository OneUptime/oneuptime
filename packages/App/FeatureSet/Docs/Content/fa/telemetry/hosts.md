# میزبان‌ها

یک ماشین Linux، Windows یا macOS را با یک فرمان به OneUptime اضافه کنید. این فرمان OpenTelemetry Collector را روی میزبان نصب می‌کند و OneUptime پیکربندی کالکتور را برایش می‌فرستد و به‌روز نگه می‌دارد: هیچ `config.yaml` لازم نیست بنویسید، روی هر میزبان کپی کنید یا یکسان نگه دارید. برای تغییر آنچه میزبان‌هایتان جمع‌آوری می‌کنند، یک بار یک پیکربندی کالکتور را ویرایش کنید تا هر میزبانی که آن پیکربندی برایش صدق می‌کند، ظرف یک دقیقه تغییر را دریافت کند.

:::cards
- [افزودن یک میزبان](#افزودن-یک-میزبان): یک فرمان روی Linux، Windows یا macOS.
- [تغییر آنچه میزبان‌ها جمع‌آوری می‌کنند](#تغییر-آنچه-میزبانها-جمعآوری-میکنند): پیکربندی‌های کالکتور بر اساس سیستم و برچسب، با نگه‌داشتن هر نسخه.
- [بررسی کالکتور یک میزبان](#بررسی-کالکتور-یک-میزبان): پیکربندی‌ای که اجرا می‌کند، نسخه‌اش و اینکه چرا یک پیکربندی راه‌اندازی نشد.
- [یک پیکربندی چه کارهایی می‌تواند بکند](#یک-پیکربندی-چه-کارهایی-میتواند-بکند): خواندن میزبان و فرستادن فقط به همین OneUptime.
:::

## چگونه کار می‌کند

این فرمان دو برنامه را از انتشارهای OpenTelemetry Collector نصب می‌کند و هر کدام را با SHA-256 منتشرشده برای آن انتشار بررسی می‌کند: `otelcol-contrib`، کالکتوری که میزبان را می‌خواند، و `opampsupervisor` که کالکتور را اجرا می‌کند و آن را روی پیکربندی‌ای نگه می‌دارد که OneUptime از طریق OpAMP (OpenTelemetry Agent Management Protocol) می‌فرستد. هر دو به‌عنوان سرویس `oneuptime-collector` اجرا می‌شوند.

```mermaid title="یک فرمان، و سپس OneUptime میزبان را پیکربندی‌شده نگه می‌دارد"
flowchart TB
    command["فرمان نصب<br/>روی میزبان"] --> supervisor["opampsupervisor"]
    supervisor -->|"هر ۳۰ ثانیه<br/>پیکربندی‌اش را می‌خواهد"| oneuptime["OneUptime"]
    oneuptime -->|"پیکربندی‌ای که<br/>میزبان اجرا می‌کند"| supervisor
    supervisor --> collector["otelcol-contrib"]
    collector -->|"OTLP روی HTTPS"| oneuptime
```

ناظر تقریباً هر ۳۰ ثانیه با کلید دریافت شما پیکربندی میزبان را از OneUptime درخواست می‌کند و گزارش می‌دهد میزبان کدام پیکربندی را اجرا می‌کند و آیا راه‌اندازی شد. میزبان با اولین اتصال ناظر، با نام ماشین در **میزبان‌ها** ثبت می‌شود و صفحه‌هایش با رسیدن معیارها و لاگ‌ها پر می‌شوند.

هر میزبان یک پیکربندی اجرا می‌کند که به این ترتیب انتخاب می‌شود:

| آنچه میزبان اجرا می‌کند | چه زمانی |
| --- | --- |
| پیکربندی‌ای که در صفحه **کالکتور** آن برایش انتخاب شده است | کسی یکی را انتخاب کرده باشد. |
| اولین مورد از **پیکربندی‌های کالکتور** که برایش صدق می‌کند | یک پیکربندی وقتی صدق می‌کند که برای سیستم میزبان باشد و اگر برچسب‌هایی را نام می‌برد، میزبان یکی از آن‌ها را داشته باشد. |
| پیش‌فرض OneUptime برای سیستمش | هیچ پیکربندی‌ای صدق نکند. |

پیش‌فرض OneUptime روی هر سیستمی CPU، حافظه، دیسک‌ها، سیستم‌های فایل، شبکه و فرایندها را می‌خواند؛ روی Linux، journal و یونیت‌های systemd را هر جا میزبان داشته باشد؛ روی Windows، لاگ‌های رویداد System، Application و Security و سرویس‌های Windows را؛ و روی macOS، لاگ‌های نصب و Wi-Fi در `/var/log` را. سیستم‌های فایلی را که طبق طراحی پر هستند، مانند بسته‌های snap و `/dev` در macOS، کنار می‌گذارد تا هیچ‌گاه الگوی High Filesystem Usage را پیوسته فعال نگه ندارند. این پیش‌فرض همراه انتشارهای OneUptime به‌روز می‌شود، پس میزبانی که از آن استفاده می‌کند بهبودهای OneUptime را دریافت می‌کند.

## پیش از شروع

- یک کلید دریافت. **افزودن میزبان** یکی برایتان می‌سازد، یا کلیدی را که در **تنظیمات پروژه** > **تله‌متری و APM** > **کلیدهای دریافت داده** ساخته‌اید انتخاب کنید.
- دسترسی مدیر روی میزبان: `sudo` روی Linux و macOS، و PowerShell اجراشده به‌عنوان مدیر روی Windows.
- Linux با systemd، Windows 10 یا Windows Server 2019 و جدیدتر، یا macOS روی Apple silicon یا Intel.
- ارتباط HTTPS خروجی از میزبان به نشانی OneUptime شما، مستقیم یا از طریق یک پراکسی.

## افزودن یک میزبان

:::steps
### افزودن میزبان را باز کنید

**محصولات** > **زیرساخت** > **میزبان‌ها** را باز کنید و **افزودن میزبان** را انتخاب کنید. انتخاب کنید روی میزبان چه چیزی اجرا می‌شود: Linux، Windows یا macOS. گره‌های یک کلاستر Kubernetes را به‌جای آن [Kubernetes Agent](/docs/telemetry/kubernetes-agent) پایش می‌کند.

### یک کلید دریافت انتخاب کنید

یک کلید انتخاب کنید یا از پنجره آن را بسازید. فرمان زیر آن را پر می‌کند.

### فرمان را روی میزبان اجرا کنید

فرمان را از پنجره کپی کنید و روی میزبان اجرا کنید. حدود یک دقیقه طول می‌کشد. این‌ها همان فرمان‌ها هستند که در آن‌ها نشانی OneUptime و کلید شما به‌جای نمونه‌ها قرار می‌گیرد:

:::tabs
@tab Linux
```bash
curl -fsSL https://oneuptime.com/docs/static/scripts/host-collector/install.sh | sudo sh -s -- --url https://oneuptime.com --key YOUR_INGESTION_KEY
```
@tab macOS
```bash
curl -fsSL https://oneuptime.com/docs/static/scripts/host-collector/install.sh | sudo sh -s -- --url https://oneuptime.com --key YOUR_INGESTION_KEY
```
@tab Windows
```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor [Net.SecurityProtocolType]::Tls12; & ([scriptblock]::Create((Invoke-RestMethod -Uri 'https://oneuptime.com/docs/static/scripts/host-collector/install.ps1'))) -Url 'https://oneuptime.com' -Key 'YOUR_INGESTION_KEY'
```
:::

هر OneUptime نصب‌کننده‌های خودش را ارائه می‌کند، پس یک OneUptime خودمیزبان نصب‌کننده انتشار خودش را می‌دهد: `https://oneuptime.com` را در هر دو جا با نشانی خودتان جایگزین کنید.

### منتظر میزبان بمانید

مرحله آخر پنجره نشان می‌دهد میزبان چه زمانی متصل شد، همراه پیوندی به آن. در فهرست، تا رسیدن اولین معیارها (معمولاً ظرف یک دقیقه) به‌صورت **در حال شروع** نمایش داده می‌شود و سپس به‌صورت متصل، با کالکتوری که **در حال اجرا** است. صفحهٔ **توپولوژی** میزبان آنچه روی آن اجرا می‌شود، آنچه آن را فرا می‌خواند و آنچه آن فرا می‌خواند را روی یک نقشه می‌کشد: [توپولوژی](/docs/telemetry/topology#باز-کردن-نقشهٔ-خود-یک-منبع) را ببینید.
:::

## برچسب‌گذاری میزبان‌ها

برچسب‌ها را به فرمان اضافه کنید تا میزبان از لحظه اتصال آن‌ها را داشته باشد:

:::tabs
@tab Linux
```bash
curl -fsSL https://oneuptime.com/docs/static/scripts/host-collector/install.sh | sudo sh -s -- --url https://oneuptime.com --key YOUR_INGESTION_KEY --label env=production --label team=payments
```
@tab macOS
```bash
curl -fsSL https://oneuptime.com/docs/static/scripts/host-collector/install.sh | sudo sh -s -- --url https://oneuptime.com --key YOUR_INGESTION_KEY --label env=production --label team=payments
```
@tab Windows
```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor [Net.SecurityProtocolType]::Tls12; & ([scriptblock]::Create((Invoke-RestMethod -Uri 'https://oneuptime.com/docs/static/scripts/host-collector/install.ps1'))) -Url 'https://oneuptime.com' -Key 'YOUR_INGESTION_KEY' -Label 'env=production','team=payments'
```
:::

`env=production` به برچسب `env:production` تبدیل می‌شود. برچسب‌ها فقط اضافه می‌شوند و هرگز برداشته نمی‌شوند: فرمان را با برچسب دیگری دوباره اجرا کنید تا میزبان هر دو را داشته باشد. همچنین می‌توانید در فهرست **میزبان‌ها** یا با **قواعد برچسب** به میزبان‌ها برچسب بزنید. پیکربندی کالکتوری که برچسب‌هایی را نام می‌برد فقط برای میزبان‌هایی است که یکی از آن‌ها را دارند، پس همان فرمان با برچسب‌های متفاوت به هر گروه از میزبان‌ها پیکربندی خودش را می‌دهد.

## تغییر آنچه میزبان‌ها جمع‌آوری می‌کنند

:::steps
### یک پیکربندی کالکتور بسازید

**محصولات** > **زیرساخت** > **میزبان‌ها** > **پیکربندی‌های کالکتور** را باز کنید و **ساخت پیکربندی کالکتور** را انتخاب کنید. به آن یک نام، سیستم میزبان‌هایی که برایشان است و اگر فقط بخشی از آن‌ها را در نظر دارید، برچسب‌هایشان را بدهید. پیکربندی آن از پیش‌فرض OneUptime برای آن سیستم شروع می‌شود.

### config.yaml آن را ویرایش کنید

در صفحه پیکربندی، **ویرایش پیکربندی** را انتخاب کنید، YAML را تغییر دهید و ذخیره کنید. OneUptime ابتدا آن را بررسی می‌کند و پیکربندی‌ای را که نمی‌تواند بفرستد، با ذکر دلیل رد می‌کند: [یک پیکربندی چه کارهایی می‌تواند بکند](#یک-پیکربندی-چه-کارهایی-میتواند-بکند) را ببینید.

### رسیدن آن به میزبان‌ها را ببینید

هر تغییر ذخیره‌شده یک نسخه جدید است و میزبان‌هایی که برایشان صدق می‌کند، ظرف یک دقیقه آن را دریافت می‌کنند. فهرست **میزبان‌ها** در پیکربندی، هر میزبان، وضعیت کالکتورش و نسخه‌ای را که اجرا می‌کند نشان می‌دهد.
:::

هر میزبان اولین پیکربندی فهرست را که برایش صدق می‌کند اجرا می‌کند: برای تغییر ترتیب، ردیف‌ها را در **پیکربندی‌های کالکتور** بکشید. محدودترین پیکربندی‌ها را اول بگذارید، مثلاً یکی برای سرورهای وب `env:production`، و پیکربندی‌های گسترده را بعد از آن‌ها، مثلاً یکی برای همه میزبان‌های Linux. کارت **پیش‌فرض‌های OneUptime** زیر فهرست نشان می‌دهد وقتی هیچ پیکربندی‌ای صدق نکند، میزبان چه چیزی اجرا می‌کند.

### نسخه‌ها و بازگرداندن

فهرست **نسخه‌ها** در هر پیکربندی، هر تغییر ذخیره‌شده را از جدیدترین به قدیمی‌ترین، همراه با اینکه چه کسی و چه زمانی ذخیره‌اش کرده نگه می‌دارد. برای خواندن یک نسخه **مشاهده** و برای فرستادن دوباره آن به میزبان‌ها **بازگرداندن** را انتخاب کنید: آن نسخه به‌عنوان نسخه‌ای جدید ذخیره می‌شود که می‌گوید کدام نسخه را بازگردانده است، پس فهرست همیشه نشان می‌دهد به هر میزبان چه چیزی فرستاده شده است.

### برای یک میزبان پیکربندی انتخاب کنید

در صفحه **کالکتور** یک میزبان، **تغییر پیکربندی** را انتخاب کنید و پیکربندی‌ای فقط برای همین میزبان برگزینید. پیکربندی‌های مربوط به سیستم میزبان و پیکربندی‌های مربوط به هر سیستمی پیشنهاد می‌شوند. برای سپردن دوباره میزبان به فهرست، خودکار را انتخاب کنید. میزبانی که پیکربندی انتخاب‌شده‌اش حذف شود، خودبه‌خود به فهرست برمی‌گردد.

### وقتی یک پیکربندی راه‌اندازی نمی‌شود

ناظر پیش از رفتن به یک پیکربندی جدید، آن را با کالکتور بررسی می‌کند و اگر راه‌اندازی نشود، به آخرین پیکربندی سالم برمی‌گردد. میزبان در تمام این مدت به فرستادن ادامه می‌دهد. صفحه **کالکتور** آن، **پیکربندی ناموفق بود** را همراه دلیل کالکتور نشان می‌دهد، مثلاً یک فایل لاگ که کالکتور اجازه خواندنش را ندارد، و OneUptime تا وقتی آن پیکربندی تغییر نکند، دوباره آن را به میزبان نمی‌فرستد. پس از رفع علت روی میزبان، برای فرستادن دوباره آن **تلاش دوباره** را انتخاب کنید.

## یک پیکربندی چه کارهایی می‌تواند بکند

پیکربندی‌ای که OneUptime می‌فرستد روی هر میزبانی که برایش صدق می‌کند اجرا می‌شود، پس OneUptime هر بار که ذخیره می‌شود آن را بررسی می‌کند و پیکربندی‌ای را که قاعده‌ای را بشکند رد می‌کند:

| قاعده | چرا |
| --- | --- |
| فقط receivers، processors، exporters، extensions و connectors موجود در فهرست OneUptime | پیکربندی میزبان و سرویس‌های روی آن را می‌خواند. مؤلفه‌ای که برنامه اجرا می‌کند یا اعتبارنامه‌های ابر یا کلاستر را می‌خواند در فهرست نیست. |
| داده‌ها فقط از طریق exporter `otlp_http` و به `${env:ONEUPTIME_URL}/otlp` با سرآیند `x-oneuptime-token: ${env:ONEUPTIME_INGESTION_KEY}` از میزبان خارج می‌شوند | هر میزبان با کلیدی که با آن نصب شده به همین OneUptime می‌فرستد. هیچ پیکربندی‌ای کلید ندارد. |
| تنها `${...}` قابل استفاده `${env:NAME}` است | یک `${file:...}` یا `${https:...}` روی هر میزبان خوانده می‌شد و می‌توانست جای دیگری فرستاده شود. |
| هیچ تنظیمی که برنامه‌ای اجرا کند یا فایلی را که می‌خواند بفرستد، مانند `journalctl_path` در journald | پیکربندی نمی‌تواند از خواندن میزبان فراتر برود. |

با این حال، یک پیکربندی ممکن است چیزی باشد که میزبان نتواند اجرایش کند، مثل receiver سیستمی دیگر یا فایل لاگی که آنجا وجود ندارد. کالکتور هر میزبان پیش از تغییر این را بررسی می‌کند، همان‌طور که [وقتی یک پیکربندی راه‌اندازی نمی‌شود](#وقتی-یک-پیکربندی-راهاندازی-نمیشود) توضیح می‌دهد.

## بررسی کالکتور یک میزبان

میزبان و صفحه **کالکتور** آن را باز کنید. این صفحه وضعیت کالکتور، پیکربندی‌ای که اجرا می‌کند و **چرا این پیکربندی**، نسخه‌ای که اجرا می‌کند، **آخرین گزارش** و **انتشار کالکتور** آن را نشان می‌دهد. زیر **روی میزبان** فرمان‌های بررسی آن از یک شل روی میزبان آمده است: اینکه سرویسش اجرا می‌شود یا نه، لاگ آن و راه‌اندازی مجدد.

:::tabs
@tab Linux
```bash
sudo systemctl status oneuptime-collector
sudo journalctl -u oneuptime-collector -n 50
sudo systemctl restart oneuptime-collector
```
@tab macOS
```bash
sudo launchctl print system/com.oneuptime.collector
sudo tail -n 50 /usr/local/oneuptime-collector/log/collector.log
sudo launchctl kickstart -k system/com.oneuptime.collector
```
@tab Windows
```powershell
Get-Service oneuptime-collector
Get-WinEvent -FilterHashtable @{ LogName = 'Application'; ProviderName = 'oneuptime-collector' } -MaxEvents 50 | Format-List TimeCreated, Message
Restart-Service oneuptime-collector
```
:::

روی Linux، کالکتور با کاربر بدون دسترسی ویژه `oneuptime-collector` و در گروه‌های `systemd-journal` و `adm` اجرا می‌شود تا بتواند journal و لاگ‌های `/var/log` را بخواند. روی macOS مانند دیمن‌های launchd با root اجرا می‌شود و روی Windows با LocalSystem، تا بتواند همه لاگ‌های رویداد و سرویس‌های Windows را بخواند.

## میزبان‌هایی که دستی راه‌اندازی شده‌اند

میزبانی که کالکتورش را خودتان با راهنمای [کالکتور OpenTelemetry روی میزبان](/docs/telemetry/host-otel-collector) نصب کرده‌اید، مثل قبل به گزارش دادن ادامه می‌دهد و OneUptime پیکربندی‌ای برایش نمی‌فرستد. برای سپردن آن به OneUptime، صفحه **کالکتور** میزبان را باز کنید: فرمان آنجا `--replace-existing` را اضافه می‌کند که کالکتور نصب‌شده به‌صورت دستی (سرویس `otelcol-contrib`) را متوقف و غیرفعال می‌کند تا میزبان دو بار گزارش ندهد. میزبان نام، سابقه و برچسب‌هایش را نگه می‌دارد.

## گزینه‌های نصب

برای تغییر هر یک از این‌ها یا رفتن به انتشاری جدیدتر، فرمان را دوباره اجرا کنید: آنچه را نصب کرده بود جایگزین می‌کند و میزبان را در OneUptime همان‌طور که هست نگه می‌دارد.

| Linux و macOS | Windows | کاری که انجام می‌دهد |
| --- | --- | --- |
| `--url URL` | `-Url URL` | نشانی OneUptime. |
| `--key KEY` | `-Key KEY` | یک کلید دریافت تله‌متری از پروژه شما. |
| `--label KEY=VALUE` | `-Label KEY=VALUE` | به میزبان برچسب می‌زند. برای برچسب‌های بیشتر آن را تکرار کنید؛ روی Windows آن‌ها را با ویرگول فهرست کنید. |
| `--env NAME=VALUE` | `-EnvVar NAME=VALUE` | برای پیکربندی‌هایی که `${env:NAME}` را می‌خوانند، یک متغیر محیطی به کالکتور می‌دهد. |
| `--version VERSION` | `-Version VERSION` | انتشار کالکتوری که نصب می‌شود، به‌طور پیش‌فرض 0.161.0. |
| `--download-url URL` | `-DownloadUrl URL` | انتشارها را از آینه‌ای با همان ساختار پوشه GitHub دانلود می‌کند. |
| `--proxy URL` | `-Proxy URL` | دانلودها و همه ترافیک کالکتور را از یک پراکسی HTTP عبور می‌دهد. |
| `--replace-existing` | `-ReplaceExisting` | کالکتوری را که دستی نصب شده متوقف و غیرفعال می‌کند. |
| `--uninstall` | `-Uninstall` | کالکتور و هر آنچه فرمان نصب کرده را حذف می‌کند. |

## حذف نصب

:::tabs
@tab Linux
```bash
curl -fsSL https://oneuptime.com/docs/static/scripts/host-collector/install.sh | sudo sh -s -- --uninstall
```
@tab macOS
```bash
curl -fsSL https://oneuptime.com/docs/static/scripts/host-collector/install.sh | sudo sh -s -- --uninstall
```
@tab Windows
```powershell
& ([scriptblock]::Create((Invoke-RestMethod -Uri 'https://oneuptime.com/docs/static/scripts/host-collector/install.ps1'))) -Uninstall
```
:::

میزبان با سابقه‌اش در OneUptime باقی می‌ماند: آن را در فهرست **میزبان‌ها** بایگانی یا حذف کنید.

## عیب‌یابی

:::details فرمان می‌گوید OneUptime کلید را رد کرد
HTTP `401`: کلید نادرست است، منقضی شده یا حذف شده است. HTTP `422`: کلید غیرفعال است، کلید مرورگر است یا به یک سرویس محدود شده است. در **افزودن میزبان** یک کلید سرور فعال انتخاب کنید و فرمان را دوباره اجرا کنید: کلید روی میزبان را جایگزین می‌کند.
:::

:::details میزبان نمایش داده نمی‌شود
بررسی کنید میزبان بتواند از طریق HTTPS به نشانی OneUptime شما برسد، سپس لاگ کالکتور را با فرمان مربوط به سیستمش در [بررسی کالکتور یک میزبان](#بررسی-کالکتور-یک-میزبان) بخوانید.
:::

:::details میزبان می‌گوید پیکربندی‌اش ناموفق بود
صفحه **کالکتور** آن نشان می‌دهد چرا پیکربندی راه‌اندازی نشد. میزبان به اجرای آخرین پیکربندی سالم ادامه می‌دهد و وقتی پیکربندی تغییر کند یا شما **تلاش دوباره** را انتخاب کنید، پیکربندی ناموفق را دوباره دریافت می‌کند.
:::

:::details میزبان «بدون گزارش‌دهی» نشان می‌دهد
OneUptime بیش از ۱۵ دقیقه است که از ناظر میزبان خبری نگرفته است. بررسی کنید سرویس `oneuptime-collector` اجرا می‌شود و میزبان هنوز به OneUptime دسترسی دارد.
:::

## گام‌های بعدی

:::cards
- [کالکتور OpenTelemetry روی میزبان](/docs/telemetry/host-otel-collector): به‌جای آن، کالکتور را خودتان نصب کنید و پیکربندی‌اش را بنویسید.
- [مانیتور میزبان](/docs/monitor/host-monitor): برای آنچه میزبان‌هایتان گزارش می‌دهند هشدار بگیرید.
- [کلیدهای دریافت](/docs/telemetry/ingestion-keys): کلیدهایی را که میزبان‌ها با آن‌ها می‌فرستند بسازید، محدود کنید و تعویض کنید.
- [Kubernetes Agent](/docs/telemetry/kubernetes-agent): گره‌ها و بارهای کاری یک کلاستر را پایش کنید.
:::
