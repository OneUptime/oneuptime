# رفع اشکال

جستجوی سریع خطاهایی که آدم‌ها واقعاً با ارائه‌دهنده Terraform در OneUptime به آن‌ها می‌خورند، و پس از آن جزئیات هرکدام.

## نشانه → علت → راه‌حل

| نشانه | علت محتمل | راه‌حل |
|---------|-------------|-----|
| `Provider produced inconsistent result after apply` | نسخه قدیمی ارائه‌دهنده که فیلدهای محاسبه‌شده توسط کارساز را بد اداره می‌کرد | ارائه‌دهنده را ارتقا دهید (`terraform init -upgrade` درون `~> 11.0`)؛ اگر ماند گزارش کنید |
| `ProjectId required` در هر عملیاتی | کلید API ارشد یا کاربر به‌جای کلید API پروژه | زیر **Project Settings > API Keys** کلیدی بسازید و همان را به کار ببرید |
| مقدار `priority` یا `order` وضعیت/حالت پس از apply منحرف می‌شود | اولویت‌ها جایگاه درج‌اند: ساختن یکی هر مدخل موجود در آن مقدار یا بالاتر را جابه‌جا می‌کند، و پس از ساخت قابل ویرایش نیستند | از مقادیر بالا و فاصله‌دار (برای نمونه `101`، `102`، `103`) استفاده کنید که به ترتیب صعودی با زنجیره `depends_on` ساخته شوند |
| خطاهای `402` / پرداخت لازم | محدودیت طرح (مانیتور، صفحه وضعیت، ...) در طرح OneUptime شما پر شده | طرح را ارتقا دهید یا شمار منابع را کم کنید |
| `403` / دسترسی رد شده روی یک نوع منبع | کلید API پروژه دسترسی Create/Read/Update/Delete برای آن نوع را ندارد | دسترسی‌های کلید را در Project Settings > API Keys ویرایش کنید |
| `401` / احراز هویت شکست خورد | کلید باطل، منقضی، یا مقدار `ONEUPTIME_API_KEY` اشتباه | کلید API پروژه تازه‌ای تولید کنید |
| ارائه‌دهنده هنگام آغاز `terraform plan` درباره نبود کلید API خطا می‌دهد | نه ویژگی `api_key` و نه متغیر محیطی `ONEUPTIME_API_KEY` | یکی از آن‌ها را تنظیم کنید |
| `no matching version found for oneuptime/oneuptime` | سنجاق نسخه دقیق روی نسخه‌ای که هرگز منتشر نشده | از محدودیتی بدبینانه مانند `~> 11.0` استفاده کنید |
| خطای منبع داده: بدون تطابق / بیش از یک تطابق | جستجوی نام صفر یا چند منبع یافت | نام را اصلاح کنید، یا با `id` جستجو کنید |
| `x509: certificate signed by unknown authority` (خودمیزبان) | نمونه گواهی TLSای سرو می‌کند که میزبان Terraform به آن اعتماد ندارد | ‏CA را روی ماشینی که Terraform را اجرا می‌کند نصب کنید |
| اتصال رد شد / ۴۰۴ روی هر فراخوان API (خودمیزبان) | مقدار `oneuptime_url` اشتباه (پسوند مسیر، درگاه اشتباه، http در برابر https) | `oneuptime_url` را روی مبدأ خالی نمونه بگذارید، برای نمونه `https://oneuptime.example.com` |
| ‏JSON مانیتور از داشبورد رد می‌شود | ‏JSON صادرشده داشبورد به‌عنوان پیکربندی Terraform چسبانده شده | به‌صورت HCL بازبسازید — پایین‌تر را ببینید |
| `monitor_steps` فهرست، نگاشت یا رشته خالی را رد می‌کند | `[]`، `{}` یا `""` به‌عنوان جانگهدار داده شده | ویژگی را کلاً بگذارید نباشد — نبود یعنی تنظیم‌نشده |

## «Provider produced inconsistent result after apply»

این خطا یعنی Terraform تشخیص داده ارائه‌دهنده مقادیری متفاوت از آنچه طرح‌ریزی کرده برگردانده است. نسخه‌های تاریخی ارائه‌دهنده آن را روی فیلدهای محاسبه‌شده کارساز تولید می‌کردند — `monitor_steps` پیش‌فرضی که کارساز تزریق می‌کند، مهرهای زمانی نرمال‌شده، مقادیر پیچیده‌ای مانند `probe_version`. ارائه‌دهنده‌های جاری 11.x همه این‌ها را اداره می‌کنند: پیش‌فرض‌های کارساز بدون انحراف پذیرفته می‌شوند، مهرهای زمانی از نظر معنایی مقایسه می‌شوند، و آرایه‌های برچسب مجموعه‌های بدون ترتیب‌اند.

**راه‌حل:**

1. مطمئن شوید روی ارائه‌دهنده‌ای جاری هستید: `version = "~> 11.0"` سپس `terraform init -upgrade`.
2. ‏apply را دوباره اجرا کنید.

اگر ارائه‌دهنده‌ای جاری همچنان خطا تولید کرد، این اشکالی در ارائه‌دهنده است که گزارشش می‌ارزد. در [github.com/OneUptime/oneuptime/issues](https://github.com/OneUptime/oneuptime/issues) یک issue باز کنید و این‌ها را بگنجانید: نسخه ارائه‌دهنده، نوع منبع، کمینه بلوک `resource` که بازتولیدش می‌کند، و خروجی کامل خطا (که ویژگی دقیقی را که نوسان کرده نام می‌برد). آن نام ویژگی مفیدترین چیزی است که می‌توانید بدهید.

## «ProjectId required»

‏OneUptime دو خانواده اعتبارنامه API دارد:

- **کلیدهای API پروژه** — ساخته‌شده در **Project Settings > API Keys**، محدود به یک پروژه. این همان چیزی است که ارائه‌دهنده Terraform لازم دارد.
- **کلیدهای ارشد** (خودمیزبان) و توکن‌های سطح کاربر — به هیچ پروژه‌ای محدود نیستند.

ارائه‌دهنده پروژه را از خود کلید مشتق می‌کند. کلید ارشد پروژه‌ای حمل نمی‌کند، پس هر فراخوان منبعی با `ProjectId required` شکست می‌خورد. کلید API پروژه‌ای بسازید، به آن Create/Read/Update/Delete روی نوع‌های منبعی که مدیریت می‌کنید بدهید، و در `ONEUPTIME_API_KEY` بگذاریدش.

## خطاهای ۴۰۲ و دسترسی

- **۴۰۲ Payment Required** — به محدودیت منبعی از طرح OneUptime خود خورده‌اید (برای نمونه سقف مانیتور در رده رایگان). Terraform خطای API را همان‌طور که هست نمایان می‌کند. یا طرح را در Project Settings > Billing ارتقا دهید، یا پیکربندی را هرس کنید.
- **۴۰۳ Forbidden روی نوع‌های منبع مشخص** — کلید API پروژه برای آن نوع دسترسی ندارد. کلیدها دسترسی به ازای هر نوع منبع دارند؛ کلیدی که می‌تواند مانیتورها را مدیریت کند نمی‌تواند صفحه وضعیت بسازد مگر آنکه به آن داده شود. کلید را در **Project Settings > API Keys** ویرایش کنید و Create/Read/Update/Delete را برای نوع کم اضافه کنید. وارد کردن دست‌کم به Read نیاز دارد.

## «no matching version found» از رجیستری

نسخه‌های ارائه‌دهنده نسخه‌های پلتفرم OneUptime را دنبال می‌کنند، و **هر انتشار وصله پلتفرم** در رجیستری **منتشر نمی‌شود**. بنابراین سنجاق‌های دقیق مانند `version = "= 11.0.3"` هر وقت که آن وصله دقیق رد شده باشد شکست می‌خورند.

از محدودیتی بدبینانه استفاده کنید و بگذارید Terraform تازه‌ترین تطابق منتشرشده را برگزیند:

```hcl
version = "~> 11.0"
```

کاربران خودمیزبانی که باید در نسخه پلتفرمشان یا پایین‌تر بمانند می‌توانند به‌جای سنجاق کردن وصله، بازه را کران‌دار کنند — [راه‌اندازی خودمیزبان](/docs/terraform/self-hosted) را ببینید.

## خودمیزبان: مشکل‌های نشانی و TLS

- مقدار `oneuptime_url` باید **فقط مبدأ نمونه شما** باشد — طرح و میزبان، بدون پسوند `/api`، بدون مسیر داشبورد: `https://oneuptime.example.com`. ارائه‌دهنده خودش مسیرهای API را می‌افزاید.
- همان مقدار می‌تواند از متغیر محیطی `ONEUPTIME_URL` بیاید.
- اگر نمونه شما CA خصوصی به کار می‌برد، Terraform (برنامه‌ای Go) **انباره اعتماد سامانه** ماشینی را که اجرایش می‌کند می‌خواند. گواهی CA را روی آن ماشین نصب کنید (برای نمونه `/usr/local/share/ca-certificates/` + `update-ca-certificates` روی Debian/Ubuntu). ویژگی‌ای در ارائه‌دهنده برای رد کردن تأیید TLS وجود ندارد — اعتماد را درست کنید، غیرفعالش نکنید.
- نمونه‌های HTTP ساده برای راه‌اندازی آزمایشگاهی کار می‌کنند (`oneuptime_url = "http://oneuptime.lab.internal"`)، اما جلوی هر چیز واقعی TLS بگذارید: کلید API با هر درخواستی سفر می‌کند.

## ‏JSON صادرشده داشبورد پیکربندی Terraform نیست

داشبورد می‌تواند منابع را به‌صورت JSON نشان دهد یا صادر کند. آن JSON یک **محموله API** است، نه HCL، و چسباندنش در فایل `.tf` کار نمی‌کند — نام ویژگی‌های Terraform به شکل snake_case هستند، مقادیر جور دیگری تایپ‌شده‌اند، و بیشتر فیلدهای صادرشده محاسبه‌شده توسط کارسازند.

به‌جایش چه کنید:

- منبع را به‌صورت HCL بازبسازید، با استفاده از [نمونه‌ها](/docs/terraform/examples) به‌عنوان قالب.
- به‌ویژه برای مراحل یک مانیتور: شیء صادرشده `monitorSteps` را به ویژگی‌های تودرتوی تایپ‌شده `monitor_steps` ترجمه کنید ([مراحل مانیتور](/docs/terraform/monitor-steps) را ببینید) — پوشش‌های `{_type, value}` را بیندازید، کلیدهای camelCase را به snake_case تبدیل کنید، و همه فیلدهای `id` را حذف کنید.
- برای پذیرفتن منبع موجود به‌جای بازساختنش، از [وارد کردن](/docs/terraform/importing-resources) استفاده کنید و بگذارید `terraform plan -generate-config-out` نسخه HCL را پیش‌نویس کند.

## هنوز گیر کرده‌اید؟

در [github.com/OneUptime/oneuptime/issues](https://github.com/OneUptime/oneuptime/issues) یک issue با نسخه ارائه‌دهنده (`terraform version` پس از init چاپش می‌کند)، بلوک منبع، و متن دقیق خطا باز کنید. ارائه‌دهنده از پایگاه کد OneUptime تولید می‌شود، پس مسائل در مخزن اصلی ردیابی می‌شوند.
