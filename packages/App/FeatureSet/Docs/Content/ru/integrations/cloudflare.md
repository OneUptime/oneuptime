# Cloudflare

Импортируйте в события безопасности OneUptime то, что межсетевой экран [Cloudflare](https://www.cloudflare.com) сделал на периметре: запросы, которые его управляемые и собственные правила WAF, ограничение частоты, IP Access Rules, управление ботами и защита от HTTP DDoS заблокировали, проверили или записали в журнал. Каждый стоит рядом с собственными запросами вашего приложения, поэтому кейс говорит, что остановил Cloudflare и что всё же дошло до вашего приложения. OneUptime читает их API-токеном, который может только читать, и ничего не меняет в Cloudflare.

:::cards
- [Настройка подключения](#настройка-подключения): API-токен с двумя правами на чтение и форма подключения.
- [Что импортируется](#что-импортируется): Какие события и как каждое из них становится событием безопасности.
- [Как работает опрос](#как-работает-опрос): Окно, которое читает каждый опрос, и почему оно перекрывает предыдущее на 10 минут.
- [Устранение неполадок](#устранение-неполадок): Что означает каждая ошибка и что нужно изменить.
:::

## Как это работает

```mermaid title="От запроса, на который отреагировал Cloudflare, к событию безопасности"
flowchart TB
    edge["Межсетевой экран<br/>Cloudflare реагирует<br/>на запрос"] --> poll["OneUptime опрашивает<br/>с интервалом<br/>подключения"]
    poll --> zones["Он читает события<br/>межсетевого экрана<br/>каждой зоны с<br/>прошлого раза"]
    zones --> event["Каждое сохраняется<br/>как событие<br/>HTTP Activity"]
```

Каждую минуту OneUptime опрашивает каждое включённое подключение, у которого истёк интервал опроса. Опрос получает список зон аккаунта, читает из узла settings в GraphQL Analytics API, что разрешает тариф каждой зоны, и читает события межсетевого экрана каждой зоны с прошлого опроса из набора данных `firewallEventsAdaptive` ([Security Events](https://developers.cloudflare.com/waf/analytics/security-events/)), начиная с самых старых. Каждое событие сохраняется как событие [OCSF](https://schema.ocsf.io/) HTTP Activity.

## Перед началом работы

- В OneUptime роль Владелец проекта, Администратор проекта или Администратор безопасности. Роли Участник безопасности и Зритель безопасности видят подключения и историю их запусков, но не могут их менять.
- Пользователь Cloudflare, который может создавать API-токены для зон аккаунта.
- Зоны, трафик которых идёт через Cloudflare: их DNS-записи проксируются.
- Исходящий HTTPS от приложения и воркеров OneUptime к `api.cloudflare.com`.

## Настройка подключения

Подключение читает [API-токеном](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/), а не Global API Key: токен ограничен аккаунтом и его зонами, и его можно отозвать отдельно. Ему нужны два [права](https://developers.cloudflare.com/fundamentals/api/reference/permissions/), оба только на чтение:

| Право | Что OneUptime читает с ним |
| --- | --- |
| `Zone > Zone > Read` | Зоны, с их аккаунтами и тарифами. |
| `Zone > Analytics > Read` | События межсетевого экрана каждой зоны, через GraphQL Analytics API. |

:::steps
### Создайте токен API

1. В панели Cloudflare откройте **My Profile → API Tokens**, выберите **Create Token**, затем **Create Custom Token**.
2. Назовите его `oneuptime-security-events`. В разделе **Permissions** добавьте `Zone > Zone > Read` и `Zone > Analytics > Read`.
3. В разделе **Zone Resources** включите все зоны аккаунта или зоны, которые нужно импортировать.
4. Выберите **Continue to summary**, затем **Create Token**, и скопируйте токен. Cloudflare показывает его один раз.

### Добавьте подключение в OneUptime

Откройте **Продукты → События безопасности → Подключения** (`/dashboard/{projectId}/security-events/connections`), нажмите **Добавить подключение**, выберите **Cloudflare** в разделе **Облачная безопасность** и нажмите **Далее**. Вставьте токен в **API-токен**. Затем OneUptime перечисляет аккаунты и зоны, которые токен может читать: выберите **Аккаунт**, а в **Зоны** оставьте **Все зоны** или выберите зоны для импорта.

### Проверьте его перед сохранением

Нажмите **Проверить эти настройки** в разделе **Проверка перед сохранением**. Проверка проверяет каждое право со значениями из формы, называет недостающее и ничего не сохраняет. Затем нажмите **Далее**, задайте подключению **Имя** и создайте его.
:::

| Параметр | Что ввести |
| --- | --- |
| **Аккаунт** | Аккаунт Cloudflare для чтения, выбранный из аккаунтов, которые читает ваш API-токен. Токен, который читает один аккаунт, выбирает его за вас. |
| **Зоны** | Необязательно. Пустое поле читает все активные зоны аккаунта, включая добавленные позже. Одно подключение читает не больше 50 зон. |
| **API-токен** | Только токен, без `Bearer`. Он шифруется, никогда не возвращается API и больше не показывается. Замените его через **Обновить учётные данные** у подключения. |

На шаге **Опрос** также есть необязательное **Описание**, **Интервал опроса (минуты)** — целое число от `1` до `1440`, начальное значение `5`, — и **Включено**, изначально включено. События Cloudflare — это запросы, а не оповещения, поэтому форма не спрашивает **Открывать кейсы от**: кейсы появляются из правил обнаружения, которые их читают.

### Доступ на запись — отдельное решение

Это подключение никогда ничего не меняет в Cloudflare. Блокировка адресов там — отдельное согласие, которому нужны права на запись: `Account > Account Filter Lists > Edit` для списков, `Zone > Zone WAF > Edit` в каждой зоне, где нужно блокировать, и `Account > Account Firewall Access Rules > Edit` на тарифах без достаточного числа списков. Добавляйте их к токену, только когда включаете блокировку.

## Что импортируется

У каждого события поставщик `Cloudflare` и продукт `Cloudflare WAF`, и это событие HTTP Activity (`4002`).

| Поле Cloudflare | В событии безопасности |
| --- | --- |
| `clientIP` | IP субъекта и `client.address` |
| `clientRequestHTTPHost`, `clientRequestPath`, `clientRequestQuery` | Целевой хост, целевой ресурс (путь и строка запроса) и `url.original` |
| `clientRequestHTTPMethodName`, `userAgent` | Действие, `http.request.method` и `user_agent.original` |
| `action` | Статус и `oneuptime.edge.action` |
| `source`, `ruleId`, `description` | ID правила, имя правила и `cloudflare.source` |
| `rayName`, `clientCountryName`, `clientAsn` | `cloudflare.ray_id`, `cloudflare.client.country` и `cloudflare.client.asn` |
| `sampleInterval` | `oneuptime.edge.sample_interval` |

| Что сделал Cloudflare | Статус | `oneuptime.edge.action` | Результат запроса | Серьёзность |
| --- | --- | --- | --- | --- |
| Заблокировал, закрыл соединение, или проверка не пройдена | Blocked или Dropped для закрытого соединения | `blocked` | Rejected | Low |
| Ответил управляемой, JS- или интерактивной проверкой | Challenge | `challenged` | Rejected | Low |
| Проверка пройдена, или посетитель уже прошёл её раньше | Allowed | `passed-challenge` | Нет | Informational |
| Записал в журнал и пропустил | Logged | `logged` | Код состояния источника | Medium; High, когда источник дал сбой; Low, когда он отклонил запрос |
| Пропустил по вашему правилу skip или allow | Allowed | `let-through` | Код состояния источника | Как для записанного запроса |

Запрос, который пропустило одно из ваших правил skip или allow, импортируется, только если он несёт атаку (SQL-инъекцию, обход каталогов или поиск Log4Shell) или WAF attack score Cloudflare считает его атакой. Остальное — трафик, который вы разрешаете намеренно, например ваши мониторы: каждый запуск считает его и не импортирует.

Cloudflare делает выборку событий загруженной зоны. Каждое событие хранит свой интервал выборки — число похожих запросов, которые оно представляет, — и каждое число, которое OneUptime из них получает, идёт со словом *около*.

События видны в разделе событий, в кампаниях (атакующие запросы по адресам), в риске сущностей и в правилах обнаружения. Кейс по адресу показывает в разделе **На периметре** своих последствий, что Cloudflare сделал с запросами адреса, рядом с тем, что дошло до вашего приложения. Правила Cloudflare из библиотеки правил читают их в том виде, в каком они импортируются здесь: много срабатываний управляемых правил с одного адреса, адрес, который прошёл проверку и затем отправил атаки, и атака, которую Cloudflare пропустил и которая дошла до вашего приложения.

## Ограничения тарифов

На каждом тарифе события межсетевого экрана доступны через API. **What each zone's plan gives** в **Проверить подключение** читает у Cloudflare собственные ограничения каждой зоны.

| Тариф | Free | Pro | Business | Enterprise |
| --- | --- | --- | --- | --- |
| Хранение событий межсетевого экрана | 31 день | 31 день | 31 день | 31 день |
| Самый длинный запрос | 30 дней | 30 дней | 30 дней | 31 день |

Logpush от Cloudflare тоже может отправлять события межсетевого экрана — на каждом тарифе с 30 сентября 2026 года, с оплатой по использованию. Это подключение вместо этого опрашивает, поэтому ему не нужно ничего, кроме двух прав на чтение.

## Как работает опрос

- **События читаются по времени, когда они произошли на периметре.** Аналитику Cloudflare можно запросить через минуту-две после запроса.
- **Первый опрос смотрит на 24 часа назад**, чтобы новое подключение сразу показало свои недавние события.
- **Каждый следующий опрос начинается за 10 минут до сохранённого курсора**, поэтому событие, которое Cloudflare делает доступным с опозданием, читается следующим опросом, а дубликаты отбрасываются по Ray ID каждого события в пределах проекта.
- **Опрос читает не больше 24 часов после курсора.** Подключение, курсор которого отстал, догоняет серией 24-часовых окон.
- **Зоны читаются по очереди**, по странице до 2 000 событий каждая, поэтому загруженная зона не может исчерпать опрос до того, как прочитана спокойная.
- **Ограничения частоты Cloudflare соблюдаются.** Cloudflare разрешает 1 200 запросов REST и 300 запросов GraphQL за пять минут. Ответ `429`, который просит подождать 30 секунд или меньше, выжидается и повторяется; более долгий останавливает опрос, а следующий продолжает.
- **Зона, которую токен не может читать, ничего не задерживает.** Остальные зоны импортируются, запуск — **Частично**, и его предупреждение называет зону. Дайте токену там `Zone > Analytics > Read`, затем используйте **Импортировать этот диапазон**, чтобы восстановить окно.
- **Неудачный запуск ничего не меняет.** После сетевой ошибки или статуса ошибки от Cloudflare курсор и длина окна остаются прежними, и следующий опрос снова читает то же окно. Единственное исключение — запрос, превысивший время ожидания: курсор остаётся, но следующее окно вдвое короче, так как окно, слишком тяжёлое для ответа вовремя, превышало бы время ожидания при каждой попытке.

### Когда окно содержит больше, чем может прочитать один опрос

Опрос отправляет не больше 120 запросов, читает не больше 20 000 событий и останавливается через 4 минуты. События читаются начиная с самых старых, поэтому когда бюджет останавливает опрос, запуск — **Частично**, а следующий опрос продолжает с самого старого события, до которого были прочитаны незавершённые зоны. Когда не каждую зону удалось прочитать хотя бы раз, OneUptime вместо этого сокращает окно:

1. **Сузить.** Следующий опрос читает вдвое более короткое окно от той же точки и снова сокращает его вдвое, пока окно не будет прочитано полностью, вплоть до одной минуты. Предупреждение запуска говорит об этом: `This window holds more records than one poll can read; the next poll reads a {n} minute window from the same starting point.` События, уже импортированные из более длинного окна, пропускаются как дубликаты.
2. **Снова расти.** После того как окно прочитано целиком, курсор переносится на его конец, а следующее окно снова вдвое длиннее, до 24 часов.
3. **Пройти мимо одной минуты.** Если даже одна минута содержит больше, чем может прочитать опрос, опрос проходит мимо неё, чтобы новые события продолжали поступать. Запуск остаётся **Частично**, а **Последняя ошибка** гласит `More records were created in the one minute from {cursor} to {end} than one poll can read. Polling moved past this minute so newer records keep arriving; use Import this time range in Diagnostics on this minute to recover what one run can read.` Импортируйте эту минуту через **Импортировать этот диапазон**, чтобы восстановить то, что может прочитать один запуск.

Изменение **Интервал опроса (минуты)** ничего из этого не меняет: оно определяет, как часто начинается опрос, а не где начинается его окно.

### Запуск, просмотр и импорт по требованию

Нажмите **Диагностика** в подключении, чтобы увидеть его последние запуски и работать с ним вручную. Запускать эти действия может любой, кто может менять подключение; читать историю может любой, кто может его видеть.

- **Запустить сейчас** сразу запускает опрос с обычным курсором, даже если подключение не **Включено**.
- **Предпросмотр: события межсетевого экрана** читает диапазон времени до 7 дней и ничего не импортирует.
- **Импортировать этот диапазон** импортирует диапазон до 7 дней после вашего подтверждения, не сдвигая курсор. Уже импортированные события пропускаются. Cloudflare хранит события межсетевого экрана 31 день.
- **Скопировать диагностику** в запуске копирует его отчёт для поддержки. Он никогда не содержит учётных данных.

## Проверка подключения

**Проверить подключение** в строке подключения и **Проверить эти настройки** в форме выполняются в процессе API, а не в фоновом worker, поэтому проверка отвечает даже тогда, когда проблема в самих worker. Она выполняет такие проверки по порядку:

| Проверка | Что она проверяет |
| --- | --- |
| **Конфигурация** | Токен, аккаунт и зоны правильно оформлены. Если эта проверка не пройдена, ни к чему не обращаются. |
| **Verify the API token** | Cloudflare принимает токен — пользователя или принадлежащий аккаунту — и он активен. Токен, срок которого истекает в течение 14 дней, — предупреждение. |
| **List the zones** | У токена есть `Zone > Zone > Read`: он перечисляет зоны аккаунта и каждую выбранную зону. |
| **Read firewall events** | У токена есть `Zone > Analytics > Read` в каждой зоне. Сбой называет зоны, где этого права нет. |
| **What each zone's plan gives** | Как долго тариф каждой зоны хранит события межсетевого экрана и какой длины может быть один запрос. Зона, у тарифа которой их нет, — предупреждение. |
| **Firewall events available to import** | Около скольких событий за последние 24 часа и за последние 7 дней. Ни одного — предупреждение. |
| **Background workers**, **Poll scheduler**, **Security event storage** | Сторона самого OneUptime: процесс забирает задания из очереди Worker, задание опроса выполняется каждую минуту, а хранилище событий безопасности отвечает. |
| **Запланированный опрос** | Для сохранённого подключения: опрос включён, ни один запуск не застрял в ожидании worker, а опросы выполняются вовремя. |

У каждого запроса в проверке срок 20 секунд. Проверка никогда ничего не импортирует и не перемещает курсор, а каждая неудачная проверка сообщает, что нужно изменить.

## Устранение неполадок

**Последняя ошибка** подключения хранит полное сообщение об ошибке со скрытыми учётными данными. Если у подключения есть ошибка, выберите **Просмотреть ошибку** в его столбце **Действия**, чтобы прочитать её, и **Скопировать ошибку** в диалоге, чтобы скопировать её. Каждое сообщение называет запрос, который не удался, и цитирует причину от Cloudflare.

:::details Последняя ошибка гласит `Invalid API Token (1000)`
Cloudflare не знает этот токен: его удалили, перевыпустили или вставили не полностью. Global API Key отклоняется до отправки. Создайте токен, как описано выше, и сохраните его через **Обновить учётные данные**.
:::

:::details Последняя ошибка гласит `Unauthorized to access requested resource (9109)`
Токен не может перечислить зоны. Дайте ему `Zone > Zone > Read` с зонами для импорта в разделе **Zone Resources**.
:::

:::details Последняя ошибка гласит `cannot read the analytics of`
Токену не хватает `Zone > Analytics > Read` в зонах, которые называет сообщение. Добавьте его там, затем используйте **Импортировать этот диапазон**, чтобы восстановить то, что не было импортировано.
:::

:::details Последняя ошибка гласит `rate limit`
Что-то ещё, что использует того же пользователя Cloudflare, исчерпало его квоту. Опрос продолжится сам, когда пройдут пять минут; дайте OneUptime токен отдельного пользователя, чтобы разделить квоту.
:::

:::details Последняя ошибка сообщает `did not complete`
Запрос не получил ответа: истекло время ожидания, имя не разрешается или адрес отклонён. Проверьте, что приложение и воркеры OneUptime могут достучаться до `api.cloudflare.com` через любой используемый вами прокси.
:::

:::details Кейс показывает действия Cloudflare, но ни одного запроса адреса в вашем приложении
За Cloudflare ваше приложение видит адреса Cloudflare, если не читает адрес посетителя из заголовка `CF-Connecting-IP`. Записывайте этот адрес в журналы и трассировки как `client.address`, чтобы OneUptime мог сопоставить запросы вашего приложения с адресом, на который отреагировал Cloudflare.
:::

:::details Проверка проходит, но Last Polled — Never
Задание опроса ни разу не выполнялось. Прочитайте проверки **Background workers** и **Poll scheduler**. В самостоятельно размещённой установке обычная причина — `DISABLE_QUEUE_WORKERS=true` в приложении без отдельного развёртывания worker, которое забирало бы задания: установите `false` или запустите развёртывание worker (Helm: `worker.enabled: true`, по умолчанию `false`).
:::
