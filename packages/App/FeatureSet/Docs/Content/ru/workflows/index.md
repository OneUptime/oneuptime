# Обзор рабочих процессов

Рабочие процессы позволяют автоматизировать задачи в OneUptime, не написав ни строчки кода. Выложите несколько блоков на холст, соедините их между собой — и у вас готова автоматизация, которая срабатывает, как только что-то происходит: открывается инцидент, наступает время по расписанию или другой инструмент присылает данные в OneUptime.

Считайте рабочие процессы фоновыми помощниками вашего проекта: они реагируют на события, общаются с другими инструментами и тихо держат всё в согласованном состоянии, пока вы заняты своим делом.

## Что можно делать с помощью рабочих процессов

- **Связать OneUptime с остальными вашими инструментами** — отправлять инциденты в Slack, заводить тикеты в Jira, слать данные в webhook внутри вашего стека.
- **Реагировать на то, что происходит в OneUptime** — при создании критического инцидента автоматически уведомить дежурную команду и открыть тикет.
- **Запускать задачи по расписанию** — каждые пять минут, каждую ночь, каждое утро понедельника.
- **Принимать данные извне** — разрешить другим системам присылать данные в OneUptime по уникальному URL.
- **Переиспользовать типовую автоматизацию** — собрать один раз и вызывать из любого другого рабочего процесса.

## Как устроен рабочий процесс

У каждого рабочего процесса три части:

1. **Триггер** — то, что его запускает. Это может быть кнопка ручного запуска, расписание, входящий webhook или событие в OneUptime (например, новый инцидент).
2. **Один или несколько компонентов** — то, что рабочий процесс делает. Отправить сообщение, сделать HTTP-вызов, выполнить быструю проверку, разветвиться по условию.
3. **Связи между ними** — вы проводите линии от одного блока к следующему и тем самым задаёте порядок.

Всё это вы собираете визуально, на холсте. Для большинства рабочих процессов код не нужен вовсе — но когда он всё же нужен, можно добавить фрагмент JavaScript.

## Ключевые термины

| Термин                     | Что это значит                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Рабочий процесс**        | Вся автоматизация целиком — имя, холст и переключатель, который её включает и выключает.               |
| **Триггер**                | Первый блок. Он решает, когда рабочий процесс запускается. У каждого рабочего процесса ровно один триггер. |
| **Компонент**              | Блок-действие: отправляет сообщение, делает запрос, проверяет условие.                                  |
| **Запуск**                 | Одно выполнение рабочего процесса. Сохраняется с отметками времени и выводом каждого блока.             |
| **Глобальная переменная**  | Значение (например, ключ API), которое вы сохраняете один раз и переиспользуете в любом рабочем процессе. |

## Где искать рабочие процессы в OneUptime

Откройте **Рабочие процессы** в левой навигации. В этом разделе лежат:

- **Рабочие процессы** — список ваших рабочих процессов. Создайте новый или откройте существующий.
- **Глобальные переменные** — значения, общие для всех ваших рабочих процессов.
- **Запуски и журналы** — история выполнения по всем рабочим процессам проекта.

Откройте отдельный рабочий процесс — и в его собственном левом меню будут:

- **Обзор** — имя, описание, метки и переключатель **Включено**.
- **Конструктор** — холст, на котором вы проектируете рабочий процесс.
- **Переменные рабочих процессов** — значения в пределах этого одного рабочего процесса.
- **Запуски и журналы** — каждый запуск этого рабочего процесса, с подробностями.
- **Настройки** — секретный ключ вебхука, дублирование и экспорт.

## Собираем первый рабочий процесс

1. **Создайте** — выберите отправную точку и дайте рабочему процессу имя.
2. **Выберите триггер** — ручной, по расписанию, webhook или событие из OneUptime.
3. **Добавьте компоненты** — выложите действия на холст и соедините их.
4. **Включите его** — переведите **Включено** во включённое положение на странице **Обзор**. Отключённый рабочий процесс не запустится вообще, даже вручную.
5. **Проверьте** — нажмите **Запустить рабочий процесс** на странице **Конструктор** и посмотрите журнал запуска.

## Короткий пример

Допустим, вы хотите писать в Slack каждый раз, когда создан критический инцидент:

1. Создайте рабочий процесс с именем «Критические инциденты в Slack».
2. Выберите триггер **On Create Incident**.
3. Добавьте блок **If / Else**. Настройте его на проверку того, содержит ли заголовок инцидента «Sev 1».
4. От ветки **Yes** добавьте блок **Slack**. Выберите канал и напишите текст сообщения.
5. Включите рабочий процесс.

В следующий раз, когда кто-нибудь заведёт инцидент со словами «Sev 1» в заголовке, Slack оживёт.

## Как рабочие процессы связаны с остальным OneUptime

- **Мониторы** замечают проблему. **Инциденты** её фиксируют. **Рабочие процессы** на неё реагируют.
- **Runbook-и** — это пошаговые инструкции для людей. Рабочие процессы — это автоматизация без участия человека. Берите runbook, когда решение должен принимать человек; берите рабочий процесс, когда шаги выполняются сами.
- **Подключения рабочего пространства** (Slack, Teams) — это то, куда рабочие процессы отправляют свои сообщения.
