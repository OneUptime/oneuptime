# Секреты монитора

Для безопасного хранения конфиденциальных данных, используемых в проверках мониторинга, можно применять секреты. Секреты шифруются и хранятся в защищённом виде.

### Добавление секрета

Чтобы добавить секрет, перейдите в OneUptime Dashboard -> Мониторы -> Настройки -> Секреты -> Создать секрет монитора.

![Создание секрета](/docs/static/images/CreateMonitorSecret.png)

Задайте имя и значение секрета, затем на шаге **Доступ** выберите, какие мониторы могут его использовать. В этом примере мы добавили секрет `ApiKey`.

**Обратите внимание**: секреты шифруются и хранятся безопасно. После сохранения значение больше не показывается — ни в таблице, ни в форме редактирования, ни через API. Если вы потеряли значение, получите его из исходного источника и задайте заново. Чтобы обновить секрет, используйте кнопку **Обновить значение секрета** в его строке; удалять и создавать заново не нужно.

### Выбор мониторов, которые могут использовать секрет

У каждого секрета один из трёх вариантов доступа:

- **Все мониторы**: любой монитор проекта может использовать секрет, включая мониторы, которые вы создадите позже. Подходит для учётных данных, которые используют многие мониторы.
- **Определённые мониторы**: секрет могут использовать только выбранные вами мониторы. Это вариант по умолчанию; так же работают секреты, созданные до появления этих вариантов.
- **Мониторы с метками**: секрет могут использовать мониторы, у которых есть хотя бы одна из выбранных меток. Если добавить одну из этих меток монитору, он получит доступ, а если убрать метку, монитор потеряет доступ при следующем запуске.

Вариант можно изменить в любой момент с помощью кнопки **Редактировать** в строке секрета. Сохраняется только список выбранного варианта: при переходе на **Все мониторы** списки мониторов и меток секрета очищаются, а при переключении между **Определённые мониторы** и **Мониторы с метками** очищается список, который вы перестаёте использовать.

Секрет никогда не доступен мониторам другого проекта.

Любой, кто может редактировать монитор с доступом к секрету, может отправить этот секрет на любой адрес, к которому подключается монитор. При варианте **Все мониторы** это любой, кто может создавать или редактировать мониторы в проекте. При варианте **Мониторы с метками** — также любой, кто может добавить монитору одну из этих меток.

В API вариант доступа задаётся полем `monitorAccess`: `All Monitors`, `Specific Monitors` или `Monitors With Labels`. Поля `monitors` и `labels` содержат списки. Секрет, созданный без `monitorAccess`, получает `Specific Monitors`.

### Использование секрета

Секреты можно использовать в следующих типах мониторинга:

- API (в заголовках запроса, теле запроса и URL)
- Сайт, IP, Порт, Ping, SSL-сертификат (в URL)
- Синтетический монитор, Монитор пользовательского кода (в коде)
- SNMP-монитор (в строке сообщества, ключе аутентификации и ключе шифрования SNMPv3)

![Использование секрета](/docs/static/images/UsingMonitorSecret.png)

Для использования секрета добавьте `{{monitorSecrets.SECRET_NAME}}` в поле, где требуется использовать секрет. Например, в данном случае мы добавили `{{monitorSecrets.ApiKey}}` в поле «Заголовки запроса».

Секреты внедряются в зонд до выполнения скриптов синтетического монитора или монитора пользовательского кода, поэтому ссылки вида `{{monitorSecrets.ApiKey}}` разрешаются в расшифрованное значение внутри выполняемого скрипта.

Если монитор ссылается на секрет, который ему недоступен, ссылка остаётся как есть и не заменяется значением.

Когда вы тестируете монитор до сохранения, подставляются только секреты с вариантом **Все мониторы**, потому что новый монитор не входит ни в один список и ещё не имеет меток. После сохранения монитора тесты используют все секреты, доступные этому монитору.
