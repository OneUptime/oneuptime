# Шаблоны мониторов

Шаблон монитора — это сохранённая конфигурация монитора (тип, критерии, интервал, метки и значения пользовательских полей по умолчанию), из которой мониторы создаются одним щелчком. Мониторы, созданные из шаблона или связанные с ним, остаются связанными: измените шаблон, а затем синхронизируйте изменение со всеми. Используйте шаблоны, когда многие мониторы должны вести себя одинаково, например одна и та же проверка работоспособности на каждом сервисе или одни и те же проверки API в продакшене и на staging.

:::cards
- [Создать шаблон](#создание-шаблона): Четыре шага, как в «Создать монитор».
- [Создать из него мониторы](#создание-мониторов-из-шаблона): Один щелчок, или свяжите мониторы, которые у вас уже есть.
- [Синхронизировать изменения](#синхронизация-изменений-со-связанными-мониторами): Что копирует каждая кнопка синхронизации.
- [Перенести мониторы в другой шаблон](#перенос-мониторов-в-другой-шаблон): Более подходящий шаблон, и каждый монитор сохраняет свою историю.
- [Сохранить значения каждого монитора](#сохранение-значений-каждого-монитора): Защитить адрес назначения или заголовки от синхронизации.
:::

## Как работают шаблоны

Шаблон сам ничего не отслеживает. Мониторы создаются из него или связываются с ним, а страница шаблона показывает их как **Связанные мониторы**. Когда вы меняете шаблон, на этих мониторах ничего не меняется, пока вы не выполните синхронизацию: каждая кнопка синхронизации копирует одну часть шаблона на каждый связанный монитор, а защищённые поля сохраняют собственное значение каждого монитора.

## Перед началом

- **Роль, которая может создавать шаблоны**: Владелец проекта, Администратор проекта, Участник проекта, Администратор мониторов или Участник мониторов либо пользовательская роль с разрешением Create Monitor Template. Для изменения шаблона нужны те же роли или разрешение Edit Monitor Template.
- **Разрешение на обновление связанных мониторов.** Синхронизация записывает изменения в каждый связанный монитор от вашего имени и пропускает мониторы, на которые не распространяются ваши разрешения.

## Создание шаблона

:::steps
### Откройте шаблоны

Перейдите в **Мониторы → Настройки → Шаблоны** и нажмите **Создать: Шаблон монитора**.

### Назовите шаблон

В разделе **Информация о шаблоне** введите **Название шаблона**, например `Production API Health`. **Описание шаблона** необязательно. Затем нажмите **Далее**.

### Задайте значения монитора по умолчанию

В разделе **Значения монитора по умолчанию** выберите **Тип монитора** с помощью того же выбора, что и в «Создать монитор». При желании введите **Название монитора по умолчанию**; если оставить его пустым, каждый монитор получит имя ресурса, который он отслеживает. **Описание монитора по умолчанию** и **Метки** ждут в разделе **Дополнительные поля**. Нажмите **Далее**.

### Задайте критерии и интервал

В разделе **Критерии** укажите, что проверять, и критерии, как в [Создать монитор](/docs/monitor/create-monitor#критерии). Карточка **Настройки синхронизации шаблона** вверху позволяет защитить поля от синхронизации (см. [Сохранить значения каждого монитора](#сохранение-значений-каждого-монитора)). Для типа монитора, который проверяют зонды, последний шаг, **Интервал**, запрашивает **Интервал мониторинга**. Нажмите **Создать: Шаблон монитора** на последнем шаге.
:::

Шаблон добавляется в список. Откройте его, чтобы увидеть страницу с карточкой для каждой части: **Информация о шаблоне**, **Значения монитора по умолчанию**, **Критерии**, **Интервал мониторинга** (с **Минимальное согласие зондов**), **Метки**, **Значения пользовательских полей по умолчанию** (если в проекте есть пользовательские поля мониторов) и **Связанные мониторы**. Каждую часть вы меняете в её собственной карточке, например через **Редактировать критерии** или **Редактировать интервал**.

## Создание мониторов из шаблона

- **Новый монитор.** Нажмите **Создать монитор** в строке шаблона в списке или **Создать монитор из шаблона** на его странице. **Создать монитор** откроется с уже заполненными типом и настройками шаблона; измените то, что нужно, и создайте монитор. Новый монитор будет связан с шаблоном.
- **Мониторы, которые у вас уже есть.** В разделе **Связанные мониторы** нажмите **Связать существующие мониторы** и выберите их. Если **Использовать критерии и интервал шаблона** включено, при связывании они получают критерии, интервал и согласие зондов шаблона; если выключено, они сохраняют свои настройки до синхронизации. Монитор, связанный с другим шаблоном, переходит к этому.

Значения, заданные в **Значения пользовательских полей по умолчанию**, записываются в каждый монитор, созданный из шаблона, включая мониторы, которые создают из него правила автоматического импорта и политики оповещений.

## Синхронизация изменений со связанными мониторами

Редактирование шаблона меняет только шаблон. Чтобы скопировать изменение на связанные мониторы, используйте кнопку синхронизации на карточке, которую вы изменили. Каждая кнопка показывает, сколько мониторов она затронет, например **Синхронизировать критерии со связанными мониторами (3)**, и неактивна, пока ничего не связано. Синхронизацию нельзя отменить.

| Кнопка | Копирует на каждый связанный монитор | Не трогает |
| --- | --- | --- |
| **Синхронизировать критерии со связанными мониторами** | Критерии и настройки шага, например адреса назначения и параметры запроса, кроме защищённых полей | Интервал мониторинга, минимальное согласие зондов, имя, описание, метки и значения пользовательских полей |
| **Синхронизировать интервал со связанными мониторами** | Интервал мониторинга и минимальное согласие зондов | Критерии, имя, описание, метки и значения пользовательских полей |
| **Синхронизировать метки со связанными мониторами** | Метки, и ничего больше | Всё остальное |
| **Синхронизировать пользовательские поля со связанными мониторами** | Пользовательские поля, для которых в шаблоне задано значение по умолчанию, вместо того, что было у каждого монитора | Пользовательские поля, которые шаблон оставляет пустыми, и всё остальное |

Чтобы синхронизировать один монитор, нажмите **Синхронизировать из шаблона** в его строке в разделе **Связанные мониторы**. Это копирует критерии и настройки шага (кроме защищённых полей), интервал мониторинга, минимальное согласие зондов и метки, а имя, описание и значения пользовательских полей монитора не трогает. Чтобы отсоединить монитор, см. [Отвязка мониторов от шаблона](#отвязка-мониторов-от-шаблона).

После синхронизации сводка показывает, сколько мониторов обновлено. **Синхронизировано частично** означает, что у некоторых связанных мониторов осталась прежняя конфигурация, обычно потому, что на них не распространяются ваши разрешения.

## Перенос мониторов в другой шаблон

Когда шаблон заменяется более подходящим, перенесите его мониторы в новый шаблон, а не удаляйте их. Каждый монитор сохраняет имя, историю статуса, метки, владельцев и инциденты и получает критерии нового шаблона.

:::steps
### Выберите мониторы

Откройте шаблон, с которым они сейчас связаны. В разделе **Связанные мониторы** выберите нужные мониторы или все сразу. Мониторы можно выбрать и в списке мониторов, отфильтровав его по любому столбцу.

### Перенесите их

В меню **Массовые действия** нажмите **Перенести в другой шаблон** (в списке мониторов — **Связать с шаблоном**). Выберите шаблон.

### Оставьте настройки шаблона включёнными

Оставьте **Использовать критерии и интервал шаблона** включённым, чтобы каждый монитор сразу получил критерии, настройки шага, интервал и согласие зондов шаблона. Если выключить, каждый монитор сохранит свои до синхронизации. Затем подтвердите.
:::

Что делает перенос:

- Критерии, интервал и согласие зондов мониторов заменяются заданными в шаблоне. Открытый инцидент или оповещение, для которых старые критерии настроили автоматическое устранение, устраняются, а новые критерии откроют новые, если проблема сохраняется. Каждый монитор сетевого устройства продолжает следить за своим устройством, а каждый монитор адреса или URL продолжает проверять адрес своего устройства.
- Имена, описания, история статуса, метки, владельцы, значения пользовательских полей и связи с инцидентами остаются прежними.
- Монитор, созданный импортом, правилом автоимпорта или сетевой политикой оповещений, сохраняет шаблон, из которого он был создан. Это правило больше никогда не создаёт его заново, а политика оповещений отпускает его: она больше не удаляет и не заменяет его.
- У устройства есть по одному монитору от каждого шаблона. Если у устройства уже есть монитор, созданный для него из нового шаблона, другой его монитор пропускается, и изменение называет мешающий монитор: удалите один из двух, затем повторите перенос.
- Монитор другого типа, чем у шаблона, пропускается.

Изменение выполняется на сервере, до 10 000 мониторов за раз, и показывает ход выполнения: что перенесено, что пропущено и почему, а также открытые инциденты и оповещения, которые оно устранило. Закрытие окна его не останавливает, а страница шаблона показывает изменение, которое ещё выполняется. **Остановить** останавливает его перед следующим монитором, а **Повторить** заново обрабатывает мониторы, на которых произошла ошибка или до которых изменение не дошло.

> [!TIP]
> Переносите устройства правила автоимпорта на новый шаблон? Сначала перенесите мониторы, затем укажите в правиле новый шаблон. В обратном порядке правило даст каждому устройству второй монитор, из нового шаблона, рядом с уже имеющимся.

## Отвязка мониторов от шаблона

Нажмите **Отвязать от шаблона** в строке монитора в разделе **Связанные мониторы** или выберите мониторы там либо в списке мониторов и используйте **Отвязать от шаблона** в меню **Массовые действия**. Выберите, что сохранят мониторы:

| Вариант | Что мониторы делают после этого |
| --- | --- |
| **Сохранить их настройки** | Они продолжают проверять и отправлять оповещения по критериям, которые у них есть сейчас, как самостоятельные мониторы, и больше не получают обновлений шаблона. |
| **Удалить из них критерии шаблона** | Они продолжают проверять, но не создают инцидентов и оповещений и не задают статус, пока вы снова не свяжете их с шаблоном. Открытый инцидент или оповещение, для которых их критерии настроили автоматическое устранение, устраняются. |

В обоих случаях они сохраняют имена, историю статуса, метки, владельцев и инциденты, а правило, которое их создало, больше никогда не создаёт их заново.

## Удаление шаблона

Шаблон, из которого сетевая политика оповещений или правило автоимпорта создают мониторы, удалить нельзя: сначала укажите в политике или правиле другой шаблон. Если с шаблоном связаны мониторы, при удалении спрашивается, что с ними будет:

- **Сохранить их настройки** (по умолчанию): удаление отвязывает их, и они продолжают проверять и отправлять оповещения по своим критериям.
- **Удалить из них критерии этого шаблона**: каждый отвязывается с удалением критериев, как описано выше, а затем шаблон удаляется. Если какой-то монитор остаётся связанным, например тот, на который не распространяются ваши разрешения, шаблон сохраняется, и окно сообщает, сколько их.

Чтобы вместо этого перенести мониторы в другой шаблон, используйте **Перенести в другой шаблон** до удаления.

## Сохранение значений каждого монитора

Синхронизация критериев копирует и настройки шага, например адреса назначения, заголовки запроса и тайм-ауты, если вы не защитите эти поля. Защитите поле, чтобы каждый связанный монитор сохранил своё собственное значение.

:::steps
### Откройте шаблон

Перейдите в **Мониторы → Настройки → Шаблоны** и откройте шаблон.

### Измените его критерии

На карточке **Критерии** нажмите **Редактировать критерии**.

### Защитите поля

В разделе **Настройки синхронизации шаблона** отметьте **Не синхронизировать это поле** рядом с каждым полем, которое нужно сохранить на связанных мониторах.

### Сохраните

Сохраните изменения. Карточка **Критерии** и подтверждение обеих синхронизаций ниже перечисляют защищённые поля.

### Синхронизируйте

Используйте **Синхронизировать критерии со связанными мониторами** или **Синхронизировать из шаблона** на отдельном связанном мониторе.
:::

Например, защитите **Цель монитора** и **Заголовки запроса** в шаблоне API. Мониторы продакшена и staging сохранят свои URL и заголовки, а оба получат обновлённые критерии шаблона и другие незащищённые настройки.

Доступные параметры зависят от типа монитора. Среди них адреса назначения и порты, параметры HTTP-запросов, подключения к базам данных, настройки DNS, селекторы инфраструктуры и запросы телеметрии. Связанные учётные данные, например клиентский сертификат и его закрытый ключ, сохраняются вместе.

### Как работают исключения

- Отмеченные поля сохраняют текущее значение каждого существующего монитора, включая пустое или незаданное значение. Заголовки запроса и другие коллекции сохраняются целиком.
- Неотмеченные поля по-прежнему синхронизируются из шаблона. Снимите отметку с защищённого поля и сохраните, чтобы при следующей синхронизации скопировать его значение из шаблона.
- Исключения действуют для массовой и одиночной синхронизации. Они хранятся в шаблоне, а не выбираются отдельно для каждой синхронизации.
- Новые мониторы по-прежнему начинают со значений полей шаблона. Исключения влияют только на синхронизацию существующих мониторов.
- Критерии синхронизируются всегда. Синхронизация только критериев не трогает интервал мониторинга, метки и другие настройки уровня монитора.
- У существующих шаблонов нет исключений полей, пока вы их не настроите. Мониторы сетевых устройств по-прежнему автоматически сохраняют собственную привязку к устройству, а мониторы Ping, IP, Port и NTP, созданные для устройств импортом сетевого обнаружения, продолжают проверять собственный адрес каждого устройства. Созданные этим импортом мониторы Веб-сайт, API и SSL-сертификат сохраняют адрес каждого устройства в качестве хоста своего URL и берут из шаблона схему, порт и путь.

Для шаблонов с несколькими шагами защищённые значения сопоставляются по ID шагов. Независимо созданные мониторы с одним шагом тоже могут получать шаблон с одним шагом. Если защищённый шаг сопоставить нельзя, синхронизация отклоняется до обновления какого-либо монитора, чтобы новый или переупорядоченный шаг не мог случайно скопировать адрес назначения или учётные данные другого шага.

> [!IMPORTANT]
> Прежде чем менять тип монитора сохранённого шаблона (через **Редактировать значения монитора по умолчанию**), удалите в **Редактировать критерии** исключения, которые не относятся к новому типу. Все исключения шаблона должны существовать для его типа монитора.

## Настройка через API

Каждый шаг шаблона принимает массив `doNotSyncFields` в своём объекте `MonitorStep.value`. Для монитора API защитите его адрес назначения и всю коллекцию заголовков так:

```json title="monitorSteps (excerpt)"
{
  "_type": "MonitorSteps",
  "value": {
    "monitorStepsInstanceArray": [
      {
        "_type": "MonitorStep",
        "value": {
          "id": "<step id>",
          "doNotSyncFields": ["monitorDestination", "requestHeaders"]
        }
      }
    ]
  }
}
```

Не указывайте массив или задайте его как `[]`, чтобы синхронизировать все поддерживаемые настройки шага. Неподдерживаемые имена полей и поля, которые не относятся к типу монитора шаблона, отклоняются. Синхронизацией управляет массив шаблона; такие метаданные на связанном мониторе его не переопределяют.

:::details Имена полей для doNotSyncFields по типам мониторов
| Тип монитора | Имена полей |
| --- | --- |
| Веб-сайт, API, Ping, IP, Порт, SSL-сертификат, NTP | `monitorDestination`, `requestTimeoutInMs`, `retryCount` |
| Только API | `requestHeaders`, `requestType`, `requestBody` |
| Веб-сайт и API | `doNotFollowRedirects`, `allowSelfSignedCertificates`, `tlsClientAuthentication` (клиентский сертификат, ключ и парольная фраза вместе) |
| Порт, NTP | `monitorDestinationPort` |
| Синтетический монитор, Пользовательский код JavaScript | `customCode` |
| Синтетический монитор | `browserTypes`, `screenSizeTypes`, `retryCountOnError` |
| DNS | `dnsMonitor.queryName`, `dnsMonitor.recordType`, `dnsMonitor.resolver` (DNS-сервер и порт вместе), `dnsMonitor.timeout`, `dnsMonitor.retries` |
| Домен | `domainMonitor.domainName`, `domainMonitor.lookupMethod`, `domainMonitor.timeout`, `domainMonitor.retries` |
| DNSSEC | `dnssecMonitor.domainName`, `dnssecMonitor.resolvers`, `dnssecMonitor.checkNameserverConsistency`, `dnssecMonitor.signatureExpiryWarningDays`, `dnssecMonitor.timeout`, `dnssecMonitor.retries` |
| SQL-запрос | `sqlMonitor.connection`, `sqlMonitor.connectionTimeoutInMs`, `sqlMonitor.statementTimeoutInMs`, `sqlMonitor.query`, `sqlMonitor.maxRows` |
| Состояние базы данных | `databaseMonitor.connection`, `databaseMonitor.connectionTimeoutInMs`, `databaseMonitor.statementTimeoutInMs`, `databaseMonitor.enabledMetricGroups` |
| Внешняя страница статуса | `externalStatusPageMonitor.statusPageUrl`, `externalStatusPageMonitor.provider`, `externalStatusPageMonitor.components`, `externalStatusPageMonitor.timeout`, `externalStatusPageMonitor.retries` |
| Журналы, События безопасности, Трассировки, ИИ / LLM, Метрики, Исключения, Профили | `logMonitor`, `securityEventsMonitor`, `traceMonitor`, `llmMonitor`, `metricMonitor`, `exceptionMonitor`, `profileMonitor` (вся конфигурация монитора) |
| Статус зонда | `probeStatusMonitor.probeIds` |

Мониторы инфраструктуры (Kubernetes, Контейнер Docker, Хост, Контейнер Podman, Proxmox, Docker Swarm, Ceph, Система хранения, IoT-устройство) предлагают свой селектор ресурсов, фильтры (все, кроме Хоста), запросы метрик и временное окно запроса. Их имена перечислены в **Настройки синхронизации шаблона** в шаблоне этого типа.
:::

## Устранение неполадок

:::details Синхронизация сообщает «Синхронизировано частично»
Некоторые связанные мониторы не были обновлены, обычно потому, что на них не распространяются ваши разрешения. Попросите того, кто может обновлять все связанные мониторы, снова запустить синхронизацию.
:::

:::details Синхронизация завершается ошибкой «a template step cannot be matched to an existing monitor step»
Защищённое поле не удалось сопоставить с шагом одного из мониторов, поэтому синхронизация остановилась до изменения любого из них. Дайте шагам шаблона те же ID, что и шагам мониторов, или используйте шаблон с одним шагом для мониторов с одним шагом.
:::

:::details Кнопки синхронизации неактивны
С шаблоном ещё не связан ни один монитор. Создайте монитор из шаблона или нажмите **Связать существующие мониторы** в разделе **Связанные мониторы**.
:::

:::details Перенос пропускает монитор: «У устройства, для которого создан этот монитор, уже есть монитор, связанный с этим шаблоном»
У устройства есть монитор, созданный для него из шаблона, в который вы переносите, обычно потому, что правило автоимпорта указали на этот шаблон до переноса. Удалите ненужный (у более нового меньше всего истории), затем повторите перенос.
:::

:::details После перевода правила автоимпорта на новый шаблон у устройств по два монитора
Правило дало каждому устройству монитор нового шаблона рядом с прежним. Удалите новые мониторы, затем перенесите старые в новый шаблон: они сохранят свою историю, а правило больше не создаст ни одного.
:::

:::details Сохранение завершается ошибкой «Unsupported do not sync field»
Имя в `doNotSyncFields` не является полем типа монитора шаблона. Сверьте его с именами полей выше.
:::
