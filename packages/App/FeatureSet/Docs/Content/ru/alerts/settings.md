# Правила и настройки оповещений

Настройка оповещений находится внутри **Оповещения**, а не в **Настройки проекта**: правила, действующие на каждое новое оповещение, и настройки, определяющие каждое оповещение в проекте. Эта страница — справочник по каждому из них и по тому, что запускается само при создании оповещения.

:::cards
- [Правила, через которые проходит новое оповещение](#правила-через-которые-проходит-новое-оповещение): По порядку и что делает каждое.
- [Правила дежурства](#правила-дежурства): Вызывайте нужных людей, не выбирая политику каждый раз.
- [Правила напоминаний](#правила-напоминаний): Напоминайте владельцам, пока оповещение остаётся открытым.
- [Настройки](#настройки): Шаблоны заметок, пользовательские поля, измерения, участие в эпизодах и нумерация.
:::

## Где находятся настройки оповещений

Откройте **Оповещения** из меню **Продукты** в верхней панели. Разделы **Правила** и **Настройки** в его боковом меню сначала свёрнуты, поэтому сначала раскройте их. Каждая страница здесь действует на весь проект, по адресам, начинающимся с `/dashboard/{projectId}/alerts/settings/`.

| Страница правил                 | Что она делает                                                                                 |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| **Правила группировки**         | Объединяет связанные оповещения в эпизоды. См. [Эпизоды оповещений и правила группировки](/docs/alerts/episodes). |
| **Правила дежурства**           | Запускает политики дежурства для совпавших оповещений и эпизодов.                              |
| **Правила владельца**           | Добавляет владельцев к совпавшим оповещениям и эпизодам.                                       |
| **Правила runbook-ов**          | Запускает runbook-и для совпавших оповещений.                                                  |
| **Правила конфиденциальности**  | Делает совпавшие оповещения и эпизоды приватными.                                              |
| **Правила меток**               | Добавляет метки к совпавшим оповещениям и эпизодам.                                            |
| **Reminder Rules**              | Напоминает владельцам с заданным интервалом, пока оповещение открыто.                          |

Раздел **Настройки** содержит **Состояние оповещения** и **Серьёзность оповещения**, описанные на странице [Состояния и уровни серьёзности оповещений](/docs/alerts/states-and-severities), а затем **Шаблоны заметок**, **Пользовательские поля**, **Измерения**, **Участие в эпизодах** и **Нумерация**, описанные ниже.

Ещё два раздела действуют на оповещения. **Оповещения → ИИ → Настройки** определяет, что OneUptime AI делает сам: **Расследовать новые оповещения**, включено для новых проектов, и **Автоматически исправлять новые оповещения**, выключено, пока вы его не включите. См. [AI SRE](/docs/ai/ai-sre). **Оповещения → Рабочее пространство** содержит правила Slack и Microsoft Teams, которые публикуют оповещения и эпизоды в каналы, и свою вкладку **Summary**. См. [Slack](/docs/workspace-connections/slack).

## Правила, через которые проходит новое оповещение

```mermaid title="Правила, через которые проходит новое оповещение, по порядку"

    subgraph shape["Кто видит и владеет"]
        direction LR
        privacy["Правила<br/>конфиденциальности"] --> owner["Правила<br/>владельца"]
    end
    subgraph more["Что оно получает"]
        direction LR
        label["Правила<br/>меток"] --> oncall["Правила<br/>дежурства"]
    end
    subgraph page["Что оно запускает"]
        direction LR
        runbook["Правила<br/>runbook-ов"] --> execute["Политики<br/>выполняются"]
    end
    subgraph follow["Затем"]
        direction LR
        grouping["Правила<br/>группировки"] --> reminder["Правила<br/>напоминаний"]
    end
    shape --> more
    more --> page
    page --> follow
```

Правила различаются тем, как разрешаются несколько совпадений:

- **Правила группировки** и **Reminder Rules** проверяются сверху вниз по своему списку, и побеждает первое совпадение. Перетащите правило, чтобы изменить его место; новое правило попадает в конец.
- **Правила дежурства**, **Правила владельца**, **Правила меток**, **Правила конфиденциальности** и **Правила runbook-ов** действуют все, когда совпадают. Политики дежурства, владельцы и метки, которые добавляют несколько правил, добавляются один раз.

У **Правила дежурства**, **Правила владельца**, **Правила меток** и **Правила конфиденциальности** есть две вкладки: **Alert Rules** для оповещений и **Episode Rules**, которые так же действуют на каждый новый эпизод оповещений. Новое правило создаётся включённым; выключите **Включено** в его форме редактирования, чтобы приостановить его, а список показывает для каждого правила зелёное **Включено** или красное **Отключено**.

Большинство правил действует на оповещения и эпизоды, созданные после их сохранения. Чтобы применить правило владельца, меток или конфиденциальности к уже существующим, используйте **Run Now**: см. [Применение правил к существующим ресурсам](/docs/configuration/run-rules-now). Правила напоминаний — исключение: при сохранении такого правила заново сопоставляется каждое открытое оповещение.

### Условия

Условия правила определяют, на какие оповещения оно действует, и читаются как предложения: «Если **Заголовок оповещения** содержит `database`», «И **Метки монитора** содержит любое из *Production*». Правило без условий совпадает с каждым оповещением.

| Условие                                                       | С чем сравнивает                                                                                               |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Мониторы**, **Оповещение Серьёзности**, **Метки оповещений**, **Метки монитора** | **Содержит любое из**, **Содержит все из** или **Не содержит ни одного из** выбранных значений.      |
| **Заголовок оповещения**, **Описание оповещения**, **Имя монитора**, **Описание монитора** | **Содержит**, **Не содержит**, **Равно**, **Не равно**, **Начинается с**, **Заканчивается на** без учёта регистра или **Соответствует шаблону** и **Не соответствует шаблону** для регулярного выражения или подстановочного знака `*`. |

При двух и более условиях выберите **Соответствие всем**, где должно выполняться каждое, или **Соответствие любому**, где достаточно одного. Правила эпизодов вместо этого сопоставляют серьёзность, метки, заголовок и описание эпизода.

## Правила дежурства

**Оповещения → Правила → Правила дежурства** делает вызовы автоматическими. Каждое совпавшее правило добавляет свои политики к новому оповещению, и оповещение запускает их вместе с уже имевшимися политиками, каждую по одному разу.

:::steps
### Назовите правило

Нажмите **Создать: Alert On-Call Rule**. На шаге **Основная информация** задайте **Имя**, например «Вызывать команду базы данных при любом оповещении БД», и при желании **Описание**.

### Выберите оповещения

На шаге **Критерии совпадения** добавьте условия, которым должно соответствовать оповещение. Оставьте их пустыми, чтобы совпадало каждое новое оповещение.

### Выберите политики

На шаге **Политики дежурств** выберите **Политики дежурства**, которые запускает правило, затем создайте правило.
:::

Уровень серьёзности сам по себе никого не вызывает: правило дежурства, совпадающее по **Оповещение Серьёзности**, — это способ настроить «вызывать команду базы данных при каждом оповещении High». Чтобы увидеть, что запускалось для одного оповещения, откройте его страницу **Выполнения дежурств**. Затем каждый человек получает вызов так, как он настроил в **Настройки пользователя → Правила дежурства** на вкладке **Оповещения**; см. [Правила эскалации](/docs/on-call/escalation-rules).

## Правила владельца и меток

**Правила владельца** добавляют пользователей и команды-владельцев к совпавшим новым оповещениям, а **Правила меток** добавляют метки. Создание занимает два шага: **Совпадение** — условия, затем **Владельцы** или **Метки** — то, что добавляет правило. **Имя** правила следует за вашим выбором, пока вы не введёте своё.

- **Правило может наследовать.** Шесть переключателей, свёрнутых в **Наследовать владельцев** или **Наследовать метки**, передают владельцев или метки монитора, хостов, кластеров Kubernetes, хостов Docker, хостов Podman и сервисов оповещения. У правил эпизодов таких переключателей нет.
- **Новое правило должно что-то добавлять**: выберите хотя бы одного владельца или метку или включите переключатель.
- **Уведомить владельцев** в разделе **Дополнительные поля** правила владельца определяет, сообщать ли добавленным людям.

[Правила меток и владельцев](/docs/configuration/label-and-owner-rules) пошагово описывает форму для каждого вида ресурсов.

## Правила конфиденциальности и runbook-ов

**Правила конфиденциальности** делают совпавшие новые оповещения приватными до того, как запустится что-либо ещё: видеть их могут только их владельцы, а также администраторы и владельцы проекта. У правила есть шаг **Основная информация** и шаг **Критерии совпадения**, и оно делает приватным каждое совпавшее оповещение. См. [Приватные оповещения](/docs/alerts/index#приватные-оповещения).

**Правила runbook-ов** запускают runbook, когда совпадает новое оповещение, если только оповещение не было создано устранённым. См. [Правила runbook-ов](/docs/runbooks/rules).

## Правила напоминаний

**Оповещения → Правила → Reminder Rules** напоминает владельцам оповещения, пока оно остаётся открытым. Каждое новое оповещение получает первое совпавшее правило, сверху вниз по списку.

:::steps
### Назовите правило напоминаний

Нажмите **Создать: Alert Reminder Rule**. На шаге **Rule Info** задайте **Имя**, например «Critical Alert Reminders».

### Выберите, о каких оповещениях напоминать

На шаге **Критерии совпадения** выберите **Оповещение Серьёзности** и **Метки**, к которым оно применяется. Оставьте их пустыми, чтобы напоминать о каждом оповещении.

### Задайте интервал

На шаге **Reminder Settings** задайте **Reminder Interval (minutes)** — как часто напоминать владельцам — и **Stop Reminders When**: **Устранён** по умолчанию или **Подтверждён**. Затем создайте правило.
:::

Владельцы получают каждое напоминание как **Alert reminder**, которое по умолчанию включено по электронной почте. Правило оповещения сопоставляется заново, когда меняются его серьёзность или метки. Чтобы прекратить напоминания для одного оповещения, выключите **Отправлять напоминания** на его странице **Настройки**; это сохраняется в момент переключения.

## Настройки

### Шаблоны заметок

**Оповещения → Настройки → Шаблоны заметок** хранит готовый текст для приватных заметок. Карточка **Шаблоны приватных заметок для оповещений** показывает их; **Создать: Оповещение Заметка Шаблон** запрашивает **Название шаблона**, **Описание шаблона** и **Заметка**. Шаблон предлагается, когда кто-то пишет приватную заметку к оповещению или эпизоду, а также при подтверждении или устранении, и его текст можно отредактировать перед публикацией. Шаблоны заметок оповещений — это простой текст: в отличие от шаблонов заметок инцидентов, они не подставляют переменные.

### Пользовательские поля

**Оповещения → Настройки → Пользовательские поля** добавляет ваши собственные поля к каждому оповещению, например уровень клиента или ссылку на тикет. Заполняйте их на странице **Пользовательские поля** оповещения или через API как `customFields`. Поле может копировать значение из пользовательского поля монитора вместо ручного ввода: см. [Поля, скопированные из монитора](/docs/incidents/settings#поля-скопированные-из-монитора) — для оповещений это работает так же.

### Измерения

**Оповещения → Настройки → Измерения** измеряет, сколько времени занимают события для каждого оповещения. Выберите **Время до подтверждения** или **Время до устранения** либо два собственных момента, например когда **Оповещение создано** и когда оно переходит в выбранное вами состояние. Каждое измерение показывается на странице оповещения и строится на графиках как `oneuptime.alert.measurement.<key>`. См. [Измерения](/docs/incidents/settings#измерения) — для оповещений это работает так же.

### Участие в эпизодах

**Оповещения → Настройки → Участие в эпизодах** определяет, может ли оповещение входить больше чем в один эпизод. Включите **Оповещение может входить только в один эпизод**, и оповещение, которое входит в эпизод, не будет добавлено ни в какой другой — ни из панели управления, ни через API, рабочий процесс или правило группировки, — если его сначала не убрать из этого эпизода. Переключатель выключен, пока вы его не включите, и изменять его могут только Project Owners и Project Admins. Включение не убирает ни одно оповещение из эпизода. См. [Один эпизод на инцидент](/docs/incidents/episodes#один-эпизод-на-инцидент) — для оповещений это работает так же.

### Нумерация

**Оповещения → Настройки → Нумерация** задаёт текст перед номерами оповещений и эпизодов: `ALT-` и `AE-` в новом проекте или `#`, если префикса нет. **Обновить** открывает **Префикс номера оповещения** и **Префикс номера эпизода оповещений** с предпросмотром по мере ввода. Новый префикс получают только оповещения и эпизоды, созданные после этого. Правила для префикса описаны в разделе [Префиксы номеров](/docs/incidents/settings#префиксы-номеров).

Карточка **Следующий номер** под ней задаёт номер, который получат следующее оповещение и следующий эпизод, чтобы продолжить номера другого инструмента: **Обновить** открывает **Следующий номер оповещения** и **Следующий номер эпизода оповещения**, каждый больше самого большого из использованных. См. [Следующие номера](/docs/incidents/settings#следующие-номера).

> [!NOTE]
> В OneUptime Cloud шаблоны заметок и пользовательские поля требуют тарифа **Growth** или выше.

## Рабочие процессы

У каждой модели оповещений есть триггеры и действия рабочих процессов, названные по ней: **On Create Alert**, **On Update Alert**, **On Create or Update Alert** и **On Delete Alert**, то же для **Оповещение Эпизод**, **Оповещение Состояние Хронология** и других, а также действия вроде **Create One Alert** и **Update One Alert**. Единственное исключение — определения пользовательских полей оповещений: у них нет триггеров рабочих процессов. См. [Обзор рабочих процессов](/docs/workflows/index).

## Кто может это менять

Для правил, пользовательских полей и измерений нужен Project Owner или Project Admin либо пользовательская роль с собственным разрешением этого правила. **Alert Member** работает с оповещениями и эпизодами, их заметками, владельцами и хронологиями состояний, а также с шаблонами заметок, а **Alert Admin** дополнительно управляет состояниями и уровнями серьёзности оповещений. См. [Пользователи, команды и разрешения](/docs/permissions/index).
