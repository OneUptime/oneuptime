# Правила и настройки оповещений

Настройка оповещений находится внутри **Оповещения**, а не в **Настройки проекта**: правила, действующие на каждое новое оповещение, и настройки, определяющие каждое оповещение в проекте. Эта страница — справочник по каждому из них и по тому, что запускается само при создании оповещения.

:::cards
- [Правила, через которые проходит новое оповещение](#правила-через-которые-проходит-новое-оповещение): По порядку и что делает каждое.
- [Правила дежурства](#правила-дежурства): Вызывайте нужных людей, не выбирая политику каждый раз.
- [Правила напоминаний](#правила-напоминаний): Напоминайте владельцам, пока оповещение остаётся открытым.
- [Настройки](#настройки): Шаблоны заметок, пользовательские поля, измерения, участие в эпизодах, нумерация и хранение данных.
:::

## Где находятся настройки оповещений

Откройте **Оповещения** из меню **Продукты** в верхней панели. Разделы **Правила** и **Настройки** в его боковом меню сначала свёрнуты, поэтому сначала раскройте их. Каждая страница здесь действует на весь проект, по адресам, начинающимся с `/dashboard/{projectId}/alerts/settings/`.

| Страница правил                 | Что она делает                                                                                 |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| **Правила группировки**         | Объединяет связанные оповещения в эпизоды. См. [Эпизоды оповещений и правила группировки](/docs/alerts/episodes). |
| **Правила дежурства**           | Запускает политики дежурства для совпавших оповещений и эпизодов.                              |
| **Правила инцидентов** | Объявляет инцидент по подходящим оповещениям — сразу или когда оповещение остаётся нерешённым. |
| **Правила владельца**           | Добавляет владельцев к совпавшим оповещениям и эпизодам.                                       |
| **Правила runbook-ов**          | Запускает runbook-и для совпавших оповещений.                                                  |
| **Правила конфиденциальности**  | Делает совпавшие оповещения и эпизоды приватными.                                              |
| **Правила меток**               | Добавляет метки к совпавшим оповещениям и эпизодам.                                            |
| **Правила напоминаний**              | Напоминает владельцам с заданным интервалом, пока оповещение открыто.                          |

Раздел **Настройки** содержит **Состояние оповещения** и **Серьёзность оповещения**, описанные на странице [Состояния и уровни серьёзности оповещений](/docs/alerts/states-and-severities), а затем **Шаблоны заметок**, **Пользовательские поля**, **Измерения**, **Участие в эпизодах**, **Нумерация** и **Хранение данных**, описанные ниже.

Ещё два раздела действуют на оповещения. **Оповещения → ИИ → Настройки** определяет, что OneUptime AI делает сам: **Расследовать новые оповещения**, включено для новых проектов, и **Автоматически исправлять новые оповещения**, выключено, пока вы его не включите. См. [AI SRE](/docs/ai/ai-sre). **Оповещения → Рабочее пространство** содержит правила Slack и Microsoft Teams, которые публикуют оповещения и эпизоды в каналы, и свою вкладку **Сводка**. См. [Slack](/docs/workspace-connections/slack).

```mermaid title="Правила, через которые проходит новое оповещение, по порядку"

    subgraph more["Что оно получает"]

    end
```

Правила различаются тем, как разрешаются несколько совпадений:

- **Правила группировки**, **Правила инцидентов** и **Правила напоминаний** проверяются сверху вниз по своему списку, и побеждает первое совпадение. Перетащите правило, чтобы изменить его место; новое правило попадает в конец.
- **Правила дежурства**, **Правила владельца**, **Правила меток**, **Правила конфиденциальности** и **Правила runbook-ов** действуют все, когда совпадают. Политики дежурства, владельцы и метки, которые добавляют несколько правил, добавляются один раз.

У **Правила дежурства**, **Правила владельца**, **Правила меток** и **Правила конфиденциальности** есть две вкладки: **Правила оповещений** для оповещений и **Правила эпизодов**, которые так же действуют на каждый новый эпизод оповещений. Новое правило создаётся включённым; выключите **Включено** в его форме редактирования, чтобы приостановить его, а список показывает для каждого правила зелёное **Включено** или красное **Отключено**.

Большинство правил действует на оповещения и эпизоды, созданные после их сохранения. Чтобы применить правило владельца, меток или конфиденциальности к уже существующим, используйте **Запустить сейчас**: см. [Применение правил к существующим ресурсам](/docs/configuration/run-rules-now). Правила напоминаний — исключение: при сохранении такого правила заново сопоставляется каждое открытое оповещение.

### Условия

Условия правила определяют, на какие оповещения оно действует, и читаются как предложения: «Если **Заголовок оповещения** содержит `database`», «И **Метки монитора** содержит любое из *Production*». Правило без условий совпадает с каждым оповещением.

| Условие                                                       | С чем сравнивает                                                                                               |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Мониторы**, **Уровни серьёзности оповещений**, **Метки оповещений**, **Метки монитора** | **Содержит любое из**, **Содержит все из** или **Не содержит ни одного из** выбранных значений.      |
| **Заголовок оповещения**, **Описание оповещения**, **Имя монитора**, **Описание монитора** | **Содержит**, **Не содержит**, **Равно**, **Не равно**, **Начинается с**, **Заканчивается на** без учёта регистра или **Соответствует шаблону** и **Не соответствует шаблону** для регулярного выражения или подстановочного знака `*`. |

При двух и более условиях выберите **Соответствие всем**, где должно выполняться каждое, или **Соответствие любому**, где достаточно одного. Правила эпизодов вместо этого сопоставляют серьёзность, метки, заголовок и описание эпизода.

## Правила дежурства

**Оповещения → Правила → Правила дежурства** делает вызовы автоматическими. Каждое совпавшее правило добавляет свои политики к новому оповещению, и оповещение запускает их вместе с уже имевшимися политиками, каждую по одному разу.

:::steps
### Выберите оповещения

Нажмите **Создать: Alert On-Call Rule**. На шаге **Совпадение** вариант **Все оповещения**, с которого начинается новое правило, совпадает с каждым новым оповещением. Чтобы сузить правило, выберите **Только оповещения, соответствующие условиям** и добавьте условия, которым должно соответствовать оповещение.

### Выберите политики

На шаге **Политики дежурств** выберите **Политики дежурств**, которые вызывает правило. **Имя** следует за ними, например «Вызвать Platform on-call», пока вы не введёте своё, а **Описание** ждёт в разделе **Дополнительные поля**. Затем создайте правило.
:::

Уровень серьёзности сам по себе никого не вызывает: правило дежурства, совпадающее по **Уровни серьёзности оповещений**, — это способ настроить «вызывать команду базы данных при каждом оповещении High». Чтобы увидеть, что запускалось для одного оповещения, откройте его страницу **Выполнения дежурств**. Затем каждый человек получает вызов так, как он настроил в **Настройки пользователя → Как со мной связаться** на вкладке **Оповещения**; см. [Правила эскалации](/docs/on-call/escalation-rules).

Правило вызывает людей, как только оповещение ему подходит. Чтобы правило вместо этого ждало рабочих часов, ответьте на **Когда это правило должно вызывать?** в разделе **Дополнительные поля** вариантом **Только в рабочие часы**. **Рабочие часы** сначала — с понедельника по пятницу, с 09:00 до 17:00, в вашем часовом поясе: выберите другие дни, другое **Время начала** или **Время окончания** или другой **Часовой пояс**, и фраза под выбором скажет, что произойдёт. В списке правило показывает свои часы под названием. Оповещение, подошедшее вне этих часов, получает выполнение, которое ждёт и никого не вызывает; когда рабочие часы начинаются, политика вызывает людей по своему первому правилу эскалации и эскалирует как обычно. Если оповещение подтвердят или устранят раньше, никого не вызовут. Если оповещение изменится, пока выполнение ждёт, и теперь подойдёт правилу, которое вызывает сразу, например потому что его серьёзность повысили, выполнение тут же начнёт вызывать людей, а лента оповещения сообщит почему. Два правила, запускающие одну политику, запускают её, как только это позволяет любое из них: правило для самых высоких серьёзностей, которое вызывает сразу, рядом с правилом для остальных, которое ждёт рабочих часов, сохраняет ночи спокойными.

Правило вызывает людей своих политик, чтобы они реагировали: подтверждение вызова подтверждает оповещение. Чтобы держать команду в курсе, пока реагирует другая, ответьте на **Вызывать людей этих политик как** в разделе **Дополнительные поля** вариантом **Наблюдатели**. Их вызов говорит, что они наблюдатели, а его подтверждение лишь говорит, что они его видели: оповещение не подтверждается, и ничей другой вызов не прекращается. Их вызов продолжается, пока кто-то из них не ответит или оповещение не будет устранено, а в списке правило под своим названием говорит, что вызывает как наблюдателей. Политика, которую одно подходящее правило вызывает для реагирования, а другое — как наблюдателей, вызывает для реагирования.

Правило может принадлежать командам. **Ответственные команды** в разделе **Дополнительные поля** закрепляет его за выбранными командами: редактировать и удалять его могут только их участники и администраторы проекта, а все остальные, кто видит правила, видят его только для чтения. Правило, которое не принадлежит ни одной команде, может менять любой, кому можно редактировать правила дежурства, а правила эпизодов тоже могут принадлежать командам. См. [Правила, принадлежащие командам](/docs/permissions/index#правила-принадлежащие-командам).

## Правила инцидентов

**Оповещения → Правила → Правила инцидентов** сами превращают оповещения в инциденты. Первое правило, подходящее новому оповещению, сверху вниз по списку, объявляет по нему инцидент, как это сделала бы кнопка **Объявить инцидент** на странице оповещения, и связывает оповещение с ним.

:::steps
### Отберите оповещения

В шаге **Совпадение** вариант **Все оповещения**, с которого начинается новое правило, подходит каждому новому оповещению. Чтобы сузить его, выберите **Только оповещения, соответствующие условиям** и добавьте условия, которым должно отвечать оповещение.

### Опишите инцидент

В шаге **Инцидент** выберите **Серьёзность инцидента** или оставьте поле пустым, чтобы каждый инцидент получил серьёзность, соответствующую серьёзности его оповещения. Задайте **Declare After (Minutes)** больше 0, чтобы объявлять инцидент, только если к этому времени оповещение всё ещё не решено. **Имя** правила следует за серьёзностью, например «Declare SEV1 incidents», пока вы не введёте своё. Затем создайте правило.
:::

Инцидент получает название, описание, монитор, затронутые ресурсы и метки оповещения и становится приватным, если приватно оповещение. Затем для него выполняются его собственные правила, как для любого нового инцидента, поэтому кого вызывать, решают его правила дежурства. Оповещение, решённое до конца ожидания, никогда не становится инцидентом, а оповещение, уже связанное с инцидентом, остаётся как есть. **Показывать на страницах состояния** в разделе **Дополнительные поля** решает, появится ли инцидент на страницах состояния, где показан его монитор.

## Правила владельца и меток

**Правила владельца** добавляют пользователей и команды-владельцев к совпавшим новым оповещениям, а **Правила меток** добавляют метки. Создание занимает два шага: **Совпадение** — условия, затем **Владельцы** или **Метки** — то, что добавляет правило. **Имя** правила следует за вашим выбором, пока вы не введёте своё.

- **Правило может наследовать.** Шесть переключателей, свёрнутых в **Наследовать владельцев** или **Наследовать метки**, передают владельцев или метки монитора, хостов, кластеров Kubernetes, хостов Docker, хостов Podman и сервисов оповещения. У правил эпизодов таких переключателей нет. Раздел **Наследовать владельцев** правила владельцев заканчивается полем **Команда создателя**: из перечисленных там команд владельцем становится и каждая, в которой состоит человек, создающий оповещение.
- **Новое правило должно что-то добавлять**: выберите хотя бы одного владельца или метку или включите переключатель. В правиле владельцев инцидентов или оповещений достаточно и команды в **Команда создателя**.
- **Уведомить владельцев** в разделе **Дополнительные поля** правила владельца определяет, сообщать ли добавленным людям.

[Правила меток и владельцев](/docs/configuration/label-and-owner-rules) пошагово описывает форму для каждого вида ресурсов.

## Правила конфиденциальности и runbook-ов

**Правила конфиденциальности** делают совпавшие новые оповещения приватными до того, как запустится что-либо ещё: видеть их могут только их владельцы, а также администраторы и владельцы проекта. У правила два шага: **Совпадение** — оповещения, которые оно делает приватными, затем **Имя**, уже заполненное как «Сделать оповещения приватными». См. [Приватные оповещения](/docs/alerts/index#приватные-оповещения).

**Правила runbook-ов** запускают runbook, когда совпадает новое оповещение, если только оповещение не было создано устранённым. См. [Правила runbook-ов](/docs/runbooks/rules).

## Правила напоминаний

**Оповещения → Правила → Правила напоминаний** напоминает владельцам оповещения, пока оно остаётся открытым. Каждое новое оповещение получает первое совпавшее правило, сверху вниз по списку.

:::steps
### Выберите, о каких оповещениях напоминать

Нажмите **Создать: Alert Reminder Rule**. На шаге **Совпадение** оставьте выбранным **Все оповещения**, чтобы напоминать о каждом оповещении, или выберите **Только оповещения, соответствующие условиям**, а затем **Уровни серьёзности оповещений** и **Метки**, к которым оно применяется.

### Задайте интервал

На шаге **Напоминания** задайте **Интервал напоминаний (минуты)** — как часто напоминать владельцам — и **Прекратить напоминания, когда**: **Устранён** по умолчанию или **Подтверждён**. **Имя** следует за ними, например «Напоминать раз в 30 мин. до устранения», пока вы не введёте своё. Затем создайте правило.
:::

Владельцы получают каждое напоминание как **Напоминание об оповещении**, которое по умолчанию включено по электронной почте. Правило оповещения сопоставляется заново, когда меняются его серьёзность или метки. Чтобы прекратить напоминания для одного оповещения, выключите **Отправлять напоминания** на его странице **Настройки**; это сохраняется в момент переключения.

## Настройки

### Шаблоны заметок

**Оповещения → Настройки → Шаблоны заметок** хранит готовый текст для приватных заметок. Карточка **Шаблоны приватных заметок для оповещений** показывает их; **Создать: Шаблон заметки оповещения** запрашивает **Название шаблона**, **Описание шаблона** и **Заметка**. Шаблон предлагается, когда кто-то пишет приватную заметку к оповещению или эпизоду, а также при подтверждении или устранении, и его текст можно отредактировать перед публикацией. Шаблоны заметок оповещений — это простой текст: в отличие от шаблонов заметок инцидентов, они не подставляют переменные.

### Пользовательские поля

**Оповещения → Настройки → Пользовательские поля** добавляет ваши собственные поля к каждому оповещению, например уровень клиента или ссылку на тикет. Заполняйте их на странице **Пользовательские поля** оповещения или через API как `customFields`. Поле может копировать значение из пользовательского поля монитора вместо ручного ввода: см. [Поля, скопированные из монитора](/docs/incidents/settings#поля-скопированные-из-монитора) — для оповещений это работает так же.

### Измерения

**Оповещения → Настройки → Измерения** измеряет, сколько времени занимают события для каждого оповещения. Выберите **Время до подтверждения** или **Время до устранения** либо два собственных момента, например когда **Оповещение создано** и когда оно переходит в выбранное вами состояние. Каждое измерение показывается на странице оповещения и строится на графиках как `oneuptime.alert.measurement.<key>`. См. [Измерения](/docs/incidents/settings#измерения) — для оповещений это работает так же.

**Время до подтверждения после вызова** отсчитывается от момента **Кого-то впервые вызвали**, когда политика дежурства или прямой вызов впервые уведомили кого-то об оповещении, а не от его создания: оповещению, которое возникло ночью, а вызов по нему ушёл утром, ночь не засчитывается. У оповещения, по которому никого не вызывали, значения нет. См. [Время до подтверждения после вызова](/docs/incidents/settings#время-до-подтверждения-после-вызова).

### Участие в эпизодах

**Оповещения → Настройки → Участие в эпизодах** определяет, может ли оповещение входить больше чем в один эпизод. Включите **Оповещение может входить только в один эпизод**, и оповещение, которое входит в эпизод, не будет добавлено ни в какой другой — ни из панели управления, ни через API, рабочий процесс или правило группировки, — если его сначала не убрать из этого эпизода. Переключатель выключен, пока вы его не включите, и изменять его могут только Project Owners и Project Admins. Включение не убирает ни одно оповещение из эпизода. См. [Один эпизод на инцидент](/docs/incidents/episodes#один-эпизод-на-инцидент) — для оповещений это работает так же.

### Нумерация

**Оповещения → Настройки → Нумерация** задаёт текст перед номерами оповещений и эпизодов: `ALT-` и `AE-` в новом проекте или `#`, если префикса нет. **Обновить** открывает **Префикс номера оповещения** и **Префикс номера эпизода оповещений** с предпросмотром по мере ввода. Новый префикс получают только оповещения и эпизоды, созданные после этого. Правила для префикса описаны в разделе [Префиксы номеров](/docs/incidents/settings#префиксы-номеров).

Карточка **Следующий номер** под ней задаёт номер, который получат следующее оповещение и следующий эпизод, чтобы продолжить номера другого инструмента: **Обновить** открывает **Следующий номер оповещения** и **Следующий номер эпизода оповещения**, каждый больше самого большого из использованных. См. [Следующие номера](/docs/incidents/settings#следующие-номера).

### Хранение данных

**Оповещения → Настройки → Хранение данных** удаляет оповещения, когда они устранены достаточно давно, так же как [Хранение данных](/docs/incidents/settings#хранение-данных) делает это для инцидентов. Её карточка **Устранённые оповещения** спрашивает **Удалять через**, **Никогда**, пока вы не выберете срок, и перед удалением большего просит подтверждения кнопкой **Удалить старые оповещения**. Оповещение остаётся, пока оно не устранено, пока входит в эпизод, который ещё открыт или был устранён меньше этого срока назад, и пока остаётся инцидент, с которым оно связано. Изменять это могут только Project Owners и Project Admins; в API это поле проекта `alertRetentionInDays`.

> [!NOTE]
> В OneUptime Cloud шаблоны заметок и пользовательские поля требуют тарифа **Growth** или выше.

## Рабочие процессы

У каждой модели оповещений есть триггеры и действия рабочих процессов, названные по ней: **On Create Alert**, **On Update Alert**, **On Create or Update Alert** и **On Delete Alert**, то же для **Эпизод оповещений**, **Хронология состояний оповещения** и других, а также действия вроде **Create One Alert** и **Update One Alert**. Единственное исключение — определения пользовательских полей оповещений: у них нет триггеров рабочих процессов. См. [Обзор рабочих процессов](/docs/workflows/index).

## Кто может это менять

Для правил, пользовательских полей и измерений нужен Project Owner или Project Admin либо пользовательская роль с собственным разрешением этого правила. **Участник оповещений** работает с оповещениями и эпизодами, их заметками, владельцами и хронологиями состояний, а также с шаблонами заметок, а **Администратор оповещений** дополнительно управляет состояниями и уровнями серьёзности оповещений. См. [Пользователи, команды и разрешения](/docs/permissions/index).
