# Руководство по самостоятельному хостингу

Пройдите эту страницу сверху вниз, чтобы от пустого сервера прийти к своему OneUptime, который работает по HTTPS, прислал вам тестовое письмо и может вас оповещать. Каждый шаг заканчивается тем, как понять, что он сработал, и ссылается на более подробные страницы.

:::cards
- [Установите OneUptime](#установите-oneuptime): Docker Compose на одном сервере или Helm-чарт в Kubernetes.
- [Завершите настройку сервера](#завершите-настройку-сервера): Почта, затем SMS и звонки, каждый с проверкой.
- [Проверьте установку](#проверьте-установку): Одна команда, которая называет, что не так.
- [Быстрый старт](/docs/introduction/quickstart): Ваш первый монитор, первая политика дежурств и первая страница статуса.
:::

## Что понадобится

- **Сервер.** Для Docker Compose — Linux-сервер с 8 ГБ памяти, 4 ядрами и 20 ГБ диска, чтобы попробовать OneUptime, или 16 ГБ, 8 ядер и 400 ГБ для команды: см. [Подбор размеров и планирование ёмкости](/docs/installation/sizing). Для Helm-чарта — кластер Kubernetes.
- **Доменное имя**, по которому будут открывать OneUptime, например `oneuptime.example.com`, с DNS-записью `A`, указывающей на сервер. Можно начать с IP-адреса сервера, но сертификату от Let's Encrypt нужно доменное имя.
- **Порты 80 и 443**, доступные из интернета, для HTTPS.
- **Способ отправлять почту**: почтовый сервер, например вашей компании, Microsoft 365 или Google Workspace, или учётная запись в Amazon SES, SendGrid, Mailgun, Postmark или Resend.
- **Учётная запись Twilio**, чтобы получать оповещения по SMS и телефонным звонком. Почте и push-уведомлениям она не нужна.

**Сработало, если** `dig +short oneuptime.example.com` выводит IP-адрес сервера.

## Установите OneUptime

:::tabs
@tab Docker Compose
На новом сервере с Ubuntu, Debian или системой на основе RHEL одна команда установит недостающие Docker, Git и Node.js, клонирует OneUptime в папку `oneuptime`, спросит адрес, по которому к нему будут обращаться, и запустит его:

```bash
curl -fsSL https://oneuptime.com/install.sh | bash
```

Чтобы сделать то же вручную, с установленными Docker, Git и Node.js:

```bash
git clone --depth 1 --single-branch --branch release https://github.com/OneUptime/oneuptime.git
cd oneuptime
cp config.example.env config.env
```

Откройте `config.env` и укажите в `HOST`, первой его настройке, ваше доменное имя или IP-адрес, без `http://`. Это единственная настройка, которую нужно изменить: почта, SMS и звонки настраиваются в Admin Dashboard, а всё, что ниже `ADVANCED`, работает как есть. Затем запустите OneUptime:

```bash
npm start
```

**Сработало, если** `npm start` заканчивается строкой **OneUptime is up!** и адресом, который нужно открыть. Первый запуск занимает несколько минут, пока Docker скачивает образы. Если `npm start` остановится раньше, он скажет, что изменить. В [Docker Compose](/docs/installation/docker-compose) есть все подробности.
@tab Kubernetes
Создайте `values.yaml` с вашим доменным именем или IP-адресом, без `http://`:

```yaml title="values.yaml"
host: oneuptime.example.com
```

Чарт хранит данные в классе хранилища вашего кластера по умолчанию. Если `kubectl get storageclass` не отмечает ни один как `(default)`, добавьте `global.storageClass` с именем одного из них. Затем установите чарт:

```bash
helm repo add oneuptime https://helm-chart.oneuptime.com/
helm install my-oneuptime oneuptime/oneuptime -f values.yaml
```

**Сработало, если** `kubectl get pods` показывает каждый под в состоянии `Running`, а адрес, который вывел `helm install`, открывает OneUptime. В [руководстве по установке чарта](https://github.com/OneUptime/oneuptime/blob/main/HelmChart/Public/oneuptime/docs/installation.md) есть все подробности.
:::

## Включите HTTPS

Когда доменное имя указывает на сервер, позвольте OneUptime получить бесплатный сертификат от Let's Encrypt. Он сам продлевает сертификат.

:::tabs
@tab Docker Compose
Задайте эти значения в `config.env`, затем снова выполните `npm start`:

```ini title="config.env"
HOST=oneuptime.example.com
PROVISION_SSL=true
HTTP_PROTOCOL=https
```

Уже используете обратный прокси, например Caddy, Nginx или балансировщик нагрузки? Оставьте `PROVISION_SSL=false`, задайте `HTTP_PROTOCOL=https` и `TRUSTED_PROXY_HOPS=2` и прочитайте [Ваш собственный обратный прокси](/docs/installation/docker-compose#ваш-собственный-обратный-прокси).
@tab Kubernetes
Задайте эти значения в `values.yaml`, затем примените их:

```yaml title="values.yaml"
host: oneuptime.example.com
httpProtocol: https
ssl:
  provision: true
```

```bash
helm upgrade my-oneuptime oneuptime/oneuptime -f values.yaml
```

Чтобы вместо этого завершать TLS на своём ingress-контроллере, оставьте `ssl.provision` выключенным и задайте только `httpProtocol: https`.
:::

**Сработало, если** `https://oneuptime.example.com` открывается без предупреждения о сертификате. Первый сертификат обычно приходит в течение нескольких минут. Пробуете OneUptime на `localhost`? Пропустите этот шаг: сертификату нужно доменное имя.

## Создайте учётную запись администратора

Откройте свой адрес, например `https://oneuptime.example.com`, и зарегистрируйтесь. Первая учётная запись на новом сервере становится его главным администратором, который может открыть Admin Dashboard по адресу `/admin`.

**Сработало, если** `/admin` открывает Admin Dashboard. Пока почта, HTTPS или решение о регистрации ещё не готовы, он открывается на странице **Завершите настройку этого сервера**.

## Завершите настройку сервера

Страница **Настройка сервера** в Admin Dashboard, по адресу `/admin/setup`, перечисляет, что нужно новому серверу, самое важное первым. Почта, HTTPS и то, кто может регистрироваться, обязательны. SMS и звонки, глобальный зонд, резервные копии и проверки обновлений рекомендуются. У каждого пункта есть кнопка, которая открывает место, где он настраивается, а `npm start` в конце выводит адрес этой страницы.

:::steps
### Настройте почту

Нажмите **Настроить почту**. Откроется **Настройки > Уведомления > Электронные письма**, где вы указываете свой почтовый сервер (большинство использует порт `587`) или почтового провайдера и адрес, с которого уходят письма. Сохраните, затем нажмите **Отправить тестовое письмо** и отправьте его себе.

**Сработало, если** письмо пришло, а список отметил почту как готовую. Если проверка не удалась, она показывает, что ответил почтовый сервер: см. [SMTP](/docs/emails/smtp#устранение-неполадок).

### Выберите, кто может регистрироваться

Зарегистрироваться может любой, кто может открыть ваш адрес. Когда у вашей команды будут учётные записи, выключите **Разрешить регистрацию** в разделе **Настройки > Аутентификация**: те, кого вы пригласите в проект, всё равно смогут присоединиться. Чтобы оставить регистрацию открытой, нажмите **Оставить регистрацию открытой**.

**Сработало, если** список отметил регистрацию как готовую.

### Настройте SMS и звонки или используйте только почту и push

Чтобы получать оповещения по SMS и телефонным звонком, нажмите **Настроить SMS и звонки** и добавьте свою учётную запись Twilio в разделе **Настройки > Уведомления > Звонки и SMS**: в [Интеграции с Twilio](/docs/self-hosted/twilio-integration) показано, где найти каждое значение. Затем нажмите **Отправить тестовое SMS** и **Сделать тестовый звонок**. Чтобы вместо этого отправлять их через свой шлюз, см. [Шлюз SMS и звонков](/docs/self-hosted/sms-and-call-gateway). Если почты и push-уведомлений достаточно, нажмите **Только почта и push-уведомления**.

**Сработало, если** пришло SMS и зазвонил телефон, или список показывает ваш выбор.
:::

Пункт HTTPS готов, как только работает [Включите HTTPS](#включите-https), а каждый рекомендуемый пункт говорит, что делать.

## Проверьте установку

:::tabs
@tab Docker Compose
В папке `oneuptime` запустите doctor:

```bash
npm run doctor
```

Он проверяет каждый контейнер, `config.env`, что `HOST` доходит до этого сервера, сертификат и свободное место на диске, и спрашивает OneUptime, что тот видит о себе, например почту и зонды. Для каждой проблемы он называет исправление: см. [Проверка установки](/docs/installation/docker-compose#проверка-установки).
@tab Kubernetes
Запустите диагностический скрипт чарта на своём кластере, как показано в [руководстве по устранению неполадок чарта](https://github.com/OneUptime/oneuptime/blob/main/HelmChart/Public/oneuptime/docs/troubleshooting.md#run-it). Он только читает и заканчивается сводкой найденного, самое серьёзное первым.
:::

**Сработало, если** doctor заканчивается строкой **Everything looks right.** и завершается с кодом `0`. Он завершается с кодом `1`, когда что-то нужно исправить, и с кодом `2`, когда не смог выполнить проверки. В Kubernetes в сводке нет ни одной находки `CRITICAL`.

## Отслеживайте что-нибудь и получайте оповещения

Теперь ваш сервер может отправлять письма и оповещать людей. [Быстрый старт](/docs/introduction/quickstart) продолжается в продукте: монитор для вашего сайта, политика дежурств, которая оповестит вас, когда он упадёт, и страница статуса, примерно за пятнадцать минут. Его последняя часть объявляет тестовый инцидент, чтобы вы увидели, как приходит оповещение.

## Устранение неполадок

:::details npm start останавливается и говорит, что HOST ещё не адрес
`HOST` в `config.env` всё ещё содержит заглушку, например `<your-address>`. Укажите в нём ваше доменное имя или IP-адрес, без `http://`, и снова выполните `npm start`.
:::

:::details Тестовое письмо не отправляется
Сообщение под кнопкой — это ответ почтового сервера. Проверьте имя хоста, порт, имя пользователя и пароль, а также что почтовый сервер разрешает отправку с адреса, с которого уходят письма. См. [SMTP](/docs/emails/smtp#устранение-неполадок).
:::

:::details Браузер предупреждает о сертификате
Let's Encrypt нужны порты 80 и 443, доступные из интернета, и доменное имя, указывающее на этот сервер. Подождите несколько минут, затем выполните `npm run doctor`: он проверит сертификат и скажет, что не так.
:::
