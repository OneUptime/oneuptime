# Ключи приёма

Ключ приёма связывает вашу телеметрию с вашим проектом. Приложения, OpenTelemetry Collectors и агенты отправляют его с каждым запросом, и OneUptime относит их логи, трассировки и метрики к проекту, которому принадлежит ключ. На этой странице показано, как создать ключ, какой тип выбрать и как хранить ключи в безопасности. Чтобы отличить ключ приёма от API-ключа, см. [Что выбрать?](/docs/introduction/which-one#ключ-приёма-или-api-ключ).

:::cards
- [Создать ключ приёма](#создать-ключ-приёма): Имя, тип и секрет, который нужно скопировать.
- [Сервер, браузер или мобильное приложение](#сервер-браузер-или-мобильное-приложение): Какой ключ нужен отправителю.
- [Защитить браузерный ключ](#защитить-браузерный-ключ): Источники, одно имя сервиса и лимит.
- [Сменить, отключить или удалить ключ](#сменить-отключить-или-удалить-ключ): Что делать, если ключ утек.
:::

## Как проверяется ключ

Каждый запрос несет секрет ключа, обычно в заголовке `x-oneuptime-token`. OneUptime находит ключ, проверяет, что он еще может отправлять, и только тогда принимает данные в проект ключа.

```mermaid title="Что OneUptime проверяет, прежде чем принять телеметрию"
flowchart TB
    request["Запрос с<br/>x-oneuptime-token"] --> known{"Известен, включён,<br/>не истёк?"}
    known -->|"Да"| origin{"Разрешённый<br/>источник для<br/>браузерного ключа?"}
    origin -->|"Да"| limit{"В пределах лимита?"}
    limit -->|"Да"| accepted["Принят в<br/>проект ключа"]
    known -->|"Нет"| refused["Отклонён со<br/>статусом, где<br/>сказано почему"]
    origin -->|"Нет"| refused
    limit -->|"Нет"| refused
```

- **Ключ определяет проект.** Вы никогда не отправляете ID проекта: данные, отправленные с ключом, попадают в проект, которому принадлежит ключ.
- **Изменения доходят до всех серверов за несколько секунд.** Отключение ключа, сброс его секрета или изменение его источников, срока действия или лимита вступают в силу на всех серверах за несколько секунд.
- **У ключа могут быть собственные бюджеты.** Дневной бюджет и скорость в секунду для каждого сигнала в пределах бюджетов проекта: см. [Бюджеты приема](/docs/telemetry/ingestion-budgets).
- **Серверный ключ — это пароль.** Любой, у кого он есть, может отправлять телеметрию в ваш проект. Храните его в секретах ваших серверов, никогда — в системе контроля версий, на веб-странице или в мобильном приложении.

## Сервер, браузер или мобильное приложение

Выбирайте тип по тому, где будет находиться ключ. Тип нельзя изменить после создания ключа.

| | **Сервер** | **Браузер** | **Мобильный** |
| --- | --- | --- | --- |
| Для | Приложения, коллекторы и агенты на машинах, которыми вы управляете | Веб-страницы и React Native Session Replay | Одно приложение iOS, Android или React Native |
| Отправляет | Любую телеметрию на любые конечные точки | Трассировки, логи, метрики, Session Replays и [события Sentry](/docs/telemetry/compatible-endpoints#sdk-sentry) | Трассировки, логи и метрики этого приложения, по OTLP/HTTP |
| Секрет | Да: храните его на своих серверах | Нет: его может прочитать любой, кто открыл страницу | Нет: его может скопировать любой, у кого есть приложение |
| Источники | Не проверяются | Принимаются только перечисленные источники | Запрос с веб-страницы отклоняется |
| Запросов в минуту | Без лимита, если вы его не зададите | 6000, если вы не зададите другой лимит | 6000, если вы не зададите другой лимит |

Во всех остальных местах OneUptime отклоняет браузерный ключ, например по gRPC и MQTT, для профилей, Syslog, Fluent Bit и Fluentd, а также для загрузки source maps, а мобильный ключ — везде, кроме трассировок, логов и метрик OTLP по HTTP. Чтобы перевести отправителя на другой тип, создайте ключ этого типа, переключите отправителя на него, а затем удалите старый ключ.

## Перед началом

- **Роль, которая управляет ключами приёма.** Владелец проекта или Администратор проекта либо пользовательская роль с разрешением Create Ingestion Key. Роли Telemetry не включают ключи приёма.
- **В OneUptime Cloud — способ оплаты.** Телеметрия оплачивается по мере использования, поэтому проекту на плане Free нужен способ оплаты, прежде чем он сможет создать ключ. Тогда окно создания завершается шагом **Биллинг** с ценами.

## Создать ключ приёма

:::steps
### Открыть ключи приёма

Перейдите в **Настройки проекта → Телеметрия и APM → Ключи приёма**. **Телеметрия и APM** сначала свернут в боковом меню: нажмите на него, чтобы открыть. Список показывает для каждого ключа столбцы **Имя**, **Тип**, **Последнее использование** и **Описание**.

### Назвать ключ и выбрать его тип

Нажмите **Создать ключ приёма**. Окно открывается с именем **Ключ сервера** и типом **Сервер**. Выберите **Тип ключа** и переименуйте ключ по тому, что будет его использовать, например `checkout-collector`. **Описание** находится в разделе **Расширенный**.

### Добавить источники браузерного ключа или приложение мобильного ключа

Ключ типа **Браузер** запрашивает свои **Разрешённые источники** на следующем шаге, **Настройки браузера**, а свое **Закреплённое имя сервиса** — в разделе **Расширенный**. См. [Защитить браузерный ключ](#защитить-браузерный-ключ). Ключ типа **Мобильный** вместо этого запрашивает **Закреплённое имя сервиса** на первой странице: `service.name` приложения, внутри которого он поставляется.

### Создать ключ и скопировать его секрет

Нажмите **Создать ключ приёма**. Откроется страница ключа: скопируйте его **Секретный ключ** и передайте его отправителям.
:::

**Руководство по настройке** каждого продукта начинается с **Выберите ключ приёма**, где перечислены ключи, которые может использовать это руководство, и можно сразу создать новый. Фрагменты кода в руководстве затем содержат этот ключ.

## Отправлять телеметрию с ключом

Отправители кладут секрет в заголовок `x-oneuptime-token`:

```text
x-oneuptime-token: YOUR_ONEUPTIME_INGESTION_KEY
```

- SDK OpenTelemetry читают его из `OTEL_EXPORTER_OTLP_HEADERS`. См. [быстрый старт OpenTelemetry](/docs/telemetry/open-telemetry#быстрый-старт).
- По OTLP/gRPC он передается в метаданных `x-oneuptime-token`.
- Устройство MQTT отправляет его как пароль. См. [IoT-устройства](/docs/telemetry/iot-devices).
- OneUptime также читает ключ из заголовка `x-oneuptime-ingestion-key` или `x-oneuptime-service-token`, который отправляют некоторые старые настройки.

## Защитить браузерный ключ

Браузерный ключ находится на вашей странице, где его может скопировать кто угодно. Эти настройки ограничивают то, что может сделать копия. Меняйте их на странице ключа через **Редактировать: Ключ приёма**.

| Настройка | Что она делает |
| --- | --- |
| **Разрешённые источники** | Единственные источники, с которых принимается ключ. Запрос с любого другого источника или вовсе без заголовка `Origin` отклоняется. У браузерного ключа должен остаться хотя бы один. |
| **Закреплённое имя сервиса** | Относит все, что ключ отправляет по OTLP/HTTP, к этому одному сервису, какое бы `service.name` ни задал отправитель. Копия ключа тогда может писать только в этот сервис. |
| **Лимит запросов в минуту** | Наибольшее число запросов, для которых ключ принимается каждую минуту, общее для всех посетителей. Браузерный ключ получает 6000, если оставить поле пустым. |
| **Истекает в** | Дата, после которой ключ отклоняется, чтобы опубликованная копия перестала работать. |

Источник — это схема, хост и необязательный порт: `https://app.example.com` не покрывает `https://app.example.com:8443`. Один ведущий `*.` покрывает все поддомены, но не сам домен. React Native Session Replay отправляет точную идентичность `app://`, которая не допускает подстановочных знаков:

```json
[
  "https://app.example.com",
  "https://*.example.com",
  "app://com.example.mobile"
]
```

Раздел [Сервисы](/docs/telemetry/services#как-сервис-попадает-в-каталог) показывает, как закрепленное имя определяет сервис. Runner и ИИ-агент агента Kubernetes, а также ИИ-агенты инфраструктуры не регистрируются с закрепленным ключом: дайте им серверный ключ без закрепленного имени.

## Что ограничивает мобильный ключ

Мобильный ключ поставляется внутри вашего приложения, и любой, у кого есть приложение, может его скопировать. Эти ограничения привязывают каждую копию к приложению, для которого ключ создан:

- **Он пишет только как одно приложение.** Всё, что он отправляет, относится к имени из поля **Закреплённое имя сервиса** как мобильное приложение RUM, какой бы сервис или хост ни назвал отправитель. Копия не может писать в ваши бэкенд-сервисы, хосты или кластеры.
- **Он отправляет только телеметрию этого приложения.** Трассировки, логи и метрики OTLP по HTTP. Он отклоняется по gRPC и MQTT, для Session Replays, профилей и source maps, на любой другой конечной точке и с любой веб-страницы.
- **Его частота ограничена.** 6000 запросов в минуту для всех копий вместе, если вы не зададите для него **Лимит запросов в минуту**.
- **Вы можете его остановить.** Выключите **Включено** или задайте **Истекает в**, и каждая копия будет отклоняться в течение нескольких секунд.

Чего он не может предотвратить: тот, у кого есть ваше приложение, всё равно может отправлять выдуманные трассировки, логи и метрики для этого одного приложения в пределах лимита ключа, пока вы не выключите ключ или пока он не истечёт. Меняйте ключ с каждым выпуском, чтобы старая копия переставала работать вместе со своей версией.

## Сменить, отключить или удалить ключ

Страница ключа показывает его **Статус**, его **Секретный ключ** за **Нажмите, чтобы показать** и его **Последнее использование**: время, когда OneUptime последний раз принял данные, отправленные с ним.

| Чтобы | Сделайте это | Что видят отправители |
| --- | --- | --- |
| Сразу остановить ключ с возможностью отменить это позже | Нажмите **Редактировать: Ключ приёма**, откройте **Доступ и ограничения** и выключите **Включено**. Статус показывает **Disabled — telemetry refused**. | `422`, пока вы снова его не включите |
| Заменить утекший секрет | Нажмите **Сбросить секретный ключ** и подтвердите. Ключ сохраняет свои настройки и получает новый секрет. | `401`, пока они не отправят новый секрет |
| Остановить ключ навсегда | Нажмите **Удалить: Ключ приёма** внизу его страницы. | `401` |

Чтобы сменить секрет без потери данных, создайте второй ключ, переведите на него отправителей и удалите старый ключ, когда его **Последнее использование** перестанет меняться. **Последнее использование** обновляется раз в несколько минут, а не при каждом запросе.

## Устранение неполадок

Отклоненный запрос получает статус и фразу, объясняющую причину.

Страница ключа тоже ведёт счёт: **Отклонённая телеметрия** показывает, что было отклонено от ключа за последние 30 дней, почему, на каком эндпоинте, сколько запросов и когда. Отсутствующий или неверно набранный ключ не принадлежит ни одному проекту, поэтому его никто не считает.

| Ответ | Что это значит |
| --- | --- |
| `401` с `Missing ingestion token` | В запросе нет ключа. Отправьте его в `x-oneuptime-token`. |
| `401` с `Invalid ingestion token` | Ни у одного ключа нет такого секрета: он набран с ошибкой, сброшен или удален. |
| `401` с `This telemetry ingestion key expired.` | Дата **Истекает в** прошла. Задайте более позднюю дату или используйте другой ключ. |
| `402` с `Add a payment method` | В OneUptime Cloud проект находится на плане Free и еще не имеет способа оплаты. |
| `422` с `This telemetry ingestion key has been disabled.` | Кто-то выключил **Включено**. |
| `422` с `A browser ingestion key cannot be used for` | Браузерный ключ попал на конечную точку, которая принимает только серверные ключи. |
| `422` с `did not send an Origin header` | Браузерный ключ был отправлен не из браузера. Используйте мобильный ключ в мобильном приложении, а серверный ключ — во всех остальных местах. |
| `422` с `A mobile ingestion key cannot be used for` | Мобильный ключ попал на конечную точку, отличную от трассировок, логов и метрик OTLP по HTTP, например на gRPC или Session Replay. |
| `422` с `A mobile ingestion key cannot be used from a web page` | Мобильный ключ был отправлен из браузера. На веб-странице используйте браузерный ключ. |
| `422` с `is not allowed for this browser ingestion key` | Источника страницы нет в **Разрешённые источники**. |
| `422` с `is pinned to a single service` | Ключ с **Закреплённое имя сервиса** использовали для регистрации агента. Используйте серверный ключ без закрепленного имени. |
| `429` с `Too many telemetry requests for this ingestion key` | Ключ упёрся в свой **Лимит запросов в минуту**. Экспортеры повторяют попытку после времени из `Retry-After`. |

Другие ответы, которые может получить экспортер OTLP, см. в разделе [Ответы](/docs/telemetry/open-telemetry#ответы).

:::details Данные все еще приходят после отключения ключа
Каждый сервер OneUptime не реже раза в секунду проверяет, не изменился ли ключ, поэтому изменение доходит до всех за несколько секунд, и запросы после этого отклоняются. Пока сервер не может связаться с кешем OneUptime, он может до минуты исходить из того, что знал о ключе. MQTT-клиент, подключившийся с этим ключом, отключается в течение нескольких секунд.
:::

:::details Браузерный ключ работает на моем ноутбуке, но не в продакшене
Источник включает схему и порт. `http://localhost:3000` и `https://app.example.com` — разные источники: перечислите каждый, с которого отдается страница.
:::

:::details Last Used At по-прежнему показывает Никогда
Никто не отправлял данные с этим ключом с тех пор, как OneUptime начал учитывать его использование. Проверьте, что у ваших отправителей есть секрет этого ключа и что их запросы доходят до OneUptime.
:::
