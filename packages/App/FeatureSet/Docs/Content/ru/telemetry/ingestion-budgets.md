# Бюджеты приема

Бюджет приема ограничивает, сколько телеметрии проект отправляет за день, чтобы один шумный сервис или зациклившееся логирование не заполнили ваше хранилище. Администратор экземпляра задаёт дневной бюджет для каждого сигнала — для всех проектов или для одного проекта, а любой, кто редактирует ключ приема, может дать ключу собственный бюджет поменьше. У каждого бюджета также может быть лимит скорости в секунду.

:::cards
- [Как работают бюджеты](#как-работают-бюджеты): Три уровня, учёт по мере поступления телеметрии.
- [Задать бюджеты по умолчанию для всех проектов](#задать-бюджеты-по-умолчанию-для-всех-проектов): В настройках Admin Dashboard.
- [Дать ключу приема собственный бюджет](#дать-ключу-приема-собственный-бюджет): Доля бюджета проекта.
- [Настроить оповещения по бюджету](#настроить-оповещения-по-бюджету): До того, как он исчерпан, и когда он исчерпан.
:::

## Как работают бюджеты

Телеметрия учитывается по мере поступления: в бюджете своего проекта для своего сигнала и в бюджете своего ключа приема, если у ключа он есть. Когда дневной бюджет исчерпан, этот сигнал отклоняется до сброса бюджета.

```mermaid title="Что OneUptime проверяет, прежде чем сохранить телеметрию"
flowchart TB
    request["Телеметрия пришла<br/>с ключом приема"] --> budget{"Бюджет на сегодня<br/>исчерпан?"}
    budget -->|"Да"| refused["Отклонена с 403<br/>до сброса"]
    budget -->|"Нет"| rate{"Быстрее<br/>лимита скорости?"}
    rate -->|"Да"| throttled["Отклонена с 429:<br/>отправитель<br/>повторяет"]
    rate -->|"Нет"| counted["Учтена, затем<br/>сохранена"]
```

- **Три уровня.** Значение по умолчанию для экземпляра действует для всех проектов. Администратор экземпляра может вместо этого дать одному проекту собственный бюджет или вовсе снять для него ограничение. Бюджет ключа лишь делит бюджет его проекта: он может быть меньше, но никогда не больше.
- **Пять сигналов.** У логов, трассировок, метрик, профилей и событий безопасности у каждого свой бюджет. У записей сеансов свои ограничения: см. [Воспроизведение сеансов](/docs/telemetry/session-replay).
- **Байты учитываются в распакованном виде.** Запрос учитывается по размеру тела после распаковки, поэтому сжатие не меняет учитываемый объём. GB — это 1024³ байт, а MB — 1024² байт.
- **Учитывается то, что приходит, а не то, что хранится.** Телеметрия, которую [фильтр отбрасывания](/docs/telemetry/drop-filters-and-scrub-rules) удаляет позже, всё равно учитывается, поэтому бюджет может показывать больше, чем страница [Использование телеметрии](/docs/telemetry/usage), которая учитывает сохранённое.
- **Последний запрос сохраняется целиком.** Запрос, пришедший, пока в бюджете ещё есть место, сохраняется полностью, поэтому исчерпанный бюджет может показывать чуть больше 100%.
- **Пока бюджет не задан, ничего не ограничивается.** Каждая установка начинается без бюджетов, а проект без бюджета вообще не учитывается.
- **Изменения доходят до всех серверов в течение минуты.**
- **Телеметрия принимается, когда её нельзя учесть.** Бюджеты учитываются в Valkey. Пока он недоступен, OneUptime сохраняет телеметрию без учёта, а не отклоняет её, и страницы бюджетов сообщают об этом.

## Перед началом

- **Для бюджетов экземпляра и проекта — Admin Dashboard.** В самостоятельно размещённой установке их задаёт только администратор экземпляра. Владельцы и администраторы проекта видят его бюджеты, но не могут их изменить.
- **Для собственного бюджета ключа — роль, которая редактирует ключи приема.** Project Owner или Project Admin либо пользовательская роль с разрешением Edit Ingestion Key.
- **Для просмотра бюджетов — роль, которая видит использование проекта.** Роли, которые видят страницу [Использование телеметрии](/docs/telemetry/usage), видят на ней и бюджеты.

## Задать бюджеты по умолчанию для всех проектов

:::steps
### Открыть Бюджеты приема

В Admin Dashboard перейдите в **Настройки → Телеметрия → Бюджеты приема**. Раздел **Телеметрия** сначала свёрнут в боковом меню: нажмите на него, чтобы открыть.

### Задать дневные бюджеты

На карточке **Дневные бюджеты по умолчанию** нажмите **Изменить дневные бюджеты по умолчанию**, введите число GB для каждого сигнала, который нужно ограничить, например **Журналы (GB в день)**, и нажмите **Сохранить изменения**. Оставьте сигнал пустым, чтобы не ограничивать его.

### Задать лимиты скорости, если они нужны

На карточке **Лимиты скорости по умолчанию** нажмите **Изменить лимиты скорости по умолчанию** и введите число MB в секунду для сигнала, например **Журналы (MB в секунду)**. Лимит скорости не даёт одному всплеску израсходовать дневной бюджет за считаные минуты.
:::

Карточка **Предупреждение и сброс** содержит порог предупреждения и время, когда сбрасывается бюджетный день: см. [Предупреждение и сброс](#предупреждение-и-сброс).

## Задать бюджеты одного проекта

:::steps
### Открыть проект

В Admin Dashboard перейдите в **Проекты**, нажмите на проект, а затем на **Бюджеты приема** в его боковом меню. Страница начинается с того, сколько проект израсходовал из своих бюджетов сегодня.

### Задать его дневные бюджеты

На карточке **Дневные бюджеты этого проекта** нажмите **Изменить дневные бюджеты**. Введите для сигнала число GB вместо значения по умолчанию для экземпляра или 0, чтобы совсем не ограничивать его. Оставьте сигнал пустым, чтобы сохранить значение по умолчанию для экземпляра.

### Задать его лимиты скорости

На карточке **Лимиты скорости этого проекта** нажмите **Изменить лимиты скорости** и задайте их так же: число MB в секунду, 0 — без ограничения, пустое поле — значение по умолчанию для экземпляра.
:::

Участники проекта видят эти бюджеты на своей странице [Использование телеметрии](/docs/telemetry/usage) только для чтения.

## Дать ключу приема собственный бюджет

Бюджет ключа — это доля бюджета его проекта: отправитель, который заваливает данными свой ключ, останавливается на бюджете ключа, а другие ключи проекта продолжают отправлять данные.

:::steps
### Открыть ключ

Перейдите в **Настройки проекта → Телеметрия и APM → Ключи приема** и нажмите на ключ. **Телеметрия и APM** сначала свернут в боковом меню: нажмите на него, чтобы открыть.

### Задать его бюджеты

На карточке **Бюджеты приема** нажмите **Редактировать бюджеты приема**. На шаге **Дневные бюджеты** введите число GB в день для каждого сигнала, который нужно ограничить, а на шаге **Лимиты скорости** — число MB в секунду. Оставьте сигнал пустым, чтобы у ключа не было собственного бюджета для него.

### Сохранить бюджеты

Нажмите **Сохранить изменения**. Бюджет ключа не может быть больше бюджета его проекта: OneUptime отклоняет такой бюджет и сообщает, каким он может быть самое большее.
:::

- **Действуют оба бюджета.** Телеметрия, отправленная с ключом, учитывается и в бюджете ключа, и в бюджете проекта, а отклоняет её тот, который исчерпается первым.
- **Сниженный бюджет проекта ограничивает и ключ.** Если бюджет проекта снижен ниже бюджета ключа, ключ ограничивается бюджетом проекта.

## Что видят отправители

| Когда | По HTTP | По OTLP/gRPC | Что делает отправитель |
| --- | --- | --- | --- |
| Дневной бюджет исчерпан | `403` | `RESOURCE_EXHAUSTED` | Отбрасывает пакет: повторная попытка не поможет до сброса |
| Превышен лимит скорости | `429` с `Retry-After` | `RESOURCE_EXHAUSTED` с задержкой повтора | Повторяет отправку пакета после задержки |

Каждый отказ объясняет причину. По OTLP/HTTP его тело — это `google.rpc.Status` в protobuf или JSON, в зависимости от того, как был отправлен запрос, поэтому в логе отправителя видна причина, например:

```text
This project's daily logs ingestion budget of 10 GB is used up, so OneUptime is not storing logs from this project until the budget resets at 2026-11-10 00:00 UTC.
```

- **Другие HTTP-отправители получают JSON.** Fluent Bit, Fluentd, syslog и другие конечные точки HTTP получают `error`, `message` и `resetsAt`, а при лимите скорости — ещё и `retryAfterSeconds`.
- **MQTT и облачные потоки нельзя уведомить.** Телеметрия, которая приходит по MQTT или из потока облачного провайдера, отбрасывается, когда её бюджет исчерпан. Лимит скорости к ней не применяется: её нельзя было бы отправить повторно.
- **Отказы учитываются.** То, что исчерпанный бюджет отклоняет или отбрасывает, учитывается как отброшенное, а каждый запрос, отклонённый лимитом скорости, — как троттлинг: см. [Посмотреть сегодняшнее использование и отброшенные данные](#посмотреть-сегодняшнее-использование-и-отброшенные-данные).

## Предупреждение и сброс

- **Предупреждение.** Когда дневной бюджет проходит порог предупреждения — 80%, если администратор экземпляра его не изменит, — владельцы проекта получают письмо, а обозреватели показывают баннер над данными этого сигнала. Ещё одно письмо они получают, когда бюджет исчерпан. Каждый бюджет отправляет каждое письмо не чаще одного раза в день.
- **Сброс.** Каждый бюджетный день начинается заново в 00:00 UTC, если администратор экземпляра этого не изменит. Карточка **Предупреждение и сброс** задаёт **Порог предупреждения (%)** от 1 до 99, **Время сброса** в формате HH:MM и **Часовой пояс сброса**: нажмите **Изменить предупреждение и сброс**.
- **Летнее время.** Сброс следует часам часового пояса, поэтому бюджетный день, в который переводят часы, на час короче или длиннее. Время сброса, которое пропускается при переводе часов, наступает на столько же позже скачка.
- **Изменённый сброс начинает новый день.** Изменение времени сброса или часового пояса сразу начинает новый бюджетный день, в котором пока ничего не учтено.

## Посмотреть сегодняшнее использование и отброшенные данные

Перейдите в **Настройки проекта → Телеметрия и APM → Использование**. Пока для проекта задан бюджет или лимит скорости, страница начинается с карточки **Бюджеты приема**, а ключи с собственными бюджетами находятся на карточке **Бюджеты ключей приема**:

| Столбец | Что показывает |
| --- | --- |
| **Сигнал** | Сигнал, к которому относится строка. |
| **Использовано сегодня** | Сколько учтено с начала бюджетного дня и какая это доля бюджета. |
| **Дневной бюджет** | Действующий бюджет и где он задан: **По умолчанию для экземпляра**, **Задан для этого проекта** или **Собственный бюджет ключа**. |
| **Лимит скорости** | Действующий лимит скорости. |
| **Отброшено** | То, что было отклонено или отброшено, потому что бюджет был исчерпан. |
| **Троттлинг** | Сколько запросов отклонил лимит скорости. |
| **Статус** | **В рамках бюджета**, **Выше порога предупреждения** или **Исчерпан**, **Без дневного бюджета** для сигнала только с лимитом скорости и **Неизвестно**, пока подсчёты нельзя прочитать. |

- **На странице ключа** карточка **Использование бюджета за сегодня** показывает, сколько ключ израсходовал из своих собственных бюджетов.
- **В обозревателях** баннер над данными логов, трассировок, метрик, профилей и событий безопасности сообщает, когда бюджет этого сигнала прошёл порог предупреждения или исчерпан, со ссылкой **Открыть бюджеты**, которая открывает страницу Использование.
- **В Admin Dashboard** страница проекта **Бюджеты приема** показывает те же цифры.

## Настроить оповещения по бюджету

Каждые 5 минут OneUptime записывает показатели каждого бюджета за день как метрики проекта, и [монитор метрик](/docs/monitor/metrics-monitor) оповещает по ним, как по любой другой метрике:

| Метрика | Единица | Что содержит |
| --- | --- | --- |
| `oneuptime.telemetry.budget.used.bytes` | `By` | Байты, учтённые в дневном бюджете с начала бюджетного дня. |
| `oneuptime.telemetry.budget.used.percent` | `%` | То же самое в процентах от дневного бюджета. При 100 и более сигнал отклоняется до сброса. |
| `oneuptime.telemetry.budget.dropped.bytes` | `By` | Байты, отклонённые или отброшенные с начала бюджетного дня, потому что бюджет был исчерпан. |
| `oneuptime.telemetry.budget.throttled.requests` | `{request}` | Запросы, которые лимит скорости отклонил с начала бюджетного дня. |

Каждая точка несёт следующие атрибуты:

| Атрибут | Значение |
| --- | --- |
| `projectId` | ID проекта. |
| `signal` | `logs`, `traces`, `metrics`, `profiles` или `security-events`. |
| `scope` | `project` или `ingestion-key` для собственного бюджета ключа. |
| `ingestionKeyId` | ID ключа — для собственного бюджета ключа. |
| `ingestionKeyName` | Имя ключа на момент записи точки — для собственного бюджета ключа. |

Чтобы получить оповещение при 90% бюджета логов проекта, создайте монитор метрик на `oneuptime.telemetry.budget.used.percent` с фильтром по `signal` `logs` и `scope` `project`, который оповещает, когда максимум выше 90:

- **Агрегируйте по максимуму.** В течение бюджетного дня каждый показатель только растёт.
- **Используйте окно от 15 минут.** Точка записывается каждые 5 минут, а окно без единой точки закрывает оповещение.
- **Ожидайте пропусков, а не нулей.** Для показателя, равного 0, ничего не записывается, как и пока подсчёты нельзя прочитать.
- **Они ничего не стоят.** Эти метрики не учитываются ни в каком бюджете и не считаются использованием телеметрии, а хранятся столько же, сколько метрики мониторов: 30 дней, если администратор экземпляра это не изменит. Имена метрик, начинающиеся с `oneuptime.telemetry.budget.`, зарезервированы для них: метрики, которые ваши приложения отправляют под таким именем, отбрасываются.

## Устранение неполадок

:::details Коллектор пишет в лог 403 для своих экспортов
Дневной бюджет проекта или ключа для этого сигнала исчерпан, и коллектор отбрасывает то, что не может отправить, до сброса бюджета. Посмотрите **Использовано сегодня** на странице Использование. Попросите администратора экземпляра увеличить бюджет проекта или отправляйте меньше: фильтр отбрасывания здесь не поможет, так как он удаляет телеметрию после того, как она учтена.
:::

:::details Коллектор пишет в лог 429 и повторяет попытки
Он отправляет быстрее, чем позволяет лимит скорости. Он повторяет попытку после задержки из `Retry-After`, поэтому ничего не теряется, если только его очередь не переполнится. Увеличьте лимит скорости или распределите отправку равномернее.
:::

:::details Использовано сегодня больше, чем показывает страница Использование телеметрии
Бюджет учитывает телеметрию по мере поступления, в распакованном виде, включая то, что фильтры отбрасывания удаляют позже. Страница Использование учитывает сохранённое, на следующий день.
:::

:::details Бюджеты сообщают, что сегодняшние подсчёты не удалось прочитать
OneUptime не может подключиться к Valkey, где учитываются бюджеты. Пока подключение не восстановится, телеметрия сохраняется без учёта и ни один бюджет не применяется.
:::
