# Эпизоды

Эпизод объединяет связанные инциденты или связанные оповещения, чтобы команда работала с ними как с одним целым: одно место, где их видно, один круг владельцев, одно состояние, которое подтверждают и устраняют. Правила группировки открывают эпизоды и добавляют в них инциденты и оповещения по мере их появления (см. [Правила группировки инцидентов](/docs/incidents/settings#правила-группировки-инцидентов)). Вы также можете сами добавлять инциденты в эпизод, по несколько за раз: из самого эпизода или из списков инцидентов.

Всё на этой странице так же работает и для эпизодов оповещений: читайте «оповещение» там, где написано «инцидент». Эпизоды инцидентов находятся в разделе **Инциденты → Эпизоды**, эпизоды оповещений — в разделе **Оповещения → Эпизоды**.

## Добавление инцидентов из эпизода

Откройте эпизод, выберите **Инциденты участников** в боковом меню (`/dashboard/{projectId}/incidents/episodes/{episodeId}/incidents`) и нажмите **Добавить инциденты**. В диалоге перечислены 50 самых новых инцидентов, которые вы можете видеть и которых ещё нет в эпизоде, у каждого — номер, заголовок, состояние и серьёзность. Чтобы найти более старый, ищите по заголовку или номеру: `INC-42`, `42` и `#42` находят инцидент 42.

- Отметьте столько, сколько нужно, до 100 за раз. Кнопка их считает: **Добавить элементы (Инциденты): 3**.
- Инцидент, который уже входит в другой эпизод, сообщает об этом под заголовком и называет номер того эпизода. Если добавить его сюда, он останется и там: инцидент может входить в несколько эпизодов.
- Если какие-то инциденты добавить не удалось, диалог остаётся открытым и перечисляет их с причиной; остальные добавляются.

## Добавление инцидентов из списков инцидентов

Выберите инциденты в списке **Инциденты** или в любом другом списке инцидентов, например в списке монитора, и откройте **Массовые действия**:

| Действие | Что оно делает |
| --- | --- |
| **Добавить в существующий эпизод** | Выберите один эпизод. Сначала идут продолжающиеся эпизоды, от новых к старым, затем недавно устранённые; любой другой можно найти поиском по заголовку или номеру. Перед добавлением диалог сообщает, сколько выбранных инцидентов уже входит в этот эпизод, где они остаются как есть, и сколько входит в другой эпизод, где они тоже остаются. |
| **Добавить в новый эпизод** | Создаёт эпизод с выбранными инцидентами. Запрашивает только заголовок и серьёзность, оба заполняются по самому серьёзному из выбранных инцидентов; заголовок приватного инцидента никогда не копируется. Владельцев, политики дежурств и заметки добавляйте на странице эпизода. |

Оба действия принимают до 100 выбранных инцидентов. Результат показывает, сколько добавлено, сколько уже было в эпизоде и какие не добавлены и почему, а также ссылку, открывающую эпизод.

## Что делает добавление

- **Одна запись в ленте эпизода** называет каждый добавленный инцидент: первые 20 — по номеру и заголовку, затем сколько ещё. Она публикуется один раз в канал эпизода в Slack или Microsoft Teams, а не по разу на каждый инцидент. Приватный инцидент называется только по номеру.
- **Лента каждого инцидента** сообщает, в какой эпизод он добавлен.
- **Серьёзность эпизода** повышается до серьёзности самого серьёзного инцидента, добавленного в существующий эпизод, и никогда не понижается. Новый эпизод начинается с выбранной вами серьёзности.
- **Устранённый эпизод остаётся устранённым.** Добавление не открывает его снова и никогда не меняет состояние инцидента.
- **Владельцы эпизода получают уведомление** о том, что добавлены инциденты, как и при добавлении одного инцидента. Если эпизод создаётся вместе с ними, их охватывает собственное уведомление эпизода о создании.

## Как убрать инцидент

В разделе **Инциденты участников** кнопка **Удалить** в строке или для выбранных строк в **Массовые действия** убирает инцидент только из этого эпизода. Сам инцидент не удаляется и остаётся во всех других эпизодах, в которые входит.

## Кто может добавлять

Для добавления нужно разрешение добавлять инциденты в эпизод. Оно есть у ролей Project Owner, Project Admin, Project Member, Incident Admin и Incident Member, а также у пользовательской роли с Create Incident Episode Member. Добавлять можно только те инциденты, которые вы видите: приватный инцидент могут добавить только его владельцы, а также владельцы и администраторы проекта. Для действия «Добавить в новый эпизод» нужно ещё и разрешение создавать эпизод. Если действие вам недоступно, оно заблокировано, а его подсказка называет недостающее разрешение.

## Через API

Добавьте несколько инцидентов в эпизод одним запросом:

```bash
curl -X POST 'https://oneuptime.com/api/incident-episode-member/add-incidents' \
  -H "ApiKey: $ONEUPTIME_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "incidentEpisodeId": "<episode id>",
    "incidentIds": ["<incident id>", "<incident id>"]
  }'
```

Ответ называет каждый отправленный инцидент ровно один раз: добавлен, уже в эпизоде или не добавлен и почему. Запрос, в котором больше 100 идентификаторов, отклоняется.

```json
{
  "added": ["<incident id>"],
  "alreadyInEpisode": ["<incident id>"],
  "notAdded": [
    {
      "id": "<incident id>",
      "reason": "This incident does not exist in this project, or you do not have access to it."
    }
  ]
}
```

Для оповещений отправьте `alertEpisodeId` и `alertIds` на `/api/alert-episode-member/add-alerts`. Чтобы создать эпизод сразу с инцидентами, передайте их идентификаторы в запросе, который создаёт эпизод, `POST /api/incident-episode`, в виде `{ "data": { "title": "Checkout outage" }, "miscDataProps": { "incidentIdsToAdd": ["<incident id>"] } }`; для эпизода оповещений — `POST /api/alert-episode` с `alertIdsToAdd`. Если какой-либо из них нельзя добавить, эпизод не создаётся.
