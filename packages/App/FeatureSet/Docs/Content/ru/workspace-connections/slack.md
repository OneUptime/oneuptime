# Подключение OneUptime к Slack

### Шаги по подключению OneUptime к Slack

1. **Создайте учётную запись OneUptime**

   - Перейдите на [OneUptime.com](https://oneuptime.com) и создайте учётную запись.
   - После создания учётной записи создайте новый проект.

2. **Подключите Slack к проекту OneUptime**

   - В вашем проекте OneUptime перейдите в **Настройки проекта** > **Slack**.
   - Следуйте инструкциям для подключения учётной записи Slack к проекту OneUptime.

3. **Настройте уведомления об инцидентах**

   - После подключения учётной записи Slack перейдите на **Страницу инцидентов** > **Slack**.
   - Добавьте правила для отправки уведомлений об инцидентах в Slack. Например, можно создать правило, которое создаёт новый канал Slack и приглашает ответственных за инцидент при его создании.

4. **Настройте уведомления об оповещениях и плановых работах**
   - Аналогичные правила можно применить к оповещениям и плановым работам, перейдя на соответствующие страницы и настроив нужные правила.

## Проверка правила

**Тестовое правило** в строке правила отправляет тестовое сообщение этого правила в каналы, которые оно указывает, чтобы вы увидели, что оно доходит. Если правило создаёт канал для каждого события, тест тоже создаёт канал и приглашает в него людей правила.

Как и **Отправить тест** рядом с каналом в **Настройки проекта** > **Workspace** > **Slack**, для этого нужно право создавать правила уведомлений: **Project Owner**, **Project Admin**, **Project Member**, **Settings Admin**, **Settings Member** или **Create Workspace Notification Rule** и **Read Workspace Notification Rule** в пользовательской роли. Для того, кто может только просматривать правила, например **Viewer**, кнопка **Тестовое правило** заблокирована, а подсказка говорит, что для неё нужно; API отклоняет его тест с сообщением «You do not have permission to send test notifications in this project.» В OneUptime Cloud проверка правила, как и его добавление, требует тарифа **Growth**.

В OneUptime Cloud **Отправить тест** рядом с каналом тоже требует тарифа **Growth**: публиковать в канал — это то, что делают правила и сводки. **Отправить тест сейчас** у сводки требует права создавать сводки (**Create Workspace Notification Summary** и **Read Workspace Notification Summary** в пользовательской роли), а в OneUptime Cloud — тарифа **Growth**; для всех остальных кнопка заблокирована, а подсказка говорит, что для неё нужно. MCP-клиент, подключённый только для чтения, не может отправить ни одного теста.

## Сводки

Вкладка **Summary** в разделе **Инциденты** > **Workspace** > **Slack** (и в разделе **Оповещения**) регулярно публикует обзор в указанных вами каналах: сколько было инцидентов или оповещений, как быстро их подтвердили и устранили, и список со ссылками. Новая сводка отправляется каждую неделю и охватывает последние 7 дней. Оставьте поле **Отправить первый отчёт в** пустым, и первая сводка уйдёт в 09:00 в начале следующей недели, дня или месяца; форма покажет, когда именно.

Сводка отправляется по часам, заданным в поле **Часовой пояс**, где изначально стоит ваш часовой пояс. Там она сохраняет своё время весь год: сводка, настроенная на 09:00 в Берлине, и после перевода часов приходит в 09:00 по берлинскому времени, а даты в её сообщении тоже берлинские. Через API передавайте `timezone` как имя часового пояса IANA, например `Europe/Berlin`. Сводка, созданная без него, получает часовой пояс из профиля своего создателя или UTC, если её создаёт ключ API.
