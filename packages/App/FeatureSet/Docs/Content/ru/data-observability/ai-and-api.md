# OneUptime AI и API

OneUptime AI знает ваши данные: он расследует оповещение о данных, начиная с тех, кто пишет в таблицу, её запусков и вышестоящих таблиц, отвечает, актуальна ли таблица, где бы его ни спросили, и пишет проверку по правилу, сформулированному одной фразой. Всё, что показывает Наблюдаемость данных, доступно и вашим собственным инструментам — через её эндпоинты, метрики и MCP-сервер.

## OneUptime AI

- **Расследования оповещений о данных.** Когда OneUptime AI расследует оповещение по таблице, пайплайну или базе данных, он начинает с того, что находится рядом: с актуальности таблицы и её открытых оповещений, с оповещения, следствием которого оно является, с запусков пайплайнов, которые пишут в таблицу, начиная с предыдущего дня (неудачный запуск с его ошибкой или запуск, который так и не состоялся), с сервисов, которые пишут в неё, с их неудачными записями, развёртываниями и другими изменениями, с таблиц, из которых она строится, и со столбцов, которые изменились. Он называет запуск, развёртывание или вышестоящую таблицу, которые стоят за оповещением. См. [AI SRE](/docs/ai/ai-sre).
- **Актуальна ли эта таблица?** Спросите через [Спросить ИИ](/docs/ai/ask-ai), Slack или Microsoft Teams: «актуальна ли таблица orders?». Ответ покажет актуальность таблицы по её собственному ритму, время последнего изменения, открытые оповещения, последние запуски тех, кто в неё пишет, и продукты данных, в которые она входит. Если одно имя есть в нескольких базах данных, ответ даётся для каждой из них, чтобы никому не сказали, что актуальна не та таблица.
- **Проверка по фразе.** На вкладке **Проверки** таблицы **Написать проверку по фразе** превращает правило в проверку «Свой SQL» на SQL вашей СУБД. См. [Проверки и сверки](/docs/data-observability/checks).

- **Медленный дрейф.** Если число строк таблицы или значение проверки за неделю меняется на пятую часть или больше, слишком медленно для любого оповещения, это попадает в «Аналитика ИИ» как подсказка «посмотрите сюда». Никого не вызывает.
- **Устаревшие данные за AI-приложениями.** Сервис, который и вызывает модель, и читает таблицу, считается AI-потребителем этой таблицы. Когда такая таблица опаздывает, об этом говорит страница **Разговоры** AI-продукта: приложение, отвечающее по старым данным, ничего не показывает в собственных трассировках.

Для каждой из этих возможностей в проекте должен быть включён OneUptime AI, и каждая действует с разрешениями того, кто спрашивает.

## ИИ-агенты и MCP-сервер

ИИ-агентам стоит проверять, что данные актуальны, прежде чем их использовать. Для этого у [MCP-сервера](/docs/ai/mcp-server) есть инструмент только для чтения:

| Инструмент | На что он отвечает |
| --- | --- |
| `get_data_table_freshness` | Актуальна ли отслеживаемая таблица, когда она менялась в последний раз, её открытые оповещения, последние запуски тех, кто в неё пишет, и её продукты данных. Передайте `table` как `schema.table`, только имя таблицы или её ID |

Он работает со входом только для чтения и отвечает от имени человека или API-ключа, под которым выполнен вход.

## Эндпоинты

| Эндпоинт | Для чего он | Чем подписан |
| --- | --- | --- |
| `POST /telemetry/openlineage/api/v1/lineage` | События OpenLineage из Airflow, Dagster, Spark, dbt или Flink | Ключ приёма телеметрии |
| `POST /telemetry/dbt/v1/artifacts` | `manifest` и `run_results` сборки dbt | Ключ приёма телеметрии |
| `POST /telemetry/fivetran/v1/webhook/<ingestion key ID>` | Вебхуки синхронизаций Fivetran | Ключ приёма как секрет подписи Fivetran |
| `POST /telemetry/airbyte/v1/webhook/<ingestion key>` | Вебхуки синхронизаций Airbyte | Ключ приёма в URL |
| `POST /api/data-observability/tables/freshness` | Актуальность таблицы в том виде, в каком её возвращает инструмент MCP, с `{ "table": "public.orders" }` | API-ключ |
| `POST /api/data-observability/checks/apply` | Приводит проверки проекта в соответствие с файлом, как это делает `oneuptime data-checks apply`, с `{ "manifest": "...", "isDryRun": true, "shouldPrune": false }` | API-ключ |
| `GET /api/data-observability/data-products/<data product ID>/badge?token=<badge token>` | Значок «data as of» продукта данных | Собственный токен значка |

Таблицы, проверки, сверки, пайплайны, продукты данных, BI-подключения и задания хранилищ — это также обычные ресурсы [API](/docs/api-reference/api-reference), которые читаются и изменяются с API-ключом, у которого есть соответствующие разрешения, а также ресурсы MCP-сервера и рабочих процессов.

## Метрики

Каждое число, которое хранит Наблюдаемость данных, — это метрика, которую можно вывести на график, разместить на дашборде или использовать для оповещений: `oneuptime.data.table.*` для каждой таблицы, `oneuptime.data.check.value` для каждой проверки, `oneuptime.data.reconciliation.*` для каждой сверки, `oneuptime.data.pipeline.*` для каждого пайплайна и `oneuptime.data.product.*` для каждого продукта данных. Это собственные эксплуатационные данные OneUptime, и они не тарифицируются как телеметрия.
