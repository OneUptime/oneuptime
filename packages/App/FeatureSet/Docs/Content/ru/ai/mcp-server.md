# MCP-сервер

MCP-сервер OneUptime (Model Context Protocol) предоставляет LLM прямой доступ к вашему экземпляру OneUptime, обеспечивая мониторинг на основе AI, управление инцидентами и операции наблюдаемости.

## Что такое MCP-сервер OneUptime?

MCP-сервер OneUptime — это мост между большими языковыми моделями (LLM) и вашим экземпляром OneUptime. Он реализует протокол Model Context Protocol (MCP), позволяя AI-ассистентам, таким как Claude, напрямую взаимодействовать с вашей инфраструктурой мониторинга.

## Как это работает

MCP-сервер размещён вместе с вашим экземпляром OneUptime и доступен через транспорт Streamable HTTP. Локальная установка не требуется.

**Облачные пользователи**: `https://oneuptime.com/mcp`
**Пользователи с самостоятельным размещением**: `https://your-oneuptime-domain.com/mcp`

## Ключевые возможности

- **~155 инструментов**: Полные CRUD-инструменты для 22 типов ресурсов (инциденты, алерты, мониторы, страницы статуса, дежурство и другое), инструменты телеметрии только для чтения, а также рабочие и вспомогательные инструменты
- **Операции в реальном времени**: Создание, чтение, обновление и удаление ресурсов в реальном времени
- **Типобезопасный интерфейс**: Полностью типизированный с комплексной валидацией входных данных
- **Безопасная аутентификация**: Вход с учётной записью OneUptime (OAuth 2.1) или передача ключа API в каждом запросе для агентов, работающих без участия человека
- **Аннотации безопасности**: Инструменты только для чтения помечены `readOnlyHint`, а инструменты удаления — `destructiveHint`, поэтому MCP-клиенты могут автоматически одобрять безопасные вызовы и запрашивать подтверждение перед разрушительными
- **Простая интеграция**: Работает с Claude Desktop и другими MCP-совместимыми клиентами
- **Отсутствие состояния по замыслу**: Никаких идентификаторов сессий — каждый запрос самодостаточен, поэтому сервер работает за балансировщиками нагрузки и в развёртываниях с несколькими репликами

## Что вы можете делать

С MCP-сервером OneUptime AI-ассистенты могут помочь вам:

- **Управление мониторами**: Создавать и настраивать мониторы, проверять их статус и просматривать историю статусов
- **Реагирование на инциденты**: Создавать, подтверждать и разрешать инциденты, добавлять внутренние или публичные заметки и отслеживать разрешение
- **Операции с командой**: Управлять командами и политиками дежурств
- **Страницы статуса**: Управлять страницами статуса и создавать объявления
- **Алертинг**: Подтверждать и разрешать алерты, добавлять заметки к алертам и управлять состояниями и уровнями серьёзности алертов
- **Запланированное техническое обслуживание**: Создавать запланированные события технического обслуживания и управлять ими
- **Телеметрия**: Запрашивать логи, метрики, трассировки, исключения и логи мониторов (только чтение)

## Требования

- Экземпляр OneUptime (облачный или с самостоятельным размещением)
- MCP-совместимый клиент (Claude Desktop, VS Code с GitHub Copilot и т.д.)
- Учётная запись OneUptime для входа или ключ API OneUptime для агента, работающего без участия человека (требуется только для аутентифицированных операций — публичные инструменты работают без того и другого)

## Вход через OneUptime

Самый простой способ подключиться — указать MCP-клиенту URL сервера и больше ничего. Когда клиенту впервые понадобятся ваши данные, он откроет в вашем браузере страницу OneUptime, на которой вы:

1. Входите в OneUptime, если ещё не вошли
2. Выбираете проект, в котором должен работать клиент
3. Выбираете, что разрешить клиенту: **чтение и запись** или **только чтение**
4. Нажимаете **Разрешить**

После этого клиент действует в этом проекте от вашего имени. Нет ключа API, который нужно создавать, копировать или ротировать, и в файле конфигурации не хранится ничего секретного.

Что может делать подключённый клиент:

- **У него ваши разрешения — и никогда не больше.** Клиент может делать ровно то, что ваши команды разрешают делать вам в проекте. Если ваша роль изменится или вы покинете проект, это будет учтено уже при следующем запросе клиента. Уход из проекта также отключает клиента: его авторизация удаляется, и если вы вернётесь в проект, клиента нужно будет подключить снова.
- **Только чтение значит только чтение.** Клиент, которому разрешено только чтение, может использовать инструменты `get_`, `list_` и `count_`. Инструменты, которые создают, обновляют, удаляют, подтверждают (acknowledge) или разрешают (resolve), отклоняются — и MCP-сервером, и стоящим за ним API OneUptime. Вы никогда не сможете дать клиенту больше доступа, чем он запросил.
- **Он действует в одном проекте.** Чтобы работать со вторым проектом, подключите клиент ещё раз и выберите этот проект.
- **Он работает только через MCP-сервер.** Токен доступа клиента принимается конечной точкой MCP и больше нигде. Его нельзя использовать для прямых вызовов REST API OneUptime.
- **Администраторы экземпляра не получают особых привилегий.** Клиент, подключённый мастер-администратором, получает то, что команды этого человека дают ему в проекте, а не доступ ко всему экземпляру.

### Управление подключёнными клиентами

Каждый клиент, подключённый через вход, отображается в разделе **Настройки проекта** → **MCP-сервер** → **Connected MCP Clients** (подключённые MCP-клиенты) — с указанием того, кто его подключил, что ему разрешено и когда он использовался в последний раз. Вы видите клиенты, которые подключили сами; владельцы и администраторы проекта видят клиенты всех участников.

Нажмите **Disconnect** (отключить), чтобы завершить сеанс клиента. Он немедленно перестаёт работать.

Клиент остаётся подключённым, пока им пользуются. Клиент, которым не пользовались 30 дней, должен войти заново.

### Управление тем, кто может подключать клиенты

По умолчанию любой участник проекта может подключить MCP-клиент. Чтобы запретить это участникам какой-либо команды, откройте команду, перейдите в раздел **Заблокировать разрешения** и добавьте разрешение **Authorize MCP Client** (авторизация MCP-клиента). Клиенты, уже подключённые этими участниками, сразу перестанут работать.

Если в проекте требуется единый вход (SSO), войдите в проект через SSO в браузере, прежде чем разрешать клиенту доступ. Подключение клиента действует, пока действует этот вход через SSO; когда он истечёт, подключите клиент заново.

В OneUptime Cloud подключение MCP-клиента доступно на тех же тарифах, что и ключи API (Growth и выше).

В Enterprise Edition каждое изменение, внесённое подключённым клиентом, записывается в журнал аудита от имени того, кто подключил клиент, вместе с названием клиента. Для изменений, внесённых с помощью ключа API, указывается название ключа.

## Получение ключа API

Используйте ключ API для агента, работающего без участия человека, — запланированного задания или конвейера CI, — когда войти в систему некому.

1. Войдите в ваш экземпляр OneUptime
2. Перейдите в **Настройки проекта** → **Ключи API**
3. Нажмите **Create API Key**
4. Укажите имя (например, "MCP Server")
5. Выберите соответствующие разрешения для вашего случая использования
6. Скопируйте сгенерированный ключ API

Ключи API привязаны к проекту: MCP-сервер определяет ваш проект по ключу, поэтому инструментам создания никогда не требуется аргумент `projectId`.

> **Предупреждение — никогда не передавайте AI-агенту мастер-ключ.** *Мастер*-ключ API OneUptime также принимается в этом заголовке и предоставляет административный доступ ко всему экземпляру. Всегда используйте ключ API проекта с минимально необходимыми агенту привилегиями (ключа только для чтения достаточно для всех инструментов `get_`/`list_`/`count_`).

## Конфигурация

### Подключение через вход в учётную запись

Добавьте URL сервера в клиент без учётных данных. Для экземпляра с самостоятельным размещением используйте `https://your-oneuptime-domain.com/mcp`.

**Claude Code**

```bash
claude mcp add --transport http oneuptime https://oneuptime.com/mcp
```

Затем выполните `/mcp` в Claude Code и выберите **oneuptime**, чтобы войти.

**Claude (веб-версия и приложение для компьютера)**

Откройте **Customize** → **Connectors**, выберите **Add custom connector** и введите `https://oneuptime.com/mcp`. Claude попросит вас войти в OneUptime, когда ему впервые понадобятся ваши данные.

**VS Code с GitHub Copilot**

Добавьте это в конфигурацию MCP (где находится этот файл, см. в разделе [VS Code с GitHub Copilot](#vs-code-с-github-copilot)). При запуске сервера VS Code откроет OneUptime, чтобы вы могли войти:

```json
{
  "servers": {
    "oneuptime": {
      "type": "http",
      "url": "https://oneuptime.com/mcp"
    }
  }
}
```

**Cursor**

```json
{
  "mcpServers": {
    "oneuptime": {
      "url": "https://oneuptime.com/mcp"
    }
  }
}
```

Любой другой клиент, поддерживающий авторизацию MCP, работает так же: укажите ему URL, и всё остальное он обнаружит сам. Подробности протокола см. в разделе [Вход (OAuth 2.1)](#вход-oauth-21).

## Доступные конечные точки

| Конечная точка | Метод  | Описание                                                                                                                    |
| -------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `/mcp`         | POST   | Запросы JSON-RPC для вызовов инструментов и других операций                                                                    |
| `/mcp`         | GET    | Без SSE-заголовка `Accept`: дружелюбный JSON-ответ для обнаружения. С ним: `405` — сервер без состояния не предоставляет отдельный SSE-поток (совместимые клиенты продолжают работу без него) |
| `/mcp`         | DELETE | Ничего не делает (сервер не хранит состояние, поэтому завершать нечего — сессии отсутствуют)                                    |
| `/mcp/health`  | GET    | Конечная точка проверки работоспособности                                                                                      |
| `/mcp/tools`   | GET    | REST API для перечисления доступных инструментов                                                                               |

MCP-клиенты, выполняющие вход, также используют перечисленные ниже конечные точки OAuth. Клиент находит их сам; здесь они приведены для тех, кто пишет клиент или настраивает прокси.

| Конечная точка                                | Метод  | Описание |
| --------------------------------------------- | ------ | ------------------------------------------------------------------------ |
| `/mcp/.well-known/oauth-protected-resource`   | GET    | Метаданные защищённого ресурса (RFC 9728). Также доступны по адресу `/.well-known/oauth-protected-resource/mcp` |
| `/.well-known/oauth-authorization-server/mcp` | GET    | Метаданные сервера авторизации (RFC 8414). Также доступны по адресу `/mcp/.well-known/oauth-authorization-server` |
| `/mcp/oauth/authorize`                        | GET    | Конечная точка авторизации: сюда клиент направляет ваш браузер для входа |
| `/mcp/oauth/token`                            | POST   | Конечная точка токенов: обменивает код авторизации или токен обновления |
| `/mcp/oauth/register`                         | POST   | Динамическая регистрация клиентов (RFC 7591) |
| `/mcp/oauth/revoke`                           | POST   | Отзыв токенов (RFC 7009) |

## Аутентификация

MCP-сервер поддерживает три режима работы:

### Публичные инструменты (аутентификация не требуется)

Вы можете подключиться к MCP-серверу без ключа API для доступа к публичным инструментам:

- **`oneuptime_help`**: Получение справки и руководства по возможностям MCP OneUptime
- **`oneuptime_list_resources`**: Перечисление доступных ресурсов и их операций
- **`get_public_status_page_overview`**: Получение обзора публичной страницы статуса
- **`get_public_status_page_incidents`**: Получение инцидентов с публичной страницы статуса
- **`get_public_status_page_scheduled_maintenance`**: Получение запланированных событий технического обслуживания
- **`get_public_status_page_announcements`**: Получение объявлений с публичной страницы статуса

Инструменты публичной страницы статуса принимают как идентификатор страницы статуса (UUID), так и доменное имя страницы статуса.

### Вход (OAuth 2.1)

Для всех других операций (управление мониторами, инцидентами, командами и т.д.) вызывающая сторона должна быть идентифицирована. Клиент, который не передаёт учётных данных и вызывает один из таких инструментов, получает ответ `401 Unauthorized` и заголовок `WWW-Authenticate`, указывающий на метаданные защищённого ресурса сервера. Именно по этому сигналу MCP-клиент запускает ваш вход; `initialize`, `tools/list` и публичные инструменты никогда не требуют входа.

Сервер реализует [спецификацию авторизации MCP](https://modelcontextprotocol.io/specification/latest/basic/authorization):

- **Поток**: код авторизации OAuth 2.1 с PKCE (только `S256`). Токены доступа передаются в виде `Authorization: Bearer`.
- **Обнаружение**: метаданные защищённого ресурса (RFC 9728) и метаданные сервера авторизации (RFC 8414). Издатель (issuer) и ресурс — в обоих случаях `https://<host>/mcp`.
- **Идентификация клиента**: Client ID Metadata Document (идентификатор клиента — это URL `https`, который запрашивает сервер) или динамическая регистрация клиентов (Dynamic Client Registration, RFC 7591). Администратору не нужно регистрировать ни один клиент.
- **Области действия (scopes)**: `mcp:read` — для инструментов `get_`, `list_` и `count_`; `mcp:write` добавляет все инструменты, которые что-либо изменяют, и включает `mcp:read`. Токен только для чтения, вызвавший инструмент записи, получает в ответ `403` и `error="insufficient_scope"`.
- **Срок действия токенов**: токен доступа действует один час. Токен обновления (refresh token) действует 30 дней и заменяется при каждом использовании; использование уже заменённого токена обновления завершает подключение.
- **Индикаторы ресурса** (RFC 8707): токен выдаётся для `https://<host>/mcp` и больше нигде не принимается.
- **Отзыв** (RFC 7009): отзыв любого из двух токенов завершает подключение.

### Ключ API

Агент, работающий без участия человека, аутентифицируется с помощью ключа API OneUptime в одном из следующих заголовков:

- `x-api-key`: Ваш ключ API OneUptime
- `Authorization`: Токен Bearer с вашим ключом API (например, `Bearer your-api-key-here`)

Схема `Bearer` нечувствительна к регистру. От запроса, содержащего ключ API, вход никогда не требуется.

Ошибки инструментов возвращаются как обычные результаты инструментов (`isError: true`) с полем `statusCode`, подробностями и рекомендацией — а не как ошибки протокола MCP, — поэтому агенты могут прочитать причину сбоя и исправиться самостоятельно.

## Рабочие инструменты

Помимо CRUD-инструментов для отдельных ресурсов, сервер включает специализированные рабочие инструменты для реагирования на инциденты и алерты:

- **`acknowledge_incident`** / **`resolve_incident`**: Перевод инцидента в состояние Acknowledged или Resolved проекта — эквивалент нажатия кнопки в панели управления
- **`acknowledge_alert`** / **`resolve_alert`**: То же самое для алертов
- **`add_incident_note`**: Добавление заметки к инциденту с `visibility: "internal"` (только для команды, по умолчанию) или `visibility: "public"` (публикуется на странице статуса). Поддерживается Markdown
- **`add_alert_note`**: Добавление внутренней заметки к алерту

Типичный цикл: `list_incidents` → `acknowledge_incident` → расследование с помощью `list_logs` → `add_incident_note` (публичная) → `resolve_incident`.

## Кто я

Инструмент **`oneuptime_whoami`** возвращает проект, которому принадлежат ваши учётные данные (идентификатор и имя). Для клиента, выполнившего вход, он также возвращает, от чьего имени выполнен вход и может ли клиент вносить изменения. Это полезный первый вызов, позволяющий агенту сориентироваться, — а поскольку инструменты создания определяют `projectId` по учётным данным, агенту никогда не нужно передавать идентификатор проекта.

## Запросы к телеметрии

Логи, метрики, трассировки (спаны), исключения и логи мониторов доступны через инструменты `list_` и `count_` только для чтения (`list_logs`, `list_metrics`, `list_spans`, `list_exception_instances`, `list_monitor_logs` и их аналоги `count_`). Телеметрия поступает через OpenTelemetry, поэтому инструментов создания нет.

Всегда запрашивайте телеметрию с фильтром по временному диапазону. Поля запроса принимают либо непосредственное значение, либо объект оператора:

```json
{
  "query": {
    "time": { "_type": "GreaterThan", "value": "2026-07-04T00:00:00.000Z" }
  },
  "sort": { "time": "DESC" },
  "limit": 50
}
```

Поддерживаемые операторы: `EqualTo`, `NotEqual`, `IsNull`, `NotNull`, `EqualToOrNull`, `GreaterThan`, `LessThan`, `GreaterThanOrEqual`, `LessThanOrEqual`, `InBetween`, `Search`, `Includes`. Значения сортировки — `"ASC"` или `"DESC"`.

## Выбор полей и пагинация

Инструменты `get_` и `list_` принимают необязательный массив `select` с именами полей. По умолчанию возвращаются все читаемые поля, кроме тяжёлых (столбцы JSON, очень длинный текст и HTML), которые нужно явно запрашивать в `select`.

Инструменты списков поддерживают пагинацию через `limit` (по умолчанию 10, максимум 100) и `skip`, и каждый ответ списка точно сообщает, что было возвращено:

```json
{
  "returnedCount": 10,
  "totalCount": 42,
  "skip": 0,
  "limit": 10,
  "hasMore": true,
  "data": ["..."]
}
```

## Разрешения ключей API

### Доступ только для чтения

Для просмотра данных добавьте разрешения на чтение для вашего ключа API.

### Полный доступ

Для полного доступа к созданию, обновлению и удалению ресурсов убедитесь, что ваш ключ API имеет разрешения администратора проекта.

### Рекомендации

- Ротируйте ключи API: Регулярно обновляйте ключи API
- Следите за использованием: Отслеживайте использование ключей API в OneUptime
- Используйте отдельные ключи: Применяйте разные ключи API для разных сред

## Конфигурация при самостоятельном размещении

На экземпляре с самостоятельным размещением вход работает без дополнительной настройки. Доступны два параметра:

| Переменная окружения | Значение Helm | Что делает |
| --- | --- | --- |
| `DISABLE_MCP_OAUTH` | `mcpOAuth.disabled` | Установите `true`, чтобы отключить вход. Конечные точки OAuth перестают обслуживаться, и MCP-сервер принимает только ключи API. Ничего не удаляется; подключённые клиенты снова заработают, когда параметр будет возвращён в прежнее состояние. |
| `DISABLE_MCP_OAUTH_CLIENT_ID_METADATA_DOCUMENTS` | `mcpOAuth.disableClientIdMetadataDocuments` | Установите `true` на экземпляре без доступа к интернету. Клиент может идентифицировать себя с помощью URL, который запрашивает OneUptime; если параметр установлен, клиенты вместо этого регистрируются непосредственно на вашем экземпляре, для чего исходящий запрос не нужен. |

Если перед OneUptime у вас работает собственный обратный прокси, пересылайте `/.well-known/oauth-protected-resource` и `/.well-known/oauth-authorization-server` (и все вложенные в них пути) в OneUptime вместе с `/mcp`. Входящий в комплект ingress уже делает это.

Сервер строит все URL OAuth на основе параметров `HOST` и `HTTP_PROTOCOL`, поэтому они должны соответствовать адресу, по которому пользователи обращаются к вашему экземпляру.

## Устранение неполадок

### Проблемы со входом

- **Клиент никогда не предлагает мне войти**: возможно, клиент не поддерживает авторизацию MCP или в его конфигурации указан заголовок с ключом API, который имеет приоритет. Удалите заголовок, чтобы использовать вход.
- **Мой проект отображается серым на странице авторизации**: причина указана на странице рядом с названием проекта — тариф проекта не включает подключение MCP-клиентов, проект требует SSO, а в этом браузере вход в него через SSO не выполнен, либо вашей команде запрещено подключать клиенты.
- **Инструмент отклоняется с сообщением "read-only"**: клиенту было разрешено только чтение. Подключите его заново и выберите **Чтение и запись**.
- **Клиент перестал работать**: он был отключён, не использовался 30 дней, вас удалили из проекта или истёк срок действия входа в проект через SSO. Подключите его заново.
- **Самостоятельное размещение — клиент сообщает, что не может найти сервер авторизации**: проверьте, что `HOST` и `HTTP_PROTOCOL` соответствуют вашему публичному адресу и что ваш прокси пересылает пути `/.well-known/oauth-*`.

### Ошибки разрешений

Убедитесь, что ваш ключ API — или, в случае клиента, выполнившего вход, ваша собственная учётная запись — имеет необходимые разрешения:

- Доступ на чтение для перечисления ресурсов
- Доступ на запись для создания/обновления ресурсов
- Доступ на удаление, если вы хотите удалять ресурсы

### Проблемы с подключением

1. Убедитесь, что URL OneUptime указан правильно
2. Проверьте, что ваш ключ API действителен
3. Убедитесь, что ваш экземпляр OneUptime доступен
4. Проверьте конечную точку работоспособности

### Недействительный ключ API

- Проверьте ключ API в настройках OneUptime
- Проверьте наличие лишних пробелов или символов
- Убедитесь, что срок действия ключа не истёк

### Ошибки сессии

Если вы получаете ошибки, связанные с сессией:

- MCP-сервер не хранит состояние — он не выдаёт и не отслеживает идентификаторы сессий, поэтому каждый запрос работает с любой репликой сервера
- Клиенты, отправляющие заголовок `mcp-session-id` от предыдущей версии сервера, могут просто не передавать его; он игнорируется
- Обновите конфигурации старых MCP-клиентов, которые ожидают, что сервер вернёт идентификатор сессии

## Доступные ресурсы

MCP-сервер предоставляет инструменты для следующих ресурсов:

**Мониторинг**: монитор, статус монитора, событие статуса монитора
**Инциденты**: инцидент, состояние инцидента, серьёзность инцидента, хронология состояний инцидента, публичная заметка инцидента, внутренняя заметка инцидента
**Алерты**: алерт, состояние алерта, серьёзность алерта, хронология состояний алерта, внутренняя заметка алерта
**Страницы статуса**: страница статуса, объявление страницы статуса
**Запланированное техническое обслуживание**: событие запланированного технического обслуживания, состояние запланированного технического обслуживания, хронология состояний запланированного технического обслуживания
**Команды и дежурство**: команда, политика дежурств
**Метки**: метка
**Телеметрия (только чтение)**: лог, метрика, спан, экземпляр исключения, лог монитора

Каждый ресурс базы данных поддерживает операции Create, Get, List, Update, Delete и Count через инструменты в snake_case — например, `create_incident`, `get_incident`, `list_incidents`, `update_incident`, `delete_incident`, `count_incidents`. Ресурсы телеметрии предоставляют только инструменты `list_` и `count_` (например, `list_logs`, `count_spans`).
