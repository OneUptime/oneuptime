# Проверки обновлений и безопасности

Раз в день самостоятельно размещённый OneUptime спрашивает GitHub, не вышел ли более новый выпуск и не затрагивает ли версию, которая у вас работает, какой-либо бюллетень безопасности, опубликованный OneUptime. Если затрагивает, ваших главных администраторов просят обновиться. На этой странице описано, что отправляет проверка, что вы видите и как её отключить.

:::cards
- [Что отправляет проверка](#что-отправляет-проверка): Два публичных вопроса и ничего о вашей установке.
- [Что вы видите](#что-вы-видите): Подвал, панель администратора и по одному письму на каждый бюллетень.
- [Как отключить проверку](#как-отключить-проверку): Для сети без доступа к интернету или чтобы использовать зеркало.
:::

## Что отправляет проверка

Воркер отправляет в API GitHub (`api.github.com`) два запроса без токена:

| Запрос | Что он спрашивает |
| --- | --- |
| `GET /repos/OneUptime/oneuptime/releases/latest` | Какой выпуск OneUptime последний |
| `GET /repos/OneUptime/oneuptime/security-advisories?state=published` | Какие бюллетени безопасности опубликовал OneUptime, какие версии затрагивает каждый из них и какой выпуск его исправляет |

В них нет ничего о вашей установке: ни версии, которая у вас работает, ни её адреса, ни сведений о ваших пользователях, проектах или данных мониторинга. GitHub видит публичный IP-адрес вашего сервера, как и при любом запросе, и `User-Agent`, в котором указан OneUptime. Затрагивает ли бюллетень вашу версию, определяется на вашем сервере, и ни один браузер не обращается к GitHub.

Проверка выполняется при запуске воркера и затем раз в день. Повторно она обращается к GitHub не чаще чем раз в 12 часов, а после неудачного запроса — не чаще чем раз в час.

## Что вы видите

Сообщается только главным администраторам. Обновить сервер могут именно они, а сообщить кому-то ещё, что сервер работает на версии с известной проблемой безопасности, значило бы указать на сервер без исправлений.

- Более новый выпуск добавляет **Доступно обновление** в подвал Dashboard и панели администратора. Эта метка открывает руководство по обновлению.
- Если версию, которая у вас работает, затрагивает опубликованный бюллетень безопасности, вместо этого там появляется **Обновление безопасности**, выделенное красным.
- Тогда первая страница панели администратора перечисляет каждый такой бюллетень: его уровень серьёзности, затронутые версии, выпуск с исправлением и ссылку на бюллетень на GitHub. Там же указано, когда проверка в последний раз читала бюллетени и почему последняя проверка не удалась, если это случилось.
- Ваши главные администраторы и адрес из «Email уведомлений администратора» (**Настройки** > **Email** в панели администратора) получают по одному письму о каждом бюллетене, который затрагивает вашу версию, и никогда — второе.

Всё это исчезает, как только вы переходите на версию, которую не затрагивает ни один бюллетень. О том, как обновиться, см. [Обновление](/docs/installation/upgrading).

## Как отключить проверку

В сети без доступа к интернету или если ваш сервер не должен обращаться к GitHub, отключите проверку. Тогда ничего не показывается и не отправляется по почте.

:::tabs
@tab Kubernetes
```yaml
updateCheck:
  disabled: true
```
@tab Docker Compose
```bash
DISABLE_UPDATE_CHECK=true
```
Задайте это в `config.env`, затем выполните `npm start`.
:::

Чтобы вместо этого сверяться с зеркалом внутри вашей сети, направьте проверку на него. Зеркало должно отвечать в том же формате, что и GitHub.

| Значение Helm | Параметр Docker Compose | По умолчанию |
| --- | --- | --- |
| `updateCheck.url` | `LATEST_RELEASE_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/releases/latest` |
| `updateCheck.securityAdvisoriesUrl` | `SECURITY_ADVISORIES_CHECK_URL` | `https://api.github.com/repos/OneUptime/oneuptime/security-advisories` |

## Когда GitHub недоступен

В сети без доступа к интернету неудачный запрос ожидаем и не считается ошибкой. Воркер записывает его в лог на уровне debug, сохраняет то, что прочитал в последний раз, и повторяет попытку позже. Панель администратора показывает, когда бюллетени читались в последний раз и почему последняя проверка не удалась: ограничение частоты запросов GitHub, нет маршрута до GitHub, тайм-аут или ответ не от GitHub.
