# Шлюз SMS и звонков

OneUptime может отправлять свои SMS и звонки не через Twilio, а через шлюз, который вы держите сами. Используйте его, когда ваши правила требуют, чтобы каждое сообщение проходило через вашего собственного провайдера SMS и голосовой связи или через систему, которая проверяет его, прежде чем оно покинет вашу сеть. OneUptime отправляет каждое SMS и каждый звонок на ваш шлюз в виде подписанного JSON-запроса, а ваш шлюз их доставляет.

:::cards
- [Настройка шлюза](#настройка-шлюза): URL и секрет подписи, созданный для вас.
- [Что получает ваш шлюз](#что-получает-ваш-шлюз): Один подписанный JSON-запрос на каждое SMS или звонок.
- [Действия с вызовом](#действия-с-вызовом): Подтвердить, эскалировать или устранить из звонка или ответного сообщения.
- [Доставка и повторы](#доставка-и-повторы): Что происходит, когда ваш шлюз недоступен.
:::

## Как это работает

```mermaid title="SMS через ваш собственный шлюз"
flowchart LR
    OneUptime["OneUptime"]
    Gateway["Ваш шлюз"]
    Provider["Ваш провайдер SMS и голосовой связи"]
    Phone["Телефон"]
    OneUptime -->|"подписанный JSON-запрос"| Gateway
    Gateway --> Provider
    Provider --> Phone
```

Шлюз заменяет собственную учётную запись Twilio сервера во всём, что шло бы через неё: вызовы дежурных, уведомления, коды подтверждения и SMS подписчикам страниц статуса. Проекты, которые добавляют собственную конфигурацию Twilio на карточке **Конфигурация Twilio** в разделе **Настройки проекта > Уведомления > Настройки уведомлений**, по-прежнему отправляют через эту конфигурацию. Переключатели SMS и звонков каждого проекта, а там, где включён биллинг, и его баланс проверяются так же, как для Twilio.

## Настройка шлюза

:::steps
1. В Admin Dashboard перейдите в **Настройки > Звонок и SMS** и нажмите **Edit Provider** на карточке **SMS and Call Provider**.
2. Выберите **Your own gateway** и введите **Gateway URL**. Шлюз может находиться в вашей частной сети.
3. Сохраните. OneUptime создаёт для вас секрет подписи. Скопируйте его с карточки в свой шлюз.
4. Нажмите **Send Test**. Ваш шлюз должен ответить статусом 2xx и ничего не отправлять.
:::

Чтобы заменить секрет, очистите **Signing Secret** в разделе **Дополнительные поля** и сохраните: OneUptime создаст новый. Чтобы вернуться к Twilio, выберите **Twilio** и сохраните.

## Что получает ваш шлюз

Каждое SMS и каждый звонок — это один запрос `POST` с телом в формате JSON и такими заголовками:

| Заголовок | Значение |
| --- | --- |
| `Content-Type` | `application/json` |
| `X-OneUptime-Event` | `sms`, `call` или `test` |
| `X-OneUptime-Signature` | `sha256=`, за которым следует HMAC-SHA256 тела в шестнадцатеричном виде, вычисленный с секретом подписи в качестве ключа |
| `User-Agent` | `OneUptime-CallAndSmsGateway/1.0` |

```json title="An on-call page by SMS"
{
  "version": 1,
  "event": "sms",
  "id": "7c5b0d0e-3e5f-4d1a-9a4f-2b8e6c1d9f00",
  "sentAt": "2026-10-27T09:30:00.000Z",
  "to": "+15551234567",
  "message": "OneUptime: A new alert has been created. Alert #42: Database is down…",
  "isSensitive": false,
  "project": {
    "id": "0f6b8c3a-1d2e-4f5a-8b9c-0d1e2f3a4b5c",
    "name": "Production"
  },
  "actions": {
    "acknowledge": "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/acknowledge?token=…",
    "escalate": "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/escalate?token=…",
    "resolve": "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/resolve?token=…"
  }
}
```

| Поле | Что это |
| --- | --- |
| `version` | Для этой формы всегда `1`. Поля в неё только добавляются. |
| `event` | `sms`, `call` или `test`, как в `X-OneUptime-Event`. |
| `id` | Уникален для этого сообщения и одинаков во всех попытках его доставить: по нему можно пропустить сообщение, которое вы уже отправили. |
| `sentAt` | Когда OneUptime его отправил, в формате ISO 8601. |
| `to` | Номер телефона в формате E.164. `null` в тесте. |
| `message` | Текст SMS или то, что говорится в звонке. SMS содержит не более 1600 символов, текст звонка — не более 16 384. Более длинный текст обрезается и заканчивается пометкой о том, что остальное есть в OneUptime. |
| `isSensitive` | `true` для кода подтверждения. Не допускайте попадания этого сообщения в собственные логи. |
| `project` | `id` и `name` проекта или `null`, если сообщение отправил не проект. |
| `actions` | Для вызова дежурного — ссылки, которые действуют на этот вызов. В остальных случаях `null`. |

Звонок описывается, а не задаётся сценарием: `message` — это то, что в нём говорится, без «нажмите 1, чтобы подтвердить» из Twilio. Предложите действия по-своему, например через нажатия клавиш, и вызовите соответствующую ссылку.

### Проверка подписи

Вычислите HMAC необработанного тела запроса до его разбора и сравните его с заголовком. Проверка та же, что и для [пользовательского канала](/docs/self-hosted/custom-notification-channels#проверка-подписи), поэтому одна функция проверки подходит для обоих:

```javascript title="Node.js"
const crypto = require("crypto");

function isFromOneUptime(rawBody, signatureHeader, secret) {
  const expected =
    "sha256=" + crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  const received = String(signatureHeader || "");

  return (
    received.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(received), Buffer.from(expected))
  );
}
```

## Действия с вызовом

Когда человек отвечает во время звонка или ответным сообщением, ваш шлюз отправляет запрос `POST` по соответствующей ссылке из `actions`. Ссылки работают так же, как у пользовательского канала: им не нужен ключ API, каждая несёт токен только для этого вызова, действительный 7 дней, и действие записывается как выполненное человеком, которого вызвали. Каждое действие и ответ описаны в разделе [Действия с вызовом](/docs/self-hosted/custom-notification-channels#действия-с-вызовом).

```bash title="Acknowledge a page"
curl -X POST "https://oneuptime.example.com/api/custom-notification-channel/page/5f2c…/acknowledge?token=…"
```

## Доставка и повторы

Запрос считается доставленным, когда ваш шлюз отвечает статусом 2xx в течение 10 секунд. Запрос, на который он не ответил или ответил статусом 408, 429 или 5xx, отправляется повторно через 1 секунду и ещё через 4 секунды: всего три попытки. При любом другом статусе 4xx запрос повторно не отправляется.

В журнале SMS или звонков, а для вызова дежурного и в журнале дежурств этого человека, указано `Sent to the SMS and call gateway (HTTP 200).` или причина, по которой сообщение не было доставлено, но никогда не URL. OneUptime не узнаёт, дошло ли сообщение до телефона, поэтому SMS отображается как отправленное, как только ваш шлюз его принимает, а номер, с которого оно ушло, остаётся пустым.

## Тестовые запросы

**Send test** отправляет запрос, в котором `event` равен `test`, а `to`, `project` и `actions` равны `null`. Ответьте на него статусом 2xx и ничего не отправляйте.
