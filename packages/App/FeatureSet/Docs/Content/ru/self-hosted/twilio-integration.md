# Интеграция SMS и голосовых звонков Twilio

Самостоятельно размещённый OneUptime использует вашу учётную запись Twilio для отправки SMS и голосовых оповещений. Вы платите Twilio напрямую. Настройте учётные данные в панели управления OneUptime: доставка уведомлений использует сохранённую конфигурацию, а в Helm-чарте нет параметров учётных данных Twilio. Ранее миграция импортировала `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` и `TWILIO_PHONE_NUMBER`; изменение этих переменных не является способом обновления учётных данных существующей установки.

## 1. Подготовьте учётную запись Twilio

1. Откройте [консоль Twilio](https://console.twilio.com/) и получите **Account SID** и **Auth Token**.
2. Получите телефонный номер Twilio с необходимыми возможностями SMS и/или голосовых звонков. Используйте формат E.164 с кодом страны для номеров отправителя и получателя.
3. Проверьте баланс учётной записи, разрешения для стран назначения и применимые требования регистрации отправителя. Пробные учётные записи имеют ограничения по получателям, географии и другим параметрам, которые могут помешать работе настоящих оповещений OneUptime; перед тестированием ознакомьтесь с [документацией Twilio об учётных записях и пробном периоде](https://www.twilio.com/docs/usage/tutorials/how-to-use-your-free-trial-account). Для промышленной эксплуатации используйте учётную запись с платным тарифом.

## 2. Сохраните учётные данные в OneUptime

Для проекта:

1. Перейдите в **Project Settings > Notifications > Notification Settings**.
2. В разделе **Twilio Config** выберите **Create Twilio Config**.
3. Введите имя, **Twilio Account SID**, **Twilio Auth Token** и **Twilio Primary Phone Number**. При необходимости укажите через запятую **Twilio Secondary Phone Numbers** для других стран.
4. Включите **Set as Project Default**, чтобы использовать эту конфигурацию для SMS и звонков участникам проекта, включая уведомления дежурных. Создание конфигурации без включения этого переключателя не выбирает её для таких уведомлений.
5. Сохраните изменения. Только одна конфигурация может использоваться в проекте по умолчанию. Страницы статуса используют конфигурацию, явно назначенную каждой странице.

Для настройки значения по умолчанию для всей установки администратор может вместо этого открыть **Admin Dashboard > Settings > Call and SMS**, изменить учётные данные Twilio и телефонные номера и сохранить их. Уведомления участников используют эту глобальную конфигурацию, если у проекта нет конфигурации по умолчанию. Храните Auth Token в тайне.

## 3. Настройте сетевой доступ

Закрытой установке требуется исходящий HTTPS-доступ к Twilio для отправки запросов на SMS и звонки. Twilio рекомендует разрешить исходящий HTTPS к `*.twilio.com`, поскольку адреса API динамические; см. [IP-адреса Twilio](https://help.twilio.com/articles/115015934048-All-About-Twilio-IP-Addresses). Примените это к исходящему трафику приложения OneUptime, включая Kubernetes NetworkPolicies и внешние межсетевые экраны. Разрешите разрешение DNS-имён и исходящий HTTPS (TCP 443) из приложения OneUptime.

Необходимость входящего доступа зависит от функции:

| Функция | Требуется ли Twilio доступ к OneUptime? |
| --- | --- |
| Запрос на отправку SMS | Нет. Однако для обновлений статуса доставки нужен обратный вызов. |
| Простой тестовый голосовой звонок | Нет. OneUptime передаёт голосовые инструкции в исходящем запросе API. |
| Нажатие 1 для подтверждения оповещения дежурного | Да. Twilio передаёт нажатия клавиш в OneUptime. |
| Политики входящих звонков | Да. Twilio запрашивает инструкции для звонков и сообщает результаты дозвона. |

Ниже приведены внешние пути через шлюз Nginx OneUptime; заполнители различаются для каждого уведомления:

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/notification/sms/status-callback/:smsLogId/:token` | Статус доставки SMS |
| POST | `/api/user-notification-log-timeline/call/gather-input/:itemId?token=...` | Подтверждение нажатием клавиши |
| POST | `/notification/incoming-call/voice` | Необязательные инструкции для входящих звонков |
| POST | `/notification/incoming-call/dial-status/:callLogId/:callLogItemId` | Необязательные результаты маршрутизации входящих звонков |

OneUptime автоматически создаёт URL для SMS и подтверждений. Не заменяйте их токены статическим URL вебхука. Для входящих звонков следуйте руководству [Политики входящих звонков](/docs/on-call/incoming-call-policy), которое настраивает вебхук номера при его подключении.

Twilio требует [общедоступные URL вебхуков](https://www.twilio.com/docs/usage/webhooks/webhooks-overview). Используйте общедоверенный сертификат TLS и сохраняйте исходные хост, протокол, путь, параметры запроса, тело запроса и заголовок `X-Twilio-Signature` при передаче через прокси. Обработчики входящих звонков проверяют подписи Twilio; доставка SMS использует отдельный URL-токен для каждого сообщения, а подтверждение нажатием клавиши — подписанный токен в параметрах запроса. Не раскрывайте токены в общих журналах или снимках экрана. См. [Безопасность вебхуков Twilio](https://www.twilio.com/docs/usage/webhooks/webhooks-security).

### Промышленная эксплуатация: опубликуйте шлюз к закрытой установке

1. **Выберите имя хоста**, например `oneuptime.example.com`. Опубликуйте DNS-записи, указывающие на шлюз, доступный из интернета. Частные IP-адреса и внутренние DNS-имена недоступны провайдерам. При разделённом DNS сотрудники могут разрешать то же имя хоста в адрес закрытого ingress и продолжать использовать панель управления через VPN. Закрытый ingress также должен обслуживать HTTPS с сертификатом, действительным для этого имени хоста.

2. **Подключите шлюз к OneUptime.** Разместите его в DMZ с маршрутом к закрытому ingress либо используйте публичный шлюз, подключённый через ваш собственный VPN между площадками/частный канал. Разрешите трафик от шлюза к ingress на порту внутренней службы. Для Kubernetes/Portainer одной закрытой службы `ClusterIP` недостаточно: шлюзу нужен ingress/controller или другая доступная внутренняя служба. Оставьте базы данных и другие внутренние службы закрытыми.

3. **Завершайте HTTPS на порту 443** с общедоверенным сертификатом и полной цепочкой промежуточных сертификатов. Разрешите входящий TCP 443 к шлюзу. Установка сертификата или изменение DNS сами по себе не создают маршрут к закрытой внутренней службе.

4. Опубликуйте только пути обратных вызовов из таблицы выше через шлюз Nginx OneUptime, который направляет `/notification` в приложение. Сохраните `/api` в пути подтверждения нажатием клавиши. Сохраните метод, путь, строку запроса, тело и заголовки аутентификации (`X-Twilio-Signature`). Сохраните публичный `Host` и задайте доверенные заголовки `X-Forwarded-Host` и `X-Forwarded-Proto: https`. Не добавляйте перенаправления.

5. Исключите эти пути из браузерного SSO, CAPTCHA и страниц входа прокси. Оставьте аутентификацию OneUptime включённой. Разрешите доступ к исходному серверу только шлюзу и авторизованным внутренним клиентам; скрывайте токены в журналах.

6. **Задайте канонический URL OneUptime**:

   Docker Compose, в `config.env`:

   ```dotenv
   HOST=oneuptime.example.com
   HTTP_PROTOCOL=https
   ```

   Значения Helm/Portainer:

   ```yaml
   host: oneuptime.example.com
   httpProtocol: https
   ```

   Замените пример своим доменом. Эти параметры формируют URL, но не создают DNS, TLS или правила межсетевого экрана. Примените конфигурацию Compose или обновление Helm и дождитесь перезапуска приложения. В OneUptime нет отдельного имени хоста для обратных вызовов Twilio. При изменении имени обновите также вебхуки существующих телефонных номеров Twilio.

[Параметры доступа к закрытой сети](/docs/self-hosted/private-network-access) управляют исходящими запросами OneUptime к внутренним службам. Включение `ALLOW_PRIVATE_NETWORK_WEBHOOKS` не делает OneUptime доступным для Twilio.

### Исходящий доступ и ограничения IP

Адреса источников обычных вебхуков Twilio меняются; не используйте SIP- или медиа-диапазоны как список разрешённых адресов. Подходящие редакции предоставляют [Static Proxy for Webhooks](https://www.twilio.com/docs/iam/twilio-editions/twilio-static-proxy). Проверьте условия и поддерживаемые продукты, затем настройте межсетевой экран по актуальным опубликованным диапазонам. Продолжайте аутентифицировать обратные вызовы.

### Тестирование и установки без входящего доступа

Без входящего доступа отправка SMS и простое голосовое воспроизведение могут работать через исходящий HTTPS. Статусы доставки, подтверждение клавишей и маршрутизация входящих звонков требуют доступных обратных вызовов. Полностью отключённая от сети установка не может использовать Twilio.

Для разработки [руководство Twilio по тестированию вебхуков](https://www.twilio.com/docs/usage/webhooks/webhook-testing) описывает публичный туннель. Направьте его на прокси, разрешающий только необходимые пути, настройте полученное имя хоста, как описано выше, и остановите туннель после тестирования. Туннель всё равно предоставляет входящий доступ.

## 4. Проверяйте доставку и обратные вызовы отдельно

1. Из-за пределов корпоративной сети и VPN проверьте, что имя хоста обратных вызовов разрешается в публичный шлюз и предъявляет действительный сертификат TLS. GET из браузера не проверяет эти POST-вызовы.
2. Используйте **Send Test SMS** и **Send Test Call** в конфигурации Twilio проекта. Подтвердите получение на телефоне адресата.
3. Настройте подтверждённый контакт пользователя для SMS/звонков и правила уведомлений, затем инициируйте контролируемое оповещение дежурного. Нажмите 1 и проверьте подтверждение в OneUptime. Если вы используете политики входящих звонков, позвоните на настроенный номер и проверьте маршрутизацию и журнал звонков.
4. Проверьте статус доставки SMS в OneUptime и журналах сообщений Twilio. Принятый запрос на отправку не доказывает доставку; [Twilio сообщает о последующих изменениях статуса через обратные вызовы](https://www.twilio.com/docs/messaging/guides/track-outbound-message-status).

Если отправка не удаётся, проверьте учётные данные, возможности номера, ограничения учётной записи и исходящее подключение. Если сообщение или звонок поступает, но статус или подтверждение не обновляется, изучите URL обратного вызова и журналы публичного ingress. [Руководство Twilio по ошибкам получения HTTP-ресурсов](https://www.twilio.com/docs/api/errors/11200) помогает диагностировать недоступные обратные вызовы, проблемы TLS и ошибки HTTP. Успешный тестовый звонок сам по себе не проверяет доступность обратных вызовов.
