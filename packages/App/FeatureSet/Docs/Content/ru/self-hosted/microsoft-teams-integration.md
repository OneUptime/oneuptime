# Интеграция с Microsoft Teams

Для интеграции Microsoft Teams с вашим самостоятельно размещённым экземпляром OneUptime необходимо настроить регистрацию приложения Azure и задать необходимые переменные среды.

## Предварительные требования

- Учётная запись Azure — создайте на [https://azure.com](https://azure.com)
- Доступ к конфигурации вашего сервера OneUptime

## Сетевой доступ

OneUptime использует Azure Bot для интеграции с Teams. URL Incoming Webhook или Teams Workflow не заменяет конечную точку сообщений этого бота. Microsoft требует [общедоступную конечную точку HTTPS для самостоятельно размещённого бота](https://learn.microsoft.com/en-us/azure/bot-service/bot-service-resources-faq-security?view=azure-bot-service-4.0). Частный IP-адрес, внутреннее DNS-имя или VPN-подключение сотрудника не предоставляют Azure Bot Service доступ к OneUptime.

| Функция | От OneUptime к провайдеру | От провайдера к OneUptime |
| --- | --- | --- |
| Уведомления Teams | HTTPS к API Microsoft | Требуется для полной интеграции бота, включая обнаружение бесед |
| Команды Teams, кнопки карточек, события установки в чатах | HTTPS | `POST /api/microsoft-bot/messages` |

Перенаправления регистрации приложения `/api/microsoft-teams/auth` и `/api/microsoft-teams/admin-consent/callback` возвращаются через браузер пользователя. Этот браузер должен иметь доступ к OneUptime, например через корпоративную сеть или VPN. Сообщения бота и действия с карточками поступают с серверов Microsoft и требуют собственного доступного ingress. Исходящая доставка оповещений сама по себе не проверяет входящее подключение.

### Промышленная эксплуатация: опубликуйте шлюз к закрытой установке

1. **Выберите имя хоста**, например `oneuptime.example.com`. Опубликуйте DNS-записи, указывающие на шлюз, доступный из интернета. Частные IP-адреса и внутренние DNS-имена недоступны провайдерам. При разделённом DNS сотрудники могут разрешать то же имя хоста в адрес закрытого ingress и продолжать использовать панель управления через VPN. Закрытый ingress также должен обслуживать HTTPS с сертификатом, действительным для этого имени хоста.

2. **Подключите шлюз к OneUptime.** Разместите его в DMZ с маршрутом к закрытому ingress либо используйте публичный шлюз, подключённый через ваш собственный VPN между площадками/частный канал. Разрешите трафик от шлюза к ingress на порту внутренней службы. Для Kubernetes/Portainer одной закрытой службы `ClusterIP` недостаточно: шлюзу нужен ingress/controller или другая доступная внутренняя служба. Оставьте базы данных и другие внутренние службы закрытыми.

3. **Завершайте HTTPS на порту 443** с общедоверенным сертификатом и полной цепочкой промежуточных сертификатов. Разрешите входящий TCP 443 к шлюзу. Установка сертификата или изменение DNS сами по себе не создают маршрут к закрытой внутренней службе.

4. Опубликуйте только `/api/microsoft-bot/messages` и укажите этот полный общедоступный HTTPS-URL как конечную точку сообщений Azure Bot на шаге 4. Адаптер Bot Framework в OneUptime должен получать и аутентифицировать запросы. Сохраните метод, путь, строку запроса, тело и заголовки аутентификации (`Authorization`). Сохраните публичный `Host` и задайте доверенные заголовки `X-Forwarded-Host` и `X-Forwarded-Proto: https`. Не добавляйте перенаправления.

5. Исключите эти пути из браузерного SSO, CAPTCHA и страниц входа прокси. Оставьте аутентификацию OneUptime включённой. Разрешите доступ к исходному серверу только шлюзу и авторизованным внутренним клиентам; скрывайте токены в журналах.

6. **Задайте канонический URL OneUptime**:

   Docker Compose, в `config.env`:

   ```dotenv
   HOST=oneuptime.example.com
   HTTP_PROTOCOL=https
   ```

   Значения Helm/Portainer:

   ```yaml
   host: oneuptime.example.com
   httpProtocol: https
   ```

   Замените пример своим доменом. Эти параметры формируют URL, но не создают DNS, TLS или правила межсетевого экрана. Примените конфигурацию Compose или обновление Helm и дождитесь перезапуска приложения. При изменении имени хоста обновите конечную точку Azure Bot и URI перенаправления регистрации приложения, затем заново скачайте и загрузите манифест Teams.

[Параметры доступа к закрытой сети](/docs/self-hosted/private-network-access) управляют исходящими запросами OneUptime к внутренним службам. Включение `ALLOW_PRIVATE_NETWORK_WEBHOOKS` не делает OneUptime доступным для Teams.

### Исходящий доступ и ограничения IP

Разрешите разрешение DNS-имён и исходящий HTTPS (TCP 443) из приложения OneUptime. Teams использует `graph.microsoft.com`, `login.microsoftonline.com`, конечные точки аутентификации и каналов Bot Framework и URL службы соединителя для беседы. Используйте [рекомендации Microsoft по межсетевым экранам](https://learn.microsoft.com/en-us/azure/bot-service/bot-service-resources-faq-security?view=azure-bot-service-4.0) и проверяйте заблокированный трафик при тестировании; приведённые примеры не являются полным списком доменов. Резервный соединитель коммерческого облака — `https://smba.trafficmanager.net/teams/`; URL службы конкретной беседы может отличаться.

Microsoft не поддерживает фиксированные списки разрешённых входящих IP-адресов Bot Framework, поскольку адреса меняются. Медиа-диапазоны клиентов Teams не являются источниками вебхуков бота. Оставьте аутентификацию Bot Framework включённой.

### Тестирование и установки без входящего доступа

Из сети вне вашей VPN проверьте публичные DNS и TLS, затем проверьте маршрут Teams:

```bash
curl -sS -i https://oneuptime.example.com/api/microsoft-bot/messages
```

В текущих версиях OneUptime ожидается `405 Method Not Allowed` с `Allow: POST`. Это подтверждает, что GET-запрос достиг маршрута, но не гарантирует работу аутентифицированного POST-запроса бота. Старые версии могут возвращать JSON-ошибку 404 OneUptime; проверьте тело ответа и журналы прокси. Ошибки TLS, тайм-ауты или HTML-страница ошибки прокси указывают на проблемы с сертификатом или маршрутизацией.

Подключите Teams, отправьте тестовое уведомление, напишите боту и нажмите кнопку карточки. Проверьте действие в OneUptime и сопоставьте диагностику Microsoft с журналами шлюза и приложения. Доставленное уведомление не проверяет аутентифицированный входящий POST.

Для разработки [руководство Microsoft по тестированию Teams](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/how-to/authentication/add-authentication#testing-the-bot-locally-in-teams) описывает публикацию локальной службы с помощью туннеля. Направляйте трафик на ingress OneUptime и используйте `/api/microsoft-bot/messages` вместо примера пути Microsoft `/api/messages`. Обновляйте конечную точку Azure Bot при каждом изменении публичного URL туннеля, а для промышленной эксплуатации используйте постоянный ingress. Настройте также соответствующее имя хоста OneUptime. Остановите туннель после тестов: он всё равно предоставляет входящий доступ.

Если все входящие подключения запрещены, полная интеграция Teams не работает: команды, действия карточек и обнаружение бесед зависят от них. Полностью отключённая от сети установка не может использовать Teams.

Azure Bot Private Endpoint не заменяет этот ingress для Teams. [Инструкции Microsoft по сетевой изоляции](https://learn.microsoft.com/en-us/azure/bot-service/dl-network-isolation-how-to?view=azure-bot-service-4.0) описывают изоляцию Direct Line и указывают, что отключение публичного сетевого доступа удаляет конфигурацию каналов Teams.

## Инструкции по настройке

### Шаг 1: Создание регистрации приложения Azure

1. Перейдите на [портал Azure](https://portal.azure.com)
2. Откройте «Регистрации приложений» и нажмите «Новая регистрация»
3. Заполните форму регистрации:
   - **Имя:** oneuptime
   - **Поддерживаемые типы учётных записей:** Учётные записи в любом каталоге организации (Any Microsoft Entra ID tenant - Multitenant)
   - **URI перенаправления:** Web - `https://your-oneuptime-domain.com/api/microsoft-teams/auth`
   - Также добавьте: `https://your-oneuptime-domain.com/api/microsoft-teams/admin-consent/callback`
4. Нажмите «Зарегистрировать»
5. Запишите «Идентификатор приложения (клиента)» — он понадобится позже

### Шаг 2: Настройка разрешений приложения

1. В регистрации приложения перейдите в «Разрешения API»
2. Нажмите «Добавить разрешение» и выберите «Microsoft Graph»

**Добавьте делегированные разрешения** (при действии от имени вошедшего пользователя):

- **User.Read** — необходимо для получения профиля аутентифицированного пользователя (отображаемое имя, email) в процессе OAuth
- **Team.ReadBasic.All** — необходимо для просмотра команд, в которых состоит пользователь, при выборе команды для подключения
- **Channel.ReadBasic.All** — необходимо для чтения информации о каналах и их списков для доставки уведомлений
- **ChannelMessage.Send** — необходимо для отправки оповещений и уведомлений об инцидентах в каналы Teams

**Добавьте разрешения для приложения** (при действии от имени самого приложения без вошедшего пользователя):

- **Team.ReadBasic.All** — необходимо для просмотра всех команд в организации после предоставления согласия администратора
- **Channel.ReadBasic.All** — необходимо для проверки существования канала и получения его сведений

`ChannelMessage.Send` — только делегированное разрешение; в [справочнике разрешений Microsoft Graph](https://learn.microsoft.com/en-us/graph/permissions-reference#channelmessagesend) у него нет варианта разрешения приложения. Оставьте его в списке делегированных разрешений выше.

**Примечание:** Bot Framework обрабатывает доставку сообщений с использованием разрешений Resource-Specific Consent (RSC), определённых в манифесте приложения Teams:

- **ChannelMessage.Send.Group** — позволяет боту отправлять сообщения в каналы команды
- **ChannelMessage.Read.Group** — позволяет боту читать сообщения в каналах для интерактивных команд
- **Channel.Create.Group** — позволяет боту создавать каналы при необходимости

3. Нажмите «Предоставить согласие администратора» для вашей организации

### Шаг 3: Создание секрета клиента

1. Перейдите в «Сертификаты и секреты» в регистрации приложения
2. Нажмите «Новый секрет клиента»
3. Добавьте описание и установите срок действия (рекомендуется 24 месяца)
4. Нажмите «Добавить» и немедленно скопируйте значение секрета — просмотреть его повторно не получится

**Важно:** Скопируйте значение секрета, а не его идентификатор — значение обычно длиннее и содержит больше символов.

### Шаг 4: Создание службы Bot

1. На портале Azure откройте «Azure Bot» и нажмите «Создать»
2. Заполните форму создания бота:

   - **Bot handle:** oneuptime-bot
   - **Подписка:** ваша подписка Azure
   - **Группа ресурсов:** создайте новую или используйте существующую
   - **Расположение:** выберите ближайшее к пользователям
   - **Ценовая категория:** F0 (Бесплатно) достаточно для тестирования
   - Используйте идентификатор приложения (клиента) и идентификатор клиента из регистрации приложения, созданной ранее

3. Нажмите «Проверить + создать», затем «Создать»

4. После развёртывания откройте ресурс бота и перейдите в «Конфигурация»
5. Установите «Конечная точка для обмена сообщениями» на `https://your-oneuptime-domain.com/api/microsoft-bot/messages`
6. Сохраните конфигурацию

### Шаг 5: Добавление канала Microsoft Teams к боту

1. В ресурсе Azure Bot перейдите в «Каналы»
2. Найдите и выберите «Microsoft Teams», нажмите «Открыть» или «Добавить»
3. Просмотрите параметры (включите для Teams, оставьте параметры обмена сообщениями по умолчанию, если нет особых требований)
4. Нажмите «Сохранить» (и «Готово»/«Опубликовать» при запросе) для включения канала Teams

### Шаг 6: Настройка переменных среды OneUptime

#### Docker Compose

При использовании Docker Compose добавьте следующие переменные среды в вашу конфигурацию:

```bash
MICROSOFT_TEAMS_APP_CLIENT_ID=YOUR_TEAMS_APP_CLIENT_ID
MICROSOFT_TEAMS_APP_CLIENT_SECRET=YOUR_TEAMS_APP_CLIENT_SECRET
MICROSOFT_TEAMS_APP_TENANT_ID=YOUR_MICROSOFT_TENANT_ID
```

#### Kubernetes с Helm

При использовании Kubernetes с Helm добавьте следующие значения в файл `values.yaml`:

```yaml
microsoftTeamsApp:
  clientId: YOUR_TEAMS_APP_CLIENT_ID
  clientSecret: YOUR_TEAMS_APP_CLIENT_SECRET
  tenantId: YOUR_MICROSOFT_TENANT_ID
```

**Важно:** Перезапустите сервер OneUptime после добавления переменных среды, чтобы изменения вступили в силу.

### Шаг 7: Загрузка манифеста приложения Teams

1. Перейдите в **Настройки проекта** > **Рабочее пространство** > **Microsoft Teams**
2. Загрузите манифест приложения Teams оттуда
3. Откройте Microsoft Teams и нажмите «Приложения» на боковой панели
4. Внизу нажмите «Управление приложениями»
5. Нажмите «Загрузить пользовательское приложение»
6. Выберите «Загрузить для меня или моих команд»
7. Загрузите ранее скачанный zip-файл манифеста

## Устранение неполадок

При возникновении проблем:

- Убедитесь, что приложению предоставлены необходимые разрешения
- Проверьте точное совпадение URI перенаправления (замените `your-oneuptime-domain.com` на ваш реальный домен)
- Убедитесь в правильности переменных среды
- Убедитесь, что конечная точка обмена сообщениями бота доступна из интернета
- Убедитесь в правильности настройки бота с каналом Teams
- Убедитесь, что манифест приложения Teams был успешно загружен
