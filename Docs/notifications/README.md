# Writing notifications

Feed items, chat messages, emails, SMS, calls and push notifications carry text that people and monitored systems wrote: names, titles, labels, response bodies, logs, screenshots. Three rules keep that text safe, fast and private. Read this before you write a feed item, a message for any channel or an email template, or code that reads or converts such text.

## Feed and chat Markdown

Feed items and Slack / Microsoft Teams messages are Markdown with people's text in them: names, titles, labels, rule names. Write that Markdown with the `mdText` tag from [`packages/Common/Utils/Markdown/FeedMarkdown.ts`](../../packages/Common/Utils/Markdown/FeedMarkdown.ts). It escapes every value for where it sits (a sentence, a link's words or address, a code span, a table row, the start of a line), and places a `MarkdownText` (built with `mdText` or a `FeedMarkdown` helper) as it is, so nothing is escaped twice.

- Join pieces with `FeedMarkdown.join` / `bulletList` / `numberedList`, not `Array.join` or `+`, and never turn a `MarkdownText` into a string to place it again.
- Markdown a person wrote goes in with `FeedMarkdown.asMarkdown`, OneUptime AI's with `FeedMarkdown.aiWritten` (`aiWrittenForTeams` for the Teams bot), and text from outside OneUptime with `FeedMarkdown.writtenOutside` / `reportedValue`.
- Only `packages/Common/Utils/Markdown/` imports `MarkdownEscape` or `UntrustedMarkdown`.

[`FeedAndChatPlainTextEscapedGuard`](../../packages/Common/Tests/Server/Services/FeedAndChatPlainTextEscapedGuard.test.ts) enforces this for every feed and chat sink, including `ee/Server`.

## Megabyte-long values

Any text a notification carries can be megabytes on one line, or a paragraph of a hundred thousand lines: a synthetic monitor's screenshot reaches descriptions and emails as several megabytes of base64, a description template can place a response body or a log, and a person can paste a log into a note. Everything that handles such text must run in time linear in its input, whatever its shape.

### Regular expressions

Do not run a regular expression with an unbounded quantifier over a value that long. V8 backtracks on a stack that can grow with every character a quantifier takes, and a process that has been running a while compiles regular expressions without optimization, so they run out of stack ("Maximum call stack size exceeded") on about three megabytes - in production, and in a CI test worker that has already run many test files.

- Scan such a value with a loop or `indexOf`, like `isBase64` in `packages/Common/Utils/Markdown/InlineImageDataUri.ts`.
- A regular expression that can cross lines gets a bounded quantifier (`{0,65536}`, as in `Markdown.convertToPlainText`), and a step that only needs a loop uses one.

### Markdown parsers

The Markdown parsers - marked for emails, remark for the Dashboard and for slackify - read lines and paragraphs with regular expressions, or in time that grows with their square. So:

- Keep a screenshot's data out of the parser: `holdBackBase64Data` (`packages/Common/Utils/Markdown/Base64Data.ts`) holds it back from marked (`Markdown.holdBackFromMarked`) and from remark (`packages/Common/UI/Components/Markdown.tsx/MarkdownViewerOverLongText.ts`) alike. Read as Markdown, base64 is one long word of punctuation, which the slow-Markdown measure below would hold back as text, and the Dashboard would show the screenshot as text.
- Before a parser reads such Markdown, hold back what is too long with `holdBackOverLongText` (`packages/Common/Utils/Markdown/OverLongText.ts`: the middle of every line over 64 KB, and the plain lines of every run of lines over 64 KB), and write it back, escaped, where the parser put the token - as the email renderer (`Markdown.holdBackFromMarked`) and `MarkdownViewer` (`MarkdownViewerOverLongText.ts`) do. A link, an image or a link reference definition that runs from a line's kept start into its middle keeps its shape: the rest of its address and its title are held back as two pieces, with the white space between them in view, so the parser still reads the link with its title (`holdBackMiddle`); one that runs from the middle into the line's kept end keeps its `[` (an image's `![`) and `](` in view; a word cut at the start of the middle is held back alone, up to its trailing punctuation. Markdown of at most 64 KB holds back nothing and renders exactly as before.
- A token in an image's or link's address does not survive remark-rehype, which percent-encodes it, so the viewer puts addresses back in the Markdown tree first (`remarkPutBackHeldUrls`). remark-rehype also copies a link reference definition's address and title into every reference to it, so what is put back there is limited in all (`MAX_HELD_TEXT_IN_REFERENCES`): a 3 MB screenshot defined once and referenced 200 times is 600 MB of HTML. marked does the same for an email. There the first reference to a definition renders as an image's or a link's own address does, and every later one is a copy: copies of screenshots put back at most `MAX_EMAIL_HELD_TEXT_IN_REFERENCES` (8 MiB) per field; copies of any other address and copies of titles stay in the HTML, and each kind writes at most `MAX_EMAIL_COPIED_HTML_IN_REFERENCES` (64 KiB, a quarter of what a field keeps) - past that, an image is the too-large note, a link its text, and a title is left out; a copy of a held-back title writes nothing, and an address an email cannot keep (a `data:` link) nothing (`Markdown.withHeldDataInUrls`). The email's tokenizer (`EmailMarkedTokenizer`) gives marked a mark in place of each definition's address and title, so marked never holds a copy of them for each reference. An email field cut to fit (`Markdown.cutEmailMarkdown`) keeps the definitions its kept references need, before the kept part, so a screenshot defined at the end of a long field still shows: `packages/Common/Utils/Markdown/LinkReferenceDefinitions.ts` finds them where marked does, with loops - in block quotes and list items too (to 16 levels deep, as deep as an email reads nesting), right after a setext heading or an HTML block, and never inside HTML, code or a table. A definition in a quote or a list item comes on a line of its own, as marked reads it there: without the quote's markers or the item's bullet and indentation.
- marked, remark and slackify read some shapes in quadratic time far below 64 KB - emphasis, brackets or code spans that never close, a long word of punctuation, a `_` inside words for remark, long tables and lists - and 64 KB of one took from seconds to over a minute. Before a parser reads Markdown longer than 2 KB, `holdBackSlowMarkdown` (`packages/Common/Utils/Markdown/SlowMarkdown.ts`) measures its blocks in one pass and holds back the costly ones whole, written back as text, with each parser's limits (`EMAIL_SLOW_MARKDOWN_LIMITS`, `VIEWER_SLOW_MARKDOWN_LIMITS`, `SlackUtil.SLOW_MARKDOWN_LIMITS`). A new converter does the same. For the emails, a block is counted as marked reads it (`countAsMarked`): a link, an image or a reference whose label closes costs marked a copy of its block, a link's address and title are read once, and so is a definition, label and all - so a paragraph of a thousand references, a block of a thousand definitions, or a link to an address with a long query, renders as links. The measure itself stays linear: a link's address that does not close is read again by each link inside it, so the link tails of a line read at most `MARKED_TAIL_READING_SHARE` (8) times the line, and past that a link counts as one that does not close. A newly found slow shape gets counted in `getInlineCharacterCount` or `getWordPunctuationWork` (for marked, in `readMarkedLine`), and a timed entry in the tests below.
- When too much is still left - long tables, logs whose lines hold a `|`, a `<` or a backtick - show the text as written: an email field with more than `MAX_MARKED_EMAIL_MARKDOWN_LENGTH` (1 MiB) left, or a RangeError from marked, is sent as escaped text, and the viewer shows more than `MAX_PARSED_MARKDOWN_LENGTH` (128 KB) as text.

### Message sizes

- Chat messages are cut before any converter reads them, ending with a note: Slack at `SlackUtil.MARKDOWN_MAX_LENGTH` (`cutMarkdown`), and Teams to an 80 KB message (`MicrosoftTeamsMessageSize.fitMarkdownText`).
- Every message is held to what its channel takes, measured as it is sent, and a cut one ends with "… (truncated — see OneUptime for the full text)": an email field to `MAX_EMAIL_FIELD_HTML_BYTES` and a whole email to `MAX_EMAIL_BYTES` (`packages/Common/Server/Utils/Mail/EmailSize.ts`; the note links to the record), a Teams card to its channel's budget (`MicrosoftTeamsMessageSize.fitAdaptiveCard`, `MICROSOFT_TEAMS_INCOMING_WEBHOOK_BUDGET_IN_BYTES`), and SMS, call, push, WhatsApp, Telegram and Discord messages to their providers' limits (`packages/Common/Utils/MessageFit.ts`, `TelegramMessageFit.ts`, `WhatsAppTemplateFit.ts`). A new channel or sender is held the same way.

## Emails load nothing from outside the installation

An email is read wherever its reader is - on a network without the internet, behind a mail gateway that flags remote images - and every image it fetches tells whoever serves it who opened the email, and when. (Every email's header once loaded its logo from res.cloudinary.com.) So an email's own markup loads nothing it does not carry:

- An image is either inside the email, or an address the installation builds on its own host and hands the template (a logo its operator uploaded). OneUptime's logo (`oneUptimeLogoUrl`, `packages/Common/Server/Utils/Mail/EmailLogo.ts`) and screenshots go out as inline attachments that the HTML points at by Content-ID (`EmailInlineImages.ts`).
- Just before an email is sent, a logo an operator uploaded - the installation's own, or a status page's - goes inside the email in place of its address when it is a PNG, JPEG or GIF of at most 512 KB (`EmailCarriedLogos.ts`; the readers are `getCarriedProductLogo` in App's EmailBranding and `StatusPageCarriedLogo`, which the notification service registers when it starts). Any other logo keeps its address.
- Never a CDN, a web font, a tracking pixel or any other address that a template or the code that writes email markup spells out. The only host a template names is `oneuptime.com`, in the footer's link of an installation that is not renamed.

[`EmailsLoadNothingFromOutside.test.ts`](../../packages/App/Tests/Notification/EmailsLoadNothingFromOutside.test.ts) renders and sends every template on every transport.
