# Виджеты

Виджет — это одна плитка на дашборде. Эта страница перечисляет все виджеты, которые можно добавить, что они показывают и в каком случае к ним обращаться.

О том, как перетаскивать виджеты по холсту, читайте в разделе [Создание дашборда](/docs/dashboards/authoring).

## Графики и числа

### Chart

Линейный, столбчатый или площадной график одной или нескольких метрических серий за временной диапазон дашборда.

**Настройки**:

- Один или несколько запросов к метрикам.
- Опциональная формула, объединяющая два запроса (например, `errors / total * 100`, чтобы получить процент ошибок).
- Опция «показывать как rate» для накопительных счётчиков, которые растут без сброса.
- Параметры отображения: с накоплением или наложением, единица оси Y, положение легенды, тип графика.

Используйте, когда: важны тренды. Задержки во времени, число ошибок, глубина очереди — всё, где форма линии рассказывает историю.

### Value

Одно большое число с опциональными цветными порогами.

**Настройки**:

- Запрос к метрике, возвращающий одно число (последнее значение, среднее или максимум за временной диапазон).
- Опциональный порог **warning** (жёлтый, когда выше).
- Опциональный порог **critical** (красный, когда выше).
- Формат числа и единица измерения.

Используйте, когда: на вопрос отвечает одно число. Текущая частота ошибок, P95 задержек прямо сейчас, число открытых инцидентов.

### Gauge

Круговой индикатор с минимумом, максимумом, полосой предупреждения и критической полосой.

**Настройки**: запрос к метрике и четыре границы.

Используйте, когда: значение укладывается в известный диапазон. Процент CPU (0–100%), загрузка диска, ёмкость очереди.

### Table

Таблица результатов метрики, по одной строке на группу.

**Настройки**: запрос к метрике (обычно сгруппированный по метке вроде host или service), отображаемые столбцы и лимит строк.

Используйте, когда: нужна разбивка, а не тренд. Топ-10 самых шумных хостов, число ошибок по сервисам, запросы по эндпоинтам.

## Text

Статический блок Markdown.

**Настройки**: тело в формате Markdown. Заголовки, списки, ссылки, выделение и блоки кода — всё рендерится.

Используйте, когда: нужен заголовок секции, абзац с контекстом, список ссылок на runbook-и или временный баннер во время инцидента.

## HTML

Ваши собственные HTML, CSS и JavaScript, отрендеренные как виджет.

**Настройки**: тело HTML, опциональная таблица стилей, опциональный скрипт и три переключателя разрешений.

Используйте, когда: нужно то, чего не покрывает ни один встроенный виджет, — встроенный сторонний бейдж, таблица, подтянутая из внутреннего API, своя легенда, набор стилизованных ссылок на ваши собственные инструменты.

### Что он может и чего не может

Виджет рендерится в изолированном (sandboxed) фрейме на собственном отдельном origin. Внутри этого фрейма ваш код может делать практически что угодно: строить DOM, запускать таймеры, выполнять fetch к любому URL, рисовать на canvas.

Чего он не может — так это добраться до окружающей его страницы OneUptime. У него нет доступа к DOM дашборда, к cookie, локальному хранилищу или API-сессии, и он не может увести браузерную вкладку на другой адрес. Это верно независимо от того, приватный дашборд или открыт публично.

Два следствия, о которых стоит знать, прежде чем вставлять сюда что-то:

- `fetch` из виджета — это кросс-доменный запрос с непрозрачного (opaque) origin, поэтому сервер, к которому вы обращаетесь, должен разрешить его через CORS. Вызов API OneUptime отсюда не поддерживается.
- Изначально виджет прозрачный. Задайте фон для `body` в своём CSS, если хотите, чтобы он заполнял карточку.

### Использование переменных дашборда

Напишите `{{variableName}}` в любом месте HTML, CSS или JavaScript — и перед рендерингом виджета это будет заменено текущим значением соответствующей переменной. Выбор нового значения перерисовывает виджет. Плейсхолдер, называющий несуществующую переменную, остаётся как есть.

Скрипты получают те же значения плюс временной диапазон дашборда — в `window.ONEUPTIME`:

```javascript
window.ONEUPTIME.variables.environment; // текущее значение или "", если не задано
window.ONEUPTIME.startDate; // строка ISO 8601, начало временного диапазона дашборда
window.ONEUPTIME.endDate; // строка ISO 8601, его конец
```

Виджет перезагружается при каждом обновлении дашборда, поэтому виджет, который сам загружает свои данные, поспевает за интервалом обновления.

### Разрешения

**Run JavaScript** («Выполнять JavaScript», включено по умолчанию) запускает ваш скрипт. Отключите его, чтобы отрендерить только разметку и стили: тогда скрипт вообще не попадает в виджет, а не просто блокируется.

**Open links in a new tab** («Открывать ссылки в новой вкладке», включено по умолчанию) разрешает ссылкам и `window.open` открывать вкладку браузера. Ссылки всегда открываются в новой вкладке; виджет никогда не может увести на другой адрес сам дашборд.

**Allow forms to submit** («Разрешить отправку форм», выключено по умолчанию) разрешает отправку `form` внутри виджета.

Любой, кто может редактировать дашборд, решает, что выполняет этот виджет, и все, кто просматривает дашборд, это выполняют — а на публичном дашборде в их число входят анонимные посетители. Относитесь к праву редактирования дашборда с HTML-виджетом так же, как к доступу к любому другому коду, который вы поставляете.

## Логи и трейсы

### Log Chart

График объёма логов во времени на временном диапазоне дашборда. Каждая серия соответствует уровню важности, поэтому всплески ошибок выделяются на фоне обычного трафика.

**Настройки**:

- Отображение столбцами, линиями или областями. Столбчатые диаграммы и диаграммы с областями складывают серии уровней важности.
- Необязательные фильтры по уровню важности.
- Необязательный текстовый поиск по телу лога.
- Точные фильтры по атрибутам OpenTelemetry через строки ключ/значение с поиском. Имена атрибутов и известные значения подсказываются по мере ввода, при этом свои значения по-прежнему поддерживаются.
- Необязательный заголовок.

Элементы управления временным диапазоном и обновлением дашборда автоматически перезапрашивают график. Переменные телеметрических атрибутов дашборда тоже применяются к нему, включая переменные с множественным выбором.

Log Chart пока требует дашборда с входом. На публичных дашбордах виджет показывается как недоступный, вместо того чтобы анонимно раскрывать агрегаты логов проекта.

Используйте, когда: нужно замечать изменения объёма логов или сравнивать ошибки, предупреждения и информационные записи, не покидая дашборд.

### Log Stream

Живой поток строк лога, подходящих под фильтр.

**Настройки**: фильтры лога (service, severity, атрибуты) и отображаемые столбцы.

Используйте, когда: хочется видеть, что приложение говорит прямо сейчас, не покидая дашборд.

### Trace List

Список свежих трейсов, подходящих под фильтр, с длительностью, статусом и сервисом.

**Настройки**: фильтры трейсов (service, status, атрибуты).

Используйте, когда: нужен список свежей активности, а не график. Типичный приём — график задержек сверху и список медленных трейсов под ним.

## Живые списки

### Incident List

Живой список инцидентов, подходящих под фильтр.

**Настройки**: фильтры по состоянию, уровню критичности, меткам, монитору или команде.

Используйте, когда: дашборд отвечает на вопрос «что сломано прямо сейчас?»

### Alert List

Живой список оповещений, подходящих под фильтр.

**Настройки**: фильтры по состоянию, уровню критичности, меткам.

Используйте, когда: командный дашборд отслеживает оповещения по своим сервисам.

### Monitor List

Живой список мониторов и их текущего состояния.

**Настройки**: фильтры по типу монитора, меткам или текущему состоянию.

Используйте, когда: нужен обзор флота — «все ли сайты живы?»

## Цели уровня обслуживания

### SLO

Одна цель уровня обслуживания, показанная либо одним числом, либо линией во времени.

**Настройки**: какой SLO, какое из трёх его чисел (SLI, Error Budget Remaining или Burn Rate), отображение Tile или Chart и необязательный заголовок.

- **Tile** показывает текущее число, а также вторую строку, если она есть — цель под SLI, оставшиеся минуты под бюджетом ошибок. Индикатор состояния окрашивает всю плитку.
- **Chart** рисует то же число на временном диапазоне дашборда, отмечая цель пунктирной линией на серии SLI. Историю записывает воркер оценки каждые несколько минут, поэтому совсем новый SLO рисуется пустым, пока не будет оценён впервые.

Используйте, когда: дашборд отвечает на вопрос «выполняем ли мы то, что обещали?», а не «что происходит прямо сейчас?».

Виджет SLO работает на [публичных дашбордах](/docs/dashboards/sharing). Публикуются ключевые числа SLO — название, цель, текущий SLI, остаток бюджета ошибок, скорость расходования и статус — независимо от того, какое из них рисует виджет. Определение остаётся закрытым: мониторы, за которыми он следит, его метки, описание, запрос и расписание оценки никогда не отправляются публичному посетителю. Виджет Tile публикует только эти текущие числа; виджет Chart публикует также историю той единственной серии, которую рисует, и ничего больше.

## Списки ресурсов Kubernetes

Для проектов с установленным [Kubernetes Agent](/docs/monitor/kubernetes-agent). У каждого виджета есть опциональные фильтры по кластеру, пространству имён и меткам.

- **Kubernetes Pod List** — поды с их фазой, перезапусками и нодой.
- **Kubernetes Node List** — ноды с их условиями и ёмкостью.
- **Kubernetes Namespace List** — пространства имён и количество рабочих нагрузок.
- **Kubernetes Deployment List** — deployment-ы с желаемым и готовым числом реплик.
- **Kubernetes StatefulSet List** — stateful set-ы с готовыми репликами.
- **Kubernetes DaemonSet List** — daemon set-ы с желаемыми и готовыми.
- **Kubernetes Job List** — задания и их статус завершения.
- **Kubernetes CronJob List** — cron-задания с расписанием и последним запуском.

Используйте, когда: хочется одного дашборда, объединяющего состояние Kubernetes с телеметрией от этих рабочих нагрузок.

## Списки ресурсов Docker

Для проектов с настроенным мониторингом Docker.

- **Docker Host List** — хосты, на которых работает Docker, с количеством контейнеров.
- **Docker Container List** — контейнеры со статусом, образом, хостом, временем работы.
- **Docker Image List** — образы и их размеры.
- **Docker Network List** — сети Docker и подключённые контейнеры.
- **Docker Volume List** — тома Docker и их использование.

## Инфраструктура

### Host List

Хосты, отслеживаемые серверным монитором OneUptime, со статусом, CPU, памятью и временем работы.

**Настройки**: фильтры по меткам или текущему состоянию.

## Сеть

### Network Map

Ваши сетевые площадки, нанесённые на карту мира: каждая закреплена на своей широте и долготе и окрашена по сводному состоянию мониторов на ней. Близко расположенные площадки делят один маркер с числом внутри; маркер, за которым стоит ровно одна площадка, по клику открывает её.

Карта сама подбирает рамку под нарисованные площадки — хозяйство внутри одной страны заполняет кадр этой страной, разбросанное по континентам открывается на весь мир. Элементов зума и панорамирования нет: плитка дашборда — это картинка, а ходить по иерархии нужно на странице Network Map в разделе Network.

Над картой печатается, сколько площадок недоступно, потому что красную точку в два пикселя среди двухсот зелёных на расстоянии дашборда никто не разглядит. Под картой строка покрытия говорит, чего карта _не_ показывает — площадки без координат и достигнут ли предел числа строк.

**Настройки**: заголовок, вид карты или списка, максимум отображаемых площадок, печатать ли названия площадок, а также фильтры по типу площадки и по состоянию. Названия площадок убираются автоматически, когда карта становится слишком плотной, чтобы их читать; всплывающая подсказка по-прежнему называет каждый маркер.

Площадка появляется только при наличии координат. Укажите широту и долготу у площадки (или импортируйте их из CSV), чтобы закрепить её.

## Какой виджет выбрать?

Несколько быстрых правил:

- **Тренд во времени?** Chart.
- **Объём логов или всплески ошибок во времени?** Log Chart.
- **Одно число, которое важно прямо сейчас?** Value (или Gauge, если есть чёткие min/max).
- **Разбивка по множеству объектов?** Table.
- **Что происходит в системе прямо сейчас?** Log Stream, Trace List, Incident List.
- **Состояние конкретной группы ресурсов?** Подходящий виджет-список.
- **Выполняем ли мы обещанную надёжность?** SLO.
- **Где в мире находится ваша сеть и что горит красным?** Network Map.
- **Заголовок, абзац или ссылка?** Text.
- **Что-то, чего не покрывает ничего из перечисленного?** HTML — но только после того, как убедитесь, что встроенный виджет действительно с этим не справится.

Большинство дашбордов сочетают несколько типов — график сверху, рядом одно-два значения, текстовый разделитель, ниже один-два списка.
