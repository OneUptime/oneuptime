# Обзор страниц статуса

Страница статуса — это публичное лицо всего, что вы мониторите: один URL, который ваши клиенты могут открыть вместо того, чтобы писать вам письмо с вопросом, только ли у них что-то не работает. Она показывает текущее состояние сервисов, которые вы решили сделать видимыми, инциденты, над которыми вы сейчас работаете, запланированные работы по обслуживанию и любое объявление, которое вы хотите закрепить наверху.

Когда что-то ломается в два часа ночи, страница статуса — это первое, на что ссылается ваша служба поддержки. Это же то, что получают уведомление ваши подписчики, — так что стоит настроить её до того, как она понадобится, а не во время сбоя.

Страницы статуса находятся в разделе **Status Pages** в левой навигации дашборда, в группе **essentials**. Всё на этой странице привязано к конкретной странице статуса: проект может иметь их сколько угодно — публичную для клиентов, приватную для внутренней аудитории, отдельную для конкретного региона.

## Коротко

- **Создаётся по двум полям.** Новая страница статуса запрашивает только **Name** и **Description**. Ресурсы, брендинг и домены настраиваются после.
- **Ресурсы — это то, что видят посетители.** Каждая строка на странице — это **Status Page Resource** — монитор (или группа мониторов) со своим отображаемым именем, подсказкой и настройками аптайма. Группы разбивают длинную страницу на разделы и могут быть вложенными.
- **URL для предпросмотра с первого дня.** Каждая страница статуса получает ссылку для предпросмотра, чтобы вы могли посмотреть на неё до того, как появится собственный домен.
- **Публичные маршруты закрыты настройками.** Инциденты, объявления, запланированные события и страница подписки появляются только тогда, когда включён соответствующий переключатель в **Advanced Settings**.
- **Три способа сделать страницу приватной.** Приватные пользователи, мастер-пароль или SAML SSO / OIDC — плюс белый список IP.
- **Подписчики оповещаются автоматически.** Email, SMS, Slack, Microsoft Teams и подписчики через webhook могут следить за страницей, каждый канал за своим переключателем.

## Ключевые термины

| Термин                  | Что это значит                                                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Status page**          | Одна публичная (или приватная) страница со своим брендингом, доменами, ресурсами и подписчиками. Модель `StatusPage`.                  |
| **Resource**              | Одна строка, которую видят посетители, — монитор или группа мониторов, вынесенные на страницу с отображаемым именем и настройками аптайма. |
| **Group**                 | Именованный раздел, содержащий ресурсы. Группы вкладываются друг в друга, и каждый уровень агрегирует статус всего, что под ним.       |
| **Announcement**          | Сообщение, которое вы публикуете на одной или нескольких страницах статуса, с временем начала и необязательным временем окончания.       |
| **Subscriber**            | Кто-то (или что-то), следящее за страницей через email, SMS, Slack, Microsoft Teams или webhook.                                       |
| **Custom domain**         | Ваш собственный домен — `status.example.com` — направленный на страницу через CNAME и SSL-сертификат.                                  |
| **Private user**          | Аккаунт, который может войти на приватную страницу статуса. Отдельно от пользователей вашего проекта OneUptime.                        |

## Создание страницы статуса

1. Откройте **Status Pages → All Status Pages** и нажмите **Create Status Page**.
2. В модальном окне **Create New Status Page** заполните **Name** (обязательно, минимум два символа) и, при желании, **Description**.
3. Нажмите **Create Status Page**.

Это вся форма создания. Список, на который вы вернётесь, показывает **Name**, **Description**, **Labels** и **Owners** и может быть отфильтрован по **Status Page ID**, **Name** и **Description**.

Откройте новую страницу — и вы окажетесь на её экране **Overview**, который содержит две карточки: **Status Page Preview URL** со ссылкой на саму страницу и **Status Page Details**, где можно отредактировать только что заданные имя, описание и метки.

Далее, примерно в порядке полезности:

- Добавьте ресурсы, чтобы на странице что-то появилось — см. [Ресурсы и группы страницы статуса](/docs/status-pages/resources-and-groups).
- Задайте заголовок страницы, favicon, логотип и обложку, затем подключите собственный домен — см. [Оформление и домены страницы статуса](/docs/status-pages/branding-and-domains).
- Решите, на каких каналах люди смогут подписаться — см. [Подписчики и объявления](/docs/status-pages/subscribers).
- Настройте, что появляется на странице, в разделе **Advanced Settings**.

## Где что находится

Когда страница статуса открыта, её собственное боковое меню разбито на девять разделов. Используйте это как карту для остальной части этой группы документации.

| Раздел                     | Что в нём есть                                                                                                                                 |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Basic**                   | **Overview**, **Announcements**, **Owners**.                                                                                                        |
| **Resources**                | Единственный экран **Resources** — группы слева, мониторы выбранной группы справа.                                                                  |
| **Subscribers**              | **Email Subscribers**, **SMS Subscribers**, **Slack Subscribers**, **MS Teams Subscribers**, **Webhook Subscribers**, **Subscriber Settings**.       |
| **Notification Logs**        | **Notification Logs** — что было отправлено подписчикам.                                                                                            |
| **Audit**                    | **Audit Logs**.                                                                                                                                       |
| **Branding**                 | **Essential Branding**, **HTML, CSS & JavaScript**, **Custom Domains**, **Header**, **Footer**, **Overview Page**, **Languages**.                    |
| **Security**                 | **Private Users**, **SSO**, **OIDC**, **SCIM**, **Authentication Settings**.                                                                          |
| **AI**                       | **MCP**.                                                                                                                                               |
| **Advanced**                 | **Monitor Rules**, **Embedded Status**, **Reports**, **Custom Fields**, **Advanced Settings**, **Delete Status Page**.                               |

Две особенности именования, о которых стоит знать заранее:

- Пункт **Resources** называется **Resources** только тогда, когда в проекте включены группы мониторов. Иначе он читается как **Monitors**. Это один и тот же экран в обоих случаях.
- Отдельной страницы Groups не существует. Группы и ресурсы объединили, и старый маршрут `/groups` теперь перенаправляет на экран ресурсов.

За пределами отдельной страницы сам раздел **Status Pages** имеет секцию **More** с пунктом **Announcements** и свёрнутую секцию **Settings**, содержащую **Announcement Templates**, **Subscriber Templates**, **Custom Fields**, **Owner Rules** и **Label Rules** — они общие для проекта и распространяются на все страницы статуса.

## Что видят посетители

Публичная страница — это отдельное приложение с небольшим набором маршрутов:

- `/` — **Overview**.
- `/incidents` и `/incidents/:id` — список инцидентов и отдельный инцидент.
- `/announcements` и `/announcements/:id`.
- `/scheduled-events` и `/scheduled-events/:id`.
- `/subscribe/email`, `/subscribe/sms`, `/subscribe/slack`, `/subscribe/microsoft-teams`, `/subscribe/webhooks`.
- `/rss` — лента.
- `/login`, `/sso` и `/master-password` — актуальны только для приватной страницы.

Верхняя панель навигации всегда показывает **Overview**; остальное появляется только когда включено. Для **Incidents**, **Announcements** и **Scheduled Events** нужен включённый соответствующий переключатель; для **Subscribe** нужны и **Show Subscriber Page**, и хотя бы один включённый канал подписки. На приватной странице также появляется пункт **Logout**.

### Страница обзора

Overview — это страница, которую видит большинство посетителей. Сверху вниз она отображает:

1. **Все активные объявления** — объявления, у которых время начала уже наступило, а время окончания ещё не наступило.
2. **Общий баннер статуса** — одна строка, обобщающая, затронуты ли все ресурсы или только часть.
3. **Общий процент аптайма**, если вы его включили. По умолчанию выключен.
4. **Группы ресурсов**, каждая со своими ресурсами, их текущим статусом и полосами истории аптайма.
5. **Active Incidents**.
6. **Scheduled Maintenance Events**.

Совершенно новая страница без ничего показывает пустое состояние, предлагающее добавить ресурсы из дашборда, — это сигнал перейти на экран **Resources**.

О том, что именно выводит инцидент на эту страницу и что убирает его обратно, читайте в [Состояния и уровни серьёзности инцидентов](/docs/incidents/states-and-severities).

## Выбор того, что показывается на странице

Большинство переключателей отображения находятся в одном месте: **Status Pages → ваша страница → Advanced → Advanced Settings**. У каждой карточки своя кнопка **Edit Settings**.

**Incident Settings**:

- **Show Incidents** (`showIncidentsOnStatusPage`) — включено по умолчанию. Выключение также убирает пункт навигации **Incidents**.
- **Show Incident History (in days)** (`showIncidentHistoryInDays`) — насколько далеко назад простирается список инцидентов. По умолчанию 14.
- **Show Incident Labels** (`showIncidentLabelsOnStatusPage`) — выключено по умолчанию.

**Episode Settings** — те же три переключателя для эпизодов инцидентов: **Show Episodes** (`showEpisodesOnStatusPage`, включено по умолчанию), **Show Episode History (in days)** (по умолчанию 14) и **Show Episode Labels** (выключено по умолчанию). Эпизоды — это отдельная модель со своими эндпоинтами, а не представление инцидентов.

**Announcement Settings**:

- **Show Announcements** (`showAnnouncementsOnStatusPage`) — включено по умолчанию.
- **Show Announcement History (in days)** (`showAnnouncementHistoryInDays`) — по умолчанию 14.

**Scheduled Event Settings**:

- **Show Scheduled Maintenance Events** (`showScheduledMaintenanceEventsOnStatusPage`) — включено по умолчанию.
- **Show Scheduled Event History (in days)** (`showScheduledEventHistoryInDays`) — по умолчанию 14.
- **Show Event Labels** (`showScheduledEventLabelsOnStatusPage`) — выключено по умолчанию.

**Uptime History Settings**:

- **Show Uptime History (in days)** (`showUptimeHistoryInDays`) — длина полосы аптайма рядом с каждым ресурсом. По умолчанию 90, должна быть от 1 до 90. Каждая опция **Show Uptime %** и **Show Status History Chart** на ресурсе или группе использует это число.

**Subscriber Settings**:

- **Show Subscriber Page** (`showSubscriberPageOnStatusPage`) — включено по умолчанию, плюс пять переключателей включения по каналам. Те же переключатели каналов также есть на отдельном экране **Subscriber Settings** в разделе **Subscribers**; считайте его каноническим местом для их настройки.

**Powered By OneUptime Branding**:

- **Hide Powered By OneUptime Branding** — выключено по умолчанию, поэтому в футере для посетителей будет написано «Powered by OneUptime», пока вы это не включите.

**Где находятся цвета.** Цвета полосы аптайма находятся не здесь — **Default Bar Color**, правила цвета полосы, **Downtime Monitor Statuses** и **Show Overall Uptime Percent** находятся в **Status Pages → ваша страница → Branding → Overview Page**. Нигде нет настройки темы или фирменного цвета; всё, что выходит за рамки этих элементов управления, делается через **Custom CSS**.

## Предпросмотр перед публикацией

Экран **Overview** каждой страницы статуса содержит карточку **Status Page Preview URL** со ссылкой прямо на страницу. Используйте её, пока всё ещё добавляете ресурсы и до того, как появится собственный домен.

Под капотом у каждого публичного маршрута есть двойник для предпросмотра под `/status-page/{statusPageId}/...` — предпросмотр обзора, предпросмотр списка инцидентов, предпросмотр страницы подписки и так далее. Это значит, что URL или скриншот, взятые из предпросмотра в дашборде, не будут совпадать с тем, что видит клиент после подключения собственного домена, — так что дважды проверяйте любую ссылку, которую вставляете в runbook или письмо.

## Ограничение доступа к странице

Не каждая страница статуса предназначена для публики. Все элементы управления находятся в разделе **Security**.

### Приватные пользователи

Выключите **Is Visible to Public** в **Status Pages → ваша страница → Security → Authentication Settings** (колонка `isPublicStatusPage`). После этого посетители попадают на `/login` и должны войти.

Добавьте людей, которые могут войти, в **Status Pages → ваша страница → Security → Private Users**. Есть действие **Add in Bulk** — вставьте список email-адресов, и каждый получит письмо-приглашение. У приватных пользователей есть собственный процесс восстановления и сброса пароля, отдельный от аккаунтов вашего проекта OneUptime.

### Мастер-пароль

**Authentication Settings** также содержит карточку **Master Password** с переключателем **Require Master Password** и самим паролем. После этого посетители попадают на `/master-password` и разблокируют страницу единым общим секретом.

**Мастер-пароль и приватные пользователи не сочетаются.** Пока включён мастер-пароль, аутентификация приватных пользователей отключена, и экран **Private Users** показывает баннер об этом.

### SSO и OIDC

Для приватной страницы, привязанной к вашему провайдеру идентификации, **Status Pages → ваша страница → Security → SSO** настраивает SAML (URL входа, издатель, x509-сертификат, методы подписи и дайджеста), а **Status Pages → ваша страница → Security → OIDC** настраивает OpenID Connect (URL обнаружения, издатель, ID и секрет клиента, области, имена claim'ов). **SCIM** автоматически подготавливает приватных пользователей из IdP. Это функции определённого тарифного плана, поэтому они могут быть доступны не в каждой инсталляции.

Карточка **SSO Settings** содержит **Force SSO for Login** (`requireSsoForLogin`, выключено по умолчанию). Проверьте настройку SSO перед тем, как включать это, — если она не сработает, вы заблокируете себе доступ к странице статуса.

### Белый список IP

**Authentication Settings** также содержит карточку **IP Whitelist**, основанную на колонке `ipWhitelist`, для страниц, которые должны отвечать только известным сетям.

## Встраиваемый значок и RSS-лента

Два способа показать статус где-то ещё, кроме самой страницы.

**Embedded status badge.** Включите **Enable Embedded Status Badge** (`enableEmbeddedOverallStatus`, выключено по умолчанию) в карточке **Embedded Status Badge** в **Status Pages → ваша страница → Advanced → Embedded Status**. Он работает в паре с `embeddedOverallStatusToken` и отдаёт значок с `/badge/:statusPageId`, так что вы можете вставить текущий общий статус в свою документацию, футер приложения или маркетинговую страницу.

**RSS-лента.** Каждая страница статуса отдаёт `/rss` — ленту с заголовком «{status page name} Updates», элементы которой имеют префиксы `Incident: `, `Announcement: ` и `Scheduled Maintenance: `. Удобно для тех, кто предпочитает получать ваши обновления через ридер или чат-бота, а не подписываться по email.

Если вы хотите забирать данные самостоятельно, страница статуса поддерживается публичными эндпоинтами для чтения обзора, инцидентов, запланированных работ по обслуживанию, объявлений и эпизодов — см. [Публичный API](/docs/status-pages/public-api).
