# Триггеры

Триггер — это первый блок в рабочем процессе, он определяет, когда запускается рабочий процесс. У каждого рабочего процесса ровно один триггер. Вы выбираете из четырёх видов.

## Manual

Запустите рабочий процесс по запросу, нажав **Run Workflow** на странице **Builder**, заполнив поля триггера и подтвердив кнопкой **Run Workflow Manually**. Триггер Manual принимает JSON-полезную нагрузку, которую может прочитать остальной рабочий процесс.

Подходит для: автоматизаций в один клик, для которых нужна кнопка, например «повернуть этот ключ» или «отправить тестовое оповещение».

**Вывод**: JSON, который вы вставили, или пустой объект, если вы этого не сделали.

## Schedule

Запускайте рабочий процесс по повторяющемуся расписанию с помощью cron-выражения.

Подходит для: ночной очистки, часовой синхронизации, еженедельных отчётов.

**Настройка**: cron-выражение. Несколько распространённых примеров:

- `0 * * * *` — каждый час, в начале часа.
- `*/5 * * * *` — каждые 5 минут.
- `0 9 * * 1` — каждый понедельник в 9:00.

Если система на короткое время недоступна, запуск подхватывается сразу же после восстановления — вам не нужно беспокоиться о пропущенных тактах при кратких сбоях.

## Webhook

OneUptime создаёт уникальный URL. Всё, что обращается к этому URL, запускает рабочий процесс. Заголовки, параметры запроса и тело запроса передаются внутрь.

Подходит для: приёма данных в OneUptime от другого инструмента — обратных вызовов CI/CD, оповещений из других систем мониторинга, регистраций в вашей CRM.

**Вывод**:

- **Request Headers** — все заголовки входящего запроса.
- **Request Query Params** — разобранная строка запроса.
- **Request Body** — разобранное тело запроса (или необработанный текст, если это не JSON).

URL принимает как `GET`, так и `POST`. Вызывающая сторона получает быстрое подтверждение — сам рабочий процесс выполняется в фоне.

Относитесь к URL как к паролю. Любой, кто им обладает, может запустить ваш рабочий процесс.

## Триггеры событий OneUptime

Практически всё в OneUptime — мониторы, инциденты, оповещения, плановое обслуживание, страницы статуса, политики дежурств, команды — может запускать рабочий процесс. Каждое из них предлагает три события:

- **On Create** — срабатывает, когда добавляется новый объект.
- **On Update** — срабатывает, когда объект изменяется.
- **On Delete** — срабатывает, когда объект удаляется.

Так вы строите логику «когда в OneUptime происходит X, делай Y», не проверяя ничего в цикле.

Полная запись передаётся в следующий блок. Например, триггер **Incident → On Create** передаёт новый инцидент, чтобы следующий блок мог прочитать его заголовок, описание, серьёзность и любое другое поле.

### События, которые команды используют чаще всего

- **Incident** — реагировать, когда инцидент открыт, изменён (подтверждён, устранён) или удалён.
- **Alert** — те же три события для оповещений.
- **Monitor** — реагировать, когда монитор добавлен, изменён или удалён.
- **Scheduled Maintenance** — автоматически анонсировать окно обслуживания, когда оно запланировано.
- **Status Page Subscriber** — приветствовать того, кто подписывается на страницу статуса.
- **On-Call Duty Policy** — синхронизировать изменения расписания с другой системой учёта дежурств.

Найдите нужный вариант, выполнив поиск по имени в панели **Add Trigger**.

## Какой триггер выбрать?

| Если вы хотите…                                  | Выберите             |
| ------------------------------------------------- | --------------------- |
| Нажать кнопку, чтобы запустить рабочий процесс     | **Manual**            |
| Запускать по повторяющемуся расписанию             | **Schedule**          |
| Позволить другой системе отправлять данные внутрь  | **Webhook**           |
| Реагировать на что-то внутри OneUptime             | **OneUptime event**   |

Рабочий процесс может иметь только один триггер. Если вам нужны два способа запуска одной и той же автоматизации, соберите общую логику в одном рабочем процессе и вызывайте его из двух тонких «обёрточных» рабочих процессов с помощью компонента **Execute Workflow**.
