# Компоненты

Компоненты — это те кирпичики, которые вы добавляете после триггера. Каждый делает что-то одно — отправляет сообщение, вызывает API, проверяет условие — и соединяется с тем, что идёт дальше.

Эта страница — каталог. О том, как добавлять компоненты на холст и соединять их, читайте в [Создании рабочего процесса](/docs/workflows/authoring).

## API

Выполнить HTTP-запрос по любому адресу.

**Настройки**:

- **Method** — `GET`, `POST`, `PUT`, `PATCH` или `DELETE`.
- **URL** — адрес, к которому обращаемся.
- **Headers** — заголовки, которые нужно отправить.
- **Body** — тело запроса для `POST` / `PUT` / `PATCH`.

**Выходы**:

- **Success** — срабатывает, когда вызов удался (ответ 2xx). Передаёт дальше статус, заголовки и тело.
- **Error** — срабатывает при сетевом сбое или ответе не из 2xx. Передаёт дальше текст ошибки.

Подходит для: любого внешнего API, ваших собственных служебных эндпойнтов и любой интеграции, у которой нет своего компонента.

## AI

### Generate Text with AI

Получить один текстовый ответ по промпту и, если нужно, по JSON-контексту. Компонент использует LLM-провайдера, заданного для проекта по умолчанию, а если такого нет — глобального провайдера установки. Учётные данные и адреса провайдеров настраиваются централизованно, аргументами рабочего процесса они не являются.

**Настройки**:

- **System Instructions** — необязательные указания о роли модели, тоне и ограничениях.
- **Prompt** — обязательная задача. Может содержать переменные рабочего процесса и выводы предыдущих компонентов.
- **Context** — необязательный JSON, который вы осознанно прикладываете к запросу. Он дописывается после явного маркера конца сообщения и дальше по тексту трактуется как недоверенные данные.
- **Temperature** — разброс от `0` до `1`. По умолчанию `0.2` — предсказуемо для автоматизации.
- **Maximum Output Tokens** — от `1` до `4096`. По умолчанию `1024`.

System Instructions, Prompt и сериализованный Context вместе ограничены 50 000 символами. У запроса к провайдеру предельная длительность 60 секунд, и попытка делается одна. Одновременно в проекте выполняется не больше трёх AI-запросов рабочих процессов.

**Выходы**:

- **Response** — сгенерированный текст.
- **Provider** и **Model** — конфигурация, с которой сделан вызов.
- **Total Tokens** и **Completion Tokens** — расход, о котором отчитался провайдер.
- **LLM Log ID** — учтённая запись AI-журнала для этого вызова.
- **Error** — ошибка валидации, доступа, провайдера, бюджета, биллинга или таймаута, если она была.

Подключите **Success** к компонентам, которые должны воспользоваться ответом. Подключите **Error** к явной запасной ветке, оповещению или журналированию. Компонент делает один запрос к модели без определений инструментов и без специфичных для провайдера полей возможностей: сам по себе он не может обращаться к OneUptime, вызывать API или менять данные проекта. Кроме фиксированной инструкции OneUptime по безопасности компонента, провайдеру уходят только заданные вами System Instructions, Prompt и Context — уже после подстановки переменных рабочего процесса в эти поля. Настроенные провайдер и модель остаются границей доверия, потому что у модели могут быть собственные возможности, управляемые провайдером.

Вывод модели — недоверенный текст. Проверяйте его, прежде чем отправлять что-то клиентам, и не используйте свободный AI-текст как единственное основание для разрушительных действий рабочего процесса. Подробности о провайдерах, исходящем трафике, журналировании и стоимости — в [Конфигурации и безопасности рабочего процесса](/docs/workflows/configuration).

## Webhook (исходящий)

Упрощённая версия компонента API для случаев «отправил и забыл». Отправляет POST-запросом JSON-тело на указанный адрес.

Берите **API**, если вам нужно прочитать ответ. Берите **Webhook**, если нужно просто послать уведомление и идти дальше.

## Slack

Опубликовать сообщение в канал Slack.

**Настройки**:

- **Channel** — имя канала. Бот уже должен быть в этом канале.
- **Message** — текст сообщения. Форматирование Slack поддерживается.

Сначала подключите Slack к проекту в **Настройки проекта → Рабочее пространство → Slack**. См. [Подключение рабочего пространства Slack](/docs/workspace-connections/slack).

## Microsoft Teams

Опубликовать сообщение в канал Microsoft Teams.

**Настройки**:

- **Team and channel** — куда публиковать.
- **Message** — текст сообщения.

О настройке читайте в [Подключении рабочего пространства Microsoft Teams](/docs/workspace-connections/microsoft-teams).

## Discord

Опубликовать сообщение в канал Discord через URL входящего вебхука.

## Telegram

Отправить сообщение в чат Telegram, используя токен бота и ID чата.

## Email

Отправить письмо через OneUptime.

**Настройки**:

- **To** — адрес получателя.
- **Subject** — тема письма.
- **Body** — текст в Markdown или HTML.

Письмо уходит от настроенного в проекте отправителя — см. [SMTP](/docs/emails/smtp).

## Custom Code

Выполнить небольшой фрагмент JavaScript, когда нужно то, чего не умеют остальные блоки.

**Настройки**:

- **Code** — ваш JavaScript. Выводом блока становится последнее значение (или то, что вы вернули из асинхронной функции).
- **Arguments** — именованные значения, которые можно передать внутрь.

**Выходы**: success (ваше возвращённое значение) и error (любое исключение).

Подходит для: перекладывания данных между двумя системами, небольших вычислений — всего, что не заслуживает отдельного блока. Для более серьёзных скриптов возьмите [Runbook](/docs/runbooks/index).

## JSON

Преобразование между текстом и JSON.

- **JSON → Text** — превратить JSON-объект в строку. Полезно, когда следующий блок ждёт текст.
- **Text → JSON** — разобрать строку в JSON-объект. Полезно, когда что-то пришло текстом, а вам нужно прочитать поле.

## Conditions

Ветвление по результату сравнения. На панели **Добавить компонент** этот блок называется **If / Else** и лежит в категории Conditions.

**Настройки**:

- **Left value** — обычно значение из предыдущего блока.
- **Operator** — `==`, `!=`, `>`, `>=`, `<`, `<=`, `contains`, `starts with`, `ends with`.
- **Right value** — то, с чем сравниваем.

**Выходы**: **Yes** и **No**. Подключайте следующие блоки к той ветке, которая вам нужна.

## Delay

Приостановить рабочий процесс на заданное время и только потом продолжить. Пригодится, когда другой системе нужно дать мгновение, чтобы догнать.

## Log

Записать строку в журнал запуска. Никакого внешнего эффекта — она просто появляется в логах рабочего процесса, чтобы вы её прочитали. Удобно при отладке.

## Execute Workflow

Вызвать из этого рабочего процесса другой. Вызванный рабочий процесс выполняется сам по себе — ваш продолжает работу, не дожидаясь его завершения.

Так удобно выносить общую логику. Соберите один раз рабочий процесс «написать в канал инцидента» и вызывайте его из любого другого, которому нужно уведомить этот канал.

Есть предохранитель, чтобы рабочие процессы не вызывали друг друга бесконечно. См. [Конфигурацию и безопасность рабочего процесса](/docs/workflows/configuration).

## Компоненты данных OneUptime

Для каждого вида записей в OneUptime (мониторы, инциденты, оповещения, страницы статуса, политики дежурств и многое другое) на панели **Добавить компонент** есть перечисленные ниже компоненты — ищите по названию типа. Заголовок каждого собирается из типа записи, так что для монитора набор читается так:

- **Find One Monitor** — прочитать одну запись, подходящую под запрос.
- **Find Many Monitors** — прочитать список записей, подходящих под запрос.
- **Create One Monitor** — добавить одну запись из JSON-объекта.
- **Create Many Monitors** — добавить несколько записей из JSON-массива.
- **Update One Monitor** — применить полезную нагрузку к одной подходящей записи.
- **Update Many Monitors** — применить полезную нагрузку к подходящим записям, не больше чем на Limit.
- **Delete One Monitor** — удалить одну подходящую запись.
- **Delete Many Monitors** — удалить подходящие записи, не больше чем на Limit.

Тот же набор даёт вам три триггера — **On Create Monitor**, **On Update Monitor** и **On Delete Monitor**. См. [Триггеры рабочего процесса](/docs/workflows/triggers).

Тип предлагает только те компоненты, которые допускает его модель. У типа «только для чтения» есть два компонента Find и больше ничего, так что если **Delete One Monitor** не находится на панели — значит, этот тип такого не разрешает.

Вот так рабочий процесс и читает и меняет данные OneUptime. Например, вебхук от вашего CI-инструмента может через **Create One Incident** открыть инцидент с подробностями сбоя.

## Работа с записями

Все поля компонентов данных ключуются по собственным именам **колонок** записи — тем же, которыми пользуется API, а не по подписям формы в дашборде. Колонка идентификатора называется `_id`. Написание `id` принимается как синоним везде, где можно ввести имя колонки, но запись отдаёт обратно именно `_id` — значит, на выходе читать нужно его:

```json
{ "_id": "00000000-0000-0000-0000-000000000000" }
```

**Query** решает, с какими записями компонент работает. Ключи — колонки, значения — то, чему они должны соответствовать:

```json
{ "monitorType": "Website", "isEnabled": true }
```

Запрос всегда ограничен проектом, в котором выполняется рабочий процесс. До записей другого проекта не дотянуться, и указывать проект в запросе самому не нужно.

**JSON Object** у Create One, **JSON Array** у Create Many и **Data (JSON Object)** у компонентов Update несут поля для записи, ключуемые точно так же:

```json
{ "name": "Checkout API", "monitorType": "Website" }
```

Ключ, который не является колонкой, не отвергается, а игнорируется — журнал запуска называет все отброшенные, так что при пропаже поля загляните туда. **Select Fields** у компонентов Find и у триггеров пользуется теми же ключами колонок со значением `true`: `{"_id": true, "name": true}`.

**Skip** и **Limit** — два числовых поля у Find Many, Update Many и Delete Many: `Skip: 0` вместе с `Limit: 100` возьмёт первую сотню совпадений. По умолчанию Limit равен `10`, а у Update Many и Delete Many он ограничивает, сколько записей будет действительно изменено, а не сколько вернётся. То есть `Items Deleted: 10` означает, что удалено десять записей, а не что совпало десять. Поднимайте Limit, если собираетесь менять больше десяти.

**Success** и **Error** сообщают, отработал ли запрос, а не что он нашёл. Запрос, не нашедший ничего, вернёт `0` и всё равно уйдёт по Success — это не сбой. Чтобы ветвиться по тому, нашлось ли что-нибудь, прочитайте возвращённый счётчик в блоке **If / Else**.

## Какой компонент выбрать?

Несколько простых правил:

- Если для задачи есть специальный блок (Slack, Email, запись OneUptime) — берите его: обработка ошибок аккуратнее, а логи понятнее.
- Для любого другого внешнего API — **API**.
- Чтобы обобщить, классифицировать или составить текст по явно выбранным данным рабочего процесса — **Generate Text with AI**.
- Чтобы переложить данные между блоками — **Custom Code** или **JSON**.
- Чтобы делать разное в зависимости от значения — **Conditions**.
