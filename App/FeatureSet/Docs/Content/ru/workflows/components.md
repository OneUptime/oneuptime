# Компоненты

Компоненты — это строительные блоки, которые вы добавляете после триггера. Каждый делает что-то одно — отправляет сообщение, вызывает API, проверяет условие — и соединяется с тем, что идёт дальше.

Эта страница — каталог. О том, как добавлять и соединять их на холсте, см. [Создание рабочего процесса](/docs/workflows/authoring).

## API

Выполняет HTTP-запрос по произвольному URL.

**Settings**:

- **Method** — `GET`, `POST`, `PUT`, `PATCH` или `DELETE`.
- **URL** — адрес для вызова.
- **Headers** — заголовки, которые нужно отправить.
- **Body** — тело запроса для `POST` / `PUT` / `PATCH`.

**Outputs**:

- **Success** — срабатывает, когда вызов прошёл успешно (ответ 2xx). Передаёт дальше статус, заголовки и тело.
- **Error** — срабатывает при сетевой ошибке или ответе не 2xx. Передаёт дальше сообщение об ошибке.

Используйте для: любого внешнего API, ваших собственных административных эндпоинтов или любой интеграции, у которой нет отдельного компонента.

## AI

### Generate Text with AI

Генерирует один текстовый ответ по промпту и опциональному JSON-контексту. Компонент использует настроенного в проекте провайдера LLM по умолчанию, при его отсутствии — переходит на глобального провайдера инсталляции. Учётные данные и адреса провайдера настраиваются централизованно; это не аргументы рабочего процесса.

**Settings**:

- **System Instructions** — необязательные указания о роли, тоне и ограничениях модели.
- **Prompt** — обязательное задание. Может включать переменные рабочего процесса и выводы предыдущих компонентов.
- **Context** — необязательный JSON, который вы намеренно добавляете к запросу. Он добавляется после явного маркера границы доверия в конце сообщения и на протяжении остальной части сообщения обрабатывается как недоверенные данные.
- **Temperature** — разброс от `0` до `1`. По умолчанию `0.2` для предсказуемой автоматизации.
- **Maximum Output Tokens** — от `1` до `4096`. По умолчанию `1024`.

Суммарная длина System Instructions, Prompt и сериализованного Context ограничена 50 000 символами. Запрос к провайдеру имеет максимальную длительность 60 секунд и выполняется одной попыткой. Одновременно на проект может выполняться не более трёх запросов AI рабочих процессов.

**Outputs**:

- **Response** — сгенерированный текст.
- **Provider** и **Model** — конфигурация, использованная для вызова.
- **Total Tokens** и **Completion Tokens** — использование, о котором отчитался провайдер.
- **LLM Log ID** — запись в измеряемом (metered) журнале AI для этого вызова.
- **Error** — ошибка валидации, доступа, провайдера, бюджета, биллинга или тайм-аута, если она возникла.

Соедините **Success** с компонентами, которые должны использовать ответ. Соедините **Error** с явным путём отката, оповещения или логирования. Компонент делает один запрос к модели без определений инструментов (tools) и без provider-native полей возможностей: он не может сам обращаться к OneUptime, вызывать API или менять данные проекта. Помимо фиксированных инструкций безопасности компонента от OneUptime, провайдеру отправляются только настроенные вами System Instructions, Prompt и Context — после того как переменные рабочего процесса в этих полях разрешены. Настроенные провайдер и модель остаются границей доверия, поскольку модель может обладать собственными, управляемыми провайдером возможностями.

Вывод модели — это недоверенный текст. Проверяйте его перед отправкой клиентам и не используйте свободный текст от AI как единственное основание для авторизации деструктивных действий рабочего процесса. См. [Конфигурация и безопасность рабочего процесса](/docs/workflows/configuration) — детали о провайдере, исходящем трафике, логировании и стоимости.

## Webhook (исходящий)

Упрощённая версия компонента API для случаев «отправил и забыл». Отправляет JSON-тело по URL.

Используйте **API**, если нужно прочитать ответ. Используйте **Webhook**, если просто нужно отправить уведомление и двигаться дальше.

## Slack

Публикует сообщение в канал Slack.

**Settings**:

- **Channel** — имя канала. Бот уже должен быть в этом канале.
- **Message** — текст для отправки. Поддерживает форматирование Slack.

Сначала подключите Slack к вашему проекту в разделе **Project Settings → Workspace → Slack**. См. [Подключение рабочего пространства Slack](/docs/workspace-connections/slack).

## Microsoft Teams

Публикует сообщение в канал Microsoft Teams.

**Settings**:

- **Team and channel** — куда отправлять.
- **Message** — текст для отправки.

Настройка описана в разделе [Подключение рабочего пространства Microsoft Teams](/docs/workspace-connections/microsoft-teams).

## Discord

Публикует сообщение в канал Discord через URL входящего webhook-а.

## Telegram

Отправляет сообщение в чат Telegram, используя токен бота и ID чата.

## Email

Отправляет письмо через OneUptime.

**Settings**:

- **To** — адрес электронной почты получателя.
- **Subject** — строка темы.
- **Body** — текст письма в Markdown или HTML.

Письмо отправляется с настроенного отправителя вашего проекта — см. [SMTP](/docs/emails/smtp).

## Custom Code

Запускает небольшой фрагмент JavaScript, когда нужно сделать то, что не умеют другие блоки.

**Settings**:

- **Code** — ваш JavaScript. Последнее значение (или то, что вы возвращаете из асинхронной функции) становится выходом блока.
- **Arguments** — именованные значения, которые можно передать внутрь.

**Outputs**: success (ваше возвращаемое значение) и error (любое исключение).

Используйте для: преобразования данных между двумя системами, небольших вычислений, всего того, что не заслуживает отдельного блока. Для более тяжёлых скриптов используйте [Runbook](/docs/runbooks/index).

## JSON

Преобразует данные между текстом и JSON.

- **JSON → Text** — превратить JSON-объект в строку. Полезно, когда следующий блок ожидает текст.
- **Text → JSON** — разобрать строку в JSON-объект. Полезно, когда что-то пришло как текст, а вам нужно прочитать поле.

## Conditions

Ветвление по сравнению. В панели **Add Component** этот блок называется **If / Else**, в категории Conditions.

**Settings**:

- **Left value** — обычно значение из предыдущего блока.
- **Operator** — `==`, `!=`, `>`, `>=`, `<`, `<=`, `contains`, `starts with`, `ends with`.
- **Right value** — то, с чем сравнивать.

**Outputs**: **Yes** и **No**. Соедините следующие блоки с той ветвью, которая вам нужна.

## Delay

Приостанавливает рабочий процесс на заданное время перед продолжением. Полезно, когда нужно дать другой системе время, чтобы догнать.

## Log

Пишет строку в журнал запуска. Никакого внешнего эффекта — она просто появляется в журналах рабочего процесса, чтобы вы могли её прочитать. Удобно для отладки.

## Execute Workflow

Вызывает другой рабочий процесс из этого. Вызванный рабочий процесс выполняется самостоятельно — ваш рабочий процесс продолжает работу, не дожидаясь его завершения.

Используйте это, чтобы переиспользовать общую логику. Соберите один раз рабочий процесс «опубликовать в канале инцидента», а затем вызывайте его из любого другого, которому нужно уведомить этот канал.

Есть предохранитель, чтобы рабочие процессы не могли бесконечно вызывать друг друга по кругу. См. [Конфигурация и безопасность рабочего процесса](/docs/workflows/configuration).

## Компоненты для данных OneUptime

Для каждого типа записи в OneUptime (мониторы, инциденты, оповещения, страницы статуса, политики дежурств и многих других) в панели **Add Component** есть такие компоненты — ищите по имени типа. Каждое название формируется из типа записи, поэтому для Monitor набор такой:

- **Find One Monitor** — прочитать одну запись, подходящую под запрос.
- **Find Many Monitors** — прочитать список записей, подходящих под запрос.
- **Create One Monitor** — добавить одну запись из JSON-объекта.
- **Create Many Monitors** — добавить несколько записей из JSON-массива.
- **Update One Monitor** — применить payload записи к одной подходящей записи.
- **Update Many Monitors** — применить payload записи к подходящим записям, в пределах Limit.
- **Delete One Monitor** — удалить одну подходящую запись.
- **Delete Many Monitors** — удалить подходящие записи, в пределах Limit.

Тот же набор даёт три триггера — **On Create Monitor**, **On Update Monitor** и **On Delete Monitor**. См. [Триггеры рабочего процесса](/docs/workflows/triggers).

Тип предлагает только те компоненты, которые допускает его модель. Тип, доступный только для чтения, имеет лишь два компонента Find и ничего больше, так что если вы не находите **Delete One Monitor** в панели — этот тип такого не позволяет.

Так рабочий процесс может читать и изменять данные OneUptime. Например: webhook от вашего CI-инструмента может через **Create One Incident** открыть инцидент с подробностями сбоя.

## Работа с записями

Каждое поле в компоненте данных ключуется по собственным именам **столбцов (column)** записи — тем же именам, что использует API, а не по меткам в форме дашборда. Столбец ID — это `_id`. Написание `id` принимается как псевдоним везде, где можно указать имя столбца, но именно `_id` возвращает запись, так что читать на выходе нужно именно его:

```json
{ "_id": "00000000-0000-0000-0000-000000000000" }
```

**Query** определяет, с какими записями работает компонент. Ключи — это столбцы, значения — то, чему нужно соответствие:

```json
{ "monitorType": "Website", "isEnabled": true }
```

Query всегда ограничен проектом, в котором выполняется рабочий процесс. Вы не можете обратиться к записям другого проекта, и добавлять проект в запрос самостоятельно не нужно.

**JSON Object** на Create One, **JSON Array** на Create Many и **Data (JSON Object)** на компонентах Update содержат поля для записи, ключуемые так же:

```json
{ "name": "Checkout API", "monitorType": "Website" }
```

Ключ, не являющийся столбцом, игнорируется, а не отклоняется — в журнале запуска указано, какие именно были отброшены, так что проверяйте там, если поле не применилось. **Select Fields**, на компонентах Find и триггерах, использует те же ключи столбцов со значениями `true`: `{"_id": true, "name": true}`.

**Skip** и **Limit** — это два числовых поля на Find Many, Update Many и Delete Many — `Skip: 0` с `Limit: 100` берёт первые сто совпадений. Limit по умолчанию равен `10`, и на Update Many и Delete Many он ограничивает, сколько записей реально записывается, а не только сколько возвращается. Так что `Items Deleted: 10` означает, что удалено десять записей, а не что совпало десять. Увеличьте Limit, если хотите изменить больше десяти.

**Success** и **Error** сообщают о том, выполнился ли запрос, а не о том, что он нашёл. Query, не нашедший ничего, возвращает `0` и всё равно уходит через Success — это не сбой. Чтобы ветвиться в зависимости от того, нашлось ли что-то, прочитайте возвращённый счётчик в блоке **If / Else**.

## Какой компонент выбрать?

Несколько быстрых правил:

- Если для нужного действия есть отдельный блок (Slack, Email, запись OneUptime), используйте его — вы получите более удобную обработку ошибок и более понятные журналы.
- Для любого другого внешнего API используйте **API**.
- Чтобы обобщить, классифицировать или составить текст на основе явно выбранных данных рабочего процесса, используйте **Generate Text with AI**.
- Чтобы преобразовать данные между блоками, используйте **Custom Code** или **JSON**.
- Чтобы выполнять разные действия в зависимости от значения, используйте **Conditions**.
