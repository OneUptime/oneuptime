# Обзор рабочих процессов

Рабочие процессы позволяют автоматизировать задачи в OneUptime без написания кода. Добавьте несколько блоков на холст, соедините их между собой — и у вас есть автоматизация, которая запускается всякий раз, когда что-то происходит: открывается инцидент, срабатывает расписание или другой инструмент отправляет данные в OneUptime.

Думайте о рабочих процессах как о фоновых помощниках вашего проекта: они реагируют на события, общаются с другими инструментами и незаметно поддерживают синхронизацию, пока вы занимаетесь своей работой.

## Что можно делать с рабочими процессами

- **Подключить OneUptime к другим вашим инструментам** — отправлять инциденты в Slack, создавать тикеты в Jira, публиковать данные на webhook в вашем стеке.
- **Реагировать на происходящее в OneUptime** — когда создаётся критический инцидент, автоматически уведомлять дежурную команду и открывать тикет.
- **Запускать задачи по расписанию** — каждые пять минут, каждую ночь, каждое утро понедельника.
- **Принимать данные извне** — позволить другим системам отправлять данные в OneUptime через уникальный URL.
- **Переиспользовать общую автоматизацию** — собрать её один раз и вызывать из любого другого рабочего процесса.

## Как устроен рабочий процесс

У каждого рабочего процесса есть три части:

1. **Триггер** — то, что запускает рабочий процесс. Это может быть ручная кнопка, расписание, входящий webhook или событие в OneUptime (например, новый инцидент).
2. **Один или несколько компонентов** — то, что делает рабочий процесс. Отправить сообщение, выполнить HTTP-запрос, провести быструю проверку, разветвиться в зависимости от условия.
3. **Соединения между ними** — вы проводите линии от одного блока к следующему, чтобы задать порядок выполнения.

Всё это вы собираете визуально на холсте. Для большинства рабочих процессов код не нужен, хотя вы можете добавить фрагмент JavaScript, когда это потребуется.

## Ключевые понятия

| Термин                    | Что это значит                                                                              |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Рабочий процесс**       | Вся автоматизация целиком — имя, холст и переключатель, включающий или выключающий её.       |
| **Триггер**                | Первый блок. Он определяет, когда запускается рабочий процесс. У каждого рабочего процесса ровно один триггер. |
| **Компонент**              | Блок действия — отправляет сообщение, выполняет запрос, проверяет условие.                    |
| **Запуск (Run)**           | Одно выполнение рабочего процесса. Сохраняется с отметками времени и выводом каждого блока.  |
| **Глобальная переменная** | Значение (например, ключ API), которое вы сохраняете один раз и переиспользуете в любом рабочем процессе. |

## Где найти рабочие процессы в OneUptime

Откройте **Workflows** в левой навигации. Этот раздел содержит:

- **Workflows** — ваш список рабочих процессов. Создайте новый или откройте существующий.
- **Global Variables** — значения, общие для всех ваших рабочих процессов.
- **Runs & Logs** — история выполнения по всем рабочим процессам проекта.

Откройте отдельный рабочий процесс, и его собственное левое меню будет содержать:

- **Overview** — имя, описание, метки и переключатель **Enabled**.
- **Builder** — холст, на котором вы проектируете рабочий процесс.
- **Workflow Variables** — значения, привязанные к этому конкретному рабочему процессу.
- **Runs & Logs** — каждый запуск этого рабочего процесса, с подробностями.
- **Settings** — секрет webhook, дублирование и экспорт.

## Создание вашего первого рабочего процесса

1. **Create** — выберите отправную точку, затем задайте имя вашему рабочему процессу.
2. **Выберите триггер** — вручную, по расписанию, через webhook или по событию из OneUptime.
3. **Добавьте компоненты** — добавьте действия на холст и соедините их.
4. **Включите его** — переключите **Enabled** на странице **Overview**. Отключённый рабочий процесс не может запуститься вообще, даже вручную.
5. **Протестируйте** — нажмите **Run Workflow** в **Builder** и понаблюдайте за журналом запуска.

## Небольшой пример

Допустим, вы хотите публиковать сообщение в Slack всякий раз, когда создаётся критический инцидент:

1. Создайте рабочий процесс с именем «Critical incidents to Slack».
2. Выберите триггер **On Create Incident**.
3. Добавьте блок **If / Else**. Настройте его на проверку того, содержит ли заголовок инцидента «Sev 1».
4. От ветки **Yes** добавьте блок **Slack**. Выберите канал и напишите сообщение.
5. Включите рабочий процесс.

В следующий раз, когда кто-то откроет инцидент с «Sev 1» в заголовке, в Slack загорится сообщение.

## Как рабочие процессы соотносятся с остальным OneUptime

- **Мониторы** замечают проблему. **Инциденты** её фиксируют. **Рабочие процессы** на неё реагируют.
- **Runbook-и** — это пошаговые инструкции для людей. Рабочие процессы — это автоматизация без участия человека. Используйте runbook, когда человеку нужно принимать решения; используйте рабочий процесс, когда шаги выполняются автоматически.
- **Workspace connections** (Slack, Teams) — это то, куда рабочие процессы отправляют свои сообщения.
