# Доступ интеграций из закрытых сетей

Самостоятельно размещённый экземпляр OneUptime может отправлять запросы в Twilio и Microsoft, оставаясь недоступным для их облачных служб. VPN-подключение сотрудника не предоставляет ни одному из провайдеров доступ к закрытой сети. Используйте [руководство по настройке Twilio](/docs/self-hosted/twilio-integration) и [руководство по настройке Teams](/docs/self-hosted/microsoft-teams-integration) вместе с приведёнными ниже шагами настройки сети.

## В каком направлении нужен доступ?

| Функция | От OneUptime к провайдеру | От провайдера к OneUptime |
| --- | --- | --- |
| Отправка SMS или воспроизведение простого исходящего голосового оповещения | HTTPS | Не требуется для запроса на отправку SMS или воспроизведения инструкций, переданных в запросе |
| Обновления доставки SMS, действия клавишами во время звонка, маршрутизация входящих звонков | HTTPS | Обратные вызовы обязательны; маршруты приведены в руководстве Twilio |
| Уведомления Teams | HTTPS к API Microsoft | Требуется для полной интеграции бота, включая обнаружение бесед |
| Команды Teams, кнопки карточек, события установки в чатах | HTTPS | `POST /api/microsoft-bot/messages` |

[Параметры доступа к закрытой сети](/docs/self-hosted/private-network-access) управляют исходящими запросами OneUptime к внутренним службам. Включение `ALLOW_PRIVATE_NETWORK_WEBHOOKS` не делает OneUptime доступным для Twilio или Teams.

## Промышленная эксплуатация: опубликуйте шлюз к закрытой установке

```text
Twilio / Azure Bot Service
          | HTTPS :443
          v
Публичный шлюз (обратный прокси или балансировщик нагрузки)
          | Закрытое подключение; только маршруты обратных вызовов
          v
Закрытый ingress OneUptime -> Приложение OneUptime
```

1. **Выберите имя хоста**, например `oneuptime.example.com`. Опубликуйте DNS-записи, указывающие на шлюз, доступный из интернета. Частные IP-адреса и внутренние DNS-имена недоступны провайдерам. При разделённом DNS сотрудники могут разрешать то же имя хоста в адрес закрытого ingress и продолжать использовать панель управления через VPN. Закрытый ingress также должен обслуживать HTTPS с сертификатом, действительным для этого имени хоста.
2. **Подключите шлюз к OneUptime.** Разместите его в DMZ с маршрутом к закрытому ingress либо используйте публичный шлюз, подключённый через ваш собственный VPN между площадками/частный канал. Разрешите трафик от шлюза к ingress на порту внутренней службы. Для Kubernetes/Portainer одной закрытой службы `ClusterIP` недостаточно: шлюзу нужен ingress/controller или другая доступная внутренняя служба. Оставьте базы данных и другие внутренние службы закрытыми.
3. **Завершайте HTTPS на порту 443** с общедоверенным сертификатом и полной цепочкой промежуточных сертификатов. Разрешите входящий TCP 443 к шлюзу. Установка сертификата или изменение DNS сами по себе не создают маршрут к закрытой внутренней службе.
4. **Перенаправляйте только необходимые пути обратных вызовов** из таблицы в руководстве Twilio и `/api/microsoft-bot/messages` для Teams. Направляйте их через ingress OneUptime, который уже сопоставляет `/notification` с приложением. Сохраняйте метод, исходный путь, строку запроса, тело, `Authorization` и `X-Twilio-Signature`. Сохраняйте публичный `Host` и задавайте доверенные `X-Forwarded-Host` и `X-Forwarded-Proto: https` на шлюзе. Не удаляйте `/api` и не добавляйте перенаправления. Запретите остальные пути на публичном шлюзе; сотрудники могут использовать закрытый ingress для панели управления и обратных вызовов при входе через браузер.
5. **Сохраняйте аутентификацию обратных вызовов.** Исключите эти маршруты из браузерного SSO, CAPTCHA и страниц входа прокси, поскольку провайдеры не могут их пройти. OneUptime по-прежнему проверяет токены обратных вызовов, подписи Twilio на маршрутах входящих звонков и аутентификацию Bot Framework. Не удаляйте эти проверки. Разрешайте доступ к исходному серверу только со своего шлюза и от авторизованных внутренних клиентов и скрывайте токены обратных вызовов в журналах. Twilio описывает эту [архитектуру DMZ-прокси и безопасность вебхуков](https://www.twilio.com/docs/usage/webhooks/webhooks-security).
6. **Задайте канонический URL OneUptime** до настройки любой из интеграций:

   Docker Compose, в `config.env`:

   ```dotenv
   HOST=oneuptime.example.com
   HTTP_PROTOCOL=https
   ```

   Значения Helm/Portainer:

   ```yaml
   host: oneuptime.example.com
   httpProtocol: https
   ```

   Эти параметры управляют создаваемыми URL; они не настраивают DNS, TLS или доступ через межсетевой экран. Примените конфигурацию Compose или обновление релиза Helm и дождитесь перезапуска приложения. OneUptime не предоставляет отдельный параметр имени хоста для обратных вызовов Twilio. Если имя хоста изменится, обновите существующие вебхуки телефонных номеров Twilio, конечную точку сообщений Azure Bot и URI перенаправления регистрации приложения, а также повторно скачайте и загрузите манифест Teams.

## Исходящий доступ и ограничения IP

Разрешите разрешение DNS-имён и исходящий HTTPS из приложения OneUptime. Twilio рекомендует доступ к `*.twilio.com`, поскольку адреса API меняются; см. [рекомендации Twilio по IP-адресам](https://help.twilio.com/articles/115015934048-All-About-Twilio-IP-Addresses). Teams использует `graph.microsoft.com`, `login.microsoftonline.com`, конечные точки аутентификации и каналов Bot Framework и URL службы соединителя для беседы. Используйте [рекомендации Microsoft по межсетевым экранам](https://learn.microsoft.com/en-us/azure/bot-service/bot-service-resources-faq-security?view=azure-bot-service-4.0) и проверяйте заблокированный трафик при тестировании; приведённые примеры не являются полным списком доменов.

Не используйте диапазоны SIP/медиа Twilio или диапазоны медиатрафика клиентов Teams в качестве списков разрешённых источников вебхуков. Обычные адреса вебхуков Twilio динамические; подходящие редакции Twilio предлагают [Static Proxy for Webhooks](https://www.twilio.com/docs/iam/twilio-editions/twilio-static-proxy), требующий отдельной настройки с Twilio. Рекомендации Microsoft по межсетевым экранам предупреждают, что фиксированные списки разрешённых входящих IP-адресов Bot Framework не поддерживаются. Аутентифицируйте обратные вызовы в приложении, а не предполагайте, что фиксированный IP-адрес источника подтверждает его личность.

## Тестирование и установки без входящего доступа

Из сети вне вашей VPN проверьте публичные DNS и TLS, затем проверьте маршрут Teams:

```bash
curl -sS -i https://oneuptime.example.com/api/microsoft-bot/messages
```

В текущих версиях OneUptime ожидается `405 Method Not Allowed` с `Allow: POST`. Это подтверждает, что GET-запрос достиг маршрута, но не гарантирует работу аутентифицированного POST-запроса бота. Старые версии могут возвращать JSON-ошибку 404 OneUptime; проверьте тело ответа и журналы прокси. Ошибки TLS, тайм-ауты или HTML-страница ошибки прокси указывают на проблемы с сертификатом или маршрутизацией.

Браузерный GET-запрос не проверяет POST-обратный вызов Twilio. Отправьте настоящее тестовое SMS, проверьте обновление доставки, ответьте на тестовый звонок об инциденте и выполните действие клавишей, затем отправьте сообщение боту Teams и нажмите кнопку карточки. Сопоставьте диагностику доставки провайдера с журналами шлюза и приложения, скрывая токены. Успешная исходящая доставка сама по себе не доказывает работоспособность обратных вызовов.

Для разработки Twilio описывает [тестирование через туннель](https://www.twilio.com/docs/usage/webhooks/webhooks-overview), а Microsoft — [локальную отладку Teams](https://learn.microsoft.com/en-us/microsoftteams/platform/concepts/build-and-test/debug). Направьте публичный HTTPS-туннель на прокси, разрешающий только необходимые маршруты, настройте полученное имя хоста, как описано выше, и остановите туннель после тестирования. Туннель по-прежнему открывает входящую конечную точку; он не делает установку полностью изолированной от сети.

Если политика запрещает любые входящие подключения, запросы на отправку SMS и простое воспроизведение переданных голосовых инструкций всё ещё могут работать через исходящий HTTPS, но обратные вызовы доставки, действия клавишами, маршрутизация входящих звонков и полная интеграция бота Teams работать не смогут. Частные конечные точки Azure Bot для Direct Line не решают проблему подключения Teams: в [руководстве Microsoft по сетевой изоляции](https://learn.microsoft.com/en-us/azure/bot-service/dl-network-isolation-how-to?view=azure-bot-service-4.0) указано, что отключение публичного доступа удаляет остальные каналы, включая Teams. Полностью отключённая установка не может использовать эти облачные интеграции.
