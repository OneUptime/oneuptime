# コンポーネント

コンポーネントは、トリガーの後に追加していくビルディングブロックです。それぞれが 1 つのことを行います — メッセージを送る、API を呼び出す、条件をチェックするなど — そして次に続くものへとつながります。

このページはそのカタログです。キャンバス上での追加・接続の方法については [Authoring a Workflow](/docs/workflows/authoring) を参照してください。

## API

任意の URL に HTTP リクエストを送ります。

**Settings**:

- **Method** — `GET`、`POST`、`PUT`、`PATCH`、`DELETE` のいずれか。
- **URL** — 呼び出す先のアドレス。
- **Headers** — 送信するヘッダー。
- **Body** — `POST` / `PUT` / `PATCH` のリクエストボディ。

**Outputs**:

- **Success** — 呼び出しが成功した（2xx 応答）ときに発火します。ステータス、ヘッダー、ボディを渡します。
- **Error** — ネットワーク障害または 2xx 以外の応答で発火します。エラーメッセージを渡します。

こんなときに使います: 任意の外部 API、自社の管理用エンドポイント、専用コンポーネントを持たないあらゆる連携。

## AI

### Generate Text with AI

プロンプトと任意の JSON コンテキストから、1 つのテキスト応答を生成します。このコンポーネントはプロジェクトに設定された既定の LLM プロバイダーを使い、利用できる場合はインストール全体のグローバルプロバイダーにフォールバックします。プロバイダーの認証情報とエンドポイントは中央で設定されるものであり、ワークフローの引数ではありません。

**Settings**:

- **System Instructions** — モデルの役割、トーン、制約についての任意のガイダンス。
- **Prompt** — 必須のタスク内容。ワークフロー変数や前のコンポーネントの出力を含められます。
- **Context** — リクエストに意図的に含める任意の JSON。明示的なメッセージ末尾の信頼境界マーカーの後に追加され、メッセージの残りの部分では信頼できないデータとして扱われます。
- **Temperature** — `0` から `1` までのばらつき。既定値は、予測可能な自動化のために `0.2` です。
- **Maximum Output Tokens** — `1` から `4096` まで。既定値は `1024` です。

System Instructions、Prompt、シリアライズされた Context を合わせて 50,000 文字までに制限されます。プロバイダーへのリクエストは最大 60 秒で、1 回だけ試行されます。プロジェクトごとに、同時に実行できるワークフロー AI リクエストは最大 3 件です。

**Outputs**:

- **Response** — 生成されたテキスト。
- **Provider** と **Model** — その呼び出しで使われた設定。
- **Total Tokens** と **Completion Tokens** — プロバイダーが報告した使用量。
- **LLM Log ID** — その呼び出しの計測用 AI ログエントリ。
- **Error** — 存在する場合の、検証・アクセス・プロバイダー・予算・請求・タイムアウトのいずれかのエラー。

**Success** は、その応答を使うべきコンポーネントに接続してください。**Error** は、明示的なフォールバック、アラート、またはログ出力の経路に接続してください。このコンポーネントはツール定義やプロバイダー固有の機能フィールドを持たない単一のモデルリクエストを行うだけです。それ自体で OneUptime に問い合わせたり、API を呼び出したり、プロジェクトのデータを変更したりすることはできません。OneUptime が固定しているコンポーネントの安全性に関する指示を除けば、プロバイダーに送られるのは設定した System Instructions、Prompt、Context のみで、それらのフィールド内のワークフロー変数が解決された後に送信されます。モデルには本質的にプロバイダー管理の機能が備わっている場合があるため、設定されたプロバイダー / モデルは依然として信頼境界であり続けます。

モデルの出力は信頼できないテキストです。顧客向けのコミュニケーションに送る前にレビューしてください。また、自由形式の AI テキストだけを根拠に破壊的なワークフローの操作を許可しないでください。プロバイダー、外部通信、ログ、コストの詳細については [Configuration & Safety](/docs/workflows/configuration) を参照してください。

## Webhook (outbound)

「送りっぱなし」で構わないケース向けの、API コンポーネントの簡易版です。URL に JSON ボディを POST します。

応答を読み取る必要がある場合は **API** を使ってください。通知を送って先に進むだけでよい場合は **Webhook** を使います。

## Slack

Slack のチャンネルにメッセージを投稿します。

**Settings**:

- **Channel** — チャンネル名。ボットが事前にそのチャンネルに参加している必要があります。
- **Message** — 送信するテキスト。Slack のフォーマットに対応しています。

まず **Project Settings → Workspace → Slack** で、プロジェクトに Slack を接続してください。[Slack Workspace Connection](/docs/workspace-connections/slack) を参照してください。

## Microsoft Teams

Microsoft Teams のチャンネルにメッセージを投稿します。

**Settings**:

- **Team and channel** — 投稿先。
- **Message** — 送信するテキスト。

セットアップについては [Microsoft Teams Workspace Connection](/docs/workspace-connections/microsoft-teams) を参照してください。

## Discord

受信 Webhook URL を通じて、Discord のチャンネルにメッセージを投稿します。

## Telegram

ボットトークンとチャット ID を使って、Telegram のチャットにメッセージを送信します。

## Email

OneUptime 経由でメールを送信します。

**Settings**:

- **To** — 受信者のメールアドレス。
- **Subject** — 件名。
- **Body** — Markdown または HTML によるメッセージ本文。

メールは、プロジェクトに設定された送信元から送信されます — [SMTP](/docs/emails/smtp) を参照してください。

## Custom Code

他のブロックではできないことが必要なときに、小さな JavaScript を実行します。

**Settings**:

- **Code** — 実行する JavaScript。最後の値（または非同期関数から return した値）がブロックの出力になります。
- **Arguments** — 渡すことのできる名前付きの値。

**Outputs**: success（return した値）と error（発生した例外）。

こんなときに使います: 2 つのシステム間でのデータの整形、ちょっとした計算、専用ブロックを用意するほどでもない処理。より重いスクリプトが必要な場合は [Runbook](/docs/runbooks/index) を使ってください。

## JSON

テキストと JSON の間で変換します。

- **JSON → Text** — JSON オブジェクトを文字列に変換します。次のブロックがテキストを期待している場合に便利です。
- **Text → JSON** — 文字列を JSON オブジェクトにパースします。何かがテキストとして届いていて、そこからフィールドを読み取りたい場合に便利です。

## Conditions

比較に基づいて分岐します。**Add Component** パネルでは、このブロックは Conditions カテゴリの下の **If / Else** という名前です。

**Settings**:

- **Left value** — たいていは前のブロックからの値。
- **Operator** — `==`、`!=`、`>`、`>=`、`<`、`<=`、`contains`、`starts with`、`ends with`。
- **Right value** — 比較対象。

**Outputs**: **Yes** と **No**。次のブロックを、望むほうの分岐に接続してください。

## Delay

続行する前に、決めた時間だけワークフローを一時停止します。別のシステムが追いつくまで少し待たせたいときに便利です。

## Log

実行ログに 1 行書き込みます。外部への影響はありません — ワークフローのログに表示され、あなたが読めるだけです。デバッグに便利です。

## Execute Workflow

このワークフローから別のワークフローを呼び出します。呼び出されたワークフローは独立して実行されます — こちらのワークフローは、その完了を待たずに続行します。

共通のロジックを共有するのに使います。「インシデントチャンネルに投稿する」ワークフローを一度作っておけば、そのチャンネルに通知する必要がある他のどのワークフローからでも呼び出せます。

ワークフロー同士がループ状に呼び合い続けないよう、安全のための上限があります。[Configuration & Safety](/docs/workflows/configuration) を参照してください。

## OneUptime data components

OneUptime のあらゆる種類のレコード（モニター、インシデント、アラート、ステータスページ、オンコールポリシーなど多数）について、**Add Component** パネルには次のコンポーネントがあります — その種類の名前で検索してください。それぞれのタイトルはレコードタイプから生成されるため、Monitor のセットは次のようになります。

- **Find One Monitor** — クエリに一致するレコードを 1 件読み取ります。
- **Find Many Monitors** — クエリに一致するレコードのリストを読み取ります。
- **Create One Monitor** — JSON オブジェクトからレコードを 1 件追加します。
- **Create Many Monitors** — JSON 配列から複数のレコードを追加します。
- **Update One Monitor** — 一致する 1 件のレコードに書き込みペイロードを適用します。
- **Update Many Monitors** — 一致するレコードに、Limit までの件数で書き込みペイロードを適用します。
- **Delete One Monitor** — 一致する 1 件のレコードを削除します。
- **Delete Many Monitors** — 一致するレコードを、Limit までの件数で削除します。

同じセットが 3 つのトリガー — **On Create Monitor**、**On Update Monitor**、**On Delete Monitor** — も提供します。[Triggers](/docs/workflows/triggers) を参照してください。

どのコンポーネントが使えるかは、そのモデルが許可するものだけです。読み取り専用のタイプには 2 つの Find コンポーネントしかないので、パネルに **Delete One Monitor** が見当たらない場合、そのタイプはそれを許可していないということです。

これが、ワークフローが OneUptime のデータを読み書きする方法です。たとえば、CI ツールからの Webhook が **Create One Incident** を使って、失敗の詳細を含むインシデントを開くことができます。

## レコードを扱う

データコンポーネントのすべてのフィールドは、レコード自身の **column（列）** 名をキーにしています — これはダッシュボードのフォームに表示されるラベルではなく、API が使うのと同じ名前です。ID の列は `_id` です。`id` という綴りも、列名を入力できる場所ならどこでもエイリアスとして受け付けられますが、レコードが返してくるのは `_id` なので、読み取り時に見るべきなのはそちらです。

```json
{ "_id": "00000000-0000-0000-0000-000000000000" }
```

**Query** は、そのコンポーネントがどのレコードを対象にするかを決めます。キーが列名で、値が一致させたい内容です。

```json
{ "monitorType": "Website", "isEnabled": true }
```

クエリは常に、そのワークフローが実行されているプロジェクトの範囲に限定されます。他のプロジェクトのレコードには到達できませんし、クエリに自分でプロジェクトを加える必要もありません。

Create One の **JSON Object**、Create Many の **JSON Array**、Update 系コンポーネントの **Data (JSON Object)** には、書き込むフィールドを同じキーの付け方で入れます。

```json
{ "name": "Checkout API", "monitorType": "Website" }
```

列に存在しないキーは、拒否されるのではなく無視されます — 実行ログには、そのとき除外されたキーの名前が記録されるので、フィールドが反映されないときはそこを確認してください。**Select Fields** は、Find コンポーネントとトリガーで使われ、同じ列名のキーに `true` の値を組み合わせます: `{"_id": true, "name": true}`。

**Skip** と **Limit** は、Find Many、Update Many、Delete Many にある 2 つの数値フィールドです — `Skip: 0` に `Limit: 100` を組み合わせると、最初の 100 件が対象になります。Limit の既定値は `10` で、Update Many と Delete Many では、実際に何件返ってくるかだけでなく、実際に何件書き込まれるかの上限にもなります。つまり `Items Deleted: 10` は、10 件が一致したという意味ではなく、10 件が削除されたという意味です。10 件より多く変更したい場合は Limit を上げてください。

**Success** と **Error** は、クエリが実行できたかどうかを報告するものであり、何が見つかったかを報告するものではありません。何にも一致しないクエリは `0` を返し、それでも Success 側に進みます — それは失敗ではありません。何かが一致したかどうかで分岐したい場合は、**If / Else** ブロックで返ってきた件数を読み取ってください。

## どのコンポーネントを使うべきか?

いくつかの簡単な指針です。

- やりたいことに専用のブロック（Slack、Email、OneUptime のレコードなど）があるなら、それを使ってください — エラー処理がより自然で、ログも分かりやすくなります。
- それ以外の外部 API には **API** を使います。
- 明示的に選んだワークフローのデータを要約・分類・下書きするには、**Generate Text with AI** を使います。
- ブロック間でデータを整形するには **Custom Code** か **JSON** を使います。
- 値に応じて異なる動作をさせるには **Conditions** を使います。
