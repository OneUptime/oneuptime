# ワークフロー 概要

ワークフローを使うと、コードを書かずに OneUptime 内の作業を自動化できます。キャンバスにいくつかのブロックを追加してつなげるだけで、何かが起きたとき — インシデントが開いたとき、スケジュールが発火したとき、あるいは他のツールが OneUptime にデータを送ってきたとき — に実行される自動化ができあがります。

ワークフローは、プロジェクトのための裏方のヘルパーだと考えてください。イベントに反応し、他のツールとやり取りし、あなたが本来の作業に集中している間に静かに物事を同期させ続けます。

## ワークフローでできること

- **OneUptime を他のツールとつなぐ** — インシデントを Slack に送る、Jira チケットを作成する、あなたのスタックの webhook に投げる。
- **OneUptime 内で起きたことに反応する** — 重大なインシデントが作成されたら、オンコールチームに通知し、自動でチケットを開く。
- **スケジュールでジョブを実行する** — 5 分ごと、毎晩、毎週月曜の朝。
- **外部からデータを受け取る** — 他のシステムが専用の URL を通じて OneUptime にデータを送り込めるようにする。
- **共通の自動化を使い回す** — 一度作れば、他のどのワークフローからでも呼び出せる。

## ワークフローの仕組み

すべてのワークフローには 3 つの要素があります。

1. **トリガー** — ワークフローを開始するもの。手動のボタン、スケジュール、受信 webhook、あるいは OneUptime 内のイベント (新しいインシデントなど) が使えます。
2. **1 つ以上のコンポーネント** — ワークフローが行うこと。メッセージを送る、HTTP 呼び出しをする、簡単なチェックを実行する、条件で分岐する。
3. **それらの間の接続** — あるブロックから次のブロックへ線を引いて、実行順序を決めます。

これらはすべてキャンバス上で視覚的に組み立てます。ほとんどのワークフローはコーディング不要ですが、必要であれば JavaScript のスニペットを追加することもできます。

## キー用語

| 用語               | 意味                                                                             |
| ------------------ | -------------------------------------------------------------------------------- |
| **ワークフロー**   | 自動化全体 — 名前、キャンバス、そしてオン/オフを切り替えるスイッチ。             |
| **トリガー**       | 最初のブロック。ワークフローがいつ実行されるかを決めます。すべてのワークフローには必ず 1 つのトリガーがあります。 |
| **コンポーネント** | アクションブロック — メッセージを送る、リクエストを行う、条件をチェックする。   |
| **実行**           | ワークフローの 1 回の実行。タイムスタンプと各ブロックの出力とともに保存されます。 |
| **グローバル変数** | 一度保存して、どのワークフローでも再利用できる値 (API キーなど)。               |

## OneUptime 内でワークフローが見つかる場所

左ナビゲーションの **ワークフロー** を開きます。そのセクションには次が含まれます。

- **ワークフロー** — あなたのワークフローの一覧。新規作成、または既存のものを開けます。
- **グローバル変数** — すべてのワークフローで共有される値。
- **実行とログ** — プロジェクト内のすべてのワークフローにまたがる実行履歴。

個々のワークフローを開くと、その専用の左メニューには次があります。

- **概要** — 名前、説明、ラベル、そして **有効** スイッチ。
- **ビルダー** — ワークフローを設計するキャンバス。
- **ワークフロー変数** — このワークフローだけに紐付いた値。
- **実行とログ** — このワークフローのすべての実行と、その詳細。
- **設定** — webhook のシークレット、複製、エクスポート。

## 最初のワークフローを作る

1. **作成** — 起点を選び、ワークフローに名前を付けます。
2. **トリガーを選ぶ** — 手動、スケジュール、webhook、または OneUptime のイベントから選びます。
3. **コンポーネントを追加** — キャンバスにアクションを追加してつなげます。
4. **オンにする** — **概要** ページから **有効** をオンに切り替えます。無効なワークフローは、手動であっても一切実行できません。
5. **テスト** — **ビルダー** で **ワークフローを実行** をクリックし、実行ログを確認します。

## クイック例

重大なインシデントが作成されるたびに Slack に投稿したいとします。

1. 「Critical incidents to Slack」という名前のワークフローを作成します。
2. **On Create Incident** トリガーを選びます。
3. **If / Else** ブロックを追加します。インシデントのタイトルに「Sev 1」が含まれるかどうかをチェックするよう設定します。
4. **Yes** の分岐から **Slack** ブロックを追加します。チャンネルを選び、メッセージを書きます。
5. ワークフローをオンにします。

次に誰かがタイトルに「Sev 1」を含むインシデントを開くと、Slack が反応します。

## ワークフローと OneUptime の他の機能との関係

- **モニター** が問題を見つけます。**インシデント** がそれを記録します。**ワークフロー** がそれに反応します。
- **Runbook** は人間のための手順書です。ワークフローは無人の自動化です。人間が判断を下す必要があるときは Runbook を、手順が自動的に決まるときはワークフローを使いましょう。
- **ワークスペース連携** (Slack、Teams) は、ワークフローがメッセージを送る先です。
