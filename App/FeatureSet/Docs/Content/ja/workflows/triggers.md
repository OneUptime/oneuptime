# トリガー

トリガーはワークフローの最初のブロックで、ワークフローがいつ実行されるかを決めます。すべてのワークフローには必ず 1 つのトリガーがあります。4 種類の中から選びます。

## 手動

**ビルダー** ページで **ワークフローを実行** をクリックし、トリガーのフィールドに入力してから **Run Workflow Manually** で確定することで、任意のタイミングでワークフローを実行できます。手動トリガーは、ワークフローの残りの部分が読み取れる JSON ペイロードを受け取ります。

向いている用途: 「このキーをローテーションする」「テストアラートを送る」のような、ボタン一つで実行したい自動化。

**出力**: 貼り付けた JSON。何も貼り付けなかった場合は空のオブジェクト。

## スケジュール

cron 式を使って、繰り返しスケジュールでワークフローを実行します。

向いている用途: 毎晩のクリーンアップ、毎時の同期、週次レポート。

**設定**: cron 式。よく使われるものをいくつか挙げます。

- `0 * * * *` — 毎時ちょうど。
- `*/5 * * * *` — 5 分ごと。
- `0 9 * * 1` — 毎週月曜の午前 9 時。

システムが一時的に利用できなくなっても、復旧次第すぐに実行が拾われます。短い停止であれば、取りこぼしたタイミングを心配する必要はありません。

## Webhook

OneUptime が専用の URL を作成します。その URL にアクセスするものは何でもワークフローを開始します。受信リクエストのヘッダー、クエリパラメータ、ボディが渡されます。

向いている用途: 他のツールから OneUptime へのデータ受信 — CI/CD のコールバック、他の監視ツールからのアラート、CRM でのサインアップなど。

**出力**:

- **Request Headers** — 受信リクエストのすべてのヘッダー。
- **Request Query Params** — パースされたクエリ文字列。
- **Request Body** — パースされたボディ (JSON でない場合は生のテキスト)。

この URL は `GET` と `POST` の両方を受け付けます。呼び出し元にはすぐに確認応答が返り、ワークフロー自体はバックグラウンドで実行されます。

この URL はパスワードと同じように扱ってください。知っている人は誰でもあなたのワークフローを開始できます。

## OneUptime イベントトリガー

モニター、インシデント、アラート、定期メンテナンス、ステータスページ、オンコールポリシー、チームなど、OneUptime のほぼすべてのものがワークフローをトリガーできます。それぞれに 3 つのイベントが用意されています。

- **On Create** — 新しいものが追加されたときに発火。
- **On Update** — 何かが変更されたときに発火。
- **On Delete** — 何かが削除されたときに発火。

これが、ループで確認し続けることなく「OneUptime で X が起きたら Y を行う」を組み立てる方法です。

レコード全体が次のブロックに渡されます。たとえば **Incident → On Create** トリガーは新しいインシデントを渡すので、次のブロックはそのタイトル、説明、重大度、その他のフィールドを読み取れます。

### 最もよく使われるイベント

- **Incident** — インシデントが開かれた、更新された (承認、解決)、削除されたときに反応。
- **Alert** — アラートについても同じ 3 種類。
- **Monitor** — モニターが追加、編集、削除されたときに反応。
- **Scheduled Maintenance** — メンテナンスウィンドウがスケジュールされたら自動でアナウンス。
- **Status Page Subscriber** — ステータスページに購読した人を歓迎する。
- **On-Call Duty Policy** — スケジュールの変更を別のローテーション管理システムに同期する。

**Add Trigger** パネルで名前を検索して、目的のものを見つけてください。

## どのトリガーを使うべきか

| やりたいこと…                             | 選ぶもの             |
| ------------------------------------------ | -------------------- |
| ボタンをクリックしてワークフローを実行する | **Manual**           |
| 繰り返しスケジュールで実行する             | **Schedule**         |
| 他のシステムにデータを送り込ませる         | **Webhook**          |
| OneUptime 内の何かに反応する               | **OneUptime event**  |

ワークフローが持てるトリガーは 1 つだけです。同じ自動化を 2 通りの方法で開始したい場合は、共通のロジックを 1 つのワークフローにまとめ、**Execute Workflow** コンポーネントを使って 2 つの薄い「ラッパー」ワークフローから呼び出してください。
