# ワークフローを作成する

ワークフローを作成するには、**ワークフロー** を開いて **Create Workflow** をクリックします。**Create a workflow** というウィザードが手順を案内します。最初は **Start from** — **Start from scratch** かいずれかのテンプレートを選び、次に **Name**、最後に **Configure** ステップです。これは選んだテンプレートが独自の設定を必要とする場合にのみ表示されます。

作成が終わったら、左メニューの **ビルダー** を開きます。そこがワークフローを設計するキャンバスです。

## キャンバス

ゼロから始めたワークフローは、**Please click here to add trigger** と書かれた 1 つの破線のブロックだけで開きます。そのブロックが起点で、クリックするとトリガーを選べます。テンプレートから作成したワークフローは、すでにブロックが配置された状態で開きます。

すべてのワークフローには、必ず 1 つの **トリガー** が一番上にあります。それ以外はすべて何かを行う **コンポーネント** です。2 つ目のトリガーを追加すると最初のものを置き換え、最後の 1 つを削除すると破線のプレースホルダーが戻ってきます。

ブロックの追加方法:

- **トリガー** — 破線のプレースホルダーブロックをクリックします。**Add Trigger** というパネルが開きます。
- **それ以外すべて** — キャンバス上部のツールバーで **コンポーネントを追加** をクリックします。同じパネルが **Add Component** というタイトルで開きます。

どちらのパネルも検索可能です — `/` を押すと検索ボックスにジャンプします — カテゴリごとにグループ化されています。1 つのブロックを選んで **Add to Workflow** をクリックします。

新しいブロックは常にキャンバス上の同じ場所に置かれるため、新しいものがすでに配置した何かの上に重なることがあります。ドラッグしてどかしてください。キャンバスは動かすたびにグリッドにスナップします。ブロックの位置は保存されるので、次にそのワークフローを開く人にも、あなたが残した配置がそのまま見えます。

変更は自動的に保存されます。ツールバーのピルがそれを追跡します — 変更が処理中は **Saving…**、その後 **Saved**、うまくいかなければ **Could not save** です。保存ボタンや、別途の公開ステップはありません。

## ブロックに含まれるもの

| フィールド                       | 何をするか                                                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Identifier** (**ID** の下)     | ブロック上に表示される短い ID、たとえば `log-1`。他のブロックがこのブロックを参照する方法なので、名前を変更すると、それを指すすべての `{{local.components.…}}` 参照が壊れます。ブロックの見出しはそのコンポーネント自身の名前で、変更できません。 |
| **Settings**                     | ブロックがその役割を果たすために必要なもの — URL、Slack チャンネル、メッセージ本文など。任意項目には **(Optional)** というラベルが付き、それ以外はすべて必須です。あまり使わない設定は **Advanced** の折りたたみの中にあります。 |
| **Input**                        | 上端にあるドット。前のブロックからの線がここに入ってきます。トリガーにはこれがありません — トリガーの前には何も実行されないためです。                                     |
| **Outputs**                      | 下端に並ぶドットで、それぞれの上にラベルが付いています。ここから線が次のブロックへ出ていきます。多くのブロックには **Success** と **Error** の別々の出力があり、両方のケースを扱えます。 |

## ブロックをつなぐ

あるブロックの下端のドットから、次のブロックの上端のドットへドラッグします。引いた線が、次に何が実行されるかを決めます。

- **Success** から接続すると、次のブロックは前のブロックが成功したときだけ実行されます。
- **Error** から接続すると、次のブロックは前のブロックが失敗したときだけ実行されます。
- 出力を接続しなければ、その経路はそこで止まります。

1 つの出力を複数のブロックに接続できます。すべて実行されますが、並列ではなく単一のキューで順番に実行されます。分岐同士の順序に依存したり、時間的に重なることを当てにしたりしないでください。各ブロックは 1 回の実行につき最大 1 回しか実行されないため、前のブロックへループして戻っても、そのブロックが二重に実行されることはありません。

## ブロックを設定する

ブロックをクリックすると、その設定がダイアログで開きます。それぞれの設定には適切な種類の入力欄があります — テキストフィールド、ドロップダウン、コードエディタ、トグルなどです。入力して **保存** をクリックします。

同じダイアログには次もあります。

- **削除** — このブロックを削除します。
- **Run just this step** — ワークフローの他の部分を実行せずに、このブロック単体を実行します。他のステップから読み取るはずだった値は空のまま渡され、実際に送信・書き込み・削除される内容は本当に実行されます。
- **Documentation**、**Inputs**、**Outputs**、**Returns** — このブロックが何を期待し、何を生成するかのリファレンスカードです。

ほとんどのテキストフィールドは変数を受け付けます — これがデータをあるブロックから次のブロックへ流す方法です。構文を手で入力するのではなく、エディタ内の value picker を使ってください。選んだブロックとフィールドから正しい参照を組み立ててくれます。詳しくは [変数](/docs/workflows/variables) を参照してください。

## 組み立てながらのチェック

**ビルダー** は変更するたびにグラフ全体をチェックし、その結果をツールバーのピルで報告します。ピルをクリックすると **Problems with this workflow** が開き、各問題と、責任のあるブロックへのジャンプ先が一覧表示されます。問題のあるブロックには、キャンバス上に赤いバッジも付きます。

これは、実行が失敗するまで見えないままになりがちなミスを捕捉します — トリガーがない、2 つのブロックが同じ ID を共有している、ID の中にドットがある、何もつながっていないブロック、空のままの必須設定、不正な形式の JSON、`{{ }}` の中のスペース、存在しないステップや戻り値への参照などです。

チェックできないことが 1 つあります。それは変数名が実際に存在するかどうかです。変数名を変更した場合、それは実行ログにしか現れません。

## 最初のワークフロー

キャンバスの感触をつかむ、いちばん手早い方法です。

1. 破線のプレースホルダーブロックをクリックし、**Add Trigger** パネルで **Manual** を選び、**Add to Workflow** をクリックします。
2. **コンポーネントを追加** をクリックし、(**Utils** の下にある) **Log** を選び、**Add to Workflow** をクリックします。新しいブロックをトリガーからドラッグして離し、トリガーの **Execute** ドットを Log ブロックの入力ドットへつなぎます。
3. Log ブロックを開き、その **Value** を `Hello from {{local.components.manual-1.returnValues.value.name}}` に設定します。`manual-1` はトリガーブロックに表示されている **Identifier** です — 一致しているか確認してください。
4. **概要** に移動し、**Workflow Details** カードの **Edit Workflow** をクリックして **有効** をオンに切り替えます。無効なワークフローは、手動であっても一切実行できません。
5. **ビルダー** に戻り、**ワークフローを実行** をクリックし、**JSON** フィールドに `{ "name": "Ada" }` と入力し、**Run Workflow Manually** をクリックして、**Run** で確定します。
6. **Workflow Run** パネルが自動的に開き、実行を追跡します。ログには `Value:` に続けて `Hello from Ada` と表示されます。

追加、接続、設定、実行、ログを読む — このサイクルが、あらゆるワークフローの組み立て方です。

## オンにする

新しいワークフローは無効な状態で始まります。複製やインポートしたワークフローも同様です。

**有効** スイッチは、ワークフローの **概要** ページの **Workflow Details** カードにあります — **Settings** ページではありません。同じカードには、現在の状態が緑の **Enabled** または赤の **Disabled** のピルとして表示されます。

無効なワークフローは一切実行できません。手動実行も、トリガーされた実行と同じく「This workflow is not enabled」で拒否されます。したがって手順は、有効にする、**ワークフローを実行** でテストする、実行ログを読む、トリガーを発火させる準備ができていなければ **有効** をオフに戻す、という順序になります。ワークフロー全体を実行せずに 1 つのブロックだけをテストするには、そのブロックの設定にある **Run just this step** を使ってください。

削除せずにワークフローを一時停止するには、**有効** をオフにします。新しい実行は開始されません。実行中の実行は最後まで終わりますが、**Sleep** ブロックで待機中の実行は、目覚めたタイミングでキャンセルされ、エラーとして記録されます。

## 整理する

- ブロックはドラッグして移動できます。レイアウトは保存されます。
- 線を削除するには、どちらかの端をドットから外し、空いているキャンバスにドロップします。
- ブロックを削除するには、それをクリックし、設定ダイアログの下部にある **削除** を使います。ブロックや線を選択して Backspace を押しても削除されます。
- 単一のブロックを複製する方法はありません。ワークフローの **Settings** ページにある **Duplicate Workflow** はワークフロー全体をコピーし、コピーは無効な状態で作成されます。
- ブロックは上から下へ、実行される方向に読めるように積み重ねましょう — 入力は上端、出力は下端にあるので、流れは自然に下向きになります。
