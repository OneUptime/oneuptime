# リソースとグループ

リソースは、ステータスページ上の 1 行 — モニター（またはモニターグループ）に、訪問者が理解できる名前、現在のステータス、そして任意で稼働率の数値と履歴チャートを付けたものです。グループはリソースを保持するセクションで、40 個のモニターを持つページも "API"、"Web app"、"Data pipeline" のように読めるようになります。1 つの終わりのない一覧になってしまうことはありません。

この両方を 1 つの画面で構築します。ステータスページを開いて、サイドメニューの **リソース** を選びます（モニターグループが有効でないプロジェクトでは、この項目は **モニター** と表示されます）。グループはかつて独自のページを持っていましたが、今はそうではなく、古い `/groups` URL はここにリダイレクトされるだけです。

ここさえ正しくできれば、ステータスページの残りは装飾です。訪問者はこれらの行から「自分だけの問題なのか、それとも本当に障害なのか」を判断するので、顧客があなたの製品について話すときの言葉で名付けてください — `prod-checkout-lb-healthcheck-us-east-1` ではなく **Checkout API** のように。

## リソース画面

画面は 2 つに分かれています。左側にはページ上のすべてのグループを一覧するナビゲーターがあり、右側には選択したグループの中身が表示されます。

- **グループナビゲーター（左）** — グループのツリーで、上部に検索ボックス（**Search groups...**）、下部に `3 groups · 12 resources` のような実行中のカウントが表示されます。ページが表示しきれない数のグループを持つ場合、**Show N more of M** ボタンで残りが表示されます。
- **Top of page** — ナビゲーターの最初の行。どのグループにも属さないリソースを保持し、そのツールチップは意味を正確に説明します。訪問者にはこれらがすべてのグループより前、最初に表示されます。ページにグループがまったくない場合、右側のペインは代わりに **All resources** というタイトルになります。
- **リソースペイン（右）** — 選択したグループの名前がタイトルになります。ヘッダーには **Edit Group**、プライマリの **Add Monitor** ボタン、そして **More actions** のオーバーフローがあります。

カードのヘッダー自体には 2 つのボタンがあります — **New Group**、そして **Import groups from CSV** と **Refresh** を持つ 3 点リーダーのオーバーフローです。

カードの説明文は、ページの形に応じて変わります。グループがある場合は、これが訪問者に見えるものすべてであり、その中身を編集するには左でグループを選んでください、と書かれます。まだグループがない場合は、長いページをセクションに分けるためにグループを作成するよう促されます。

**空の状態が次にすべきことを教えてくれます。** 空のグループには **No monitors here yet** とともに **Add Monitor**、**Add Multiple**、そして — ステータスページにグループがまったくない場合のみ — **Create a Group** が表示されます。何にも一致しない検索には **No resources match your search** が表示されます。空のナビゲーターには、グループが長いステータスページをセクションに分割するものであり、入れ子にできることが説明されます。

## モニターを追加する

リソースを配置したいグループを選択し（グループ化しない行にしたい場合は **Top of page**）、**Add Monitor** をクリックします。モーダルのタイトルは **Add a monitor to {group}** で、**Monitor Details** と **Advanced** の 2 つのステップがあります。

**Monitor Details** では：

- **Monitor** — プロジェクト内のモニターのドロップダウン、プレースホルダーは **Select Monitor**。必須。
- **Display Name** — 必須。これは訪問者が読むテキストで、モニター自体の名前とは別に保存されるため、監視に触れることなくここで名前を変更できます。
- **Description** — 任意の Markdown で、行の下に表示されます。そのサービスが実際に何をしているかを説明する 1 文に向いています。

プロジェクトでモニターグループが有効な場合、ドロップダウンの下に **Add a Monitor Group instead.** というリンクが表示されます — クリックすると **Monitor** ドロップダウンが **Monitor Group** ドロップダウン（**Select Monitor Group**）に切り替わります。そのリンクは **Add a Monitor instead.** に変わり、元に戻せます。ページ上の 1 行で複数のチェックをまとめて表したいときはモニターグループを使ってください。

### 複数を一度に追加する

**Add Multiple**（**More actions** メニューにも **Add multiple monitors** としてあります）は **Add Multiple Monitors** を開きます。同じ 2 つのステップですが、最初のステップは単一のドロップダウンではなく **Monitors** の複数選択になり、**Advanced** で選んだ表示オプションは選んだすべてのモニターに適用されます。新しいページに種をまく最速の方法です。

## リソースの表示オプション

**Advanced** ステップは、単体追加フォームと一括モーダルで共通です。ここにあるものはすべてリソースごとの設定です — 同じグループ内の 2 行でも異なる設定にできます。

| フィールド                                                | 用途                                                                                          |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Tooltip**（`displayTooltip`）                             | ステータスページ上でリソースの横に表示される追加テキスト。範囲を示すのに使えます — "US and EU customers"。 |
| **Show Current Resource Status**（`showCurrentStatus`）     | デフォルトでオン。運用中、劣化、オフラインといった現在のステータスを行の隣に表示します。       |
| **Show Uptime %**（`showUptimePercent`）                    | デフォルトでオフ。リソースの隣に稼働率をパーセントで表示します。                              |
| **Select Uptime Precision**（`uptimePercentPrecision`）     | **Show Uptime %** がオンのときだけ表示されます。必須、デフォルトは小数点以下 1 桁。            |
| **Show Status History Chart**（`showStatusHistoryChart`）   | デフォルトでオン。リソースの日別稼働率履歴のバーチャートを表示します。                        |

最初のステップの **Display Name**（`displayName`）と **Description**（`displayDescription`）も表示専用です — モニター自体が変更されることはありません。

## 稼働率と履歴チャート

**Show Uptime %** と **Show Status History Chart** はどちらも、別の場所にある設定に依存しています。それらがカバーする期間は、**ステータスページ → 対象のページ → Advanced → 詳細設定** の **Uptime History Settings** カードにある **Show Uptime History (in days)** です。1 日から 90 日まで指定でき、デフォルトは 90 です。

つまり流れとしては、リソースごとにトグルをオンにし、ページ全体で一度だけ期間を設定します。

**精度は判断が分かれるところです。** **Select Uptime Precision** ドロップダウンは `99% (No Decimal)`、`99.9% (One Decimal)`、`99.99% (Two Decimal)`、`99.999% (Three Decimal)` を用意しています。小数点以下の桁が多いほど精密に見えて、3 桁目についての議論を招きます。3 ナインで SLA を公開しているなら、それに合わせて、それ以上は出さないようにしましょう。

グループにはこれらのトグルの独自のコピーがあります — 後述 — ので、グループはまとめたパーセントを表示しつつ、その中の個々のモニターは静かにしておく、あるいはその逆も可能です。

履歴チャートのバーの色と、どのモニターステータスを「ダウン」として扱うかは **Overview Page** のブランディング画面で設定します。詳しくは [ステータス ページのブランディングとドメイン](/docs/status-pages/branding-and-domains) を参照してください。

## グループ

**New Group** をクリックすると **Create New Status Page Group** が開きます。フォームには **Group Details**、**Layout**、**Advanced** の 3 つのステップがあります。

**Group Details**：

- **Group Name**（`name`）— 必須。訪問者が見るセクションの見出しです。
- **Group Description**（`description`）— 任意の Markdown で、見出しの下に表示されます。
- **Parent Group**（`parentStatusPageGroupId`）— 任意。グループをトップレベルに保つには **No parent group (top level)** のままにします。
- **Expand on Status Page by Default**（`isExpandedByDefault`）— セクションが訪問者に対して開いた状態で始まるか、折りたたまれた状態で始まるか。

**Advanced** はグループレベルでリソースのトグルを反映します：

- **Show Current Group Status**（`showCurrentStatus`）— デフォルトでオン。グループの見出しの隣にステータスを表示します。
- **Show Uptime %**（`showUptimePercent`）— デフォルトでオフ。オンになると **Select Uptime Precision** が表示されます。

編集も同じ方法で行います — ペインヘッダーの **Edit Group**、またはナビゲーターの行メニューの **Edit group** をクリックすると **Edit Status Page Group** が開き、**Save Changes** ボタンがあります。

ペインヘッダーには、現在オンになっている設定のチップが表示されます — **Grid**、**Collapsed by default**、**Uptime %** — フォームを開かなくても、グループがどう設定されているか確認できます。

### グループを管理する

ナビゲーターの行ごとのメニューには **Edit group**、**Move up**、**Move down**、**Show ID**、**Delete group** があります。ペインの **More actions** オーバーフローには、より詳しい同等の項目があります — **Edit this group**、**Add a sub group**、**Move group up**、**Move group down**、**Show group ID**、**Refresh**、**Delete this group**。名前を付けずに保存されたグループは **Untitled group** と表示され、何かを入力し忘れているサインです。

## グループを入れ子にする

グループは入れ子にできます — 子グループで **Parent Group** を設定するか、ナビゲーターの **Add a sub group inside this group** アクションを使います。フォーム自身のヘルプテキストには、Corporate Units › Region › Market のような、想定されている形が説明されており、各階層はその下にあるすべてのものをまとめたステータスと稼働率を表示すると書かれています。

グループに子がある場合、リソースペインには各子への直接リンクを持つ **Sub groups** チップの行が表示されるので、ナビゲーターに戻ることなく階層をたどれます。

入れ子は大きなページで真価を発揮します — 製品の中にリージョンがあるホスティングプロバイダーや、事業単位の中に市場がある小売業者などです。モニターが 12 個程度のページでは、1 段のフラットな構成の方が親切です。

## リストレイアウトとグリッドレイアウト

**Layout** ステップはグループの **View Mode**（`viewMode`）を設定し、グループが公開時にどう表示されるかを変えます。

| やりたいこと                                                       | 選択                       |
| -------------------------------------------------------------------- | ---------------------------- |
| サービスの単純な縦一列のリストを、1 行ずつ表示する                   | **List**（デフォルト）     |
| 同じサービスを複数のリージョンやテナントにまたがるマトリクスとして表示する | **Grid**                   |

**Grid** を選ぶと、さらに 4 つのフィールドが表示されます。

- **Row Axis Label** — 行の次元の名前。プレースホルダーは `Service`。
- **Row Axis Values** — 行そのもの。**Add Row** で 1 つずつ追加します（プレースホルダーは `e.g. Auth`）。
- **Column Axis Label** — 列の次元。プレースホルダーは `Region`。
- **Column Axis Values** — **Add Column** で追加します（プレースホルダーは `e.g. US-East`）。

グリッドグループ内の各モニターはセルに配置されるので、一括モーダルではモニターとあわせて行と列を、自分で付けた軸ラベルを使って尋ねられます。

**軸はモニターを追加する前に設定してください。** 行または列がないグリッドグループには、軸ができるまでモニターを置く場所がないと伝えるアンバー色の通知と **Set up the grid** ボタンが表示され、それを行うまで **Add Monitor** ボタンは使えません。

## 訪問者が見る順序

順序はアルファベット順ではなく明示的なもので、3 か所で設定します。

- **グループ内のリソース** — 行をドラッグします。ペインには **Drag a row to change the order visitors see** と表示されます。
- **グループ同士の相対的な順序** — ナビゲーターの行メニューの **Move up** / **Move down**、またはペインのオーバーフローの **Move group up** / **Move group down**。
- **グループ化されていないリソース** — **Top of page** にあり、常にすべてのグループより上に表示されるので、誰もが最初に確認するものをここに置いてください。

**ドラッグが無効になる 2 つのケース。** **Search in {group}...** ボックスでペインを絞り込むと並べ替えが無効になり、ペインには `N of M shown · drag to reorder is off while filtering` と表示されます。まず検索をクリアしてください。また、グリッドグループは位置が行と列の軸から決まるため、ドラッグによる並べ替えを一切サポートしません。

最もよく聞かれるサービスを一番上に置いてください。障害中にページを訪れた訪問者は、たいてい最初の画面を読んだところで読むのをやめます。

## CSV からグループをインポートする

深い階層を手作業で作るのは面倒です。カードヘッダーの 3 点リーダーのオーバーフローには **Import groups from CSV** があり、**Import Groups from CSV** モーダルが開きます。

流れとしては、**Download CSV Template** で `status-page-groups-template.csv` を取得し、記入して、**Choose CSV File**、そして **Preview Import** で何も書き込まれる前に作成される内容を確認します。結果は **Groups Imported** と **Some Groups Could Not Be Imported** に分かれるので、不正な行が黙って消えることはありません。

必須なのは `name` だけです。受け付けられる列は次のとおりです。

| 列                       | 設定される内容                                       |
| ------------------------- | ------------------------------------------------------ |
| `name`                    | グループ名。必須。                                     |
| `parentName`              | このグループが入れ子になる親グループの名前。            |
| `description`             | グループの説明。                                       |
| `isExpandedByDefault`     | セクションが訪問者に対して開いた状態で始まるかどうか。   |
| `showCurrentStatus`       | グループの見出しの隣にステータスを表示するかどうか。     |
| `showUptimePercent`       | グループの隣に稼働率をパーセントで表示するかどうか。     |
| `uptimePercentPrecision`  | そのパーセントが使用する小数点以下の桁数。               |
| `viewMode`                | `List` または `Grid`。                                  |
| `rowAxisLabel`            | グリッドグループの行の次元名。                          |
| `rowAxisValues`           | グリッドグループの行の値。                              |
| `columnAxisLabel`         | グリッドグループの列の次元名。                          |
| `columnAxisValues`        | グリッドグループの列の値。                              |

インポートが作成するのはグループであり、リソースではありません — その後 **Add Monitor** または **Add Multiple** でモニターを追加してください。
