# リソースとグループ

リソースとは、ステータスページ上の 1 行のことです — 訪問者に伝わる名前と現在の状態を持ち、必要なら稼働率の数値と履歴チャートも付いたモニター（またはモニターグループ）です。グループはリソースをまとめるセクションで、40 個のモニターを載せたページを、果てしない 1 本の一覧ではなく「API」「Web アプリ」「データパイプライン」として読ませてくれます。

どちらも 1 つの画面で作ります。ステータスページを開き、サイドメニューで **リソース** を選んでください（モニターグループが有効でないプロジェクトでは **モニター** と表示されます）。グループにはかつて専用ページがありましたが、今はもうありません。古い `/groups` の URL はここへリダイレクトされます。

ここさえ決まれば、ステータスページの残りは飾りです。訪問者は「自分の問題か、向こうの問題か」をこれらの行から判断します。だから顧客が製品を語るときの言葉で名前を付けてください — `prod-checkout-lb-healthcheck-us-east-1` ではなく **Checkout API** です。

## リソース画面

画面は左右に分かれています。左はページ上のすべてのグループを並べたナビゲーター、右は選択したグループの中身です。

- **グループナビゲーター（左）** — グループのツリーです。上に検索ボックス（**Search groups...**）、下に `3 groups · 12 resources` のような現在の件数が表示されます。グループが表示枠に収まらないときは、**Show N more of M** ボタンで残りが開きます。
- **Top of page** — ナビゲーターの最初の行です。どのグループにも属さないリソースが入り、ツールチップがその意味をそのまま説明します。訪問者はここを、すべてのグループより先に目にします。ページにグループが 1 つもない場合、右ペインのタイトルは代わりに **All resources** になります。
- **リソースペイン（右）** — 選択中のグループ名がタイトルになります。ヘッダーには **Edit Group**、主要ボタンの **モニターを追加**、そして **More actions** のオーバーフローがあります。

カードのヘッダー自体にもボタンが 2 つあります。**New Group** と、**Import groups from CSV** と **更新** を収めた三点リーダーのオーバーフローです。

カードの説明文はページの形に応じて変わります。グループがある場合は、これが訪問者に見えるすべてであり、中身を編集するには左でグループを選ぶように、と書かれています。グループがまだない場合は、長いページをセクションに分けるためにグループを作るよう促します。

**空の状態が次にやることを教えてくれます。** 空のグループには **No monitors here yet** と、**モニターを追加**、**Add Multiple**、そして — ステータスページにグループが 1 つもないときだけ — **Create a Group** が表示されます。検索が何にも一致しないときは **No resources match your search** が出ます。ナビゲーターが空のときは、グループが長いステータスページをセクションに分けること、そして入れ子にできることが説明されます。

## モニターを追加する

リソースを入れたいグループ（グループなしの行にするなら **Top of page**）を選び、**モニターを追加** をクリックします。モーダルのタイトルは **Add a monitor to {group}** で、**モニター詳細** と **詳細** の 2 ステップです。

**モニター詳細** では次を指定します。

- **モニター** — プロジェクト内のモニターのドロップダウン。プレースホルダーは **モニターを選択**。必須です。
- **表示名** — 必須。訪問者が読むテキストで、モニター自身の名前とは別に保存されます。監視側に手を入れずにここで名前を変えられます。
- **説明** — 任意の Markdown で、行の下に表示されます。そのサービスが実際に何をするのかを 1 文で書くのに向いています。

プロジェクトでモニターグループが有効なら、ドロップダウンの下に **Add a Monitor Group instead.** というリンクが出ます。クリックすると **モニター** のドロップダウンが **モニター グループ**（**モニターグループを選択**）に切り替わります。リンクは **Add a Monitor instead.** に変わるので元に戻せます。ページ上の 1 行で複数のチェックをまとめて表したいときにモニターグループを使ってください。

### 複数を一度に追加する

**Add Multiple**（**More actions** メニューでは **Add multiple monitors**）は **Add Multiple Monitors** を開きます。ステップは同じ 2 つですが、最初のステップが単一のドロップダウンではなく **モニター** の複数選択になり、**詳細** で選んだ表示オプションは選んだすべてのモニターに適用されます。新しいページに中身を入れる最速の方法です。

## リソースの表示オプション

**詳細** ステップは単体追加のフォームでも一括追加のモーダルでも同じです。ここにある項目はすべてリソース単位です — 同じグループの 2 行を別々に設定できます。

| フィールド                                               | 役割                                                                                                |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **ツールチップ**（`displayTooltip`）                     | ステータスページ上でリソースの横に表示する補足テキスト。「米国と EU の顧客向け」のような範囲の説明に。 |
| **現在のリソースステータスを表示**（`showCurrentStatus`） | 既定でオン。稼働中・劣化・停止といった現在の状態を行の横に表示します。                              |
| **稼働率を表示**（`showUptimePercent`）                  | 既定でオフ。リソースの横に稼働率のパーセントを表示します。                                          |
| **稼働率の精度を選択**（`uptimePercentPrecision`）       | **稼働率を表示** をオンにしたときだけ現れます。必須で、既定は小数第 1 位です。                      |
| **ステータス履歴チャートを表示**（`showStatusHistoryChart`） | 既定でオン。リソースの日ごとの稼働率履歴を棒グラフで表示します。                                 |

最初のステップにある **表示名**（`displayName`）と **説明**（`displayDescription`）も表示専用です — モニター本体を変えることはありません。

## 稼働率と履歴チャート

**稼働率を表示** と **ステータス履歴チャートを表示** はどちらも、別の場所にある設定に依存します。対象期間は **ステータスページ → 対象のページ → 詳細 → 詳細設定** の **稼働時間履歴設定** カードにある **稼働率履歴の表示（日数）** です。1 日から 90 日を受け付け、既定は 90 です。

つまり順序はこうです。リソースごとにトグルをオンにし、期間はページ全体で一度だけ設定します。

**精度は判断の問題です。** **稼働率の精度を選択** のドロップダウンには `99% (No Decimal)`、`99.9% (One Decimal)`、`99.99% (Two Decimal)`、`99.999% (Three Decimal)` があります。小数を増やすほど正確そうに見えますが、3 桁目をめぐる議論も呼び込みます。SLA をスリーナインで公開しているなら、それに合わせてそれ以上は出さないことです。

グループにも同じトグルの独自のコピーがあります — 後述します — ので、中のモニターは黙らせたままグループだけ集約したパーセントを出す、あるいはその逆もできます。

履歴チャートのバーの色と、どのモニターステータスを「ダウン」と数えるかは、**概要ページ** のブランディング画面で設定します。詳しくは [ステータス ページのブランディングとドメイン](/docs/status-pages/branding-and-domains) を参照してください。

## グループ

**New Group** をクリックすると **Create New Status Page Group** が開きます。フォームは **グループの詳細**、**レイアウト**、**詳細** の 3 ステップです。

**グループの詳細**:

- **グループ名**（`name`）— 必須。訪問者に見えるセクション見出しです。
- **グループの説明**（`description`）— 任意の Markdown で、見出しの下に表示されます。
- **Parent Group**（`parentStatusPageGroupId`）— 任意。**No parent group (top level)** のままにすればトップレベルのグループになります。
- **デフォルトでステータスページに展開する**（`isExpandedByDefault`）— 訪問者にとってセクションが開いた状態で始まるか、たたまれた状態で始まるか。

**詳細** はリソースのトグルをグループ単位で写したものです。

- **現在のグループステータスを表示**（`showCurrentStatus`）— 既定でオン。グループ見出しの横に状態を表示します。
- **稼働率を表示**（`showUptimePercent`）— 既定でオフ。オンにすると **稼働率の精度を選択** が現れます。

編集も同じ流れです。ペインヘッダーの **Edit Group**、またはナビゲーターの行メニューの **Edit group** から **Edit Status Page Group** が開き、**変更を保存** で保存します。

ペインのヘッダーには現在オンになっている設定がチップで並びます — **Grid**、**Collapsed by default**、**Uptime %** — ので、フォームを開かなくてもグループの設定を確認できます。

### グループを管理する

ナビゲーターの行ごとのメニューには **Edit group**、**Move up**、**Move down**、**IDを表示**、**Delete group** があります。ペインの **More actions** オーバーフローには、より説明的な同等の項目 — **Edit this group**、**Add a sub group**、**Move group up**、**Move group down**、**Show group ID**、**更新**、**Delete this group** — が並びます。名前を付けずに保存したグループは **Untitled group** と表示されます。何か入力し忘れた良い目印です。

## グループを入れ子にする

グループは入れ子にできます。子側で **Parent Group** を設定するか、ナビゲーターの **Add a sub group inside this group** を使います。フォームのヘルプテキストが、想定している形 — Corporate Units › Region › Market のようなもの — を説明し、どの階層も配下すべての状態と稼働率を集約して表示すると書いています。

グループに子があると、リソースペインに **Sub groups** のチップ行が出て、各子グループへ直接飛べます。ナビゲーターに戻らずに階層をたどれるということです。

入れ子が本当に効いてくるのは大きなページです。製品の下にリージョンを持つホスティング事業者や、事業部の下に市場を持つ小売業などです。モニターが 12 個のページなら、フラットな 1 階層のほうが親切です。

## リストレイアウトとグリッドレイアウト

**レイアウト** ステップではグループの **表示モード**（`viewMode`）を設定します。これは公開時のグループの見え方を変えます。

| やりたいこと                                             | 選ぶもの               |
| -------------------------------------------------------- | ---------------------- |
| サービスを 1 行ずつ、素直な縦一列で見せる               | **List**（既定）       |
| 同じサービスを複数のリージョンやテナントで行列表示する | **Grid**               |

**Grid** を選ぶと、さらに 4 つのフィールドが現れます。

- **行軸ラベル** — 行の軸の名前。プレースホルダーは `Service`。
- **行軸の値** — 行そのもの。**Add Row**（プレースホルダー `e.g. Auth`）で 1 つずつ追加します。
- **列軸のラベル** — 列の軸。プレースホルダーは `Region`。
- **列軸の値** — **Add Column**（プレースホルダー `e.g. US-East`）で追加します。

グリッドグループの各モニターはセルに配置されるので、一括追加のモーダルではモニターと一緒に行と列も尋ねられます。ラベルにはあなたが決めた軸名が使われます。

**モニターを追加する前に軸を用意してください。** 行も列もないグリッドグループには、軸ができるまでモニターの置き場所がないという琥珀色の注意書きと **Set up the grid** ボタンが表示され、それまで **モニターを追加** ボタンは引っ込んでいます。

## 訪問者が見る順序

順序はアルファベット順ではなく明示的に決まり、設定する場所は 3 か所あります。

- **グループ内のリソース** — 行をドラッグします。ペインにもそう書かれています。**Drag a row to change the order visitors see**。
- **グループどうしの順序** — ナビゲーターの行メニューの **Move up** / **Move down**、またはペインのオーバーフローの **Move group up** / **Move group down**。
- **グループなしのリソース** — **Top of page** に入り、常にすべてのグループより上に表示されます。誰もが最初に確認するものはここに置いてください。

**ドラッグが効かないケースが 2 つあります。** **Search in {group}...** ボックスでペインを絞り込んでいるあいだは並べ替えが無効になります。ペインには `N of M shown · drag to reorder is off while filtering` と表示されるので、まず検索をクリアしてください。もう 1 つ、グリッドグループはドラッグでの並べ替えに一切対応しません。位置は行と列の軸で決まるからです。

いちばん問い合わせの多いサービスを先頭に置いてください。障害中にページを訪れた人は、たいてい最初の 1 画面で読むのをやめます。

## CSV からグループをインポートする

深い階層を手で作るのは骨が折れます。カードヘッダーの三点リーダーのオーバーフローにある **Import groups from CSV** から、**Import Groups from CSV** のモーダルが開きます。

流れはこうです。**Download CSV Template** で `status-page-groups-template.csv` を取得し、記入してから **Choose CSV File**、そして **Preview Import** で、何も書き込まれる前に作成される内容を確認します。結果は **Groups Imported** と **Some Groups Could Not Be Imported** に分かれるので、不正な行が黙って消えることはありません。

必須なのは `name` だけです。受け付ける列は次のとおりです。

| 列                       | 設定する内容                                       |
| ------------------------ | ---------------------------------------------------- |
| `name`                   | グループ名。必須。                                   |
| `parentName`             | このグループが属する親グループの名前。               |
| `description`            | グループの説明。                                     |
| `isExpandedByDefault`    | 訪問者にとってセクションが開いた状態で始まるか。     |
| `showCurrentStatus`      | グループ見出しの横に状態を出すか。                   |
| `showUptimePercent`      | グループの横に稼働率のパーセントを出すか。           |
| `uptimePercentPrecision` | そのパーセントの小数桁数。                           |
| `viewMode`               | `List` または `Grid`。                               |
| `rowAxisLabel`           | グリッドグループの行の軸の名前。                     |
| `rowAxisValues`          | グリッドグループの行の値。                           |
| `columnAxisLabel`        | グリッドグループの列の軸の名前。                     |
| `columnAxisValues`       | グリッドグループの列の値。                           |

インポートが作るのはグループであってリソースではありません — モニターは後から **モニターを追加** か **Add Multiple** で足してください。
