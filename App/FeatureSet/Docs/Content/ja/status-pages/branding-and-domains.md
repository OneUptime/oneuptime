# ブランディングとカスタムドメイン

ステータスページは、顧客が実際に見る唯一の OneUptime の画面です。だから自分たちのものらしく見え、自分たちのドメインに載っているべきです。そのどちらも、ステータスページのサイドメニューの **ブランディング** セクションと、**詳細設定** に隠れている設定 1 つで構成します。

始める前に知っておきたいこと。ブランディングは 7 つの画面に分かれていて、その分かれ方は必ずしも予想どおりではありません。ロゴとカバー画像は **基本ブランディング** ではなく **ヘッダー** にあります。ファビコンは **基本ブランディング** です。色は **概要ページ** にあります。「テーマ」と呼びたくなるそれ以外のものは、すべてカスタム CSS の仕事です。

このページでは各画面を順に見ていき、そのあと `status.yourcompany.com` にページを載せるための CNAME から SSL までの手順をひととおり案内します。

## 各ブランディング設定の場所

ステータスページを開くと、サイドメニューの **ブランディング** セクションに 7 つの項目があります。探し回らずに済むよう、地図を置いておきます。

| ページ                     | そこで設定するもの                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| **基本ブランディング**     | ページタイトル、ページの説明、検索エンジンのインデックス、ファビコン。                     |
| **ヘッダー**               | ロゴ、カバー画像、それらの代替テキスト、ヘッダーのリンクバー。                             |
| **フッター**               | 著作権表示とフッターのリンクバー。                                                         |
| **概要ページ**             | 概要の説明、履歴チャートのバーの色、ダウンとみなすステータス、全体の稼働率。               |
| **HTML、CSS、JavaScript**  | ヘッダー HTML、フッター HTML、カスタム CSS、カスタム JavaScript。                          |
| **カスタムドメイン**       | 自社ドメイン、CNAME の検証、SSL。                                                          |
| **言語**                   | 既定の言語と、フッターの切り替えで提供する言語。                                           |

## 基本ブランディング

**ステータスページ → 対象のページ → ブランディング → 基本ブランディング**（`{id}/branding`）には 3 つのカードがあります。

- **タイトルと説明** — カードにも書かれているとおり、これは SEO にも使われます。**編集** を押すと **ページタイトル**（プレースホルダー `Please enter page title here.`）と **ページの説明** が開きます。検索エンジンとリンクプレビューに出るものなので、社内向けではなく顧客向けに書いてください。
- **Search Engine Indexing** — トグルが 1 つ、**Allow Search Engines to Index this Status Page** です。製品の説明では、Google や Bing がこのページを検索結果に載せてよいかを制御するとされています。既定でオンです。オフにすると、ページは `noindex, nofollow` 付きで配信されます。
- **ファビコン** — **Edit Favicon** で **ファビコン** の画像アップロードが開きます。ブラウザーのタブに出る小さなアイコンです。

こんなときに: ページが社内限定だったり、まだ準備中だったりする場合。**Allow Search Engines to Index this Status Page** をオフにして、作りかけのページが自社ブランド名で検索順位を取り始めないようにします。

## ヘッダー画面

**ステータスページ → 対象のページ → ブランディング → ヘッダー**（`{id}/header-style`）です。サイドメニューの名前に反して、いちばん大きなブランド資産 2 つはここにあります。

最初のカードは **ロゴ、カバー、ファビコン** で、**Edit Images** ボタンが付いています。

- **ロゴ** — 画像アップロード。プレースホルダーは `Upload logo`。
- **Logo Alt Text** — プレースホルダーは `Logo of My Company`。空のままにすると、代わりにステータスページのタイトルが使われます。
- **カバー** — 画像アップロード。プレースホルダーは `Upload cover image`。ヘッダーの背後に敷く横長のバナーです。
- **Cover Image Alt Text** — カバーに対する同じ仕組み。

その下には **ヘッダーリンク** のテーブル（"Header Links for your status page"）があります。各リンクは **タイトル** と **リンク**（URL、プレースホルダー `https://link.com`）を持ち、行はドラッグで並べ替えます。何も設定していないと "No status header link for this status page." と表示されます。

向いている使い方: 訪問者をマーケティングサイト、ドキュメント、サポートポータルへ戻す導線を、URL を推測させずに用意すること。

## フッター画面

**ステータスページ → 対象のページ → ブランディング → フッター**（`{id}/footer-style`）は **ヘッダー** と同じ形で、カード 1 つとテーブル 1 つです。

- **著作権情報** — **Edit Copyright** を押すと **著作権情報** という単一のフィールドが開きます。プレースホルダーは `Acme, Inc.`。
- **フッターリンク** — **タイトル** と **リンク** の組み合わせは同じで、ドラッグで並べ替えます。空のときのメッセージは "No status footer link for this status page."。

法務、プライバシー、利用規約へのリンクはここに置きます。ヘッダーリンクは案内のため、フッターリンクは細かい取り決めのためのものです。

## 概要ページのブランディング

**ステータスページ → 対象のページ → ブランディング → 概要ページ**（`{id}/overview-page-branding`）は、色を設定できる唯一の画面であり、チャート上で「ダウン」が何を意味するかを決める場所でもあります。

- **概要ページ** — **Edit Branding** で Markdown フィールド **概要ページの説明。** が開き、リソース一覧の上に表示されます。このページが何を対象にしているか、サポートの窓口はどこかを 1 文添えるのに使ってください。
- **Rules for Bar Colors of History Chart** — 順序を持ち、ドラッグで並べ替えられるルールのテーブルです。各ルールは **稼働率（%）が次の値以上のとき** と **次に、このバーの色を使用** を持ち、テーブルの列見出しは `When Uptime Percent >=` と `Then, Bar Color is` です。順序が意味を持つので、評価してほしい順に並べてください。
- **ダウンタイムモニターのステータス** — **Edit Statuses** を押すと "These monitor statuses are considered as down" と説明された複数選択が開きます。たとえば劣化状態をこのページの稼働率のマイナスに数えるかどうかを、ここで決めます。
- **履歴チャートのデフォルトのバーの色** — **Edit Default Bar Color** で **デフォルトのバーの色** のピッカーが開きます。どのルールにも一致しなかったときに使う色です。
- **全体の稼働率（パーセント）** — **Edit Settings** で **全体的な稼働率を表示** のトグルと **稼働率の精度を選択** のドロップダウンが開きます。既定は小数第 2 位（`99.99% (Two Decimal)`）です。

**チャートが何日分を対象にするかはここでは決めません。** それは **ステータスページ → 対象のページ → 詳細 → 詳細設定**（`{id}/settings`）にある **稼働率履歴の表示（日数）** で、1 から 90 が有効です。

## カスタム HTML、CSS、JavaScript

**ステータスページ → 対象のページ → ブランディング → HTML、CSS、JavaScript**（`{id}/custom-code`）には、それぞれ独立して編集できるカードが 4 つあります。ステータスページの `headerHTML`、`footerHTML`、`customCSS`、`customJavaScript` カラムに対応します。

- **ヘッダーHTML** — プレースホルダーは `Insert Custom HTML here.`。ページのヘッダーに挿入されます。
- **フッターHTML** — フッターに対する同じもの。
- **カスタム CSS** — プレースホルダーは `Insert Custom CSS here.`
- **カスタム JavaScript** — プレースホルダーは `Insert Custom JavaScript here.`

**テーマの選択肢はありません。** OneUptime のステータスページにはテーマもブランドカラーの設定もありません。組み込みの色の設定は、**概要ページ** 画面にある **デフォルトのバーの色** と履歴チャートのバーの色のルールだけです。フォント、背景色、アクセントカラー、レイアウトの調整はすべてここの **カスタム CSS** を通します。「ブランドカラー」のフィールドを探していたなら、答えはこれです — そんなフィールドはなく、この入力欄が抜け道です。

> カスタム JavaScript は訪問者のブラウザーで動きます。しかもそのページを人が開くのは、何かが壊れていると心配しているまさにそのときです。小さく保ち、可能な限り自前でホストし、頼りにする前にテストしてください。

## 言語設定

**ステータスページ → 対象のページ → ブランディング → 言語**（`{id}/languages`）には 2 つのカードがあり、どちらもページのフッターに出る言語切り替えに関するものです。

- **デフォルト言語** — **Edit Default Language** を押すと、対応言語をネイティブ名と英語名（`Deutsch (German)`）で並べたドロップダウンが開きます。カードの説明では、初めて訪れた人が目にする言語であり、訪問者はいつでもフッターから切り替えられる、とされています。既定は英語です。
- **有効な言語** — **Edit Enabled Languages** で複数選択が開きます。プレースホルダーは `All languages`。空のままにすると、対応するすべての言語が提供されます。いくつか選ぶと、フッターの切り替えにはそれだけが並びます。

OneUptime には 16 の言語が同梱されています。英語、ドイツ語、フランス語、スペイン語、イタリア語、ポルトガル語、オランダ語、デンマーク語、ノルウェー語、スウェーデン語、ロシア語、日本語、韓国語、中国語（簡体字）、中国語（繁体字）、ヒンディー語です。

## カスタムドメイン

既定では、ステータスページは **概要** 画面に表示されるプレビュー URL でアクセスできます。自分のホスト名に載せるには、**ステータスページ → 対象のページ → ブランディング → カスタムドメイン**（`{id}/domains`）へ進みます。

カードのタイトルは **カスタムドメイン** で、説明が要件をそのまま述べています。これを動かすには、対象のドメインの CNAME としてインストールのステータスページ CNAME レコードを追加してください、というものです。何も設定していないとテーブルには "No custom domains found." と表示されます。テーブルの列は **ドメイン** と **ステータス** の 2 つで、**ドメイン**、**CNAME が有効**、**SSL プロビジョニング済み** で絞り込めます。

### 始める前に

前提が 2 つあり、どちらかを飛ばすのがうまくいかない典型的な原因です。

- **親ドメインが検証済みであること。** **ドメイン** のドロップダウンにはプロジェクト設定で検証済みのドメインしか並びません。フィールドのヘルプテキストも、まず **もっと → プロジェクト設定 → カスタムドメイン** で追加するよう案内しています。
- **インストールにステータスページ CNAME レコードが設定されていること。** セルフホストなら Docker Compose の `STATUS_PAGE_CNAME_RECORD` 環境変数、または Helm の `values.yaml` の `statusPage.cnameRecord` です。これがないと、**CNAME を追加** と **無料SSLを注文** のモーダルには手順の代わりに "Custom Domains not enabled for this OneUptime installation" というメッセージが出ます。

### ドメインを追加する

**Create Status Page Domain** をクリックします。モーダル（**Create New Status Page Domain**）は 2 ステップです。

**基本**

- **サブドメイン** — ラベル部分だけを入れます。プレースホルダーは `status (leave blank for root)`。ホスト名全体ではなく `status` だけを入力してください。空のままにするか `@` を入れるとルート（アペックス）ドメインになります。
- **ドメイン** — 検証済みドメインのドロップダウン。プレースホルダーは `Select domain`。

**もっと**

- **カスタム証明書をアップロード** — トグルで、既定はオフです。オフのままなら OneUptime が無料の証明書を取得します。オンにすると、自前の PEM を入れる **証明書** と **証明書の秘密鍵** のフィールドが現れます。

## CNAME を検証する

ドメインが未検証のあいだ、行には **CNAME を追加** のアクションが出ます。押すと **CNAME を追加** というモーダルが開き、DNS プロバイダーに貼り付ける内容がそのまま示されます。

- **レコードタイプ** — `CNAME`
- **名前** — いま作成したドメイン全体。たとえば `status.yourcompany.com`
- **コンテンツ** — インストールのステータスページ CNAME レコード

モーダルには、レコードを設定してから自動検証が終わるまで最大 24 時間かかることがある、と書かれています。それを待つ必要はありません。モーダルの送信ボタンは **CNAMEを確認** で、その場でレコードを確認します。

まず DNS レコードを作り、それから **CNAMEを確認** をクリックしてください。レコードがない状態で押しても失敗するだけです。

## SSL 証明書を注文する

CNAME が検証されると — そして自前の証明書をアップロードしていない場合に限り — 行に **無料SSLを注文** のアクションが現れます。そのモーダル **Order Free SSL Certificate for this Status Page** は、OneUptime が LetsEncrypt を使うこと、この手続きは安全で無料であること、注文後のプロビジョニングに数時間かかることを説明します。送信ボタンは **無料SSLを注文** です。

**画面によって書かれている所要時間が食い違います** ので、どれか 1 つの数字を真に受けないでください。注文のモーダルは 3 時間、**ステータス** 列は 1 時間、カスタム証明書は 30 分と言います。どれも「今日のうちにまた見に来る」くらいに捉え、それでも何も起きなければサポートに連絡してください。

プロビジョニングが済めば、更新は自動です。以後、定期的にやることはありません。

## ドメインの Status 列の読み方

**ステータス** 列は、セットアップの状態遷移がまるごと 1 つのセルに収まったものです。それぞれのメッセージが、次にやることか、もう終わっていることを教えてくれます。

| ステータス列の表示                                    | 意味                                                                            |
| ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| Action Required: Please add your CNAME record.        | CNAME がまだ検証されていません。レコードを追加してから **CNAMEを確認** します。  |
| Action Required: Please order SSL certificate.        | CNAME は検証済みですが証明書が未注文です。**無料SSLを注文** をクリックします。   |
| No action is required, allow 30 minutes to provision. | カスタム証明書をアップロードし、いまインストール中です。                        |
| No action is required, this will be provisioned soon. | 無料証明書は注文済みで処理中です。いつまでも届かなければサポートに連絡を。      |
| Certificate Provisioned. No action required.          | 完了です。OneUptime が証明書を自動で更新します。                                |

DNS エントリを作ってからずいぶん経つのに行が "Action Required: Please add your CNAME record." のままなら、レコードの名前がドメイン全体になっているか、内容がインストールの CNAME レコードと完全に一致しているかを確認してください。

## Powered by OneUptime

"Powered by OneUptime" の一行は、ブランディングセクションの設定ではありません。**ステータスページ → 対象のページ → 詳細 → 詳細設定**（`{id}/settings`）の **Powered By OneUptimeブランディング** カードにある、**「Powered By OneUptime」ブランディングを非表示** というトグル 1 つです。そのページの他のカードと同じく、**Edit Settings** で開きます。
