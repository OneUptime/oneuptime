# ステータスページ概要

ステータスページは、監視しているすべてのものの公開窓口です。何かがおかしいのか自分だけの問題なのかをメールで問い合わせる代わりに、顧客が開ける 1 つの URL です。公開すると決めたサービスの現在の状態、対応中のインシデント、予定しているメンテナンス、そして上部に固定しておきたいお知らせを表示します。

深夜 2 時に何かが壊れたとき、サポートキューが最初にリンクするのがステータスページです。購読者に通知が届くのもここからなので、障害が起きてからではなく、事前に用意しておく価値があります。

ステータスページはダッシュボードの左ナビゲーションの **essentials** グループにある **ステータスページ** の配下にあります。このページのすべての項目はステータスページごとに設定します。1 つのプロジェクトはいくつでもステータスページを持てます — 顧客向けの公開ページ、社内向けの非公開ページ、特定の市場向けのリージョンごとのページなど。

## ひと目で

- **2 つの項目だけで作成できます。** 新しいステータスページで必要なのは **名前** と **説明** だけです。リソース、ブランディング、ドメインはあとから設定します。
- **リソースは訪問者が目にするものです。** ページの各行は **ステータスページリソース** — 独自の表示名、ツールチップ、稼働率オプションを持つモニター（またはモニターグループ）です。グループは長いページをセクションに分割し、入れ子にできます。
- **初日からプレビュー URL があります。** すべてのステータスページには、カスタムドメインができる前に見られるプレビューリンクが付きます。
- **訪問者向けのルートは設定でゲートされます。** インシデント、お知らせ、予定イベント、購読ページはそれぞれ **詳細設定** のトグルがオンのときだけ表示されます。
- **非公開にする方法は 3 つ。** プライベートユーザー、マスターパスワード、または SAML SSO / OIDC — さらに IP ホワイトリストもあります。
- **購読者には自動で通知されます。** メール、SMS、Slack、Microsoft Teams、Webhook の購読者がページをフォローでき、各チャネルはそれぞれ個別のトグルで制御できます。

## キー用語

| 用語                   | 意味                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| **ステータスページ**   | 独自のブランディング、ドメイン、リソース、購読者を持つ 1 つの公開（または非公開）ページ。`StatusPage` モデル。 |
| **リソース**           | 訪問者が目にする 1 行 — 表示名と稼働率オプションを付けてページに表示されるモニターまたはモニターグループ。   |
| **グループ**           | リソースを保持する名前付きのセクション。グループは他のグループの中に入れ子にでき、各階層はその下にあるすべてのステータスを集約します。 |
| **お知らせ**           | 開始時刻と任意の終了時刻を持つ、1 つ以上のステータスページに投稿するメッセージ。                              |
| **購読者**             | メール、SMS、Slack、Microsoft Teams、または Webhook でページをフォローする人（または仕組み）。               |
| **カスタムドメイン**   | あなた自身のドメイン — `status.example.com` — を CNAME と SSL 証明書でページに紐付けたもの。                 |
| **プライベートユーザー** | 非公開のステータスページにログインできるアカウント。OneUptime プロジェクトのユーザーとは別物です。            |

## ステータスページを作成する

1. **ステータスページ → すべてのステータスページ** を開き、**ステータスページを作成** をクリックします。
2. **新しいステータスページを作成** モーダルで、**名前**（必須、2 文字以上）と、任意で **説明** を入力します。
3. **ステータスページを作成** をクリックします。

作成フォームはこれで全部です。戻ってきた一覧には **名前**、**説明**、**ラベル**、**所有者** が表示され、**ステータスページ ID**、**名前**、**説明** で絞り込めます。

新しいページを開くと **概要** 画面に移動し、そこには 2 つのカードがあります。ページ自体へのリンクを持つ **ステータスページプレビュー URL** と、たった今設定した名前、説明、ラベルを編集できる **ステータスページの詳細** です。

次に、役に立つ順におおよそ並べると：

- ページに何か表示されるようにリソースを追加する — [ステータスページのリソースとグループ](/docs/status-pages/resources-and-groups) を参照。
- ページタイトル、ファビコン、ロゴ、カバーを設定してからカスタムドメインを紐付ける — [ステータスページのブランディングとドメイン](/docs/status-pages/branding-and-domains) を参照。
- どのチャネルで購読できるかを決める — [購読者とお知らせ](/docs/status-pages/subscribers) を参照。
- **詳細設定** でページに表示される内容を調整する。

## どこに何があるか

ステータスページを開くと、その独自の左サイドメニューは 9 つのセクションにグループ分けされています。このドキュメントグループの残りを読むときの地図として使ってください。

| セクション             | 内容                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Basic**              | **概要**、**アナウンス**、**所有者**。                                                                     |
| **Resources**          | 単一の **リソース** 画面 — 左にグループ、右に選択したグループのモニター。                                  |
| **Subscribers**        | **メール購読者**、**SMS 購読者**、**Slack 購読者**、**MS Teams 購読者**、**Webhook購読者**、**購読者設定**。 |
| **Notification Logs**  | **通知ログ** — 購読者に送信された内容。                                                                    |
| **Audit**              | **監査ログ**。                                                                                              |
| **Branding**           | **基本ブランディング**、**HTML、CSS、JavaScript**、**カスタムドメイン**、**ヘッダー**、**フッター**、**概要ページ**、**言語**。 |
| **Security**           | **プライベートユーザー**、**SSO**、**OIDC**、**SCIM**、**認証設定**。                                       |
| **AI**                 | **MCP**。                                                                                                    |
| **Advanced**           | **モニタールール**、**埋め込みステータス**、**レポート**、**カスタムフィールド**、**詳細設定**、**ステータスページを削除**。 |

事前に知っておくと役立つ、名前に関する 2 つの癖があります。

- **リソース** 項目は、プロジェクトでモニターグループが有効なときだけ **リソース** と表示されます。それ以外では **モニター** と表示されます。どちらも同じ画面です。
- 独立した Groups ページはありません。グループとリソースは統合され、古い `/groups` ルートは現在リソース画面にリダイレクトされます。

個々のページの外側では、**ステータスページ** セクション自体に **アナウンス** を持つ **More** セクションと、**アナウンステンプレート**、**購読者テンプレート**、**カスタムフィールド**、**所有者ルール**、**ラベルルール** を保持する折りたたまれた **設定** セクションがあります — これらはプロジェクト全体のもので、すべてのステータスページで共有されます。

## 訪問者が見るもの

公開ページはそれ自体が 1 つのアプリで、少数のルートを持ちます。

- `/` — **概要**。
- `/incidents` と `/incidents/:id` — インシデントの一覧と個別のインシデント。
- `/announcements` と `/announcements/:id`。
- `/scheduled-events` と `/scheduled-events/:id`。
- `/subscribe/email`、`/subscribe/sms`、`/subscribe/slack`、`/subscribe/microsoft-teams`、`/subscribe/webhooks`。
- `/rss` — フィード。
- `/login`、`/sso`、`/master-password` — 非公開ページでのみ意味を持ちます。

上部のナビバーには常に **概要** が表示され、それ以外は有効になっているときだけ表示されます。**インシデント**、**アナウンス**、**予定イベント** はそれぞれのトグルがオンである必要があり、**購読** には **購読者ページを表示** と、少なくとも 1 つの購読者チャネルの有効化の両方が必要です。非公開ページには **ログアウト** 項目も追加されます。

### 概要ページ

概要は、ほとんどの訪問者が目にする唯一のページです。上から下に、次のものを表示します。

1. **現在配信中のお知らせ** — 開始時刻が過ぎていて、終了時刻がまだ来ていないお知らせ。
2. **全体ステータスバナー** — すべてのリソースが影響を受けているのか、一部だけなのかを要約する 1 行。
3. **全体の稼働率** — オンにした場合のみ。デフォルトではオフです。
4. **リソースグループ** — それぞれのリソース、現在のステータス、稼働率の履歴バーとともに表示されます。
5. **アクティブなインシデント**。
6. **予定されているメンテナンスイベント**。

何もない新しいページには、ダッシュボードからリソースを追加するよう促す空の状態が表示されます — これは **リソース** 画面に向かうべきサインです。

何がこのページにインシデントを表示させ、何がそれを再び消すのかについては、[インシデントの状態と重大度](/docs/incidents/states-and-severities) を参照してください。

## ページに表示する内容を選ぶ

表示切り替えのほとんどは 1 か所にあります — **ステータスページ → 対象のページ → Advanced → 詳細設定**。各カードには独自の **Edit Settings** ボタンがあります。

**Incident Settings**：

- **Show Incidents**（`showIncidentsOnStatusPage`）— デフォルトでオン。オフにすると **インシデント** のナビ項目も削除されます。
- **Show Incident History (in days)**（`showIncidentHistoryInDays`）— インシデント一覧がさかのぼる範囲。デフォルトは 14。
- **Show Incident Labels**（`showIncidentLabelsOnStatusPage`）— デフォルトでオフ。

**Episode Settings** — インシデントのエピソード向けの同じ 3 つのトグルです。**Show Episodes**（`showEpisodesOnStatusPage`、デフォルトでオン）、**Show Episode History (in days)**（デフォルト 14）、**Show Episode Labels**（デフォルトでオフ）。エピソードはインシデントのビューではなく、独自のエンドポイントを持つ独立したモデルです。

**Announcement Settings**：

- **Show Announcements**（`showAnnouncementsOnStatusPage`）— デフォルトでオン。
- **Show Announcement History (in days)**（`showAnnouncementHistoryInDays`）— デフォルトは 14。

**Scheduled Event Settings**：

- **Show Scheduled Maintenance Events**（`showScheduledMaintenanceEventsOnStatusPage`）— デフォルトでオン。
- **Show Scheduled Event History (in days)**（`showScheduledEventHistoryInDays`）— デフォルトは 14。
- **Show Event Labels**（`showScheduledEventLabelsOnStatusPage`）— デフォルトでオフ。

**Uptime History Settings**：

- **Show Uptime History (in days)**（`showUptimeHistoryInDays`）— 各リソースの隣にある稼働率バーの長さ。デフォルトは 90 で、1 から 90 の間である必要があります。リソースやグループの **Show Uptime %** と **Show Status History Chart** のオプションは、いずれもこの数値を参照します。

**Subscriber Settings**：

- **Show Subscriber Page**（`showSubscriberPageOnStatusPage`）— デフォルトでオン。さらにチャネルごとに 5 つの有効化トグルがあります。同じチャネルトグルは **Subscribers** セクション配下の専用の **購読者設定** 画面にも表示されます。設定する際は、そちらを正規の場所として扱ってください。

**Powered By OneUptime Branding**：

- **Hide Powered By OneUptime Branding** — デフォルトでオフ。これをオンにするまで、訪問者向けのフッターには "Powered by OneUptime" と表示されます。

**色の設定場所について。** 稼働率バーの色はここにはありません — **Default Bar Color**、バーカラーのルール、**Downtime Monitor Statuses**、**Show Overall Uptime Percent** はすべて **ステータスページ → 対象のページ → Branding → 概要ページ** にあります。テーマやブランドカラーの設定はどこにもなく、これらのコントロールを超える調整はすべて **Custom CSS** で行います。

## 公開する前にプレビューする

すべてのステータスページの **概要** 画面には、ページ自体への直接リンクを持つ **ステータスページプレビュー URL** カードがあります。まだリソースを追加している最中で、カスタムドメインがまだ存在しない間はこれを使ってください。

裏側では、すべての公開ルートに `/status-page/{statusPageId}/...` 配下のプレビュー版があります — プレビュー用の概要、プレビュー用のインシデント一覧、プレビュー用の購読ページなど。つまり、ダッシュボードのプレビューから取った URL やスクリーンショットは、カスタムドメインが紐付いた後に顧客が見るものとは一致しません。Runbook やメールに貼り付けるリンクは必ず確認し直してください。

## ページを見られる人を制限する

すべてのステータスページが一般公開向けとは限りません。すべてのコントロールは **Security** セクションにあります。

### プライベートユーザー

**ステータスページ → 対象のページ → Security → 認証設定** で **Is Visible to Public** をオフにします（`isPublicStatusPage` カラム）。訪問者は `/login` に着地し、サインインする必要があります。

サインインできる人は **ステータスページ → 対象のページ → Security → プライベートユーザー** で追加します。**Add in Bulk**（一括追加）アクションがあり、メールアドレスの一覧を貼り付けると、それぞれに招待メールが送られます。プライベートユーザーは、OneUptime プロジェクトのアカウントとは別の、独自のパスワード忘却・再設定フローを持ちます。

### マスターパスワード

**認証設定** には、**Require Master Password** トグルとパスワード自体を持つ **Master Password** カードもあります。訪問者は `/master-password` に着地し、1 つの共有シークレットでページをアンロックします。

**マスターパスワードとプライベートユーザーは併用できません。** マスターパスワードがオンの間、プライベートユーザー認証は無効になり、**プライベートユーザー** 画面にはその旨のバナーが表示されます。

### SSO と OIDC

アイデンティティプロバイダーに紐付いた非公開ページでは、**ステータスページ → 対象のページ → Security → SSO** で SAML（サインオン URL、発行者、x509 証明書、署名・ダイジェスト方式）を設定し、**ステータスページ → 対象のページ → Security → OIDC** で OpenID Connect（ディスカバリー URL、発行者、クライアント ID とシークレット、スコープ、クレーム名）を設定します。**SCIM** は IdP からプライベートユーザーを自動でプロビジョニングします。これらはプランの機能でゲートされているため、すべての導入環境で利用できるとは限りません。

**SSO Settings** カードには **Force SSO for Login**（`requireSsoForLogin`、デフォルトでオフ）があります。オンにする前に SSO 設定をテストしてください — うまく動作しないと、自分自身がステータスページからロックアウトされてしまいます。

### IP ホワイトリスト

**認証設定** には **IP Whitelist** カードもあり、`ipWhitelist` カラムに支えられています。既知のネットワークからのみ応答すべきページ向けです。

## 埋め込みバッジと RSS フィード

ページ自体以外の場所にステータスを表示する 2 つの方法があります。

**埋め込みステータスバッジ。** **ステータスページ → 対象のページ → Advanced → 埋め込みステータス** の **埋め込みステータスバッジ** カードで **Enable Embedded Status Badge**（`enableEmbeddedOverallStatus`、デフォルトでオフ）をオンにします。これは `embeddedOverallStatusToken` と対になり、`/badge/:statusPageId` からバッジを配信するので、現在の全体ステータスをドキュメントやアプリのフッター、マーケティングページに埋め込めます。

**RSS フィード。** すべてのステータスページは `/rss` を配信します — タイトルが「{ステータスページ名} Updates」で、項目には `Incident: `、`Announcement: `、`Scheduled Maintenance: ` という接頭辞が付きます。更新をメール購読ではなく、リーダーやチャットボットに流し込みたい人に便利です。

自分でデータを取得したい場合は、ステータスページは概要、インシデント、予定されているメンテナンスイベント、お知らせ、エピソードのための公開読み取りエンドポイントに支えられています — [公開 API](/docs/status-pages/public-api) を参照。
