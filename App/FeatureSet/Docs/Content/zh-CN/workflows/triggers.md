# 触发器

触发器是工作流中的第一个方块——它决定工作流何时运行。每个工作流恰好有一个触发器。你可以从四种类型中选择。

## 手动

在 **生成器** 页面点击 **运行工作流**、填好触发器的字段，并用 **Run Workflow Manually** 确认，即可按需运行工作流。手动触发器接受一个 JSON 载荷，工作流的其余部分可以读取它。

适合：你想为它配一个按钮的一键自动化，比如"轮换这个密钥"或"发送一条测试告警"。

**输出**：你粘贴进去的 JSON，如果没有粘贴则是一个空对象。

## 计划

使用 cron 表达式按重复计划运行工作流。

适合：夜间清理、每小时同步、每周报告。

**设置**：一个 cron 表达式。几个常见的例子：

- `0 * * * *`——每小时整点。
- `*/5 * * * *`——每 5 分钟。
- `0 9 * * 1`——每周一上午 9:00。

如果系统短暂不可用，一旦恢复就会立刻补跑那次运行——对于短暂的中断，你不必担心错过的执行节点。

## Webhook

OneUptime 会创建一个专属 URL。任何请求命中这个 URL 都会启动工作流。请求的请求头、查询参数和正文都会被传入。

适合：从另一个工具向 OneUptime 接收数据——CI/CD 回调、来自其他监控系统的告警、你 CRM 中的注册事件。

**输出**：

- **Request Headers**——传入请求的全部请求头。
- **Request Query Params**——解析后的查询字符串。
- **Request Body**——解析后的正文（如果不是 JSON，则是原始文本）。

该 URL 同时接受 `GET` 和 `POST`。调用方会得到一个快速的确认响应——工作流本身在后台运行。

把这个 URL 当作密码来对待。任何拿到它的人都能启动你的工作流。

## OneUptime 事件触发器

OneUptime 中几乎所有东西——监视器、事件、告警、计划维护、状态页、值班策略、团队——都能触发一个工作流。每一种都提供三种事件：

- **On Create**——当新增一个时触发。
- **On Update**——当有一个被修改时触发。
- **On Delete**——当有一个被删除时触发。

这就是你在不需要循环轮询的情况下，构建"当 OneUptime 中发生 X 时，执行 Y"的方式。

完整记录会被传给下一个方块。例如，**Incident → On Create** 触发器会传入这个新事件，这样下一个方块就能读取它的标题、描述、严重性以及任何其他字段。

### 团队最常用的事件

- **Incident**——在一个事件被打开、更新（已确认、已解决）或删除时做出反应。
- **Alert**——告警的同样三种事件。
- **Monitor**——在一个监视器被添加、编辑或移除时做出反应。
- **Scheduled Maintenance**——在一个维护窗口被安排时自动发出公告。
- **Status Page Subscriber**——欢迎订阅了某个状态页的人。
- **On-Call Duty Policy**——把值班表变更同步到另一个排班系统。

在 **Add Trigger** 面板中按名称搜索，找到你想要的那一个。

## 我该用哪种触发器？

| 如果你想……                       | 就选           |
| ---------------------------------- | -------------- |
| 点一个按钮来运行工作流             | **手动**       |
| 按重复计划运行                     | **计划**       |
| 让另一个系统把数据推送进来         | **Webhook**    |
| 对 OneUptime 内部发生的事做出反应  | **OneUptime 事件** |

一个工作流只能有一个触发器。如果你需要两种方式来启动同一套自动化，就把共享逻辑搭建在一个工作流里，然后用 **Execute Workflow** 组件从两个瘦身的"包装"工作流中调用它。
