# 创建工作流

要新建一个工作流，打开 **工作流** 并点 **创建工作流**。一个叫 **Create a workflow** 的向导会带着你走完：先是 **Start from**——选 **Start from scratch** 或者某个模板——然后是 **名称**，最后是 **配置** 那一步，它只在你挑的模板本身需要设置时才出现。

创建好之后，在左侧菜单里打开 **生成器**。那就是你设计工作流的画布。

## 画布

从零开始的工作流，打开时只有一个虚线方块，上面写着 **Please click here to add trigger**。那个方块就是起点——点它来挑一个触发器。用模板创建的工作流，打开时方块已经摆好了。

每个工作流最上面恰好有一个 **触发器**。除此之外的每一个方块都是干活的 **组件**。再加一个触发器会顶掉原来那个；删掉最后一个触发器，虚线占位方块又会回来。

添加方块：

- **触发器**——点那个虚线占位方块，会打开一个标题为 **Add Trigger** 的面板。
- **其余所有方块**——点画布上方工具栏里的 **添加组件**，同一个面板会打开，标题变成 **添加组件**。

两个面板都能搜索——按 `/` 直接跳到搜索框——而且按类别分好了组。选中一个方块，点 **Add to Workflow**。

新方块总是落在画布上同一个位置，所以新加的那个可能会盖住你已经摆好的东西。把它拖开就行；拖的时候画布会自动对齐网格。方块的位置会被保存，下一个人看到的还是你留下的那个布局。

改动自动保存。工具栏里有个小标签在跟踪这件事：改动还在路上时是 **Saving…**，成功之后是 **已保存**，没成功则是 **无法保存**。这里没有保存按钮，也没有单独的发布步骤。

## 一个方块上都有什么

| 字段                          | 它是干什么的                                                                                                                                                                                                |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier**（在 **ID** 下面） | 方块上显示的那个短 id，比如 `log-1`。别的方块靠它来引用这个方块，所以给它改名会让每一个指向它的 `{{local.components.…}}` 引用全部失效。方块的标题是组件自己的名字，改不了。 |
| **设置**                      | 这个方块干活需要的东西——一个 URL、一个 Slack 频道、一段消息正文。可选字段标着 **(Optional)**，其余都是必填的。不常用的设置收在 **高级** 折叠区里面。 |
| **Input**                     | 上边缘的那个圆点，前面方块的连线接到这里。触发器没有输入——它们之前没有任何东西会运行。                                                                                       |
| **Outputs**                   | 下边缘的那一排圆点，标签就写在它们正上方，连线从这里出去接到后面的方块。很多方块有各自独立的 **成功** 和 **错误** 输出，两种情况你都能分别处理。                  |

## 连接方块

从一个方块底部的圆点往下拖到下一个方块顶部的圆点。你画的这条线决定接下来跑什么。

- 从 **成功** 接出去，下一个方块只在前一个跑通时运行。
- 从 **错误** 接出去，下一个方块只在前一个失败时运行。
- 某个输出你没接线，这条路就到此为止。

一个输出可以接到好几个方块。它们都会运行——但是排成一队一个接一个地跑，不是并行。别指望分支之间有固定的先后，也别指望它们在时间上重叠。每个方块在一次运行里最多跑一次，所以一条绕回前面方块的连线不会让它再跑一遍。

## 配置一个方块

点一个方块，它的设置会在一个对话框里打开。每项设置都配了合适的输入方式——文本框、下拉框、代码编辑器、开关等等。填好后点 **保存**。

同一个对话框里还有：

- **删除**——移除这个方块。
- **Run just this step**——只跑这一个方块，不带工作流的其余部分。它本该从别的步骤读到的值会是空的；而它发出去、写进去或删掉的东西，是真的会发生。
- **文档**、**Inputs**、**Outputs** 和 **Returns**——这个方块期望什么、产出什么的参考卡片。

大多数文本框都接受变量——数据就是这样从一个方块流到下一个的。与其手敲语法，不如用编辑器里的取值选择器：你选好方块和字段，它就把正确的引用拼出来。见[工作流变量](/docs/workflows/variables)。

## 搭建过程中的检查

你每改一次，生成器都会把整张图检查一遍，并把结果报在工具栏的一个小标签上。点这个标签会打开 **Problems with this workflow**，里面逐条列出问题，并把你带到出问题的那个方块。有问题的方块在画布上还会带一个红色角标。

它抓的正是那些不跑一次就看不出来的毛病——没有触发器、两个方块用了同一个 id、id 里带了点号、某个方块没人连、必填的设置空着、JSON 格式不对、`{{ }}` 里面有空格，以及引用了并不存在的步骤或返回值。

有一件事它查不了：变量名到底存不存在。改过名的变量只有在运行日志里才会露馅。

## 你的第一个工作流

想快点摸清这张画布，就这么来：

1. 点那个虚线占位方块，在 **Add Trigger** 面板里选 **Manual**，再点 **Add to Workflow**。
2. 点 **添加组件**，选 **日志**（在 **Utils** 下面），再点 **Add to Workflow**。把新方块拖开、别压着触发器，然后把触发器的 **Execute** 圆点连到日志方块的输入圆点上。
3. 打开日志方块，把它的 **值** 设成 `Hello from {{local.components.manual-1.returnValues.value.name}}`。`manual-1` 是触发器的 **Identifier**，就写在触发器方块上——对一下是不是一致。
4. 去 **概览**，在 **工作流详情** 卡片上点 **编辑工作流**，把 **已启用** 打开。被禁用的工作流根本跑不了，手动也不行。
5. 回到 **生成器**，点 **运行工作流**，在 **JSON** 字段里填 `{ "name": "Ada" }`，点 **Run Workflow Manually**，再用 **Run** 确认。
6. 一个 **Workflow Run** 面板会自己打开，跟着这次运行往下走。日志里会出现 `Value:`，后面跟着 `Hello from Ada`。

添加、连接、配置、运行、读日志——你之后搭的每一个工作流，走的都是这个循环。

## 把它打开

新建的工作流一开始是关着的，你复制出来或者导入进来的工作流也一样。

**已启用** 开关在工作流的 **概览** 页面上，在 **工作流详情** 卡片里——不在设置页面上。同一张卡片会用一个绿色的 **已启用** 或红色的 **已禁用** 标签显示当前状态。

被禁用的工作流根本跑不了。手动运行也会被拒绝，提示 "This workflow is not enabled"，跟被触发的运行一模一样。所以顺序是：先启用，用 **运行工作流** 测一测，读运行日志，如果你还没准备好让它的触发器真的开火，就把 **已启用** 关回去。想只测一个方块、不跑整个工作流，就用那个方块设置里的 **Run just this step**。

想暂停一个工作流又不想删掉它，把 **已启用** 关掉。不会再有新的运行开始。已经跑到一半的运行会跑完，但停在 **Sleep** 方块上的那次会在醒来时被取消，并记为一次错误。

## 收拾画布

- 拖动方块来挪位置，布局会被保存下来。
- 要删一条线，把它任意一端从圆点上拖开，丢在画布的空白处。
- 要删一个方块，点它，用设置对话框底部的 **删除**。选中一个方块或一条线按 Backspace 也能删。
- 没有办法单独复制一个方块。工作流 **设置** 页面上的 **Duplicate Workflow** 会把整个工作流复制一份，而且副本是禁用状态。
- 把方块自上而下摞起来，让它们读起来的方向就是它们跑起来的方向——输入在上边缘，输出在下边缘，流程自然往下走。
