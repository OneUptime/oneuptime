# 创建工作流

要创建一个工作流，打开 **工作流** 并点击 **创建工作流**。一个名为 **Create a workflow** 的向导会引导你完成整个过程：先是 **Start from**——选择 **Start from scratch** 或某个模板——然后是 **Name**，最后是一个 **Configure** 步骤，这一步只有在你选的模板需要自己的设置时才会出现。

创建完成后，打开左侧菜单中的 **生成器**。那就是你设计工作流的画布。

## 画布

从零开始的工作流会打开一个带虚线的单独方块，上面写着 **Please click here to add trigger**。这个方块就是起点——点击它来选择一个触发器。从模板创建的工作流打开时，方块已经就位。

每个工作流最上方恰好有一个 **触发器**。其余的都是做具体事情的 **组件**。添加第二个触发器会替换第一个，删除最后一个触发器会让虚线占位符重新出现。

添加方块：

- **触发器**——点击虚线占位符方块。会打开一个标题为 **Add Trigger** 的面板。
- **其他所有东西**——点击画布上方工具栏中的 **添加组件**。会打开同一个面板，标题是 **Add Component**。

两个面板都可以搜索——按 `/` 跳到搜索框——并按类别分组。选中一个方块，点击 **Add to Workflow**。

新方块总是落在画布上同一个位置，所以新的一个可能会落在你已经放好的东西上面。把它拖开；画布在你拖动时会吸附到网格上。方块的位置会被保存，所以下一个人看到的会是你留下的同一种排布。

变更会自动保存。工具栏中的一个小圆角标签会跟踪这个过程：变更进行中时是 **Saving…**，然后是 **已保存**，如果没保存成功则是 **无法保存**。没有保存按钮，也没有单独的发布步骤。

## 一个方块上有什么

| 字段                       | 作用                                                                                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier**（在 **ID** 下） | 方块上显示的简短 id，比如 `log-1`。其他方块靠这个来引用这个方块，所以重命名它会破坏所有指向它的 `{{local.components.…}}` 引用。方块的标题是组件自身的名称，无法更改。 |
| **Settings**                | 这个方块完成任务所需要的东西——一个 URL、一个 Slack 频道、一段消息正文。可选字段会标上 **(Optional)**；其他一切都是必填的。不常用的设置藏在一个 **高级** 折叠面板后面。 |
| **Input**                   | 方块顶边上的那个点，线从更早的方块流入这里。触发器没有这个——在它们之前没有东西运行。                                                                             |
| **Outputs**                 | 方块底边上的那些点，紧挨着标注了名字，线从这里流向下一批方块。许多方块都有独立的 **Success** 和 **Error** 输出，方便你分别处理两种情况。                          |

## 连接方块

从一个方块底部的点拖到下一个方块顶部的点。你画的这条线决定了接下来运行什么。

- 如果你从 **Success** 连出去，下一个方块只会在前一个方块成功时运行。
- 如果你从 **Error** 连出去，下一个方块只会在前一个方块失败时运行。
- 如果你没有连接某个输出，那条路径就此终止。

你可以把一个输出连接到好几个方块。它们都会运行——但是一个接一个地在一个单一队列里运行，不是并行的。不要依赖分支之间的顺序，也不要指望它们在时间上会重叠。每个方块在一次运行中最多运行一次，所以回连到更早的方块不会让它运行两次。

## 配置一个方块

点击一个方块，在一个对话框里打开它的设置。每个设置都有恰当的输入方式——文本字段、下拉菜单、代码编辑器、开关等等。填好之后点击 **Save**。

同一个对话框里还能找到：

- **Delete**——移除这个方块。
- **Run just this step**——单独运行这一个方块，不运行工作流的其余部分。它原本会从其他步骤读到的值会以空值传入，而它发送、写入或删除的任何东西都会真实地发生。
- **Documentation**、**Inputs**、**Outputs** 和 **Returns**——说明这个方块期望什么、产出什么的参考卡片。

大多数文本字段都接受变量——这就是数据从一个方块流到下一个方块的方式。与其手动输入语法，不如用编辑器里的取值选择器：它会根据你选择的方块和字段，构建出一个正确的引用。参见[工作流变量](/docs/workflows/variables)。

## 边搭建边检查

生成器每次你做出改动都会检查整张图，并把发现的问题汇报在工具栏的一个小圆角标签里。点击这个标签会打开 **Problems with this workflow**，列出每一个问题，并跳转到对应的方块。有问题的方块在画布上也会带一个红色徽章。

它能捕捉到那些原本要等到某次运行出错才会显现的错误——没有触发器、两个方块共用一个 id、id 中带了一个点、一个没有任何东西连接的方块、一个留空的必填设置、格式错误的 JSON、`{{ }}` 内部有空格，以及引用了一个不存在的步骤或返回值。

有一件事它检查不了：一个变量名是否真的存在。一个被重命名的变量只会在运行日志里显露出来。

## 你的第一个工作流

熟悉画布最快的方法：

1. 点击虚线占位符方块，在 **Add Trigger** 面板中选择 **手动**，然后点击 **Add to Workflow**。
2. 点击 **添加组件**，选择（**Utils** 下的）**日志**，然后点击 **Add to Workflow**。把新方块拖离触发器，然后把触发器的 **Execute** 点连到日志方块的输入点上。
3. 打开日志方块，把它的 **Value** 设为 `Hello from {{local.components.manual-1.returnValues.value.name}}`。`manual-1` 是触发器的 **Identifier**，显示在触发器方块上——检查一下它是否一致。
4. 前往 **概览**，在 **Workflow Details** 卡片上点击 **Edit Workflow**，把 **已启用** 打开。一个被禁用的工作流完全无法运行，哪怕手动运行也不行。
5. 回到 **生成器**，点击 **运行工作流**，在 **JSON** 字段里填入 `{ "name": "Ada" }`，点击 **Run Workflow Manually**，再用 **Run** 确认。
6. 一个 **Workflow Run** 面板会自动打开并跟踪这次运行。日志会显示 `Value:`，后面跟着 `Hello from Ada`。

添加、连接、配置、运行、查看日志——这个循环就是你搭建每一个工作流的方式。

## 打开它

新建的工作流默认是禁用的，你复制或导入的任何工作流也一样。

**已启用** 开关在工作流的 **概览** 页面，位于 **Workflow Details** 卡片中——不在设置页面上。同一张卡片会以绿色的 **已启用** 或红色的 **已禁用** 小标签显示当前状态。

一个被禁用的工作流完全无法运行。手动运行会像被触发的运行一样，被拒绝并提示"This workflow is not enabled"，所以正确的顺序是：先启用它，再用 **运行工作流** 测试它，查看运行日志，如果你还没准备好让它的触发器真正触发，就把 **已启用** 重新关掉。要在不运行整个工作流的情况下测试单个方块，用该方块设置里的 **Run just this step**。

要在不删除工作流的情况下暂停它，把 **已启用** 关掉。不会再有新的运行开始。一个正在执行中的运行会正常结束，但一个停在 **Sleep** 方块上的运行，会在它醒来时被取消，并记录为一个错误。

## 整理

- 拖动方块来移动它们。布局会被保存。
- 要删除一条线，把它任意一端从点上拖开，松开在空白画布上。
- 要删除一个方块，点击它，用它设置对话框底部的 **Delete**。选中一个方块或一条线后按 Backspace 也能删除它。
- 没有办法复制单个方块。工作流 **设置** 页面上的 **Duplicate Workflow** 会复制整个工作流，副本会以禁用状态出现。
- 让方块从上到下叠放，这样它们的阅读顺序就和运行方向一致——输入在顶边，输出在底边，流程自然而然地向下走。
