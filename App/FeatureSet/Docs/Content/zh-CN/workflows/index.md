# 工作流概览

工作流让你无需编写代码即可在 OneUptime 中自动化任务。在画布上添加几个方块，把它们连接起来，你就得到了一套自动化——每当发生某件事时它就会运行：一个事件被打开、一个计划触发，或者另一个工具向 OneUptime 发送数据。

把工作流看作你项目的后台助手：它们对事件做出反应、与其他工具沟通，并在你专注于自己工作的同时默默保持一切同步。

## 用工作流能做什么

- **把 OneUptime 连接到你的其他工具**——把事件发送到 Slack、创建 Jira 工单、向你技术栈里的一个 webhook 发帖。
- **对 OneUptime 中发生的事做出反应**——当创建了一个严重事件时，自动通知值班团队并打开一个工单。
- **按计划运行任务**——每五分钟、每晚、每周一早上。
- **接收来自外部的数据**——让其他系统通过一个专属 URL 把数据推送进 OneUptime。
- **复用常见自动化**——搭建一次，让其他任何工作流来调用它。

## 工作流是如何运作的

每个工作流都有三个部分：

1. **一个触发器**——启动工作流的东西。可以是一个手动按钮、一个计划、一个传入的 webhook，或者 OneUptime 中的一个事件（比如一个新事件）。
2. **一个或多个组件**——工作流要做的事。发送一条消息、发起一次 HTTP 调用、运行一次快速检查、根据条件分支。
3. **它们之间的连接**——你从一个方块画线到下一个方块，来决定执行顺序。

你在画布上以可视化的方式完成这一切。大多数工作流不需要写代码，不过在需要时你也可以加一小段 JavaScript。

## 关键术语

| 术语             | 含义                                                             |
| ---------------- | ------------------------------------------------------------------ |
| **工作流**       | 整个自动化——一个名称、一个画布，以及一个用来开关它的开关。          |
| **触发器**       | 第一个方块。它决定工作流何时运行。每个工作流恰好有一个触发器。       |
| **组件**         | 一个动作方块——发送一条消息、发起一次请求、检查一个条件。            |
| **运行**         | 工作流的一次执行。会连同时间戳和每个方块的输出一起被保存。           |
| **全局变量**     | 一个你保存一次、可在任何工作流中复用的值（比如一个 API 密钥）。      |

## 在 OneUptime 中哪里能找到工作流

打开左侧导航中的 **工作流**。这个板块包含：

- **工作流**——你的工作流列表。创建一个新的，或打开一个已有的。
- **全局变量**——在你所有工作流之间共享的值。
- **运行和日志**——你项目中每个工作流的执行历史。

打开某一个工作流后，它自己的左侧菜单包含：

- **概览**——名称、描述、标签，以及 **已启用** 开关。
- **生成器**——你设计工作流的画布。
- **工作流变量**——仅作用于这一个工作流的值。
- **运行和日志**——这个工作流的每一次运行，附带详情。
- **设置**——webhook 密钥、复制和导出。

## 搭建你的第一个工作流

1. **创建**——选一个起点，然后给你的工作流起个名字。
2. **选一个触发器**——手动、计划、webhook，或来自 OneUptime 的一个事件。
3. **添加组件**——把动作添加到画布上并连接起来。
4. **打开它**——在 **概览** 页面把 **已启用** 打开。一个被禁用的工作流完全无法运行，哪怕手动运行也不行。
5. **测试**——在生成器上点击 **运行工作流**，然后查看运行日志。

## 一个简单的例子

假设你想在每次创建严重事件时向 Slack 发帖：

1. 创建一个名为"严重事件转发到 Slack"的工作流。
2. 选择 **On Create Incident** 触发器。
3. 添加一个 **If / Else** 方块。设置它检查事件标题是否包含"Sev 1"。
4. 从 **Yes** 分支出发，添加一个 **Slack** 方块。选择频道并写好消息。
5. 打开这个工作流。

下次有人创建标题中带有"Sev 1"的事件时，Slack 就会亮起来。

## 工作流如何与 OneUptime 其他部分配合

- **监视器发现问题。事件记录问题。工作流对此做出反应。**
- **Runbook** 是给人看的分步指南。工作流是无人值守的自动化。当需要人来做决策时用 Runbook；当步骤是自动的时候用工作流。
- **工作区连接**（Slack、Teams）是工作流发送消息的去处。
