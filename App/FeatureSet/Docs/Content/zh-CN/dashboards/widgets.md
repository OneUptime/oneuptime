# 组件

组件是仪表板上的一块瓦片。本页列出你可以添加的每个组件、它显示什么、什么时候使用它。

关于如何在画布上拖动组件,见 [创作仪表板](/docs/dashboards/authoring)。

## 图表与数字

### 图表

按仪表板的时间范围展示一条或多条指标系列的折线图、柱状图或面积图。

**设置**:

- 一个或多个指标查询。
- 一个可选的公式,用于组合两个查询(例如 `errors / total * 100` 得到错误率)。
- 一个"作为速率显示"的选项,用于不断增长不会重置的累计计数器。
- 显示选项:堆叠或叠加、Y 轴单位、图例位置、图表类型。

适用于:关注趋势时。延迟随时间变化、错误数、队列深度——任何能从线的形状中讲故事的内容。

### 单值

一个带有可选彩色阈值的大号数字。

**设置**:

- 一个返回单个数字的指标查询(时间范围内的最新值、平均值或最大值)。
- 一个可选的 **警告** 阈值(超过变黄)。
- 一个可选的 **严重** 阈值(超过变红)。
- 数字格式和单位。

适用于:一个数字就能回答问题时。当前错误率、此刻的 P95 延迟、未解决事件数。

### 仪表盘

一个圆形仪表盘,带有最小值、最大值、警告区间和严重区间。

**设置**:一个指标查询和四个边界。

适用于:值落在已知范围内时。CPU 百分比(0–100%)、磁盘使用率、队列容量。

### 表格

按分组每行展示一个指标结果的表格。

**设置**:一个指标查询(通常按主机或服务等标签分组)、要显示的列,以及行数上限。

适用于:你想要分组对比而非趋势时。最吵的 10 台主机、各服务的错误数、每个端点的请求数。

## 文本

一段静态的 Markdown。

**设置**:Markdown 正文。标题、列表、链接、强调和代码块都会渲染。

适用于:你想要一个分区标题、一段说明、一组指向 Runbook 的链接,或者事件期间的临时横幅。

## HTML

你自己的 HTML、CSS 和 JavaScript,作为组件渲染。

**设置**:HTML 正文、一个可选的样式表、一个可选的脚本,以及三个权限开关。

适用于:你需要内置组件都覆盖不了的东西时——嵌入的第三方徽章、从内部 API 拉来的表格、自定义图例,或者一组指向你自己工具的带样式链接。

### 它能做什么、不能做什么

组件在一个沙箱化的框架里渲染,处于它自己的隔离源(origin)上。在这个框架内部,你的代码几乎可以做任何事:构建 DOM、跑定时器、从任意 URL 取数据、在 canvas 上绘图。

它做不到的是触及外面那张 OneUptime 页面。它无法访问仪表板的 DOM、cookie、本地存储或 API 会话,也不能把浏览器标签页导航走。无论仪表板是私有的还是被公开分享,这一点都成立。

在你把东西粘进来之前,有两个后果值得知道:

- 从组件发出的 `fetch` 是一个来自不透明源的跨源请求,所以你调用的服务器必须用 CORS 允许它。不支持从这里调用 OneUptime API。
- 组件初始是透明的。如果你想让它铺满整张卡片,就在 CSS 里给 `body` 设一个背景。

### 使用仪表板变量

在 HTML、CSS 或 JavaScript 的任何位置写 `{{variableName}}`,它会在组件渲染之前被替换成那个变量的当前值。选择一个新值会让组件重新渲染。指向不存在的变量的占位符会原样保留。

脚本能拿到同样的值,外加仪表板的时间范围,都在 `window.ONEUPTIME` 上:

```javascript
window.ONEUPTIME.variables.environment; // 当前值,未设置时为 ""
window.ONEUPTIME.startDate; // ISO 8601 字符串,仪表板时间范围的开始
window.ONEUPTIME.endDate; // ISO 8601 字符串,它的结束
```

仪表板每次刷新时组件都会重新加载,所以一个自己取数据的组件会跟上刷新间隔。

### 权限

**Run JavaScript**(运行 JavaScript,默认开启)会运行你的脚本。关掉它就只渲染标记和样式——此时脚本会被完全排除在组件之外,而不只是被阻止执行。

**Open links in a new tab**(在新标签页中打开链接,默认开启)让链接和 `window.open` 可以打开浏览器标签页。链接始终在新标签页中打开;组件永远不能导航仪表板本身。

**Allow forms to submit**(允许表单提交,默认关闭)让组件内的 `<form>` 可以提交。

谁能编辑这张仪表板,谁就决定这个组件运行什么;而每个查看仪表板的人都会运行它——在公开仪表板上,这包括匿名访客。对待带有 HTML 组件的仪表板的编辑权限,要像对待你发布的任何其他代码的访问权限一样。

## 日志与追踪

### 日志流

匹配某个筛选条件的日志行的实时尾部。

**设置**:日志筛选条件(服务、严重程度、属性)和要显示的列。

适用于:你想看到应用此刻在说什么,而又不离开仪表板。

### 追踪列表

匹配某个筛选条件的近期追踪列表,带有耗时、状态和服务。

**设置**:追踪筛选条件(服务、状态、属性)。

适用于:你想要近期活动列表而非图表时。常见组合是上方一个延迟图表,下方是慢追踪列表。

## 实时列表

### 事件列表

匹配某个筛选条件的事件实时列表。

**设置**:按状态、严重程度、标签、监控或团队筛选。

适用于:仪表板回答"现在什么坏了?"

### 告警列表

匹配某个筛选条件的告警实时列表。

**设置**:按状态、严重程度、标签筛选。

适用于:团队仪表板跟踪自己服务上的告警。

### 监控列表

监控及其当前状态的实时列表。

**设置**:按监控类型、标签或当前状态筛选。

适用于:你想要一个全景视图——"所有站点都在线吗?"

## Kubernetes 资源列表

适用于已安装 [Kubernetes Agent](/docs/monitor/kubernetes-agent) 的项目。每个组件都接受集群、命名空间和标签的可选筛选条件。

- **Kubernetes Pod 列表**——Pod,带阶段、重启次数和节点。
- **Kubernetes 节点列表**——节点,带状况和容量。
- **Kubernetes 命名空间列表**——命名空间和工作负载计数。
- **Kubernetes Deployment 列表**——Deployment,带期望副本数对比就绪副本数。
- **Kubernetes StatefulSet 列表**——StatefulSet,带就绪副本数。
- **Kubernetes DaemonSet 列表**——DaemonSet,带期望对比就绪。
- **Kubernetes Job 列表**——Job 及其完成状态。
- **Kubernetes CronJob 列表**——CronJob,带计划和上次运行时间。

适用于:你想要一张把 Kubernetes 状态和这些工作负载的遥测混在一起的仪表板。

## Docker 资源列表

适用于已设置 Docker 监控的项目。

- **Docker 主机列表**——运行 Docker 的主机,带容器计数。
- **Docker 容器列表**——容器,带状态、镜像、主机、运行时长。
- **Docker 镜像列表**——镜像及其大小。
- **Docker 网络列表**——Docker 网络和已连接的容器。
- **Docker 卷列表**——Docker 卷及其使用情况。

## 基础设施

### 主机列表

由 OneUptime 服务器监控所监控的主机,带有状态、CPU、内存和运行时长。

**设置**:按标签或当前状态筛选。

## 我该用哪个组件?

几条简单规则:

- **随时间变化的趋势?** 图表。
- **一个此刻重要的数字?** 单值(如果有明确的最小/最大值,则用仪表盘)。
- **跨多对象的分组对比?** 表格。
- **系统此刻在发生什么?** 日志流、追踪列表、事件列表。
- **某组特定资源的状态?** 对应的列表组件。
- **一个标题、一段文字,或一个链接?** 文本。
- **以上都覆盖不了的东西?** HTML——但只有在确认内置组件真的做不到之后才用。

大多数仪表板会混合几种——顶部一个图表、旁边一两个数值、中间用文本分隔,下方放一两个列表。
