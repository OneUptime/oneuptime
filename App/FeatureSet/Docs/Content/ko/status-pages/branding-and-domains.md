# 브랜딩 및 사용자 정의 도메인

상태 페이지는 고객이 실제로 들여다보는 유일한 OneUptime 화면이므로, 여러분의 것처럼 보여야 하고 여러분의 도메인 위에 있어야 합니다. 둘 다 상태 페이지 사이드 메뉴의 **브랜딩** 섹션에서 설정하고, 여기에 **고급 설정**에 숨어 있는 항목 하나가 더해집니다.

시작하기 전에 알아 둘 것이 있습니다. 브랜딩은 일곱 개의 별도 화면으로 나뉘어 있는데, 나뉜 지점이 늘 예상과 맞지는 않습니다. 로고와 커버 이미지는 **필수 브랜딩**이 아니라 **헤더**에 있습니다. 파비콘은 **필수 브랜딩**에 있습니다. 색상은 **개요 페이지**에 있습니다. "테마"라고 부를 만한 나머지 전부는 사용자 지정 CSS입니다.

이 페이지는 각 화면을 차례로 훑은 다음, `status.yourcompany.com`에 페이지를 올리기 위한 CNAME → SSL 전체 순서를 안내합니다.

## 각 브랜딩 컨트롤이 있는 곳

상태 페이지를 열면 사이드 메뉴의 **브랜딩** 섹션에 일곱 개 항목이 있습니다. 더 헤매지 않도록 지도를 드립니다.

| 페이지                       | 거기서 설정하는 것                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| **필수 브랜딩**     | 페이지 제목, 페이지 설명, 검색 엔진 색인, 파비콘.                             |
| **헤더**                 | 로고, 커버 이미지, 각각의 대체 텍스트, 그리고 헤더 링크 바.                                |
| **푸터**                 | 저작권 문구와 푸터 링크 바.                                                    |
| **개요 페이지**          | 개요 설명, 기록 차트 막대 색상, 다운타임 상태, 전체 가동 시간 비율. |
| **HTML, CSS 및 JavaScript** | 헤더 HTML, 푸터 HTML, 사용자 지정 CSS, 사용자 지정 JavaScript.                                    |
| **사용자 정의 도메인**         | 여러분의 도메인, CNAME 검증, SSL.                                            |
| **언어**              | 기본 언어와 푸터 전환기에서 제공할 언어들.                             |

## 필수 브랜딩

**상태 페이지 → 해당 페이지 → 브랜딩 → 필수 브랜딩**(`{id}/branding`)에는 카드 세 개가 있습니다.

- **제목 및 설명** — 카드는 이것이 SEO에도 쓰인다고 알려 줍니다. **편집**을 누르면 **페이지 제목**(플레이스홀더 `Please enter page title here.`)과 **페이지 설명**이 열립니다. 검색 엔진과 링크 미리보기에 나오는 내용이니, 팀이 아니라 고객을 향해 쓰세요.
- **Search Engine Indexing** — 토글 하나인 **Allow Search Engines to Index this Status Page**이며, 제품에서는 Google과 Bing이 이 페이지를 검색 결과에 실을 수 있는지를 제어한다고 설명합니다. 기본적으로 켜져 있습니다. 끄면 페이지가 `noindex, nofollow`로 제공됩니다.
- **파비콘** — **Edit Favicon**을 누르면 **파비콘** 이미지 업로드가 열립니다. 브라우저 탭에 보이는 작은 아이콘이죠.

이럴 때 쓰세요. 페이지가 내부용이거나 아직 준비 중일 때입니다. **Allow Search Engines to Index this Status Page**를 꺼서 반쯤 만든 페이지가 브랜드 이름으로 검색 순위에 오르지 않게 하세요.

## 헤더 화면

**상태 페이지 → 해당 페이지 → 브랜딩 → 헤더**(`{id}/header-style`)입니다. 사이드 메뉴 이름과 달리, 가장 중요한 브랜드 자산 두 가지가 여기 있습니다.

첫 번째 카드는 **로고, 커버 및 파비콘**이고 **Edit Images** 버튼이 있습니다.

- **로고** — 이미지 업로드이며 플레이스홀더는 `Upload logo`입니다.
- **Logo Alt Text** — 플레이스홀더는 `Logo of My Company`입니다. 비워 두면 상태 페이지 제목이 대신 쓰입니다.
- **표지** — 이미지 업로드이며 플레이스홀더는 `Upload cover image`입니다. 헤더 뒤에 깔리는 넓은 배너입니다.
- **Cover Image Alt Text** — 커버에 대한 같은 개념입니다.

그 아래에는 **헤더 링크** 테이블("상태 페이지의 헤더 링크")이 있습니다. 각 링크는 **제목**과 **링크**(URL, 플레이스홀더 `https://link.com`)를 가지며, 행은 드래그로 순서를 바꿉니다. 아무것도 설정하지 않으면 테이블에는 "No status header link for this status page."라고 표시됩니다.

이럴 때 좋습니다. 방문자를 마케팅 사이트나 문서, 지원 포털로 돌려보낼 때, URL을 짐작하게 만들지 않아도 되죠.

## 푸터 화면

**상태 페이지 → 해당 페이지 → 브랜딩 → 푸터**(`{id}/footer-style`)는 **헤더**와 같은 형태로, 카드 하나와 테이블 하나입니다.

- **저작권 정보** — **Edit Copyright**을 누르면 필드 하나인 **저작권 정보**가 열리고, 플레이스홀더는 `Acme, Inc.`입니다.
- **푸터 링크** — 똑같은 **제목** + **링크** 짝이며 드래그로 순서를 바꾸고, 비었을 때 메시지는 "No status footer link for this status page."입니다.

법무, 개인정보 처리방침, 이용약관 링크가 여기 들어갑니다. 헤더 링크는 이동을 위한 것이고, 푸터 링크는 작은 글씨를 위한 것입니다.

## 개요 페이지 브랜딩

**상태 페이지 → 해당 페이지 → 브랜딩 → 개요 페이지**(`{id}/overview-page-branding`)는 색상을 설정할 수 있는 유일한 화면이며, 차트에서 "다운"이 무엇을 뜻하는지도 여기서 정합니다.

- **개요 페이지** — **Edit Branding**을 누르면 리소스 목록 위에 렌더링되는 마크다운 필드 **개요 페이지 설명.**이 열립니다. 이 페이지가 무엇을 다루는지, 지원은 어디로 문의하면 되는지 같은 맥락 한 문장을 적기 좋습니다.
- **Rules for Bar Colors of History Chart** — 드래그로 정렬 가능한 순서 있는 규칙 테이블입니다. 각 규칙은 **When uptime % is greater than or equal to**와 **Then, use this bar color**를 갖고, 테이블 열 이름은 `When Uptime Percent >=`와 `Then, Bar Color is`입니다. 순서가 중요하니 평가되길 원하는 순서대로 배치하세요.
- **다운타임 모니터 상태** — **Edit Statuses**를 누르면 "이 모니터 상태들은 다운으로 간주됩니다"라고 설명된 다중 선택이 열립니다. 예컨대 저하됨 상태를 이 페이지의 가동 시간에서 깎을지 여기서 정합니다.
- **Default Bar Color of the History Chart** — **Edit Default Bar Color**를 누르면 어떤 규칙도 맞지 않을 때 쓰이는 색상인 **기본 막대 색상** 선택기가 열립니다.
- **전체 가동 시간 백분율** — **Edit Settings**를 누르면 **전체 가동 시간 비율 표시** 토글과 **가동 시간 정밀도 선택** 드롭다운이 열리며, 드롭다운의 기본값은 소수점 두 자리(`99.99% (Two Decimal)`)입니다.

**차트가 며칠을 다루는지는 여기서 정하지 않습니다.** 그것은 **상태 페이지 → 해당 페이지 → 고급 → 고급 설정**(`{id}/settings`)의 **가동 시간 기록 표시(일 단위)**이며, 1에서 90까지 유효합니다.

## 사용자 지정 HTML, CSS, JavaScript

**상태 페이지 → 해당 페이지 → 브랜딩 → HTML, CSS 및 JavaScript**(`{id}/custom-code`)에는 각각 독립적으로 편집하는 카드 네 개가 있으며, 상태 페이지의 `headerHTML`, `footerHTML`, `customCSS`, `customJavaScript` 열이 이를 뒷받침합니다.

- **헤더 HTML** — 플레이스홀더 `Insert Custom HTML here.`, 페이지 헤더에 주입됩니다.
- **푸터 HTML** — 푸터에 대한 같은 것입니다.
- **사용자 지정 CSS** — 플레이스홀더 `Insert Custom CSS here.`
- **사용자 지정 JavaScript** — 플레이스홀더 `Insert Custom JavaScript here.`

**테마 선택기는 없습니다.** OneUptime 상태 페이지에는 테마나 브랜드 색상 설정이 없습니다. 어디를 봐도 내장된 색상 컨트롤은 **개요 페이지** 화면의 **기본 막대 색상**과 기록 차트 막대 색상 규칙뿐입니다. 글꼴, 배경색, 강조색, 레이아웃 조정은 모두 여기 **사용자 지정 CSS**로 처리합니다. "브랜드 색상" 필드를 찾고 계셨다면 이것이 답입니다 — 그런 필드는 없고, 이 상자가 탈출구입니다.

> 사용자 지정 JavaScript는 방문자의 브라우저에서 실행되며, 그것도 사람들이 뭔가 고장 났다고 걱정하는 바로 그 순간에 여는 페이지에서 실행됩니다. 작게 유지하고, 가능하면 직접 호스팅하고, 의존하기 전에 반드시 테스트하세요.

## 언어 설정

**상태 페이지 → 해당 페이지 → 브랜딩 → 언어**(`{id}/languages`)에는 카드 두 개가 있고, 둘 다 방문자가 페이지 푸터에서 보게 되는 언어 전환기에 관한 것입니다.

- **기본 언어** — **Edit Default Language**를 누르면 지원되는 각 언어를 원어 이름과 영어 이름으로 나열한 드롭다운이 열립니다(`Deutsch (German)`). 카드는 이것을 처음 방문한 사람이 보는 언어라고 설명하며, 방문자는 언제든 푸터에서 바꿀 수 있습니다. 기본값은 영어입니다.
- **활성화된 언어** — **Edit Enabled Languages**를 누르면 다중 선택이 열리고 플레이스홀더는 `All languages`입니다. 비워 두면 지원되는 모든 언어가 제공됩니다. 몇 개만 고르면 푸터 전환기에는 그것들만 나열됩니다.

OneUptime에는 열여섯 개 언어가 기본 포함됩니다. 영어, 독일어, 프랑스어, 스페인어, 이탈리아어, 포르투갈어, 네덜란드어, 덴마크어, 노르웨이어, 스웨덴어, 러시아어, 일본어, 한국어, 중국어(간체), 중국어(번체), 힌디어입니다.

## 사용자 정의 도메인

기본적으로 상태 페이지는 **개요** 화면에 표시되는 미리보기 URL로 접근할 수 있습니다. 여러분의 호스트 이름에 올리려면 **상태 페이지 → 해당 페이지 → 브랜딩 → 사용자 정의 도메인**(`{id}/domains`)으로 가세요.

카드 제목은 **사용자 정의 도메인**이고, 설명이 요구 사항을 곧이곧대로 말해 줍니다. 이것이 동작하려면 설치 환경의 상태 페이지 CNAME 레코드를 해당 도메인들의 CNAME으로 추가해야 한다고요. 아무것도 설정하지 않으면 테이블에는 "No custom domains found."라고 표시됩니다. 테이블에는 **도메인**과 **상태** 두 개의 열이 있고, **도메인**, **CNAME 유효**, **SSL 프로비저닝됨**으로 필터링할 수 있습니다.

### 시작하기 전에

전제 조건이 두 가지 있는데, 이게 안 되는 흔한 이유가 둘 중 하나를 건너뛴 것입니다.

- **상위 도메인이 이미 검증되어 있어야 합니다.** **도메인** 드롭다운은 프로젝트 설정에서 검증된 도메인만 나열합니다 — 필드의 도움말이 먼저 도메인을 추가하도록 **더보기 → 프로젝트 설정 → 사용자 정의 도메인**을 가리킵니다.
- **설치 환경에 상태 페이지 CNAME 레코드가 설정되어 있어야 합니다.** 자체 호스팅 배포에서는 Docker Compose의 `STATUS_PAGE_CNAME_RECORD` 환경 변수이거나 Helm `values.yaml`의 `statusPage.cnameRecord`입니다. 이것이 없으면 **CNAME 추가**와 **무료 SSL 주문** 모달 모두 안내 대신 "Custom Domains not enabled for this OneUptime installation" 메시지를 보여 줍니다.

### 도메인 추가하기

**Create Status Page Domain**을 클릭하세요. 모달(**Create New Status Page Domain**)은 두 단계입니다.

**기본**

- **서브도메인** — 레이블만 입력하며 플레이스홀더는 `status (leave blank for root)`입니다. 전체 호스트 이름이 아니라 `status`만 입력하세요. 비워 두거나 `@`를 입력하면 루트/에이펙스 도메인을 사용합니다.
- **도메인** — 검증된 도메인 드롭다운이며 플레이스홀더는 `Select domain`입니다.

**더보기**

- **사용자 지정 인증서 업로드** — 토글이며 기본적으로 꺼져 있습니다. 꺼 두면 OneUptime이 무료 인증서를 대신 발급받습니다. 켜면 여러분의 PEM 자료를 넣을 **인증서**와 **인증서 개인 키** 필드가 나타납니다.

## CNAME 검증하기

도메인이 검증되지 않은 동안에는 행에 **CNAME 추가** 동작이 표시됩니다. 이것은 **CNAME 추가**라는 제목의 모달을 열어, DNS 공급자에 그대로 붙여 넣을 내용을 정확히 알려 줍니다.

- **레코드 유형** — `CNAME`
- **이름** — 방금 만든 전체 도메인, 예를 들어 `status.yourcompany.com`
- **콘텐츠** — 설치 환경의 상태 페이지 CNAME 레코드

모달은 레코드가 자리를 잡은 뒤 자동 검증까지 최대 24시간이 걸릴 수 있다고 안내합니다. 그렇게까지 기다릴 필요는 없습니다. 모달의 제출 버튼이 **CNAME 인증**이고, 이것이 레코드를 즉시 확인해 줍니다.

DNS 레코드를 먼저 만들고, 그다음에 **CNAME 인증**을 클릭하세요. 레코드가 없는 상태에서 누르면 그냥 실패합니다.

## SSL 인증서 주문하기

CNAME이 검증되고 나면 — 그리고 직접 인증서를 업로드하지 않은 경우에만 — 행에 **무료 SSL 주문** 동작이 나타납니다. 그 모달인 **Order Free SSL Certificate for this Status Page**는 OneUptime이 LetsEncrypt를 사용한다는 것, 이 과정이 안전하고 무료라는 것, 주문 후 프로비저닝에 몇 시간이 걸린다는 것을 설명합니다. 제출 버튼은 **무료 SSL 주문**입니다.

**표시되는 소요 시간은 화면마다 서로 다릅니다.** 그러니 어느 한 숫자를 너무 믿지 마세요. 주문 모달은 세 시간이라고 하고, **상태** 열은 한 시간이라고 하며, 사용자 지정 인증서는 30분이라고 합니다. 전부 "오늘 안에 다시 확인하기" 정도로 받아들이고, 그때까지 아무 일도 없으면 지원에 문의하세요.

프로비저닝이 끝나면 갱신은 자동입니다. 여러분이 주기적으로 할 일은 없습니다.

## 도메인 상태 열 읽기

**상태** 열은 설정 상태 기계 전체가 한 칸에 담긴 것입니다. 각 메시지는 다음에 무엇을 해야 하는지, 아니면 다 끝났다는 것을 알려 줍니다.

| 상태 열에 나오는 문구                           | 무슨 뜻인가                                                                     |
| ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| Action Required: Please add your CNAME record.        | CNAME이 아직 검증되지 않았습니다. 레코드를 추가한 뒤 **CNAME 인증**을 누르세요.             |
| Action Required: Please order SSL certificate.        | CNAME은 검증되었지만 주문된 인증서가 없습니다. **무료 SSL 주문**을 클릭하세요.       |
| No action is required, allow 30 minutes to provision. | 사용자 지정 인증서를 업로드했고 지금 설치되는 중입니다.                                      |
| No action is required, this will be provisioned soon. | 무료 인증서가 주문되어 진행 중입니다. 끝내 도착하지 않으면 지원에 문의하세요. |
| Certificate Provisioned. No action required.          | 완료되었습니다. OneUptime이 인증서를 자동으로 갱신합니다.                                       |

DNS 항목을 만든 지 한참 지났는데도 행이 "Action Required: Please add your CNAME record."에 머물러 있다면, 레코드 이름이 전체 도메인인지 그리고 콘텐츠가 설치 환경의 CNAME 레코드와 정확히 일치하는지 확인하세요.

## Powered by OneUptime

"Powered by OneUptime" 문구는 브랜딩 섹션의 설정이 아닙니다. 이것은 **상태 페이지 → 해당 페이지 → 고급 → 고급 설정**(`{id}/settings`)의 **Powered By OneUptime 브랜딩** 카드에 토글 하나로 있습니다. **Powered By OneUptime 브랜딩 숨기기**입니다. 그 페이지의 다른 모든 카드와 마찬가지로 **Edit Settings**로 엽니다.
