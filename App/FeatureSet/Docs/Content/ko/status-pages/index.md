# 상태 페이지 개요

상태 페이지는 여러분이 모니터링하는 모든 것의 공개 얼굴입니다. 고객이 "혹시 나만 그런 건가요?"라고 이메일을 보내는 대신 열어볼 수 있는 URL 하나입니다. 여러분이 공개하기로 선택한 서비스의 현재 상태, 대응 중인 인시던트, 예정된 유지보수, 그리고 상단에 고정하고 싶은 공지를 보여줍니다.

새벽 2시에 무언가 고장 나면, 상태 페이지는 지원 문의가 가장 먼저 링크하는 대상입니다. 또한 구독자에게 알림이 발송되는 창구이기도 합니다. 그러니 장애가 나기 전에 준비해 두는 편이 좋습니다.

상태 페이지는 대시보드 왼쪽 내비게이션의 **essentials** 그룹 아래 **상태 페이지**에 있습니다. 이 페이지의 모든 항목은 상태 페이지별로 존재합니다. 하나의 프로젝트는 원하는 만큼 여러 개를 운영할 수 있습니다 — 고객용 공개 페이지, 내부 대상용 비공개 페이지, 특정 시장을 위한 지역별 페이지 등입니다.

## 한눈에 보기

- **두 개의 필드로 생성됩니다.** 새 상태 페이지를 만들 때 필요한 것은 **이름**과 **설명**뿐입니다. 리소스, 브랜딩, 도메인은 모두 나중에 설정합니다.
- **리소스는 방문자가 보는 것입니다.** 페이지의 각 행은 하나의 **상태 페이지 리소스**입니다 — 자체 표시 이름, 툴팁, 가동 시간 옵션을 가진 모니터(또는 모니터 그룹)입니다. 그룹은 긴 페이지를 여러 섹션으로 나누며 중첩할 수 있습니다.
- **첫날부터 미리보기 URL이 있습니다.** 모든 상태 페이지는 사용자 지정 도메인이 없는 상태에서도 미리 볼 수 있는 미리보기 링크를 받습니다.
- **방문자용 경로는 설정으로 게이트됩니다.** 인시던트, 공지, 예정된 이벤트, 구독 페이지는 각각 **고급 설정**에서 해당 토글이 켜져 있을 때만 나타납니다.
- **비공개로 만드는 방법은 세 가지입니다.** 비공개 사용자, 마스터 비밀번호, 또는 SAML SSO / OIDC — 여기에 IP 화이트리스트를 더할 수 있습니다.
- **구독자에게는 자동으로 알림이 갑니다.** 이메일, SMS, Slack, Microsoft Teams, 웹훅 구독자가 모두 페이지를 팔로우할 수 있으며, 각 채널은 자체 토글로 제어됩니다.

## 핵심 용어

| 용어              | 의미                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| **상태 페이지**   | 자체 브랜딩, 도메인, 리소스, 구독자를 가진 하나의 공개(또는 비공개) 페이지입니다. `StatusPage` 모델입니다. |
| **리소스**        | 방문자가 보는 한 행 — 표시 이름과 가동 시간 옵션과 함께 페이지에 노출되는 모니터 또는 모니터 그룹입니다.  |
| **그룹**          | 리소스를 담는 이름 있는 섹션입니다. 그룹은 다른 그룹 안에 중첩되며, 각 단계는 그 아래 모든 것의 상태를 종합해 보여줍니다. |
| **공지**          | 하나 이상의 상태 페이지에 게시하는 메시지로, 시작 시간과 선택적인 종료 시간을 가집니다.                  |
| **구독자**        | 이메일, SMS, Slack, Microsoft Teams 또는 웹훅으로 페이지를 팔로우하는 사람(또는 시스템)입니다.           |
| **사용자 정의 도메인** | 여러분의 도메인 — `status.example.com` — 을 CNAME과 SSL 인증서로 페이지에 연결한 것입니다.          |
| **비공개 사용자** | 비공개 상태 페이지에 로그인할 수 있는 계정입니다. OneUptime 프로젝트 사용자와는 별개입니다.               |

## 상태 페이지 생성하기

1. **상태 페이지 → 모든 상태 페이지**를 열고 **상태 페이지 생성**을 클릭합니다.
2. **새 상태 페이지 생성** 모달에서 **이름**(필수, 최소 두 글자)을 입력하고, 선택적으로 **설명**을 입력합니다.
3. **상태 페이지 생성**을 클릭합니다.

생성 양식은 이게 전부입니다. 돌아가는 목록에는 **이름**, **설명**, **레이블**, **소유자**가 표시되며, **상태 페이지 ID**, **이름**, **설명**으로 필터링할 수 있습니다.

새 페이지를 열면 **개요** 화면으로 이동하며, 이곳에는 두 개의 카드가 있습니다. 페이지 자체로의 링크가 있는 **상태 페이지 미리보기 URL**과, 방금 설정한 이름·설명·레이블을 수정할 수 있는 **상태 페이지 세부 정보**입니다.

다음으로, 대략 유용한 순서대로 할 일입니다.

- 페이지에 내용이 있도록 리소스를 추가하세요 — [상태 페이지 리소스 및 그룹](/docs/status-pages/resources-and-groups)을 참고하세요.
- 페이지 제목, 파비콘, 로고, 커버를 설정하고 사용자 정의 도메인을 연결하세요 — [상태 페이지 브랜딩 및 도메인](/docs/status-pages/branding-and-domains)을 참고하세요.
- 사람들이 구독할 수 있는 채널을 정하세요 — [구독자 및 공지](/docs/status-pages/subscribers)를 참고하세요.
- **고급 설정**에서 페이지에 표시되는 항목을 조정하세요.

## 각 항목의 위치

상태 페이지를 열면 자체 왼쪽 사이드 메뉴가 아홉 개 섹션으로 묶여 있습니다. 이 문서 그룹의 나머지 부분을 읽을 때 지도로 활용하세요.

| 섹션               | 포함된 항목                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **기본**             | **개요**, **공지**, **소유자**.                                                                          |
| **리소스**           | 단일 **리소스** 화면 — 왼쪽에 그룹, 오른쪽에 선택한 그룹의 모니터.                                        |
| **구독자**           | **이메일 구독자**, **SMS 구독자**, **Slack 구독자**, **MS Teams 구독자**, **Webhook 구독자**, **구독자 설정**. |
| **알림 로그**        | **알림 로그** — 구독자에게 무엇이 전송되었는지.                                                          |
| **감사**             | **감사 로그**.                                                                                            |
| **브랜딩**           | **필수 브랜딩**, **HTML, CSS 및 JavaScript**, **사용자 정의 도메인**, **헤더**, **푸터**, **개요 페이지**, **언어**. |
| **보안**             | **비공개 사용자**, **SSO**, **OIDC**, **SCIM**, **인증 설정**.                                            |
| **AI**               | **MCP**.                                                                                                  |
| **고급**             | **Monitor Rules**, **임베디드 상태**, **보고서**, **사용자 정의 필드**, **고급 설정**, **상태 페이지 삭제**. |

미리 알아두면 좋은 두 가지 명명 특이 사항이 있습니다.

- **리소스** 항목은 프로젝트에 모니터 그룹이 활성화된 경우에만 **리소스**라는 이름이 붙습니다. 그렇지 않으면 **모니터**라고 표시됩니다. 어느 쪽이든 같은 화면입니다.
- 별도의 그룹 페이지는 없습니다. 그룹과 리소스가 하나로 합쳐졌으며, 예전의 `/groups` 경로는 이제 리소스 화면으로 리디렉션됩니다.

개별 페이지 바깥에서, **상태 페이지** 섹션 자체는 **공지**를 담은 **More** 섹션과, **공지 템플릿**, **구독자 템플릿**, **사용자 정의 필드**, **소유자 규칙**, **레이블 규칙**을 담은 접힌 **설정** 섹션을 가지고 있습니다 — 이들은 프로젝트 전체에 걸쳐 모든 상태 페이지에서 공유됩니다.

## 방문자가 보는 것

공개 페이지는 그 자체로 하나의 앱이며, 작은 경로 집합으로 이루어져 있습니다.

- `/` — **개요**.
- `/incidents`와 `/incidents/:id` — 인시던트 목록과 개별 인시던트.
- `/announcements`와 `/announcements/:id`.
- `/scheduled-events`와 `/scheduled-events/:id`.
- `/subscribe/email`, `/subscribe/sms`, `/subscribe/slack`, `/subscribe/microsoft-teams`, `/subscribe/webhooks`.
- `/rss` — 피드.
- `/login`, `/sso`, `/master-password` — 비공개 페이지에서만 의미가 있습니다.

상단 내비게이션 바는 항상 **개요**를 보여주며, 나머지는 활성화되었을 때만 나타납니다. **인시던트**, **공지**, **예정된 이벤트**는 각각 자체 토글이 켜져 있어야 하고, **구독**은 **구독자 페이지 표시**와 최소 하나의 구독자 채널이 모두 활성화되어 있어야 합니다. 비공개 페이지에는 **로그아웃** 항목도 추가됩니다.

### 개요 페이지

개요는 대부분의 방문자가 실제로 보게 되는 페이지입니다. 위에서 아래로 다음을 렌더링합니다.

1. **진행 중인 공지** — 시작 시간이 지났고 종료 시간이 아직 지나지 않은 공지입니다.
2. **전체 상태 배너** — 모든 리소스가 영향을 받는지, 일부만 영향을 받는지를 한 줄로 요약합니다.
3. **전체 가동 시간 비율** — 활성화한 경우에만 표시되며, 기본값은 꺼짐입니다.
4. **리소스 그룹** — 각 리소스, 그 현재 상태, 가동 시간 기록 막대와 함께 표시됩니다.
5. **활성 인시던트**.
6. **예정된 유지보수 이벤트**.

아무것도 없는 새 페이지는 대시보드에서 리소스를 추가하라고 안내하는 빈 상태를 보여줍니다 — 이는 **리소스** 화면으로 가라는 신호입니다.

무엇이 인시던트를 이 페이지에 올리고, 무엇이 다시 내리는지는 [인시던트 상태 및 심각도](/docs/incidents/states-and-severities)를 참고하세요.

## 페이지에 표시할 항목 선택하기

표시 관련 스위치의 대부분은 한곳에 모여 있습니다: **상태 페이지 → 해당 페이지 → 고급 → 고급 설정**. 각 카드에는 자체 **Edit Settings** 버튼이 있습니다.

**인시던트 설정**:

- **인시던트 표시** (`showIncidentsOnStatusPage`) — 기본값은 켜짐입니다. 끄면 **인시던트** 내비게이션 항목도 함께 사라집니다.
- **인시던트 기록 표시(일 단위)** (`showIncidentHistoryInDays`) — 인시던트 목록이 얼마나 과거까지 도달하는지입니다. 기본값은 14입니다.
- **인시던트 레이블 표시** (`showIncidentLabelsOnStatusPage`) — 기본값은 꺼짐입니다.

**Episode Settings** — 인시던트 에피소드에 대한 동일한 세 가지 스위치입니다: **에피소드 표시** (`showEpisodesOnStatusPage`, 기본값 켜짐), **에피소드 기록 표시(일 단위)** (기본값 14), **에피소드 레이블 표시** (기본값 꺼짐). 에피소드는 인시던트의 뷰가 아니라, 자체 엔드포인트를 가진 독립된 모델입니다.

**공지 설정**:

- **공지사항 표시** (`showAnnouncementsOnStatusPage`) — 기본값은 켜짐입니다.
- **공지사항 기록 표시(일 단위)** (`showAnnouncementHistoryInDays`) — 기본값은 14입니다.

**예정된 이벤트 설정**:

- **예정된 유지 관리 이벤트 표시** (`showScheduledMaintenanceEventsOnStatusPage`) — 기본값은 켜짐입니다.
- **예정된 이벤트 기록 표시(일 단위)** (`showScheduledEventHistoryInDays`) — 기본값은 14입니다.
- **이벤트 레이블 표시** (`showScheduledEventLabelsOnStatusPage`) — 기본값은 꺼짐입니다.

**가동 시간 기록 설정**:

- **가동 시간 기록 표시(일 단위)** (`showUptimeHistoryInDays`) — 각 리소스 옆 가동 시간 막대의 길이입니다. 기본값은 90이며 1에서 90 사이여야 합니다. 리소스나 그룹의 모든 **가동 시간 % 표시**와 **상태 기록 차트 표시** 옵션이 이 숫자를 참조합니다.

**구독자 설정**:

- **구독자 페이지 표시** (`showSubscriberPageOnStatusPage`) — 기본값은 켜짐이며, 채널별 활성화 토글 다섯 개가 함께 있습니다. 같은 채널 토글은 **구독자** 섹션의 전용 **구독자 설정** 화면에도 나타납니다. 그곳을 이들을 설정하는 정식 장소로 취급하세요.

**Powered By OneUptime Branding**:

- **Powered By OneUptime 브랜딩 숨기기** — 기본값은 꺼짐이며, 이를 켜기 전까지 방문자 페이지 하단에는 "Powered by OneUptime"이 표시됩니다.

**색상이 있는 위치.** 가동 시간 막대 색상은 이곳에 없습니다 — **기본 막대 색상**, 막대 색상 규칙, **다운타임 모니터 상태**, **전체 가동 시간 비율 표시**는 모두 **상태 페이지 → 해당 페이지 → 브랜딩 → 개요 페이지**에 있습니다. 테마나 브랜드 색상 설정은 어디에도 없으며, 이 컨트롤을 넘어서는 것은 무엇이든 **사용자 지정 CSS**로 처리합니다.

## 공개 전 미리보기

모든 상태 페이지의 **개요** 화면에는 페이지로 직접 연결되는 **상태 페이지 미리보기 URL** 카드가 있습니다. 아직 리소스를 추가하는 중이거나 사용자 지정 도메인이 아직 없을 때 이 링크를 사용하세요.

내부적으로는 모든 공개 경로마다 `/status-page/{statusPageId}/...` 아래에 미리보기 쌍이 존재합니다 — 미리보기 개요, 미리보기 인시던트 목록, 미리보기 구독 페이지 등입니다. 즉 대시보드 미리보기에서 가져온 URL이나 스크린샷은 사용자 정의 도메인이 연결된 뒤 고객이 실제로 보는 것과 일치하지 않으므로, 런북이나 이메일에 붙여넣는 링크는 반드시 다시 확인하세요.

## 페이지를 볼 수 있는 사람 제한하기

모든 상태 페이지가 공개용은 아닙니다. 관련 컨트롤은 모두 **보안** 섹션 아래에 있습니다.

### 비공개 사용자

**상태 페이지 → 해당 페이지 → 보안 → 인증 설정**에서 **공개 표시 여부**(`isPublicStatusPage` 컬럼)를 끄세요. 그러면 방문자는 `/login`으로 이동해 로그인해야 합니다.

**상태 페이지 → 해당 페이지 → 보안 → 비공개 사용자**에서 로그인할 수 있는 사람을 추가하세요. **일괄 추가** 작업이 있습니다 — 이메일 주소 목록을 붙여넣으면 각각에게 초대 이메일이 발송됩니다. 비공개 사용자는 OneUptime 프로젝트 계정과 분리된 자체 비밀번호 찾기·재설정 흐름을 가집니다.

### 마스터 비밀번호

**인증 설정**에는 **Require Master Password** 토글과 비밀번호 자체를 담은 **마스터 비밀번호** 카드도 있습니다. 방문자는 `/master-password`로 이동해 공유된 단일 비밀로 페이지를 잠금 해제합니다.

**마스터 비밀번호와 비공개 사용자는 함께 쓸 수 없습니다.** 마스터 비밀번호가 켜져 있는 동안에는 비공개 사용자 인증이 비활성화되며, **비공개 사용자** 화면에는 이를 알리는 배너가 표시됩니다.

### SSO와 OIDC

여러분의 아이덴티티 제공자와 연결된 비공개 페이지의 경우, **상태 페이지 → 해당 페이지 → 보안 → SSO**에서 SAML(로그인 URL, 발급자, x509 인증서, 서명 및 다이제스트 방식)을 설정하고, **상태 페이지 → 해당 페이지 → 보안 → OIDC**에서 OpenID Connect(디스커버리 URL, 발급자, 클라이언트 ID와 시크릿, 스코프, 클레임 이름)를 설정합니다. **SCIM**은 IdP에서 비공개 사용자를 자동으로 프로비저닝합니다. 이들은 요금제 기능으로 제한되어 있어 모든 설치본에서 사용할 수 있는 것은 아닙니다.

**SSO Settings** 카드는 **로그인에 SSO 강제 적용**(`requireSsoForLogin`, 기본값 꺼짐)을 제공합니다. 이를 켜기 전에 SSO 설정을 반드시 테스트하세요 — 작동하지 않으면 상태 페이지에서 스스로 잠겨 나가게 됩니다.

### IP 화이트리스트

**인증 설정**에는 `ipWhitelist` 컬럼을 기반으로 하는 **IP 화이트리스트** 카드도 있습니다. 알려진 네트워크에서만 응답해야 하는 페이지에 사용합니다.

## 임베디드 배지와 RSS 피드

페이지 자체가 아닌 다른 곳에 상태를 노출하는 두 가지 방법입니다.

**임베디드 상태 배지.** **상태 페이지 → 해당 페이지 → 고급 → 임베디드 상태**의 **Embedded Status Badge** 카드에서 **임베디드 상태 배지 활성화**(`enableEmbeddedOverallStatus`, 기본값 꺼짐)를 켜세요. 이는 `embeddedOverallStatusToken`과 짝을 이루고 `/badge/:statusPageId`에서 배지를 제공하므로, 현재 전체 상태를 문서, 앱 하단, 또는 마케팅 페이지에 넣을 수 있습니다.

**RSS 피드.** 모든 상태 페이지는 `/rss`를 제공합니다 — 제목이 "{status page name} Updates"인 피드로, 항목은 `Incident: `, `Announcement: `, `Scheduled Maintenance: `로 시작합니다. 이메일 구독보다 리더나 챗봇으로 업데이트를 받고 싶은 사람에게 유용합니다.

직접 데이터를 가져오고 싶다면, 상태 페이지는 개요, 인시던트, 예정된 유지보수 이벤트, 공지, 에피소드에 대한 공개 읽기 엔드포인트로 뒷받침됩니다 — [공용 API](/docs/status-pages/public-api)를 참고하세요.
