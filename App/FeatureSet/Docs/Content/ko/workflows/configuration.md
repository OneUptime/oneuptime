# 설정 및 보안

실제 트래픽에 워크플로를 연결하기 전에 알아둘 만한 설정과 안전 한도를 다룹니다.

## 워크플로 켜고 끄기

모든 워크플로에는 **Settings**에 **Enabled** 스위치가 있습니다. 꺼져 있으면 워크플로는 실행되지 않으며, 웹훅 호출, 예정된 실행 시각, OneUptime 이벤트가 모두 무시됩니다. 새 워크플로는 비활성화 상태로 시작합니다.

이 스위치를 "준비 완료" 관문으로 사용하세요.

1. 워크플로를 만듭니다.
2. **Builder**에서 현실적인 값으로 **Run Workflow**를 클릭합니다.
3. **Logs**를 확인해 모든 블록이 예상한 대로 진행되었는지 점검합니다.
4. **Enabled**를 켭니다.

워크플로를 끈다고 해서 이미 진행 중인 실행이 멈추지는 않습니다. 새로운 실행이 시작되지 않을 뿐입니다.

## 소유자와 레이블

- **Owners** — 소유자로 등록된 사용자와 팀은 워크플로에 접근할 수 있고, 워크플로가 실패했을 때 알림을 받도록 설정할 수 있습니다. **Settings → Owners**에서 설정합니다.
- **Labels** — 워크플로를 그룹화하는 태그입니다. 워크플로 목록에서 레이블로 필터링할 수 있어 워크플로가 많은 프로젝트를 탐색하기가 훨씬 쉬워집니다. 팀, 통합, 환경별로 워크플로를 구성할 때 유용합니다.
- **Label rules** — **Workflows → Settings → Label Rules**에서, 이름이나 설명 패턴에 따라 새 워크플로에 레이블을 자동으로 적용합니다.
- **Owner rules** — **Workflows → Settings → Owner Rules**에서, 새 워크플로에 소유자를 자동으로 지정합니다.

## 시크릿

민감한 정보를 담고 있다면 전역 변수를 **secret**으로 표시하세요. 저장한 후에는 일반적인 API와 UI 조회에서 값이 숨겨지고, 워크플로 로깅은 실행 로그가 저장되기 전에 해석된 값을 지워냅니다.

다음과 같은 경우에 시크릿 변수를 사용하세요.

- 외부 서비스의 API 키.
- 인증 토큰.
- 웹훅 서명 키.
- 읽기 전용 접근 권한을 가진 사람에게 보이고 싶지 않은 모든 것.

시크릿을 블록에 직접 붙여넣지 마세요 — `Authorization: Bearer eyJh...` 같은 값은 워크플로와 로그에 그대로 노출됩니다. 대신 `{{global.variables.MY_SECRET}}`을 사용하세요.

## 워크플로 내보내기와 가져오기

워크플로를 JSON 파일로 프로젝트 간에, 또는 셀프 호스팅 설치와 OneUptime Cloud 사이에 옮길 수 있습니다.

- **Export** — 워크플로를 열고 **Settings**에서 **Export Workflow**를 사용합니다. 워크플로 목록에서 여러 워크플로를 선택해 하나의 파일로 내보낼 수도 있습니다.
- **Import** — **Workflows** 목록에서 **Import JSON**을 클릭하고, 임의의 OneUptime 프로젝트에서 내보낸 파일을 선택합니다.

이 파일에는 워크플로의 이름, 설명, 활성화 상태, 그래프가 담깁니다. 다음은 의도적으로 담기지 않습니다.

- **웹훅 시크릿 키.** 워크플로가 생성될 때 새 키가 생성되므로, 가져온 워크플로는 웹훅 URL이 달라집니다. 원래 URL을 호출하던 것들은 새 URL로 다시 연결해야 합니다.
- **전역 변수.** `{{global.variables.MY_SECRET}}`을 읽는 블록은 그 참조를 그대로 유지하지만, 값은 파일에 없습니다. 가져온 워크플로를 실행하기 전에 대상 프로젝트에 해당 변수를 만들어야 합니다.
- **소유자와 레이블.** 프로젝트 자체의 레이블 규칙과 소유자 규칙이, 마치 직접 만든 것처럼 가져온 워크플로에 대해 실행됩니다.

가져온 워크플로는 내보낼 때 활성화 상태였더라도 항상 **비활성화** 상태로 생성됩니다. 그래프가 대상 프로젝트에 존재하지 않는 모니터, 온콜 정책, 다른 워크플로를 가리킬 수 있기 때문입니다. 검토하고, 활성화하고, **Run Workflow**로 테스트한 다음 켜 두세요. 워크플로 복제도 동일하게 동작하므로, 복제본을 편집하기 전에 원본과 함께 실행되기 시작하는 일은 없습니다.

그래프가 그대로 옮겨지기 때문에 블록에 직접 입력된 것도 함께 옮겨집니다. 이것이 자격 증명을 시크릿 변수에 보관해야 하는 실질적인 이유입니다 — 토큰을 하드코딩한 워크플로를 내보내면, 그 파일을 받는 사람에게 토큰을 그대로 건네주는 셈이 됩니다.

## 실행이 걸릴 수 있는 최대 시간

각 실행 시도에는 실시간(wall-clock) 기한이 있습니다. 러너는 매 구성 요소의 전후로 이 기한을 확인하며, 제어권이 돌아오는 즉시 기한을 넘긴 실행을 **Timeout**으로 표시합니다. 네트워크나 스크립트 작업을 수행하는 구성 요소는 자체적으로도 타임아웃을 두어야 합니다. 러너는 임의의 구성 요소 코드를 강제로 중단시킬 수 없기 때문입니다.

AI 구성 요소는 워크플로에 남은 시간으로부터 공급자 요청 타임아웃을 산출하며, 최대 60초로 제한하여 로깅과 정리를 위한 약간의 여유를 남깁니다.

## 다른 워크플로 호출 제한

**Execute Workflow** 구성 요소는 한 워크플로가 다른 워크플로를 호출할 수 있게 해줍니다. 워크플로 A가 B를 호출하고 B가 다시 A를 호출하는 것과 같은 우발적인 루프를 막기 위해, 체인이 얼마나 깊어질 수 있는지에 상한이 있습니다. 이 한도를 넘는 실행은 명확한 오류와 함께 종료됩니다.

한 번의 실행마다 항목 하나씩 처리하는 작업처럼 긴 체인이 실제로 필요하다면, 대개는 **Custom Code**를 사용해 하나의 워크플로 안에서 반복하는 편이 더 간단합니다.

## 웹훅 보안

Webhook 트리거는 고유한 URL을 제공합니다. 이 URL을 아는 사람은 누구나 호출할 수 있습니다. 원치 않는 호출이나 실수로부터 보호하려면 다음을 참고하세요.

- 이 URL을 비밀번호처럼 다루세요. 공개적으로 공유하거나 공개 저장소에 커밋하지 마세요.
- 민감한 워크플로의 경우, 호출하는 시스템이 공유 토큰을 헤더(예: `X-Webhook-Token`)로 보내도록 요청하고, 중요한 작업을 하기 전에 **Conditions** 블록으로 이를 확인하세요. 예상 토큰은 시크릿 변수로 저장하세요.
- 매우 민감한 워크플로라면, 공개 웹훅 대신 OneUptime 이벤트 트리거와 수동 가져오기 단계를 사용하는 편을 선호하세요.

## 아웃바운드 네트워크 접근

API 및 기타 HTTP 블록은 OneUptime에서 요청을 보냅니다. 셀프 호스팅하는 경우, 설치 환경이 호출하려는 서비스에 접근할 수 있는지 확인하세요. OneUptime Cloud를 사용하는 경우, 아웃바운드 IP 대역이 [IP Addresses](/docs/configuration/ip-addresses)에 나열되어 있으니 상대 쪽에서 이를 허용할 수 있습니다.

## AI 구성 요소

**Generate Text with AI**는 OneUptime에 설정된 LLM 게이트웨이를 통해 요청을 하나 보냅니다. 프로젝트의 기본 LLM 공급자를 사용하며, 프로젝트에 지정된 공급자가 없으면 설치 전역의 공급자를 사용합니다. 공급자는 **Project Settings → AI → LLM Providers**에서 설정하며, 공급자 API 키나 임의의 모델 엔드포인트를 워크플로 자체에 절대 넣지 마세요.

AI 구성 요소에는 명시적인 이그레스(egress) 경계가 있습니다.

- OneUptime은 고정된 구성 요소 안전 지침에 더해, 해석된 **System Instructions**, **Prompt**, 직렬화된 **Context**를 설정된 공급자에게 보냅니다. Context는 사용자 메시지 끝의 명시적인 마커 뒤에 덧붙여지며, 고정 지침은 그 마커 이후의 모든 내용이 태그나 지시문을 담고 있더라도 신뢰할 수 없는 데이터로 남는다고 명시합니다.
- 트리거 페이로드, 워크플로 이력, 다른 구성 요소의 출력, 프로젝트 레코드, 텔레메트리, 시크릿을 자동으로 첨부하지 않습니다. 위 세 가지 입력 중 하나에서 참조할 때만 데이터가 전송됩니다.
- 도구 정의나 공급자 고유의 기능 필드를 전혀 보내지 않습니다. 모델은 이 구성 요소를 통해 OneUptime을 조회하거나, HTTP 요청을 보내거나, 프로젝트 데이터를 변경할 수 없습니다. 설정된 공급자/모델은 여전히 관리자가 신뢰하는 경계이므로, 엄격하게 오프라인 생성이 필요한 설치 환경에서는 공급자가 관리하는 자체 검색 기능이 없는 모델을 선택해야 합니다.
- 공급자 수준의 추가 파라미터는 생성 전용 튜닝 필드의 허용 목록으로 제한됩니다. 워크플로 메시지를 대체하거나, 도구나 공급자 고유의 웹 검색/데이터 소스를 추가하거나, 텍스트 이외의 모달리티를 활성화하거나, 다중 응답을 요청하거나, 스트리밍을 활성화하거나, 공급자 저장 플래그를 통해 요청을 보존하거나, 이 구성 요소의 출력 토큰 상한을 올릴 수 없습니다. 알려지지 않은 향후 기능 필드는 기본적으로 무시됩니다.
- System Instructions, Prompt, Context, 생성된 Response 값은 자동 워크플로 실행 로그에서 이 AI 구성 요소 자체의 인자 및 반환값 항목에서는 편집(redact)됩니다. 실행이 진행되는 동안에는 이후 구성 요소에서 계속 사용할 수 있습니다. 이를 다른 구성 요소에 삽입하면 그 구성 요소의 로깅 정책이 적용되어 해석된 값이 기록될 수 있으므로, 재사용은 명시적인 공개로 취급하세요. 공급자/모델 이름, 토큰 수, LLM Log ID, 안전한 오류 메시지는 운영과 청구를 위해 계속 표시됩니다. 원본 공급자 오류 본문은 공급자가 요청 내용을 그대로 돌려보낼 수 있기 때문에 워크플로 로그, LLM 로그, 애플리케이션 로그, 트레이스에서 제외됩니다.

참조하는 모든 변수는 공급자에게 의도적으로 보내는 데이터로 취급하세요. 특히, 그 공개가 반드시 필요하고 해당 공급자가 이를 받을 수 있도록 승인되지 않은 이상, 시크릿 전역 변수를 프롬프트나 컨텍스트에 넣지 마세요. Ollama 같은 셀프 호스팅 로컬 공급자는 요청을 자체 인프라 안에 유지할 수 있는 반면, 호스팅형 공급자는 그 공급자의 데이터 처리 약관에 따라 요청을 받습니다.

각 호출은 공급자, 모델, 상태, 토큰, 비용, 청구 정보와 함께 **Project Settings → AI → AI Logs**에 기록됩니다. 프롬프트와 응답 미리보기, 원본 공급자 오류 세부 정보는 AI 로그에 저장되지 않습니다. 유료 전역 공급자를 통한 호출은 프로젝트의 AI 크레딧 잔액을 소비합니다. 워크플로 AI 사용량도 프로젝트의 일일 자율 AI 토큰 예산에 포함되며, 예산이 소진되면 이 구성 요소는 모델에 연결하지 않고 **Error** 경로를 탑니다. 프로젝트 AI가 활성화되어 있어야 합니다. OneUptime Cloud에서는 구독이 유료여야 하고 Growth 플랜(또는 Growth 기능을 포함하는 플랜)이 필요합니다. 청구가 비활성화된 셀프 호스팅 설치에는 이 플랜 제한이 적용되지 않습니다.

무인 호출을 유한하게 유지하기 위한 기본 한도가 있습니다. System Instructions, Prompt, 직렬화된 Context를 합쳐 최대 50,000자, Temperature는 `0`부터 `1`까지, Maximum Output Tokens는 `1`부터 `4096`까지(기본값 `1024`)이며, 공급자 요청은 한 번만 시도되고 최대 60초 후 타임아웃됩니다. 프로젝트당 동시에 실행되는 워크플로 AI 호출은 최대 3개이며, 그 이상의 호출은 **Error** 경로를 타고 이후 워크플로 실행에서 다시 시도할 수 있습니다. 검증, 설정, 접근, 예산, 잔액, 동시성, 공급자, 타임아웃 오류는 모두 **Error** 경로를 타고 **Error** 출력을 채웁니다. 프로덕션 워크플로를 활성화하기 전에 이 경로를 연결하세요.

## 권한

워크플로는 프로젝트의 역할 기반 접근 제어(RBAC)를 따릅니다. 관련 권한은 다음과 같습니다.

- **Create / Read / Edit / Delete Workflow** — 워크플로 자체에 대한 기본 권한입니다.
- **Run Workflow** — 워크플로를 수동으로 실행하거나 API를 통해 트리거하는 데 필요합니다.
- **Read Workflow Log** — 실행 내역을 보는 데 필요합니다.
- **Read / Create / Edit / Delete Workflow Variable** — 전역 변수 목록에 대한 통제 권한입니다.

대부분의 엔지니어는 워크플로에 대한 생성/편집/읽기 권한은 있어야 하지만 변수에 대해서는 그렇지 않아도 됩니다. 변수 편집 권한은 프로젝트의 시크릿을 관리하는 사람들을 위해 남겨 두세요.

## 플랜 한도

OneUptime Cloud는 작은 플랜에서 월간 실행 횟수에 상한을 둡니다. 현재 한도는 **Project Settings → Billing**에서 확인할 수 있습니다. 한도에 도달하면 다음 결제 주기까지 새로운 트리거가 거부됩니다. 셀프 호스팅 설치에는 이 한도가 없습니다.

## 워크플로가 적합하지 않은 경우

다른 도구를 찾아야 하는 몇 가지 경우입니다.

- **무거운 연산이나 대용량 데이터셋** — 워크플로는 가벼운 연결 작업을 위해 설계된 것이지, 대량 연산을 위한 것이 아닙니다. 무거운 작업은 자체 인프라에서 실행하고, 워크플로는 이를 시작시키는 역할만 하게 하세요.
- **장시간 실행되는 능동적 연산** — 하나의 실행 시도는 빠르게 끝나도록 설계되어 있습니다. "A를 하고, 두 시간 기다리고, B를 한다"처럼 수동적인 지연이 필요하다면 **Sleep** 구성 요소를 사용하세요. 워커를 점유하지 않고 실행을 저장해 두었다가 나중에 재개합니다.
- **사람이 개입하는 단계별 인시던트 대응** — 이럴 때는 [Runbooks](/docs/runbooks/index)를 사용하세요. 워크플로는 무인 자동화를 위한 것입니다.
