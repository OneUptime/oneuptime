# 트리거

트리거는 워크플로의 첫 번째 블록으로, 워크플로가 언제 실행될지를 결정합니다. 모든 워크플로에는 정확히 하나의 트리거가 있습니다. 네 가지 종류 중에서 고를 수 있습니다.

## Manual

**Builder** 페이지에서 **Run Workflow**를 클릭하고, 트리거의 필드를 채운 다음, **Run Workflow Manually**로 확인하여 원할 때 워크플로를 실행합니다. Manual 트리거는 워크플로의 나머지 부분이 읽을 수 있는 JSON 페이로드를 받습니다.

적합한 용도: "이 키를 교체", "테스트 알림 보내기"처럼 버튼 하나로 실행하고 싶은 자동화.

**출력**: 붙여넣은 JSON, 또는 아무것도 붙여넣지 않았다면 빈 객체입니다.

## Schedule

cron 표현식을 사용해 워크플로를 반복 일정으로 실행합니다.

적합한 용도: 야간 정리, 시간별 동기화, 주간 리포트.

**설정**: cron 표현식입니다. 자주 쓰이는 몇 가지 예시입니다.

- `0 * * * *` — 매시 정각.
- `*/5 * * * *` — 5분마다.
- `0 9 * * 1` — 매주 월요일 오전 9시.

시스템이 잠시 사용할 수 없는 상태였다면, 복구되는 즉시 실행이 처리됩니다 — 짧은 장애로 인한 누락된 실행 시각을 걱정할 필요가 없습니다.

## Webhook

OneUptime이 고유한 URL을 생성합니다. 이 URL로 들어오는 모든 요청이 워크플로를 시작시킵니다. 요청의 헤더, 쿼리 파라미터, 본문이 함께 전달됩니다.

적합한 용도: 다른 도구로부터 OneUptime으로 데이터를 받는 경우 — CI/CD 콜백, 다른 모니터링 도구의 알림, CRM의 가입 이벤트 등.

**출력**:

- **Request Headers** — 들어온 요청의 모든 헤더입니다.
- **Request Query Params** — 파싱된 쿼리 문자열입니다.
- **Request Body** — 파싱된 본문(JSON이 아니면 원본 텍스트)입니다.

이 URL은 `GET`과 `POST`를 모두 받습니다. 호출한 쪽에는 즉시 확인 응답이 전달되며, 워크플로 자체는 백그라운드에서 실행됩니다.

이 URL은 비밀번호처럼 다루세요. 이 URL을 아는 사람은 누구나 워크플로를 시작시킬 수 있습니다.

## OneUptime 이벤트 트리거

모니터, 인시던트, 알림, 예정된 유지 관리, 상태 페이지, 온콜 정책, 팀 등 OneUptime 안의 거의 모든 것이 워크플로를 트리거할 수 있습니다. 각각은 세 가지 이벤트를 제공합니다.

- **On Create** — 새로 추가될 때 실행됩니다.
- **On Update** — 변경될 때 실행됩니다.
- **On Delete** — 삭제될 때 실행됩니다.

이것이 반복문으로 계속 확인할 필요 없이 "OneUptime에서 X가 일어나면 Y를 한다"를 만드는 방법입니다.

전체 레코드가 다음 블록으로 전달됩니다. 예를 들어 **Incident → On Create** 트리거는 새로 생성된 인시던트를 전달하므로, 다음 블록에서 그 제목, 설명, 심각도, 그 밖의 어떤 필드도 읽을 수 있습니다.

### 팀이 가장 많이 사용하는 이벤트

- **Incident** — 인시던트가 열리거나, 업데이트되거나(인지됨, 해결됨), 삭제될 때 반응합니다.
- **Alert** — 알림에 대해서도 동일한 세 가지 이벤트가 있습니다.
- **Monitor** — 모니터가 추가, 수정, 제거될 때 반응합니다.
- **Scheduled Maintenance** — 유지 관리 기간이 예약되면 자동으로 공지합니다.
- **Status Page Subscriber** — 상태 페이지 구독자를 환영합니다.
- **On-Call Duty Policy** — 일정 변경 사항을 다른 로스터 시스템과 동기화합니다.

원하는 이벤트를 찾으려면 **Add Trigger** 패널에서 이름으로 검색하세요.

## 어떤 트리거를 사용해야 할까요?

| 원하는 것…                              | 선택                 |
| ---------------------------------------- | -------------------- |
| 버튼을 눌러 워크플로 실행                | **Manual**           |
| 반복 일정으로 실행                       | **Schedule**         |
| 다른 시스템이 데이터를 밀어 넣게 함      | **Webhook**          |
| OneUptime 내부의 무언가에 반응           | **OneUptime event**  |

워크플로는 하나의 트리거만 가질 수 있습니다. 동일한 자동화를 두 가지 방식으로 시작해야 한다면, 공통 로직을 하나의 워크플로에 만들고 **Execute Workflow** 구성 요소를 사용해 두 개의 얇은 "래퍼" 워크플로에서 이를 호출하세요.
