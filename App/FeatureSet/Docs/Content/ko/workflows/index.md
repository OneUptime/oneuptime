# 워크플로 개요

워크플로를 사용하면 코드를 작성하지 않고도 OneUptime에서 작업을 자동화할 수 있습니다. 캔버스에 몇 개의 블록을 추가하고 서로 연결하기만 하면, 인시던트가 열리거나, 일정이 실행되거나, 다른 도구가 OneUptime으로 데이터를 보낼 때마다 실행되는 자동화가 완성됩니다.

워크플로는 프로젝트를 위한 백그라운드 도우미라고 생각하면 됩니다. 이벤트에 반응하고, 다른 도구와 대화하며, 사용자가 본업에 집중하는 동안 조용히 모든 것을 동기화 상태로 유지합니다.

## 워크플로로 할 수 있는 일

- **OneUptime을 다른 도구와 연결** — 인시던트를 Slack으로 보내고, Jira 티켓을 생성하고, 사용 중인 스택의 웹훅으로 게시합니다.
- **OneUptime에서 일어나는 일에 반응** — 심각한(critical) 인시던트가 생성되면 온콜 팀에 알리고 자동으로 티켓을 엽니다.
- **일정에 따라 작업 실행** — 5분마다, 매일 밤, 매주 월요일 아침 등.
- **외부로부터 데이터 수신** — 고유한 URL을 통해 다른 시스템이 OneUptime으로 데이터를 밀어 넣을 수 있게 합니다.
- **공통 자동화 재사용** — 한 번 만들어 두고 다른 어떤 워크플로에서도 호출합니다.

## 워크플로의 작동 방식

모든 워크플로에는 세 가지 부분이 있습니다.

1. **트리거** — 워크플로를 시작시키는 것입니다. 수동 버튼, 일정, 수신 웹훅, 또는 OneUptime 내부의 이벤트(예: 새 인시던트)가 될 수 있습니다.
2. **하나 이상의 구성 요소** — 워크플로가 수행하는 작업입니다. 메시지 전송, HTTP 호출, 빠른 확인, 조건에 따른 분기 등입니다.
3. **이들 사이의 연결** — 한 블록에서 다음 블록으로 선을 그려 실행 순서를 정합니다.

이 모든 작업은 캔버스에서 시각적으로 이루어집니다. 대부분의 워크플로에는 코딩이 필요 없지만, 필요할 때는 JavaScript 코드 조각을 추가할 수도 있습니다.

## 핵심 용어

| 용어                 | 의미                                                                              |
| -------------------- | --------------------------------------------------------------------------------- |
| **워크플로**         | 전체 자동화 — 이름, 캔버스, 그리고 켜고 끌 수 있는 스위치로 구성됩니다.            |
| **트리거**           | 첫 번째 블록입니다. 워크플로가 언제 실행될지를 결정합니다. 모든 워크플로에는 정확히 하나의 트리거가 있습니다. |
| **구성 요소**        | 동작 블록입니다 — 메시지를 보내고, 요청을 만들고, 조건을 확인합니다.               |
| **실행**             | 워크플로의 한 번의 실행입니다. 타임스탬프와 각 블록의 출력이 함께 저장됩니다.       |
| **전역 변수**        | 한 번 저장해 두고 어떤 워크플로에서든 재사용할 수 있는 값(예: API 키)입니다.       |

## OneUptime에서 워크플로 찾기

왼쪽 내비게이션에서 **Workflows**를 엽니다. 이 섹션에는 다음이 있습니다.

- **Workflows** — 워크플로 목록입니다. 새 워크플로를 만들거나 기존 워크플로를 엽니다.
- **Global Variables** — 모든 워크플로에서 공유되는 값입니다.
- **Runs & Logs** — 프로젝트의 모든 워크플로에 대한 실행 이력입니다.

하나의 워크플로를 열면 자체 왼쪽 메뉴에 다음이 있습니다.

- **Overview** — 이름, 설명, 레이블, 그리고 **Enabled** 스위치입니다.
- **Builder** — 워크플로를 설계하는 캔버스입니다.
- **Workflow Variables** — 이 워크플로 하나에만 적용되는 값입니다.
- **Runs & Logs** — 이 워크플로의 모든 실행과 그 세부 정보입니다.
- **Settings** — 웹훅 시크릿, 복제, 내보내기입니다.

## 첫 워크플로 만들기

1. **Create** — 시작점을 고른 다음, 워크플로에 이름을 붙입니다.
2. **트리거 선택** — 수동, 일정, 웹훅, 또는 OneUptime의 이벤트 중에서 고릅니다.
3. **구성 요소 추가** — 캔버스에 동작을 추가하고 서로 연결합니다.
4. **켜기** — **Overview** 페이지에서 **Enabled**를 켭니다. 비활성화된 워크플로는 수동으로도 전혀 실행할 수 없습니다.
5. **테스트** — Builder에서 **Run Workflow**를 클릭하고 실행 로그를 지켜봅니다.

## 간단한 예시

심각한 인시던트가 생성될 때마다 Slack에 게시하고 싶다고 해봅시다.

1. "Critical incidents to Slack"이라는 워크플로를 만듭니다.
2. **On Create Incident** 트리거를 고릅니다.
3. **If / Else** 블록을 추가합니다. 인시던트 제목에 "Sev 1"이 포함되어 있는지 확인하도록 설정합니다.
4. **Yes** 분기에서 **Slack** 블록을 추가합니다. 채널을 고르고 메시지를 작성합니다.
5. 워크플로를 켭니다.

다음에 누군가 제목에 "Sev 1"이 포함된 인시던트를 열면, Slack에 알림이 뜹니다.

## 워크플로가 OneUptime의 나머지 부분과 맞물리는 방식

- **모니터**가 문제를 발견합니다. **인시던트**가 이를 기록합니다. **워크플로**가 이에 반응합니다.
- **Runbook**은 사람을 위한 단계별 안내서입니다. 워크플로는 무인 자동화입니다. 사람이 판단을 내려야 할 때는 runbook을, 단계가 자동적일 때는 워크플로를 사용합니다.
- **작업 공간 연결**(Slack, Teams)은 워크플로가 메시지를 보내는 대상입니다.
