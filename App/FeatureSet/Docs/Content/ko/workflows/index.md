# 워크플로 개요

워크플로를 사용하면 코드를 쓰지 않고도 OneUptime에서 작업을 자동화할 수 있습니다. 캔버스에 블록 몇 개를 올리고 서로 연결하면, 무슨 일이 생길 때마다 — 인시던트가 열리거나, 일정이 돌아오거나, 다른 도구가 OneUptime으로 데이터를 보낼 때마다 — 실행되는 자동화가 완성됩니다.

워크플로는 프로젝트의 백그라운드 조력자라고 생각하세요. 이벤트에 반응하고, 다른 도구와 대화하며, 여러분이 본업에 집중하는 동안 조용히 상태를 맞춰 둡니다.

## 워크플로로 할 수 있는 일

- **OneUptime을 다른 도구와 연결하기** — 인시던트를 Slack으로 보내고, Jira 티켓을 만들고, 사내 스택의 웹훅으로 게시합니다.
- **OneUptime에서 일어나는 일에 반응하기** — 심각한 인시던트가 생성되면 온콜 팀에 알리고 자동으로 티켓을 엽니다.
- **일정에 맞춰 작업 실행하기** — 5분마다, 매일 밤, 매주 월요일 아침에.
- **외부에서 데이터 받기** — 다른 시스템이 고유 URL을 통해 OneUptime으로 데이터를 밀어 넣게 합니다.
- **자주 쓰는 자동화 재사용하기** — 한 번 만들어 두고 다른 어떤 워크플로에서든 호출합니다.

## 워크플로가 동작하는 방식

모든 워크플로는 세 부분으로 이루어집니다.

1. **트리거** — 워크플로를 시작시키는 것. 수동 버튼일 수도, 일정일 수도, 수신 웹훅일 수도, OneUptime 안의 이벤트(새 인시던트 같은)일 수도 있습니다.
2. **하나 이상의 구성 요소** — 워크플로가 하는 일. 메시지 보내기, HTTP 호출하기, 간단한 점검 실행하기, 조건에 따라 분기하기 등입니다.
3. **그 사이의 연결** — 블록에서 블록으로 선을 그어 순서를 정합니다.

이 모든 것을 캔버스에서 시각적으로 만듭니다. 대부분의 워크플로는 코딩이 전혀 필요 없지만, 필요할 때는 JavaScript 조각을 넣을 수 있습니다.

## 핵심 용어

| 용어             | 의미                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------- |
| **워크플로**    | 자동화 전체 — 이름, 캔버스, 그리고 켜고 끄는 스위치.                          |
| **트리거**       | 첫 번째 블록. 워크플로가 언제 실행될지를 정합니다. 모든 워크플로에는 트리거가 정확히 하나 있습니다. |
| **구성 요소**    | 동작 블록 — 메시지를 보내고, 요청을 만들고, 조건을 확인합니다.                |
| **실행**         | 워크플로의 한 번의 수행. 타임스탬프와 모든 블록의 출력이 함께 저장됩니다.       |
| **전역 변수**    | API 키처럼 한 번 저장해 두고 어떤 워크플로에서든 재사용하는 값.                |

## OneUptime에서 워크플로를 찾는 곳

왼쪽 내비게이션에서 **워크플로**를 엽니다. 이 섹션에는 다음이 있습니다.

- **워크플로** — 워크플로 목록입니다. 새로 만들거나 기존 것을 열 수 있습니다.
- **전역 변수** — 모든 워크플로가 공유하는 값입니다.
- **실행 및 로그** — 프로젝트 안 모든 워크플로의 실행 이력입니다.

워크플로 하나를 열면 그 자체의 왼쪽 메뉴에 다음이 있습니다.

- **개요** — 이름, 설명, 레이블, 그리고 **활성화됨** 스위치.
- **빌더** — 워크플로를 설계하는 캔버스.
- **워크플로 변수** — 이 워크플로에만 적용되는 값.
- **실행 및 로그** — 이 워크플로의 모든 실행과 그 상세 내역.
- **설정** — 웹훅 시크릿, 복제, 내보내기.

## 첫 워크플로 만들기

1. **만들기** — 시작점을 고른 다음 워크플로에 이름을 붙입니다.
2. **트리거 고르기** — 수동, 일정, 웹훅, 또는 OneUptime 이벤트 중에서 고릅니다.
3. **구성 요소 추가하기** — 캔버스에 동작을 추가하고 서로 연결합니다.
4. **켜기** — **개요** 페이지에서 **활성화됨**을 켭니다. 비활성화된 워크플로는 손으로도 실행할 수 없습니다.
5. **테스트하기** — 빌더에서 **워크플로 실행**을 클릭하고 실행 로그를 지켜봅니다.

## 간단한 예시

심각한 인시던트가 생성될 때마다 Slack에 게시하고 싶다고 해 봅시다.

1. "Critical incidents to Slack"이라는 워크플로를 만듭니다.
2. **On Create Incident** 트리거를 고릅니다.
3. **If / Else** 블록을 추가합니다. 인시던트 제목에 "Sev 1"이 들어 있는지 확인하도록 설정합니다.
4. **예** 분기에서 **Slack** 블록을 추가합니다. 채널을 고르고 메시지를 작성합니다.
5. 워크플로를 켭니다.

다음에 누군가 제목에 "Sev 1"이 들어간 인시던트를 열면 Slack에 불이 들어옵니다.

## 워크플로가 OneUptime의 나머지와 맞물리는 방식

- **모니터**가 문제를 발견합니다. **인시던트**가 이를 기록합니다. **워크플로**가 이에 반응합니다.
- **런북**은 사람을 위한 단계별 안내서이고, 워크플로는 무인 자동화입니다. 사람이 판단해야 할 때는 런북을, 단계가 자동으로 정해질 때는 워크플로를 사용하세요.
- **Workspace connections**(Slack, Teams)는 워크플로가 메시지를 보내는 대상입니다.
