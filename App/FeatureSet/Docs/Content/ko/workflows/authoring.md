# 워크플로 작성

워크플로를 만들려면 **Workflows**를 열고 **Create Workflow**를 클릭합니다. **Create a workflow**라는 마법사가 안내해 줍니다. 먼저 **Start from**에서 **Start from scratch** 또는 템플릿 중 하나를 고르고, 다음으로 **Name**을 입력하고, 마지막으로 **Configure** 단계는 고른 템플릿이 자체 설정을 요구할 때만 나타납니다.

생성되면 왼쪽 메뉴에서 **Builder**를 엽니다. 워크플로를 설계하는 캔버스입니다.

## 캔버스

처음부터 시작한 워크플로는 **Please click here to add trigger**라고 적힌 점선 블록 하나로 시작합니다. 이 블록이 시작점입니다 — 클릭하면 트리거를 고를 수 있습니다. 템플릿에서 만든 워크플로는 블록이 이미 배치된 상태로 열립니다.

모든 워크플로에는 맨 위에 정확히 하나의 **트리거**가 있습니다. 나머지는 모두 무언가를 수행하는 **구성 요소**입니다. 두 번째 트리거를 추가하면 첫 번째 트리거를 대체하며, 마지막 트리거를 삭제하면 점선 자리표시자가 다시 나타납니다.

블록 추가하기.

- **트리거** — 점선 자리표시자 블록을 클릭합니다. **Add Trigger**라는 제목의 패널이 열립니다.
- **그 외 모든 것** — 캔버스 위 툴바에서 **Add Component**를 클릭합니다. 같은 패널이 **Add Component**라는 제목으로 열립니다.

두 패널 모두 검색이 가능합니다 — `/`를 눌러 검색창으로 이동하며, 카테고리별로 그룹화되어 있습니다. 블록 하나를 선택하고 **Add to Workflow**를 클릭합니다.

새 블록은 항상 캔버스의 같은 위치에 놓이므로, 새 블록이 이미 배치해 둔 것 위에 겹칠 수 있습니다. 끌어서 옮기면 되며, 캔버스는 이동하는 동안 격자에 맞춰집니다. 블록 위치는 저장되므로, 다음에 보는 사람도 남겨 둔 것과 같은 배치를 보게 됩니다.

변경 사항은 자동으로 저장됩니다. 툴바의 알약(pill) 표시가 이를 추적합니다. 변경이 진행 중일 때는 **Saving…**, 그다음 **Saved**, 실패하면 **Could not save**로 표시됩니다. 별도의 Save 버튼이나 게시 단계는 없습니다.

## 블록에 있는 것

| 필드                        | 하는 일                                                                                                                                                       |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Identifier**(**ID** 아래) | 블록에 표시되는 짧은 id로, 예를 들면 `log-1`입니다. 다른 블록이 이 블록을 참조하는 방식이므로, 이름을 바꾸면 이 블록을 가리키는 모든 `{{local.components.…}}` 참조가 깨집니다. 블록의 제목은 구성 요소 자체의 이름이며 바꿀 수 없습니다. |
| **Settings**                | 블록이 작업을 수행하는 데 필요한 것 — URL, Slack 채널, 메시지 본문 등입니다. 선택적 필드에는 **(Optional)** 표시가 붙으며, 그 외에는 모두 필수입니다. 잘 쓰이지 않는 설정은 **Advanced** 접이식 메뉴 안에 있습니다. |
| **Input**                   | 블록 위쪽 가장자리의 점으로, 이전 블록에서 오는 선이 들어오는 곳입니다. 트리거에는 이것이 없습니다 — 트리거보다 먼저 실행되는 것은 없기 때문입니다.               |
| **Outputs**                 | 블록 아래쪽 가장자리를 따라 있는 점들로, 바로 위에 이름표가 붙어 있으며, 다음 블록으로 선이 나가는 곳입니다. 많은 블록은 두 경우를 모두 처리할 수 있도록 별도의 **Success**와 **Error** 출력을 가집니다. |

## 블록 연결하기

한 블록의 아래쪽 점에서 다음 블록의 위쪽 점까지 끌어다 놓습니다. 그린 선이 다음에 무엇이 실행될지를 결정합니다.

- **Success**에서 연결하면, 이전 블록이 성공했을 때만 다음 블록이 실행됩니다.
- **Error**에서 연결하면, 이전 블록이 실패했을 때만 다음 블록이 실행됩니다.
- 출력을 연결하지 않으면, 그 경로는 거기서 멈춥니다.

하나의 출력을 여러 블록에 연결할 수 있습니다. 모두 실행되지만 — 병렬이 아니라 하나의 큐 안에서 순서대로 실행됩니다. 분기 사이의 순서에 의존하지 말고, 시간이 겹칠 것이라고 가정하지도 마세요. 각 블록은 한 번의 실행당 최대 한 번만 실행되므로, 이전 블록으로 되돌아가는 루프가 있어도 그 블록이 두 번 실행되지는 않습니다.

## 블록 설정하기

블록을 클릭하면 대화 상자에서 설정이 열립니다. 각 설정에는 텍스트 필드, 드롭다운, 코드 에디터, 토글 등 알맞은 종류의 입력이 있습니다. 값을 채우고 **Save**를 클릭합니다.

같은 대화 상자에서 다음도 찾을 수 있습니다.

- **Delete** — 이 블록을 제거합니다.
- **Run just this step** — 나머지 워크플로 없이 이 블록 하나만 실행합니다. 다른 단계에서 읽어야 했을 값은 비어 있는 채로 들어오며, 이 블록이 보내거나 쓰거나 삭제하는 것은 실제로 일어납니다.
- **Documentation**, **Inputs**, **Outputs**, **Returns** — 이 블록이 무엇을 기대하고 무엇을 생성하는지에 대한 참조 카드입니다.

대부분의 텍스트 필드는 변수를 받습니다 — 이것이 데이터가 한 블록에서 다음 블록으로 흐르는 방식입니다. 문법을 직접 입력하는 대신, 에디터의 값 선택기를 사용하세요. 고른 블록과 필드로부터 올바른 참조를 만들어 줍니다. [Variables](/docs/workflows/variables)를 참고하세요.

## 만드는 동안의 검사

Builder는 변경할 때마다 전체 그래프를 검사하고, 그 결과를 툴바의 알약(pill) 표시로 알려줍니다. 이 알약을 클릭하면 **Problems with this workflow**가 열려 각 문제를 나열하고 해당 블록으로 바로 이동시켜 줍니다. 문제가 있는 블록에는 캔버스에 빨간 배지도 표시됩니다.

트리거가 없거나, 두 블록이 같은 id를 공유하거나, id 안에 점이 있거나, 아무것도 연결되지 않은 블록이 있거나, 필수 설정이 비어 있거나, JSON 형식이 잘못되었거나, `{{ }}` 안에 공백이 있거나, 존재하지 않는 단계나 반환값을 참조하는 등 실행해 보기 전까지는 보이지 않는 실수들을 잡아냅니다.

검사할 수 없는 한 가지는 변수 이름이 실제로 존재하는지입니다. 이름이 바뀐 변수는 실행 로그에서만 드러납니다.

## 첫 워크플로

캔버스를 감 잡는 가장 빠른 방법입니다.

1. 점선 자리표시자 블록을 클릭하고, **Add Trigger** 패널에서 **Manual**을 고른 다음 **Add to Workflow**를 클릭합니다.
2. **Add Component**를 클릭하고, (**Utils** 아래의) **Log**를 고른 다음 **Add to Workflow**를 클릭합니다. 새 블록을 트리거에서 떨어뜨려 놓고, 트리거의 **Execute** 점에서 Log 블록의 입력 점까지 연결합니다.
3. Log 블록을 열고 **Value**를 `Hello from {{local.components.manual-1.returnValues.value.name}}`으로 설정합니다. `manual-1`은 트리거 블록에 표시된 트리거의 **Identifier**입니다 — 일치하는지 확인하세요.
4. **Overview**로 이동해 **Workflow Details** 카드에서 **Edit Workflow**를 클릭하고 **Enabled**를 켭니다. 비활성화된 워크플로는 수동으로도 전혀 실행할 수 없습니다.
5. 다시 **Builder**로 돌아와 **Run Workflow**를 클릭하고, **JSON** 필드에 `{ "name": "Ada" }`를 입력한 다음 **Run Workflow Manually**를 클릭하고 **Run**으로 확인합니다.
6. **Workflow Run** 패널이 저절로 열려 실행을 따라갑니다. 로그에는 `Value:` 뒤에 `Hello from Ada`가 표시됩니다.

추가, 연결, 설정, 실행, 로그 확인이라는 이 순환이 앞으로 모든 워크플로를 만드는 방식입니다.

## 켜기

새 워크플로는 비활성화 상태로 시작하며, 복제하거나 가져온 워크플로도 마찬가지입니다.

**Enabled** 스위치는 워크플로의 **Overview** 페이지, **Workflow Details** 카드에 있습니다 — Settings 페이지가 아닙니다. 같은 카드에 현재 상태가 녹색 **Enabled** 또는 빨간색 **Disabled** 알약으로 표시됩니다.

비활성화된 워크플로는 전혀 실행할 수 없습니다. 수동 실행도 트리거된 실행과 마찬가지로 "This workflow is not enabled"로 거부됩니다. 그러므로 순서는 다음과 같습니다. 활성화하고, **Run Workflow**로 테스트하고, 실행 로그를 읽고, 트리거가 실행될 준비가 되지 않았다면 **Enabled**를 다시 끕니다. 전체를 실행하지 않고 블록 하나만 테스트하려면 해당 블록 설정의 **Run just this step**을 사용하세요.

삭제하지 않고 워크플로를 일시 중지하려면 **Enabled**를 끄세요. 새 실행은 시작되지 않습니다. 이미 진행 중인 실행은 끝까지 완료되지만, **Sleep** 블록에서 대기 중인 실행은 깨어날 때 취소되어 오류로 기록됩니다.

## 정리하기

- 블록을 끌어서 옮깁니다. 배치는 저장됩니다.
- 선을 삭제하려면 한쪽 끝을 점에서 끌어내 빈 캔버스에 놓습니다.
- 블록을 삭제하려면 블록을 클릭한 다음 설정 대화 상자 아래쪽의 **Delete**를 사용합니다. 블록이나 선을 선택하고 Backspace를 눌러도 제거됩니다.
- 블록 하나만 복제하는 방법은 없습니다. 워크플로의 **Settings** 페이지에 있는 **Duplicate Workflow**는 전체를 복사하며, 복사본은 비활성화 상태로 생성됩니다.
- 블록은 실행되는 방향으로 읽히도록 위에서 아래로 쌓으세요 — 입력은 위쪽 가장자리에, 출력은 아래쪽 가장자리에 있으므로 흐름이 자연스럽게 아래로 향합니다.
