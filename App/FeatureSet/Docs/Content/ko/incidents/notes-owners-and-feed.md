# 노트, 소유자 및 피드

인시던트는 대응하는 동안 글로 된 기록을 쌓아 갑니다. 그 기록의 일부는 고객을 위한 것입니다 — 새벽 2시 14분에 문제의 배포를 찾았다고 상태 페이지에 나가는 업데이트 같은 것이죠. 나머지는 팀을 위한 것입니다 — 누군가 붙여 넣은 스택 트레이스, 마침내 앞뒤가 맞은 그래프, 페일오버하기로 한 결정.

OneUptime은 이 두 독자를 갈라 둡니다. **공개 노트**는 상태 페이지에 게시되고 구독자에게 알릴 수 있습니다. **비공개 노트**(`IncidentInternalNote` 모델)는 대시보드 안에 머무릅니다. 그 아래에는 인시던트에 일어난 모든 일을 기록하는 추가 전용 타임라인인 **인시던트 피드**와, 누가 소식을 들을지 정하는 **소유자** 목록이 있습니다.

이 모든 것은 인시던트의 왼쪽 사이드 메뉴에 걸려 있습니다. **노트 → 공개 노트**, **노트 → 비공개 노트**, **팀 → 소유자**입니다. 피드는 인시던트 **개요** 페이지에 있습니다.

## 공개 노트와 비공개 노트

두 노트 유형은 대시보드에서 비슷해 보이지만 동작은 크게 다릅니다.

- **공개 노트** — `IncidentPublicNote` 모델이며, 인시던트 타임라인의 일부로 상태 페이지에 제공됩니다. 직접 지정할 수 있는 **게시 시각** 날짜와 **상태 페이지 구독자에게 알림** 체크박스를 가집니다.
- **비공개 노트** — `IncidentInternalNote` 모델입니다. 상태 페이지 앱은 이것을 읽지 않습니다. 게시 시각 필드도 없고(목록은 `createdAt`으로 찍히고 정렬됩니다) 구독자 관련 필드도 전혀 없어서, 비공개 노트는 구독자 알림을 유발할 수 없습니다.

**"비공개"가 실제로 뜻하는 것.** 이는 "상태 페이지에 게시되지 않는다"는 뜻이지 "더 좁은 사람들에게만 열려 있다"는 뜻이 아닙니다. 두 노트 유형은 읽기 권한이 같아서, 인시던트를 읽을 수 있는 사람은 그 비공개 노트도 읽을 수 있습니다. 인시던트 자체를 볼 수 있는 사람을 제한하고 싶다면 인시던트의 **비공개 인시던트** 플래그(`isPrivate`)를 쓰세요. 이 플래그는 인시던트를 모든 상태 페이지에서 숨기고 인시던트의 소유자 사용자, 소유자 팀의 구성원, 프로젝트 관리자와 프로젝트 소유자로 접근을 좁힙니다.

**소유자는 둘 다 봅니다.** 소유자 알림 작업은 공개 노트와 비공개 노트를 함께 조회합니다. 비공개 노트는 구독자에게 비공개인 것이지 대응하는 사람들에게 비공개인 것이 아닙니다.

| 이렇게 하고 싶다면…                                    | 이것을 고르세요  |
| ------------------------------------------------------ | ---------------- |
| 아는 것과 다음 소식 시점을 고객에게 알린다            | **공개 메모**    |
| 다른 데로 이미 보낸 업데이트를 과거 시각으로 남긴다   | **공개 메모**    |
| 가설, 실행한 명령, 막다른 길을 기록한다               | **비공개 메모**  |
| 힙 덤프나 내부 대시보드 스크린샷을 붙인다             | **비공개 메모**  |

## 공개 노트 작성하기

인시던트 사이드 메뉴에서 **노트 → 공개 노트**를 열고 노트를 만듭니다. 카드는 여기에 쓴 내용이 상태 페이지에 나타난다고 알려 주고, 빈 상태에서는 이 인시던트에 아직 만들어진 공개 노트가 없다고 표시됩니다.

| 필드                               | 용도                                                                                                                  |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **공개 인시던트 메모**             | 마크다운으로 쓰는 본문이며 필수입니다. 양식은 이 노트가 상태 페이지에 보인다는 점을 상기시키고 치트시트를 링크합니다. |
| **첨부 파일**                      | 상태 페이지에서 구독자와 공유되는 파일입니다. 선택 사항입니다.                                                        |
| **상태 페이지 구독자에게 알림**    | 체크박스이며 기본적으로 켜져 있습니다. 조용히 게시하려면 끄세요.                                                      |
| **게시 시각**                      | 필수 날짜·시각이며 기본값은 현재 시각이고 현재 시간대로 표시됩니다.                                                   |

**게시 시각이 노트의 진짜 시각입니다.** 상태 페이지는 공개 노트를 입력한 시각이 아니라 `postedAt`으로 정렬해 보여 줍니다 — 그러니 40분 전에 보낸 업데이트를 상태 페이지에 뒤늦게 반영하는 중이라면 **게시 시각**을 실제로 일어난 시각으로 맞추세요. API로 들어온 노트에 값이 없으면 OneUptime이 현재 시각을 찍습니다.

목록에는 각 노트를 누가 썼는지, **게시 시각**, 첨부 파일과 함께 렌더링된 마크다운, 그리고 **구독자 알림 상태** 열이 표시됩니다. **생성자**, **노트**, **생성일**로 필터링할 수 있습니다.

## 비공개 노트 작성하기

**노트 → 비공개 노트**는 일부러 더 단순합니다. 필드가 둘뿐입니다.

- **비공개 인시던트 메모** — 마크다운 본문이며 필수입니다. 양식은 이것이 팀 전용이며 상태 페이지에 보이지 않는다고 대놓고 알려 줍니다.
- **첨부 파일** — 인시던트 대응 팀을 위한 파일입니다.

**게시 시각**도, 구독자 체크박스도 없습니다 — 노트는 만들어질 때 시각이 찍힙니다.

## 노트의 첨부 파일

두 노트 유형 모두 **첨부 파일** 필드로 파일 첨부를 받고, 둘 다 노트 본문 아래에 파일별 **Download attachment** 링크가 달린 첨부 목록을 렌더링합니다.

갈라지는 지점은 누가 그 파일을 가져갈 수 있느냐입니다.

- **공개 노트의 첨부 파일**은 상태 페이지 방문자가 노트와 함께 상태 페이지 경로를 통해 내려받을 수 있습니다.
- **비공개 노트의 첨부 파일**은 인증된 대시보드 API로만 접근할 수 있습니다. 상태 페이지 경로가 아예 없습니다.

그래서 첨부 파일도 노트 본문과 똑같은 공개/비공개 판단의 대상입니다. 고객에게 보여 줄 타임라인 이미지는 공개 노트에, 설정 덤프는 비공개 노트에 붙이세요.

## AI로 노트 생성하기

두 노트 페이지 모두 **Generate with AI** 버튼을 가지고 있습니다. 이 버튼은 인시던트를 프로젝트의 AI 제공자에 보내고 생성된 마크다운을 노트 편집기에 넣어 주며, 여러분이 저장 전에 손보게 합니다 — 자동으로 게시되는 것은 없습니다.

- **Generate Public Note with AI** — 인시던트 데이터를 분석해 고객용 노트를 만든다고 설명되어 있습니다. 템플릿으로는 **Status Update**와 **Resolution Notice**가 있습니다.
- **Generate Private Note with AI** — 대신 내부용 기술 노트를 만듭니다. 템플릿으로는 **Investigation Update**와 **Technical Analysis**가 있습니다.

버튼 뒤에서 대시보드는 고른 템플릿과 `public` 또는 `internal` 노트 유형을 담아 `/incident/generate-note-from-ai/{incidentId}`로 요청을 보냅니다.

## 노트 템플릿

장애가 날 때마다 팀이 같은 업데이트 세 개를 쓰고 있다면, 한 번 저장해 두세요. 두 노트 페이지 모두 **메모 템플릿 선택** 드롭다운이 있는 **템플릿에서 메모 만들기** 선택기를 여는 **템플릿에서 생성** 버튼을 가지고 있습니다.

템플릿은 공개 노트와 비공개 노트가 공유합니다. 하나의 템플릿 목록이 둘 다를 담당하며, 같은 템플릿을 어느 쪽 노트에나 넣을 수 있습니다.

관리는 **인시던트 → 설정 → 노트 템플릿**에서 합니다 — 카드 제목은 **인시던트용 공개 또는 비공개 메모 템플릿**이고, 양식은 **템플릿 정보** 단계(**템플릿 이름**과 **템플릿 설명**, 둘 다 필수)와 본문을 쓰는 **메모 세부정보** 단계로 이루어져 있습니다. 하나도 만들지 않은 채 **템플릿에서 생성**을 누르면 OneUptime이 아직 없다고 알려 주는데, 그 안내는 프로젝트 설정을 가리키지만 실제 페이지는 **인시던트 → 설정 → 노트 템플릿** 아래에 있습니다.

## Slack이나 Microsoft Teams에서 노트 작성하기

워크스페이스를 연결해 두었다면 대응자는 채널을 떠날 필요가 없습니다. Slack과 Microsoft Teams 모두 노트 추가 작업을 제공하는데, **공개 메모** 또는 **비공개 메모**를 고르는 드롭다운과 텍스트 상자가 있는 모달을 열고 결과를 곧바로 인시던트에 기록합니다.

알아 둘 만한 세부 사항이 둘 있습니다.

- **중복 방지** — 각 노트는 자신이 비롯된 Slack 메시지를 기록하므로(`postedFromSlackMessageId`, 형식은 `channel_id:message_ts`), 여러 사람이 같은 메시지에 반응해도 노트는 다섯 개가 아니라 하나만 생깁니다.
- **노트는 되울립니다** — 어느 쪽 노트를 올리든 연결된 인시던트 채널에도 메시지가 들어갑니다. 노트의 피드 항목이 워크스페이스 알림을 켠 채로 만들어지기 때문입니다.

## 공개 노트가 실제로 구독자에게 도달하는 조건

**상태 페이지 구독자에게 알림**을 켠 채 공개 노트를 만들었다고 해서 그것만으로 이메일이 나가지는 않습니다. 노트는 일련의 검사를 통과해야 하고, 통과하지 못할 때마다 오류를 내는 대신 구체적인 사유가 기록됩니다.

1. **상태 페이지 구독자에게 알림**이 켜져 있어야 합니다. 꺼져 있으면 노트는 만들어지는 즉시 건너뜀으로 표시됩니다.
2. 노트는 여전히 존재하는 인시던트에 속해 있어야 합니다.
3. 인시던트에 모니터가 최소 하나는 붙어 있어야 합니다 — 모니터가 없으면 노트를 보낼 상태 페이지 리소스가 없습니다.
4. 인시던트의 **상태 페이지에 표시** 플래그(`isVisibleOnStatusPage`)가 참이어야 합니다.
5. 인시던트가 도달하는 각 상태 페이지에서 **인시던트 표시**(`showIncidentsOnStatusPage`)가 켜져 있어야 합니다.
6. 각 구독자가 자신의 설정을 통과해야 합니다 — 구독 취소 상태가 아니어야 하고, 해당 리소스를 구독하고 있어야 하며, 페이지가 이벤트 유형 선택을 허용한다면 `Incident` 유형도 구독하고 있어야 합니다.

**알림은 즉시 나가지 않습니다.** 발송 작업은 1분에 한 번 돌기 때문에 노트를 저장하고 메일이 떠나기까지 최대 1분 정도를 예상하세요. **Sending Soon** 라벨이 뜻하는 것이 바로 그것입니다.

**구독자 알림 상태** 열은 그 여정 전체를 따라갑니다.

| 상태                         | 무엇을 뜻하는가                                          |
| ---------------------------- | ------------------------------------------------------ |
| **Notifications skipped.**   | 위 관문 중 하나가 닫혔습니다. 사유가 기록됩니다.        |
| **Sending Soon**             | 대기열에 올라 발송 작업의 다음 회차를 기다립니다.       |
| **Notifications Being Sent** | 작업이 구독자 목록을 훑고 있습니다.                     |
| **전송된 알림**              | 모든 구독자 알림이 나갔습니다.                          |
| **실패**                     | 작업이 예외를 냈고, 오류가 노트와 함께 저장됩니다.      |

상태에서 **자세히 보기**를 클릭하면 **알림 상태 세부정보**가 열립니다. 재발송이 말이 되는 경우 그 모달의 버튼은 **Retry**이며, 노트를 다시 대기 상태로 돌려 다음 회차가 집어 가게 합니다.

구독자가 실제로 받는 메시지는 상태 페이지별, 채널별로 템플릿이 정해집니다. 이메일, SMS, Slack, Microsoft Teams 각각이 **Subscriber Incident Note Created** 이벤트용 자체 템플릿을 가지며, 상태 페이지 이름과 URL, 상세 링크, 영향받는 리소스, 인시던트 심각도와 제목, 노트 본문, 구독자별 구독 취소 링크 변수를 씁니다. 이 템플릿과 채널을 어떻게 설정하는지는 [구독자 및 공지](/docs/status-pages/subscribers)를 보세요.

## 인시던트 피드

**인시던트 피드** 카드는 인시던트 **개요** 페이지 왼쪽 열의 맨 아래에 있습니다. 인시던트의 이야기를 순서대로 담고 있으며, 각 항목은 아이콘, 그 일을 일으킨 사람의 아바타와 이름, 마우스를 올리면 정확한 현지 시각이 나오는 상대 시각, 그리고 마크다운 본문으로 이루어집니다. 항목은 오래된 것부터 정렬됩니다.

일부 항목은 추가 정보를 담고 있습니다 — 예를 들어 소유자 알림은 메일을 받은 사람 전원을 나열합니다. 그런 항목에는 **More Information** 패널을 여는 **More Information** 버튼이 붙습니다.

카드 헤더에는 **작업** 메뉴도 있어서 타임라인을 떠나지 않고 조치를 취할 수 있습니다.

- **런북 실행** — 이 인시던트에 대해 [런북](/docs/runbooks/index)을 시작합니다.
- **온콜 정책 실행** — 정책을 즉시 호출합니다.
- **공개 노트 추가** — 공개 노트 페이지와 같은 네 개의 필드를 모달로 엽니다.
- **비공개 노트 추가** — 노트 본문과 첨부 파일만 있습니다.

그 옆의 **새로고침**은 피드를 다시 가져옵니다.

**피드는 추가 전용이며, 감사 로그는 아닙니다.** API는 피드 항목의 생성과 조회는 허용하지만 수정과 삭제는 허용하지 않으므로, 누구도 인시던트의 역사를 조용히 고쳐 쓸 수 없습니다. 그렇다고 영구적이지도 않습니다. 유료 설치 환경에서는 3년이 지난 피드 행이 제거됩니다. 누가 무엇을 바꿨는지에 대한 오래 남는 기록이 필요하다면 인시던트 사이드 메뉴의 **감사 → 감사 로그**를 쓰세요.

## 피드가 기록하는 것

피드 항목은 인시던트 서비스 자체, 두 노트 서비스, 상태 타임라인, 소유자 및 구성원 변경, 규칙 엔진, 온콜 실행, AI 조사 및 포스트모템 러너, 그리고 알림 크론 작업이 씁니다. 이벤트 유형은 다음을 아우릅니다.

- **인시던트 자체** — `IncidentCreated`, `IncidentUpdated`, `IncidentStateChanged`.
- **노트와 기록물** — `PublicNote`, `PrivateNote`, `RootCause`, `RemediationNotes`, `PostmortemNote`.
- **사람** — `OwnerUserAdded`, `OwnerTeamAdded`, `OwnerUserRemoved`, `OwnerTeamRemoved`, `IncidentMemberAdded`, `IncidentMemberRemoved`.
- **알림** — `OwnerNotificationSent`, `SubscriberNotificationSent`, `OnCallPolicy`, `OnCallNotification`.
- **자동화** — `LabelRuleExecuted`, `OwnerRuleExecuted`, `PrivacyRuleExecuted`, `OnCallRuleExecuted`, `AutoRemediation`.

유형마다 아이콘이 달라서 긴 피드를 훑으면서도 잡담 사이에서 상태 변경을 골라낼 수 있습니다. AI가 만든 근본 원인 분석은 따로 표시되고 제한된 마크다운 모드로 렌더링됩니다.

피드는 인시던트의 공개 설정을 따릅니다. 비공개 인시던트의 경우 피드 조회도 인시던트와 같은 방식으로 걸러집니다.

## 소유자

소유자는 인시던트를 책임지는 사람과 팀입니다. 인시던트에 벌어지는 모든 일의 알림 대상이며 — 모두가 "누군가 하고 있겠지"라고 생각하는 사이에 인시던트가 방치되지 않게 하는 장치이기도 합니다.

인시던트 사이드 메뉴에서 **팀 → 소유자**를 엽니다. **소유자** 카드는 개수 배지를 보여 주고, 소유자를 이 인시던트를 책임지며 변경 사항을 통지받는 사람과 팀으로 설명하면서 "2 people · 1 team" 같은 현재 개수를 함께 표시합니다. 소유자는 겹쳐진 아바타로 렌더링되며, 하나에 마우스를 올리면 그 사람의 이메일이 보이거나 항목이 **Team**으로 표시됩니다.

- **소유자 추가**를 클릭하면 사람이나 팀을 찾는 검색 상자가 있는 선택기가 열립니다.
- 아바타의 제거 컨트롤을 클릭하면 **소유자 제거** 확인이 열리고, 이어서 **제거**를 누릅니다.
- 아직 소유자가 없으면 카드가 그 사실을 알리며 변경 사항을 통지받을 팀원이나 팀을 추가하라고 권합니다.

소유자 사용자와 소유자 팀은 별개의 레코드입니다. 팀을 추가하면 그 팀의 모든 구성원이 알림 목적상 소유자가 되며, 개별로 나열할 필요가 없습니다.

## 소유자가 배정되는 방식

소유자 목록에 오르는 경로는 네 가지입니다.

- **인시던트 템플릿에서** — 템플릿은 **소유자 - 팀**과 **소유자 - 사용자** 필드를 가지며, 인시던트를 소유하고 생성 또는 갱신 시 통지받을 팀과 사용자로 설명됩니다. 템플릿에서 인시던트를 만들면 이 값이 미리 채워집니다. [인시던트 선언](/docs/incidents/declaring-incidents)을 보세요.
- **인시던트 소유자 규칙에서** — 일치하는 규칙이 생성 시점에 소유자를 자동으로 추가합니다.
- **API로 생성할 때** — 생성 호출과 함께 넘긴 소유자 사용자와 팀은 즉시 추가되며, "소유자로 추가되었습니다" 이메일을 보낼지 결정하는 플래그도 함께 넘길 수 있습니다.
- **직접** — 인시던트가 진행되는 어느 시점에든 **소유자** 페이지의 **소유자 추가** 컨트롤을 쓰면 됩니다.

같은 사람을 두 번 추가해도 안전합니다. 이미 배정된 소유자는 중복되지 않습니다.

## 인시던트 소유자 규칙

**인시던트 소유자 규칙**은 조건에 맞는 인시던트가 생성될 때 소유자 사용자와 팀을 자동으로 배정합니다 — 아무도 신경 쓰지 않아도 데이터베이스 인시던트가 데이터베이스 팀에게 가도록 하는 라우팅 계층입니다. 나머지 인시던트 자동화와 함께 [인시던트 설정 및 자동화](/docs/incidents/settings)에서 다룹니다.

규칙 양식은 **기본 정보**, **일치 기준**, **소유자** 세 단계로 되어 있고, 소유자 단계에는 두 개의 섹션이 있습니다.

- **할당할 소유자** — **소유자 팀**과 **소유자 사용자**를 고릅니다. 규칙이 일치하면 선택한 사용자와 팀이 모두 소유자로 추가되며, 이미 배정된 소유자는 중복되지 않습니다.
- **소유자 상속** — 소유자를 직접 지정하는 대신 관련 엔터티에서 물려받습니다. **모니터에서 소유자 상속**은 인시던트에 붙은 모니터의 모든 소유자를 인시던트의 소유자로 만들고, **Inherit Owners From Hosts**, **… From Kubernetes Clusters**, **… From Docker Hosts**, **… From Podman Hosts**, **… From Services**가 각 리소스에 대해 같은 일을 합니다.

**소유자에게 알림** 토글은 사람들이 그 사실을 알게 될지를 결정합니다. 실제 라우팅이라면 켜 두고, 조용히 소유자만 추가하고 싶다면 끄세요 — 규칙이 호출이 아니라 장부 정리 목적일 때 유용합니다.

모든 규칙 실행은 인시던트 피드에 기록되므로, 어떤 사람이 규칙으로 추가됐는지 사람이 추가했는지 언제든 구분할 수 있습니다.

## 소유자가 통지받는 것

소유자에게 알리는 작업은 다섯 가지이며, 각각 1분에 한 번 실행됩니다.

- **인시던트 생성** — 제목은 `[New Incident {number}] - {title}`입니다.
- **노트가 올라옴** — 공개 노트와 비공개 노트 *모두*에 대해, 제목은 `[Update Incident {number}] - {title}`입니다.
- **인시던트 상태가 바뀜** — [인시던트 상태 및 심각도](/docs/incidents/states-and-severities)를 보세요.
- **소유자로 추가됨** — 제목은 `You have been added as the owner of Incident {number} - {title}`입니다.
- **아직 미해결** — 인시던트의 다음 알림 시각으로 구동되는 리마인더이며, 제목은 `[Reminder] Incident {number} is still {state} - {title}`입니다.

각 알림은 이메일, SMS, 음성 통화, 푸시, WhatsApp용으로 만들어져 사용자의 알림 설정에 넘겨지고, 실제로 무엇이 발송될지는 그 설정이 정합니다. 수신자는 이들을 하나씩 개별로 끌 수 있습니다 — 사용자별 설정은 인시던트 생성, 노트 게시, 상태 변경, 소유자 추가, 구성원 배정, 미해결 리마인더 알림을 보낸다는 문구로 표현되어 있습니다. 상태 변경에만 전화를 받고 싶은 사람은 정확히 그렇게 설정할 수 있습니다.

**소유자가 없는 인시던트도 조용하지 않습니다.** 인시던트에 소유자가 하나도 없으면 알림 작업이 프로젝트 소유자로 대체되므로 아무것도 바닥에 떨어지지 않습니다. 통지받은 사람은 모두 해당 피드 항목에 함께 기록되므로, 누구에게 어떤 주소로 알렸는지 나중에 정확히 확인할 수 있습니다.
