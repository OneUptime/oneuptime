# یکپارچه‌سازی ایمیل ورودی SendGrid

**مانیتور ایمیل ورودی** در OneUptime به شما امکان می‌دهد بر پایه ایمیل‌هایی که به نشانی‌های یکتای مخصوص هر مانیتور فرستاده می‌شوند هشدار بسازید و برطرف کنید. این برای یکپارچه‌سازی با سامانه‌های قدیمی، ابزارهای هشداردهی یا هر سرویسی که می‌تواند ایمیل بفرستد مفید است.

این راهنما توضیح می‌دهد چگونه SendGrid Inbound Parse را برای فرستادن ایمیل‌های ورودی به نمونه خودمیزبان OneUptime خود راه بیندازید.

## پیش‌نیازها

- حسابی در SendGrid (رده رایگان کار می‌کند)
- دامنه‌ای که کنترلش می‌کنید و به تنظیمات DNS آن دسترسی دارید
- نمونه OneUptime شما باید عمومی دست‌یافتنی باشد (تا SendGrid بتواند وب‌هوک بفرستد)

## چگونه کار می‌کند

1. در OneUptime یک **مانیتور ایمیل ورودی** می‌سازید
2. ‏OneUptime نشانی ایمیل یکتایی برای آن مانیتور تولید می‌کند (برای نمونه `monitor-abc123@inbound.yourdomain.com`)
3. وقتی ایمیلی به آن نشانی فرستاده شود، SendGrid آن را دریافت و از راه وب‌هوک به OneUptime می‌فرستد
4. ‏OneUptime ایمیل را بر پایه معیارهای پیکربندی‌شده شما می‌سنجد تا هشدار بسازد یا برطرف کند

## دستورالعمل راه‌اندازی

### گام ۱: دامنه ایمیل ورودی خود را برگزینید

به زیردامنه‌ای اختصاصی برای دریافت ایمیل‌های ورودی نیاز دارید. زیردامنه‌ای مانند این‌ها را توصیه می‌کنیم:

- `inbound.yourdomain.com`
- `email.yourdomain.com`
- `monitor.yourdomain.com`

این زیردامنه منحصراً برای ایمیل‌های مانیتور OneUptime به کار خواهد رفت.

### گام ۲: پیکربندی رکورد MX در DNS

رکوردی MX به پیکربندی DNS خود اضافه کنید تا ایمیل‌های زیردامنه ورودی‌تان به SendGrid مسیردهی شوند.

| نوع | میزبان/نام | اولویت | مقدار |
| ---- | --------- | -------- | --------------- |
| MX | inbound | 10 | mx.sendgrid.net |

**نمونه:** اگر دامنه شما `example.com` است و از `inbound.example.com` استفاده می‌کنید:

```
inbound.example.com.  IN  MX  10  mx.sendgrid.net.
```

**توجه:** تغییرات DNS می‌توانند تا ۴۸ ساعت طول بکشند تا منتشر شوند، اما معمولاً ظرف چند ساعت کامل می‌شوند.

### گام ۳: تأیید دامنه در SendGrid (اختیاری اما توصیه‌شده)

برای تحویل‌پذیری بهتر و پرهیز از علامت خوردن ایمیل‌ها به‌عنوان هرزنامه:

1. به [داشبورد SendGrid](https://app.sendgrid.com) وارد شوید
2. به **Settings** > **Sender Authentication** بروید
3. روی **Authenticate Your Domain** کلیک کنید
4. برای افزودن رکوردهای لازم DNS (رکوردهای CNAME برای DKIM) دستورها را دنبال کنید

### گام ۴: پیکربندی SendGrid Inbound Parse

1. به [داشبورد SendGrid](https://app.sendgrid.com) وارد شوید
2. به **Settings** > **Inbound Parse** بروید
3. روی **Add Host & URL** کلیک کنید
4. این‌ها را پیکربندی کنید:

| فیلد | مقدار |
| ----------------------------------- | ----------------------------------------------------------------------- |
| **Receiving Domain** | زیردامنه ورودی شما (برای نمونه `inbound.yourdomain.com`) |
| **Destination URL** | `https://your-oneuptime-domain.com/incoming-email/sendgrid/YOUR_SECRET` |
| **Check incoming emails for spam** | اختیاری — در صورت تمایل فعالش کنید |
| **Send raw, full MIME message** | بدون تیک بگذارید (لازم نیست) |
| **POST the raw, full MIME message** | بدون تیک بگذارید (لازم نیست) |

5. روی **Add** کلیک کنید

### گام ۵: پیکربندی متغیرهای محیطی OneUptime

#### Docker Compose

این متغیرهای محیطی را به فایل `config.env` خود اضافه کنید:

```bash
# Inbound Email Configuration
INBOUND_EMAIL_PROVIDER=SendGrid
INBOUND_EMAIL_DOMAIN=inbound.yourdomain.com
# INBOUND_EMAIL_WEBHOOK_SECRET=your-optional-secret  # Optional: for additional security
```

#### Kubernetes با Helm

این‌ها را به فایل `values.yaml` خود اضافه کنید:

```yaml
inboundEmail:
  provider: "SendGrid"
  domain: "inbound.yourdomain.com"
  # webhookSecret: "your-optional-secret"  # Optional
```

**مهم:** پس از افزودن این متغیرهای محیطی، کارساز OneUptime خود را بازراه‌اندازی کنید.

### گام ۶: ساخت یک مانیتور ایمیل ورودی

1. به داشبورد OneUptime خود وارد شوید
2. به **Monitors** > **Create Monitor** بروید
3. نوع مانیتور را **Incoming Email** برگزینید
4. مانیتورتان را پیکربندی کنید:
   - **Name:** نامی توصیفی به مانیتورتان بدهید
   - **Description:** توضیح دهید این مانیتور برای چیست
5. **Alert Creation Criteria** را پیکربندی کنید (کی هشداری ساخته شود):
   - نمونه: موضوع ایمیل دربردارنده "ALERT" یا "CRITICAL"
6. **Alert Resolution Criteria** را پیکربندی کنید (کی هشداری برطرف شود):
   - نمونه: موضوع ایمیل دربردارنده "RESOLVED" یا "OK"
7. روی **Create** کلیک کنید

پس از ساخت، نشانی ایمیل یکتای این مانیتور را می‌بینید (برای نمونه `monitor-abc123def456@inbound.yourdomain.com`).

### گام ۷: آزمایش یکپارچه‌سازی

1. نشانی ایمیل مانیتور را از داشبورد OneUptime کپی کنید
2. ایمیلی آزمایشی با موضوعی که با معیارهای هشدارتان می‌خواند به آن نشانی بفرستید
3. برای تأیید، داشبورد OneUptime را بررسی کنید:
   - ایمیل دریافت شد (در Monitor Summary دیده می‌شود)
   - هشداری ساخته شد (اگر معیارها مطابقت کردند)

## مرجع متغیرهای محیطی

| متغیر | توضیح | الزامی | پیش‌فرض |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- | -------- | ------- |
| `INBOUND_EMAIL_PROVIDER` | ارائه‌دهنده ایمیل ورودی‌ای که به کار می‌رود | بله | - |
| `INBOUND_EMAIL_DOMAIN` | زیردامنه پیکربندی‌شده برای ایمیل‌های ورودی | بله | - |
| `INBOUND_EMAIL_WEBHOOK_SECRET` | راز اعتبارسنجی درخواست‌های وب‌هوک. وقتی تنظیم شود، این راز را به نشانی وب‌هوک بیفزایید: `/incoming-email/sendgrid/YOUR_SECRET` | خیر | - |

## معیارهای پشتیبانی‌شده ایمیل

هنگام پیکربندی مانیتور ایمیل ورودی خود، می‌توانید بر پایه این‌ها معیار بسازید:

| فیلد | توضیح | پالایه‌های در دسترس |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------ |
| **Email Subject** | خط موضوع ایمیل | Contains، Not Contains، Equals، Not Equals، Starts With، Ends With، Is Empty، Is Not Empty |
| **Email From** | نشانی ایمیل فرستنده | Contains، Not Contains، Equals، Not Equals، Starts With، Ends With، Is Empty، Is Not Empty |
| **Email Body** | متن ساده بدنه ایمیل | Contains، Not Contains، Equals، Not Equals، Starts With، Ends With، Is Empty، Is Not Empty |
| **Email To** | نشانی ایمیل گیرنده | Contains، Not Contains، Equals، Not Equals، Starts With، Ends With، Is Empty، Is Not Empty |
| **Email Received** | زمان سپری‌شده از آخرین ایمیل دریافتی | Received In Minutes، Not Received In Minutes |

## نمونه موارد کاربرد

### هشدارهای سامانه قدیمی

بسیاری از سامانه‌های قدیمی فقط می‌توانند هشدار ایمیلی بفرستند. مانیتور ایمیل ورودی بسازید تا:

- وقتی سامانه قدیمی ایمیل `[CRITICAL]` می‌فرستد، هشدار OneUptime بسازید
- وقتی ایمیل‌های `[RESOLVED]` دریافت می‌شوند، هشدارها را برطرف کنید

### یکپارچه‌سازی با سرویس شخص ثالث

با سرویس‌هایی که اعلان ایمیلی می‌فرستند یکپارچه شوید:

- ابزارهای مانیتورینگی که یکپارچه‌سازی API ندارند
- اعلان‌های ارائه‌دهنده ابری
- ابزارهای پویش امنیتی

### ضربان قلب از راه ایمیل

از معیار «Email Received» استفاده کنید تا مطمئن شوید ایمیل‌های دوره‌ای دریافت می‌کنید:

- اگر ۶۰ دقیقه ایمیلی دریافت نشد هشدار بسازید
- برای زیر نظر گرفتن کارهای دسته‌ای یا وظیفه‌های زمان‌بندی‌شده‌ای که ایمیل تکمیل می‌فرستند مفید است

## رفع اشکال

### ایمیل‌ها دریافت نمی‌شوند

1. **انتشار DNS را بررسی کنید:**

   ```bash
   dig MX inbound.yourdomain.com
   ```

   باید `mx.sendgrid.net` برگرداند

2. **تنظیمات SendGrid Inbound Parse را تأیید کنید:**

   - به داشبورد SendGrid وارد شوید
   - به Settings > Inbound Parse بروید
   - تأیید کنید دامنه و نشانی وب‌هوکتان درست‌اند

3. **گزارش‌های OneUptime را بررسی کنید:**
   - در گزارش‌های سرویس ProbeIngest دنبال درخواست‌های وب‌هوک بگردید
   - هر پیام خطایی را بررسی کنید

### وب‌هوک‌ها شکست می‌خورند

1. **مطمئن شوید OneUptime عمومی دست‌یافتنی است:**

   - نشانی وب‌هوک باید از اینترنت دست‌یافتنی باشد
   - با این آزمایش کنید: `curl -X POST https://your-oneuptime-domain.com/incoming-email/sendgrid`

2. **قواعد دیوار آتش را بررسی کنید:**

   - ترافیک HTTPS ورودی از محدوده‌های IP در SendGrid را مجاز کنید

3. **گواهی SSL را تأیید کنید:**
   - ‏SendGrid به گواهی SSL معتبر نیاز دارد
   - گواهی‌های خودامضا ممکن است مشکل بسازند

### مانیتور هشدار نمی‌سازد

1. **پیکربندی معیارها را تأیید کنید:**

   - بررسی کنید معیارهای ساخت هشدارتان با محتوای ایمیل بخوانند
   - پیش از استفاده از تطبیق الگو، نخست با رشته‌های دقیق آزمایش کنید

2. **وضعیت مانیتور را بررسی کنید:**

   - مطمئن شوید مانیتور غیرفعال نباشد
   - تأیید کنید نوع مانیتور «Incoming Email» باشد

3. **‏Monitor Summary را مرور کنید:**
   - بررسی کنید ایمیل دریافت و پردازش شده باشد
   - گزارش‌های ارزیابی را برای جزئیات تطبیق معیارها مرور کنید

### گزارش‌های تحویل وب‌هوک در SendGrid

برای بررسی اینکه SendGrid وب‌هوک‌ها را با موفقیت می‌فرستد یا نه:

1. متأسفانه SendGrid گزارش تفصیلی برای Inbound Parse ارائه نمی‌دهد
2. گزارش‌های کارساز OneUptime خود را برای درخواست‌های وب‌هوک ورودی بررسی کنید
3. برای آزمایش موقت تحویل وب‌هوک از ابزاری مانند [RequestBin](https://requestbin.com) استفاده کنید

## بهترین شیوه‌های امنیتی

1. **از HTTPS استفاده کنید:** همیشه برای نقطه پایانی وب‌هوکتان HTTPS به کار ببرید
2. **راز وب‌هوک:** مقدار `INBOUND_EMAIL_WEBHOOK_SECRET` را پیکربندی کنید و برای اعتبارسنجی بیشتر آن را در نشانی وب‌هوکتان بگنجانید (برای نمونه `/incoming-email/sendgrid/your-secret`)
3. **تأیید دامنه:** برای امنیت ایمیل بهتر، دامنه‌تان را در SendGrid تأیید کنید
4. **محدود کردن دسترسی:** فقط برای منابع ایمیل مورد اعتماد مانیتور بسازید
5. **پایش گزارش‌ها:** گزارش‌های ایمیل ورودی را مرتب برای فعالیت مشکوک مرور کنید

## ارائه‌دهندگان جایگزین

‏OneUptime طوری طراحی شده که از چند ارائه‌دهنده ایمیل ورودی پشتیبانی کند. در حال حاضر پشتیبانی‌شده:

| ارائه‌دهنده | وضعیت |
| -------------------- | --------- |
| SendGrid | پشتیبانی‌شده |
| Haraka (خودمیزبان) | برنامه‌ریزی‌شده |

اگر به پشتیبانی از ارائه‌دهنده دیگری نیاز دارید، لطفاً با ما تماس بگیرید یا درخواست قابلیت ثبت کنید.

## پشتیبانی

اگر با یکپارچه‌سازی ایمیل ورودی SendGrid به مشکل خوردید:

1. بخش رفع اشکال بالا را بررسی کنید
2. گزارش‌های OneUptime را برای پیام‌های خطای تفصیلی مرور کنید
3. با [hello@oneuptime.com](mailto:hello@oneuptime.com) تماس بگیرید
