# نقشه‌های منبع

## نمای کلی

بسته‌های فرانت‌اند تولیدی کوچک‌سازی می‌شوند، پس استثنایی که با SDK وب OpenTelemetry از مرورگر ثبت می‌شود با قاب‌های پشته‌ای مانند این می‌رسد:

```
TypeError: Cannot read properties of undefined (reading 'id')
    at e.onSelect (https://app.example.com/assets/main.a8f1b2.js:1:48291)
```

نقشه‌های منبع ساختتان را در OneUptime بارگذاری کنید و داشبورد Exceptions آن قاب‌ها را به فایل، خط و نام تابع اصلی برمی‌گرداند — و وقتی نقشه با `sourcesContent` ساخته شده باشد، خط‌های پیرامون منبع اصلی‌تان را هم.

نقشه‌ها از راه APIای احراز شده در OneUptime بارگذاری می‌شوند و **هرگز از سایت شما گرفته نمی‌شوند**، پس می‌توانید (و باید) همچنان با `hidden-source-map` (وب‌پک) یا `sourcemap: 'hidden'` (Vite / Rollup) بسازید و هرگز فایل‌های `.map` را کنار بسته‌هایتان منتشر نکنید.

## تطبیق چگونه کار می‌کند

نقشه منبع در برابر سه کلید ذخیره می‌شود:

| کلید | باید بخواند با |
|---|---|
| نام سرویس | ویژگی منبع `service.name` در OpenTelemetry که برنامه وب شما تله‌متری را با آن می‌فرستد |
| نسخه سرویس | ویژگی منبع `service.version` (شناسه انتشار شما) |
| مسیر بسته | فایل کوچک‌شده‌ای که نقشه برایش تولید شده، برای نمونه `main.a8f1b2.js` |

وقتی استثنایی را باز می‌کنید، OneUptime نقشه‌های بارگذاری‌شده برای سرویس و انتشار آن استثنا را جستجو می‌کند، هر قاب پشته را با نام فایل به بسته‌ای تطبیق می‌دهد (پسوند مسیر مشکلی ندارد — `main.a8f1b2.js` با `https://app.example.com/assets/main.a8f1b2.js` می‌خواند)، و خط و ستون کوچک‌شده را از راه نقشه تفکیک می‌کند. تفکیک هنگام دیده شدن استثنا و تنبل رخ می‌دهد، هرگز روی مسیر دریافت — پس نقشه‌ای که چند دقیقه *پس از* نخستین خطای انتشاری تازه بارگذاری شود همچنان به‌گذشته اعمال می‌شود.

یعنی برنامه وب شما باید `service.version` را با تله‌متری‌اش بفرستد:

```javascript
import { Resource } from "@opentelemetry/resources";

const resource = new Resource({
  "service.name": "my-web-app",
  "service.version": "1.4.2", // same value you upload maps with
});
```

هر شناسه پایدار انتشاری کار می‌کند — نسخه‌ای معنایی، یک SHA کامیت گیت، شماره ساخت — تا وقتی `serviceVersion` بارگذاری‌شده و ویژگی منبع `service.version` همان رشته باشند.

## بارگذاری نقشه‌های منبع

پس از هر ساخت تولیدی از CI بارگذاری کنید، با استفاده از یک **کلید دریافت تله‌متری** (_Project Settings → Telemetry Ingestion Keys_) برای احراز هویت:

```bash
curl --fail -X POST "https://oneuptime.com/source-maps/v1/upload" \
  -H "x-oneuptime-token: YOUR_TELEMETRY_INGESTION_KEY" \
  -F "serviceName=my-web-app" \
  -F "serviceVersion=1.4.2" \
  -F "sourcemap=@dist/assets/main.a8f1b2.js.map" \
  -F "sourcemap=@dist/assets/vendor.9c3d4e.js.map"
```

برای نصب‌های خودمیزبان، به‌جای `oneuptime.com` میزبان OneUptime خود را بگذارید. هدر `Authorization: Bearer YOUR_KEY` به‌عنوان جایگزین `x-oneuptime-token` پذیرفته می‌شود.

جزئیات:

- مسیر بسته هر فایل بارگذاری‌شده نام فایلش با `.map` پایانی حذف‌شده است — `main.a8f1b2.js.map` به `main.a8f1b2.js` تبدیل می‌شود. اگر نام فایل نقشه شما این قرارداد را دنبال نمی‌کند، به ازای هر درخواست یک فایل بارگذاری کنید و فیلد صریح `bundlePath` بدهید.
- بارگذاری دوباره همان بسته برای همان سرویس و نسخه، نقشه پیشین را جایگزین می‌کند، پس تلاش دوباره CI امن است.
- فایل‌ها باید JSON از نوع [source map v3](https://tc39.es/ecma426/) باشند (که همان چیزی است که هر بسته‌ساز امروزی منتشر می‌کند — نقشه‌های نمایه‌دار با `sections` هم پشتیبانی می‌شوند).
- محدودیت‌ها: هر فایل `.map` می‌تواند تا ۵۰ مگابایت باشد، اما ingress **کل بدنه درخواست** را هم روی ۵۰ مگابایت سقف می‌گذارد — پس نقشه‌های بزرگ را به ازای هر درخواست یکی بارگذاری کنید. به ازای هر درخواست تا ۵۰ فایل پذیرفته می‌شود، و یک انتشار (سرویس + نسخه) می‌تواند در مجموع حداکثر ۱۰۰۰ نقشه نگه دارد؛ بارگذاری‌ای که از آن بگذرد با پیامی که محدودیت را نام می‌برد رد می‌شود. ساختی که نقشه‌های بیشتری از آنچه یک درخواست می‌پذیرد منتشر می‌کند باید صرفاً چند درخواست بفرستد — بارگذاری‌های همان انتشار انباشته می‌شوند.
- نصب‌های خودمیزبان می‌توانند این‌ها را تغییر دهند. هر پنج تا متغیر محیطی معمولی‌اند، و نمودار Helm آن‌ها را زیر `sourceMaps` در `values.yaml` در معرض می‌گذارد:

  | `values.yaml` | متغیر محیطی | پیش‌فرض |
  | --- | --- | --- |
  | `sourceMaps.maxMapsPerRelease` | `SOURCE_MAP_MAX_MAPS_PER_RELEASE` | `1000` |
  | `sourceMaps.maxFilesPerRequest` | `SOURCE_MAP_MAX_FILES_PER_REQUEST` | `50` |
  | `sourceMaps.maxFileSizeBytes` | `SOURCE_MAP_MAX_FILE_SIZE_BYTES` | `52428800` |
  | `sourceMaps.maxBytesPerResolve` | `SOURCE_MAP_MAX_BYTES_PER_RESOLVE` | `536870912` |
  | `sourceMaps.retentionDays` | `SOURCE_MAP_RETENTION_DAYS` | `90` |

  اگر ساختتان از پیش‌فرض بزرگ‌تر شد، `maxMapsPerRelease` همان چیزی است که باید بالا ببرید؛ محدودیتی درباره شکل ذخیره‌سازی است و نه بیشتر، چون تفکیک را `maxBytesPerResolve` کران‌دار می‌کند نه شمار نقشه‌های یک انتشار. مقادیر `maxFilesPerRequest` و `maxFileSizeBytes` را فقط می‌توان **پایین آورد** — بدنه چندبخشی پیش از احراز هویت درخواست تفکیک می‌شود، پس سقف‌های مشترک بالای آن‌ها همان چیزی است که فراخوان احراز نشده به آن پایبند است، و مقدار بزرگ‌تر به‌جای اعمال شدن تنگ می‌شود.
- با گنجاندن `sourcesContent` بسازید (پیش‌فرض بیشتر بسته‌سازها) تا در داشبورد پیرامون هر قاب تفکیک‌شده، قطعه‌های منبع اصلی بگیرید.
- اگر اپراتور خودمیزبان شما دریافت تله‌متری را غیرفعال کرده باشد (`DISABLE_TELEMETRY_INGESTION`)، بارگذاری‌ها پاسخ موفق خالی برمی‌گردانند و چیزی ذخیره نمی‌شود — همان رفتاری که هر نقطه پایانی دریافت تله‌متری در آن حالت دارد. بارگذاری موفق همیشه بدنه‌ای JSON با فهرست نقشه‌های ذخیره‌شده برمی‌گرداند، پس CI می‌تواند بر آن ادعا بگذارد.

گام معمول CI هر نقشه‌ای را که ساخت منتشر کرده بارگذاری می‌کند:

```bash
VERSION="$(git rev-parse --short HEAD)"

find dist -name "*.js.map" -print0 | while IFS= read -r -d '' map; do
  curl --fail -X POST "https://oneuptime.com/source-maps/v1/upload" \
    -H "x-oneuptime-token: $ONEUPTIME_INGESTION_KEY" \
    -F "serviceName=my-web-app" \
    -F "serviceVersion=$VERSION" \
    -F "sourcemap=@$map"
done
```

## دیدن ردیابی پشته تفکیک‌شده

هر استثنایی را زیر **Exceptions** در داشبورد باز کنید. قاب‌هایی که از راه نقشه منبع تفکیک شده‌اند نشان **MAPPED** دارند و نام تابع و مکان فایل اصلی را نشان می‌دهند؛ گستراندن یک قاب، قطعه منبع اصلی را (وقتی نقشه `sourcesContent` را حمل کند) در کنار مکان کوچک‌شده نشان می‌دهد.

نقشه‌های بارگذاری‌شده یک سرویس را می‌توان زیر **Resources → Services → سرویس شما → Source Maps** مرور و حذف کرد.

## نگهداشت

نقشه‌های منبع ۹۰ روز پس از بارگذاری نگه داشته می‌شوند، سپس خودکار حذف می‌شوند. نقشه فقط تا وقتی مفید است که استثناهای انتشارش درون پنجره نگهداشت تله‌متری شما باشند، پس این با فاصله بیش از استثناهایی که بازمی‌گشایدشان عمر می‌کند. اگر دوباره لازمشان دارید، نقشه‌های آن انتشار را دوباره بارگذاری کنید.

## امنیت

- نقشه‌ها از راه نقطه پایانی احراز شده بارگذاری و در پروژه OneUptime شما ذخیره می‌شوند — هرگز از وب‌سایت شما گرفته نمی‌شوند، پس نقشه‌های منبع پنهان پنهان می‌مانند.
- محتوای خام نقشه (که وقتی با `sourcesContent` ساخته شود منبع اصلی شما را دربر دارد) فقط برای مالکان و مدیران پروژه قابل بازخواندن است. دیگر اعضای تیم صرفاً قاب‌های تفکیک‌شده و چند خط منبع پیرامون هر محل فروریزی استثناهایی را می‌بینند که از پیش به آن‌ها دسترسی دارند.
- حذف سرویسی نقشه‌های منبعش را حذف می‌کند.
