# مؤلفه‌ها

مؤلفه‌ها بلوک‌های سازنده‌ای هستند که پس از تریگر اضافه می‌کنید. هرکدام یک کار انجام می‌دهد — فرستادن پیام، فراخوانی API، بررسی یک شرط — و به هر چه بعد می‌آید وصل می‌شود.

این صفحه فهرست است. برای نحوه افزودن و وصل کردنشان روی بوم، [نوشتن یک گردش کاری](/docs/workflows/authoring) را ببینید.

## API

درخواستی HTTP به هر نشانی‌ای بفرستید.

**تنظیمات**:

- **Method** — ‏`GET`، `POST`، `PUT`، `PATCH` یا `DELETE`.
- **URL** — نشانی‌ای که فرا خوانده می‌شود.
- **Headers** — هر هدری که فرستاده می‌شود.
- **Body** — بدنه درخواست برای `POST` / `PUT` / `PATCH`.

**خروجی‌ها**:

- **Success** — وقتی شلیک می‌کند که فراخوان کار کرده باشد (پاسخ ۲xx). وضعیت، هدرها و بدنه را عبور می‌دهد.
- **Error** — بر شکست شبکه یا پاسخ غیر ۲xx شلیک می‌کند. پیام خطا را عبور می‌دهد.

از این برای این‌ها استفاده کنید: هر API بیرونی، نقطه‌های پایانی مدیریتی خودتان، یا هر یکپارچه‌سازی‌ای که مؤلفه اختصاصی ندارد.

## هوش مصنوعی

### تولید متن با هوش مصنوعی

از یک اعلان و زمینه اختیاری JSON، یک پاسخ متنی تولید کنید. مؤلفه از ارائه‌دهنده LLM پیش‌فرض پیکربندی‌شده پروژه استفاده می‌کند و در صورت وجود، به ارائه‌دهنده سراسری نصب بازمی‌گردد. اعتبارنامه‌ها و نقطه‌های پایانی ارائه‌دهنده متمرکز پیکربندی می‌شوند؛ آرگومان گردش کاری نیستند.

**تنظیمات**:

- **System Instructions** — راهنمای اختیاری برای نقش، لحن و محدودیت‌های مدل.
- **Prompt** — وظیفه الزامی. می‌تواند متغیرهای گردش کاری و خروجی مؤلفه‌های پیشین را دربر داشته باشد.
- **Context** — ‏JSON اختیاری که عمداً همراه درخواست می‌گنجانید. پس از نشانگر صریح پایان اعتماد پیام افزوده می‌شود و در باقی پیام به‌عنوان داده غیرقابل‌اعتماد رفتار می‌شود.
- **Temperature** — تنوع از `0` تا `1`. پیش‌فرض `0.2` برای خودکارسازی قابل پیش‌بینی است.
- **Maximum Output Tokens** — از `1` تا `4096`. پیش‌فرض `1024` است.

مجموع System Instructions، Prompt و Context سریال‌شده به ۵۰٬۰۰۰ نویسه محدود است. درخواست ارائه‌دهنده بیشینه ۶۰ ثانیه طول می‌کشد و یک بار تلاش می‌شود. به ازای هر پروژه حداکثر سه درخواست هوش مصنوعی گردش کاری می‌توانند هم‌زمان اجرا شوند.

**خروجی‌ها**:

- **Response** — متن تولیدشده.
- **Provider** و **Model** — پیکربندی به‌کاررفته برای فراخوان.
- **Total Tokens** و **Completion Tokens** — مصرف گزارش‌شده توسط ارائه‌دهنده.
- **LLM Log ID** — مدخل گزارش اندازه‌گیری‌شده هوش مصنوعی برای این فراخوان.
- **Error** — خطای اعتبارسنجی، دسترسی، ارائه‌دهنده، بودجه، صورت‌حساب یا اتمام مهلت، در صورت وجود.

خروجی **Success** را به مؤلفه‌هایی وصل کنید که باید پاسخ را به کار ببرند. خروجی **Error** را به مسیر صریح پشتیبان، هشدار یا گزارش وصل کنید. مؤلفه یک درخواست به مدل می‌فرستد، بدون تعریف ابزار یا فیلدهای قابلیت بومی ارائه‌دهنده: خودش نمی‌تواند از OneUptime پرس‌وجو کند، API فرا بخواند یا داده پروژه را تغییر دهد. جدا از دستورهای ثابت ایمنی مؤلفه در OneUptime، فقط System Instructions، Prompt و Contextای که پیکربندی می‌کنید — پس از تفکیک متغیرهای گردش کاری در آن فیلدها — به ارائه‌دهنده فرستاده می‌شوند. ارائه‌دهنده/مدل پیکربندی‌شده همچنان مرزی از اعتماد است، چون یک مدل می‌تواند قابلیت‌های ذاتی و مدیریت‌شده توسط ارائه‌دهنده داشته باشد.

خروجی مدل متنی غیرقابل‌اعتماد است. پیش از فرستادن ارتباط‌های رو به مشتری بازبینی‌اش کنید، و متن آزاد هوش مصنوعی را به‌تنهایی برای مجاز کردن کنش‌های ویرانگر گردش کاری به کار نبرید. برای جزئیات ارائه‌دهنده، خروج ترافیک، گزارش‌گیری و هزینه، [پیکربندی و ایمنی](/docs/workflows/configuration) را ببینید.

## وب‌هوک (خروجی)

نسخه ساده‌تر مؤلفه API برای حالت‌های «شلیک کن و فراموش». بدنه‌ای JSON را به یک نشانی POST می‌کند.

اگر لازم است پاسخ را بخوانید از **API** استفاده کنید. اگر فقط می‌خواهید اعلانی بفرستید و بگذرید از **Webhook** استفاده کنید.

## Slack

پیامی به کانالی در Slack بفرستید.

**تنظیمات**:

- **Channel** — نام کانال. ربات باید از پیش در آن کانال باشد.
- **Message** — متنی که فرستاده می‌شود. از قالب‌بندی Slack پشتیبانی می‌کند.

نخست Slack را زیر **Project Settings → Workspace → Slack** به پروژه‌تان وصل کنید. [اتصال فضای کاری Slack](/docs/workspace-connections/slack) را ببینید.

## Microsoft Teams

پیامی به کانالی در Microsoft Teams بفرستید.

**تنظیمات**:

- **Team and channel** — جایی که پیام فرستاده می‌شود.
- **Message** — متنی که فرستاده می‌شود.

برای راه‌اندازی [اتصال فضای کاری Microsoft Teams](/docs/workspace-connections/microsoft-teams) را ببینید.

## Discord

از راه نشانی وب‌هوک ورودی، پیامی به کانالی در Discord بفرستید.

## Telegram

با استفاده از توکن ربات و شناسه گفت‌وگو، پیامی به گفت‌وگویی در Telegram بفرستید.

## ایمیل

از راه OneUptime ایمیلی بفرستید.

**تنظیمات**:

- **To** — نشانی ایمیل گیرنده.
- **Subject** — خط موضوع.
- **Body** — پیام در قالب Markdown یا HTML.

ایمیل از فرستنده پیکربندی‌شده پروژه شما بیرون می‌رود — [SMTP](/docs/emails/smtp) را ببینید.

## کد سفارشی

وقتی چیزی لازم دارید که بلوک‌های دیگر نمی‌توانند انجامش دهند، قطعه کوچکی از JavaScript اجرا کنید.

**تنظیمات**:

- **Code** — ‏JavaScript شما. آخرین مقدار (یا آنچه از یک تابع ناهمگام برمی‌گردانید) به خروجی بلوک تبدیل می‌شود.
- **Arguments** — مقادیر نام‌داری که می‌توانید به درون بدهید.

**خروجی‌ها**: موفقیت (مقدار بازگشتی شما) و خطا (هر استثنایی).

از این برای این‌ها استفاده کنید: بازشکل دادن داده میان دو سامانه، انجام محاسبه‌ای کوچک، هر چیزی که سزاوار بلوک اختصاصی خودش نیست. برای اسکریپت‌نویسی سنگین‌تر، به‌جایش از یک [رانبوک](/docs/runbooks/index) استفاده کنید.

## JSON

میان متن و JSON تبدیل کنید.

- **JSON → Text** — شیئی JSON را به رشته تبدیل کنید. وقتی بلوک بعدی متن انتظار دارد مفید است.
- **Text → JSON** — رشته‌ای را به شیء JSON تفکیک کنید. وقتی چیزی به‌صورت متن رسیده و لازم است فیلدی را بخوانید مفید است.

## شرط‌ها

بر پایه یک مقایسه شاخه بزنید. در پنل **Add Component** این بلوک زیر دسته Conditions با نام **If / Else** آمده است.

**تنظیمات**:

- **Left value** — معمولاً مقداری از بلوکی پیشین.
- **Operator** — ‏`==`، `!=`، `>`، `>=`، `<`، `<=`، `contains`، `starts with`، `ends with`.
- **Right value** — چیزی که با آن مقایسه می‌شود.

**خروجی‌ها**: **Yes** و **No**. بلوک‌های بعدی را به هر شاخه‌ای که می‌خواهید وصل کنید.

## تأخیر

پیش از ادامه، گردش کاری را برای مدتی مشخص مکث کنید. وقتی لازم است به سامانه‌ای دیگر لحظه‌ای فرصت بدهید تا برسد مفید است.

## گزارش

خطی در گزارش اجرا بنویسید. اثر بیرونی ندارد — فقط در گزارش‌های گردش کاری پدیدار می‌شود تا بخوانیدش. برای اشکال‌زدایی به‌کار می‌آید.

## اجرای گردش کاری

از این گردش کاری، گردش کاری دیگری را فرا بخوانید. گردش کاری فراخوانده‌شده به‌طور مستقل اجرا می‌شود — گردش کاری شما بدون انتظار برای پایانش ادامه می‌دهد.

از این برای اشتراک منطق مشترک استفاده کنید. گردش کاری «ارسال به کانال حادثه» را یک بار بسازید، سپس از هر گردش کاری دیگری که باید به کانال خبر دهد فرا بخوانیدش.

محدودیتی ایمنی هست تا گردش‌های کاری نتوانند در حلقه یکدیگر را فرا بخوانند. [پیکربندی و ایمنی](/docs/workflows/configuration) را ببینید.

## مؤلفه‌های داده OneUptime

برای هر نوع رکورد در OneUptime (مانیتورها، حادثه‌ها، هشدارها، صفحه‌های وضعیت، سیاست‌های کشیک و بسیاری دیگر)، پنل **Add Component** این مؤلفه‌ها را دارد — با نام نوع جستجو کنید. هر عنوان از نوع رکورد تولید می‌شود، پس مجموعه Monitor چنین خوانده می‌شود:

- **Find One Monitor** — خواندن یک رکورد که با پرس‌وجو می‌خواند.
- **Find Many Monitors** — خواندن فهرستی از رکوردهایی که با پرس‌وجو می‌خوانند.
- **Create One Monitor** — افزودن یک رکورد از یک شیء JSON.
- **Create Many Monitors** — افزودن چند رکورد از یک آرایه JSON.
- **Update One Monitor** — اعمال محموله نوشتن روی یک رکورد مطابق.
- **Update Many Monitors** — اعمال محموله نوشتن روی رکوردهای مطابق، تا سقف Limit.
- **Delete One Monitor** — حذف یک رکورد مطابق.
- **Delete Many Monitors** — حذف رکوردهای مطابق، تا سقف Limit.

همین مجموعه سه تریگر هم به شما می‌دهد — **On Create Monitor**، **On Update Monitor** و **On Delete Monitor**. [تریگرها](/docs/workflows/triggers) را ببینید.

هر نوع فقط مؤلفه‌هایی را ارائه می‌دهد که مدلش اجازه می‌دهد. نوعی فقط‌خواندنی دو مؤلفه Find دارد و بس، پس اگر **Delete One Monitor** را در پنل نیافتید، آن نوع اجازه‌اش را نمی‌دهد.

این‌گونه است که گردش کاری می‌تواند داده OneUptime را بخواند و تغییر دهد. برای نمونه: وب‌هوکی از ابزار CI شما می‌تواند با **Create One Incident** حادثه‌ای با جزئیات شکست باز کند.

## کار با رکوردها

هر فیلد روی یک مؤلفه داده بر پایه نام **ستون‌های** خود رکورد کلید می‌خورد — همان نام‌هایی که API به کار می‌برد، نه برچسب‌های فرم داشبورد. ستون شناسه `_id` است. املای `id` هر جا که بتوانید نام ستونی تایپ کنید به‌عنوان نام مستعار پذیرفته می‌شود، اما `_id` چیزی است که رکورد پس می‌دهد، پس همان چیزی است که در راه خروج باید بخوانید:

```json
{ "_id": "00000000-0000-0000-0000-000000000000" }
```

**Query** تصمیم می‌گیرد مؤلفه روی کدام رکوردها عمل کند. کلیدها ستون‌اند و مقادیر چیزی که باید بخواند:

```json
{ "monitorType": "Website", "isEnabled": true }
```

پرس‌وجو همیشه به پروژه‌ای که گردش کاری در آن اجرا می‌شود محدود است. نمی‌توانید به رکوردهای پروژه‌ای دیگر برسید، و لازم نیست خودتان پروژه را به پرس‌وجو بیفزایید.

فیلدهای **JSON Object** روی Create One، **JSON Array** روی Create Many و **Data (JSON Object)** روی مؤلفه‌های Update، فیلدهایی را که باید نوشته شوند حمل می‌کنند، با همان کلیدگذاری:

```json
{ "name": "Checkout API", "monitorType": "Website" }
```

کلیدی که ستون نباشد به‌جای رد شدن نادیده گرفته می‌شود — گزارش اجرا نام آن‌هایی را که کنار گذاشته می‌آورد، پس وقتی فیلدی نمی‌نشیند آنجا را بررسی کنید. فیلد **Select Fields**، روی مؤلفه‌های Find و تریگرها، همان کلیدهای ستون را با مقادیر `true` به کار می‌برد: `{"_id": true, "name": true}`.

**Skip** و **Limit** دو فیلد عددی روی Find Many، Update Many و Delete Many هستند — ‏`Skip: 0` با `Limit: 100` صد تطبیق نخست را می‌گیرد. پیش‌فرض Limit برابر `10` است، و روی Update Many و Delete Many سقف می‌گذارد که واقعاً چند رکورد نوشته شوند، نه فقط چند تا برگردند. پس `Items Deleted: 10` یعنی ده رکورد حذف شدند، نه اینکه ده تا مطابقت کردند. وقتی قصد دارید بیش از ده تا را تغییر دهید Limit را بالا ببرید.

خروجی‌های **Success** و **Error** گزارش می‌دهند که پرس‌وجو اجرا شد یا نه، نه اینکه چه یافت. پرس‌وجویی که با چیزی مطابقت نکند `0` برمی‌گرداند و همچنان از راه Success بیرون می‌رود — آن شکست نیست. برای شاخه زدن بر پایه اینکه چیزی مطابقت کرده یا نه، شمار بازگشتی را در بلوکی از نوع **If / Else** بخوانید.

## کدام مؤلفه را به کار ببرم؟

چند قاعده سریع:

- اگر برای آنچه می‌خواهید بلوکی اختصاصی هست (Slack، ایمیل، رکوردی از OneUptime)، همان را به کار ببرید — مدیریت خطای بهتر و گزارش‌های روشن‌تری می‌گیرید.
- برای هر API بیرونی دیگری، از **API** استفاده کنید.
- برای خلاصه کردن، دسته‌بندی یا پیش‌نویس کردن متن از داده‌ای که صریح از گردش کاری برگزیده‌اید، از **Generate Text with AI** استفاده کنید.
- برای بازشکل دادن داده میان بلوک‌ها، از **Custom Code** یا **JSON** استفاده کنید.
- برای انجام کنش‌های متفاوت بر پایه یک مقدار، از **Conditions** استفاده کنید.
