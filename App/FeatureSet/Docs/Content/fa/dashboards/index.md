# نمای کلی داشبوردها

داشبوردها داده‌ای را که OneUptime از پیش جمع می‌کند — متریک‌ها، لاگ‌ها، ترِیس‌ها، حوادث، مانیتورها، منابع Kubernetes، میزبان‌ها — به یک صفحه واحد تبدیل می‌کنند که با یک نگاه می‌شود فهمید چه خبر است.

نموداری از تأخیر درخواست را کنار فهرستی از حوادث باز بگذارید، کنار یک گِیج برای پردازنده، کنار یک پاراگراف بافتار. ذخیره‌اش کنید. پیوند را به اشتراک بگذارید.

## داشبوردها به چه دردی می‌خورند

- **یک صفحه «همه‌چیز خوب است؟»** — برای آنکال، جلسه روزانه تیم یا یک تلویزیون دیواری.
- **دیدن پیوندها** — دیدن جهش پردازنده هم‌زمان با افزایش تأخیر و یک حادثه باز، در یک صفحه بسیار آسان‌تر از سه زبانه مرورگر است.
- **بررسی** — وقتی در حال عیب‌یابی هستید، داشبوردی که در لحظه می‌سازید از اجرای ده کوئری پشت سر هم بهتر است.
- **اشتراک‌گذاری بیرونی** — صفحه کارایی رو به مشتری، صفحه وضعیت شریک، داشبورد عمومی برای یک پروژه متن‌باز.

## چه چیزهایی می‌توانید روی داشبورد بگذارید

- **نمودارها** برای روندها در طول زمان — تأخیر، خطاها، توان عبوری و حجم لاگ.
- **کاشی‌های تک‌مقداری و گِیج‌ها** — نرخ خطای فعلی، پردازنده، حوادث باز.
- **جدول‌ها** برای تفکیک‌ها — ۱۰ میزبان پرنوفه برتر، تعداد خطا به ازای هر سرویس.
- **بلوک‌های متنی** برای سرصفحه، بافتار و پیوند به رانبوک‌ها.
- **فهرست‌های زنده** از حوادث، هشدارها، مانیتورها، لاگ‌ها، ترِیس‌ها، منابع Kubernetes، منابع Docker و میزبان‌ها.

برای فهرست کامل و اینکه هر کدام چه چیزی نشان می‌دهند، [ویجت‌ها](/docs/dashboards/widgets) را ببینید.

## اصطلاح‌های کلیدی

| اصطلاح         | یعنی چه                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------- |
| **داشبورد**    | کل صفحه — یک نام، یک شبکه از ویجت‌ها، کنترل‌های بازه زمانی و فهرستی از متغیرها.                     |
| **ویجت**       | یک کاشی روی صفحه — یک نمودار، یک عدد، یک فهرست، یک پاراگراف.                                        |
| **متغیر**      | یک فهرست کشویی بالای صفحه که همه ویجت‌ها را یک‌جا فیلتر می‌کند (خوشه، سرویس، مشتری، محیط).          |
| **بازه زمانی** | پنجره زمانی‌ای که هر نمودار و عدد از آن استفاده می‌کند. یک بار بالای صفحه تنظیمش کنید.               |
| **تازه‌سازی**  | اینکه ویجت‌ها هر چند وقت دوباره داده را کوئری کنند. خاموش، هر چند ثانیه، هر چند دقیقه.               |
| **حالت**       | یا **Edit** (جابه‌جایی ویجت‌ها) یا **View** (فقط‌خواندنی، همان‌طور که بازدیدکنندگان می‌بینند).       |

## داشبوردها را کجا پیدا کنیم

در ناوبری سمت خود، **Dashboards** را باز کنید.

| صفحه                     | آنجا چه می‌کنید                                                        |
| ------------------------ | ---------------------------------------------------------------------- |
| **Dashboards**           | فهرست داشبوردهای شما. یکی جدید بسازید، جستجو کنید یا با برچسب فیلتر کنید. |
| **Dashboard → View**     | بوم. در سربرگ میان **Edit** و **View** جابه‌جا شوید.                    |
| **Dashboard → Overview** | توضیحات، مالکان و برچسب‌ها.                                             |
| **Dashboard → Settings** | اشتراک‌گذاری عمومی، رمز عبور، فهرست مجاز IP، دامنه سفارشی، برندینگ.     |
| **Dashboard → Owners**   | کاربران و تیم‌هایی با دسترسی صریح.                                      |
| **Dashboard → Delete**   | حذف داشبورد.                                                            |

## ساخت یک داشبورد

1. **بسازید** — نامی انتخاب کنید. بوم خالی باز می‌شود.
2. **ویجت اضافه کنید** — نوع ویجت را انتخاب کنید، داده‌اش را پیکربندی کنید و آن را هرجا می‌خواهید بکشید.
3. **(اختیاری) متغیر اضافه کنید** — برای نمونه یک فهرست کشویی `service` تا همان داشبورد برای هر سرویسی کار کند.
4. **بازه زمانی را تنظیم کنید** — پیش‌فرض‌ها خوب‌اند؛ بعداً تنظیمشان کنید.
5. **(اختیاری) عمومی به اشتراک بگذارید** — کلید را در تنظیمات بزنید و در صورت نیاز رمز عبور یا فهرست مجاز IP اضافه کنید.
6. **(اختیاری) دامنه سفارشی** — داشبورد را روی `status.your-domain.com` میزبانی کنید.

## یک نمونه سریع

هدف: یک صفحه آنکال برای سرویس پرداخت نهایی با تأخیر، نرخ خطا، حوادث باز و دنبال کردن زنده لاگ.

1. داشبوردی با نام «آنکال پرداخت نهایی» بسازید.
2. یک متغیر `service` اضافه کنید. پیش‌فرضش را `checkout` بگذارید.
3. یک ویجت **Chart** با تأخیر P95 اضافه کنید که با متغیر `service` فیلتر شده باشد.
4. کنارش یک ویجت **Value** برای نرخ خطا اضافه کنید، با هشدار روی ۱٪ و بحرانی روی ۵٪.
5. پایین‌تر، یک ویجت **Incident List** برای حوادث با برچسب `checkout` اضافه کنید.
6. زیر آن، یک **Log Chart** اضافه کنید تا جهش حجم و شدت لاگ را ببینید.
7. یک ویجت **Log Stream** اضافه کنید که لاگ‌های خام منطبق را نشان دهد.
8. ذخیره کنید. فهرست کشویی را روی `payments` بگذارید — حالا همان داشبورد سرویس پرداخت را نشان می‌دهد.

## داشبوردها چگونه با بقیه OneUptime جور می‌شوند

- **مانیتورها و تله‌متری** منابع داده‌اند. هر متریک، لاگ و ترِیسی که جمع می‌کنید روی یک ویجت قابل کوئری است.
- **حوادث و هشدارها** در ویجت‌های **Incident List** و **Alert List** ظاهر می‌شوند. داشبوردها برای این‌ها فقط‌خواندنی‌اند — ساخت و به‌روزرسانی آن‌ها جای دیگری انجام می‌شود.
- **صفحات وضعیت** ارتباط رو به مشتری هستند («آیا سامانه در دسترس است؟»). داشبوردها برای نگاه دقیق به رفتار سامانه‌اند. این دو با هم کار می‌کنند و جایگزین یکدیگر نیستند.
- **گردش‌های کاری** جایی هستند که OneUptime اقدام می‌کند. داشبوردها جایی هستند که شما می‌خوانید چه خبر است.
