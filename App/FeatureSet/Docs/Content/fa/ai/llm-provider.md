# ارائه‌دهندگان LLM

‏OneUptime از یکپارچه‌سازی با ارائه‌دهندگان گوناگون مدل زبانی بزرگ (LLM) پشتیبانی می‌کند تا قابلیت‌های مبتنی بر هوش مصنوعی را در سراسر پلتفرم فعال کند. این راهنما به شما کمک می‌کند ارائه‌دهنده LLM خودتان را پیکربندی کنید.

## ارائه‌دهندگان LLM چه می‌توانند بکنند؟

ارائه‌دهندگان LLM در OneUptime به شما کمک می‌کنند گردش کار مدیریت حادثه‌تان را خودکار و تقویت کنید:

- **بررسی‌های خودگردان**: حادثه‌ها و هشدارهای تازه را خودکار بررسی می‌کنند و تحلیل ریشه علتی با استناد روی خط زمانی منتشر می‌کنند — [AI SRE](/docs/ai/ai-sre) را ببینید
- **یادداشت‌های حادثه**: یادداشت‌ها و به‌روزرسانی‌های تفصیلی حادثه را خودکار تولید می‌کنند
- **یادداشت‌های هشدار**: توضیحات و زمینه معنادار برای هشدارها می‌سازند
- **یادداشت‌های نگهداری زمان‌بندی‌شده**: یادداشت رویدادهای نگهداری را خودکار تولید می‌کنند
- **پس‌مرگ حادثه**: گزارش‌های جامع پس‌مرگ حادثه را خودکار پیش‌نویس می‌کنند
- **بهبود کد**: اگر مخزن کدتان را به OneUptime وصل کنید، از ارائه‌دهنده LLM شما برای تحلیل داده تله‌متری (گزارش‌ها، ردیابی‌ها، سنجه‌ها، استثناها) و پیشنهاد بهبود کد استفاده می‌کنیم

## کاربران SaaS در OneUptime

اگر از **‏OneUptime SaaS** (نسخه ابری) استفاده می‌کنید، می‌توانید به‌طور پیش‌فرض و بدون هیچ پیکربندی اضافه‌ای از **ارائه‌دهنده سراسری LLM** استفاده کنید. ارائه‌دهنده سراسری LLM از پیش پیکربندی شده و برای همه قابلیت‌های هوش مصنوعی آماده استفاده است.

اگر ترجیح می‌دهید از کلیدهای API خودتان یا ارائه‌دهنده‌ای مشخص استفاده کنید، همچنان می‌توانید با دستورالعمل زیر ارائه‌دهنده سفارشی LLM پیکربندی کنید.

## خودمیزبان: بدون پیکربندی از راه متغیرهای محیطی

روی نمونه‌ای خودمیزبان، سریع‌ترین راه فعال کردن قابلیت‌های هوش مصنوعی برای **همه پروژه‌ها یک‌جا** این است که متغیرهای محیطی `GLOBAL_LLM_PROVIDER_*` را روی کارساز OneUptime خود تنظیم کنید — در `config.env` برای Docker Compose، یا از راه مقادیر Helm. هنگام راه‌اندازی، OneUptime ارائه‌دهنده سراسری LLMای از آن‌ها ثبت می‌کند (و همگام نگهش می‌دارد)؛ به راه‌اندازی داشبوردی به ازای هر پروژه نیازی نیست، و وظیفه‌های رفع هوش مصنوعی هم وقتی پروژه‌ای ارائه‌دهنده خودش را ندارد از آن استفاده می‌کنند.

| متغیر | توضیح |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `GLOBAL_LLM_PROVIDER_TYPE` | برای فعال‌سازی الزامی است. یکی از: `OpenAI`، `AzureOpenAI`، `Anthropic`، `Groq`، `Mistral`، `Ollama`، `OpenAICompatible` |
| `GLOBAL_LLM_PROVIDER_API_KEY` | کلید API — برای OpenAI، ‏Azure OpenAI، ‏Anthropic، ‏Groq و Mistral الزامی است؛ برای Ollama یا کارسازهای سازگار با OpenAI بدون کلید لازم نیست |
| `GLOBAL_LLM_PROVIDER_BASE_URL` | نقطه پایانی API — برای Azure OpenAI، ‏Ollama و کارسازهای سازگار با OpenAI الزامی است |
| `GLOBAL_LLM_PROVIDER_MODEL_NAME` | مدلی که به کار می‌رود (برای کارسازهای سازگار با OpenAI الزامی، جاهای دیگر توصیه‌شده) |
| `GLOBAL_LLM_PROVIDER_NAME` | نام دوستانه اختیاری که در داشبورد نشان داده می‌شود |

**نمونه: Ollama محلی**

```bash
GLOBAL_LLM_PROVIDER_TYPE=Ollama
GLOBAL_LLM_PROVIDER_BASE_URL=http://your-ollama-host:11434
GLOBAL_LLM_PROVIDER_MODEL_NAME=llama3.1
# No API key needed — Ollama is keyless.
```

**نمونه: OpenAI**

```bash
GLOBAL_LLM_PROVIDER_TYPE=OpenAI
GLOBAL_LLM_PROVIDER_API_KEY=sk-xxxxxxxxxxxxxxxxxxxx
GLOBAL_LLM_PROVIDER_MODEL_NAME=gpt-5.1
```

همگام‌سازی اعلانی است: تغییر متغیرها ارائه‌دهنده را در بازراه‌اندازی بعدی به‌روزرسانی می‌کند، و برداشتن `GLOBAL_LLM_PROVIDER_TYPE` حذفش می‌کند. ارائه‌دهندگان سراسری‌ای که دستی در داشبورد مدیریت ساخته شده‌اند هرگز دست‌کاری نمی‌شوند. پروژه‌ها همچنان می‌توانند ارائه‌دهنده خودشان را زیر **Project Settings** > **AI** > **LLM Providers** بیفزایند — ارائه‌دهنده متعلق به پروژه همیشه بر ارائه‌دهنده سراسری اولویت دارد.

## ارائه‌دهندگان پشتیبانی‌شده

‏OneUptime در حال حاضر از ارائه‌دهندگان LLM زیر پشتیبانی می‌کند:

| ارائه‌دهنده | توضیح | کلید API لازم است | نشانی پایه لازم است |
| --------------------- | ---------------------------------------------------------------------------- | ---------------- | ----------------- |
| **OpenAI** | ‏GPT-5.1 و دیگر مدل‌های OpenAI | بله | خیر (پیش‌فرض را به کار می‌برد) |
| **Azure OpenAI** | مدل‌های OpenAI میزبانی‌شده روی استقرار Azure شما | بله | بله |
| **Anthropic** | ‏Claude Sonnet 5، ‏Claude Opus 5، ‏Claude Haiku 4.5 و دیگر مدل‌های Claude | بله | خیر (پیش‌فرض را به کار می‌برد) |
| **Groq** | استنتاج سریع برای Llama، ‏Mixtral و دیگر مدل‌های باز | بله | خیر (پیش‌فرض را به کار می‌برد) |
| **Mistral** | مدل‌های میزبانی‌شده Mistral | بله | خیر (پیش‌فرض را به کار می‌برد) |
| **Ollama** | مدل‌های متن‌باز خودمیزبان مانند Llama 3.1، ‏Mistral، ‏Qwen و غیره | خیر | بله |
| **OpenAI Compatible** | هر کارساز سازگار با OpenAI (‏vLLM، ‏LocalAI، ‏LM Studio و غیره) | خیر (اختیاری) | بله |

## برپا کردن یک ارائه‌دهنده LLM

### گام ۱: رفتن به تنظیمات ارائه‌دهندگان LLM

1. به داشبورد OneUptime خود وارد شوید
2. به **Project Settings** > **AI** > **LLM Providers** بروید
3. برای افزودن ارائه‌دهنده‌ای تازه روی **Create LLM Provider** کلیک کنید

### گام ۲: پیکربندی ارائه‌دهنده‌تان

فیلدهای زیر را پر کنید:

- **Name**: نامی دوستانه برای این پیکربندی LLM (برای نمونه «Production OpenAI»، «Local Ollama»)
- **Description** (اختیاری): توضیحی که به شناسایی هدف این ارائه‌دهنده کمک کند
- **LLM Provider**: نوع ارائه‌دهنده را برگزینید (OpenAI، ‏Azure OpenAI، ‏Anthropic، ‏Groq، ‏Mistral، ‏Ollama یا OpenAI Compatible)
- **API Key**: کلید API شما (برای OpenAI، ‏Azure OpenAI، ‏Anthropic، ‏Groq و Mistral الزامی؛ برای Ollama و کارسازهای سازگار با OpenAI اختیاری)
- **Model Name**: مدل مشخصی که به کار می‌رود (برای نمونه `gpt-5.1`، `claude-sonnet-5`، `llama3.1`)
- **Base URL** (اختیاری): نشانی سفارشی نقطه پایانی API (برای Azure OpenAI، ‏Ollama و OpenAI Compatible الزامی؛ برای بقیه اختیاری)

## پیکربندی ویژه هر ارائه‌دهنده

### OpenAI

1. کلید API خود را از [پلتفرم OpenAI](https://platform.openai.com/api-keys) بگیرید
2. ارائه‌دهنده LLM را **OpenAI** برگزینید
3. کلید API خود را وارد کنید
4. نام مدلی برگزینید:
   - `gpt-5.1` — پیش‌فرض توصیه‌شده، در فراخوانی ابزار و بررسی‌های پیچیده قوی است
   - `gpt-5.1-mini` — سریع‌تر و به‌صرفه‌تر

**نمونه پیکربندی:**

```
Name: Production OpenAI
LLM Provider: OpenAI
API Key: sk-xxxxxxxxxxxxxxxxxxxx
Model Name: gpt-5.1
```

### Anthropic

1. کلید API خود را از [کنسول Anthropic](https://console.anthropic.com/) بگیرید
2. ارائه‌دهنده LLM را **Anthropic** برگزینید
3. کلید API خود را وارد کنید
4. نام مدلی برگزینید:
   - `claude-sonnet-5` — پیش‌فرض توصیه‌شده، بهترین توازن هوش، سرعت و هزینه
   - `claude-opus-5` — تواناترین مدل، برای سخت‌ترین بررسی‌ها
   - `claude-haiku-4-5` — سریع‌ترین و به‌صرفه‌ترین

**نمونه پیکربندی:**

```
Name: Production Anthropic
LLM Provider: Anthropic
API Key: sk-ant-xxxxxxxxxxxxxxxxxxxx
Model Name: claude-sonnet-5
```

### Ollama (خودمیزبان)

‏Ollama به شما امکان می‌دهد LLMهای متن‌باز را محلی یا روی زیرساخت خودتان اجرا کنید.

1. ‏Ollama را از [ollama.ai](https://ollama.ai) نصب کنید
2. مدل دلخواهتان را بکشید: `ollama pull llama3.1`
3. مطمئن شوید Ollama در حال اجرا و دست‌یافتنی است
4. ارائه‌دهنده LLM را **Ollama** برگزینید
5. نشانی پایه را وارد کنید (برای نمونه `http://localhost:11434`)
6. نام مدلی را که کشیده‌اید وارد کنید

**نمونه پیکربندی:**

```
Name: Local Ollama
LLM Provider: Ollama
Base URL: http://localhost:11434
Model Name: llama3.1
```

**مدل‌های محبوب Ollama:**

- `llama3.1` — مدل Llama 3.1 از Meta، قدیمی‌ترین Llama با پشتیبانی از فراخوانی ابزار
- `llama3.3` — مدل Llama 3.3 از Meta
- `qwen2.5` — مدل Qwen 2.5 از Alibaba
- `mistral-nemo` — مدل Nemo از Mistral AI

> توجه: قابلیت‌های هوش مصنوعی OneUptime عامل‌محورند — به‌شدت به فراخوانی ابزار تکیه می‌کنند. از `llama3.1` یا جدیدتر (یا مدل دیگری که فراخوانی ابزار را پشتیبانی می‌کند) استفاده کنید. مدل‌های کوچک یا مدل‌های بدون پشتیبانی از فراخوانی ابزار (برای نمونه `llama2`، ‏`llama3` اصلی) نتایج بدی می‌دهند: نمی‌توانند از مانیتورها، حادثه‌ها یا تله‌متری شما پرس‌وجو کنند، پس بررسی‌ها خالی یا توهمی برمی‌گردند.

### سازگار با OpenAI (‏vLLM، ‏LocalAI، ‏LM Studio و غیره)

از ارائه‌دهنده **OpenAI Compatible** برای هر کارسازی استفاده کنید که API ‏`/chat/completions` در OpenAI را پیاده می‌کند اما خودِ OpenAI نیست — برای نمونه [vLLM](https://docs.vllm.ai)، [LocalAI](https://localai.io)، [LM Studio](https://lmstudio.ai) یا text-generation-webui. این‌ها معمولاً روی نشانی خودتان خودمیزبان‌اند و غالباً بدون احراز هویت اجرا می‌شوند.

1. کارساز سازگار با OpenAI خود را راه بیندازید و نشانی پایه‌اش را یادداشت کنید (معمولاً به `/v1` ختم می‌شود)
2. ارائه‌دهنده LLM را **OpenAI Compatible** برگزینید
3. **Base URL** را وارد کنید (الزامی)، برای نمونه `http://your-server:8000/v1`
4. **Model Name** را وارد کنید (الزامی) — باید با مدلی بخواند که کارسازتان در معرض می‌گذارد
5. **API Key** را فقط اگر کارسازتان لازمش دارد وارد کنید؛ برای کارسازهای بدون کلید خالی بگذارید

**نمونه پیکربندی (vLLM بدون کلید):**

```
Name: Self-Hosted vLLM
LLM Provider: OpenAI Compatible
Base URL: http://vllm.internal:8000/v1
Model Name: meta-llama/Llama-3.1-8B-Instruct
API Key: (leave blank)
```

> نکته: پس از ذخیره، با دکمه **Test** روی ارائه‌دهنده تأیید کنید اتصال، نام مدل و نشانی پایه درست‌اند.

### ‏vLLM خودمیزبان روی Kubernetes ‏(Helm)

اگر OneUptime را با نمودار Helm خودمیزبان می‌کنید، می‌توانید [vLLM](https://docs.vllm.ai) را — کارساز استنتاج سازگار با OpenAI — درون خوشه‌تان اجرا کنید و مدل‌های محلی را روی GPUهای خودتان سرو کنید. هیچ داده‌ای زیرساختتان را ترک نمی‌کند.

1. در مقادیر Helm خود فعالش کنید (به گره‌های GPU انویدیا نیاز دارد):

   ```yaml
   vllm:
     enabled: true
     model: Qwen/Qwen2.5-1.5B-Instruct
   ```

2. `helm upgrade` را اجرا کنید و منتظر بمانید پاد vLLM آماده شود (نخستین آغاز، مدل را دانلود می‌کند)
3. همین — vLLM هنگام راه‌اندازی به‌طور خودکار به‌عنوان ارائه‌دهنده سراسری LLM ثبت می‌شود (`vllm.globalProvider.enabled`، پیش‌فرض `true`)، پس قابلیت‌های هوش مصنوعی برای همه پروژه‌ها، از جمله وظیفه‌های رفع هوش مصنوعی، کار می‌کنند. (همه‌جا — ابری و خودمیزبان — وظیفه‌های رفع عامل وقتی پروژه ارائه‌دهنده خودش را ندارد از ارائه‌دهنده سراسری استفاده می‌کنند؛ روی ابر آن مصرف به‌صورت توکن اندازه‌گیری‌شده صورت‌حساب می‌شود. ارائه‌دهنده متعلق به پروژه همیشه اولویت دارد.)

اگر ثبت خودکار را غیرفعال کرده‌اید (`vllm.globalProvider.enabled: false`)، ارائه‌دهنده را دستی بسازید:

1. ارائه‌دهنده LLM را **OpenAI Compatible** برگزینید (vLLM با API ‏OpenAI حرف می‌زند)
2. نشانی پایه درون‌خوشه‌ای را وارد کنید: `http://<release>-vllm.<namespace>.svc.cluster.local:8000/v1`
3. نام مدل را وارد کنید: شناسه کامل مدل HuggingFace (یا `vllm.servedModelName` اگر تنظیمش کرده‌اید)
4. کلید API را فقط اگر `vllm.apiKey` را تنظیم کرده‌اید وارد کنید؛ برای vLLM بدون کلید خالی بگذارید

**نمونه پیکربندی:**

```
Name: In-Cluster vLLM
LLM Provider: OpenAI Compatible
Base URL: http://oneuptime-vllm.default.svc.cluster.local:8000/v1
Model Name: Qwen/Qwen2.5-1.5B-Instruct
API Key: (leave blank unless vllm.apiKey is set)
```

برای زمان‌بندی GPU، مدل‌های دروازه‌دار و گزینه‌های تنظیم، [README نمودار Helm](https://github.com/OneUptime/oneuptime/tree/master/HelmChart/Public/oneuptime#local-models-with-vllm) را ببینید.

## استفاده از نشانی پایه سفارشی

برای استقرارهای سازمانی یا هنگام استفاده از سرویس‌های پراکسی، می‌توانید نشانی پایه سفارشی مشخص کنید:

- **Azure OpenAI**: نشانی نقطه پایانی Azure خود را به کار ببرید
- **APIهای سازگار با OpenAI**: هر APIای که مشخصات API ‏OpenAI را دنبال می‌کند
- **نمونه‌های خصوصی Ollama**: نشانی کارساز داخلی Ollama شما

## بهترین شیوه‌ها

1. **نام‌های توصیفی به کار ببرید**: ارائه‌دهندگانتان را روشن نام‌گذاری کنید (برای نمونه «Production OpenAI»، «Development Ollama»)
2. **کلیدهای API خود را امن کنید**: کلیدهای API در حالت سکون رمزگذاری می‌شوند، اما از به اشتراک گذاشتنشان بپرهیزید
3. **پیکربندی خود را بیازمایید**: پس از برپاسازی، تأیید کنید ارائه‌دهنده با قابلیت‌های هوش مصنوعی کار می‌کند
4. **مصرف را بپایید**: برای مدیریت هزینه‌ها مصرف API را ردیابی کنید

## رفع اشکال

### مشکل‌های اتصال

- **OpenAI/Anthropic**: تأیید کنید کلید API شما معتبر است و اعتبار کافی دارد
- **Ollama**: مطمئن شوید کارساز Ollama در حال اجراست و نشانی پایه درست است
- **OpenAI Compatible**: مطمئن شوید نشانی پایه به `/v1` ختم می‌شود (یا با کارسازتان می‌خواند)، نام مدل با مدلی که کارسازتان در معرض می‌گذارد می‌خواند، و فقط اگر کارسازتان لازم دارد کلید API بگذارید
- **دیوار آتش**: بررسی کنید شبکه شما اتصال‌های خروجی به API ارائه‌دهنده را مجاز می‌کند

### مدل یافت نشد

- تأیید کنید نام مدل درست املا شده است
- برای Ollama مطمئن شوید مدل را با `ollama pull <model-name>` کشیده‌اید
- بررسی کنید مدل در ناحیه شما در دسترس باشد (برخی مدل‌ها محدودیت ناحیه‌ای دارند)
