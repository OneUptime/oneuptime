# قواعد رانبوک

قواعد رانبوک هنگام ساخت یک **حادثه**، **هشدار** یا **رویداد تعمیر و نگهداری زمان‌بندی‌شده** به‌صورت خودکار رانبوک وصل می‌کنند. این قواعد از منوی Rules هر موجودیت مدیریت می‌شوند:

- Incidents → Rules → **Runbook Rules**
- Alerts → Rules → **Runbook Rules**
- Scheduled Maintenance → Rules → **Runbook Rules**

هر سه صفحه یک مدل قاعده زیربنایی را ویرایش می‌کنند — فقط طوری فیلتر شده‌اند که تنها قواعد همان نوع موجودیت را نشان دهند.

## ساختار یک قاعده

| فیلد                    | هدف                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| **نام**                 | برچسبی کوتاه و انسانی. در گزارش‌های ممیزی نمایش داده می‌شود.                                              |
| **توضیحات**             | بافتار اختیاری برای هم‌تیمی‌ها.                                                                          |
| **فعال**                | کلیدی برای معلق کردن یک قاعده بدون حذف آن.                                                                |
| **الگوی عنوان**         | عبارت باقاعده بدون حساسیت به بزرگی حروف که با عنوان موجودیت تطبیق داده می‌شود. خالی = تطبیق با هر عنوانی. |
| **الگوی توضیحات**       | عبارت باقاعده بدون حساسیت به بزرگی حروف که با توضیحات موجودیت تطبیق داده می‌شود. خالی = تطبیق با هر توضیحی. |
| **رانبوک‌هایی که باید شروع شوند** | یک یا چند رانبوک که هنگام فعال شدن قاعده اجرا می‌شوند.                                          |

## معنای تطبیق

یک قاعده وقتی مطابقت پیدا می‌کند که **همه معیارهای مشخص‌شده برقرار باشند**. معیارهای خالی نادیده گرفته می‌شوند، بنابراین:

- قاعده‌ای بدون هیچ الگویی روی هر رویدادی از نوع خودش اجرا می‌شود (یک قاعده سراسری «همیشه اجرا شود»).
- قاعده‌ای که فقط الگوی عنوان دارد روی رویدادهایی فعال می‌شود که عنوانشان با آن عبارت باقاعده مطابقت دارد.
- چند قاعده می‌توانند با یک رویداد مطابقت داشته باشند — همه موارد منطبق فعال می‌شوند و اجتماع رانبوک‌هایشان اجرا می‌شود (هر رانبوک اجرای خودش را می‌گیرد).

## نمونه: جابه‌جایی اضطراری پایگاه داده برای حوادث پایگاه داده

```
Name:           Start DB failover for DB incidents
Trigger:        Incident
Title Pattern:  (?:^|\b)(db|database|postgres|mysql|mongo)
Runbooks:       [DB failover playbook, Notify DBA team]
```

این قاعده هر بار که حادثه‌ای با «db»، «database»، «postgres» و مانند آن در عنوانش ساخته شود، دو اجرای رانبوک می‌سازد.

## نمونه: قاعده بهداشتی همیشه‌اجرا

```
Name:                 Always-run pre-flight check
Trigger:              Incident
Title Pattern:        (empty)
Description Pattern:  (empty)
Runbooks:             [Capture pre-incident state]
```

روی هر حادثه‌ای فعال می‌شود — برای ثبت تصویر وضعیت سامانه، متریک‌های صفحه و مانند آن مفید است.

## وقتی یک قاعده فعال می‌شود چه اتفاقی می‌افتد

1. رانبوک بارگذاری می‌شود.
2. گام‌های آن روی یک اجرای رانبوک جدید **تصویربرداری** می‌شوند.
3. اجرا در صف کارگر Runbook قرار می‌گیرد.
4. اجرا به موجودیت مبدأ پیوند می‌خورد — در صفحه آن حادثه، هشدار یا رویداد تعمیر و نگهداری زمان‌بندی‌شده و نیز در فهرست اجراهای رانبوک نمایش داده می‌شود.

همه اجراهای فعال‌شده با قاعده را می‌توانید زیر **Runbooks → Executions** با فیلتر وضعیت، رانبوک یا تاریخ ببینید.

## رانبوک‌های غیرفعال

اگر قاعده‌ای به رانبوکی ارجاع دهد که `isEnabled = false` است، قاعده همچنان مطابقت پیدا می‌کند اما اجرای رانبوک نادیده گرفته می‌شود. برای از سرگیری، رانبوک را دوباره فعال کنید.

## آزمایش یک قاعده

پیش از تکیه بر یک قاعده در محیط عملیاتی، یک حادثه (یا هشدار) آزمایشی با عنوانی که با الگو مطابقت دارد بسازید و بررسی کنید که رانبوک‌های موردانتظار فعال می‌شوند. قواعد در لحظه ساخت ارزیابی می‌شوند — تغییر عنوان یک حادثه بعداً قواعد را دوباره فعال نمی‌کند.
