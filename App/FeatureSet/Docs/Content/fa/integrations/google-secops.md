# یکپارچه‌سازی Google SecOps

سیگنال‌های SIEM از [Google SecOps](https://cloud.google.com/security/products/security-operations) (پیش‌تر Chronicle) را به OneUptime بیاورید، تا تشخیص‌های امنیتی در همان دریاچه داده ClickHouse گزارش‌ها، ردیابی‌ها و سنجه‌هایتان زندگی کنند — قابل جستجو، هم‌بسته با داده رصدپذیری، قابل هشدار، و مسیردهی‌شده به کشیک.

سه راه برای وصل شدن هست، از بدون‌کد تا همگام‌سازی کامل رویداد:

```text
1. SOAR playbook webhook   ──►  Security Events ingest  ──►  Events + Detection Rules + Alerts
2. Managed connector       ──►  polls detection alerts  ──►  Detection Finding events
3. UDM event forwarding    ──►  Security Events ingest  ──►  full event search + correlation
```

هر مسیری رویدادها را به [OCSF](https://schema.ocsf.io/) نرمال می‌کند (چارچوب باز طرحواره امنیت سایبری)، که شکل متعارف رویداد امنیتی در OneUptime است، پس قواعد و داشبوردها هر گویش منبعی که باشد یکسان کار می‌کنند.

## پیش‌نیازها

- پروژه‌ای در OneUptime با **کلید دریافت تله‌متری** (**Settings → Telemetry Ingestion Keys**) برای مسیرهای وب‌هوک و فوروارد کردن UDM.
- مستأجری در Google SecOps. برای رابط مدیریت‌شده: دسترسی ساخت حساب سرویس Google Cloud با دسترسی خواندن API ‏Chronicle، و نقش مالک پروژه، مدیر پروژه یا مدیر امنیت در OneUptime (اعضای امنیت و بینندگان می‌توانند اتصال‌ها را بخوانند اما نمی‌توانند بسازند).

## گزینه ۱ — وب‌هوک پلی‌بوک SOAR (ظرف چند دقیقه کار می‌کند)

پلی‌بوک‌های SOAR در Google SecOps می‌توانند هشدارها را به هر نقطه پایانی HTTPای POST کنند. یکی را به دریافت رویدادهای امنیتی OneUptime نشانه بگیرید:

1. در پلی‌بوک SecOps SOAR خود، کنشی از نوع **HTTP request** بیفزایید که روی هشدارهای تازه شلیک کند.
2. پیکربندی‌اش کنید:

   - **Method**: `POST`
   - **URL**: `https://oneuptime.com/security-events/v1/ingest` (یا `https://<your-host>/security-events/v1/ingest` برای خودمیزبان)
   - **Headers**:

     ```text
     Content-Type: application/json
     x-oneuptime-token: <your telemetry ingestion key>
     ```

   - **Body**: JSON هشدار. محموله‌های تشخیص (فراداده قاعده به‌علاوه رویدادهای UDM تطبیق‌یافته زیر `collectionElements`) خودکار شناخته و به‌عنوان رویدادهای **Detection Finding** ذخیره می‌شوند، با مشاهده‌پذیرها (کاربران، میزبان‌ها، IPها) که از رویدادهای تطبیق‌یافته استخراج می‌شوند.

3. هشدارها ظرف چند ثانیه زیر **Security Events** در داشبورد پدیدار می‌شوند.

## گزینه ۲ — رابط مدیریت‌شده (تشخیص‌های پیمایشی)

‏OneUptime تشخیص‌ها و هشدارهای مستأجر شما را روی فاصله‌ای پیمایش می‌کند — به پیکربندی SOAR نیازی نیست. Google SecOps یکی از فراهم‌کنندگان **Security Event Connections** است، پس درست مانند هر رابط مدیریت‌شده دیگری، در همان صفحه و به همان شیوه ساخته، آزموده، پیمایش و عیب‌یابی می‌شود.

```text
Google SecOps instance  ──►  OneUptime reads it in three passes  ──►  Detection Finding events
```

### گام ۱ — ساخت کلید حساب سرویس

1. در Google Cloud، **حساب سرویسی** روی پروژه‌ای که نمونه SecOps شما به آن مقید است بسازید و نقش **Chronicle API Viewer** ‏(`roles/chronicle.viewer`) را به آن بدهید. این نقش مجوزهای `legacySearchDetections`، `legacySearchCuratedDetections` و `legacyFetchAlertsView` را که رابط با آن‌ها می‌خواند در بر دارد.
2. در زبانه **Keys** حساب سرویس، کلیدی از نوع **JSON** بیفزایید و دانلودش کنید. کل پرونده را در اتصال می‌چسبانید. مقدار `token_uri` آن باید نشانی `https` روی میزبانی از گوگل باشد، که کلیدِ دانلودشده از Google Cloud از پیش همین است.

### گام ۲ — یافتن ناحیه و نام منبع نمونه

در Google SecOps، **SIEM Settings → Profile** را باز کنید. نام منبع نمونه به شکل `projects/{project}/locations/{location}/instances/{instance}` است، که بخش instance آن شناسه نمونه SecOps است؛ نام نمایشی اتصال یا نام حساب سرویس جایگزین آن نیست. ناحیه همان نقطه پایانی ناحیه‌ای است که آن location را سرو می‌کند، و باید با بخش locations نام منبع نمونه بخواند، وگرنه اتصال هنگام ذخیره رد می‌شود.

### گام ۳ — ساخت اتصال در OneUptime

**Security Events → Connections** را (`/dashboard/{projectId}/security-events/connections`) باز کنید، **Add connection** را بزنید، **Google SecOps** را برگزینید و فرم را پر کنید:

| فیلد                       | کجا پیدایش کنید                                                                                                                                                                                                                                             | الزامی       |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| **Region**                 | نقطه پایانی ناحیه‌ای Google SecOps ‏(`us`، `europe`، `asia-southeast1`، ...) که با location در نام منبع نمونه شما می‌خواند. پیش‌فرضی ندارد، پس مستأجری بیرون از آمریکا نمی‌تواند تصادفاً نقطه پایانی اشتباه را ذخیره کند.                                   | بله          |
| **Instance resource name** | **SIEM Settings → Profile** در Google SecOps: ‏`projects/{project}/locations/{location}/instances/{instance}`.                                                                                                                                              | بله          |
| **Service account JSON**   | ‏Google Cloud ← حساب سرویس ← **Keys**. کل پرونده کلید JSON را بچسبانید. فقط‌نوشتنی: در حالت سکون رمزگذاری می‌شود، هرگز توسط API برنمی‌گردد و هرگز در صفحه بازنشان داده نمی‌شود. برای چرخاندنش از **Update credentials** روی اتصال استفاده کنید.             | بله          |
| **Data to import**         | **Alerts** همیشه دریافت می‌شوند چون API هشدارهای گوگل همیشه آن‌ها را برمی‌گرداند. **Detections** را برگزینید تا تطبیق‌های قاعده‌ای که هشداری نساخته‌اند هم دریافت شوند. این گزینه رویدادهای خام UDM را فوروارد نمی‌کند؛ برای آن‌ها از گزینه ۳ استفاده کنید. | Alerts همیشه |

گام پیمایش فرم **Name**، **Description** اختیاری، **Enabled** بودن اتصال و **Poll Interval (Minutes)** را می‌خواهد — عددی کامل از `1` تا `1440`، پیش‌فرض `5`. هر چیزی بیرون آن بازه هنگام ذخیره رد می‌شود.

پیش از ذخیره، **Test these settings** را زیر **Test before saving** بزنید. آزمون روی مقادیر فرم اجرا می‌شود بی‌آنکه چیزی ذخیره کند، پس کلیدی بدشکل، نقشی ناموجود یا نمونه‌ای اشتباه پیش از وجود اتصال آشکار می‌شود. در فرم ویرایش، همان دکمه **Region**، **Instance resource name** و **Data to import** نمایش‌داده‌شده روی صفحه را با کلید ذخیره‌شده می‌آزماید؛ فیلد اعتبارنامه‌ای که خالی بماند کلید ذخیره‌شده را نگه می‌دارد. وقتی هر چیزِ آزموده‌شده با آنچه اتصال ذخیره کرده فرق کند، از جمله کلیدی تازه واردشده، هیچ سطری در تاریخچه اجرا ثبت نمی‌شود، چون اتصال هنوز آن تنظیمات را ندارد.

تشخیص‌های تازه به‌عنوان رویدادهای **Detection Finding** منتسب به سرویس تله‌متری `Google SecOps` دریافت می‌شوند.

فهرست اتصال‌ها **Name**، **Provider** (با انتخاب Data to import اتصال زیر آن)، **Status** (‏Enabled یا Disabled)، **Health**، **Interval (Minutes)**، **Last Polled**، **Last Successful Poll** و **Last Event Imported** را نشان می‌دهد. وقتی اتصالی خطا دارد، **View Error** در ستون **Actions** آن پدیدار می‌شود، کنار **Test connection**، **Run now**، **Diagnostics**، **Edit** و **Update credentials**. ‏Enabled یعنی پیمایش خودکار پیکربندی شده است. ‏Last Polled یک تلاش را ثبت می‌کند؛ پنجره خالیِ موفق ثابت نمی‌کند که تشخیص خاصی دریافت شده است.

**Health** تنها وقتی رویدادی دریافت شده باشد **Last poll succeeded** می‌خواند. تا آن زمان اتصالی که موفق پیمایش می‌کند **Polling, no events imported yet** می‌خواند، که همان وضعیتی است که باید با Test connection بررسی شود. وضعیت‌های دیگر **No records returned**، **Partial import**، **Catching up**، **Last poll failed**، **Poll overdue**، **Schedule paused** و **Waiting for first poll** هستند؛ نشانگر را روی هر وضعیت نگه دارید تا معنایش را ببینید.

> رابط از APIهای تشخیص‌ها و هشدارهای legacy نسخه `v1alpha` در Chronicle استفاده می‌کند، که گوگل آن‌ها را پیش از GA عرضه می‌کند. وقتی پیمایشی شکست بخورد، فیلد **Last Error** اتصال پیام خطای کامل را با اعتبارنامه‌های پوشانده‌شده نگه می‌دارد، پشت پیشوندی که گام شکست‌خورده را نام می‌برد — از جمله حالتی که Chronicle پاسخ `200` می‌دهد و رد را درون بدنه می‌گذارد. **View Error** را در ستون **Actions** اتصال بزنید تا پیام را بخوانید، سپس **Copy Error** را در کادر گفتگو بزنید تا برای پشتیبانی رونوشتش را بردارید.

### پیمایش چگونه کار می‌کند

هر دقیقه یک کارگر پس‌زمینه برای هر اتصال فعالی که فاصله‌اش از آخرین پیمایش گذشته است پیمایشی در صف می‌گذارد. هر پیمایش اجرایی در تاریخچه اتصال است که کارگری آن را انجام می‌دهد. پیمایش یک پنجره زمانی را به سه شیوه می‌خواند و نتایج را بر پایه شناسه تشخیص ادغام می‌کند، پس رکوردی که بیش از یک گذر برگرداند یک بار ذخیره می‌شود:

1. **تشخیص‌های قاعده بر پایه زمان ساخت** — `legacy:legacySearchDetections` با `ruleId=-` (هر ویرایش از هر قاعده) و `listBasis=CREATED_TIME`، با دنبال کردن `nextPageToken` تا آخرین صفحه.
2. **تشخیص‌های قواعد گزیده بر پایه زمان ساخت** — `legacy:legacySearchCuratedDetections`، به همان شیوه. مستأجری بدون دسترسی به قواعد گزیده به این گذر با `400`، `403` یا `404` پاسخ می‌دهد؛ این به‌عنوان هشداری روی اجرا ثبت می‌شود، نه شکست.
3. **نمای هشدارها بر پایه زمان تشخیص** — `legacy:legacyFetchAlertsView`، که هشدارهای تله‌متری، هشدارهای SOAR و هشدارهای هوش ماشینی را که زمان تشخیصشان نزدیک به زمان واقعی است پوشش می‌دهد. این نقطه پایانی صفحه‌بندی ندارد، پس پاسخی که گوگل محدودش کند به پنجره‌های کوچک‌تر تقسیم و دوباره خوانده می‌شود.

پیمایش بر پایه **زمان ساخت** تمام طراحی است. قاعده‌ای در Google SecOps روی زمان‌بندی اجرا می‌شود (هر ۱۰ دقیقه، ساعتی، روزانه)، و تشخیصی که می‌سازد `detectionTime`ای دارد که پایان پنجره زمانی قاعده یا زمان رویداد تطبیق‌یافته است، در حالی که `createdTime` زمانی است که موتور تشخیص واقعاً آن را تولید کرده. تشخیصی که ساعت 10:05 برای پنجره‌ای که 09:00 تمام شده ساخته شود زمان تشخیصی دارد که از پیش پشت مکان‌نمایی است که چند پیمایش پیش از 09:00 گذشته، پس رابطی که بر پایه زمان تشخیص پیمایش کند هرگز آن را نمی‌بیند، و هیچ رویداد دیررسی را هم. خواندن بر پایه زمان ساخت هر پیمایش را وامی‌دارد بپرسد «گوگل از آخرین باری که نگاه کردم چه ساخته است»، که پرسشی است که پاسخ دارد. هر اجرا تأخیر ساختش را ثبت می‌کند — چند رکورد واکشی‌شده بیش از یک فاصله پیمایش (به‌علاوه یک دقیقه) پس از زمان تشخیصشان ساخته شده‌اند، و بزرگ‌ترین فاصله — تا اثرش در Diagnostics دیده شود.

نخستین پیمایش اتصال تازه **۲۴ ساعت** بر پایه زمان ساخت به عقب نگاه می‌کند. هر پیمایش پس از آن از مکان‌نمای ذخیره‌شده اتصال با **۱ دقیقه** هم‌پوشانی از سر می‌گیرد؛ رکوردی که روی مرز پنجره ساخته شود با هر دو پیمایش خوانده و یک بار ذخیره می‌شود، چون پیمایش‌ها رویدادهایی را که از پیش با همان شناسه منبع ذخیره شده‌اند رد می‌کنند. هر پیمایش زمان‌بندی‌شده حداکثر **۲۴ ساعت** پس از مکان‌نما را می‌خواند، پس اتصالی با مکان‌نمای ذخیره‌شده قدیمی‌تر در پنجره‌های ۲۴ ساعته پیاپی عقب‌ماندگی را جبران می‌کند (‏Health می‌خواند **Catching up**) به‌جای آنکه تشخیص‌های میانه را دور بریزد. برای رکوردهایی که پیش از نخستین پنجره ۲۴ ساعته ساخته شده‌اند از **Import this time range** در Diagnostics استفاده کنید.

#### وقتی پنجره‌ای بیش از توان خواندن یک پیمایش دارد

رابط به هر پیمایش بودجه‌هایی ثابت می‌دهد: دو گذر زمان ساخت **۲۰** صفحه جستجو را شریک‌اند، نمای هشدارها **۱۶** درخواست از آنِ خود دارد، و کل خواندن پس از **۴ دقیقه** متوقف می‌شود. گذری که بودجه‌ای آن را در میانه راه متوقف کرده به‌عنوان بررسی هشداری ثبت می‌شود که بودجه را نام می‌برد (برای نمونه `Read rule detections by created time was stopped by the request budget after 20 requests.`)، و گذری که بودجه هرگز اجازه آغازش را نداده بررسی ردشده‌ای است با همان دلیل در هشدارهای اجرا — هرگز موفقیت نیست. پنجره‌ای با تشخیص‌هایی بیش از این در یک پیمایش خوانده نمی‌شود، و پیمایش هرگز همان پنجره را تا ابد دوباره نمی‌خواند:

1. **تنگ کردن.** نقاط پایانی جستجوی گوگل تازه‌ترین تشخیص‌ها را نخست برمی‌گردانند، پس پیمایشی که زود بایستد نقطه‌ای برای از سر گرفتن ندارد. پیمایش **Partial** ثبت می‌شود، مکان‌نما همان‌جا می‌ماند، و پیمایش بعدی پنجره‌ای به نصف طول را از همان نقطه آغاز می‌خواند، با هشدار `This window holds more records than one poll can read; the next poll reads a {n} minute window from the same starting point.` نصف کردن تا یک دقیقه ادامه می‌یابد تا پنجره‌ای جا شود.
2. **رشد دوباره.** هر پیمایش کامل پنجره بعدی را دو برابر می‌کند، تا بیشینه ۲۴ ساعت، پس یک انفجار به بهای چند پیمایش کوتاه تمام می‌شود نه اتصالی همیشه کند.
3. **گذشتن از یک دقیقه تنها.** اگر حتی یک دقیقه تشخیص‌هایی بیش از توان خواندن یک پیمایش داشته باشد، پیمایش مکان‌نما را از آن دقیقه جلوتر می‌برد تا تشخیص‌های تازه‌تر همچنان برسند. اجرا **Partial** است و همین متن در آغاز **Last Error** می‌آید: `More records were created in the one minute from {start} to {end} than one poll can read. Polling moved past this minute so newer records keep arriving; use Import this time range in Diagnostics on this minute to recover what one run can read.` برای بازیابی آنچه یک اجرا می‌تواند بخواند، **Diagnostics** را باز کنید، بازه‌ای سفارشی که آن دقیقه را بپوشاند برگزینید (ورودی‌های بازه به وقت محلی شماست؛ پیام به UTC است) و **Import this time range** را اجرا کنید؛ دریافت همان محدودیت‌های هر اجرا را دارد که پیمایش. تشخیص‌هایی که از پیش دریافت شده‌اند رد می‌شوند.

پیمایش Partial هشدارهایش را هم در **Last Error** ذخیره می‌کند، و آن‌جا می‌مانند تا پیمایشی کامل پاکشان کند. پیمایشی که یکسره شکست بخورد (خطا، نه رکوردهای زیاده) مکان‌نما و طول پنجره‌اش را نگه می‌دارد و در تیک بعدی دوباره تلاش می‌شود. تنها استثنا درخواستی است که مهلتش سر آمده: پیمایش بعدی پنجره‌ای به نصف طول را از همان نقطه آغاز می‌خواند (`The source did not answer in time for this window; the next poll reads a {n} minute window from the same starting point.`)، چون پنجره‌ای سنگین‌تر از آنکه به‌موقع پاسخ داده شود وگرنه در هر تلاش دوباره مهلتش سر می‌آمد. کوتاه کردن فاصله پیمایش هیچ‌کدام از این‌ها را تغییر نمی‌دهد: پنجره را مکان‌نما و نتیجه آخرین پیمایش تعیین می‌کنند، نه اینکه پیمایش‌ها هر چند وقت اجرا شوند.

### آزمون اتصال

**Test connection**، روی ردیف اتصال یا در **Diagnostics**، به‌صورت همگام در فرایند API اجرا می‌شود. به کارگر پس‌زمینه نیاز ندارد، و دقیقاً به همین دلیل می‌تواند بگوید که هیچ کارگری در حال اجرا نیست. فهرست بررسی:

1. **Configuration** — هر فیلد موجود و خوش‌شکل است: **Region** پشتیبانی‌شده‌ای که با location نمونه می‌خواند، **Instance resource name** با شکل درست، و کلید **Service account JSON** با `client_email`، `private_key` خواندنی و `token_uri` گوگلی. اگر این شکست بخورد با هیچ‌چیز تماس گرفته نمی‌شود.
2. **Authenticate with Google** — کلید در نقطه پایانی OAuth گوگل با توکن دسترسی مبادله می‌شود، پیش از آنکه با Chronicle تماس گرفته شود.
3. **Read rule detections**، **Read curated rule detections** و **Read the alerts view** — کاوشی تک‌رکوردی از هر گذر روی ۲۴ ساعت گذشته. خواندن قواعد گزیده‌ای که با `400`، `403` یا `404` پاسخ بگیرد هشدار است، چون شاید مستأجر اصلاً دسترسی به قواعد گزیده نداشته باشد.
4. **Detections available to import** — آنچه گوگل با انتخاب ذخیره‌شده **Data to import** _و_ با انتخاب دیگر (فقط Alerts، یا Alerts و **Detections**) در ۲۴ ساعت و ۷ روز گذشته دارد: شمار تطبیق‌یافته نمای هشدارها و یک صفحه جستجوی زمان ساخت برای هر بازه، که به‌صورت عدد یا `1000+` گزارش می‌شود. وقتی انتخاب ذخیره‌شده چیزی ندارد اما دیگری دارد، بررسی هشدار می‌دهد: قواعد شما تشخیص می‌سازند اما هشدار روی آن‌ها فعال نیست. اتصال را ویرایش کنید و **Detections** را زیر **Data to import** برگزینید، یا هشدار را روی قواعد در Google SecOps فعال کنید.
5. **Background workers**، **Poll scheduler** و **Security event storage** — آیا فرایندی صف Worker در OneUptime را مصرف می‌کند، آیا کار پیمایش دقیقه‌ای ثبت شده است، و آیا انباره رویدادهای امنیتی به همان جستجوی تکراری که پیمایش پیش از هر درج اجرا می‌کند پاسخ می‌دهد، تا پایگاه داده تحلیلی خراب این‌جا با نامی شکست بخورد نه یک ساعت بعد به‌عنوان خطای پیمایش.
6. **Scheduled polling** (فقط اتصال‌های ذخیره‌شده) — آیا پیمایش فعال است، آیا اجرایی در صف منتظر کارگر مانده، و آیا اتصال طبق زمان‌بندی پیمایش می‌شود.

هر درخواست در آزمون مهلتی ۲۰ ثانیه‌ای دارد. آزمون‌ها به مکان‌نمای پیمایش و انباره رویداد دست نمی‌زنند. اتصال ذخیره‌شده‌ای که با تنظیمات ذخیره‌شده‌اش آزموده شود سطری از نوع test در تاریخچه اجرا می‌گیرد، و جزئیات آن سطر همان فهرست بررسی را نشان می‌دهد.

### پیش‌نمایش، اجرا و دریافت بر حسب نیاز

**Diagnostics** را روی اتصال باز کنید تا اجراهای اخیر را ببینید و رابط را به کار بیندازید. مالکان پروژه، مدیران پروژه و مدیران امنیت می‌توانند عملیات آغاز کنند. اعضای امنیت و بینندگان می‌توانند تاریخچه را بخوانند.

- **Run now** بی‌درنگ پیمایشی در صف می‌گذارد، با همان مکان‌نما و مسیر دریافت معمول، حتی وقتی پیمایش زمان‌بندی‌شده غیرفعال است. وضعیت‌های در صف و در حال اجرا تا وقتی کارگر درخواست را انجام می‌دهد دیده می‌شوند. اگر اجرایی در صف بماند، بررسی کنید که کارگرها صف Worker را پردازش می‌کنند؛ بررسی **Background workers** در Test connection می‌گوید آیا فرایندی چنین می‌کند.
- **Preview detections** بازه زمانی برگزیده‌ای را بی دریافت یا تغییر مکان‌نما می‌خواند. ساعت گذشته، ۲۴ ساعت، ۷ روز، یا بازه‌ای سفارشی تا ۷ روز را به کار ببرید. بازه با نمای هشدارهای SecOps می‌خواند که بر پایه زمان تشخیص می‌خواند، و دو گذر جستجو تشخیص‌هایی را که در آن _ساخته_ شده‌اند و نیز تشخیص‌هایی را که زمان تشخیصشان در آن است می‌خوانند، پس پیش‌نمایش دیروز تشخیص‌هایی را هم که دیروز درباره رویدادهای قدیمی‌تر ساخته شده‌اند نشان می‌دهد. پیش‌نمایش زمان تشخیص و زمان ساخت را جدا نشان می‌دهد. نتایج انتخاب ذخیره‌شده **Data to import** اتصال را بازتاب می‌دهند.
- **Import this time range** بازه برگزیده را، پس از تأیید شما، بی جابه‌جا کردن مکان‌نمای پیمایش دریافت می‌کند. همچنین همان راه بازیابی دقیقه‌ای است که پیمایش از آن گذشته، چنان‌که بالاتر آمد. نخست پیش‌نمایش بگیرید. پیمایش‌ها و دریافت‌های تکراری رویدادهایی را که از پیش با همان شناسه منبع در پروژه ذخیره شده‌اند رد می‌کنند. دریافت‌ها ممکن است درست مانند پیمایش زمان‌بندی‌شده قواعد تشخیص و مانیتورهای پیکربندی‌شده را برانگیزند.

جزئیات هر اجرا **Requested window (UTC)**، انتخاب **Data to import** اتصال و پنج شمارش را نشان می‌دهد: **Returned by Google SecOps** (رکوردهایی که گوگل در سه گذر برگردانده، پس از ادغام بر پایه شناسه)، **Imported into OneUptime** (سطرهای نوشته‌شده در انباره رویداد)، **Already imported** (رکوردهایی که رد شده‌اند چون همان شناسه منبع از پیش در این پروژه ذخیره شده؛ هم‌پوشانی ۱ دقیقه‌ای و اجراهای دوباره این را عادی می‌کنند)، **Rejected** (اشیای برگشتی که تشخیص Google SecOps نیستند؛ شمرده و درباره‌شان هشدار داده می‌شود، هرگز دوباره تلاش نمی‌شوند و مکان‌نما را نگه نمی‌دارند) و **Failed** (رکوردهایی که نرمال نشدند؛ پیمایش آن‌ها را در پنجره‌ای کوتاه‌تر دوباره می‌آزماید). **Provider details** این‌ها را می‌افزاید: **Time basis read**، رکوردهای **Returned by each pass** (تشخیص‌های قاعده، تشخیص‌های قواعد گزیده و نمای هشدارها) و **Creation lag**. سپس بررسی‌ها، یکی برای هر گذر، هشدارها و نمونه تشخیص‌ها می‌آیند. جزئیات پیمایش زمان‌بندی‌شده **Window read by this poll** و آنچه **Next scheduled poll reads** را هم نشان می‌دهد، و پیمایش Partial می‌گوید آیا نقطه آغازش را نگه داشت و پنجره بعدی را تنگ کرد، یا از دقیقه‌ای تنها که نامش را می‌برد گذشت. **Success**، **No records returned**، **Partial** و **Failed** نتیجه‌هایی متمایزند.

از **View events in this time range** روی یک اجرا استفاده کنید تا بازه زمان رویداد تشخیص‌هایی را که برگردانده باز کنید. تشخیصی که امروز با زمان تشخیص دیروز ساخته شده وگرنه ممکن است پشت پالایه رویدادهای اخیر پنهان بماند. تاریخچه اجرا شکست‌ها را پس از آنکه پیمایش کامل بعدی Last Error را پاک کند نگه می‌دارد. هنگام تماس با پشتیبانی از **Copy diagnostics** استفاده کنید؛ اعتبارنامه‌های حساب سرویس و توکن‌ها هرگز در آن نیستند.

### چرا رویدادی نمی‌بینم؟

این‌ها را به ترتیب بررسی کنید. هر کدام در **Diagnostics** یا با **Test connection** از بعدی تمیز داده می‌شود.

1. **Data to import.** به‌طور پیش‌فرض فقط **Alerts** دریافت می‌شوند، و تشخیص قاعده تنها وقتی هشدار است که هشدار روی قاعده در Google SecOps فعال باشد. مستأجری که قواعدش بی هشدار تشخیص می‌سازند تا ابد صادقانه خالی پیمایش می‌کند. **Test connection** را اجرا کنید: بررسی **Detections available to import** با و بی **Detections** می‌شمارد و وقتی برگزیدنش رکوردی بیفزاید همین را می‌گوید. اتصال را ویرایش کنید و **Detections** را زیر **Data to import** برگزینید، یا هشدار را روی قواعد فعال کنید.
2. **بسامد اجرای قاعده و تأخیر تشخیص.** تشخیص‌ها وقتی قاعده اجرا می‌شود ساخته می‌شوند، که می‌تواند تا یک ساعت یا یک روز پس از رویدادهایی که توصیف می‌کنند باشد. رابط بر پایه زمان ساخت پیمایش می‌کند، پس آن‌ها در نخستین پیمایش پس از ساخته شدن به دست گوگل می‌رسند، نه در زمان تشخیصشان. قاعده‌ای که تازه فعال کرده‌اید هنوز چیزی نساخته، و مستأجری آرام چیزی برای ساختن ندارد. بررسی در دسترس بودن می‌گوید چند تشخیص در ۲۴ ساعت و ۷ روز گذشته ساخته شده؛ صفر با و بی **Detections** یعنی گوگل هنوز چیزی برای دریافت OneUptime ندارد.
3. **شمارش‌های آخرین اجرا را بخوانید.** در Diagnostics، **Returned by Google SecOps** با **Imported into OneUptime** صفر و شمار **Already imported** برابر، یعنی رابط همان‌گونه که طراحی شده کار می‌کند: آن تشخیص‌ها را پیمایشی پیش‌تر دریافت کرده است. رکوردهای **Rejected** اشیایی‌اند که گوگل برگردانده و اصلاً تشخیص نیستند.
4. **آیا اصلاً چیزی پیمایش می‌کند؟** **Last Polled: Never** با Last Error خالی یعنی هیچ پیمایشی برای این اتصال به پایان نرسیده است. ‏Test connection گزارش می‌دهد **Background workers** (فرایندهایی که صف Worker را مصرف می‌کنند)، **Poll scheduler** (ثبت زمان‌بند دقیقه‌ای) و **Scheduled polling** (زمان‌بندی خودِ این اتصال، از جمله پیمایشی سررسیده‌گذشته یا اجرایی گیرکرده در صف). برای تنظیمات استقراری که علتش هستند، مدخل رفع اشکال زیر را ببینید.
5. **در جای درست نگاه کنید.** رویدادها زیر زمان تشخیصشان ذخیره می‌شوند، که می‌تواند ساعت‌ها یا روزها پیش از زمان ساخته و دریافت شدنشان باشد، پس پالایه «ساعت گذشته» در Security Events تشخیصی را که یک دقیقه پیش درباره دیروز دریافت شده پنهان می‌کند. از **View events in this time range** روی اجرایی در Diagnostics استفاده کنید: بازه زمان رویداد تشخیص‌هایی را که آن اجرا برگردانده باز می‌کند.

### رفع اشکال

- **گوگل صفر رکورد برمی‌گرداند** — پنجره زمانی دقیق، مبنای زمانی و انتخاب ذخیره‌شده **Data to import** را در Diagnostics بررسی کنید، و Test connection را اجرا کنید تا شمارش‌های در دسترس بودن را با و بی **Detections** بخوانید. تطبیق قاعده بدون هشدار به گزینه **Detections** نیاز دارد. بازه‌ای را پیش‌نمایش کنید که هم زمان تشخیص و هم زمان ساختش را بپوشاند. نخستین پیمایش زمان‌بندی‌شده ۲۴ ساعت بر پایه زمان ساخت به عقب نگاه می‌کند؛ برای رکوردهای قدیمی‌تر از **Import this time range** استفاده کنید.
- **‏Health برابر Partial import است** — آخرین اجرا را در **Diagnostics** باز کنید و هشدارهایش را بخوانید؛ همان هشدارها در Last Error هم هستند. `This window holds more records than one poll can read; ...` یعنی پیمایش پنجره‌اش را از همان نقطه آغاز تنگ می‌کند و به هیچ اقدامی نیاز ندارد: وقتی پیمایش‌ها کامل شوند دوباره رشد می‌کند. `More records were created in the one minute from ...` یعنی پیمایش از آن دقیقه گذشته است؛ با **Import this time range** دریافتش کنید تا تشخیص‌هایی را که رد کرده بازیابی کنید. هشداری که می‌گوید گذری با بودجه درخواست یا بودجه زمانی پیمایش متوقف شده، یا به همین دلیل اجرا نشده، گذری را که کوتاه ماند نام می‌برد. کوتاه کردن فاصله پیمایش پنجره را تغییر نمی‌دهد. ‏Last Error خالی به‌تنها ثابت نمی‌کند پوشش کامل است.
- **‏Health برابر Poll overdue است** — پیمایش‌های زمان‌بندی‌شده به‌موقع اجرا نمی‌شوند؛ صف کارگر را بررسی کنید و Test connection را برای بررسی‌های **Background workers** و **Scheduled polling** اجرا کنید.
- **وضعیت `Disabled` است** — پیمایش زمان‌بندی‌شده از اتصال می‌گذرد. کاربران مجاز همچنان می‌توانند از Diagnostics آزمون بگیرند، پیش‌نمایش کنند، با **Run now** پیمایشی اجرا کنند، یا دریافت کنند.
- **‏Last Polled برابر `Never` است و Last Error خالی است** — هیچ پیمایشی برای این اتصال به پایان نرسیده است. **Diagnostics** را باز کنید: وقتی تاریخچه اجرایش هیچ پیمایشی ندارد، یا فقط پیمایشی گیرکرده در صف، کارگر پس‌زمینه اصلاً کار پیمایش را اجرا نکرده، پس هیچ‌چیز هرگز به Chronicle نرسیده است. در استقرارهای خودمیزبان علت معمول `DISABLE_QUEUE_WORKERS=true` روی کانتینر برنامه بدون استقرار کارگر جداگانه‌ای است که صف‌ها را تخلیه کند. یا `DISABLE_QUEUE_WORKERS=false` بگذارید (پیش‌فرض `config.example.env` که Docker Compose با آن می‌آید)، یا استقرار کارگر اختصاصی را اجرا کنید (Helm: ‏`worker.enabled: true`، که به‌طور پیش‌فرض `false` است). ‏Test connection این را به‌صورت بررسی شکست‌خورده **Background workers**، **Poll scheduler** یا **Scheduled polling** گزارش می‌دهد. پیمایشی که اجرا شده اما پیش از رسیدن به اتصال ایستاده، به‌جای آن اجرایی شکست‌خورده در همان تاریخچه است: `Another poll or import for this source is still running in this project` یعنی پیمایش یا دریافت دیگری از Google SecOps در این پروژه قفل منبع را در دست داشته، و اتصال در تیک بعدی دوباره در صف گذاشته می‌شود. زمان‌بندی که حتی نتوانسته پیمایشی در صف بگذارد `Scheduler could not queue a poll:` و دلیل را روی Last Error مهر می‌کند.
- **‏Last Error پر است** — پیمایشی تلاش شده و چیزی در آن شکست خورده، پیمایشی نتوانسته کل پنجره‌اش را بخواند، یا زمان‌بند نتوانسته پیمایشی در صف بگذارد. برای پیمایش شکست‌خورده، فیلد پیام خطای کامل را با اعتبارنامه‌های پوشانده‌شده نگه می‌دارد. وقتی اتصالی خطا دارد، **View Error** را در ستون **Actions** آن بزنید تا پیام کامل را باز کنید، سپس **Copy Error** را در کادر گفتگو بزنید تا برای پشتیبانی رونوشتش را بردارید. فیلد با پیمایش کامل بعدی پاک می‌شود، که کنش **View Error** را هم برمی‌دارد؛ تاریخچه اجرا نگهش می‌دارد. نخست پیشوند را بخوانید. پیامی که با `More records were created in the one minute from` آغاز شود همان دقیقه ردشده است نه یک شکست؛ **‏Health برابر Partial import است** را در بالا ببینید. فقط سه پیشوند وضعیت HTTP حمل می‌کنند، پس پیامی بدون آن شاهد ایرادی در سمت OneUptime نیست:
  - `Google token exchange failed (HTTP ...)` — اعتبارنامه حساب سرویس در نقطه پایانی OAuth گوگل رد شده، پیش از آنکه اصلاً با Chronicle تماس گرفته شود. معمولاً کلیدی بدشکل، باطل‌شده یا از پروژه‌ای اشتباه.
  - `Google token exchange returned ...` — همان نقطه پایانی OAuth پاسخ داده، اما با چیزی غیرقابل استفاده: بدون `access_token`، یا بدنه‌ای که JSON نیست. باز هم پیش از Chronicle، و معمولاً پراکسی یا دروازه‌ای در میانه نه خودِ کلید.
  - `Google SecOps detections search failed (HTTP ...)` — خودِ Chronicle جستجوی زمان ساخت را رد کرده است (`legacySearchDetections` یا `legacySearchCuratedDetections`). ‏`403` معمولاً یعنی حساب سرویس نقش **Chronicle API Viewer** را روی پروژه‌ای که نمونه به آن مقید است ندارد؛ در گذر قواعد گزیده `400`، `403` یا `404` به هشدار فروکاسته می‌شود چون شاید مستأجر اصلاً دسترسی به قواعد گزیده نداشته باشد.
  - `Google SecOps detections search returned ...` — ‏Chronicle به جستجو پاسخ `200` داده، اما بدنه صفحه خواندنی تشخیص‌ها نبوده: خالی، غیر JSON، یا شکلی که تفکیک‌کننده نمی‌شناسد. به‌جای شمرده شدن به‌عنوان پنجره‌ای آرام گزارش می‌شود، تا مکان‌نما نتواند از آنچه از دست رفته جلو برود.
  - `Google SecOps alerts fetch failed (HTTP ...)` — خودِ Chronicle درخواست نمای هشدارها را رد کرده است. ‏`403` معمولاً یعنی حساب سرویس نقش **Chronicle API Viewer** را روی پروژه‌ای که نمونه به آن مقید است ندارد؛ `404` معمولاً یعنی نام منبع نمونه به نمونه‌ای دیگر اشاره می‌کند، یا پیشوند ناحیه از آن‌هایی نیست که Chronicle سرو می‌کند.
  - `Google SecOps alerts fetch returned ...` — ‏Chronicle پاسخ `200` داده، اما بدنه جریان خواندنی هشدارهای تشخیص نبوده: خالی، غیر JSON، یا شکلی که تفکیک‌کننده نمی‌شناسد. عمداً به‌جای شمرده شدن به‌عنوان پنجره‌ای خالی گزارش می‌شود — رفتار با بدنه‌ای که نتوانسته بخواند به‌عنوان «بدون هشدار» مکان‌نما را از آنچه از دست رفته جلو می‌برد.
  - `Google SecOps alerts query was rejected by Chronicle on an HTTP 200` — ‏Chronicle درخواست را پذیرفته، اجرایش کرده، و پرس‌وجو را درون بدنه‌ای که برگردانده رد کرده است (`validSnapshotQuery` یا `validBaselineQuery` نادرست، یا `queryValidationErrors`). این رد گوگل است، و هیچ وضعیت HTTPای در آن نیست.
  - `timed out after 60 seconds with no response` — نه نقطه پایانی OAuth گوگل و نه Chronicle پیش از تسلیم کلاینت پاسخ داده‌اند (آزمون اتصال برای هر درخواست مهلتی ۲۰ ثانیه‌ای دارد و همین عبارت را با آن عدد گزارش می‌کند). چیزی برنگشته، پس پیام هیچ سویی را متهم نمی‌کند؛ خروج ترافیک از کارگر OneUptime و نیز مستأجر را بررسی کنید.
  - پیامی که با هیچ‌کدام از بالا نمی‌خواند از گوگل نیامده است. پیامی که با نام فیلدی آغاز شود — `Region`، `Instance resource name` یا `Service account JSON` — یعنی تنظیمات ذخیره‌شده از اعتبارسنجی نمی‌گذرند: اتصال را ویرایش کنید، یا کلید را با **Update credentials** جایگزین کنید. اتصالی که از رابط پیشین Google SecOps منتقل شده و تنظیمات ذخیره‌شده‌اش دیگر از قواعد امروز نمی‌گذرد تا ویرایش نشود همین‌جا می‌ماند. وگرنه شکست در سمت OneUptime بوده است: معمولاً تشخیص‌ها رسیده‌اند و نوشتنشان در انباره تله‌متری شکست خورده است.
- **‏Last Error می‌گوید `Google SecOps alerts fetch failed (HTTP 400)` و `Unknown name "pageSize": Cannot bind query parameter` را نقل می‌کند** — این پارامتر درخواستی پشتیبانی‌نشده روی نمای هشدارها را نشان می‌دهد. نسخه بالادستی **13.0.0** از پیش `pageSize` را روی آن نقطه پایانی با `alertListOptions.maxReturnedAlerts` جایگزین کرده است. اگر این خطا هنوز پدیدار می‌شود، ایمیج‌های واقعی برنامه و کارگر را، از جمله ساخت‌های سفارشی و کارگرهای جداگانه مستقرشده، بررسی کنید. چرخاندن کلید حساب سرویس پارامتر پرس‌وجوی پشتیبانی‌نشده را درست نمی‌کند. مبادله موفق توکن OAuth پذیرفته شدن اعتبارنامه را تأیید می‌کند؛ رد پارامتر به‌تنها احراز هویت یا مجوز را ثابت نمی‌کند.

### درخواست هشدار هنوز `400 INVALID_ARGUMENT` برمی‌گرداند

مبادله موفق توکن OAuth تأیید می‌کند که گوگل اعتبارنامه حساب سرویس را پذیرفته است. نام منبع نمونه SecOps یا مجوز خواندن آن نمونه را تأیید نمی‌کند. پاسخ کلی `Request contains an invalid argument` نمی‌گوید کدام آرگومان شکست خورده است.

نسخه بالادستی **13.0.0** از پیش `alertListOptions.maxReturnedAlerts` را روی نمای هشدارها به کار می‌برد. اگر استقراری که همین نسخه را گزارش می‌کند هنوز آن‌جا `pageSize` می‌فرستد، ایمیج‌های واقعی هر کارگر پیمایش، از جمله کارگرهای جداگانه مستقرشده و ساخت‌های سفارشی، را بررسی کنید.

1. **نسخه ایمیج‌های در حال اجرای برنامه و کارگر** را بررسی کنید. به‌روزرسانی پرونده منبع محلی رابط یا بارگذاری دوباره JSON حساب سرویس کانتینر مستقرشده را به‌روز نمی‌کند. ایمیجی حاوی اصلاح رابط را روی هر برنامه یا کارگر اختصاصی که کار پیمایش را اجرا می‌کند مستقر کنید. اگر ایمیج خودتان را می‌سازید، آن را با منبع اصلاح‌شده دوباره بسازید و برچسبی تازه و تغییرناپذیر مستقر کنید؛ راه‌اندازی دوباره پاد با ایمیج قدیمی کافی نیست.
2. درخواست نمای هشدارها را با [مرجع API گوگل](https://docs.cloud.google.com/chronicle/docs/reference/rest/v1alpha/projects.locations.instances.legacy/legacyFetchAlertsView) مقایسه کنید. این درخواست `timeRange.startTime`، `timeRange.endTime`، `snapshotQuery=` (مقدار خالی همه وضعیت‌های هشدار را در بر می‌گیرد)، `alertListOptions.maxReturnedAlerts`، و `includeNonAlertingDetections` را که صریحاً از انتخاب ذخیره‌شده **Data to import** تنظیم می‌شود به کار می‌برد. نباید روی آن نقطه پایانی `pageSize` یا `pageToken` بفرستد. دو گذر زمان ساخت [`legacySearchDetections`](https://docs.cloud.google.com/chronicle/docs/reference/rest/v1alpha/projects.locations.instances.legacy/legacySearchDetections) و `legacySearchCuratedDetections` را به کار می‌برند، که در آن‌ها `ruleId`، `listBasis`، `alertState`، `pageSize` و `pageToken` پارامترهای مستند هستند، و شکست‌هایشان به‌جای آن پیشوند جستجوی تشخیص‌ها را دارد. پالایه‌ای که هشدارهای بسته را کنار بگذارد جایگزین نکنید، چون تشخیص‌ها را از دست می‌دهد.
3. منبع کامل `projects/{project}/locations/{location}/instances/{instance}` را با مقادیر تنظیمات مستأجر Google SecOps خود مقایسه کنید. بخش instance باید شناسه نمونه SecOps باشد؛ نام نمایشی اتصال یا نام حساب سرویس جایگزین آن نیست. تأیید کنید که نقطه پایانی ناحیه‌ای با location نمونه می‌خواند.
4. پس از پایان استقرار، تا فاصله پیمایش پیکربندی‌شده بعدی صبر کنید. **Last Polled** باید جلو برود و **Last Error** با پیمایشی کامل پاک شود. اگر پنجره تشخیصی دارد، باید زیر **Security Events** پدیدار شود؛ پنجره‌ای آرام می‌تواند به‌حق صفر رویداد دریافت کند.

اگر همان خطا ماند، **View Error** را از ستون **Actions** اتصال باز کنید، **Copy Error** را در کادر گفتگو بزنید، و آن پیام، برچسب یا digest ایمیج، ناحیه و نام منبع نمونه را به پشتیبانی بدهید. اعتبارنامه‌ها در پیام ثبت‌شده پوشانده شده‌اند؛ کلید خصوصی حساب سرویس، ادعای JWT یا توکن دسترسی را جداگانه نفرستید. خطاهایی که پیش از ارتقا ثبت شده‌اند ممکن است از پیش کوتاه شده باشند؛ پیمایش شکست‌خورده بعدی پیام کامل را ثبت می‌کند. پیمایش شکست‌خورده پنجره‌اش را برای تلاش دوباره نگه می‌دارد، و پیمایش Partial پنجره بعدی‌اش را تنگ می‌کند یا از دقیقه‌ای تنها که در Last Error نامش را می‌برد می‌گذرد. جبران عقب‌ماندگی زمان‌بندی‌شده در هر اجرا تا ۲۴ ساعت را پردازش می‌کند.

### ارتقا از رابط پیشین Google SecOps

‏Google SecOps پیش‌تر کارت اتصال‌ها، API و پیمایشگر خودش را داشت. اکنون یکی از فراهم‌کنندگان Security Event Connections است، و ارتقا اتصال‌های موجود را برایتان منتقل می‌کند.

- **اتصال‌ها خودکار منتقل می‌شوند.** وقتی نسخه ارتقایافته مهاجرت‌های داده‌اش را اجرا می‌کند، هر اتصال Google SecOps با فراهم‌کننده `google-secops` در Security Event Connections رونویسی می‌شود. شناسه، نام، **Region**، **Instance resource name**، کلید حساب سرویس، وضعیت **Enabled**، فاصله پیمایش، انتخاب **Data to import**، مکان‌نمای پیمایش، Last Polled، Last Successful Poll، Last Event Imported و Last Error خود را نگه می‌دارد، پس پیمایش از همان‌جا که ایستاده بود از سر گرفته می‌شود. رابط همان هویت `Google` / `Google SecOps` را که رابط پیشین با آن دریافت می‌کرد نگه می‌دارد، پس تشخیص‌هایی که از پیش دریافت شده‌اند به‌جای دو بار ذخیره شدن **Already imported** شمرده می‌شوند.
- **تاریخچه اجرای اخیر هم می‌آید.** ۵۰۰ اجرای اخیر هر اتصال در تاریخچه اجرای آن در **Diagnostics** رونویسی می‌شود. اجرایی که هنوز در صف یا در حال اجرا بود به‌عنوان شکست‌خورده با این پیام رونویسی می‌شود: `This operation was still in progress when Google SecOps moved to Security Event Connections, so its outcome was not recorded here. Check the imported security events before running it again.`
- **سطرهای پیشین غیرفعال می‌شوند، نه حذف.** بنابراین کارگر قدیمی‌ای که در استقرار تدریجی هنوز اجرا می‌شود نمی‌تواند همان نمونه را بار دوم پیمایش کند. بازگشت به نسخه‌ای با رابط پیشین نیازمند فعال کردن دوباره آن سطرهاست.
- **اتصالی که منتقل نشود همان‌جا می‌ماند.** اتصالی بدون کلید ذخیره‌شده، یا با کلیدی که با `ENCRYPTION_SECRET` این سرور رمزگشایی نمی‌شود، رد و در گزارش کارگر نام برده می‌شود؛ آن را دوباره زیر **Security Events → Connections** بیفزایید. اتصالی که تنظیمات ذخیره‌شده‌اش دیگر از اعتبارسنجی امروز نمی‌گذرد در هر حال منتقل می‌شود، و پیمایش‌هایش با پیامی که فیلد را نام می‌برد شکست می‌خورند تا ویرایشش کنید. اتصالی که خطای گذرای پایگاه داده جلویش را گرفته، وقتی مهاجرت در راه‌اندازی بعدی کارگر دوباره اجرا شود منتقل می‌شود، و پیمایش از مکان‌نمای رونویسی‌شده‌اش از سر گرفته می‌شود.
- **مسیرهای API تغییر کرده‌اند.** مسیرهای `/google-secops-connection` و `/google-secops-connection-run`، از جمله `/google-secops-connection/test` و `/google-secops-connection/:connectionId/run`، با `/security-event-connection` و `/security-event-connection-run` با فراهم‌کننده `google-secops` جایگزین شده‌اند؛ عملیات‌ها `/security-event-connection/test` و `/security-event-connection/:connectionId/run` هستند. فیلدهای سطح بالای پیشین به `config` و `secrets` می‌روند:

  ```json
  {
    "data": {
      "name": "Google SecOps production",
      "provider": "google-secops",
      "config": {
        "region": "us",
        "instanceResourceName": "projects/{project}/locations/{location}/instances/{instance}"
      },
      "secrets": {
        "serviceAccountJson": "<the service account key file, as a JSON string>"
      },
      "alertingOnly": true,
      "pollIntervalInMinutes": 5,
      "isEnabled": true
    }
  }
  ```

  ‏`alertingOnly` وارون `includeNonAlertingDetections` پیشین است: برای دریافت **Detections** هم آن را `false` بگذارید. ‏`secrets` فقط‌نوشتنی است، همان‌گونه که `serviceAccountJson` بود.

- **رویدادها ویژگی اتصال تازه‌ای دارند.** تشخیص‌هایی که پیش از انتقال دریافت شده‌اند ویژگی `oneuptime.google_secops.connection_id` را نگه می‌دارند. تشخیص‌هایی که پس از آن دریافت شوند، مانند هر رابط مدیریت‌شده، `oneuptime.security_connection.id` را دارند (با `oneuptime.security_connection.provider` برابر `google-secops`). هر دو همان شناسه اتصال را نگه می‌دارند، پس برای جستجو در دو سوی ارتقا روی هر دو پالایش کنید. **View events in this time range** روی اجرای منتقل‌شده ویژگی‌ای را به کار می‌برد که رویدادهایش با آن نوشته شده‌اند.

## گزینه ۳ — فوروارد کردن رویدادهای UDM

برای جستجو و هم‌بستگی با وفاداری کامل، خودِ رویدادهای UDM را فوروارد کنید (برای نمونه از خط لوله صادرات BigQuery، یک Cloud Function، یا هر فورواردری که از پیش اجرا می‌کنید):

```bash
curl -X POST "https://oneuptime.com/security-events/v1/ingest?format=udm" \
  -H "Content-Type: application/json" \
  -H "x-oneuptime-token: <your telemetry ingestion key>" \
  -d '{
    "events": [
      {
        "metadata": {
          "event_type": "USER_LOGIN",
          "event_timestamp": "2026-08-21T10:00:00Z",
          "vendor_name": "Google",
          "product_name": "Google SecOps"
        },
        "principal": { "user": { "userid": "alice" }, "ip": ["203.0.113.7"] },
        "target": { "hostname": "vpn-gw-01" },
        "security_result": [{ "severity": "HIGH", "action": ["BLOCK"] }]
      }
    ]
  }'
```

- مقدار `format` می‌تواند `udm`، `ocsf`، `google-secops-alert` یا `generic` باشد؛ نگذاریدش و گویش به ازای هر رویداد تشخیص داده می‌شود.
- بدنه شیئی تنها، آرایه‌ای خالی، یا `{ "events": [...] }` می‌پذیرد.
- هدر `x-oneuptime-service-name` را بگذارید تا کنترل کنید رویدادها به کدام سرویس تله‌متری منتسب شوند (پیش‌فرض نام محصول در محموله است).

## چه می‌گیرید

- **کاوشگر رویدادهای امنیتی** — جستجو و پالایش رویدادها بر پایه شدت، کلاس OCSF، بازیگر، هدف، یا هر مشاهده‌پذیری.
- **هم‌بستگی** — مشاهده‌پذیرهای هر رویداد (کاربران، میزبان‌ها، IPها، دامنه‌ها) نمایه می‌شوند، پس «هر چیزی که این میزبان را می‌آورد» یک پرس‌وجوست، کنار گزارش‌ها و سنجه‌های همان میزبان.
- **قواعد تشخیص** — تشخیص‌های [Sigma](https://sigmahq.io/) به‌صورت کد که هر دقیقه بر رویدادهای شما سنجیده می‌شوند؛ تطبیق‌ها هشدارهای بدون تکرار (با مسیردهی کشیک) باز می‌کنند و رویدادهای Detection Finding می‌نویسند.
- **مانیتورهای رویداد امنیتی** — وقتی شمار رویدادهای مطابق از آستانه‌ای بگذرد هشدار بده، با همان معیارها، حادثه و ماشین‌آلات کشیکی که هر مانیتور دیگری دارد.
- **داشبوردها و هوش مصنوعی** — ابزارک‌های رویداد امنیتی (از جمله نمای جریان Sankey) روی داشبوردهای سفارشی، و ابزارهای دستیار هوش مصنوعی (`search_security_events`، `security_event_summary`) برای بررسی به زبان طبیعی.
