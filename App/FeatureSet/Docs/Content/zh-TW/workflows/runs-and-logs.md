# 執行與日誌

每次工作流程執行時，OneUptime 都會儲存一筆關於發生了什麼事的紀錄——何時執行、是否成功，以及每個區塊做了什麼。這筆紀錄稱為**執行（run）**。執行讓你能夠確認工作流程是否正常運作、為失敗的工作流程進行除錯，並回顧過去的活動。

## 在哪裡找到它們

| 頁面                        | 你會看到什麼                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------ |
| **Workflows → Runs & Logs** | 專案中每個工作流程的每一次執行。可依工作流程名稱、狀態與時間篩選。                 |
| **Workflow → Runs & Logs**  | 僅限這一個工作流程的執行。此頁改用 **Run ID** 篩選器，而非工作流程篩選器。         |
| **單一次執行**              | 透過執行列上的 **View Logs** 按鈕開啟——執行列本身無法點擊。                       |

## 執行狀態

| 狀態                                 | 代表的意義                                                                                                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Scheduled**                        | 觸發器已觸發，執行已排入佇列等待執行器處理。通常只需要不到一秒的時間。若排定 5 分鐘後仍為 Scheduled，即視為失敗——代表沒有執行器接手。                         |
| **Running**                          | 工作流程正在進行中。長時間執行的區塊會讓執行保持在此狀態。                                                                                                     |
| **Waiting**                          | 執行停在一個 **Sleep** 區塊，並會自行恢復。等待期間不會佔用任何工作器。                                                                                        |
| **Executed**                         | 執行到達結尾且未失敗。（這是成功狀態——標籤顯示的是 **Executed**，而不是「Success」。）                                                                        |
| **Error**                            | 執行因某個區塊拋出錯誤而停止。當已排入佇列的執行從未被接手、休眠中的執行遺失了恢復訊號、排程運算式無法解析，或工作流程在執行中途被停用時，也會使用此狀態。 |
| **Timeout**                          | 執行的時間超過了允許的範圍。請參閱[設定與安全](/docs/workflows/configuration)。                                                                                |
| **Execution Exceeded Current Plan**  | 專案在過去 30 天內已用完其工作流程執行次數，或訂閱未付款。該次執行會被記錄，但不會被執行。僅限 OneUptime Cloud。                                              |

會交接到其 **Error** 輸出的區塊——例如遇到 4xx 的 API 區塊——並不會讓執行失敗。錯誤分支會執行，而該次執行仍以 **Executed** 結束。該步驟本身仍會以紅色繪製，方便你找到它。

## 解讀一次執行

點擊執行上的 **View Logs** 即可開啟它。**Workflow Run** 檢視畫面有兩個分頁。

**Steps**——每個已執行的區塊各佔一列，依序排列。每一列顯示區塊的標題、其元件 id、耗費的時間，以及它離開時所走的輸出（`→ success`、`→ error`、`→ yes`）。展開一列可看到兩個細節區塊：

- **Received**——區塊在所有變數都被解析之後所收到的設定。
- **Returned**——它產生的內容。

失敗的步驟以紅色顯示並預設展開，錯誤訊息會印在 **Received** 上方。

**Full Log**——執行器印出的原始逐行日誌，包含區塊自己記錄的任何內容。當 Steps 檢視無法解釋失敗原因時，就使用這個分頁。

有兩個細節值得了解。每個步驟標題下印出的元件 id，正是可貼入 `{{local.components.<id>.returnValues.…}}` 參照中的確切字串，這是取得正確參照最快的方式。此外，一次執行只會保留最後 100 個步驟——執行時間過長或多次恢復的執行，會在早期步驟被捨棄的位置顯示一則琥珀色提示。

顯示的值是區塊在變數填入後所看到的內容，但有兩個例外：密鑰以及區塊標記為敏感的欄位會被遮蔽，非常長的值則會被截短並附上「…（已截斷）」。

從 **Builder** 開始一次執行，會直接開啟這個相同的檢視畫面並持續追蹤該次執行，讓你可以即時觀看，而不必事後再去尋找它。

## 常見除錯

### 「我的工作流程沒有執行。」

1. 確認該工作流程在其 **Overview** 頁面上已**啟用**。新的工作流程預設為停用，而停用的工作流程會拒絕每一次執行——包括手動執行。
2. 對於 OneUptime 事件觸發器：確認該事件確實發生了。開啟該紀錄並檢查其歷史記錄。
3. 對於 webhook 觸發器：確認另一個系統正在傳送到正確的 URL。大多數工具在傳送 webhook 時都會記錄——到那裡檢查。
4. 對於排程觸發器：確認 cron 運算式符合你預期的時間。

如果執行*確實*出現，但狀態是 **Execution Exceeded Current Plan**，代表專案在過去 30 天內已用完其工作流程執行次數，或訂閱未付款。該次執行的日誌會註明次數與你方案的上限。此項僅適用於 OneUptime Cloud。

### 「後面的某個區塊從未執行。」

一個沒有執行的區塊通常是接線問題。開啟 **Builder** 並檢查：

- 前一個區塊的輸出是否已連接到這個區塊的輸入？
- 前一個區塊是否走了與你預期不同的輸出——**Error** 而非 **Success**，或 **No** 而非 **Yes**？Steps 分頁會顯示它走了哪一個。

### 「某個變數傳過來是空的。」

開啟該次執行，並查看失敗步驟的 **Received** 區塊。

- 如果你看到字面的 `{{local.components.…}}` 文字，代表該參照沒有被解析。通常是元件 id 或回傳值 id 打錯字——記得那是區塊的 **Identifier**，而不是它上面顯示的名稱。也要檢查 `local.components` 本身的拼字：`{{local.componets.api-get-1.returnValues.response-body}}` 會被當成字面文字送出，而該次執行仍會回報為 **Executed**。
- 如果你看到的是空字串，代表前一個區塊有執行，但沒有產生那個欄位。

**Full Log** 分頁會有一行警告，指名任何未能解析的參照，通常是找到問題最快的方式。

### 「我手動執行時可以運作，但從觸發器執行卻不行。」

開啟 **Builder**，點擊 **Run Workflow**，並在觸發器的欄位中填入看起來像真實觸發器所傳送內容的值。然後將該次執行的 **Received** 值與真實執行的值並排比較。差異通常出在單一的欄位名稱或型別。

## 重新執行工作流程

沒有「重試這次執行」的按鈕。我們不會自動重新執行舊的執行，因為其副作用——Slack 訊息、API 呼叫、工單——重複執行可能並不安全。若要重做這項工作，請修正工作流程，並讓下一次真實的觸發器觸發它，或開啟 **Builder** 並以相同的值點擊 **Run Workflow**。

## 執行紀錄會保留多久？

在 OneUptime Cloud 上，執行紀錄會保留 **30 天**後刪除——這也是為什麼兩份執行清單都自稱涵蓋最近 30 天。自架安裝則會保留執行紀錄，直到你自行刪除為止；如果某個工作流程執行得非常頻繁並使你的歷史記錄變得雜亂，請停用或刪除它，以停止增加雜訊。

在加入步驟追蹤功能之前所記錄的執行，沒有 **Steps** 內容，只會顯示其 **Full Log**。
