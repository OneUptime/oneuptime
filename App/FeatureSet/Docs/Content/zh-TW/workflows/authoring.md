# 建立工作流程

要建立工作流程，打開 **工作流程** 再點 **建立工作流程**。一個叫做 **Create a workflow** 的精靈會帶你走完：先是 **Start from**——挑 **Start from scratch** 或其中一個範本——接著是 **名稱**，最後是 **設定** 這一步，只有在你挑的範本本身需要額外設定時才會出現。

建好之後，在左側選單打開 **建構器**。那就是你設計工作流程的畫布。

## 畫布

從零開始的工作流程，一打開只有一個虛線區塊，上面寫著 **Please click here to add trigger**。那個區塊就是起點——點它就能挑觸發器。用範本建立的工作流程，一打開區塊就已經排好了。

每個工作流程最上面都恰好有一個**觸發器**。其餘每一個都是負責做事的**元件**。再加第二個觸發器會取代掉第一個，而刪掉最後一個觸發器，虛線佔位區塊就會回來。

加入區塊的方式：

- **觸發器**——點那個虛線佔位區塊。會打開一個標題為 **Add Trigger** 的面板。
- **其他所有東西**——點畫布上方工具列的 **新增元件**。同一個面板會打開，標題變成 **新增元件**。

兩個面板都能搜尋——按 `/` 可以直接跳到搜尋框——而且依分類分組。選好一個區塊，再點 **Add to Workflow**。

新區塊永遠落在畫布上的同一個位置，所以新加的可能會疊在你已經放好的東西上面。把它拖開就好；拖動時畫布會自動對齊格線。區塊位置會被保存下來，所以下一個人看到的排法，就是你離開時留下的樣子。

變更會自動儲存。工具列上有個小標籤在追蹤這件事：變更還在傳送時顯示 **Saving…**，成功後變成 **已儲存**，沒成功則是 **無法儲存**。沒有儲存按鈕，也沒有另外的發布步驟。

## 區塊上有什麼

| 欄位 | 用途 |
| ---- | ---- |
| **Identifier**（在 **ID** 底下） | 顯示在區塊上的那個短 id，例如 `log-1`。其他區塊就是靠它指到這個區塊，所以改掉它會弄壞每一個指向它的 `{{local.components.…}}` 參照。區塊的標題是元件本身的名稱，不能更改。 |
| **設定** | 這個區塊完成工作所需要的東西——一個網址、一個 Slack 頻道、一段訊息內容。選填欄位會標上 **(Optional)**；其餘都是必填。比較少用的設定收在 **進階** 的摺疊區裡。 |
| **Input** | 上緣的那個點，從前面區塊拉過來的線接在這裡。觸發器沒有輸入——在它之前沒有東西會執行。 |
| **Outputs** | 下緣的那些點，正上方有標籤，連出去接到後面的區塊。很多區塊有各自獨立的 **成功** 與 **錯誤** 輸出，讓你兩種情況都能處理。 |

## 連接區塊

從一個區塊下緣的點，往下拖到下一個區塊上緣的點。你畫的這條線決定接下來執行什麼。

- 從 **成功** 連出去，下一個區塊只有在前一個成功時才會執行。
- 從 **錯誤** 連出去，下一個區塊只有在前一個失敗時才會執行。
- 沒有接出去的輸出，那條路徑就到此為止。

一個輸出可以接到好幾個區塊。它們全都會執行——但是排成一列一個接一個跑，不是平行的。不要依賴不同分支之間的先後順序，也別指望它們在時間上會重疊。每個區塊在一次執行中最多只跑一次，所以繞回前面區塊的迴圈不會讓它跑第二次。

## 設定區塊

點一個區塊，就會在對話框裡打開它的設定。每個設定都有合適的輸入方式——文字欄位、下拉選單、程式碼編輯器、開關等等。填好之後點 **儲存**。

同一個對話框裡還有：

- **刪除**——移除這個區塊。
- **Run just this step**——單獨執行這一個區塊，不跑工作流程的其餘部分。原本要從其他步驟讀來的值會是空的，而它送出、寫入或刪除的東西是真的會發生。
- **文件**、**Inputs**、**Outputs** 和 **Returns**——說明這個區塊需要什麼、產出什麼的參考卡。

大部分文字欄位都接受變數——資料就是這樣從一個區塊流到下一個。與其自己手打語法，不如用編輯器裡的值選擇器：它會依你挑的區塊和欄位組出正確的參照。請見[工作流程變數](/docs/workflows/variables)。

## 邊做邊檢查

你每改動一次，建構器就會重新檢查整張圖，並把結果報在工具列的一個小標籤上。點那個標籤會打開 **Problems with this workflow**，裡面逐條列出問題，並帶你跳到出問題的區塊。有問題的區塊在畫布上也會帶一個紅色標記。

它抓的是那些不跑一次就看不出來的錯誤——沒有觸發器、兩個區塊共用同一個 id、id 裡有小數點、沒有任何東西連到的區塊、必填設定留空、格式錯誤的 JSON、`{{ }}` 裡面有空格，以及指向不存在的步驟或回傳值的參照。

有一件事它檢查不了：變數名稱到底存不存在。改過名字的變數，只會在執行日誌裡現形。

## 你的第一個工作流程

最快摸熟畫布的做法：

1. 點那個虛線佔位區塊，在 **Add Trigger** 面板裡挑 **Manual**，然後點 **Add to Workflow**。
2. 點 **新增元件**，挑 **Log**（在 **Utils** 底下），再點 **Add to Workflow**。把新區塊拖離觸發器，然後把觸發器的 **Execute** 點連到 Log 區塊的輸入點。
3. 打開 Log 區塊，把它的 **值** 設成 `Hello from {{local.components.manual-1.returnValues.value.name}}`。`manual-1` 是觸發器的 **Identifier**，會顯示在觸發器區塊上——記得核對一下。
4. 到 **概覽**，在 **工作流程詳細資訊** 卡片上點 **編輯工作流程**，把 **已啟用** 打開。停用的工作流程完全跑不了，連手動都不行。
5. 回到 **建構器**，點 **執行工作流程**，在 **JSON** 欄位放進 `{ "name": "Ada" }`，點 **Run Workflow Manually**，再用 **Run** 確認。
6. 一個 **Workflow Run** 面板會自己打開並跟著這次執行。日誌裡會看到 `Value:` 後面接著 `Hello from Ada`。

這個循環——加入、連接、設定、執行、讀日誌——就是你之後建每一個工作流程的方式。

## 啟用它

新的工作流程一開始是停用的，你複製或匯入來的工作流程也一樣。

**已啟用** 開關在工作流程的 **概覽** 頁、**工作流程詳細資訊** 卡片裡——不在設定頁上。同一張卡片會用綠色的 **已啟用** 或紅色的 **已停用** 標籤顯示目前狀態。

停用的工作流程完全跑不了。手動執行會被擋下，訊息和被觸發的執行一樣是「This workflow is not enabled」，所以順序是：先啟用，用 **執行工作流程** 測一次，讀執行日誌，如果還沒準備好讓它的觸發器真的開火，再把 **已啟用** 關掉。想在不跑整個工作流程的情況下測單一區塊，用那個區塊設定裡的 **Run just this step**。

想暫停工作流程又不想刪掉它，就把 **已啟用** 關掉。不會有新的執行開始。跑到一半的執行會跑完，但停在 **Sleep** 區塊上的那些，醒來時會被取消並記為錯誤。

## 收拾整理

- 拖動區塊就能移動位置。版面會被保存。
- 想刪掉一條線，把它任一端從點上拖開，丟在空白的畫布上。
- 想刪掉一個區塊，點它，再用設定對話框底部的 **刪除**。選取一個區塊或一條線再按 Backspace 也能移除。
- 沒有辦法複製單一區塊。工作流程 **設定** 頁上的 **Duplicate Workflow** 會複製整個工作流程，而副本是停用的。
- 把區塊由上往下堆，讓它們的閱讀方向就是執行方向——輸入在上緣、輸出在下緣，流程自然往下走。
