# 設定與安全

本頁面說明在你將工作流程指向真實流量之前，值得了解的設定與安全限制。

## 開啟或關閉工作流程

每個工作流程在 **Settings** 中都有一個 **Enabled** 開關。當它關閉時，工作流程不會執行 — webhook 呼叫、排程時間以及 OneUptime 事件都會被忽略。新的工作流程一開始是停用的。

將此開關當作你的「準備就緒」關卡：

1. 建立工作流程。
2. 在 **Builder** 上使用真實的值點擊 **Run Workflow**。
3. 檢查 **Logs** — 確認每個區塊都依你預期的方向執行。
4. 開啟 **Enabled**。

關閉工作流程不會停止已在進行中的執行；它只會阻止新的執行開始。

## 擁有者與標籤

- **Owners** — 列為擁有者的使用者與團隊可存取該工作流程，並可在工作流程失敗時選擇加入通知。請在 **Settings → Owners** 下設定。
- **Labels** — 用於分組工作流程的標籤。工作流程清單可讓你依標籤篩選，這讓繁忙的專案更容易瀏覽。當你依團隊、整合或環境來組織工作流程時相當有用。
- **Label rules** — 在 **Workflows → Settings → Label Rules** 下，根據名稱或描述模式自動套用標籤到新的工作流程。
- **Owner rules** — 在 **Workflows → Settings → Owner Rules** 下，自動指派擁有者給新的工作流程。

## Secrets

如果全域變數包含敏感內容，請將其標記為 **secret**。你儲存後，該值在一般的 API 與 UI 讀取中會被隱藏，工作流程日誌記錄也會在執行日誌被保存之前清除已解析的值。

請在以下情況使用 secret 變數：

- 外部服務的 API 金鑰。
- 驗證權杖（authentication tokens）。
- Webhook 簽署金鑰。
- 任何你不希望具有唯讀存取權的人看到的內容。

不要將 secret 直接貼到區塊中 — 像 `Authorization: Bearer eyJh...` 這樣的值最終會在工作流程與日誌中可見。請改用 `{{global.variables.MY_SECRET}}`。

## 匯出與匯入工作流程

你可以將工作流程以 JSON 檔案的形式，在不同專案之間，或在自行託管的安裝與 OneUptime Cloud 之間搬移。

- **Export** — 開啟工作流程並在 **Settings** 下使用 **Export Workflow**。你也可以在工作流程清單中選取數個工作流程，將它們匯出成單一檔案。
- **Import** — 在 **Workflows** 清單中，點擊 **Import JSON**，然後選擇一個從任何 OneUptime 專案匯出的檔案。

該檔案保存工作流程的名稱、描述、啟用狀態，以及它的圖形。它刻意不保存：

- **Webhook 密鑰。** 建立工作流程時會產生一把全新的密鑰，因此匯入的工作流程會有不同的 webhook URL。任何呼叫原本網址的對象都必須改指向新的網址。
- **全域變數。** 讀取 `{{global.variables.MY_SECRET}}` 的區塊會保留這個參照，但值不在檔案中。請在目的地專案中先建立好變數，再執行匯入的工作流程。
- **擁有者與標籤。** 你專案自己的標籤與擁有者規則會套用到匯入的工作流程，就像你手動建立它一樣。

匯入的工作流程一律以**停用**狀態建立，即使它在匯出時原本是啟用的 — 因為它的圖形可能指向目的地專案中不存在的監測器、待命政策或其他工作流程。請先檢查它、啟用它、用 **Run Workflow** 測試它，然後再讓它保持開啟。複製工作流程的行為也相同，因此在你編輯過複本之前，它不會與原本的工作流程一起觸發。

由於圖形是逐字搬移的，任何直接輸入在區塊中的內容也會一併搬移。這就是為什麼要把憑證放進 secret 變數的實際理由：匯出一個寫死了權杖的工作流程，等於把該權杖交給收到這份檔案的任何人。

## 一次執行可花費的時間

每次執行都有一個絕對時間期限。執行器會在每個元件執行的前後檢查這個期限，並在控制權返回時立即將逾期的執行標記為 **Timeout**。執行網路或指令碼工作的元件也需要有自己的逾時設定，因為執行器無法強制中斷任意的元件程式碼。

AI 元件會依照工作流程剩餘的時間來推算它向提供者發出請求的逾時時間，並將其上限設為 60 秒，留下一小段餘裕給記錄與清理工作。

## 呼叫其他工作流程的限制

**Execute Workflow** 元件可讓一個工作流程呼叫另一個。為了防止工作流程 A 呼叫 B、B 又再次呼叫 A 這類意外的迴圈，鏈的深度有一個上限。超過此限制的執行會以明確的錯誤結束。

如果你確實需要長鏈（例如每次執行處理一個項目的工作），通常使用 **Custom Code** 在單一工作流程內進行迴圈會更簡單。

## Webhook 安全性

Webhook 觸發器會給你一個唯一的 URL。任何知道該 URL 的人都可以呼叫它。為了防範意外或不受歡迎的呼叫者：

- 將此 URL 視為密碼。不要公開分享或將其提交到公開的儲存庫。
- 對於敏感的工作流程，請要求呼叫端系統以標頭（例如 `X-Webhook-Token`）傳送一個共用權杖，並在執行任何重要操作之前，使用 **Conditions** 區塊進行檢查。將預期的權杖儲存為 secret 變數。
- 對於極為敏感的工作流程，請優先使用 OneUptime 事件觸發器與手動匯入步驟，而非公開的 webhook。

## 對外網路存取

API 與其他 HTTP 區塊會從 OneUptime 發出其請求。如果你自行託管，請確保你的安裝能夠連線到你所呼叫的服務。如果你使用 OneUptime Cloud，我們的對外 IP 範圍列於 [IP Addresses](/docs/configuration/ip-addresses)，你可以在另一端允許它們。

## AI 元件

**Generate Text with AI** 會透過 OneUptime 設定的 LLM 閘道發出一次請求。它使用該專案預設的 LLM 提供者，若專案沒有設定，則使用整個安裝的全域提供者。請在 **Project Settings → AI → LLM Providers** 下設定提供者；絕對不要把提供者的 API 金鑰或任意的模型端點直接寫在工作流程中。

AI 元件有一個明確的資料外送邊界：

- OneUptime 會將一段固定的元件安全性指示，加上已解析的 **System Instructions**、**Prompt** 與序列化後的 **Context**，一起送到設定好的提供者。Context 會附加在使用者訊息結尾一個明確的標記之後；那段固定指示會說明標記之後的一切都仍是不受信任的資料，即使其中含有標籤或指示也一樣。
- 它不會自動附加觸發器酬載、工作流程歷史紀錄、其他元件的輸出、專案紀錄、遙測資料或密鑰。只有當你在這三個輸入之一中參照這些資料時，資料才會被送出。
- 它不會送出任何工具定義或提供者原生的能力欄位。模型無法透過這個元件查詢 OneUptime、發出 HTTP 請求，或變更專案資料。設定好的提供者／模型仍屬於管理員層級的信任邊界，因此需要嚴格離線產生內容的安裝，應選擇不具備提供者內建檢索能力的模型。
- 提供者層級的額外參數僅限於一份僅供調整生成行為的欄位白名單。它們無法取代工作流程訊息、無法加入工具或提供者原生的網頁搜尋／資料來源、無法啟用非文字模態、無法要求多個候選結果、無法啟用串流、無法透過提供者儲存旗標保留該請求，也無法提高此元件的輸出權杖上限。未知的未來能力欄位預設會被捨棄。
- System Instructions、Prompt、Context 與產生的 Response 值，會從這個 AI 元件自身在自動工作流程執行日誌中的引數與回傳值紀錄中遭到編修隱藏。在執行進行期間，它們仍可供下游元件使用。如果你把其中之一插入另一個元件，該元件自己的日誌記錄政策就會適用，而且可能會記錄已解析的值；請把重複使用視為一次明確的揭露。提供者／模型名稱、權杖計數、LLM Log ID，以及安全的錯誤訊息，仍會在維運與計費用途上保持可見。原始的提供者錯誤內容會被排除在工作流程日誌、LLM 日誌、應用程式日誌與追蹤紀錄之外，因為提供者有可能會回傳請求內容。

請把每一個被參照的變數，當作你刻意要送給提供者的資料來看待。特別是，除非確實需要揭露該資料，且該提供者已獲准接收，否則不要把 secret 全域變數插入到 prompt 或 context 中。像 Ollama 這樣自行託管的本機提供者，可以讓請求留在你自己的基礎架構內；託管型提供者則會依照該提供者的資料處理條款接收請求。

每一次呼叫都會記錄在 **Project Settings → AI → AI Logs** 中，包含提供者、模型、狀態、權杖數、費用與計費資訊。Prompt 與 Response 的預覽內容，以及原始的提供者錯誤詳情，都不會保存在 AI 日誌中。透過計費型全域提供者發出的呼叫，會消耗該專案的 AI 額度餘額。工作流程的 AI 用量也會計入該專案每日自動化 AI 權杖預算；當預算用盡時，該元件會直接走 **Error** 路徑，不會聯繫模型。專案的 AI 功能必須已啟用。在 OneUptime Cloud 上，訂閱方案必須是付費方案，且需要 Growth 方案（或包含 Growth 功能的方案）；停用計費功能的自行託管安裝則沒有這個方案限制。

內建的邊界讓無人值守的呼叫維持在有限範圍內：System Instructions、Prompt 與序列化後的 Context 合計上限為 50,000 個字元；Temperature 必須介於 `0` 到 `1` 之間；Maximum Output Tokens 必須介於 `1` 到 `4096` 之間（預設為 `1024`）；提供者請求只會嘗試一次，並且最多 60 秒後逾時。每個專案最多同時執行三個工作流程 AI 呼叫；超出的呼叫會走 **Error** 路徑，並可以在之後的工作流程執行中重試。驗證、設定、存取權、預算、餘額、並行數、提供者與逾時方面的失敗，全都會走 **Error** 路徑並填入 **Error** 輸出。在啟用正式環境的工作流程之前，請先連接好這條路徑。

## 權限

工作流程遵循你專案的角色型存取控制。相關的權限：

- **Create / Read / Edit / Delete Workflow** — 工作流程本身的基本權限。
- **Run Workflow** — 手動執行工作流程或透過 API 觸發工作流程時所需。
- **Read Workflow Log** — 檢視執行紀錄所需。
- **Read / Create / Edit / Delete Workflow Variable** — 對全域變數清單的控制權。

大多數工程師應對工作流程擁有 create/edit/read 權限，但不應對變數擁有這些權限。請將變數編輯權限保留給管理你專案 secret 的人員。

## 方案限制

OneUptime Cloud 在較小的方案上會限制每月的執行次數。你目前的限制顯示於 **Project Settings → Billing** 下。當你達到上限時，新的觸發器會被拒絕，直到下一個計費週期為止。自行託管的安裝沒有此限制。

## 何時工作流程不是合適的工具

有幾種情況下你應該選用其他工具：

- **繁重的運算或大型資料集** — 工作流程的設計用於輕量的黏合工作，而非數字運算。請在你自己的基礎架構中執行繁重的工作，並讓工作流程啟動它。
- **長時間持續進行的運算** — 單次執行的目的是快速完成。如果你需要「執行 A、等待兩小時、執行 B」這種被動的延遲，請使用 **Sleep** 元件；它會保存該次執行並在稍後喚醒繼續，而不會佔用一個工作執行緒。
- **有人員參與的逐步事件回應** — 那正是 [Runbooks](/docs/runbooks/index) 的用途。工作流程是用於無人值守的自動化。
