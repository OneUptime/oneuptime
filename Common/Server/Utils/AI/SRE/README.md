# AI SRE — autonomous investigation engine

Wake-on-signal AI SRE: when an incident or alert is created (and the project has opted in), AI runs a read-only, budgeted, citation-minting investigation over the project's own telemetry and posts a root-cause analysis to the subject's feed, with a glass-box `AIRun`/`AIRunEvent` trail behind a live dashboard panel.

- `AIInvestigationEngine.ts` — shared run lifecycle, budgets, persona, quiet-mode confidence gate
- `IncidentInvestigationRunner.ts` / `AlertInvestigationRunner.ts` — per-subject context assembly + result posting
- `IncidentPostmortemRunner.ts` — auto-draft postmortem when an incident resolves
- `AIMemory.ts` — recurrence context from past resolved incidents (retrieval-only v1)
- `RemediationHandoff.ts` — the investigation → auto-remediation hand-off (RCA-first ordering). The incident/alert create hooks defer `AutoRemediationRuleEngineService` whenever an investigation was enqueued (the runners' `investigateNew*` return "enqueued"); this module releases the subject to the rule engine when that investigation **settles** — any terminal outcome. Settle-once discipline is inherited from the run-status CAS transitions (the same discipline that keeps `postAnalysis` single-shot): only the actor that WON a terminal transition calls the hand-off. The settle sites: Completed and finalized-Error via `InvestigationRequest.onSettled` / the runners' `failOrRequeue` outcome, queue-TTL expiry and terminal-stale via `InvestigationQueue`'s private hand-off. A failed investigation still hands off — remediation degrades to its pre-RCA behavior, never silently disappears; with no investigation enqueued, the create hook applies rules immediately and this module is never involved.
- `ConfidenceSignal.ts` — the structured, server-verified confidence signal (deterministic evidence floor + one constrained classification call), with per-consumer fail directions
- `FixFromIncidentTaskTrigger.ts` — the FixFromIncident recipe's two trigger forms: the human "Open Fix PR from this analysis" button (no opt-in flag — the click is the gate), and the automatic form for projects opted in via `Project.enableAutomaticCodeFixes` (default false). The automatic form fires from the runners' `postAnalysis`, only on `AIConfidenceSignal.shouldAutoEnqueueCodeFixTask` — a POSITIVE confident classification; the evidence floor and a failed classification both fail toward doing nothing. Never throws; pre-checks the daily fix-run budget as a quiet skip; same repo + per-subject dedupe gates as the button; the enqueued run is system-authored (no userId).
